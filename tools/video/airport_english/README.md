# Airport English production adapter

`prepare.mjs` converts the revised 60 lesson sources into the repository's official
`video.json`, brief, claims, translations and preparation records. It imports the
existing schema, lint, subtitle segmentation, timeline estimate and request planner.
It does not synthesize media, record approvals, certify ten minutes or publish.

```bash
node tools/video/airport_english/prepare.mjs prepare
node tools/video/airport_english/prepare.mjs prepare --days 1
node --test tools/video/airport_english/prepare.test.mjs
```

The source directory is
`docs/videos/airport-english-60-days/production/lessons`; outputs are adjacent
`dayNN/` directories. Preparation requires all five languages, the five episode-specific
guides and explicit quiz `evidence_ids`. A missing or unknown ID fails before output.
References retain source-turn IDs and stable semantic hashes; adding a turn does not
renumber existing speech or captions. Repeated dialogue uses the official `audio_ref`
contract, pointing to an earlier original take with identical words and voice.

The official `quote` card displays each full English utterance. Traveler/Staff labels
follow the source's reviewed T/S speaker flags. Translations remain CC.
Long English text uses up to three balanced rows with nonbreaking spaces so the official
font fitting checks width instead of silently creating a fourth row. This affects only
the picture; the canonical speech and caption text are unchanged.
The generated subtitle plan only segments text using the official language rules;
actual cue timings must come from checked speech. A source estimate below eight minutes
fails the normal lint; this adapter never lowers the minimum.

`duration-plan.json` distinguishes the estimate from the missing measured body, branding
and final duration. After synthesis, measure and pin the installed official branding,
then edit the lesson pacing to total 18,000 frames. Do not label the estimate a finished
600-second video or make up time with arbitrary silence, slower audio or extra loops.

Some official commands accept `--file`, but `qa`, `captions`, `status` and review gates
resolve `docs/videos/<slug>`. Stage a copy outside Git so all commands see the same source:

```bash
node tools/video/airport_english/prepare.mjs stage-project \
  --project-root /workspace/airport_production/project \
  --media-root /workspace/airport_production/media
node tools/video/airport_english/prepare.mjs run --days 1 --stage lint \
  --project-root /workspace/airport_production/project \
  --media-root /workspace/airport_production/media
node tools/video/airport_english/prepare.mjs run --days 1 --stage tts --dry-run \
  --project-root /workspace/airport_production/project \
  --media-root /workspace/airport_production/media
```

The wrapper calls the real official CLI with the staged project root. Review, credential,
quota and media evidence requirements remain in force. Staging is explicit: edits require
another snapshot and invalidate the corresponding official hashes. Approval files are
never generated by this adapter. The source repository and staged project cannot contain
the media directory.
Before actual TTS, the wrapper checks the independent review binding and the bytes of the
staged script, translations, source lesson, profile, lexicon and review evidence. A dry run
can precede a binding; once a binding exists, even a dry run refuses a stale snapshot.

`teaching-audio.json` specifies translated coaching and quizzes while reusing English
dialogue takes. Standard `dub` currently reads CC translations for every line, so this
adapter blocks it until the official mixed-language support is available. The translation
must remain in CC even when English audio is reused. English take provenance and the
translated coaching must both pass the real audio checks; a locale's common video timeline
does not by itself prove speech synchronization.

The separate teaching-audio adapter implements this contract using the official speech
client, transcription/judgement and loudness primitives:

```bash
node tools/video/airport_english/teaching-audio.mjs plan \
  --file /workspace/airport_production/project/docs/videos/airport-english-day01/video.json \
  --workdir /workspace/airport_production/media/airport-english-day01 --locale zh-TW
```

`plan` and `--dry-run` are offline. `build` requires current approved English audio with
per-line checks, pinned official branding and a measured 18,000-frame presentation.
It reuses the checked English WAVs and synthesizes only the translated teaching lines.
`check` performs the actual mixed-language audio checks. Outputs live under
`teaching-audio/<locale>/` with their own `airport-teaching-audio/v1` manifest, track,
CC and check report; they do not impersonate generic dub manifests or grant approval.

Delivery can be inspected without creating or uploading media:

```bash
node tools/video/airport_english/delivery.mjs plan \
  --project-root /workspace/airport_production/project \
  --media-root /workspace/airport_production/media
```

`build` also needs `--out /external/new-delivery`; it requires a new output directory separate
from the source and media directories. It consumes the current official English package
and all four checked teaching tracks, preserves the official metadata bytes, and creates
the local HTTP preview, file hashes and `COMBINED_REVIEW.json`. The combined-review record
does not grant formal package QA or publication approval.

The profile records the user's four CC/teaching-language choices. English and Traditional
Chinese metadata are selected; other prepared metadata are drafts and not extra upload
selections. The official thumbnail color-block fallback is allowed when no subject art is available.
Installed branding, independent review, measured media,
official audio checks, final QA and package QA remain separate required production steps.
YouTube uploading and publishing are outside this task's authorization.
