# 短劇：AI 角色短劇，從一個梗到一部系列

`.agents/skills/producer/SKILL.md` §4 的細節。站主 2026-11-03 給的兩支 Instagram 寵物短劇只是範例：長度不限於 15 秒，
同一個公式可以撐到 55 秒的 Shorts、幾分鐘的一集，或角色固定的系列。站主同時在做的《汪汪社畜》是這份文件的實際範例。

## 長度分級

| 級 | 長度 | 結構 | 走哪條路線 |
| --- | --- | --- | --- |
| 單梗 | 10–20 秒 | 一個情境、一次反轉、停在反應 | 現有 Shorts 工具收不下（下限 25 秒，見〈缺口〉）；先寫成雙反轉 |
| 雙反轉 | 25–35 秒 | 情境 → 第一次反轉 → 以為結束 → 第二次反轉 | Shorts `import` 或 `from-drama` |
| 一集短劇 | 45–55 秒 | 鉤子、三四個逐步升高的笑點、兩次反轉、結尾留下一集的鉤子 | 漫劇流程做 16:9，再 `shorts from-drama` 裁 9:16（汪汪社畜 EP1 的做法） |
| 長一點的一集 | 2–4 分鐘 | 同一組角色、一場戲接一場戲，每 20–25 秒一個鉤子 | AI 漫劇單集（`.agents/skills/youtube-video/references/drama.md`），長片上架；再剪 Shorts 導流 |
| 系列 | 每集任一級 | 固定角色、固定世界觀、每集一個題目，結尾接下一集 | 第一集照上面做，角色設定圖與人物表跨集沿用（`.agents/skills/youtube-video/references/series.md`） |

站主沒指定長度時，從**一集短劇（45–55 秒）**開始：Shorts 的推薦吃得到、笑點有空間升高，也能接成系列。

## 共通公式

**一個場景、兩三個角色、一個人人都懂的情境、在最後三分之一反轉、停在反應上。**
長度變長時不是把一個梗拉長，而是加笑點：每 8–10 秒一個真的會笑的點，一次比一次荒謬，反轉至少一次讓人猜不到、回頭看又合理。

## 範例一：《汪汪社畜》（站主進行中的系列）

2026-11-03 在雲端工作階段做的 EP1〈公司引進 AI 了〉（分支 `claude/kind-archimedes-gpoial`，尚未合併）：

- **設定**：柴犬麻糬把家當成公司，自己是任職五年、負責清理地上食物的資深員工；用職場語言（績效、罷工、轉職、資深員工）看寵物日常。
- **角色**：麻糬嘴不動，台詞全是厭世上班族的內心獨白；掃地機器人沒有台詞、燈環變色表情緒；主人只拍腰部以下不露臉；最後出場的機器狗接下一集。
- **結構**：新同事（掃地機器人）報到 → 績效被吸走 → 罷工被無視 → 老闆偏心 → 想轉職 → 一隻雞腿卡住機器人、資深員工證明自己 → 門口送來機器狗。
- **格式**：9:16、目標 50–55 秒；片段在 Colab 的 MiniMax H3 生成；八語做標題、說明與 CC（角色對話漫劇目前不能做配音）。
- **路線**：原生 9:16 漫劇還沒有工具，先做 16:9 再 `shorts from-drama` 裁切，主體放畫面中間三分之一。
- **笑點盲評**：送劇本關卡前，三位不同觀眾角色的評審只讀盲評包打分（hook、premise、laughs、escalation、surprise、character、payoff、share，滿分 100），
  中位數 ≥ 80、每人 ≥ 65、laughs 中位數 ≥ 14、surprise 中位數 ≥ 10、至少三個強笑點才過；沒過就換笑點、換評審重評，最多三輪。
  工具是 `comedy_review.mjs`，跟著那個分支合進 `animation-preproduction`；合併前要用就從分支取。

製片 skill 做喜劇短劇時，企劃階段就照這張評分表自評，送到站主面前的稿子先過一次盲評。

這兩支是單梗級；要放進我們的頻道，照上面的分級長成雙反轉或一集短劇，角色換成我們自己的。

## 格式

| 項目 | 規格 |
| --- | --- |
| 比例 | 9:16、1080×1920、30 fps；2–4 分鐘的一集用 16:9 長片，另剪 9:16 |
| 鏡頭 | 每鏡 2–5 秒；短的同一場景、機位少換，長的每 20–25 秒換一場或加一個鉤子 |
| 對白 | 每句 12 字內；內心獨白可以佔大部分（汪汪社畜的設計）；有對白就上繁中＋英文字幕 |
| 角色 | 我們自己的角色；不用既有 IP、名人或真人臉；主人類角色可以不露臉 |
| 標示 | 說明欄與上架設定都標 AI 生成（`contains_synthetic_media`） |

## 節拍表（交分鏡前填）

```
一句話：<誰> 在 <哪裡> 想 <做什麼>，結果 <出錯>，最後 <反轉>
長度級：單梗／雙反轉／一集短劇／2–4 分鐘／系列第 N 集
0–2 秒 鉤子：第一格就有衝突或怪事（動作或第一句台詞）
笑點 1、2、3…：每 8–10 秒一個，一次比一次荒謬（寫出在哪一鏡）
反轉：觀眾猜不到、回頭看合理
結尾：停在反應，或留下一集的鉤子
封面：反轉前最強的那一格表情
標題：寫情境不寫結局（「公司引進 AI 了」，不是「機器人被雞腿打敗」）
```

## 製作路線

1. 企劃與笑點盲評：節拍表 → 分鏡（`video.json`）→ 三位評審盲評，過了才送劇本關卡。
2. 鎖企劃與估價：`.agents/skills/animation-preproduction/SKILL.md`（分鏡、三鏡小樣、鎖定包）；要付點數等站主核准。
3. 片段：Colab H3（`.agents/skills/minimax-h3-colab/SKILL.md`）、RunPod H3（`.agents/skills/minimax-h3-runpod/SKILL.md`）、Hailuo 網頁或 Kling。
4. 合成：漫劇流程 `assemble`；或外部剪好的成片照 30 fps、48 kHz、−14 LUFS 輸出。
5. 上架：9:16 用 `node tools/video/shorts/cli.mjs from-drama`（從漫劇成片裁）或 `import`（外部成片），之後照 `.agents/skills/youtube-video/references/shorts.md` 的品管與上架。

## 現有工具的缺口

- Shorts 工具只收 25–55 秒（`tools/video/shorts/core.mjs` 的 `PROFILE`），單梗級的 10–20 秒成片 `import` 不會過；超過 55 秒的要走長片。
- 原生 9:16 漫劇還沒有工具（票 `2026-09-28-video-shorts-worker-drama`），目前先做 16:9 再裁；H3 直式 736×1312 沒驗過。
- 角色對話漫劇不能做配音（`video_locales_dub_not_for_drama`），多語是標題、說明與 CC。
- 沒有對白的短劇，`zh-TW.srt` 仍要有（品管逐句切音）；可以放情境字卡。
