# 稿子的格式

`video_kit.py` 讀的是一個 Markdown 檔。規則少，目的是讓同一份檔案同時是：站主讀的稿子、讀稿機文字、分鏡表、章節表。

```markdown
---
title: AI 模型這麼多，到底該怎麼挑？
format: explainer
recorded_on: 2026-09-23
article: ai-news-claude-opus-5-20260724
summary: 排行榜第一名不一定最適合你。這支用三個問題幫你挑：你要它做什麼、你能等多久、你願意付多少。
---

## 開場
[鏡頭] 正面，半身
每次有新模型出來，排行榜就換一次第一名。
但你真的每次都要換嗎？
[字卡] 排行榜第一名 ≠ 最適合你
今天用三個問題，幫你在五分鐘內決定。

## 排行榜到底在比什麼
[截圖] 排行榜頁面，框出分數欄
<!-- 截圖日期寫進 facts.md -->
排行榜比的是……

## 來源
- Anthropic 模型總覽 https://… （2026-09-23 確認）
```

## 規則

| 寫法 | 意思 |
| --- | --- |
| 開頭的 `---` 區塊 | 影片資訊。`title`、`summary` 會進上架包；`article` 是對應的 Mokaair 文章 slug（可省略）；`recorded_on` 是錄製日期 |
| `## 章節名` | 一個 YouTube 章節。第一個 `##` 就是 00:00 那一章 |
| 普通的一行字 | 口播。一行一句，讀稿機就一行一句 |
| `[字卡]`、`[截圖]`、`[錄影]`、`[鏡頭]`、`[B-roll]`、`[音效]` 開頭的行 | 畫面指示，不唸出來。會進分鏡表，時間是它前面的口播唸完的估計時間 |
| `<!-- -->` | 給自己或剪輯看的註解，不唸、不進分鏡表 |
| `## 來源` | 固定名稱，稿子的最後一節：查核用的來源與確認日期。不唸、不算章節，會進說明欄 |

`[字卡]` 後面的字就是字卡上要放的字；`[截圖]`、`[錄影]` 後面寫要拍什麼、要框出哪裡、要用哪個示範檔。畫面指示寫得越具體，剪輯越不用回頭問。

## 時間怎麼估

中文口播以每分鐘約 250 字估（`--cpm` 可調；語速快的人約 280、教學慢講約 220），英文單字一個算兩個字，數字一串算兩個字。估計只拿來排節奏與出分鏡表；上架的章節時間一定用剪完的實際時間（`chapters.txt`，每行 `分:秒 章節名`，例如 `03:42 排行榜到底在比什麼`）。
