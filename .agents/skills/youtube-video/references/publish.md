# 上架包與上架檢查

`video_kit.py metadata` 產出 `upload.md` 草稿：標題、說明（摘要、章節、來源、文章連結）、逐字稿的位置。以下是補完與檢查的規則。代理交出 `upload.md`；登入 YouTube Studio 與按發布是站主。

## 標題

- 給 3 個候選。100 字元是上限，但手機列表大約只顯示前 40 個全形字，重點放前面。
- 形式：觀眾的問題（「AI 模型這麼多，到底該怎麼挑？」）＋一個反直覺的鉤子（「排行榜第一名不一定最好用！」），或態度＋主題（「Claude Code 近期更新彙整，我好像又愛上它了」）。
- 產品名與版本寫正確的官方寫法，這是觀眾搜尋的關鍵字。
- 不寫影片裡沒有兌現的承諾；不全大寫、不堆驚嘆號。

## 說明欄

順序固定：

1. 前兩行：這支影片回答什麼、給誰看（搜尋結果與「顯示更多」之前只看得到這裡）。
2. 錄製日期與涵蓋的版本（更新彙整、教學必寫）。
3. 章節（見下）。
4. 影片中提到的指令、連結、工具。
5. 對應的 Mokaair 文章：`https://mokaair.com/<語系>/life/<slug>`（生活與 AI 類）或 `https://mokaair.com/<語系>/guides/<kind>/<slug>`（旅遊類）；語系一定要帶，例如 `zh-TW`。要追蹤來自影片的流量就加 `?utm_source=youtube&utm_medium=video&utm_campaign=<影片代號>`。
6. 來源（`## 來源` 的內容）。
7. 揭露：業配、聯盟連結、贊助一律寫明，並在 Studio 勾「含付費宣傳」。
8. 標籤行（最多 3 個 `#hashtag`，放最後，會顯示在標題上方）。

說明上限 5,000 字元，不放 `<` `>`（YouTube 會拒絕）。

## 章節

YouTube 要自動產生章節列，說明欄的時間戳必須：第一個是 `00:00`、至少 3 個、每章至少 10 秒、依時間遞增。`metadata` 會依這些規則檢查 `chapters.txt`；沒給 `chapters.txt` 時用估計時間出草稿並在最上面標「估計時間，剪完要換」。**估計時間不能直接上架。**

章節名寫成觀眾會搜尋的問題或名詞，不寫「第一部分」。

## 字幕

- 用 `teleprompter.txt` 當逐字稿：YouTube Studio →「字幕」→ 新增語言（中文（台灣））→「自動同步」→ 貼上逐字稿，YouTube 會自己對時間。比自動產生的字幕準確得多，尤其是產品名與英文名詞。
- 實際唸的和稿子不一樣的地方（臨場改口），同步前先在逐字稿改掉。
- 要英文等其他語系字幕，從已同步的中文字幕檔翻譯，專有名詞沿用官方英文寫法。

## 標籤與其他欄位

- 標籤（tags）總長 500 字元內，主要放常見錯字與別名（「Claude code」「克勞德」）；影響不大，別花時間。
- 播放清單：放進對應系列（例如 Claude Code 系列），系列順序與站上的系列文章一致。
- 結束畫面與資訊卡：結束畫面指向同系列下一支或最相關的一支。
- 置頂留言：一句重點＋文章連結，或一個具體的問題邀請留言。

## 需要站主決定的欄位（交給站主，代理不代填）

- 是否含付費宣傳。
- 「變造或合成內容」揭露：用 AI 產生了逼真的人聲、人像或看似真實的場景時要勾；只用 AI 寫稿、做字卡不需要。判斷不了就列給站主。
- 目標觀眾「是否為兒童專屬」：這類科技影片通常選「否」，但由站主選。
- 公開狀態與排程時間。

## 上架前檢查（全打勾才交）

- [ ] `facts.md` 沒有待查；會過期的事實在錄影前一週內確認過
- [ ] `video_kit.py check` 零 FAIL；開場 ≤ 30 秒
- [ ] 成片逐段看過：沒有 key、token、email、帳單、使用者名稱、無關分頁（規矩 4）
- [ ] 音樂與素材都有授權，出處寫在說明欄
- [ ] 章節用剪完的實際時間，`metadata --chapters` 沒有錯誤
- [ ] 說明欄連結都點過（文章連結帶語系、回 200）
- [ ] 縮圖在 320 寬下讀得到，字沒有被時間標籤蓋住
- [ ] 逐字稿已照實際口播修正
- [ ] 需要站主決定的欄位已列出

## 上架後

- 發布後 24 小時內看一次：章節列有沒有出現、字幕有沒有同步、說明欄連結可點。
- 留言裡指出的錯誤：確認後在置頂留言與說明欄更正，記進 `<WORKDIR>/ERRATA.md`；嚴重錯誤由站主決定是否重剪。
- 對應文章若要嵌入影片，另開一張票給 content-pipeline 處理，不在這個 skill 裡改文章。

## 全自動路線的上架包

全自動路線不用手寫 `upload.md`。站主核准成片之後，`node tools/video/cli.mjs package --slug <SLUG>` 會把要上傳的東西放進 `<VIDEO_WORKDIR>/<SLUG>/upload/`：

- `final.mp4`、`thumbnail.jpg`
- `captions/<語系>.srt`：zh-TW，加上站主勾了 CC 的語系
- `description.<語系>.txt`：第一行是標題，後面是說明，章節、文章連結、參考資料都已經組好；zh-TW，加上站主勾了標題說明的語系
- `dubs/<語系>.m4a`：站主勾了配音、工人做好的音軌
- `metadata.json`（含 `language_choice`：站主每個語言勾了什麼）、`UPLOAD.md`

`UPLOAD.md` 就是這份清單的自動版本，請站主照著做。沒勾任何語言（或按了「只出繁體中文」）的影片，上傳包只有 zh-TW。

- **API 上傳會被鎖成私人**：YouTube 規定，沒通過稽核的 API 專案用 `videos.insert` 上傳的影片會被鎖成私人，而且不能申訴。所以 mp4 一律由站主在 Studio 上傳，先設成「私人」。其他語系的標題、說明、字幕與縮圖，由網站用 API 補上（見下面「網站送到 YouTube 的東西」），只送勾了的語系。
- **非原創內容政策**：YouTube 會停止營利「用模板量產、沒有創作者觀點」的 AI 內容。全自動影片最容易踩到這一條，所以每支影片都要做到：
  - `brief.md` 的「站主觀點」由站主確認過；
  - 至少有一段實際示範或實算；
  - 版型的順序不要和其他支雷同，lint 會警告。
- **AI 揭露**：通用的 TTS 聲音唸投影片，依 YouTube 說明推論不需要揭露；如果複製的是別人的真人聲音，就一定要揭露。判斷交給站主。

## 網站送到 YouTube 的東西

站主只做兩件事：在 Studio 上傳 mp4（私人），到 `/admin/videos` 的「可以上架」卡片貼網址、選時間。其餘由網站透過 YouTube Data API 補齊（`apps/api/app/video_youtube/`，設計在 `docs/videos/HANDS-OFF.md` §YouTube API 第一步）。

**連結頻道（一次）**：影片審核 › 設定 › 共用 › 「YouTube 頻道」卡。先在 `/admin/ai-accounts` 的「Azure 語音（影片旁白）」卡填 YouTube OAuth 用戶端 ID 與密鑰（Google Cloud 的「網頁應用程式」用戶端，redirect URI 照卡片上寫的填，同意畫面發布成「正式版」，留在「測試中」的 refresh token 7 天就過期），再按「連結 YouTube 頻道」。同意畫面只要 `youtube.force-ssl` 一個權限；refresh token 加密存在 API 那一側，不會再顯示；「撤銷連結」會通知 Google 撤銷並刪掉。只有站主（`roles.manage`）能連結或撤銷，內容管理員只看得到狀態。

**什麼時候送**：貼上網址之後、工人送到一批語言之後（影片已經在 YouTube 上時）、或站主在影片頁的「送到 YouTube 的東西」卡按「重送到 YouTube」。每次都是佇列裡的一個工作，結果記在那張卡上，每一步一行：

1. **標題與說明**（`videos.update`）：先讀現值再整段送回；zh-TW 的標題、說明、標籤、分類與 `defaultLanguage`，勾了「標題與說明」而且上傳包有翻譯的語系放進 `localizations`，`privacyStatus` 一定送 `private`，`selfDeclaredMadeForKids: false`，`containsSyntheticMedia` 照上傳包 `metadata.json` 的揭露答案。
2. **上架時間**（`status.publishAt`）：只在語言已決定、勾了的部件都做好或跳過之後才送；之前這一步寫「語言還沒都做好，排程等做好那一輪再送」。影片不是私人、或時間已過，這一步失敗並寫原因，其餘照送。網站永遠不會自己把影片設成公開，公開由 YouTube 在那個時間做。
3. **字幕**（`captions.list` 再 `captions.insert`）：zh-TW 加勾了 CC 的語系，YouTube 已有的語言不再上傳，所以重送不會重複。
4. **縮圖**（`thumbnails.set`）：雜湊沒變就不再送。

送出前的檢查：影片已貼網址、頻道已連結、上傳包已核准而且 `metadata.json` 的雜湊等於核准那一份。不符就在第一步寫原因，不呼叫 YouTube。一支約 2,100 配額單位（每日 10,000）。配音仍只能站主在 Studio 上傳。

**待實測**（第一支用網站送的影片，把結果回寫這一段）：沒有稽核的專案，能不能對 Studio 上傳的影片呼叫 `captions.insert` 與設定 `publishAt`；中文字幕的語言碼 YouTube 存成 `zh-TW`／`zh-CN` 還是 `zh-Hant`／`zh-Hans`（上傳一條測試軌，再看 `captions.list` 讀回什麼；對不上就改 `apps/api/app/video_youtube/sync.py` 的 `CAPTION_LANGUAGE_CODES`）。

## 語言：每支影片由站主選

每支影片先只有繁體中文（旁白、CC、標題說明）。成片核准後，`/admin/videos` 那支影片的頁面出現「這支影片的語言」面板：en、ja、ko、zh-CN 四語，每語三個部件——**標題與說明**（YouTube 的 `localizations`）、**CC**（字幕檔）、**配音**（多語言音軌；勾配音會一起勾 CC，配音唸的就是字幕的翻譯）。三顆鈕：「照預設勾選」照設定分頁的語言預設，「只出繁體中文」記下不做其他語言，「儲存」。設計在 `docs/videos/LANGUAGES.md`，配音的做法與 2026-09-27 查到的官方規則在 `docs/videos/DUBS.md`。

**上架的順序**（`LANGUAGES.md` §上架流程）：成片核准 → 站主決定語言（沒決定前影片在「需要你」，寫「等你決定語言」）→ 工人只做勾了的（「語言製作中」）→ 全部做好、上傳包核准，影片才進「可以上架」→ 站主貼網址、選時間 →「已排定」→「已上架」。站主隨時可以先在 Studio 上傳成私人、貼網址、選時間，不用等語言；排程會在語言做好後才送出。上架後面板還在，多勾就再做一批；取消勾選只對還沒送上 YouTube 的部件有效，已經送上去的要自己在 Studio 刪。

**每語一張「語言」卡片**：工人做好一批就送一張，列每語三部件的狀態（製作中／已完成／跳過（原因）／已上傳）與下載連結（說明欄 `.txt`、字幕 `.srt`、音軌 `.m4a`）。標題說明與 CC 由網站用 API 送上（上一節），不用動手；**只有配音要站主在 Studio 上傳**，所以沒有配音的卡片伺服器直接核准，有配音的等站主上傳後按「已在 Studio 上傳配音」。

配音（多語言音軌）：

- **只能在 Studio 手動上傳**：Data API 沒有音軌的方法。每個語系一次：左選單「語言」→ 這支影片 →「新增語言」→ 選語言 →「配音」旁的「新增」→「選取檔案」→「發布」。上架前或上架後都可以加。
- **資格**：頻道要有「進階功能」（設定 → 頻道 → 功能使用資格），不需要營利資格。
- **自動配音會擋路**：YouTube 對繁中原片預設會自動配一條英文（不能編輯）；它生成之後要先在「語言」頁刪掉，自己的英文音軌才傳得上去。建議在設定 → 頻道 → 進階設定取消「允許自動配音」。
- **檔案**：官方只寫「支援的純音訊檔案格式、長度和影片大致相同」。工具出的 m4a 長度和影片一樣到取樣。第一支實測還沒做（見下面「待實測」）。
- **字幕跟配音走**：有配音的語系，`captions` 用配音的時間切字幕，選日文配音配日文字幕的觀眾讀到的就是聽到的；沒配音的語系照舊跟 zh-TW 的時間。
- **做不出來的語系**：翻譯縮短兩輪、重錄兩輪仍塞不下，或 `dub` 要站主處理（Azure 聲音、沒金鑰）的語系會被跳過，卡片、`UPLOAD.md` 與 `metadata.json` 的 `skipped_dub_locales` 會寫原因，不擋上架。
- **漫劇**：第一期只能勾標題說明與 CC，配音灰掉（多角色要重新混音，`DUBS.md` §已知限制）。

**待實測**（第一支有配音的影片上傳後，把結果回寫這一段，`DUBS.md` §站主要做的事列了清單）：Studio 收不收 `.m4a`（不收就 `dub --format mp3`）；影片還是私人時能不能加音軌、音軌的「發布」會不會動到影片的瀏覽權限；「語言」頁上原始語言是不是照影片語言（中文（台灣））標成原音。
