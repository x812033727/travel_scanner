# 上架包與上架檢查

`video_kit.py metadata` 產出 `upload.md` 草稿：標題、說明（摘要、章節、來源、文章連結）、逐字稿的位置。以下是補完與檢查的規則。代理交出 `upload.md`；登入 YouTube Studio 與按發布是站主。

## 標題

規則在 `tools/video/core/metadata.mjs`（`youtubeWarnings`），全部是警告，不擋流程；2026-10-08 站主依頻道診斷（`docs/videos/channel-review-20261007/DECISIONS.md`）定案。

- 給 3 個候選。100 字元是 YouTube 的上限；頻道自己的上限是 **36 個全形字等值**（CJK 一個算 1、ASCII 字母、數字、空格算 0.5；`titleWidth`），手機列表大約在 40 字就切掉，沒有實際量過所以取保守值。系列後綴也算在內。
- 產品名與數字放前 15 字內，這是觀眾搜尋的關鍵字；產品名與版本寫正確的官方寫法。
- 最多一個「？」：問一個問題，影片裡回答它。
- 不用「是誰說的、是誰測的、怎麼讀、怎麼看、先分清、先問」這類媒體識讀句型（參考頻道 150 支裡 0 支）；改成產品名加數字。
- 「、」列舉不超過兩項；三項以上的清單放說明欄。
- **系列名當後綴、不編號**：「Token 是什麼？AI 算的不是字數｜AI 名詞十分鐘」。「第 N 集」「EP N」「#N」會被警告（漫劇的集數是例外，lint 呼叫時帶 `numbered: true`）。
- 形式：觀眾的問題（「AI 模型這麼多，到底該怎麼挑？」）＋一個反直覺的鉤子（「排行榜第一名不一定最好用！」），或態度＋主題（「Claude Code 近期更新彙整，我好像又愛上它了」）。
- 不寫影片裡沒有兌現的承諾；不全大寫、不堆驚嘆號。

## 說明欄

順序固定，與 `tools/video/core/metadata.mjs` 的 `composeDescription` 一致（2026-10-08 改：連結不再放第一行，鉤子回到第一行；各語系同一順序，標籤文字用各語系的）：

1. 第一行：本文的第一句，鉤子（結論或反轉）。搜尋結果與「顯示更多」之前只看得到前兩三行。
2. 第二行：給誰看（「給…的人」）。
3. 第三行起：本文其餘（錄製日期與涵蓋的版本——更新彙整、教學必寫；影片中提到的指令、連結、工具；揭露：業配、聯盟連結、贊助一律寫明，並在 Studio 勾「含付費宣傳」）。
4. 🔗 對應的 Mokaair 文章，本文之後、**同一網址在整份說明欄只出現一次**（本文、🔗、📚 合起來算；「同一頁」是去掉 `utm_*`、`#` 與尾斜線之後相同的網址，其他 query 算不同頁，例如 `?n=5444` 與 `?n=5445`；`urlKey`）：`https://mokaair.com/<語系>/life/<slug>`（生活與 AI 類）或 `https://mokaair.com/<語系>/guides/<kind>/<slug>`（旅遊類）；語系一定要帶，例如 `zh-TW`。每個 mokaair.com 連結都帶 `?utm_source=youtube&utm_medium=video&utm_campaign=<影片 slug>`。
5. 📌 章節（見下）。
6. 📚 參考資料（`sources`，`## 來源` 的內容）。列的是上面還沒連過的頁：`sources` 裡等於文章本身的那筆（內容包的來源常以文章自己收尾）、本文句子裡已連的頁，以及同一頁的第二筆都不再列（`unlinkedSources`）；全部都連過就沒有這一段。
7. 📷 圖片來源（有圖庫照片才有）。
8. 標籤行（放最後，會顯示在標題上方）：前兩個是 `tags` 的前兩個題目詞，第三個是系列 hashtag，由 `category` 對映（`ai-terms` → `#AI名詞十分鐘`、`tutorial` → `#AI工具教學`、`ai-news` → `#AI新聞拆解`；表在 `metadata.mjs` 的 `SERIES_HASHTAGS`），沒有對映就只有兩個。

全自動路線只寫本文（`youtube.description`）：第一行是鉤子那一句，第二行是「給誰看」，之後才是其餘段落；工具把連結、章節、來源、hashtag 組進去，本文裡只是網址的那一行（例如以前放在第一行的文章連結）會被拿掉，句子裡的站內連結會補上 UTM。說明上限 5,000 位元組（中文一個字 3 位元組），不放 `<` `>`（YouTube 會拒絕）。

## 章節

YouTube 要自動產生章節列，說明欄的時間戳必須：第一個是 `00:00`、至少 3 個、每章至少 10 秒、依時間遞增。`metadata` 會依這些規則檢查 `chapters.txt`；沒給 `chapters.txt` 時用估計時間出草稿並在最上面標「估計時間，剪完要換」。**估計時間不能直接上架。**

章節名寫成觀眾會搜尋的問題或名詞，不寫「第一部分」。

## 字幕

- 用 `teleprompter.txt` 當逐字稿：YouTube Studio →「字幕」→ 新增語言（中文（台灣））→「自動同步」→ 貼上逐字稿，YouTube 會自己對時間。比自動產生的字幕準確得多，尤其是產品名與英文名詞。
- 實際唸的和稿子不一樣的地方（臨場改口），同步前先在逐字稿改掉。
- 要英文等其他語系字幕，從已同步的中文字幕檔翻譯，專有名詞沿用官方英文寫法。

## 標籤與其他欄位

- 標籤（tags）**最多 10 個**、總長 500 字元內：zh-TW 的詞與英文產品名優先，`video.json` 寫的順序就是取捨順序，`package` 截到前 10 個（`uploadTags`），超過 10 個 lint 警告。其他語系的標籤走翻譯流程留在 `i18n/<語系>.json`，不混進上傳包的標籤。影響不大（YouTube 說明中心 146402），別花時間。
- 播放清單：放進對應系列（例如 Claude Code 系列），系列順序與站上的系列文章一致。
- 結束畫面與資訊卡：結束畫面指向同系列下一支或最相關的一支。
- 置頂留言：一句重點＋文章連結，或一個具體的問題邀請留言。

## 需要站主決定的欄位（交給站主，代理不代填）

- 是否含付費宣傳。
- 「變造或合成內容」揭露：用 AI 產生了逼真的人聲、人像或看似真實的場景時要勾；只用 AI 寫稿、做字卡不需要。判斷不了就列給站主。
- 目標觀眾「是否為兒童專屬」：這類科技影片通常選「否」，但由站主選。
- 公開狀態與排程時間。

## 上架前檢查（全打勾才交）

- [ ] `facts.md` 沒有待查；會過期的事實在錄影前一週內確認過
- [ ] `video_kit.py check` 零 FAIL；開場 ≤ 30 秒
- [ ] 成片逐段看過：沒有 key、token、email、帳單、使用者名稱、無關分頁（規矩 4）
- [ ] 音樂與素材都有授權，出處寫在說明欄
- [ ] 章節用剪完的實際時間，`metadata --chapters` 沒有錯誤
- [ ] 說明欄連結都點過（文章連結帶語系、回 200）
- [ ] 縮圖在 320 寬下讀得到，字沒有被時間標籤蓋住
- [ ] 逐字稿已照實際口播修正
- [ ] 需要站主決定的欄位已列出

## 上架後

- 發布後 24 小時內看一次：章節列有沒有出現、字幕有沒有同步、說明欄連結可點。
- 留言裡指出的錯誤：確認後在置頂留言與說明欄更正，記進 `<WORKDIR>/ERRATA.md`；嚴重錯誤由站主決定是否重剪。
- 對應文章若要嵌入影片，另開一張票給 content-pipeline 處理，不在這個 skill 裡改文章。

## 全自動路線的上架包

全自動路線不用手寫 `upload.md`。站主核准成片之後，`node tools/video/cli.mjs package --slug <SLUG>` 會把要上傳的東西放進 `<VIDEO_WORKDIR>/<SLUG>/upload/`：

- `final.mp4`、`thumbnail.jpg`
- `captions/<語系>.srt`：zh-TW，加上站主勾了 CC 的語系
- `description.<語系>.txt`：第一行是標題，後面是說明（上面「說明欄」的順序：鉤子、給誰看、本文、文章連結、章節、參考資料、hashtag 都已經組好）；zh-TW，加上站主勾了標題說明的語系
- `dubs/<語系>.m4a`：站主勾了配音、工人做好的音軌
- `thumbnails/<語系>.jpg`：各語言自己的縮圖（見下面「多語言縮圖」），只有那個語言的 `i18n` 有縮圖文字時才有
- `metadata.json`（含 `language_choice`：站主每個語言勾了什麼；`thumbnails` 與 `skipped_thumbnail_locales`：哪些語言有自己的縮圖、其他語言為什麼沒有）、`UPLOAD.md`

`UPLOAD.md` 就是這份清單的自動版本，請站主照著做。沒勾任何語言（或按了「只出繁體中文」）的影片，上傳包只有 zh-TW。

- **API 上傳會被鎖成私人**：YouTube 規定，沒通過稽核的 API 專案用 `videos.insert` 上傳的影片會被鎖成私人，而且不能申訴。所以稽核通過之前，mp4 由站主在 Studio 上傳（私人、其他欄位不填），其餘由網站補（下一節）。

## 網站送到 YouTube（連結頻道之後）

程式在 `apps/api/app/video_youtube`（設計：`docs/videos/HANDS-OFF.md` §YouTube API）。**權杖只在 API 容器**：代理、工人、對話都碰不到，也不需要碰。

- **連結（一次）**：`/admin/videos` → 設定分頁 →「YouTube 頻道」卡片列出 Google Cloud 的五步（啟用 YouTube Data API v3、同意畫面「外部」＋名稱 Mokaair Studio Sync＋**正式版**、網頁應用程式用戶端、重新導向 URI 用卡片上顯示的那個、範圍只有 `youtube.force-ssl`）。站主自己把用戶端 ID 與密鑰貼進卡片、按「連結 YouTube 頻道」、在 Google 選擁有頻道的帳號按允許。密鑰與 refresh token 加密存在 `video_youtube_connections`，不回傳瀏覽器；卡片每 25 天自動用 `channels.list` 確認一次授權（Developer Policies III.E.4）。
- **送出**：「可以上架」卡片（或影片頁）在連結後換成「送到 YouTube」表單：
  - 影片檔：「我已經在 Studio 上傳（私人），貼網址」，或「由網站上傳 mp4」（續傳上傳，8 MiB 一段；稽核沒過時要勾「我知道會被鎖成私人」，只拿來測試與截圖）；
  - 中文標題、說明欄預填上傳包的，站主可以改；瀏覽權限：在選定時間公開（之前私人）／不公開／私人。網站**從不直接設成公開**，也拒絕動已經公開的影片。
- **網站依序做**（每一步記在影片的「YouTube 同步」面板）：`upload`（只有網站上傳時）→ `details`（先 `videos.list` 讀現值、確認在連結的頻道且不是公開，再 `videos.update` 整段送：上傳包裡的語系（站主為這支勾的，`docs/videos/LANGUAGES.md`）、標籤、分類、`selfDeclaredMadeForKids`、`containsSyntheticMedia`、`publishAt`）→ `captions`（上傳包裡的字幕，`captions.list` 後只補沒有的語系；自動字幕不算）→ `thumbnail`。一支約 2,100 單位（`captions.insert` 每次 400）。
- **失敗與重試**：面板顯示哪一步、YouTube 說了什麼；按重試只做沒完成的步驟，mp4 從 YouTube 收到的位元組接著傳，不會傳第二份。常見原因：配額用完（太平洋時間午夜重置）、縮圖 403（頻道要先完成電話驗證）、影片不是私人或不在連結的頻道、授權被撤銷（卡片會顯示「授權失效」，重新連結）。API 重啟時正在跑的那次會顯示「中斷了」，一樣按重試。
- **還沒實測的兩件事**（第一支用私人影片實測後回寫這裡）：未稽核的專案對 Studio 上傳的影片呼叫 `captions.insert` 與設 `publishAt` 是否都成功；中文字幕語言碼用 `zh-TW`／`zh-CN` 送出後，`captions.list` 讀回是不是同一個碼（程式把 `zh-Hant`／`zh-Hans` 當成同一個語系比對）。字幕軌名稱送空字串，播放器選單只顯示語言名。
- **非原創內容政策**：YouTube 會停止營利「用模板量產、沒有創作者觀點」的 AI 內容。全自動影片最容易踩到這一條，所以每支影片都要做到：
  - `brief.md` 的「站主觀點」由站主確認過；
  - 至少有一段實際示範或實算；
  - 版型的順序不要和其他支雷同，lint 會警告。
- **AI 揭露**：通用的 TTS 聲音唸投影片，依 YouTube 說明推論不需要揭露；如果複製的是別人的真人聲音，就一定要揭露。判斷交給站主。

## Shorts 的上架

Shorts 不用 `upload.md`，也不走 `tools/video/cli.mjs package`：`node tools/video/shorts/cli.mjs package --dir <成品>` 寫 `upload/metadata.json` 與說明，`push` 送上傳包審核（`files`、`descriptions`、`captions`、`disclosure` 四項全過就核准），影片進片庫，伺服器把它排進月曆的時段（做法在 `shorts.md`，設計在 `docs/videos/SHORTS.md` §上架）。上架的時間是時段的時間，不是站主每支選。

**有沒有自動上架授權**：站主在 Shorts 設定按「自動上架授權」，同意的是一段列出範圍的條文（頻道、內容線、一天最多幾支、公開時間、網站會設定的欄位、只設私人加排程）。之後工人每 5 分鐘敲一次門（`shorts/cli.mjs tick`），網站在時段前 `lock_hours`（預設 24）小時鎖定那一格，影片有 YouTube id 就自己送 `videos.update`（標題、說明、標籤、分類、兒童設定、合成內容揭露、私人加 `publishAt` 等於時段的時間）與 `captions.insert`。範圍外的那一支不送、原因寫在那一格上。沒有授權、授權過期（90 天）或按了暫停時，Shorts 照樣做、照樣排時段，每一支在「可以上架」等站主自己按「送到 YouTube」，跟長片一樣。站主隨時可以暫停，或按「撤回已排程的」把還沒公開的影片取消排程（保持私人，同時暫停）。

**稽核通過前：站主只拖檔案**（現在唯一的做法）：

1. Shorts 分頁的「等你上傳」列出接下來 `upload_ahead_days`（預設 10）天要上的 Shorts；按「下載這一批」拿到一個 zip，檔名是 `mokaair-short-<slug>.mp4`。
2. 在 YouTube Studio 把這些 mp4 一次拖進上傳視窗（一次最多 15 個），瀏覽權限選私人，其他欄位都不填、檔名帶出來的標題也不用改。
3. 回到分頁按「我上傳好了」：網站讀頻道最近上傳的影片，用上傳檔名（讀不到時用 Studio 從檔名帶出的標題）對回每一支，再核對是私人、長度跟成片差不到 1 秒。每一支回一個結果：對到、重複上傳、找不到、不是私人、長度不符。
4. 對不到的列在「需要你」，改用「送到 YouTube」表單貼網址。時段到了還沒有影片的那一支回到片庫，那一格記成錯過，不會補發在別的時間。

**稽核通過後**：網站在鎖定時自己用 `videos.insert` 上傳（票 `2026-09-28-video-shorts-auto-upload`）還沒做；在那之前，即使稽核通過，也照上面拖檔案。

**跟長片送出去的差別**：

| 欄位 | 長片 | Shorts |
| --- | --- | --- |
| 標題與說明 | zh-TW 加站主每支勾的語系 | 只有 zh-TW；Shorts 設定的「另外要出的語言」勾了才加其他語系的標題、說明與 CC |
| 章節、縮圖、配音 | 有 | 都沒有：第一格就是封面，不送 `thumbnails.set` |
| 字幕 | CC，不燒錄 | 字卡本來就在畫面上；另外送一條 zh-TW CC |
| 完整影片的連結 | — | 精華與漫劇放在說明欄第一行（Shorts 的「相關影片」只能在 Studio 設，要不要補由站主決定） |
| 分類 | 28 | 實測與精華 28，漫劇 24 |
| 揭露 | 站主判斷 | `package` 依內容線寫進 `metadata.json`：漫劇與有擬真生成圖的勾，字卡加合成旁白的不勾 |
| 標題測試 | Studio 可做 A/B | Shorts 不能做；兩個標題只是備案 |

**待實測**（`2026-09-28-video-shorts-pilot-launch` 第一批上架時在真的頻道上測，結果寫回 `docs/videos/SHORTS.md` 與這一段；程式兩種結果都處理）：

1. 拖進 Studio 但沒按完精靈的草稿，API 讀不讀得到。
2. Studio 上傳的 Shorts 讀得到 `fileDetails.fileName` 嗎（讀不到時改用標題對）。
3. 撤回時 `videos.update` 只送 `status`、不帶 `publishAt`，排程會不會清掉。
4. 1080×1920、25–55 秒的成片有沒有被 YouTube 歸成 Shorts（沒有開關，只能看結果）。
5. 沒通過稽核的專案，對 Studio 上傳的影片送 `captions.insert` 與設 `publishAt` 會不會成功。

## 語言：每支影片由站主選

每支影片先只有繁體中文（旁白、CC、標題說明）。成片核准後，`/admin/videos` 那支影片的頁面出現「這支影片的語言」面板：en、ja、ko、zh-CN 四語，每語三個部件——**標題與說明**（YouTube 的 `localizations`）、**CC**（字幕檔）、**配音**（多語言音軌；勾配音會一起勾 CC，配音唸的就是字幕的翻譯）。三顆鈕：「照預設勾選」照設定分頁的語言預設，「只出繁體中文」記下不做其他語言，「儲存」。設計在 `docs/videos/LANGUAGES.md`，配音的做法與 2026-09-27 查到的官方規則在 `docs/videos/DUBS.md`。

**上架的順序**（`LANGUAGES.md` §上架流程）：成片核准 → 站主決定語言（沒決定前影片在「需要你」，寫「等你決定語言」）→ 工人只做勾了的（「語言製作中」）→ 全部做好、上傳包核准，影片才進「可以上架」→ 站主貼網址、選時間 →「已排定」→「已上架」。站主隨時可以先在 Studio 上傳成私人、貼網址、選時間，不用等語言；排程會在語言做好後才送出。上架後面板還在，多勾就再做一批；取消勾選只對還沒送上 YouTube 的部件有效，已經送上去的要自己在 Studio 刪。

**每語一張「語言」卡片**：工人做好一批就送一張，列每語三部件的狀態（製作中／已完成／跳過（原因）／已上傳）與下載連結（說明欄 `.txt`、字幕 `.srt`、音軌 `.m4a`）。標題說明與 CC 由網站在排上架時用 API 送上，不用動手；**只有配音要站主在 Studio 上傳**，所以沒有配音的卡片伺服器直接核准，有配音的等站主上傳後按「已在 Studio 上傳配音」。

配音（多語言音軌）：

- **只能在 Studio 手動上傳**：Data API 沒有音軌的方法。每個語系一次：左選單「語言」→ 這支影片 →「新增語言」→ 選語言 →「配音」旁的「新增」→「選取檔案」→「發布」。上架前或上架後都可以加。
- **資格**：頻道要有「進階功能」（設定 → 頻道 → 功能使用資格），不需要營利資格。
- **自動配音會擋路**：YouTube 對繁中原片預設會自動配一條英文（不能編輯）；它生成之後要先在「語言」頁刪掉，自己的英文音軌才傳得上去。建議在設定 → 頻道 → 進階設定取消「允許自動配音」。
- **檔案**：官方只寫「支援的純音訊檔案格式、長度和影片大致相同」。工具出的 m4a 長度和影片一樣到取樣。第一支實測還沒做（見下面「待實測」）。
- **字幕跟配音走**：有配音的語系，`captions` 用配音的時間切字幕，選日文配音配日文字幕的觀眾讀到的就是聽到的；沒配音的語系照舊跟 zh-TW 的時間。
- **做不出來的語系**：翻譯縮短兩輪、重錄兩輪仍塞不下，或 `dub` 要站主處理（Azure 聲音、沒金鑰）的語系會被跳過，卡片、`UPLOAD.md` 與 `metadata.json` 的 `skipped_dub_locales` 會寫原因，不擋上架。
- **漫劇**：第一期只能勾標題說明與 CC，配音灰掉（多角色要重新混音，`DUBS.md` §已知限制）。

**待實測**（第一支有配音的影片上傳後，把結果回寫這一段，`DUBS.md` §站主要做的事列了清單）：Studio 收不收 `.m4a`（不收就 `dub --format mp3`）；影片還是私人時能不能加音軌、音軌的「發布」會不會動到影片的瀏覽權限；「語言」頁上原始語言是不是照影片語言（中文（台灣））標成原音。

多語言縮圖（每個語言一張，字換成該語言）：

- **官方怎麼寫**（YouTube 說明「Add Multi-language features to your videos」，support.google.com/youtube/answer/13338784，2026-10-01 重讀）：「Manage localized thumbnails」一節說長片可以上傳不同語言的縮圖，觀眾看到的是符合自己語言設定的縮圖。步驟：Studio 左選單「Content」→ 點影片 →「Upload thumbnail」先傳影片自己的縮圖 → 左選單「Languages」→ 點要加縮圖的那個語言名稱 →「Thumbnail」旁的「Add」選圖 →「Update」。整頁的多語言功能寫的前提是頻道要能使用「進階功能」。
- **官方沒寫的**：頁面沒有明說「要先有那個語言的配音或字幕」，也沒寫縮圖的尺寸、大小或數量限制，沒提 API。2026-09-28 開票時記的「要先有音軌」這次在頁面上找不到原文；能確定的只有步驟是「點語言名稱」，所以那個語言要先列在影片的「語言」頁——上傳包的字幕、標題說明或配音送上去後就會列出。尺寸照一般縮圖（1280×720、2 MB 以內），`render` 與 `qa` 就是照這個檢查。
- **只能在 Studio 手動上傳**：頁面只寫了 Studio 的做法，網站也不送它。`UPLOAD.md` 有一節「各語言的縮圖」列檔案與步驟。
- **怎麼來的**：`i18n-sheet` 的 metadata 部件多一個 `thumbnail`（`tag`、`headline`、`sub`，只列 zh-TW 縮圖有的那幾個字），`i18n-merge` 寫進 `i18n/<語系>.json` 的 `thumbnail`，雜湊在 `source_hashes.thumbnail`（三個字當一筆算，zh-TW 縮圖任何一個字改了就整組過期）。`render` 對每個縮圖文字是最新的語系，用同一張背景與版型畫 `thumbnails/<語系>.jpg`；`package` 只收畫的時候用的字和現在 `i18n` 一樣的那幾張。
- **不擋上架**：縮圖文字是選配。沒翻、過期、字型沒有那個字（ko、zh-CN、ja 的縮圖各用自己的 Noto Sans KR／SC／JP 排在第一，en 用投影片的 Noto Sans TC）、版面塞不下的語系只記成 note（`render` 的輸出、`metadata.json` 的 `skipped_thumbnail_locales`、`UPLOAD.md`），那個語言就用 `thumbnail.jpg`。`i18n-merge` 對縮圖文字的問題也只印 note，不讓合併失敗；`qa` 的縮圖項目對每張語言縮圖再跑一次同樣的檢查，有問題只出 warning。
- **變體**：A/B 測試的 `thumbnail-b.jpg`／`thumbnail-c.jpg` 只有 zh-TW，語言縮圖照 A 版做。
