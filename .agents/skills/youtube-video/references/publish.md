# 上架包與上架檢查

`video_kit.py metadata` 產出 `upload.md` 草稿：標題、說明（摘要、章節、來源、文章連結）、逐字稿的位置。以下是補完與檢查的規則。代理交出 `upload.md`；登入 YouTube Studio 與按發布是站主。

## 標題

- 給 3 個候選。100 字元是上限，但手機列表大約只顯示前 40 個全形字，重點放前面。
- 形式：觀眾的問題（「AI 模型這麼多，到底該怎麼挑？」）＋一個反直覺的鉤子（「排行榜第一名不一定最好用！」），或態度＋主題（「Claude Code 近期更新彙整，我好像又愛上它了」）。
- 產品名與版本寫正確的官方寫法，這是觀眾搜尋的關鍵字。
- 不寫影片裡沒有兌現的承諾；不全大寫、不堆驚嘆號。

## 說明欄

順序固定：

1. 前兩行：這支影片回答什麼、給誰看（搜尋結果與「顯示更多」之前只看得到這裡）。
2. 錄製日期與涵蓋的版本（更新彙整、教學必寫）。
3. 章節（見下）。
4. 影片中提到的指令、連結、工具。
5. 對應的 Mokaair 文章：`https://mokaair.com/<語系>/life/<slug>`（生活與 AI 類）或 `https://mokaair.com/<語系>/guides/<kind>/<slug>`（旅遊類）；語系一定要帶，例如 `zh-TW`。要追蹤來自影片的流量就加 `?utm_source=youtube&utm_medium=video&utm_campaign=<影片代號>`。
6. 來源（`## 來源` 的內容）。
7. 揭露：業配、聯盟連結、贊助一律寫明，並在 Studio 勾「含付費宣傳」。
8. 標籤行（最多 3 個 `#hashtag`，放最後，會顯示在標題上方）。

說明上限 5,000 字元，不放 `<` `>`（YouTube 會拒絕）。

## 章節

YouTube 要自動產生章節列，說明欄的時間戳必須：第一個是 `00:00`、至少 3 個、每章至少 10 秒、依時間遞增。`metadata` 會依這些規則檢查 `chapters.txt`；沒給 `chapters.txt` 時用估計時間出草稿並在最上面標「估計時間，剪完要換」。**估計時間不能直接上架。**

章節名寫成觀眾會搜尋的問題或名詞，不寫「第一部分」。

## 字幕

- 用 `teleprompter.txt` 當逐字稿：YouTube Studio →「字幕」→ 新增語言（中文（台灣））→「自動同步」→ 貼上逐字稿，YouTube 會自己對時間。比自動產生的字幕準確得多，尤其是產品名與英文名詞。
- 實際唸的和稿子不一樣的地方（臨場改口），同步前先在逐字稿改掉。
- 要英文等其他語系字幕，從已同步的中文字幕檔翻譯，專有名詞沿用官方英文寫法。

## 標籤與其他欄位

- 標籤（tags）總長 500 字元內，主要放常見錯字與別名（「Claude code」「克勞德」）；影響不大，別花時間。
- 播放清單：放進對應系列（例如 Claude Code 系列），系列順序與站上的系列文章一致。
- 結束畫面與資訊卡：結束畫面指向同系列下一支或最相關的一支。
- 置頂留言：一句重點＋文章連結，或一個具體的問題邀請留言。

## 需要站主決定的欄位（交給站主，代理不代填）

- 是否含付費宣傳。
- 「變造或合成內容」揭露：用 AI 產生了逼真的人聲、人像或看似真實的場景時要勾；只用 AI 寫稿、做字卡不需要。判斷不了就列給站主。
- 目標觀眾「是否為兒童專屬」：這類科技影片通常選「否」，但由站主選。
- 公開狀態與排程時間。

## 上架前檢查（全打勾才交）

- [ ] `facts.md` 沒有待查；會過期的事實在錄影前一週內確認過
- [ ] `video_kit.py check` 零 FAIL；開場 ≤ 30 秒
- [ ] 成片逐段看過：沒有 key、token、email、帳單、使用者名稱、無關分頁（規矩 4）
- [ ] 音樂與素材都有授權，出處寫在說明欄
- [ ] 章節用剪完的實際時間，`metadata --chapters` 沒有錯誤
- [ ] 說明欄連結都點過（文章連結帶語系、回 200）
- [ ] 縮圖在 320 寬下讀得到，字沒有被時間標籤蓋住
- [ ] 逐字稿已照實際口播修正
- [ ] 需要站主決定的欄位已列出

## 上架後

- 發布後 24 小時內看一次：章節列有沒有出現、字幕有沒有同步、說明欄連結可點。
- 留言裡指出的錯誤：確認後在置頂留言與說明欄更正，記進 `<WORKDIR>/ERRATA.md`；嚴重錯誤由站主決定是否重剪。
- 對應文章若要嵌入影片，另開一張票給 content-pipeline 處理，不在這個 skill 裡改文章。

## 全自動路線的上架包

全自動路線不用手寫 `upload.md`。站主核准成片之後，`node tools/video/cli.mjs package --slug <SLUG>` 會把要上傳的東西放進 `<VIDEO_WORKDIR>/<SLUG>/upload/`：

- `final.mp4`、`thumbnail.jpg`
- `captions/<語系>.srt`
- `description.<語系>.txt`：第一行是標題，後面是說明，章節、文章連結、參考資料都已經組好
- `metadata.json`、`UPLOAD.md`

`UPLOAD.md` 就是這份清單的自動版本，請站主照著做。

- **API 上傳會被鎖成私人**：YouTube 規定，沒通過稽核的 API 專案用 `videos.insert` 上傳的影片會被鎖成私人，而且不能申訴。所以稽核通過之前，mp4 由站主在 Studio 上傳（私人、其他欄位不填），其餘由網站補（下一節）。

## 網站送到 YouTube（連結頻道之後）

程式在 `apps/api/app/video_youtube`（設計：`docs/videos/HANDS-OFF.md` §YouTube API）。**權杖只在 API 容器**：代理、工人、對話都碰不到，也不需要碰。

- **連結（一次）**：`/admin/videos` → 設定分頁 →「YouTube 頻道」卡片列出 Google Cloud 的五步（啟用 YouTube Data API v3、同意畫面「外部」＋名稱 Mokaair Studio Sync＋**正式版**、網頁應用程式用戶端、重新導向 URI 用卡片上顯示的那個、範圍只有 `youtube.force-ssl`）。站主自己把用戶端 ID 與密鑰貼進卡片、按「連結 YouTube 頻道」、在 Google 選擁有頻道的帳號按允許。密鑰與 refresh token 加密存在 `video_youtube_connections`，不回傳瀏覽器；卡片每 25 天自動用 `channels.list` 確認一次授權（Developer Policies III.E.4）。
- **送出**：「可以上架」卡片（或影片頁）在連結後換成「送到 YouTube」表單：
  - 影片檔：「我已經在 Studio 上傳（私人），貼網址」，或「由網站上傳 mp4」（續傳上傳，8 MiB 一段；稽核沒過時要勾「我知道會被鎖成私人」，只拿來測試與截圖）；
  - 中文標題、說明欄預填上傳包的，站主可以改；瀏覽權限：在選定時間公開（之前私人）／不公開／私人。網站**從不直接設成公開**，也拒絕動已經公開的影片。
- **網站依序做**（每一步記在影片的「YouTube 同步」面板）：`upload`（只有網站上傳時）→ `details`（先 `videos.list` 讀現值、確認在連結的頻道且不是公開，再 `videos.update` 整段送：五語系、標籤、分類、`selfDeclaredMadeForKids`、`containsSyntheticMedia`、`publishAt`）→ `captions`（`captions.list` 後只補沒有的語系；自動字幕不算）→ `thumbnail`。一支約 2,100 單位（`captions.insert` 每次 400）。
- **失敗與重試**：面板顯示哪一步、YouTube 說了什麼；按重試只做沒完成的步驟，mp4 從 YouTube 收到的位元組接著傳，不會傳第二份。常見原因：配額用完（太平洋時間午夜重置）、縮圖 403（頻道要先完成電話驗證）、影片不是私人或不在連結的頻道、授權被撤銷（卡片會顯示「授權失效」，重新連結）。API 重啟時正在跑的那次會顯示「中斷了」，一樣按重試。
- **還沒實測的兩件事**（第一支用私人影片實測後回寫這裡）：未稽核的專案對 Studio 上傳的影片呼叫 `captions.insert` 與設 `publishAt` 是否都成功；中文字幕語言碼用 `zh-TW`／`zh-CN` 送出後，`captions.list` 讀回是不是同一個碼（程式把 `zh-Hant`／`zh-Hans` 當成同一個語系比對）。字幕軌名稱送空字串，播放器選單只顯示語言名。
- **非原創內容政策**：YouTube 會停止營利「用模板量產、沒有創作者觀點」的 AI 內容。全自動影片最容易踩到這一條，所以每支影片都要做到：
  - `brief.md` 的「站主觀點」由站主確認過；
  - 至少有一段實際示範或實算；
  - 版型的順序不要和其他支雷同，lint 會警告。
- **AI 揭露**：通用的 TTS 聲音唸投影片，依 YouTube 說明推論不需要揭露；如果複製的是別人的真人聲音，就一定要揭露。判斷交給站主。

## 多語言音軌（配音）

每支影片先只有繁體中文旁白。站主在 `/admin/videos` 那支影片的頁面勾了語言（en、ja、ko、zh-CN），工人才用同一個 Gemini 聲音唸字幕的翻譯，做成 YouTube 的多語言音軌（設計與 2026-09-27 查到的官方規則在 `docs/videos/DUBS.md`）。上傳包會多出 `dubs/<語系>.m4a`，`UPLOAD.md` 多一節「配音音軌」，成片審看頁多一組播放器。

- **只能在 Studio 手動上傳**：Data API 沒有音軌的方法。每個語系一次：左選單「語言」→ 這支影片 →「新增語言」→ 選語言 →「配音」旁的「新增」→「選取檔案」→「發布」。上架前或上架後都可以加。
- **資格**：頻道要有「進階功能」（設定 → 頻道 → 功能使用資格），不需要營利資格。
- **自動配音會擋路**：YouTube 對繁中原片預設會自動配一條英文（不能編輯）；它生成之後要先在「語言」頁刪掉，自己的英文音軌才傳得上去。建議在設定 → 頻道 → 進階設定取消「允許自動配音」。
- **檔案**：官方只寫「支援的純音訊檔案格式、長度和影片大致相同」。工具出的 m4a 長度和影片一樣到取樣。第一支實測 Studio 收不收 m4a，不收就 `dub --format mp3`；結果回寫這裡。
- **字幕跟配音走**：有配音的語系，`captions` 用配音的時間切字幕，選日文配音配日文字幕的觀眾讀到的就是聽到的；沒配音的語系照舊跟 zh-TW 的時間。
- **做不出來的語系**：翻譯縮短兩輪、重錄兩輪仍塞不下的語系會被跳過，`UPLOAD.md` 與後台卡片會寫原因，不用等。
- 上傳後回到影片頁的「配音音軌」卡片按核准，表示已上傳。
