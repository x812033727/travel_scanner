# 影片格式

三種格式涵蓋這類中文科技頻道大部分的影片，第四種是 AI 漫劇。先選一種，照它的骨架排章節，再寫稿。時間是 8–15 分鐘影片的建議比例；短片（60 秒內的 Shorts）另見最後一節。

## A. 觀點解說（explainer）

例：「AI 模型這麼多，到底該怎麼挑？排行榜第一名不一定最好用！」

觀眾帶著一個困惑進來，出去時手上有一個**判斷方法**，不是一份答案清單。

| 章節 | 比例 | 做什麼 |
| --- | --- | --- |
| 開場 | ≤ 30 秒 | 說出觀眾的困惑（「新模型每週都出，到底要用哪個？」），推翻一個常見想法（「排行榜第一名不一定最好用」），承諾這支會給什麼（「三個問題幫你決定」） |
| 為什麼會困惑 | 10–15% | 背景：市場現況、名詞一次講清楚。只講理解後面需要的 |
| 常見的誤解 | 15–20% | 大家怎麼判斷、哪裡會錯；用具體例子，不用抽象形容詞 |
| 判斷方法 | 40–50% | 框架本身，一個條件一章；每個條件配一個「如果你是這種人」的例子 |
| 我的做法 | 10–15% | 主講者自己怎麼用，明說這是個人選擇 |
| 結論 | ≤ 60 秒 | 回到開場的問題，一句話答案；下一支影片或對應文章 |

要點：框架最好是 3 個條件（記得住、字卡放得下）；每個條件都要能被觀眾套到自己身上；比較表放在「判斷方法」最後當總整理字卡。

## B. 更新彙整（roundup）

例：「Claude Code 近期更新彙整，我好像又愛上 Claude Code 了」

觀眾想知道**最近變了什麼、哪些值得馬上用**。主講者的態度（喜歡、失望、改變看法）是這種影片的主線。

| 章節 | 比例 | 做什麼 |
| --- | --- | --- |
| 開場 | ≤ 30 秒 | 態度一句話（「我好像又愛上它了」）＋這次涵蓋的時間範圍與版本 |
| 每一項更新 | 各 1–3 分鐘 | 固定四拍：**是什麼 → 示範 → 什麼時候用 → 我的評價**。一項一章 |
| 小更新快速帶過 | 5–10% | 不值得單獨示範的，一張字卡列完 |
| 總結 | ≤ 90 秒 | 最推薦的一到三項、誰應該升級、還缺什麼 |

要點：項目依「對觀眾的影響」排序，不是依發布日期；每項的版本號與日期都進 `facts.md`；示範用準備好的示範專案，不現場即興（見 visuals.md）。稿子第一行與說明欄都寫錄製日期，因為這種影片三個月後就部分過時。

## C. 操作教學（tutorial）

觀眾要**跟著做完一件事**。成功標準是觀眾照做能得到同樣的結果。

| 章節 | 比例 | 做什麼 |
| --- | --- | --- |
| 開場 | ≤ 30 秒 | 先給看成品，再說要準備什麼（帳號、方案、作業系統） |
| 準備 | 10% | 安裝、設定；把需要的指令與連結放在說明欄 |
| 步驟 | 70% | 一個步驟一章，每章開頭說「這一步做完你會看到什麼」 |
| 常見錯誤 | 10% | 你錄影時真的遇到的錯誤與解法 |
| 結尾 | ≤ 60 秒 | 下一步可以學什麼、對應的系列文章 |

要點：每個指令都要出現在畫面上**夠久**（至少讀完的時間）並放進說明欄或對應文章；版本與作業系統在開場就說；不要剪掉等待時間到讓觀眾以為瞬間完成，改成字卡「（等待約 2 分鐘）」。

## D. AI 漫劇（drama）

例：《山海经之万兽图鉴》那類 3D 寫實國風的 AI 動畫劇。觀眾要的是**一個講完的故事**：有角色、有轉折、有結局，2–4 分鐘一集，可以連載。做法在 `.agents/skills/youtube-video/references/drama.md`。

| 章節（幕） | 比例 | 做什麼 |
| --- | --- | --- |
| 開場 | ≤ 20 秒 | 一個遠景建立世界，第一句就是故事（「很久以前，發鳩山上住著炎帝最小的女兒」），沒有問候 |
| 第一幕：想要什麼 | 25–30% | 主角與她要的東西；每鏡 3–8 秒，遠景→中景→特寫 |
| 第二幕：出了什麼事 | 35–40% | 阻礙與轉折；情緒最強的一句給角色說，其餘給旁白 |
| 第三幕：結果 | 20–25% | 結局與它的意義；站主觀點藏在旁白的最後兩句 |
| 結尾卡 | ≤ 15 秒 | 下一集、對應文章或一個問題 |

要點：角色 2–4 個、每鏡最多 3 個；每鏡一張關鍵影格，長旁白拆成更多鏡頭而不是拉長鏡頭；名詞從頭到尾同一個寫法；題材是公有領域的神話、民間傳說、原創玄幻，或站上文章的改編；上架時一律勾「變造或合成內容」。

## 從 Mokaair 文章改編

站上的系列教學與 AI 新聞本來就查核過，是最省力的題材來源，但文章不能直接唸：

- 文章的結構是「查得到」，影片是「聽得懂」。先用 `from-article` 起骨架，再依上面的格式重排章節，通常會刪掉一半的段落。
- 表格改成字卡，一張字卡最多三列；超過就拆或只講重點、其餘留給文章。
- 文章裡的查核日期不等於錄製日期：錄影前把 `facts.md` 裡會過期的事實（價格、方案、版本）再確認一次。
- 說明欄連回文章（publish.md 有網址格式），文章也可以之後嵌入影片。

## Shorts（直式短片）

1080×1920、60 秒內。只講一件事：一個技巧、一個誤解、一個更新。開頭 2 秒就要出現重點字卡；不需要章節；結尾導到長片或文章。可以從長片的某一章剪出來，稿子另存 `short-<n>.md`。
