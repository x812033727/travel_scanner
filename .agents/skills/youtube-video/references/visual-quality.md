# 漫劇視覺與導演品質：從能播放到值得看

使用者覺得畫面粗糙、像樣板、表演太平，或要求提高成片質感時讀本篇。先找實際素材中的問題，再決定如何改；只有缺檔、編碼或 API 錯誤時，不必啟動整套美術重做。

「從 60 分提升到 90 分」是使用者對成片質感的主觀目標，不是自動評分公式、保證值或把 judge 設成 9 分。把目標改寫成可觀察的差異，例如「關掉 CC 仍看得出人物受困於封閉出口前」「第一眼落在人物的選擇，而非滿桌文件」。例子必須符合該鏡來源，不把前世已簽署改成當下正在簽字。

本篇補充品質判斷；來源、授權、預算、核准與交付仍沿用：

- [`.agents/skills/youtube-video/references/animation-production.md`](animation-production.md)：來源、命名造型、代表動態小樣、固定配音、CC 與模型契約。
- [`.agents/skills/youtube-video/references/drama.md`](drama.md)：正常 look／storyboard／clip／final 流程、收據與 retake 守門。

- [`.agents/skills/youtube-video/references/drama-craft.md`](drama-craft.md)：劇本與分鏡一開始照什麼規格寫（開場、鏡位與剪點、鏡頭與台詞長度），以及量分鏡的檢查腳本。診斷時先跑那支腳本：開場鏡頭數、全景、只有眼神表情的鏡頭若沒過，先改分鏡再重拍；同一個分鏡重拍，多半只會得到一樣的結構。

按需要往下讀：診斷與美術定調看前半；準備動態試作時讀「代表小樣」；審查有分歧時讀「證據與分歧」。不要為一般單鏡修正重開全部流程。

## 先把四種品質與接受狀態分開

| 層面 | 要看的實際證據 | 不能代替它的東西 |
| --- | --- | --- |
| 技術完整 | 檔案能解碼，手臉與道具穩定，動作沒有穿透、複製、接觸錯誤或明顯變形 | 能播放、解析度足夠，不代表畫面有吸引力 |
| 美術 | 構圖、光影層次、臉部設計與材質一致，觀眾能找到主體 | 漂亮概念圖、加細節或加銳化，不代表連續影片做得到 |
| 敘事與表演 | 視線有對象，動作有意圖、接觸與收勢，觀眾看懂行為的原因和後果 | 人物微動、自然眨眼或「有動畫」，不代表戲成立 |
| 剪輯與聲音 | 動作接得上，節奏支持情緒，原配音清楚，必要聲效有接觸感，CC 可關且同步 | 配樂變大、快切、字幕解說，不會自動補足演出 |

另記使用者對這一版的接受狀態。技術通過、美術候選、judge 通過、使用者接受與最終交付是不同欄位；不可合成一個含糊的「完成」。

使用者已說這版粗糙、不接受，就將本次品質版本記為 `rejected`，保留素材與原因供比較，開始修正，不再問要不要保留舊版。這不等於竄改歷史核准收據或刪除舊素材。

## 1. 實看素材，先抓最影響觀看的問題

先看有問題的實際片段、其首格與角色參考，再看使用者指定的質感參考。若只有口頭描述，先利用現有素材做可完成的診斷；缺少的參考只標未知，不憑記憶聲稱看過。

先以正常播放速度看含前後文的一段，再對可疑時間碼逐幀確認。聯絡表用於定位，不能代替實速觀看；漂亮截圖也不能代表整段沒有漂移。工具若只能抽格或讀取編碼資料，就明列已檢查的影格、實速觀看／聽音待驗；可繼續離線診斷，但不能宣稱已完整觀看或聽過。

先挑一至三個最影響觀看的問題，避免把整段拆成幾十個小瑕疵。每個問題寫清楚：

- 在哪個鏡頭／時間區間，觀眾實際看到什麼。
- 它傷害哪個故事資訊、注意焦點或情緒；區分觀察與解讀。
- 下一版改什麼可驗證的變量，哪些來源事實與既有連戲要保留。

例如「畫面很 AI」無法執行；「人被困在門前，卻像面向鏡頭展示服裝，觀眾看不出她在防備什麼」可以定位構圖、視線與表演問題。

### 參考影片研究：找可移用的方法

使用者要求研究、或尚無可接受基準時，選少量與本案表演難點接近的作品：有人物行為／反應的敘事片，比純景觀或模型展示更適合驗證角色戲。可跨 AI 動畫、AI 實寫與傳統影片，記錄媒介與製作條件差異，不列成熱門排行或保證品質的工具清單。

在使用者指定的瀏覽器開原片，記片名、作者、連結、查閱日與實際時間點。將「畫面可見」「作者說明」「本案推論」分列；先確認正片已載入，排除廣告、預覽縮圖與跳轉尚未解碼的舊畫面。只抽格就只下構圖／可見狀態結論，不聲稱驗過完整動作、口型、聲音或留存率。參考片無法開啟時記明限制，不能只靠搜尋摘要宣稱看過。

每例只提煉少量可測試的做法，寫出本案如何採用、不採用什麼及原因。借用的是視線引導、行為與剪接關係，不直接複製角色、鏡頭素材、台詞或別人的長提示。外部作品的模型、參考數量、片長或重試次數不會自動成為本案規格。

研究紀錄範例：[2026-10-03 三部敘事作品抽樣與製作筆記](../../../../docs/videos/series-plans/competition-20261002/episodes/visual-reference-study-20261003.md)。這是有觀察範圍的案例，不是「90 分已驗證」或往後每案必看的固定片單。

要的是數字而不只是印象時（多久換一個畫面、開場幾個鏡頭、台詞多長），用 `.agents/skills/youtube-video/scripts/yt_shot_probe.js` 在同一個瀏覽器裡量，做法與紀錄格式在 drama-craft.md 的「重新量參考片」；[2026-10-03 五支 AI 漫劇的量測](../../../../docs/videos/drama-craft/reference-study-20261003.md)是第一份。

## 2. 小量美術定調，先建立比較基準

在原授權範圍內做少量、可直接並排比較的方向。先改上述優先問題，不同時隨機改臉、服裝、機位、配色和劇情。兩三張樣張或一小段通常足以開始比較；數量與時長只是建議，依問題和預算決定，不是通用硬門檻。

每個方向用一小張表寫出四件事：

| 決策 | 寫成具體的畫面意圖 |
| --- | --- |
| 構圖 | 第一眼看哪裡、前中後景如何安排、人物與出口／證物的關係、必須保留的畫面軸線 |
| 光影 | 光源來自哪裡、明暗如何塑造臉與動作、場景情緒；避免每個場景沿用同一團泛光 |
| 臉與材質 | 保留哪些身份特徵，布料、皮膚、金屬與紙張如何區分；細節密度是否遮住表情 |
| 觀眾注意 | 此鏡只交代哪個主要資訊，哪些背景、紙線、裝飾需要退到次要層次 |

未另行修訂分鏡時，提示詞保留來源單格構圖與 camera，新增文字只描述畫面可見且必要的資訊。構圖本身有問題就修分鏡並重綁，不必固守失敗的機位。手部插鏡附袖口、手錶與道具即可，完整命名造型仍留在資料綁定中；不要加整套臉、髮型和裙擺描述，把插鏡拉成全身照。注意工具會替列在 `data.characters` 的角色接上整段外觀：`tools/video/media/keyframes.mjs` 的 `shotPrompt` 把每人的 appearance（或選定的命名造型）接成 `Characters:` 子句（`tools/video/core/drama.mjs` 的 `shotAppearancePrompt`），`keyframeRubric` 再為每人加一題權重 2 的 `identity_<id>`，任一題低於 4 分整張不過（`apps/api/app/video_media/judge.py` 的 `MIN_CRITERION`），沒有臉的插鏡可能答不了。插鏡的 `characters` 列或不列、哪個較穩（沒驗）與範本，在 `.agents/skills/animation-camera/SKILL.md`「寫 prompt」的手部插鏡條；同一場裡不要兩種混用。

把角色身份、命名服裝和場景風格分開。倉庫的冷門框與火光不能因全域 style 混進白天婚禮。沿實際採用影格記局部連戲，不把某張偶然生成的袖長、腕側或飾物升格成整部作品的新設定。

風格依故事與使用者目標選擇，不把品牌電影、寫實電影光或任何單一美術風格當成所有漫劇的答案。靜鏡也能有壓力與表演；不因畫面太平就一律加運鏡。

### 把導演意圖寫成畫面能執行的事

以下是可依敘事調整的工作原則，不是強制景別順序或自動評分表：

- **換景別就換觀看任務。** 場域鏡交代限制，接觸鏡看清行為，反應鏡讀到結果。連續幾鏡若只重複同一句旁白的資訊，先修畫面功能；不為熱鬧任意加切鏡。
- **用身體行為表達情緒。** 寫視線落點、軀幹重心、肩頸／肘腕支撐與手指受力。「克制」要能在姿態中讀到，不能只靠形容詞。只能演來源允許的行為。
- **道具插鏡回答故事問題。** 此時是哪份原件、是否已簽、誰掌握它？用位置、留白、接觸和前後狀態交代；不是多畫幾行假字或增加裝飾。
- **把對比留給當下重點。** 明暗、清晰邊緣、色彩和細節密度先服務臉、手或證物；其餘退後。不要每件東西同樣亮、同樣銳，也不要每個場景共用火光濾鏡。
- **主動作先於次要動態。** 眨眼、呼吸、頭紗及背景動態支持生命感；若觀眾只看到眨眼卻看不出原定握緊，演出問題仍在。可讀性不等於把微顫放大成轉筆。
- **切在理解或反應形成的時刻。** 依觀眾辨認道具、察覺選擇、等待結果的時間調節停留。先用原配音試剪，不以每鏡固定秒數、固定快切頻率或大音樂代替節奏。

沿現有分鏡補這張小卡；它是製作記錄，不新增核准表單：

```text
鏡號／來源版本／必守連戲：
此鏡讓觀眾新理解什麼：
畫面：主焦點、景別／軸線、場景光源、材質主次
演出：起始狀態 → 原定動作／接觸受力 → 結束狀態
銜接：前後資訊、原配音時窗、必要聲效、CC
驗證：實速應看見什麼；哪些現象表示沒做到
```

樣張的結論只能是「美術方向候選」。即使非常漂亮，也不能宣稱原模型能穩定生成同品質的連續表演。會改變已核准 look／storyboard 的風格或構圖，應建立新版本並重新綁定正常核准與素材 pins，不借用舊 hash 宣稱有效。

## 3. 在原模型與授權內做代表動態小樣

挑能驗證這次改進、也能暴露主要難點的連續段落：人物反應、必要的手／道具動作與前後鏡頭關係。不要只用風景、孤立美圖或容易的一鏡代表整集。

區分首次驗證整體產線的代表小樣與既有小樣的局部修正。首次小樣依 animation-production 的能力範圍選材；只修旁白鏡的構圖或手部，不為湊齊對白、接觸等項目擅加台詞、人物或劇情，也不重啟已驗證且未受影響的工序。

沿已授權的模型、規格、預算與 retake 上限生成，先確認小樣的目的和失敗條件。提高品質不代表可以加預算、換模型、改劇情、換角色或重新錄已接受的配音；若現有條件確實做不到，先整理可比較的證據與具體選項，再處理必要的範圍決策。

用原先已接受的配音做正常時間軸，配上可關閉的 CC。只補有敘事用途、來源與使用授權可查的必要聲效，例如紙張撕裂、筆落桌或環境底音；不可用誇張音效把小動作假裝成重大事件。原生生成音訊的處理沿既定製作規格。

配音已固定時，先在來源與聲音時窗內修畫面演出、切點和停留；不得把一般「調台詞」建議解讀為可自動改稿或重新 TTS。確需改動已接受錄音時，按原有範圍決策處理。

讓一個主要動作可讀：準備、動作本身、接觸或受力、收勢。微顫不應變成抬筆旋轉，握緊不應變成另一隻手加入；重拍提示應指出具體失敗與原有圖像關係，避免用互相矛盾的左右手描述要求模型重建構圖。

剪掉無效尾段可以，但採用區間仍須包含完整、合乎來源的行為與收勢。不得用凍格、循環、變速或靜圖縮放掩蓋不會演的動作，也不得只呈現合格片尾、隱瞞保留區間內的額外動作。

## 4. 以觀眾速度審，再逐幀查證

完成有聲小樣後，先從頭實速觀看，不在每個好看的影格停住。檢查「看懂了什麼」「情緒何時改變」「什麼使人想看下一鏡」，再逐幀看手、接觸、臉、光影漂移與文件文字等疑點。

請另一位未參與提示設計的審查者冷看，不先餵導演想表達的答案。讓對方用自己的話回報：

- 人物現在想做什麼、受到什麼限制，哪個畫面讓他這樣理解。
- 主要動作與道具狀態有沒有看懂；哪裡必須靠旁白才能補出因果。
- 是否想繼續看，具體原因是角色選擇、衝突、資訊差，還是只因畫面漂亮。
- 哪個時間點分心、覺得假或等太久，以及可指出的原因。

冷看可以先關 CC 理解主要行為，再開 CC 查台詞與閱讀節奏；這不是要求無聲也能完整理解所有對白。保留獨立審查的原始觀察，不把「沒看懂」改寫成稱讚。

## 5. 達到已接受標準後再批量

將新小樣與被退回版本、已接受的質感基準放在相同播放條件下比較。確認優先問題實際改善，沒有靠犧牲來源、身份、道具連續或聲音清晰度換取漂亮畫面。

沿現有 look／storyboard／clip／final 與使用者接受流程處理結果，不新增每鏡一次的詢問或核准儀式。已授權且落在固定方向內的修正可繼續；使用者拒絕的方向、未解的重大缺陷或必要的新範圍決策，才需要集中呈現具體結果。

未達已接受標準就保持 `needs_revision` 或 `rejected`，不要批量複製問題。達標後固定角色臉、命名造型、場景光色、材質、表演幅度、剪輯與聲效基準，使用實際採用媒體和正常核准 pins 擴展下一小批，再檢查漂移。

達 retake／預算上限、同一重大缺陷反覆出現，或付費請求結果未知時，停止該失敗分支。保存嘗試與曝險，不以新 request ID 無限重試；可並行完成不依賴該片段的離線工作。

## 證據與分歧

品質紀錄至少包含版本、實際媒體雜湊、來源版本、觀看方式與採用區間、優先問題、修改假設、技術／美術／敘事表演／剪輯聲音的觀察、獨立冷看意見、正常 judge 結果和使用者接受狀態。媒體與私有收據留 repo 外；公開文件不放憑證或個人機器路徑。

沒有的媒體／收據記 `not_available`，尚未檢查記 `not_checked`，已安排但未完成的審查記 `pending`。缺欄不靠猜測填滿，也不妨礙能完成的離線診斷；待驗項目不能算已通過。

把重拍經驗保留成小案例：`觀察與時間碼 → 原因假設與確信度 → 實際改動 → 修正版媒體 → 驗證結果與副作用 → 適用條件`。未生成或只改了 prompt 就標未驗證；改善部分記部分改善；一個成功例不升格為跨模型定律。新一集沿用已接受的畫面與案例，遇到同類問題先檢查適用條件，避免從零盲試。

**不得修改分數、調低 judge 門檻、刪掉不利題目，或重複評分抽到通過，作為品質改善。** 正常 judge 未通過就如實保留未通過；人工覺得可用也不是改寫 `passed` 的理由。

發生分歧，回到實際影格、時間碼、來源要求與完整上下文。例如判成「開頭睜眼」，逐幀卻是原本睜眼後一次短眨眼，應精確記錄這項差異；不要因此推定全部低分無效。先辨別來源硬限制、技術瑕疵與主觀表演判斷，再沿既有覆核或例外流程處理，沒有既有路徑就交付具體證據與待決事項。

## 例子：修正畫面功能，而非加一串形容詞
