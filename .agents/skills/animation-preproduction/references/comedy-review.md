# 故事企劃評分審核：喜劇短劇與漫劇

站主 2026-11-03 定的規矩：**故事企劃要先過評分審核才進劇本關卡；分數不夠就改，一定要有笑點、要有趣。**
這一關在 P1 劇本鎖定之前、任何花錢的步驟之前，不取代站主的劇本關卡，而是讓送到站主面前的稿子已經被打過分、改過。

適用：有笑點要求的作品（喜劇短劇、寵物短劇、《汪汪社畜》這類系列）。正劇與旁白片不套這張表。

## 流程

1. 撰稿的人寫好 `video.json`（lint 零錯）後，產生盲評包：
   `node .agents/skills/animation-preproduction/scripts/comedy_review.mjs packet <VIDEO_DOCS>/video.json --out <VIDEO_DOCS>/comedy-review/round-1/packet.md`。
   盲評包只有每一鏡的畫面、動作、台詞與音效，沒有 brief、沒有撰稿人的意圖說明。
   `--style` 寫作品類型與允許的笑法（例：「擬人化無厘頭：狗像人一樣上班，不用照真狗的行為」），放在盲評包開頭；
   它是觀眾在片頭一秒就看得出來的類型，不是意圖說明。沒寫的話評審會用寫實的標準扣分（汪汪社畜第 3 輪就是這樣）。
2. **至少三位獨立評審**，各自只讀盲評包（另開的代理，不是撰稿的人；不給前一輪的分數與意見），照下面的評分表回一份 JSON，
   存成 `round-N/judge-<名字>.json`。三位用不同的觀眾角色：一位 18–24 歲常滑 Shorts 的人、一位 30 歲上班族、一位養狗的人（依作品換）。
3. 合分：`node .agents/skills/animation-preproduction/scripts/comedy_review.mjs score <VIDEO_DOCS>/video.json round-N/judge-*.json --out round-N/summary.json`。
   結束碼 0 才能送劇本關卡；1 是沒過。
4. 沒過：照 `summary.json` 的 `reasons`、分數最低的笑點與評審的 `fixes` 改稿。不是只改字，該換的笑點整段換掉。改完 lint、
   再產生新的盲評包，**換一組新的評審**評下一輪（舊評審看過舊稿會有偏差）。
5. 最多 3 輪。第 3 輪還沒過，停下來把三輪的分數與意見交給站主決定，不再自己改。站主授權多跑時，**連兩輪中位數進步不到 3 分就停**：
   換一組評審的雜訊大約 ±3 分（汪汪社畜 EP1 第 4–6 輪：75、73、73），再改只是在評審的口味之間搖擺
   （同一張員工證，第 5 輪說是穿幫、第 6 輪建議要掛回去）。
6. 鏡號照順序連號（`s01-…`、`s02-…`），刪鏡後重編。評審會照順序自己編號，跳號會讓他把笑點記到錯的鏡頭（EP1 第 6 輪）。
7. 送劇本關卡時，在回報裡附最後一輪的中位數、各軸分數與最強的三個笑點。

## 評分表（100 分）

| 軸 | 滿分 | 評什麼 |
| --- | --- | --- |
| `hook` | 15 | 前 2 秒：第一格就有衝突或怪事，讓人不想滑走 |
| `premise` | 10 | 一句話說得出的設定，一般人一看就有共鳴 |
| `laughs` | 20 | 笑點密度：平均每 8–10 秒一個真的會笑的點，不是只有可愛 |
| `escalation` | 10 | 情況一次比一次糟或荒謬，不是同一個笑點重複 |
| `surprise` | 15 | 至少一個觀眾猜不到、但回頭看合理的反轉 |
| `character` | 10 | 角色的反應與台詞有個性、具體，不是空泛的形容 |
| `payoff` | 10 | 結尾收得有力，有重看或追下一集的理由 |
| `share` | 10 | 看完會想轉給某個具體的人 |

## 門檻（全部要過）

| 門檻 | 值 | 為什麼 |
| --- | --- | --- |
| 評審人數 | ≥ 3 | 一個人的笑點太主觀 |
| 總分中位數 | ≥ 80 | 及格線 |
| 每位評審的總分 | ≥ 65 | 不能有人覺得無聊 |
| `laughs` 中位數 | ≥ 14／20 | 「一定要有笑點」 |
| `surprise` 中位數 | ≥ 10／15 | 「要有趣」：結局不能被猜到 |
| 強笑點 | ≥ 3 個笑點的中位數 ≥ 4／5 | 評審沒列到的笑點，在那位評審那邊算 1 分 |

門檻是編輯判斷，第一季做完用 YouTube 數據（`youtube-channel-reports` 的平均觀看百分比、分享數）回頭校準，不要為了讓一集過而調低。

## 評審的指示與 JSON

給評審的提示詞要包含：你的觀眾角色、盲評包全文、這張評分表、下面的 JSON 格式，以及「誠實打分，不要客氣；
你在滑 Shorts，這支不好笑你會直接滑走」。不給撰稿人的說明、不給前一輪結果。

```json
{
  "judge": "office-worker-30",
  "scores": { "hook": 12, "premise": 9, "laughs": 15, "escalation": 8, "surprise": 11, "character": 8, "payoff": 9, "share": 8 },
  "beats": [ { "shot": "s09-kpi", "joke": "狗把績效被吸走說得像職場悲劇", "funny": 4 } ],
  "would_scroll_away_at": "s04-room",
  "fixes": [ "s15-wall：「轉職」太好猜，換成更具體的職場梗" ]
}
```

`beats` 列評審認為是笑點的每一鏡（`shot` 用盲評包的鏡號），`funny` 1–5：1 不好笑、3 會心一笑、5 笑出聲。
`fixes` 要具體到哪一鏡、改成什麼。`score` 會檢查格式，格式錯是結束碼 2。
