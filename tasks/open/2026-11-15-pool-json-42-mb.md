# 原來如此素材池：pool.json 已 42 MB，照奇聞池的做法拆檔

## Why

`docs/videos/so-thats-why/pool/pool.json` 是原來如此事務所素材池的建置產物，第三十七輪之後 42.3 MB、單檔。
每輪長約 0.6–0.8 MB，大約再十輪就超過 GitHub 的 50 MB 警告線（100 MB 直接拒收）。
奇聞池同樣的問題已在 `2026-11-15-pool-json-50-mb` 解決，這張票把同一個做法搬過來。

## Definition of done

- [ ] `pool.json` 拆成數個檔，每個明顯低於 50 MB；`cli.mjs build`／`check` 與測試照過。
- [ ] 直接讀 `pool.json` 的地方（`semantic.py`、`store.mjs`、`history.mjs`、奇聞池的跨系列快照 `external/so-thats-why-cores.json` 的產生方式、研究工作單裡叫代理用 python 讀池的指令）都跟著改。
- [ ] `README.md` 寫明檔案配置；測試擋住任何一個檔接近上限。

## Steps

- [ ] 照 `tools/video/curio/pool/core.mjs` 的 `splitPool`／`writePool`／`readSavedPool`（`POOL_PARTS`）做：大陣列搬到各自的檔，`pool.json` 留 `{ file, count }` 指標，讀回來放回原位。
- [ ] 先量大小花在哪，決定搬哪幾個欄位（奇聞池是 `sources` 與 `raw_records`）。
- [ ] 改測試與文件。

## How to verify

```bash
node tools/video/so-thats-why/pool/cli.mjs build && node tools/video/so-thats-why/pool/cli.mjs check
node --test tools/video/so-thats-why/pool/pool.test.mjs tools/video/so-thats-why/catalog.test.mjs
```

## Notes

- 動到產物檔時要把 `docs/videos/so-thats-why/pool` 加進 scope，並確認沒有進行中的擴充輪次：研究代理是直接用 python 讀 `pool.json` 去重的，輪次跑到一半改檔案配置會讓它們讀不到。
- 順手更新奇聞池的 `external/so-thats-why-cores.json`（還是 2026-11-01 的 2,837 筆）。
