# 系統說我是 BUG：第一季延長到 50 集（約 120 分鐘），寫第 31–50 集細綱並把第 2–5 篇匯入站上

## Why

站主 2026-10-24：「繼續規劃系統說我是 BUG 的劇情，預期總片長要 120 分鐘左右，每一集都要有之前講的規則；直接做完再匯入就好」，接著「可以留謎團，說不定點閱率好就做下一季」「用推薦的決定就好不用問我」。企劃包原本是第一季 30 集、合計 4,350 秒（約 72 分鐘），站上的作品 `xitong-shuo-wo-shi-bug` 也是 30 集、只核准了第 1 篇細綱（第 1–10 集，第 1–4 集在做）。

## Definition of done

- [x] 企劃包第一季是 50 集、合計 7,200 秒（120 分鐘）：第 1–30 集不動，第 31–50 集（篇章 7〈倒數〉、8〈勸捨堂〉、9〈覺醒塔〉、10〈認領〉）照同一套規則寫完；`node validate.mjs` 零錯誤、`node build.mjs --check` 最新。
- [x] m05（當機）在第 33 集揭；m02、m04、m06 留給第二季；季末收在反轉（第 50 集）。
- [x] `site-bundle.mjs` 輸出 50 集、五篇的總綱與第 1–5 篇細綱；apps/api 的 `doc_problem`／`_retention_problem`／`document_prerequisite_problem` 與工人的 `documentProblem` 離線全過。
- [ ] 站上作品 `planned_episodes` 50；設定集、總綱、第 1–5 篇細綱的最新版本是企劃包的內容並已核准；第 5–50 集 `ready`（第 1–4 集照舊在做）。

## Notes

- 劇情走向（第 31–50 集）：白珩在垃圾坑邊不出手，管理員只給唯讀，日誌倒數「回收週期：剩餘 15 日」——十年一次的清空，回收桶裡無主的東西全部化成靈石存進覺醒塔，名單最後一行是「回收程序：江河」。當機變十秒（載入上限 30），他找到「卸載」：送回原主、原主認領就移出名單（m05）；阿桂的辨味嚐得出殘片是誰丟的。白鹿城勸捨堂把倒數往前推，祁硯名冊倒戈、捨棄池變成歸還的流水線、嚴關拿回辨人；白珩說清空的靈石是下一代覺醒的燈油，金庫的帳算出燈油夠點五十年；江河把自己的技能全送出去，回收桶只剩他；公告一句話「我在落石鎮的垃圾坑。你可以不理我。」，1,237 人在除名令下認領他，清空略過。季末反轉：最後一個認領者是用管理員字體寫的另一個「江河」，「讀檔紀錄：第二次」。
- 7,200 秒的分配：每篇章最後一集 160–165 秒，其餘 135–150 秒（篇章 7–10 各 705／715／705／725 秒）。
- 站上的 `edit_doc` 只能換已經存在的文件（沒有就 404「這份文件還沒有產生」）；第 2–5 篇還沒有第一版，要先讓它存在（工人規劃，或在 api 容器用 `xitong_runner.py submit`）再換。
- 改設定集會呼叫 `invalidate_document_dependents`：總綱與所有細綱各多一個待審副本、`ready` 的集數退回 `planned`；做到一半的集數（started）不受影響。所以設定集之後要依序重新核准總綱、第 1 篇、第 2–5 篇。
- 離線驗站上規則的腳本：在 apps/api 用 `uv run python` 建一個不進資料庫的 `VideoDramaSeries`（50 集、每篇 10 集、system-game、manga），對 bundle 的每份文件依序跑 `doc_problem`、`_retention_problem`、`document_prerequisite_problem`；工人那邊用 `tools/video/automation/series.mjs` 的 `documentProblem`（worktree 要先 `npm install --no-save pinyin-pro`）。
