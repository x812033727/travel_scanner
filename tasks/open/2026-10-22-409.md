# 設定圖審核送出後，審核儲存區把其他角色剛上傳的檔案清掉，第二筆審核 409、工人不再重試

## Why

每一支有兩個以上角色的漫劇都在設定圖關卡卡死；2026-10-22 兩支都是：試片單集 `one-off-252a53bc-e001`（13 張、4 張「還沒上傳完」）與作品《系統說我是 BUG》第 1 集 `xitong-shuo-wo-shi-bug-e001`（15 張、5 張「還沒上傳完」）。免關卡的作品也過不去，所以票 `2026-10-22-bug-30` 的十集全部停在這裡。

主機 API log（16:12–16:18Z，e001）的順序是：15 個 `PUT …/files/<sha>` 全部 200 → `POST …/reviews` 201 → `POST …/reviews` 409 `video_review_files_missing`。審核儲存區 `travel_scanner_video_reviews/_data/xitong-shuo-wo-shi-bug-e001/` 事後只剩第一筆審核引用的 5 個檔。

原因是兩邊合起來的：

- 工人的設定圖關卡**一個角色一筆審核**（`tools/video/review/sync.mjs` 的 `lookSubmissions`），而且先把所有角色的候選圖都上傳完，再依序 POST。
- 伺服器 `submit_review` 最後一行 `store.keep_only(slug, kept_files([*reviews, review]))`（`admin_service.py` 約 1866 行）把這支影片裡「沒有任何審核引用」的完成檔全部刪掉。第一筆（江河）送出時，系統與唐測的 10 張剛上傳、還沒被任何審核引用，就被刪了；第二筆 POST 的 `missing` 檢查於是 409。
- 工人收到 409 後把它記成「延後 5 分鐘」，之後再也沒有重試這一鏡（試片 05:54Z 起、e001 16:17Z 起都是如此），`auto.json` 也沒留下 `blocked`；後台只看得到第一個角色的設定圖審核卡。

## Definition of done

- [x] 一次送多筆審核（設定圖三個角色）時，每一筆都 201；儲存區不會刪掉同一輪剛上傳、還沒被引用的檔案。
- [x] 工人遇到 `video_review_files_missing` 時會在下一輪重新上傳缺的檔並重送，而不是靜靜等站主。
- [ ] `xitong-shuo-wo-shi-bug-e001` 的三個角色設定圖都進了審核（免關卡下由 judge 自選），工人繼續往旁白走。
- [x] 試驗證明：`apps/api` 的測試覆蓋「兩筆連續送出、第二筆的檔案在第一筆之前上傳」。

## Steps

- [x] 伺服器：`keep_only` 不要在 `submit_review` 時刪「還沒被引用但剛到」的檔——最簡單是只刪 mtime 超過一段時間（例如一小時）而且沒有審核引用的檔，或把這次清理搬到站主做決定／審核被取代（`_supersede`）的時候；`drop_project` 與 `prune_published_previews` 的 `keep_only` 照舊。
- [x] 工人（擇一或都做）：`lookSubmissions` 改成每個角色上傳完就立刻 POST，再上傳下一個；收到 409 `video_review_files_missing` 時把缺的 sha 重傳後重送，並在 `auto.json` 記下。
- [ ] 部署後在主機對 e001 手動 `review-push --gate look` 一次，看三筆都 201，再讓工人接手。

## How to verify

主機 `docker logs travel_scanner-api-1 | grep reviews/<slug>`：三個 `POST …/reviews` 都 201；儲存區資料夾裡 15 個檔都在；後台影片頁的設定圖審核三個角色都有卡（免關卡會自動選）。

## Notes

- 試片的票 `2026-10-22-manga-pilot-run` 與十集票 `2026-10-22-bug-30` 的 Notes 有同一個現象的紀錄；試片單集已放棄。
- 品牌故事沒有設定圖關卡、動畫漫劇走海螺手動路線，所以這個問題只在站上自動做的多角色漫劇出現，之前沒踩到。
- 2026-10-23 做法（claude-fable-5.1）：
  - 伺服器：`storage.py` 的 `keep_only` 多了 `older_than` 參數——有給的話，沒被引用但 mtime 還在期限內的檔先留著；`admin_service.py` 只有 `submit_review` 傳 `older_than=UPLOAD_GRACE`（一小時），`drop_project` 與 `prune_published_previews` 照舊立刻刪。`put_part` 收到已經存在的檔會 `os.utime` 更新 mtime，所以重傳一個還在的舊檔也算「剛到」。
  - 工人：`sync.mjs` 的 `lookSubmissions` 改回傳「每個角色一個函式」，`reviewPush` 叫到才上傳那個角色的圖並立刻 POST，再換下一個；POST 收到 409 `video_review_files_missing` 時，新的 `submit()` 把 detail 裡列出的（或沒列就全部）這筆審核的檔重傳一次再重送，重傳要的是這次 push 自己上傳過的檔（`request.sources`）；第二次再 409 就照舊當服務錯誤（exit 4），工人下一輪會整批重傳再送。
  - 測試：`test_video_reviews.py` 兩個新測試（寬限的 `keep_only`、三個角色連續送出都 201 且檔案都在、一小時前的孤檔仍被清）；整合測試 `test_video_reviews_integration.py` 裡「被取代的舊成片會被刪」要先把舊檔 mtime 調老兩小時，不然寬限會留住它。`sync.test.mjs` 四個新測試（會清檔的假站台下兩個角色都 201 且呼叫順序是 PUT→POST→PUT→POST、409 一次後重傳重送、連續兩次 409 退成 exit 4、detail 列的 sha 不是自己上傳的就不重送）。
  - 沒修的：`flow.mjs` 的 `lookGate` 只要站上有任一角色這份 manifest 的審核就不再呼叫 review-push，缺角色的影片會一直等；開了票 `2026-10-22-lookgate`。e001 目前站上只有江河一筆，部署後要手動 `review-push --gate look` 一次補上另外兩個角色（Steps 第三項）。
