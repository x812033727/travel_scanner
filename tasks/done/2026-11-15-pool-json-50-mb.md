# 奇聞素材池：pool.json 超過 50 MB，拆檔或瘦身

## Why

`docs/videos/history-curiosity/pool/pool.json` 是奇聞檔案局素材池的建置產物，第五十七批之後約 55.6 MB。
GitHub 對超過 50 MB 的檔案每次 push 都警告，100 MB 會直接拒收；照每批約 0.8 MB 的成長，大約再五十批就撞牆，
而且每批的 diff 都是整檔重寫，repo 越來越肥、`cli.mjs search` 也越來越慢（擴充時研究代理已經改用 grep）。

## Definition of done

- [x] `pool.json` 進版本庫的大小明顯低於 50 MB，或不再進版本庫而由 `build` 產生，`check` 與既有測試照過。
- [x] 讀 `pool.json` 的地方（`cli.mjs`、`semantic.py`、原來如此池的跨系列去重、文件裡的指令）都跟著改。
- [x] `README.md` 寫明新的檔案配置。

## Steps

- [x] 量一下大小花在哪（`sources`、`raw_records`、`candidates` 各佔多少；有沒有同一段文字存了多份）。
- [x] 選一個做法：依軸或依批拆檔、把 `raw_records` 移出、或改成不入庫的產物。先看原來如此池怎麼處理同樣的問題。
- [x] 改工具與測試。

## How to verify

```bash
node tools/video/curio/pool/cli.mjs build && node tools/video/curio/pool/cli.mjs check
node --test tools/video/curio/pool/pool.test.mjs
```

## Notes

- 站主 2026-11-15 同意另開這張票，不併在擴充的 PR 裡；之後說「處理掉那兩張票」，所以還是在同一個分支上做完。
- 大小花在哪（壓成一行算）：`sources` 17.3 MB（幾乎全是 `readings`）、`candidates` 15.0 MB、`raw_records` 14.3 MB、`not_added` 1.6 MB。
  `candidates` 是 `raw_records` 加上計算欄位，兩者內容大半重複，但 `raw_records` 多了 18 筆別名紀錄，`history.mjs`、`store.mjs`、`semantic.py` 都直接用它，所以沒有刪，只搬出去。
- 做法：`core.mjs` 加 `splitPool`／`writePool`／`readSavedPool`。`pool.json` 的 `sources` 與 `raw_records` 改成 `{ file, count }` 指標，
  內容寫到 `pool-sources.json`、`pool-records.json`（各帶 `revision`）。讀回來把陣列放回原位，鍵的順序不變，所以 `readPool` 的漂移比對、索引、基線都不用改。
  三個檔都列進 `manifest.json` 的 `files`。
- 結果：55.6 MB → `pool.json` 19.6 MB、`pool-sources.json` 20.1 MB、`pool-records.json` 15.9 MB。照每批約 0.8 MB 三檔均分，離 45 MB 的測試上限還有約八十批。
  再長大就把 `candidates` 也拆出去（`POOL_PARTS` 加一列）。
- 沒選「不入庫」：`check` 靠入庫的那一份比對重建結果，是覆核的關卡；拿掉就只剩 manifest 的雜湊。
- `semantic.py` 的預設輸入改成 `pool-records.json`；`--input .cache/draft.json` 的用法不變。
- 原來如此池的 `pool.json` 是 42.3 MB、單檔，大約再十輪也會碰到 50 MB：另開票 `2026-11-15-pool-json-42-mb`。
- `npm run test:tools` 在這個雲端容器裡有 107 項失敗，全是沒跑 `npm ci`（找不到 `intl-messageformat` 等套件）的檔案；`tools/video/curio/pool/pool.test.mjs` 27 項全過。
