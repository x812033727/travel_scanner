# 內容檢查器有 91 個錯誤，而且 CI 完全沒在跑它

## Why

`apps/api/app/guides/pack_ingest.py` 的 `lint_all()` 是這個 repo 自己寫的內容檢查器，
規則不少（圖上畫的數字文章必須有、標籤不得小於 15px、每篇要有表格與 callout、
來源要有查核日）。它有 CLI 入口：

```bash
cd apps/api && uv run python -m app.guides.pack_cli lint
```

**但 `.github/workflows/` 裡沒有任何一個 job 會呼叫它。** 十三個 workflow 都查過了。
所以這個檢查器自從寫出來就沒有把關過任何一次合併，錯誤只進不出。

2026-09-21 在 `origin/main` 上跑一次，**exit 1、91 個 `error:`，橫跨 31 個 slug**：

| 錯誤 | 筆數 | 意思 |
|---|---|---|
| `diagram_number_not_in_text` | 82 | 圖上畫了一個數字，那一語系的文章正文從來沒寫過 |
| `svg_small_label` | 9 | 標籤 13px 或 14px，低於 15px 下限 |

這不是形式問題。`diagram_number_not_in_text` 命中的正是站主 2026-09-21 抱怨的
「資訊不清楚」：讀者在圖上看到一個費用或時間，翻遍文章找不到它的出處或前後文。

舉一個已經查到底的例子：`taiwan-convenience-store-guide` 的 `diagram-1.svg` 畫著
全家國際傳真每頁 NT$85。en 的費用表有這一列，**ko 與 zh-CN 的表沒有**，
所以那兩個語系的讀者看到一個文章裡不存在的數字。ko 與 zh-CN 的內容包
從 #454 合併起就沒再改過，等於這個缺口在正式站上放了一段時間沒人發現。

## Definition of done

- [x] `uv run python -m app.guides.pack_cli lint` 在 `main` 上 exit 0。
- [x] CI 有一個 job 會跑它，而且故意加一個錯誤時那個 job 會紅。

## Steps

- [x] 先修錯誤，**不要先接 CI**，否則第一次跑就紅。
- [x] 82 筆 `diagram_number_not_in_text`：逐筆判斷是「圖畫多了」還是「文章漏了」。
      多數看起來是後者（翻譯時整列沒跟上）。兩種修法都可以，但**不要靠刪圖上的數字**
      來讓檢查器閉嘴，那會讓圖變得更沒有資訊。
- [x] 9 筆 `svg_small_label`：13–14px 調到 15px 以上，調完要重新量一次有沒有疊字。
- [x] 接進 `.github/workflows/ci.yml`。
- [x] 加完之後刻意塞一個錯誤，確認 job 真的會紅再拿掉。

## How to verify

```bash
cd apps/api && uv run python -m app.guides.pack_cli lint; echo "exit=$?"
```

exit 0 且沒有任何 `error:` 行才算過。單一 slug 用 `--slug <slug>`。

## Notes

- **×5 幾乎一定是五語系同一張圖**：那些 slug 只有一張 `diagram-1.svg`，五個語系共用，
  所以一個數字沒翻到就是五筆。從一個語系修起，另外四個通常是同一列。
- 這 91 筆**沒有一筆**在 2026-09 韓國美食／咖啡那 22 篇裡。那批的圖在
  2026-09-21 重繪時逐張跑過 `check_svg` 與 `missing_diagram_numbers`。
- `warning:` 另外還有幾百筆（`no_summary`、`text_length`、`no_diagram`），
  這張票只處理 `error:`。warning 要不要收是另一個決定。
- 接 CI 時注意 `lint_all()` 需要 `apps/web/public` 才能讀到 SVG，
  只 checkout `apps/api` 會全部報 missing。

## Done 2026-09-30 (claude-opus-5-5)

On 2026-09-30 main had 89 errors (81 `diagram_number_not_in_text`, 8
`svg_small_label`). What each turned out to be:

- 67 were step badges: a text node holding only `01`-`09` numbers the boxes of
  a flow diagram (the articles, e.g. `japan-station-locker-guide`, have no digits
  at all). `diagram_numbers` now skips a node that is nothing but a badge; the
  same digits inside other text still count. Test added.
- Some locales write figures in myriads (`1万元以上100万元以下`, `3万5千`), which
  the checker read as missing. `100万` now also counts as 1,000,000. Test added.
- 8 labels at 14 px became 15 px. Every diagram was rendered before and after
  and checked by eye; labels the larger size pushed out of their boxes were
  fitted with `textLength` (Everland en/ja, Gyeongju, Ayutthaya, Seoul), re-wrapped
  (Everland footer), shortened (Gyeongju KTX line) or moved (Seoul AREX).
- The real gaps were translations missing figures their own zh-TW or en edition
  has: Kaohsiung (24:00, R11, 1883), Tainan ja (05:50/23:00), Taipei ko/zh-CN
  (bus 1960, first train 06:03), convenience store ko/zh-CN (fax NT$85), arrival
  card ja/ko/zh-CN (other nationalities' 90/30/14 days to 2027-07-31, NT$35,000),
  Taiwan winter en (a caption line that dates are month/day), Kyoto zh-TW
  (`6 點` written `6:00`). No new fact was added.
- Taipei's shared diagram drew two estimates zh-TW withdrew in #624; those two
  labels and `<desc>` clauses now follow zh-TW. Korea winter's `15 日` axis ticks
  became `月中` (mid-month).
- Result: `pack_cli lint` exit 0 over 1,127 packs; CI's api job runs it after
  mypy. An injected 14 px label made the same command exit 1 locally.
- Follow-ups filed: `2026-09-30-bring-taipei-where-to-stay-translations`,
  `2026-09-30-correct-the-zh-cn-arrival-card`, `2026-09-30-fit-the-seoul-4-day-diagram`.
- Not done here: production. SVG-only changes ship with the next deploy; the
  text changes in kaohsiung, tainan, taipei, convenience store, arrival card,
  Taiwan winter and Kyoto need `guides-import` dry-run and `--publish` per slug
  after that deploy, with the owner's go-ahead.
