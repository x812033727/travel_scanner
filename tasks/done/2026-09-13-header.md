# Header 缺一個隨處可達的深色/淺色切換

## Why

`SiteNavigation`（`apps/web/components/site-navigation.tsx:46-47`）只在
`!discovery.enabled` 時才畫出 `TextSizeSwitcher`／`ThemeSwitcher`，discovery 模式一開
（目前正式站就是 discovery on）這兩個控制項就從整個站頭消失，手機選單抽屜也一樣打不開
（見 `mobile-nav.tsx` 的註解）。PR #457 把外觀設定卡搬到 `/my`／`/account` 最上面，是當時
唯一還能切換深色模式的地方。使用者反映想要在桌面版頁首的語言圖示左邊也補一個，不用特地
去 `/my`。

## Definition of done

- [x] 桌面版頁首（`lg:` 以上）語言切換左邊出現一個深色／淺色切換，且不受 discovery 開關影響。

## Steps

- [x] `site-header.tsx` 的 `hidden lg:flex` 容器內，`LanguageSwitcher` 前面加
      `ThemeSwitcher`（直接複用既有元件與 `.theme-switcher` 樣式）。
- [x] `site-header.test.tsx` 補一條斷言：theme 控制項在 language 控制項前面、兩者同一個
      容器。

## How to verify

`npm run test:web`（`site-header.test.tsx` 兩條都過）；瀏覽器開 https://mokaair.com
桌面寬度，確認語言地球圖示左邊有一個深色／淺色圖示，且與 discovery 開關無關。

## Notes

- **CI 抓到本機測不出來的重複**：`site-navigation.tsx` 原本在 `!discovery.enabled` 時也畫一個
  `ThemeSwitcher`，加上頁首這個之後，discovery 關閉的桌面版就有兩個一模一樣的 Appearance
  下拉，`e2e/navigation.spec.ts:197` 直接 strict mode violation（resolved to 2 elements）。
  單元測試看不到是因為 `site-header.test.tsx` 把 `SiteNavigation` mock 掉了。
  修法是把 nav 裡那個條件式的拿掉（頁首那個是無條件的，所以它才是多餘的那一個），
  `TextSizeSwitcher` 留在原處不動。
- 手機版（`< lg`）語言切換本來就不在頁首，這次也沒動；手機版的深色切換仍然只能透過 `/my`
  或（discovery 關閉時的）選單抽屜，未來如果要補手機版是另一張票。
- 跑本機 e2e 時 3000 埠被另一個 session 的 dev server 佔著（不要去砍它），
  用 `PLAYWRIGHT_PORT=3137` 另開即可。跑完記得 `git checkout -- apps/web/next-env.d.ts`：
  dev server 會把它改寫成 `.next/dev/types/...`，提交下去會弄壞 CI 用 build 跑的型別檢查。
