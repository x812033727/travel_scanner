# 測試資料的日期到了就全紅：固定 API 的開行程日期檢查、trip-editor 與 travel-services 的時鐘

## Why

2026-11-12（UTC）起 main 上每個 PR 都紅：api-tests 2–4、web-unit 3、web-e2e 2–3。測試資料寫死 2026-11-10～13 的行程，
日期一到就被產品規則擋下：API 的空白行程不收「開始日早於昨天（UTC）」，回 422；trip-editor 把今天與過去的日子畫成別的樣子；
旅遊服務的預訂面板不收早於今天的入住日，合作夥伴按鈕不開新頁。11/10 的 #2066、#2071 是同一類，當時逐一修。

## Definition of done

- [x] API：開行程的日期檢查改呼叫 `app.trips.router.trip_today()`，`tests/conftest.py` 的 autouse fixture 把它固定在 2026-11-01（只在測試已匯入 app 時才改，不提前讀設定）。
- [x] `components/trip-editor.test.tsx`：每個測試只假造 Date、固定在 2026-11-01，testing-library 等待用的計時器維持真的。
- [x] `e2e/travel-services.spec.ts`：`page.clock.setFixedTime(2026-11-01)`，跟 planner-premium、full-stack 一樣。
- [x] CI 四個必要檢查轉綠。

## How to verify

```bash
cd apps/api && uv run pytest tests/test_trip_creation.py      # 整合測試要 Postgres/Redis，交給 CI
cd apps/web && npx vitest run components/trip-editor.test.tsx
```

## Notes

- 本機：`test_trip_creation.py` 16 過、trip-editor 77 過、`lint:web`、`typecheck:web`、ruff、mypy 通過。e2e 在正式主機上起不了 dev server（inotify 上限 128，Turbopack「Too many open files」），沒有改主機設定，交給 CI。
- 失敗清單：api 約 18 個全是建立行程 422；e2e 40 個全在 travel-services.spec.ts（入住日早於今天 → `pastDates`）。
- 其他寫死日期的測試以後還會一個個到期；遇到時照這三種做法固定時鐘，不要改測試資料的日期（改了下個月又壞）。
