## 全文終審實際怎麼做

1. 記錄作者稿、五語內容包及共用材料的版本。完整閱讀繁中、英文、日文、韓文作者稿，另讀轉換後的簡中內容包；逐段核對目標、前提、步驟、預期、失敗、修正、還原與 FAQ。
2. 對照當篇官方來源的實際內容與查證日期。特別優先處理入口、支援平台、方案、模型、命令、設定與授權範圍；來源不確定就修正文案或記為待釐清。
3. 檢查程式碼、檔名、參數、URL 及資料契約是否一致，必要的參考案例依改動重跑。產品執行、參考程式執行與文字核對分開記錄。
4. 修正確實妨礙理解的問題。原有篇幅提示先判斷是否重複；保留必要步驟時寫下理由，不刪除失敗或還原案例來湊字數。一般指南對專用總目錄是否適用，需以實作及後續畫面確認。
5. 記錄五語各自結果、修正、證據與未通過項目。每篇只有全文、適用產品證據及最終頁面都完成，才增加最終驗收數。

沿用[每篇紀錄格式](deepening/review-checklist.md#每篇審核紀錄格式)。原始盤點保留作為起點，實際結果新增在 evidence，並同步摘要到[製作進度](progress.md)及[共用任務](../../tasks/open/2026-09-14-codex-depth-content.md)。內容更新後必須重核受影響的結果，不能沿用不同版本的通過標記。

## 產品證據與頁面受阻時的安排

產品證據先從五篇代表稿處理：03 桌面入口及成果、10 規則讀取與實際行為、04 手機入口與正確主機、11 命令所屬介面、23 技能選用與成功／失敗／移除。每份紀錄需連到該篇的具體步驟及最終版本。既有六張 Windows Edge 練習頁截圖只能支持所拍的練習畫面。

其他平台無法實測時，保留「依官方文件查證」的標示和來源，依既定規格判定是否足夠；不要求無法取得的實機結果，也不以示意圖或桌面窄視窗冒充實機。代表稿明訂必須有的操作證據若欠缺，仍記待完成，不降為不適用。

自動核准審查曾拒絕啟動 Next.js 預覽，包括只監聽本機的重試，回報僅為 `blocked by policy`。此限制目前未解除，沒有已知可核准的解法。保持原失敗紀錄，不換啟動器、埠、伺服器、通道或渲染方式繞過。只有執行限制實際解除後才恢復受阻驗收；全文、來源及素材需求整理可繼續。

發布前另核對 Claude Code 任務及其他共用文章修改是否已整合；共用 `series_data` 仍須依當時任務持有人協調，不覆寫他人範圍。全部驗收後的 PR、合併、匯入、正式發布、部署及公開檢查各自保留證據。
