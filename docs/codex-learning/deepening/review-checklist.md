## 每篇六道檢查

### 1. 讀者能獨立開始

- [ ] 列明成果、程度、適用平台、帳號／工具前提、閱讀及操作時間。
- [ ] 給出可取得的練習起點、目錄、完整檔案或下載材料；有原始副本或明確復原點。
- [ ] 先備連結只是補充，關鍵步驟不能依賴尚未完成或未公開的文章。
- [ ] 每一步都有「操作位置 → 完整輸入 → 預期 → 不符合時怎麼查」。三種 OS 的適用操作同等完整，手機支援與限制分開說明。

### 2. 真正教會成功、失敗與還原

- [ ] 至少一個固定輸入的正常案例，能從檔案、工具、輸出或畫面核對成果。
- [ ] 執行或判讀該篇指定的失敗／邊界案例，保留症狀、原因、最小修正與重驗；概念篇有具體答案及理由。
- [ ] 通常至少三個針對本功能的 FAQ；確實不適用時記錄理由，不填入無關問題湊數。
- [ ] 設定、檔案、排程、連接等變更有各自的停止／還原方法；指出未還原的副作用。
- [ ] 比較結果只使用觀察值；不把模擬工作、程式格式檢查或未跑案例寫成實測。

### 3. 五語語意與指令一致

- [ ] 繁中、簡中、英文、日文、韓文的步驟、前提、限制、成功判準、FAQ、還原及來源逐項對照。
- [ ] 簡中轉換後另行校對，不能只以轉換成功簽核；日韓文避免混入未翻譯的中文術語。
- [ ] 指令、參數、檔名、URL、程式碼與資料契約保持一致；可翻譯的解說與不可變的程式碼分開。
- [ ] 直接複製頁面程式碼，核對貼上位置、縮排、引號、換行及完整輸入；不只對作者檔做比較。
- [ ] 五語篇幅以完整教學為準，不為了統一字數重複說明。

### 4. 來源與易變資訊

- [ ] 每個產品入口、支援平台、指令、設定及限制，對照該篇來源的實際內容與查證日。
- [ ] 記錄依官方文件查證、實際操作、推論三者；官方網址回應正常只算連結檢查。
- [ ] 方案／計費入口集中於 [02](unit-a.md#lesson-02)，模型與推理集中於 [17](unit-e.md#lesson-17)，工作效率比較見 [60](unit-j.md#lesson-60)；其他篇用文字連結引用，不複製易過期數字。
- [ ] 與 Claude Code 對齊的是深度及導覽。其規則檔、指令與功能機制不能直接改名移植到 Codex。

### 5. 圖片與平台證據

- [ ] 依各篇「需補或核對的圖文」決定保留、重拍或新增，先核對現有圖能否支持最終文字。
- [ ] 操作截圖記錄平台、OS／應用版本、擷取日期、實際裝置或響應式視窗，以及對應步驟。
- [ ] 截圖遮蔽帳號、私人路徑、配對碼及憑證；採用虛構練習資料。
- [ ] 原創圖解標為示意；生成圖不冒充真實 UI；第三方圖保存作者、來源、授權及必要署名。
- [ ] 五語替代文字與圖說描述同一畫面；數字標記與正文對應。完整指令及大量說明仍提供文字版本。
- [ ] 未實測平台標為依官方文件查證，不能用另一平台或桌面窄視窗冒充實機。

### 6. 最終文章與全站導覽

- [ ] 在最終內容版本核對 360／390／1280px，長行可捲動，圖片、表格與頁面不溢出。
- [ ] 總目錄可依程度、平台、需求、單元及關鍵字找回此篇；URL 篩選及分享可重現。
- [ ] 篇首篇尾返回目錄、同單元上下篇、2–4 篇相關教學、首次功能提及的正文文字連結都正確。
- [ ] 站內連結同分頁並保留語言；切換五語仍停在同一個永久 ID／slug。
- [ ] 未發布、撤回、缺語系或查詢失敗的文章不產生空頁連結；需要的說明仍在本篇提供。
- [ ] 管理預覽、API 區塊驗證及舊文章相容性通過受影響檢查；既有結果要核對是否仍對應最終版本。

## 每篇審核紀錄格式

把實際紀錄放到系列 evidence，引用已提交的文章版本及證據檔。以下是待填格式，不能直接當成通過紀錄：

| 欄位 | 必填內容 |
| --- | --- |
| 文章與版本 | 永久 ID、slug、作者及內容包的 commit 或 hash |
| 語言 | 五語各自的審核範圍、結果、審核人與日期 |
| 環境 | OS、產品／CLI／瀏覽器版本、裝置或 viewport；未實測項目另列 |
| 正常案例 | 完整輸入、預期、實際、差異及證據路徑 |
| 失敗與還原 | 觸發方式、症狀、修正、重驗、已還原範圍及剩餘副作用 |
| 圖片與來源 | 素材清單、來源／授權／查證日、五語 alt／caption 核對結果 |
| 頁面與連結 | 測試版本、語言、尺寸、複製、搜尋、跨篇及返回目錄結果 |
| 結論 | 通過／需修正／受阻；缺項、下一步與對應 tasks/open 任務 |

一篇只有全部適用檢查都有證據，才計入「最終深入驗收通過」。不適用需理由；受阻不能記為不適用。修改來源後，重新核對受影響項目，保留歷次結果而不覆寫失敗歷史。

## 可先做與仍待解決的工作

目前可先逐篇完成作者稿對照、正常／失敗案例設計、固定資料與預期核對、翻譯、來源內容及圖片需求盤點。這份規劃只產出上述規格與導覽，沒有執行產品操作或網站預覽。

最終網站預覽曾被自動核准審查拒絕，回覆僅為 `blocked by policy`，限制為只監聽本機後仍被拒，未提供具體原因。不改用其他啟動方式繞過；詳細狀態見[剩餘關卡](../progress.md#尚未通過的最終關卡)。Codex 桌面／手機產品介面證據與全篇五語終審也仍待完成。

開始改作者稿、工具或網站前，先依[任務協定](../../../tasks/README.md)認領對應範圍。所有未完成事項留在原系列任務；本規劃任務的完成不會自動解除發布條件。

全部驗收後才核對最新 main、開 PR、確認精確 head 的 CI、合併，再備份、匯入、正式發布與部署，最後核對公開五語頁面。此順序沿用使用者既有授權，不能提前把草稿或規劃當成已上線。
