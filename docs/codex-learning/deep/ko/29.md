## 목표와 준비

> 가상 로컬 목록의 반복 점검을 만들어 시간·결과·수정·일시 중지를 추적합니다. 읽기 15분, 실습 20분이며 예약 대기는 별도입니다. Scheduled 지원 계정·데스크톱에서 [작업 관리](article:codex-project-management)를 먼저 읽으세요. 요청 예시는 교육용이며 사용자 예약을 만들었다는 뜻은 아닙니다.

## 1단계: 실행 위치 선택

로컬 문서는 접근 가능한 호스트·전원·실행 중인 앱·존재하는 폴더가 필요합니다. 각 OS의 실제 버전에서 Scheduled를 확인하고 Linux 미리 보기에 없으면 사용 불가로 기록하세요. CLI/IDE에는 관리 UI가 없으며 준비 후 지원 진입점에서 관리합니다.

| 필요 | 선택 | 확인 환경 |
| --- | --- | --- |
| 같은 대화에서 추적 | 대화 내 예약 | 맥락과 접근 데이터 |
| 매번 독립 보고 | 독립 예약 | 저장 요청과 프로젝트 |
| 로컬 자료 읽기 | 데스크톱 호스트 | 전원·앱·폴더 |
| 업로드·연결 자료 | 지원 웹·모바일 | 요금제·도구·권한 |

웹 예약이 PC 폴더를 자동 읽지는 않으므로 이번에는 같은 데스크톱 작업으로 돌아옵니다.

## 2단계: 일반 작업 먼저 실행

빈 practice-schedule에 아래 문서를 UTF-8로 만들고 데스크톱 프로젝트로 엽니다. daily라는 이름이 매일 실행하게 하는 것은 아니며 예약 설정이 빈도를 결정합니다. 고객 정보·키·운영 경로는 없습니다.

```markdown practice-schedule/daily-check.md
# Practice check
Revision: 1
- [x] Read the task instructions
- [ ] Review the practice report
```

```text 일반 입력창: 수동 읽기 먼저 검증
Read daily-check.md from this practice project once now.
Report its Revision, completed count and open count, using the current file contents.
If the file is missing or unreadable, report that exact limitation and stop.
Do not edit files, create a schedule, send messages elsewhere or call external services.
```

Revision 1·완료 1·미완료 1과 실제 읽기 활동을 확인하고 경로·결과·불변을 기록합니다. 일반 작업도 실패하면 경로·권한부터 수정하세요. 이는 동작 시험이며 시간 트리거·백그라운드 환경·알림 시험은 아닙니다.

## 3단계: 추적 가능한 예약 요청

```text 데스크톱: 만들 연습 예약이 맞을 때 전송
Create one recurring check named 'Practice list review' in this existing task.
Run every Monday at 09:00 in the Asia/Taipei time zone.
On each run, reread daily-check.md from this local practice project.
Report the current Revision, completed and open counts. Do not rely on an earlier report.
If the file or required access is unavailable, stop the run and report the limitation.
Keep the source file unchanged and do not contact external services.
Notify me on the first result, meaningful changes or failures; stay quiet when nothing changes.
Show the saved schedule and next run time so I can verify them.
```

Scheduled에서 저장 항목·Active·시간대·대상 프로젝트를 확인하세요. 대화상 약속은 생성 증거가 아닙니다. 월요일 9시 이후 생성하면 다음 주일 수 있으므로 오늘 실행을 가정하지 말고 다음 실행 표시를 봅니다.

즉시 실행이 제공되면 사용하고 없으면 관찰 가능한 가까운 시간으로 저장해 실제 트리거를 기다립니다. 같은 이름을 새로 하나 더 만들지 마세요. 식별 정보·다음 시간·실행 기록을 남겨 저장·시작·종료·결과를 구분합니다.

## 4단계: 매 실행 원본 재읽기 확인

첫 1/1 이후 원본을 직접 Revision 2·둘 다 완료로 바꿉니다. 새 2/0을 예약 요청에 넣지 말고 다음 실행이 파일 읽기로 얻는지 확인하세요. 답을 알려주고 반복시키는 검증과 구분합니다.

```markdown daily-check.md로 직접 저장할 두 번째 버전
# Practice check
Revision: 2
- [x] Read the task instructions
- [x] Review the practice report
```

같은 상태로 다시 실행해 무변경 알림 조건과 기록을 확인합니다. 푸시 없음이 미실행은 아니므로 OS·앱·예약 조건을 따로 봅니다. 같은 내용도 매주 받으려면 명시하고 항상 알림과 무변경 무알림을 동시에 요청하지 않습니다.

## 5단계: 수정·일시 중지·중지 범위

```text 같은 부모: 기존 예약 수정
Update the existing 'Practice list review' schedule to Wednesday at 10:00 Asia/Taipei.
Keep its task, project, read-only prompt and notification preference unchanged.
Show the updated next run time. Do not create a second schedule.
```

같은 항목의 새 시간과 중복 Active가 없는지 확인합니다. 동명은 프로젝트·요청·식별로 구분하세요. 출처·동작 변경은 일반 작업에서 먼저 재시험하고 요일·시간만 변경할 때는 관련 없는 기능을 재시험할 필요가 없습니다.

```text 실습 종료: 같은 예약 일시 중지
Pause the existing 'Practice list review' schedule after this practice.
Confirm it is Paused and show whether any run is already in progress.
If a run is in progress, report its state before stopping anything else.
```

Paused를 확인합니다. 미래 트리거 일시 중지가 이미 시작한 실행 취소는 아닐 수 있어 최근 실행도 확인하세요. 필요 없으면 제공되는 삭제 후 목록에서 사라졌는지 확인하며 이전 보고나 외부 변경이 복원됐다고 보지 않습니다. 같은 항목을 재개하고 다음 시간을 확인합니다.

## 흔한 문제와 실패 실습

미실행은 상태·시간대·다음 시간·전원·앱·프로젝트를 확인합니다. 절전 중 놓친 작업이 반드시 보충된다고 가정하지 말고 기록을 보세요. 파일 실패는 경로와 [권한](article:codex-permissions)을 확인하고 새 승인이 필요하면 해당 실패를 보고하며 백그라운드를 전면 허가로 해석하지 않습니다.

오류 실습 전에 일정을 일시 중지하고 아직 파일을 읽는 실행이 없는지 확인합니다. daily-check.saved.md가 이미 있으면 덮어쓰지 말고 다른 이름을 쓰세요. 자신의 daily-check.md를 바꾸고 원래 이름이 없는지 확인한 뒤 같은 읽기를 수동으로 시험합니다. 2/0 재사용이나 빈 목록 대신 파일 누락을 보고해야 합니다. 이름을 복원하고 Revision 2를 확인하세요. 이는 프롬프트의 누락 분기 시험이며 백그라운드 알림 시험은 아닙니다.

출처·시간대·저장 항목·실제 예약 결과·변경 후 읽기·수정 시간·Paused를 기록하고 미지원·미실행이면 부분 완료로 표시합니다. 이벤트 트리거는 별도 제한이 있어 시간 예약을 Gmail/Slack 감시로 보지 않습니다. 공식 확인이며 사용자 예약 생성이나 전 OS 실측을 주장하지 않고 다음은 [codex exec](article:codex-exec-scripting)입니다.
