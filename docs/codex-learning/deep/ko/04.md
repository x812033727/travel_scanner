## 이 글에서 완성할 것

> iPhone 또는 Android의 ChatGPT에서 자신의 Mac/Windows 컴퓨터에 연결하고 Codex 실습 작업을 열어 읽기 요청을 보냅니다. 결과가 올바른 호스트에서 왔는지 확인하는 것이 목표입니다. 읽기 약 12분, 최초 연결과 실습 약 20분입니다. 검증 가능한 Remote 흐름을 먼저 완성하고 클라우드와의 차이도 설명합니다.

휴대전화는 요청, 답변, 승인을 보내고 연결된 호스트가 파일, 터미널, 브라우저, 도구를 제공합니다. 작업이 보인다고 프로젝트가 휴대전화에 내려받아졌거나 컴퓨터를 꺼도 계속 실행되는 것은 아닙니다. 큰 수정을 요청하기 전에 작업 위치부터 구분합니다.

## 두 장치 모두 준비

컴퓨터에서 [데스크톱 입문](article:codex-desktop-getting-started)을 마치고 [할 일 자료](https://mokaair.com/guides/codex-first-project/todo-practice.zip)의 expected를 codex-practice로 복사해 엽니다. 파일 다섯 개가 있는지 확인합니다. GitHub나 별도 SSH 서버는 필요 없습니다.

iPhone은 App Store, Android는 Google Play에서 OpenAI의 ChatGPT를 설치하거나 업데이트합니다. 두 장치는 Codex를 사용할 수 있는 같은 계정과 워크스페이스를 사용해야 합니다. 조직의 Remote Control 허용, SSO, 다중 인증, 패스키가 필요할 수 있습니다. 작업을 여러 개 만들어 우회하지 말고 인증 조건부터 완료합니다.

2026-09-14 공식 Remote 문서는 iOS/Android를 모바일 진입점, Mac/Windows 데스크톱 앱을 호스트로 명시합니다. 기능은 순차 제공되며 Linux 미리보기도 이 호스트 흐름을 지원한다고 추정하면 안 됩니다. 최초 연결에서 데스크톱 앱을 CLI나 IDE 확장으로 대체할 수 없습니다.

## 1단계: 컴퓨터에서 연결 활성화

작업할 컴퓨터의 ChatGPT 데스크톱에서 Settings → Connections → Control this Mac or PC로 이동해 Set up 또는 Add를 선택합니다. 원격 접근을 활성화하고 인증을 마칩니다. 빈 테스트 컴퓨터를 연결해 자료를 찾지 못하는 일이 없도록 컴퓨터 이름과 프로젝트를 확인합니다.

표시되는 QR code는 휴대전화와 이 호스트를 연결합니다. 자신의 전화로 스캔하고 공개 튜토리얼 화면이나 다른 사람에게 공유하지 마세요. 호스트마다 연결이 필요하며 같은 계정에 로그인했다고 모든 장치가 연결된 것은 아닙니다.

Connections에서 다른 장치의 연결 허용과 사용 가능한 절전 방지 옵션을 확인합니다. 호스트는 앱이 열려 있고 온라인이며 깨어 있어야 합니다. Mac 노트북은 우선 전원을 연결하고 덮개를 열어 둡니다. Windows의 Computer Use에는 데스크톱 사용 가능 상태 등 추가 조건이 있습니다. 이번에는 파일만 읽으므로 모든 제어 기능을 활성화할 필요는 없습니다.

## 2단계: 휴대전화에서 연결 완료

iPhone 카메라로 QR code를 스캔하고 ChatGPT로 링크를 열어 Remote 설정을 진행합니다. 계정과 워크스페이스를 확인하세요. 브라우저에 머물면 최신 앱이 설치되어 있는지 확인한 뒤 호스트에서 다시 연결합니다. 웹 대화 기록 화면을 Remote 연결 성공 화면으로 오해하면 안 됩니다.

Android도 QR code를 스캔하고 ChatGPT로 열어 인증을 마칩니다. 연결 앱 선택창에서는 공식 ChatGPT를 선택합니다. Remote가 없으면 업데이트, 재실행, 기능 제공 여부를 확인합니다. 다른 모바일 브라우저로 바꾼다고 아직 제공되지 않은 기능을 사용할 수 있는 것은 아닙니다.

두 운영체제 모두 Remote에 호스트가 나타나고 선택할 수 있으며 그 프로젝트나 작업이 보여야 성공입니다. 알림은 완료나 주의 요청을 알려 주지만 실제 결과는 작업으로 돌아가 확인합니다. 알림만으로 파일 검증을 대신하지 마세요.

## 3단계: 읽기 전용 작업 실행

Remote에서 연결한 호스트를 선택하고 codex-practice의 Codex 작업을 엽니다. 새로 만들 때도 작업 위치가 호스트의 실습 폴더인지 확인합니다. 아래는 휴대전화 검색창이나 셸 명령이 아니라 작업 입력창에 붙입니다.

```text 휴대전화 ChatGPT → Remote → 호스트의 Codex 실습 작업
Read this practice project without changing files.
Report the host or environment name if available and the current working folder.
List index.html, style.css, app.js, core.mjs and core.test.mjs.
Explain how task completion is stored and name the localStorage key.
If you cannot inspect a file, report the limitation instead of guessing.
```

실습 경로, 저장 키 mokaair-codex-todo-v1, completed 필드가 소스에 근거해 설명되어야 합니다. 컴퓨터에서 app.js와 core.mjs를 대조하고 파일이 수정되지 않았는지 확인합니다. 일반적인 할 일 사이트 설명만 있고 경로나 코드 근거가 없으면 아직 완료가 아닙니다.

공백뿐인 항목을 거부하는 이유를 구체적인 파일과 함께 후속 질문합니다. 같은 작업과 문맥을 이어 가는지도 확인할 수 있습니다. 도구는 호스트가 제공하므로 휴대전화에 Node.js를 설치할 필요가 없습니다. 후속 글에서 테스트를 실행하기 전에 호스트에 런타임이 있는지 확인합니다.

```text 같은 모바일 Remote 작업, 후속 확인 질문
In the same project, explain what happens when the new task contains only spaces.
Identify the relevant function and file. Do not edit or reset stored data.
```

core.mjs의 addTask가 문자열을 정리하고 공백을 거부하며 폼에서 오류를 보여 준다는 설명이 예상됩니다. 컴퓨터 미리보기에서 공백을 직접 입력해 대조할 수 있습니다. 정상적인 읽기와 공백 거부라는 경계 사례 모두 비교 가능한 근거가 필요합니다.

## 연결이 끊겼을 때 상태 판단

읽기 작업이 끝난 뒤 호스트를 잠깐 오프라인으로 바꾸어 휴대전화의 연결 불가 상태를 관찰할 수 있습니다. 쓰기 중에 일부러 끊는 테스트는 하지 않습니다. 연결과 데스크톱 앱을 복구하고 원래 작업으로 돌아갑니다. 오프라인 표시는 지금 연결할 수 없다는 뜻이며 직전 작업이 실행되지 않았다는 증거는 아닙니다.

재연결 후에는 다시 보내기 전에 마지막 응답과 파일을 확인합니다. 생성, 삭제, 제출 요청을 반복하면 결과가 중복될 수 있습니다. 이 글은 읽기 요청으로 상태를 판단하는 방법을 익힌 뒤 쓰기로 넘어갑니다.

## Remote, 클라우드, 휴대전화 URL

Remote는 연결 호스트의 프로젝트와 도구를 사용하고 [클라우드 작업](article:codex-cloud-tasks-github)은 따로 설정한 환경을 사용합니다. 파일, 브랜치, 의존성이 다를 수 있으므로 제목이 비슷해도 같은 작업이라고 단정하지 않습니다. 휴대전화에서 웹사이트를 여는 것도 컴퓨터의 로컬 프로젝트 접근과 다릅니다.

컴퓨터의 http://127.0.0.1:4173에서 127.0.0.1은 그 컴퓨터입니다. 휴대전화에 같은 주소를 입력하면 전화 자신을 가리킵니다. 결과는 Remote 작업에서 호스트가 제공하는 미리보기나 화면으로 확인합니다. 이번 실습을 위해 공개 포트를 열 필요는 없습니다.

## 문제 해결과 연결 해제

호스트가 없으면 데스크톱 앱 실행, 연결 허용, 동일 계정과 워크스페이스, 깨어 있는 컴퓨터인지 차례로 확인합니다. 원인을 고친 뒤 다시 연결합니다. 오래 사용하지 않은 연결은 공식 안내에 따라 양쪽을 업데이트하고 다시 페어링합니다.

연결 요청이 없으면 휴대전화 Remote를 열고 호스트에서 설정을 재시작합니다. 조직 계정은 관리자가 Remote Control을 허용했는지 확인합니다. 로그인 성공과 조직 정책 허용은 다릅니다. 관리자에게 전달할 오류는 남기되 인증 코드는 포함하지 않습니다.

연결됐지만 파일이 없다면 호스트 이름과 작업 경로를 확인하고 그 컴퓨터에 프로젝트가 있는지 봅니다. 다른 컴퓨터의 같은 이름 폴더가 자동 동기화되지는 않습니다. 작업 이동에는 실제 환경과 Git 상태가 관련되므로 입문자는 원래 호스트에서 검증을 마칩니다.

더 이상 필요 없으면 호스트 Settings → Connections에서 원격 제어를 끄거나 사용하지 않는 연결을 제거합니다. 전화에서 더 이상 조작할 수 없는지 확인합니다. Remote를 끄는 것은 파일 복원이나 모든 작업 중지를 보장하지 않습니다. 실행 중인 작업은 먼저 작업 안에서 중지하고 상태를 확인하세요.


| 위치 | 제공 항목 | 확인 방법 |
| --- | --- | --- |
| 휴대전화 | 요청, 후속 질문, 승인 | 선택한 Remote 호스트와 작업 |
| Mac / Windows 호스트 | 파일과 로컬 도구 | 실제 경로와 파일 내용 |
| 클라우드 환경 | 별도로 설정한 코드와 의존성 | 클라우드 작업 환경과 브랜치 |

## 추가 실습과 검증 기록

휴대전화에서 작업 위치, 파일 목록, 실행하지 않은 검사를 정리하도록 요청한 다음 컴퓨터의 같은 작업에서 대조합니다. 같은 호스트와 경로를 가리키고 확인한 결과와 앞으로 할 제안을 구분할 수 있으면 성공입니다.

진입점, 연결, 호스트 조건은 2026-09-14에 [Remote connections 공식 문서](https://learn.chatgpt.com/docs/remote-connections)로 확인했습니다. 실제 iPhone/Android나 페어링을 실측하지 않았으며 그림은 관계를 설명합니다. 실습 사이트 동작은 별도 브라우저 검증이 있습니다. 다음은 [문맥 인계](article:codex-context-handoff), [권한](article:codex-permissions), [클라우드 작업](article:codex-cloud-tasks-github)을 참고하세요.
