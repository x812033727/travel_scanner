## 이 글에서 완성할 것

> 명령을 어디에 붙일지 모르는 상태에서 버전 확인, 세션 시작, 상태 보기, 계획 요청, 종료, 재개까지 진행합니다. 읽기 약 12분, 실습 약 20분입니다. 전체 흐름과 자주 쓰는 색인을 제공하며 모든 옵션을 외울 필요는 없습니다.

대상은 Codex CLI입니다. 데스크톱이나 ChatGPT 웹에도 슬래시 메뉴가 있지만 명령 집합은 다릅니다. Claude Code 명령, 옛 화면, 데스크톱 단축키를 CLI 문법으로 쓰지 말고 현재 인터페이스와 버전을 먼저 확인합니다.

## 시작 전 준비

[CLI 설치](article:codex-cli-getting-started)와 로그인을 마치고 [할 일 자료](https://mokaair.com/guides/codex-first-project/todo-practice.zip)의 expected를 codex-practice로 복사합니다. 주로 파일 읽기와 계획이므로 GitHub나 유료 외부 서비스는 필요 없습니다. codex를 찾지 못하면 먼저 설치를 해결하고 경로 문제와 인증 문제를 구분합니다.

Windows는 PowerShell, macOS는 Terminal, Linux/WSL은 해당 환경의 터미널을 실습 폴더에서 엽니다. WSL /home과 Windows C:\Users는 다른 경로입니다. 실제로 CLI가 설치된 환경에서 실행하고 위치부터 확인합니다.

## 네 가지 입력 구분

| 종류 | 입력 위치 | 예시 | 결과 |
| --- | --- | --- | --- |
| 셸 명령 | PowerShell / Terminal / Linux shell | codex --help | CLI를 실행해 도움말 표시 |
| 대화형 슬래시 명령 | Codex 시작 후 입력창 | /status | 현재 대화형 UI가 처리 |
| 단축키 | 이름을 입력하지 않고 키 누르기 | Ctrl+R | 프롬프트 기록 검색 |
| 자연어 요청 | Codex 대화 입력창 | Explain core.mjs without editing. | 에이전트가 해석하는 작업 요청 |

셸은 보통 경로와 프롬프트를 표시하고 Codex는 자체 대화 입력창이 있습니다. PowerShell의 /plan은 셸 명령이나 경로로 해석되어 Codex Plan 모드가 되지 않습니다. 반대로 설치 명령을 Codex 대화에 붙이면 직접 실행이 아닌 에이전트 실행 요청이 될 수 있습니다.

## 1단계: 버전과 도움말 확인

```text Windows PowerShell, macOS Terminal 또는 Linux shell, Codex 대화 밖
codex --version
codex --help
codex resume --help
```

한 줄씩 실행합니다. 버전, 하위 명령과 옵션, 재개 전용 도움말을 보여 주며 새 에이전트 작업은 시작하지 않습니다. 이번 Windows 확인 결과는 codex-cli 0.154.0-alpha.6.2입니다. 검증 환경 기록이며 이 미리보기 버전을 설치하라는 뜻은 아닙니다.

대괄호는 선택 인수, 꺾쇠괄호는 바꿔 넣을 값을 나타내는 경우가 많습니다. SESSION_ID 같은 자리표시자를 그대로 붙이거나 모든 옵션을 함께 넣지 마세요. 옵션이 없으면 철자, 하위 명령, 버전을 확인한 뒤 업데이트를 판단합니다.

## 2단계: 세션 시작과 상태 확인

```text 같은 시스템 터미널, codex-practice 안
codex
```

대화형 화면에서 /를 입력하고 목록에서 status를 찾아 /status를 실행합니다. 모델, 권한, 문맥 등 세션 설정이 나타나며 항목은 버전마다 다릅니다. 구매나 리셋 크레딧 사용 명령이 아닙니다.

```text Codex CLI 대화형 입력창, 상태 확인
/status
```

자연어로 작업 위치도 읽기 확인합니다. 다르면 세션을 나와 셸에서 올바른 폴더로 이동하고 다시 시작합니다. 모델 변경으로 작업 경로가 고쳐지지는 않습니다.

```text Codex CLI 대화, 실습 위치 확인
Report the current working directory and list the five Small Steps source files.
Do not edit anything. If this is not the practice folder, stop and explain.
```

## 3단계: Plan 모드로 계획 요청

[Plan 모드](article:codex-plan-mode)는 구현 전에 요구, 범위, 검증 방법을 확인합니다. 아래는 Clear completed 버튼 계획입니다. 미완료 항목을 보존하고 빈 목록도 고려해야 합니다. 이번에는 계획만 만듭니다.

```text Codex CLI 대화형 입력창, 슬래시 명령과 요청
/plan Plan a Clear completed button for this todo website. Do not implement it yet. Preserve active tasks and explain how to verify an empty list, mixed completion states, and reload behavior.
```

좋은 계획은 관련 파일, 버튼 위치, 데이터 처리, 저장 방식, 테스트 사례를 밝힙니다. 수정, 테스트, 완료만으로는 부족합니다. 존재하지 않는 React 컴포넌트나 데이터베이스를 가정하지 않는지 확인하고 결과를 판단할 수 있을 때까지 조건을 보완합니다. 나중에 구현할 때는 현재 UI의 모드 제어와 안내를 따릅니다. 계획이 있다고 사이트가 수정된 것은 아닙니다.

## 4단계: 종료 후 같은 세션 찾기

작업 이름이나 세션 정보를 기록하고 대화창에서 /quit를 실행합니다. 시스템 터미널로 돌아와 codex resume를 실행하고 선택기에서 시간, 내용, 경로를 확인합니다. 입문자는 마지막 세션이 목표라고 가정하는 것보다 직접 선택하는 편이 검증하기 쉽습니다.

```text Codex CLI 대화형 입력창, 현재 UI 종료
/quit
```

```text 시스템 터미널로 돌아온 뒤, 세션 선택기 열기
codex resume
```

codex resume --last는 현재 폴더의 최근 세션을 재개하며 --all은 검색 범위를 넓힙니다. 사용 전에 resume --help를 확인합니다. 재개 후 이전 계획과 남은 일을 요약하게 하고 경로도 확인합니다. 기능을 기억한다고 파일 위치까지 올바른 것은 아닙니다.

## 자주 쓰는 명령 색인

| 입력 | 인터페이스 | 목적과 이번 사용법 |
| --- | --- | --- |
| /model | CLI 대화 | 사용 가능한 모델과 추론 선택 확인, 취소 가능 |
| /permissions | CLI 대화 | 권한 확인과 조정, 읽기에는 권한 확대 불필요 |
| /review | CLI 대화 | 변경 검토, 지적도 검증 필요 |
| /compact | CLI 대화 | 긴 대화 요약, 전체 원문 기록은 아님 |
| /skills | CLI 대화 | 다음 글에서 쓸 스킬 찾기 |
| /copy | CLI 대화 | 최근 완료 답변 복사 |
| codex exec --help | 시스템 터미널 | 비대화형 옵션 확인 |
| Ctrl+R | CLI 단축키 | 기록 검색, Enter 선택, Esc 취소 |

[모델 선택](article:codex-model-selection), [권한](article:codex-permissions), [codex exec](article:codex-exec-scripting)에서 각 흐름을 다룹니다. /compact 전에는 정확한 재현이 필요한 오류와 완료 조건을 보존하고 [문맥 인계](article:codex-context-handoff)를 참고합니다. 목차는 /plan, AGENTS.md, resume 같은 검색어를 지원합니다.

## 검증, 문제 해결, 복원

정상 확인은 버전과 도움말이 보이고 위치가 맞으며 계획이 파일을 바꾸지 않고 같은 작업을 재개하는 것입니다. 경계 확인으로 / 메뉴에 없는 이름을 입력해 기대한 기능이 되지 않음을 확인합니다. 취소하고 문서를 찾아야 하며 권한 확대나 출처 불명 도구 설치로 해결하지 않습니다.

command not found 또는 Windows의 비슷한 오류는 셸이 codex를 찾지 못하는 상태입니다. 설치와 새 터미널 환경을 확인합니다. codex --help는 되는데 /plan만 안 되면 입력 인터페이스가 다른 경우가 많습니다.

인수를 거부하면 긴 조판용 대시 대신 일반 --를 사용하고 공백과 따옴표를 보존합니다. 주 명령의 옵션이 모든 하위 명령에서 지원되지는 않습니다.

재개 작업이 없거나 틀리면 다른 폴더, 호스트, CLI 환경에서 시작했는지 확인하고 선택기와 도움말을 봅니다. 기록 삭제로 해결하지 마세요. 이번에는 소스를 수정하지 않으므로 종료하면 끝나지만 대화 종료나 재시작이 이전 파일 작업을 취소하지는 않습니다.


그림의 01은 시스템 터미널, 02는 Codex 대화 입력, 03은 확인할 결과입니다.

## 추가 실습과 검증 기록

도움말, 상태, 읽기 요청, 재개의 네 줄 메모를 만들고 입력 위치와 예상 결과를 적어 각각 실행합니다. codex resume와 /resume의 인터페이스 차이를 설명하는 편이 많은 옵션을 외우는 것보다 실용적입니다.

2026-09-14에 [공식 CLI 명령 문서](https://learn.chatgpt.com/docs/developer-commands?surface=cli)와 로컬 --help로 확인했습니다. Windows에서는 버전, 주 명령 도움말, resume 도움말을 실행했습니다. 대화형 명령, 모델 메뉴, macOS/Linux는 공식 문서 확인이며 모두 실측한 것은 아닙니다. 다음은 [Skills](article:codex-skills)와 [테스트 및 리뷰](article:codex-testing-review)를 참고하세요.
