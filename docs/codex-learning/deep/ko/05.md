## 이 강의에서 할 수 있는 일

> 파일 준비, 설치와 로그인 확인, 올바른 폴더 읽기, 지정한 한 줄 수정, 종료와 원래 세션 찾기까지 검증 가능한 CLI 흐름을 연습합니다. 읽기 약 12분, 실습 약 25분이며 다운로드와 로그인 대기 시간은 별도입니다. 이 실습에는 GitHub, Node.js, 유료 외부 도구가 필요하지 않습니다.

CLI는 터미널에서 Codex를 사용하는 인터페이스입니다. 셸은 프로그램을 실행하고 Codex 입력창은 작업 요청을 받습니다. 둘 다 문자 중심이지만 입력을 해석하는 방식이 다릅니다. [터미널과 경로 기초](article:codex-terminal-paths)에서 현재 폴더를 확인할 수 있게 된 다음 진행하세요. 그림의 01은 실행 전 확인, 02는 세션, 03은 파일 검증입니다.

## 시작 전: 설치 방법 하나 선택하기

일반 사용자 계정으로 쓸 수 있는 연습 폴더를 실제 프로젝트와 별도로 준비합니다. 이용 자격, 로그인 방식, 사용량은 [계정과 사용량](article:codex-account-usage)에서 확인하세요. 프로그램 실행이 남은 사용량을 보장하지 않으며 로그인 성공이 모든 폴더 접근 권한을 주지도 않습니다.

| 환경 | 설치 경로 | 이 글로 돌아올 시점 |
| --- | --- | --- |
| Windows | 공식 PowerShell 독립 설치 프로그램, 기존 npm도 선택 가능 | 네이티브 PowerShell에서 버전 확인 후 |
| macOS | 공식 독립 설치 프로그램, 기존 Homebrew 사용자는 cask 선택 가능 | Terminal에서 버전 확인 후 |
| Linux / WSL2 | Linux 셸에서 공식 독립 설치 프로그램 사용 | 같은 Linux 환경에서 버전 확인 후 |

자세한 절차는 [Windows](article:codex-cli-windows), [macOS](article:codex-cli-macos), [Linux / WSL](article:codex-cli-linux-wsl)로 나뉩니다. 세 운영체제를 모두 설치하는 순서가 아니라 해당 환경 하나를 고르는 경로입니다. 글이 아직 공개되지 않았다면 아래 공식 CLI 설치 페이지에서 플랫폼을 선택해 설치하고 터미널을 다시 연 후 다음을 확인하세요. 비교만을 위해 모든 배포 방식을 함께 설치하지 마세요.

```text 시스템 터미널: 작업을 시작하지 않고 버전과 도움말 확인
codex --version
codex --help
```

두 줄은 운영체제 셸에 입력합니다. 버전과 도움말이 나온 뒤 셸 프롬프트로 돌아오며 모델 작업은 아직 시작되지 않습니다. codex를 찾지 못하면 로그인 전에 설치부터 해결하세요. 설치 버전이 글보다 새로워도 괜찮습니다. 검증에 사용한 미리 보기 버전을 설치하기보다 로컬 help와 공식 문서로 옵션을 비교하세요.

## 1단계: 식별 가능한 연습 파일 만들기

일반 텍스트 편집기로 아래 내용의 greeting.txt를 만들고 greeting.original.txt 사본도 저장합니다. 두 파일은 새로운 codex-cli-lab 폴더에 둡니다. 확장자가 .txt.txt가 되지 않았는지, 워드 문서 형식이 아닌지 확인하세요. 둘째 줄은 실제 실습 파일인지 구분하는 고정 표식이며 사본은 수정 전후 비교용입니다.

```text 파일 내용: greeting.txt에 붙여 넣고 원본 사본 저장
Hello, traveler.
Lesson marker: CLI-START-01
```

Windows에서는 탐색기로 폴더를 열고 터미널에서 열기를 선택한 뒤 PowerShell에서 Get-Location과 Get-ChildItem을 실행합니다. macOS/Linux에서는 cd 뒤에 폴더의 전체 경로를 따옴표로 넣어 이동한 다음 pwd와 ls를 실행합니다. 두 파일이 보여야 합니다. 아직 홈이나 다운로드 폴더라면 먼저 이동하세요. 익숙한 파일명만으로 위치를 판단하면 안 됩니다.

## 2단계: 로그인하고 읽기 전용 세션 시작하기

```text 시스템 터미널: 한 줄이 완료된 후 다음 줄 실행
codex login
codex login status
codex --sandbox read-only
```

앞선 명령이 끝난 다음 셸에서 한 줄씩 실행합니다. login의 브라우저 안내에서 의도한 계정과 워크스페이스를 선택합니다. login status는 인증 정보 확인이며 남은 사용량, 연결, 모델 요청 성공을 보장하지 않습니다. 마지막 줄은 읽기 전용 샌드박스로 대화 화면을 엽니다. 폴더 신뢰나 샌드박스 설정이 나타나면 경로와 설명을 확인한 뒤 실습에 맞는 설정을 선택하세요.

아래 /status는 Codex 입력창에서만 실행합니다. 해당 버전에 표시되는 작업 폴더, 모델, 권한을 확인하세요. PowerShell에 붙여 넣지 마세요. read-only는 샌드박스 정책이며 네트워크와 모든 외부 도구가 일괄 비활성화된다는 보장은 아닙니다. 외부 도구에는 각자의 권한 제어가 적용됩니다. 실습은 로컬 텍스트 파일만 사용합니다.

```text 대화형 슬래시 명령: Codex CLI 입력란에서 실행
/status
```

```text 자연어 요청: 읽기 전용 Codex 세션에 입력
Read greeting.txt in the current folder. Report the working directory and both lines exactly. Do not edit files, use external services, or infer missing content. If the file is missing, stop and report that.
```

이 문장은 Codex 대화에 넣는 자연어 작업입니다. 응답이 원문 두 줄과 현재 폴더에 일치해야 하며 실제로 읽었는지 파일 읽기 도구 기록도 확인합니다. 파일이 없으면 수정 요청을 중단합니다. 파일은 있지만 접근에 실패했다면 오류와 범위를 기록하고 [권한 설명](article:codex-permissions)을 확인하세요.

## 3단계: 지정한 한 줄만 수정하기

Codex에서 /exit를 입력하고 셸로 돌아오면 같은 연습 폴더에서 아래 쓰기 가능한 세션을 시작합니다. 읽기와 쓰기를 나눠 권한 변화를 확인하는 연습입니다. 한 줄을 바꾸기 위해 디스크 전체 접근 권한이 필요하지는 않습니다. 조직 정책이 이 모드를 허용하지 않으면 읽기 결과를 보관하고 관리 설정을 확인하세요.

```text 시스템 터미널: Codex 종료 후 쓰기 가능한 세션 시작
codex --sandbox workspace-write --ask-for-approval on-request
```

```text 자연어 요청: 쓰기 가능한 세션에 입력
In greeting.txt, replace only the first line with: Hello, Codex learner.
Preserve the lesson marker and greeting.original.txt. Do not create other project files.
Read the file after editing and report the exact before/after change.
```

첫 블록은 실행 명령이고 둘째는 Codex 안에서 보내는 요청입니다. 제안된 명령과 변경 내용을 검토합니다. 사본이 바뀌거나 파일이 추가되면 범위 이탈을 알리고 수정 후 다시 읽게 하세요. 첫 줄은 Hello, Codex learner.로 바뀌고 표식과 사본은 그대로여야 성공입니다. 완료 메시지만으로 판정하지 마세요.

## 4단계: 종료, 검증, 재개

다시 종료하고 편집기로 두 파일을 독립적으로 비교합니다. 없는 파일도 시험하세요. Codex에 greeting-missing.txt를 읽되 없으면 생성하지 말고 보고하라고 요청합니다. 파일이 없다는 명확한 결과와 기존 두 파일이 그대로인 것을 확인합니다. 파일명으로 내용을 추측하는 응답과 실제 확인을 구분할 수 있습니다.

종료 후 셸에서 codex resume를 실행하고 시간, 내용, 폴더로 이번 세션을 찾습니다. 가장 최근 항목이라고 가정하지 마세요. 변경과 남은 작업을 요약하게 한 다음 greeting.txt도 다시 읽습니다. 대화 재개는 디스크를 당시 상태로 복구하지 않습니다. 외부 편집이 있었다면 현재 파일을 기준으로 확인하세요.

```text 시스템 터미널: 실습 디렉터리에서 재개 목록 열기
codex resume
```

재개 후 상태를 확인하세요. 대화에는 첫 줄을 고쳤다고 남아 있어도 greeting.txt를 백업으로 복원했다면 다시 읽은 결과는 Hello, traveler.여야 합니다. 이전 수정을 다시 적용하지 말고 읽기와 비교만 하라고 명시하세요. 새 대화, 종료, 재개는 대화를 관리하며 파일 복구에는 별도 작업과 확인이 필요합니다. 분기나 다른 디렉터리 검색은 [세션](article:codex-sessions-resume)을 참고하세요.

다시 실습하려면 종료 후 원본 사본의 두 줄을 greeting.txt에 복사하고 일치 여부를 확인합니다. 연습 파일만 복구하면 되며 Codex 설정이나 모든 세션을 삭제할 필요는 없습니다. 업데이트도 선택한 설치 경로를 사용하고 새 터미널에서 버전을 확인합니다. 나중에 설치 경로를 바꿀 때 중복 설치를 점검하세요.

## 문제 해결과 완료 확인

명령을 찾지 못하면 셸을 확인하고 다시 연 뒤 플랫폼별 PATH를 점검합니다. 브라우저 로그인 후 대기 중이면 같은 로그인 시도와 로컬 복귀 흐름인지 확인하고 URL이나 코드는 공개하지 마세요. 로그인 후 전송 실패는 사용량, 조직 정책, 네트워크 오류로 나눕니다. 수정이 차단되면 재설치 전에 읽기 전용 세션인지 확인하세요.

버전 기록, 올바른 폴더와 읽기 증거, 한 줄 변경 파일, 온전한 사본, 없는 파일 보고, 재개 가능한 세션을 남깁니다. 다음은 [명령](article:codex-commands)과 [AGENTS.md](article:codex-agents-md)에서 프로젝트 규칙을 추가하세요. 로컬 Windows 검증은 버전/help와 실습 파일 비교 방법입니다. 설치, 계정, 대화형 모델 단계는 공식 문서로 확인했으며 macOS/Linux를 직접 시험했다고 주장하지 않습니다.
