## 목표와 준비

> 한 로컬 프로젝트에서 두 결과의 작업을 관리하며 이름, 전환, 고정, 보관, 복원을 연습합니다. 목록이 별개여도 파일은 격리되지 않음을 확인합니다. 읽기 12분, 실습 20분입니다. 로그인한 데스크톱과 편집기를 쓰며 OS별 조작은 공식 확인으로 전체 실측은 아닙니다.

[데스크톱 기초](article:codex-desktop-getting-started)가 전제입니다. 프로젝트는 공유 파일/작업을 정리하고 작업은 개별 결과/대화를 가집니다. ‘실습 목록’, ‘변경안’처럼 이름을 붙입니다. ChatGPT 프로젝트와 로컬 폴더 연결은 다르며 이번에는 후자인지 확인합니다.

## 1단계: 실습 폴더 연결

codex-project-lab에 다음 별도 note.txt/request.txt를 만듭니다. 기초 절차로 로컬 프로젝트에 추가하고 Edit project에서 경로를 확인합니다. 사용자 전체가 아닌 실습 하나만 연결하고 기본 폴더/실제 경로를 확인해 작업을 만듭니다.

```text
PROJECT-LAB
Revision: 1
Current title: Small Steps
```

```text
Propose the title Daily Steps.
Do not edit note.txt until the proposal is reviewed.
```

기본 폴더는 시작점/설정 탐색에 쓰이고 추가 폴더도 읽고 쓸 수 있습니다. 격리 사본은 아닙니다. 실습은 Git/worktree 없이 공유를 확인합니다. 동시 편집에는 [worktree](article:codex-worktrees)를 사용하고 작업 개수로 격리를 판단하지 않습니다.

## 2단계: 결과가 다른 작업 두 개 만들기

첫 작업에 목록 요청을 보내 두 파일/표식/버전 1을 확인하고 ‘PROJECT-LAB — 실습 목록’으로 이름을 바꿉니다. 메뉴로 공통 표식/결과를 남기면 표식만 기억해도 찾습니다. 읽기만 하며 새 문서는 필요 없습니다.

```text
Inventory this practice folder. Read note.txt and request.txt. Report their filenames, the lab marker, revision and current title. Do not edit files or search other directories. This task's outcome is a verified inventory only.
```

같은 프로젝트에서 다음 제안 작업을 만들고 ‘PROJECT-LAB — 제목안’으로 이름을 정합니다. Small Steps를 Daily Steps로 바꾸는 note.txt 한 줄 제안이며 아직 편집하지 않습니다. 목록 작업으로 돌아오면 그 대화가 남고 두 기록이 섞이지 않아야 합니다.

```text
Read note.txt and request.txt. Propose the smallest title change that satisfies the request. Identify exactly which line would change and how to verify it. Do not implement yet; this task's outcome is a reviewable proposal.
```

## 3단계: 작업 전환 시 파일 다시 읽기

작업 사이 다른 일을 했다고 가정해 note.txt 버전만 2로 바꾸고 제목/request.txt는 둡니다. 목록에서 새 읽기를 요청해 이전 대화의 1과 현재 2를 확인합니다. 제안 작업에도 다시 읽게 하여 같은 폴더의 2를 보는지 확인합니다.

```text
Read note.txt from disk again now. Compare its current revision with this task's earlier record. Report the actual directory, current revision and unchanged title. Do not repair the mismatch by restoring old contents.
```

불일치는 의도적이며 복원 요청이 아닙니다. 파일 공유와 대화 분리는 함께 가능하고 고정/이름 변경이 사본을 만들지 않습니다. 한쪽이 1이면 경로/호스트/새 읽기/다른 worktree를 확인합니다. 긴 작업은 [인계](article:codex-context-handoff)에 버전 차이를 남깁니다.

## 4단계: 고정, 검색, 보관과 복원

자주 쓰는 제목안을 고정하고 다른 작업 뒤에도 찾기 쉬운지 확인합니다. 대화/파일은 바뀌지 않습니다. 사이드바 Search chats에서 PROJECT-LAB을 검색해 전체 이름으로 구분합니다. 버전별 단축키 차이를 피해 보이는 진입점을 씁니다.

목록 작업만 메뉴 Archive로 보관하고 프로젝트 전체 Archive chats를 피합니다. Settings의 Archived chats에서 복원해 대화와 버전 2를 확인합니다. 목록 정리이며 기능 검수/백업/디스크 정리가 아닙니다. Delete는 필요 없습니다.

| 조작 | 바뀌는 것 | 검증 |
| --- | --- | --- |
| 이름 변경 | 표시 제목 | 표식/결과로 검색 |
| 고정 | 사이드바 위치 | 같은 대화로 돌아오기 |
| 보관/복원 | 목록 표시 상태 | 원래 대화 유지 |
| 다시 읽기 | 최신 디스크 증거 | 둘 다 버전 2 |
| 기본 폴더 변경 | 새 작업 시작점 | 실제 경로 재확인 |

## 재개, 새 시작, 중단 구분

같은 제목 변경의 조건 보완은 원래 작업으로 돌아가고 테스트 기록 정리 같은 다른 결과는 읽을 파일을 지정해 새로 만듭니다. 다른 대화의 구두 제약을 읽었다고 가정하지 않습니다. 테스트 불변 같은 공통 규칙은 AGENTS.md, 버전/미확인은 인계에 두고 새 요청에서 참조합니다.

실행 중이면 표시된 중단 조작을 먼저 쓰고 추가 편집이 멈췄는지 확인해 정리합니다. 중단/보관은 다르며 이미 쓴 것은 복원되지 않아 다시 읽습니다. 기본 경로 변경은 이전 위치를 기록하고 새 작업으로 확인하며 기존 작업 이동/추가 폴더 백업을 가정하지 않습니다.

## 문제 해결과 정리 습관

없으면 다른 프로젝트/호스트/보관/표식 검색을 확인하고 같은 이름을 여러 개 만들지 않습니다. 둘 다 같은 파일을 바꾸려면 하나를 읽기로 두고 다른 수정 뒤 검토하게 합니다. 실제 동시 기능 개발은 worktree/통합으로 진행합니다.

커지면 ‘필터: Completed 완성’, ‘문서: 시작 절차’처럼 결과/범위를 넣습니다. 변경/검증/남은 작업을 남기고 미완료는 대화뿐 아니라 목록 문서에도 저장합니다. 전환마다 전체를 다시 설명하거나 보관을 미완료 없음으로 오해하지 않게 합니다.

두 이름 있는 작업, 버전 2 재읽기, 보관/복원 결과를 남깁니다. 마지막으로 버전 1과 Small Steps를 확인하고 고정을 해제하며 삭제는 필요 없습니다. 그림 1은 범위, 2는 결과별 작업, 3은 재확인/정리입니다. 다음은 [기존 코드 읽기](article:codex-understand-codebase)입니다.
