## 목표와 사용법

> 관측 증상에서 최소 확인을 하고 모든 도구 재설치 대신 해당 심화 편으로 이동합니다. 읽기 15분, 경로 실습 20분이며 실제 장애 처리는 별도입니다. OS·모바일 진입점을 구분해 어디서 발생했는지 먼저 확인하세요. 독립 진단 시작점이자 전체 시리즈 문제 해결 색인입니다.

도식의 01은 증상 기록, 02는 최소 확인 하나, 03은 원인 수정 후 원래 동작 반복입니다. 오류마다 바로 재시도하지 말고 입력·상태·사용 가능한 환경을 보존한 뒤 문제를 좁힙니다.

## 먼저: 증상과 마지막 성공 동작 기록

시간·플랫폼·버전·현재 폴더·정확한 명령/동작·예상·오류 원문을 기록합니다. 관련 정보만 공유하고 계정·비공개 경로·키를 가리세요. 설치 후 명령이 없으면 설치 결과, 다른 run이 활동하면 작업 이름·호스트를 보존합니다. 빨간 글씨만 잘라내지 말고 직전 명령·위치를 포함해야 다음 판단에 도움이 됩니다.

```markdown issue-notes.md 서식
# Troubleshooting record
- Time and timezone:
- Surface: desktop / CLI / IDE / mobile / web
- OS and app or CLI version:
- Working folder or execution host (redacted if shared):
- Exact command or UI action:
- Expected result:
- Actual error and exit status:
- Last successful action:
- One change attempted:
- Result after that change:
- Files or settings to restore:
```

## 설치·로그인·플랫폼 진입점

| 증상 | 최소 확인 | 상세 |
| --- | --- | --- |
| codex 없음 | 터미널 재열기·실행 파일 위치 | [CLI 설치](article:codex-cli-getting-started) |
| PowerShell 차단 | 차단 파일명·호출법 기록 | [Windows CLI](article:codex-cli-windows) |
| macOS/Linux 설치 위치 다름 | shell·PATH·실행 파일 구분 | [macOS](article:codex-cli-macos), [Linux/WSL](article:codex-cli-linux-wsl) |
| 로그인 후 권한 없음 | 같은 터미널의 codex login status | [계정·사용량](article:codex-account-usage) |
| 데스크톱·모바일 조작 없음 | 버전·계정·워크스페이스·진입점 기록 | [플랫폼 선택](article:codex-platforms-guide) |

같은 PC의 Windows·WSL·컨테이너·원격도 인증·설정을 공유하지 않을 수 있으므로 실패 환경을 식별합니다.

Windows는 Get-Command codex, macOS/Linux는 command -v codex로 실행 파일을 확인합니다. 여러 설치는 기록하고 바로 버전을 지우거나 전체 보안 정책을 바꾸지 않습니다. ChatGPT 인증·API 키·조직 제한을 구분하며 재설치는 한도를 늘리지 않습니다. 서비스 장애는 공식 상태 페이지의 시간·대상을 비교하고 전체 정상이어도 자신의 네트워크·권한 정상으로 단정하지 않습니다.

## 재현 실습: 올바른 폴더 찾기

새 path-trouble에 빈 project·other를 만들고 project에만 아래 marker.md를 둡니다. other에서 터미널을 열어 일부러 marker.md를 읽어 파일 누락을 재현하세요. Codex·운영 변경은 필요 없습니다. 현재 위치·목록을 확인하고 명시한 상대 경로로 읽은 뒤 project로 cd해 원래 읽기를 반복합니다.

```markdown project/marker.md
# Correct folder: PATH-PRACTICE-1
```

```powershell Windows: other에서 시작
Get-Content -LiteralPath .\marker.md
Get-Location
Get-ChildItem
Get-Content -LiteralPath ..\project\marker.md
Set-Location -LiteralPath ..\project
Get-Content -LiteralPath .\marker.md
```

```sh macOS / Linux: other에서 시작
cat ./marker.md
pwd
ls
cat ../project/marker.md
cd ../project
cat ./marker.md
```

처음은 실패하고 뒤 두 번은 같은 PATH-PRACTICE-1이며 내용을 고친 것이 아니라 위치를 고쳤음을 확인합니다. 원래 위치로 돌아가고 자료는 보관하며 재귀 삭제는 필요 없습니다. Codex에서도 작업 루트·지정 파일 존재부터 확인해 잘못 연 프로젝트인지 판단하세요. 같은 이름 작업·다른 worktree·휴대전화의 오래된 내용이 같은 폴더의 증거는 아닙니다.

PowerShell cmdlet인 Get-Content는 $?를 즉시 저장합니다. $LASTEXITCODE는 주로 codex·node 같은 네이티브 프로그램용입니다. 경로 실습을 마치면 project에 있어야 하며 아래는 없는 other/marker.md, 실제 marker 순서로 읽습니다. PowerShell은 False·True, shell은 0이 아닌 값·0이 나와야 합니다. 다른 명령이 상태를 덮기 전에 저장하세요.

```powershell Windows PowerShell: 현재 project
Get-Content -LiteralPath ..\other\marker.md
$practiceReadOk = $?
$practiceReadOk
Get-Content -LiteralPath .\marker.md
$practiceReadOk = $?
$practiceReadOk
```

```sh macOS/Linux shell: 현재 project
cat ../other/marker.md
practice_read_exit=$?
printf '%s\n' "$practice_read_exit"
cat ./marker.md
practice_read_exit=$?
printf '%s\n' "$practice_read_exit"
```

정확한 정의는 [PowerShell 자동 변수](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_automatic_variables)를 참고하세요. 두 읽기는 marker를 바꾸지 않습니다. 예상 밖 편집은 별도로 조사해 경로 수정과 파일 원문 보존을 나누어 인계합니다.

## 문제 해결을 마치고 작업 복귀

수정 후 원래 실패 동작과 인접 동작을 검증합니다. Completed 수정 후 Active, 설정 수정 후 이전 정상 항목, MCP 재연결 후 초록 아이콘뿐 아니라 가상 문서 실제 읽기입니다. 증상·원인·단일 수정·검증을 issue-notes.md에 적고 인계에는 최소 입력·시도 절차를 제공합니다. 미해결이면 그대로 기록하고 사용 가능한 상태·다음 증거를 보존하세요.

자신의 임시 표식·설정을 되돌리고 필요한 수정·백업·기록은 유지합니다. 문제 해결을 이유로 전체 설정 삭제·세션 제거·민감 내용 공개를 하지 않습니다. 색인을 처음부터 모두 수행하지 말고 증상에 맞는 한 행을 고르세요. 각 편 위아래에서 [학습 목차](article:codex-learning-hub)로 돌아가 기능·명령·MD 이름으로 다음을 찾습니다. 플랫폼 미지원·미개방은 설치 장애와 구분합니다.
