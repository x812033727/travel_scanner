[Codex 학습 목차로 돌아가기](article:codex-learning-hub)

## 이 강의에서 할 수 있게 되는 일

> Codex, 모델, 작업, 실행 환경을 구분하고 파일 두 개로 읽기, 수정, 직접 확인하기를 연습합니다. 읽기 약 10분, 실습 약 15분입니다. 프로그래밍 경험은 필요 없으며 이 실습에서 사이트를 배포하지는 않습니다.

## 네 가지 역할 이해하기

Codex는 필요한 도구와 권한이 주어지면 파일을 읽고 수정하며 명령을 실행하는 에이전트입니다. 모델은 추론을, 작업은 요청과 대화 기록을, 환경은 접근 가능한 파일과 도구를 담당합니다. 더 강력한 모델을 선택해도 잘못 연 폴더가 자동으로 바뀌지는 않습니다. 도움을 요청할 때는 사용 화면, 작업 경로, 이용 가능한 도구부터 확인하세요.

ChatGPT와의 차이를 앱 이름만으로 판단하면 안 됩니다. 현재 공식 데스크톱 문서는 ChatGPT 데스크톱 앱에서의 Codex 작업을 설명합니다. 현재 대화에 프로젝트가 연결되어 있는지, 도구를 실행할 수 있는지, 결과가 답변인지 실제 파일 변경인지 확인하세요. 일반 채팅에도 도구가 있을 수 있고 Codex도 분석만 가능한 환경일 수 있습니다. 오래된 아이콘보다 이번 작업의 실제 기능을 기준으로 판단합니다.

로컬 작업은 선택한 컴퓨터의 폴더를, 클라우드 작업은 별도로 구성한 환경을 사용합니다. 프로젝트 이름이 같아도 커밋하지 않은 파일까지 자동 동기화되지는 않습니다. 휴대전화 원격 작업에는 연결 가능한 호스트도 필요합니다. 방식 비교는 [플랫폼 선택](article:codex-platforms-guide)을 참고하세요. 이번에는 결과를 쉽게 확인할 수 있도록 데스크톱 또는 CLI의 로컬 폴더를 사용합니다.

### 먼저 판단하기: 요청에 어떤 기능이 필요한가요

작업을 실행하지 않고 세 상황을 구분해 보세요. ① 열 줄을 붙여 넣고 설명을 요청합니다. ② 컴퓨터의 packing.txt를 수정하여 대화를 닫은 뒤에도 파일에서 결과를 확인하고 싶습니다. ③ 설정된 GitHub 저장소 환경에서 수정한 뒤 나중에 차이를 검토하고 싶습니다. 각 상황에는 제공한 텍스트 읽기, 로컬 파일 접근, 지정한 원격 환경 접근 중 무엇이 필요한가요?

정답은 다음과 같습니다. ① 제공한 텍스트만으로 충분하며 폴더 전체에 접근할 필요는 없습니다. ② 올바른 로컬 폴더를 선택하고 도구가 읽고 쓸 수 있는지 확인해야 합니다. 수정된 글을 답변으로 받았다는 사실만으로 파일이 바뀌었다고 볼 수는 없습니다. ③ 원격 저장소와 환경을 설정하고 선택해야 하며 커밋하지 않은 로컬 파일을 읽었다고 가정하면 안 됩니다. 두 번째는 [데스크톱 입문](article:codex-desktop-getting-started), 세 번째는 [클라우드 작업](article:codex-cloud-tasks-github)으로 이어집니다. 지금 세 방식을 모두 설정할 필요는 없습니다.

## 독립된 실습 폴더 준비하기

먼저 Codex에 로그인할 수 있는지 확인하세요. 설치 전이라면 [데스크톱 설정](article:codex-desktop-getting-started) 또는 [CLI 입문](article:codex-cli-getting-started)을 진행합니다. 이번에는 일반 텍스트 편집기와 터미널만 필요하며 GitHub, API 키, Node.js, Python은 필요 없습니다. 파일 관리자에서 문서 폴더에 codex-orientation을 새로 만드세요. 같은 이름이 있으면 다른 이름을 선택해 기존 작업을 보존합니다.

Windows에서는 확장자를 표시하고 메모장에서 파일 형식은 모든 파일, 인코딩은 UTF-8로 저장합니다. macOS에서는 RTF가 아닌 일반 텍스트 모드를 사용합니다. Linux에서도 텍스트 편집기를 쓰고 파일 이름의 대소문자를 유지하세요. 새 폴더에 아래 두 파일을 완성된 내용 그대로 만듭니다. 확장자는 .md와 .txt이며 예제 바깥의 파일 이름은 본문에 넣지 않습니다.

첫 파일은 codex-orientation/README.md입니다. 사람을 위한 프로젝트 설명이며 .md 확장자만으로 자동 적용되는 에이전트 규칙이 되지는 않습니다.

```markdown 파일 내용: README.md에 붙여 넣기
# Orientation exercise

This folder contains a fictional packing list.
The list has exactly three items.
No website or package installation is required.
```

둘째 파일은 codex-orientation/packing.txt입니다. 항목마다 한 줄씩 쓰며 마지막 줄 뒤에 줄바꿈이 있어도 됩니다.

```text 파일 내용: packing.txt에 붙여 넣기
Notebook
Bottle
Umbrella
```

## 1단계: 폴더를 선택하고 읽기만 요청하기

데스크톱에서는 codex-orientation을 프로젝트로 추가한 뒤 작업을 만듭니다. CLI에서는 이 폴더에서 터미널을 열고 codex를 실행합니다. 문서 폴더 전체를 열면 관련 없는 파일까지 작업 대상이 될 수 있으므로 실습 폴더로 좁힌 뒤 아래 요청을 입력하세요. 영어 입력 예제는 결과 비교를 위해 모든 번역에서 동일하며 같은 내용을 자신의 언어로 요청해도 됩니다.

```text 자연어 요청: Codex 작업 입력란에 붙여 넣기
Inspect this practice folder without changing files.
Report the working directory, list the files, and read README.md and packing.txt.
Explain what this project contains. Cite the filenames supporting your answer.
If a requested file is missing, say so instead of guessing.
```

예상 결과에는 파일 두 개, 물품 세 개, 실행할 웹사이트가 아니라는 설명이 포함됩니다. 파일 관리자에서 경로와 내용을 비교하세요. 표현이 완전히 같을 필요는 없지만 원문에 없는 사실을 추가하면 안 됩니다. 실행할 명령을 제안하기만 한다면 이 화면에 파일 도구가 있는지 확인하세요. 방법을 설명한 답변과 실제 실행은 다릅니다.

## 2단계: 확인 가능한 변경 하나 요청하기

```text 자연어 요청: 같은 Codex 작업에 붙여 넣기
In packing.txt, replace the line Umbrella with Raincoat.
Preserve the other two lines and leave README.md unchanged.
Do not add files, install tools, or run a website.
After editing, read packing.txt and report exactly what changed.
```

해당 파일 수정을 허용한 뒤 packing.txt를 다시 엽니다. Notebook, Bottle, Raincoat의 세 줄이어야 하며 README.md는 그대로이고 추가 패키지나 파일이 없어야 합니다. 도구가 폴더 밖의 접근 권한을 요구하면 이유를 확인하고 범위를 좁히세요. 이 실습에는 컴퓨터 전체 접근이 필요 없습니다. 실제 제어 방법은 [권한과 샌드박스](article:codex-permissions)를 참고합니다.

## 3단계: 실패 처리와 복원 확인하기

다음으로 missing.txt를 읽기만 하고 파일이 없으면 설명하되 만들지 말라고 요청합니다. 정상 결과는 파일이 없다는 보고이며 기존 두 파일은 그대로 남습니다. 오류를 만들기 위해 파일을 지우지 않고도 근거가 없을 때 추측하는지 확인할 수 있습니다. 내용을 지어냈다면 폴더를 다시 확인하고 근거 없는 문장을 수정하도록 요청하세요.

복원하려면 편집기에서 Raincoat를 Umbrella로 되돌리고 저장한 뒤 다시 읽습니다. 프로젝트 전체를 초기화하거나 문서 폴더를 삭제할 필요는 없습니다. 실행 중인 작업을 중단해도 이미 기록된 내용은 직접 확인하고 복원해야 합니다. 대화를 닫는다고 파일 변경이 취소되지는 않습니다. [Git](article:codex-git-basics)을 배우기 전부터 이 습관을 들이세요.

## 문제 해결과 추가 연습

내용이 다르면 같은 이름의 다른 폴더를 열었거나 편집 내용을 저장하지 않았는지 먼저 확인합니다. 모델을 반복해서 바꾸지 마세요. README.md를 못 찾으면 전체 이름을 표시해 README.md.txt, 서식 있는 텍스트, 대소문자 차이를 확인합니다. 이전 대화만 보인다면 연결된 컴퓨터와 프로젝트부터 확인하고 클라우드가 방금 만든 로컬 파일을 볼 수 있다고 가정하지 않습니다.

이번에는 직접 Bottle을 Cup으로 바꾸되 순서와 줄 수를 유지하고 다시 복원하세요. 데이터 위치, 실제 수정 파일, 세 줄의 내용, 실행하지 않은 작업을 설명할 수 있으면 완료입니다. 다음으로 [첫 프로젝트](article:codex-first-project)와 [요청 작성](article:codex-prompting)을 읽고 미리 볼 수 있는 웹사이트에 같은 검증 방법을 적용합니다.

화면 및 제품 명칭은 2026-09-14의 [공식 데스크톱 문서](https://learn.chatgpt.com/docs/app)와 [CLI 문서](https://learn.chatgpt.com/docs/codex/cli)로 확인했습니다. 직접 만든 텍스트 파일 실습이며 도구와 답변은 환경마다 다릅니다. 운영체제별 편집 안내를 세 운영체제에서 Codex를 직접 테스트한 결과로 제시하지 않습니다.

| 역할 | 이번 실습에서의 의미 |
| --- | --- |
| 에이전트 | 도구로 작업 수행 |
| 모델 | 이해와 추론 |
| 작업 | 이번 요청과 대화 |
| 환경 | 이용 가능한 파일과 도구 |

그림의 01은 작업 요청, 02는 실행 환경, 03은 검증 가능한 파일 결과입니다. 세 가지를 맞춰 작업 위치를 확인합니다.
