## 목표와 준비

> 새 CLI 세션 세 개에서 루트, 하위 폴더, override를 비교해 규칙이 적용되지 않는 이유를 구분합니다. 읽기 12분, 실습 25분입니다. CLI/AGENTS.md 기초, Git, 편집기, Codex 인증이 필요합니다. 규칙 내용은 세 OS가 같고 경로 확인 명령은 셸에 따라 다릅니다.

[AGENTS.md](article:codex-agents-md)는 작업 지침, [config.toml](article:codex-config-toml)은 다른 우선순위의 앱 설정입니다. 권한을 넓히지 않고 응답 표식과 공통 요구를 관찰합니다. 파일을 인용할 수 있다는 것만으로 시작 시 발견된 증거는 아니므로 동작과 작업 경로도 확인합니다.

## 로드 순서 이해

전역은 기본 사용자 .codex 또는 기존 CODEX_HOME 위치입니다. 프로젝트는 인식된 루트에서 현재 경로까지 탐색하며 모든 형제 폴더를 훑지 않습니다. 각 층에서 AGENTS.override.md, AGENTS.md, 설정된 대체명 순으로 최대 하나를 선택합니다. 깊은 층은 충돌 항목을 덮어쓰고 양립하는 요구는 유지합니다.

| 상황 | 선택하는 규칙 | 가정하면 안 되는 것 |
| --- | --- | --- |
| 루트 시작 | 루트 규칙 | 모든 하위 폴더 로드 |
| ui 시작 | 루트 다음 ui | 강제 정책 취소 가능 |
| ui에 비어 있지 않은 override | 루트 다음 ui override | 같은 층 AGENTS.md도 합침 |
| 이전 세션에서 편집 | 이전 문맥이 남을 수 있음 | 저장하면 새로 로드됨 |

## 1단계: 독립 규칙 실습 만들기

새 codex-rules-lab에 ui와 data를 만들고 override는 아직 두지 않습니다. 편집기로 열고 PowerShell의 Get-Location 또는 macOS/Linux의 pwd로 새 실습 경로를 확인합니다. 다음 Git 초기화로 루트를 명확히 하며 커밋이나 원격 연결은 필요 없습니다.

```sh
git init
git rev-parse --show-toplevel
```

루트 AGENTS.md에 다음 전체 내용을 저장합니다. ROOT-LAB은 관찰할 응답 접두사, KEEP-DATA는 하위에도 유지할 공통 요구입니다. 실험용 표식이므로 실제 규칙은 테스트, 자료 보존, 인계 요구로 바꿉니다.

```markdown
# Root practice instructions

- Start the final answer with ROOT-LAB.
- Include KEEP-DATA in the final answer.
- Do not change any files for the rule-discovery exercise.
- Report checks that were actually performed separately from unverified claims.
```

둘째 내용은 ui/AGENTS.md, 자료 메모는 data/README.md에 저장합니다. README는 의도적으로 AGENTS가 아니며 해당 대체명 설정이 없으면 Markdown이라는 이유만으로 시작 지침이 되지 않습니다. 대소문자와 잘못 붙은 .txt를 확인합니다.

```markdown
# UI practice instructions

- Start the final answer with UI-LAB instead of ROOT-LAB.
- Include UI-BASE in the final answer.
```

```markdown
# Data notes

This folder describes fictional practice data.
DATA-NOTE is a document marker, not a required answer prefix.
```

## 2단계: 두 경로에서 각각 시작

실습 루트에서 첫 읽기 전용 실행 명령을 쓰고 Codex에 다음 요청을 보냅니다. 규칙 전문이나 예상 접두사는 붙이지 않습니다. ROOT-LAB과 KEEP-DATA가 예상됩니다. /exit로 셸에 돌아와 resume 대신 둘째 명령으로 ui 새 세션을 시작합니다.

```sh
codex --cd . --sandbox read-only
```

```text
Without changing files, report the current working directory and the project instruction sources already available to this session. Follow the active response-format instructions. Do not search unrelated sibling folders just to collect more rules. Distinguish known loaded instructions from files you have not inspected.
```

```sh
codex --cd ui --sandbox read-only
```

ui에서도 같은 요청을 보내 UI-LAB, KEEP-DATA, UI-BASE를 확인합니다. 접두사는 하위가 덮어쓰고 양립하는 루트 요구는 남습니다. 수동 읽기를 요청한 뒤에야 설명하면 시작 시 발견과 구분해 기록합니다. 모델 자기 보고는 로드 로그가 아니며 부족한 증거를 성공 처리하지 않습니다.

## 3단계: 같은 층 override 추가 및 비교

ui를 종료하고 AGENTS.md를 남긴 채 같은 층에 다음 AGENTS.override.md를 추가합니다. 실습 루트에서 같은 ui 실행 명령/요청을 사용합니다. UI-OVERRIDE와 KEEP-DATA가 예상되며 대체된 같은 층 파일의 UI-BASE는 들어오지 않아야 합니다. override는 해당 층 후보를 바꾸며 루트/전역 전체를 지우지 않습니다.

```markdown
# UI override practice

- Start the final answer with UI-OVERRIDE instead of ROOT-LAB.
- Include OVERRIDE-ACTIVE in the final answer.
```

경계 확인은 override를 백업 후 비우고 새 시작의 실제 결과를 기록합니다. 이 컴퓨터의 codex-cli 0.154.0-alpha.6.2 진단 입력에는 빈 본문도 같은 층 AGENTS.md도 없고 루트 규칙만 남았습니다. 빈 파일을 확실한 비활성화로 믿지 말고 대체명 목록에 없는 override.saved.md로 바꾼 뒤 새로 시작해 UI-LAB, UI-BASE, KEEP-DATA를 확인합니다. 전역 파일/전체 설정은 삭제하지 않습니다.

## 실패 진단과 완료 기준

표식 누락은 확장자/내용/Git 루트/--cd, 오래된 표식은 resume가 아닌 새 시작 여부, 일부 누락은 같은 층 override/전역/상위 지침을 확인합니다. 깊은 AGENTS.md가 조직 정책, 도구 권한, 사용자 요청을 넘는 허가는 아닙니다. 충돌 출처를 찾고 자신이 관리할 수 있는 규칙을 수정합니다.

긴 지침은 기본 합계 32 KiB 제한에 걸릴 수 있으며 문자 수가 아닌 바이트입니다. 핵심 규칙을 남기고 긴 설계/예시는 필요할 때 읽는 일반 문서로 옮깁니다. 형제 폴더로 나눠도 모두 자동 로드되지는 않습니다. 대체명/한도는 [설정](article:codex-config-toml)에서 다루며 변경 후 재시작 검증합니다.

루트/ui/override/빈 override/개명 복원의 시작 경로, 파일 상태, 실제 표식을 남깁니다. KEEP-DATA를 유지하고 override 제거 후 ui로 돌아가는지 확인합니다. 로컬은 debug prompt-input의 실제 입력을 확인했으며 모델 요청/준수 주장은 없습니다. 사양과 버전 차이를 기록하고 응답 동작은 새 세션에서 별도로 확인합니다. [규칙과 문서 분담](article:codex-rules-and-context-files)으로 이어 갑니다.
