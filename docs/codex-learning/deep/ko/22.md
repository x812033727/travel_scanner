## 목표와 준비

> 다음 세션이 사용할 handoff.md를 만들고 일부러 오래된 기록으로 신뢰성을 시험합니다. 읽기 12분, 실습 22분입니다. 데스크톱 또는 CLI, 편집기, 호환 Node.js 22 이상, 독립 Small Steps 사본을 사용합니다. 세 OS에서 절차는 같고 현재 경로 확인 명령만 다릅니다.

[세션 재개](article:codex-sessions-resume)는 대화를 보존하지만 최신 디스크와 같지는 않습니다. 인계는 목표, 확인 사실, 미해결 문제, 다음 행동을 기록해 재검증하게 합니다. 전체 대화 복사도 자동 로드 보장도 아니며 새 작업에서 읽도록 명시합니다.

## 1단계: 결함 사본과 상태 표식 준비

[첫 실습 ZIP](article:codex-first-project)의 broken 안 다섯 파일을 새 codex-handoff-lab에 복사합니다. start와 달리 Completed가 미완료를 반환합니다. 루트에 다음 LAB_STATE.txt를 만들고 PowerShell Get-Location 또는 macOS/Linux pwd로 확인해 테스트합니다.

```text
Lab: codex-handoff-lab
Revision: BROKEN-1
```

```sh
node --test core.test.mjs
```

2통과1실패이며 실패는 필터입니다. 실제 관찰한 뒤 확인됨으로 씁니다. Node 누락/경로 오류면 장애와 실제 오류 요약을 쓰고 숫자를 추정하지 않습니다. 계정/키/개인 도구 전체 출력 대신 가상 표식과 필요한 테스트 정보만 남깁니다.

## 2단계: 검증 가능한 인계 작성

루트에 handoff.md를 만듭니다. 다음 완성 예시는 위 기준 결과를 실제 관찰한 전제이므로 다르면 Observed를 수정합니다. Goal은 결과, Scope는 허용 범위, Observed는 버전/명령, Not checked는 미확인, Next는 다음 확인입니다.

```markdown
# Small Steps handoff

## Goal
Completed shows only completed tasks. Keep ordering, storage and existing UI.

## Scope
Lab: codex-handoff-lab. Only core.mjs may need a program change.
Do not change tests or add dependencies. Preserve other work.

## Observed
LAB_STATE.txt: Revision: BROKEN-1.
Command: node --test core.test.mjs
Result: 2 passed, 1 failed in the filter case.
The completed branch of visibleTasks currently selects unfinished tasks.

## Not checked
Browser interaction: NOT RUN.
Publishing and deployment: NOT PERFORMED.

## Next
1. Re-read LAB_STATE.txt, core.mjs and the test file; do not trust this record over current files.
2. Re-run the baseline before deciding whether a fix is still needed.
3. If still faulty, change only the completed predicate, then test and review the diff.
4. Manually check Read completed / Build active under all three filters.

## Stop condition
If revision, test results or files differ, report the mismatch and revise this record before editing program code.
```

‘몇 가지 수정’만으로는 검증할 수 없습니다. 파일, 동작, 실행 명령, 미실행 확인을 명시합니다. Git에서는 브랜치/commit도 넣되 미커밋 차이도 봅니다. 같은 commit이어도 작업 트리는 다를 수 있습니다. 실습에 가짜 ID를 넣지 않습니다.

## 3단계: 기록을 오래된 상태로 만들고 새 작업 시작

ZIP expected/core.mjs만 실습에 덮어쓰고 LAB_STATE.txt를 Revision: FIXED-2로 바꾸며 handoff.md는 그대로 둡니다. 테스트는 3개 통과해야 합니다. 다른 협업자가 수정했지만 대화/문서만 결함 상태로 남은 상황을 재현합니다. 다른 파일과 테스트는 바꾸지 않습니다.

동일 실습의 새 데스크톱 작업을 만듭니다. CLI는 /exit 후 경로 확인하고 resume 없이 codex를 시작합니다. 다음 요청으로 FIXED-2, 오래된 BROKEN-1, 3통과 불일치를 인식하고 올바른 함수를 다시 수정하지 않고 기록 갱신을 제안하는지 확인합니다.

```text
Continue this lab using handoff.md, but first verify it against current files. Read LAB_STATE.txt, core.mjs and core.test.mjs. Run node --test core.test.mjs. Do not edit anything yet.
Compare the recorded revision, predicate and test result with current evidence. Report mismatches and propose the smallest next step. Browser checks must remain NOT RUN unless actually performed.
```

계속 Completed 수정을 제안하면 현재 틀린 줄과 실패 테스트를 요청합니다. 최신 증거를 오래된 기록으로 덮지 않습니다. 이후 handoff.md만 갱신해 Observed는 FIXED-2와 실제 3통과, Next는 남은 화면 확인으로 바꿉니다. 오래된 기록을 재검증했다는 이유도 짧게 남깁니다.

## 긴 대화, compact와 문서 역할

CLI /compact는 긴 대화를 압축합니다. 대화 입력창에 넣고 확인 안내를 따른 뒤 목표/제약/남은 작업 요약을 handoff.md와 비교합니다. 실습에서 억지로 문맥을 채울 필요는 없습니다. 파일 백업, Git 복원, 모든 상세 보존 보장이 아니므로 중요한 결정은 읽을 수 있는 문서에 남깁니다.

| 문서 | 저장 내용 | 갱신 시점 |
| --- | --- | --- |
| AGENTS.md | 장기 규칙과 명령 | 작업 관행 변경 |
| README.md | 진입점과 시작 방법 | 사용법 변경 |
| 설계 문서 | 동작, 선택 이유, 제약 | 설계 결정 채택 |
| handoff.md | 최신 증거, 장애, 다음 행동 | 중단, 인계, 검증 후 |

[규칙과 문서 역할](article:codex-rules-and-context-files)도 참고합니다. 일회성 장애 전체를 AGENTS.md에 상시 저장해 모든 작업에 오래된 정보를 주지 않습니다. 인계 위쪽에 현재 목표/확인 날짜, 해결 항목은 짧은 결과, 무효 경로/가설은 삭제하거나 표시합니다.

## 문제 해결, 복원과 검수

파일을 못 찾으면 경로/이름부터 확인하고 PC 전체 검색을 바로 요청하지 않습니다. 안 읽었다면 경로와 읽은 Revision 보고를 요청합니다. 다른 폴더의 성공은 이 코드 검증이 아닙니다. 기록과 다른 실패면 두 결과/시간을 남기고 재확인하며 옛 기록에 맞춰 테스트를 바꾸지 않습니다.

불일치 설명, 갱신한 handoff.md, core.mjs를 중복 수정하지 않았다는 증거가 완료 조건입니다. 반복 시 broken/core.mjs만 복원하고 BROKEN-1과 원래 인계로 되돌립니다. 그림 1은 기록, 2는 재검증, 3은 다음 행동 갱신입니다. 모델 대화와 /compact는 문서 절차이며 자신의 실행 결과를 기록합니다. 참고 코드 결함/수정은 별도 로컬 테스트되었습니다.
