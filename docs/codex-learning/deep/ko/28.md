## 목표와 준비

> 읽기 전용 검토를 두 독립 작업으로 나누고 모두 기다린 뒤 부모가 증거를 확인합니다. 읽기 15분, 실습 20분입니다. [첫 프로젝트](article:codex-first-project)의 expected 사본, Node.js, 하위 에이전트 지원 Codex를 준비하세요. 답변 하나를 두 부분으로 나눈 것은 두 에이전트 실행 증거가 아닙니다.

하위 에이전트는 부모에게 특정 부분을 위임받고 결과를 돌려줍니다. 자동 Git 격리도 아니며 두 창을 열었다고 조율되는 것도 아닙니다. 병렬 작업은 입력·범위·결과가 나뉘고 다른 작업의 수정 완료를 기다리지 않아야 합니다. 이번에는 둘 다 읽기만 합니다.

## 1단계: 자료와 기준 확인

완성 사본의 다섯 파일을 열고 고의 오류가 있는 start/broken과 혼동하지 마세요. 각 OS에서 현재 폴더를 확인하고 같은 명령을 실행합니다. npm 패키지나 외부 DB가 필요하지 않습니다. 버전과 기준 결과를 보존해 기존 문제를 구분하세요.

```sh 세 OS 터미널: expected 사본 안
node --version
node --test core.test.mjs
```

현재 제공 자료는 최상위 테스트 세 개가 통과해야 하지만 다른 저장소의 개수를 뜻하지 않습니다. Node나 테스트가 없으면 [문제 해결](article:codex-troubleshooting)과 경로를 먼저 확인하세요. 누락됐다고 비슷한 프로젝트를 만들게 하면 검토 대상이 달라집니다.

## 2단계: 두 하위 에이전트 명시 요청

부모 데스크톱·CLI·IDE에서 실습 폴더를 선택하고 아래 요청을 보냅니다. 현재 로컬 Codex는 직접 요청이나 적용 규칙에 따라 위임하므로 두 개를 명시합니다. 모델과 추론은 부모를 상속하고 계정에 없을 수 있는 이름을 고정하지 마세요. 각 에이전트가 사용량을 쓰므로 무제한 생성 대신 작은 읽기 범위 둘로 제한합니다.

```text 부모 입력창: 읽기 전용 하위 작업 두 개
Use exactly two subagents for a read-only review of this Small Steps reference copy.
Do not spawn additional subagents or modify files.

Agent A: Read core.mjs. Map addTask, visibleTasks and decodeTasks.
For each function, report its input, behavior, failure or boundary handling, and file/symbol evidence.

Agent B: Read core.test.mjs. Map existing test coverage to those same functions.
Distinguish covered cases from possible missing cases; do not invent a bug just because a test is absent.

Parent: Wait for both reports. Verify cited symbols and reconcile disagreements.
Run node --test core.test.mjs once in the practice directory after collecting the reports.
Return a compact evidence table, actual test result and unverified claims.
If subagents are unavailable, say so; do not present a single-agent answer as delegated work.
```

요청에 참조 사본의 전체 루트와 기준 결과를 포함하고 각 보고서에 읽은 경로를 적게 하세요. core.mjs라는 이름이 같아도 다른 checkout일 수 있으므로 부모가 같은 expected 사본인지 맞춥니다. 세 항목 통과 기준은 부모의 이전 기록이며 A나 B가 실행한 테스트로 세지 않습니다.

| 역할 | 주요 입력 | 결과 | 제외 |
| --- | --- | --- | --- |
| A 동작 | core.mjs | 함수와 경계 | 코드 수정 |
| B 테스트 | core.test.mjs | 범위와 빈틈 증거 | 버그 단정 조작 |
| 부모 | 두 보고와 실제 파일 | 조정·시험·제한 | 미확인 요약 전달 |

둘은 동시에 시작하고 테스트는 부모가 마지막에 한 번 실행합니다.

## 3단계: 활동 확인·추가 지시·중지

데스크톱은 부모 활동에서 개별 작업을 열어 파일과 상태를 봅니다. CLI /agent는 대화 안의 전환이며 codex agent라는 셸 명령이 아닙니다. IDE에 배경 패널이 있으면 펼치세요. 부모에게 방향 수정·중지를 요청하며 표시가 없으면 버전과 지원을 확인합니다.

```text Codex CLI 대화 안: 에이전트 확인
/agent
```

```text 부모에게 추가 조건
Tell Agent A to include duplicate task IDs in its analysis and keep the work read-only.
Wait for the updated evidence before the final summary.
```

부모가 A에 조건을 전달하고 업데이트에 addTask 중복 ID 처리가 있는지 확인하세요. 다른 창에 입력했다고 대상에게 전달됐다고 가정하지 않습니다. B 중지는 증거를 보존하고 미완료를 미검증으로 남기도록 요청합니다. 중지는 복원이 아니며 읽기 연습에 차이가 생기면 따로 조사합니다.

## 4단계: 완료 수 대신 증거 확인

참고판 addTask는 공백·길이·ID를 검사해 새 배열을 반환하고 visibleTasks는 active/completed를 필터링하며 decodeTasks는 잘못된 형식과 중복 ID를 거부합니다. 부모는 실제 함수와 테스트를 확인하고 중복 미검증 주장에는 추가와 저장 복원의 차이를 구분하세요. 긴 보고를 우선하지 않습니다.

부모가 기준 테스트를 한 번 실행해 실제 종료와 결과를 남깁니다. 주장·파일/함수·시험 증거·검증 상태를 기록하세요. 코드로 확인해도 브라우저 미실행일 수 있고 테스트 빈틈은 버그가 아닐 수 있습니다. 이를 구분해야 시험·재현·수정 중 다음 단계를 고를 수 있습니다.

## 선택: 좁은 사용자 역할 저장

반복 검토는 신뢰한 실습 프로젝트에 동명 파일이 없는지 확인하고 .codex/agents/data-reader.toml을 만들 수 있습니다. AGENTS.md가 아닌 에이전트 TOML이며 파일만으로 실행되지 않습니다. 새 작업에서 data_reader를 명시해 역할을 확인하세요. 앞의 두 작업 실습에 필수는 아닙니다.

```toml 실습 프로젝트: .codex/agents/data-reader.toml
name = "data_reader"
description = "Inspect Small Steps data invariants with file and symbol evidence."
sandbox_mode = "read-only"
developer_instructions = """
Read core.mjs and report inputs, invariants and error handling.
Do not edit files, invoke external services or spawn other agents.
Cite the relevant functions and distinguish confirmed behavior from assumptions.
If the file is missing, report the missing path and stop.
"""
```

모델을 생략해 사용 가능한 설정을 상속합니다. 하위 작업은 부모의 현재 권한을 받으며 CLI 런타임 덮어쓰기가 다시 적용되므로 파일 read-only가 항상 우선한다는 보장은 아닙니다. 위임 전 [권한](article:codex-permissions)을 확인하세요. 되돌릴 때 추가한 역할 파일만 제거하고 새 작업에서 확인합니다.

## 문제·경계·다음 단계

생성되지 않으면 명시 요청·지원 버전·기존 작업의 슬롯 점유를 확인하고 한 모델 역할극으로 대체하지 않습니다. 동시 편집은 중지·차이 확인 후 [Worktree](article:codex-worktrees)나 순차 작업으로 바꿉니다. 인증·승인 대기는 부모가 출처와 막힌 단계를 알리고 거부된 동작을 몰래 권한 확대하여 재시도하지 않습니다.

실제 두 작업자의 활동·증거·추가 지시 응답·부모 통합과 시험·다섯 파일 불변을 남깁니다. B 중지는 별도 실행의 중지 사례이며 두 완료로 세지 않습니다. 역할·참고 코드의 정적 확인이 사용자 계정에서 실행했다는 뜻은 아닙니다. 미실행 환경은 공식 문서 확인으로 표시하고 [품질 검증](article:codex-subagent-quality)으로 이어갑니다.
