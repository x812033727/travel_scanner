## 목표와 준비

> 독립 프로젝트에서 web_search를 설정하고 파일/유효한 설정 층/재시작 후 상태를 확인한 다음 복원합니다. 읽기 12분, 실습 25분입니다. Codex CLI, Git, 일반 텍스트 편집기가 필요하고 세 OS의 TOML은 같습니다. IDE 설정으로도 열 수 있지만 검증은 공통 CLI 진단을 사용합니다.

[AGENTS.md](article:codex-agents-md)는 지침이고 config.toml은 클라이언트 설정입니다. 일반 Markdown에 모델명을 써도 기본 설정은 바뀌지 않습니다. TOML에 주석 표시 없이 설명을 쓰면 파싱이 실패할 수 있습니다. 영향이 작은 한 항목으로 위치/검증/복구를 익힌 뒤 필요한 설정을 추가합니다.

## 사용자 설정과 프로젝트 설정 구분

사용자 설정은 기본 홈의 .codex/config.toml이며 기존 CODEX_HOME이 있으면 경로를 확인합니다. 프로젝트 설정은 저장소 안의 같은 경로이고 신뢰된 프로젝트에서 로드됩니다. 이름은 같지만 범위는 다릅니다. 실습은 프로젝트 파일만 만들며 인증 이동/전역 설정/시스템 환경 변수 변경은 필요 없습니다.

| 환경 | 사용자 기본 위치 | 실습 위치 |
| --- | --- | --- |
| Windows | 사용자 폴더 내 .codex/config.toml | codex-config-lab/.codex/config.toml |
| macOS | ~/.codex/config.toml | 같은 상대 경로 |
| Linux/WSL | Linux 사용자의 ~/.codex/config.toml | 해당 환경의 실습 경로 |
| IDE | 톱니바퀴 → Codex Settings → Open config.toml | 실제 열린 경로 확인 |

## 1단계: 시작 상태 기록

새 codex-config-lab의 note.txt에 다음 한 줄을 저장합니다. PowerShell의 Get-Location 또는 macOS/Linux의 pwd로 위치를 확인하고 새 실습에서 git init으로 루트를 정합니다. 설정 파일은 아직 만들지 않습니다. 같은 이름의 다른 프로젝트가 있으면 초기화하지 말고 새 위치를 씁니다.

```text 파일 내용: note.txt로 저장
CONFIG-LAB-01
```

셸에서 codex --cd .로 시작하고 신뢰 안내가 방금 만든 실습인지 확인합니다. 내부에서 다음 슬래시 명령을 각각 실행합니다. 셸 명령이 아닙니다. /debug-config로 층/활성 상태, /status로 작업 환경을 보고 필요한 정보만 기록하며 비공개 진단 전문은 공개하지 않습니다.

```text 대화형 슬래시 명령: Codex CLI 안에서 입력
/debug-config
```

```text 대화형 슬래시 명령: Codex CLI 안에서 입력
/status
```

/debug-config가 없으면 / 목록과 셸의 codex --version을 확인하고 설치한 공식 방식으로 업데이트합니다. 같은 이름의 셸 명령을 지어내지 않습니다. 버전/조직 환경의 진단이 부족하면 유효값을 미확인으로 남기고 모델 성공 선언만 믿지 않습니다. 기준 기록 후 /exit로 종료합니다.

## 2단계: 복원 가능한 설정 하나 추가

프로젝트 안에 .codex/config.toml을 만들고 루트 바로 아래나 .txt가 아닌지 확인합니다. 기존 파일이면 알아볼 수 있는 곳에 백업하고 원래 값을 기록한 뒤 같은 최상위 키를 수정하며 중복 추가하지 않습니다. 새 파일이면 다음 전체 예시를 씁니다.

```toml TOML 파일 내용: 새 프로젝트 .codex/config.toml
# Practice setting: disable the built-in web search tool.
web_search = "disabled"
```

키/값 철자, 일반 따옴표, # 주석을 지킵니다. 최상위 키이므로 [features] 등 아래에 무조건 붙이지 않습니다. 테이블 헤더는 뒤 키의 소속을 바꿉니다. 사이트 바깥 백틱도 넣지 말고 UTF-8 텍스트로 저장해 재확인합니다.

## 3단계: 재시작 후 유효 출처 확인

실습 루트에서 --search/-c/--profile 없이 새로 시작하고 /debug-config의 프로젝트 층/활성을 확인합니다. 미신뢰로 생략되면 출처 확인 후 정상 신뢰 절차를 따릅니다. 진단은 낮은 우선순위부터 표시할 수 있으므로 첫 행을 승자로 보지 말고 라벨/상태를 읽습니다.

유효 설정/사용 가능 도구 정보와 파일을 비교하고 다음 로컬 읽기를 요청합니다. CONFIG-LAB-01과 검색 없음이 예상되며 유효값이 표시되면 disabled인지 확인합니다. 한 번 검색하지 않은 것만으로 설정 성공이 입증되지는 않으므로 층 진단 근거도 남깁니다.

```text 자연어 요청: 이 실습 프로젝트의 새 CLI에 입력
Read note.txt from this practice project and report its exact line. Do not edit files, browse websites or call external services. If you cannot verify an effective setting from available diagnostics, say so rather than inferring it from the file alone.
```

이 설정은 내장 검색 도구를 끄며 모든 통신 차단은 아닙니다. 셸/브라우저/MCP/외부 서비스에는 별도 권한과 설정이 있습니다. [권한과 샌드박스](article:codex-permissions)를 참고하고 증명을 위해 다른 도구로 우회 통신하지 않습니다.

### 검색하지 않았다는 관찰이 뜻하는 세 가지 상태

사례: A는 파일의 disabled만 보았고, B는 신뢰되지 않아 프로젝트 계층을 건너뛰었다는 진단도 보았으며, C는 계층 활성화와 실제 적용 값 disabled를 확인했습니다. 셋 다 검색하지 않았어도 A의 적용 값은 미상, B는 로드 문제, C는 해당 설정의 진단 근거가 있는 상태입니다. C도 모든 네트워크 도구가 차단되었다고 할 수는 없습니다. 파일 내용, 로드 상태, 적용 값, 이번 동작을 따로 기록하고 근거가 없는 칸은 미확인으로 남기세요.

## 4단계: 복원 및 결과 기록

CLI 종료 후 새 파일이면 프로젝트 설정 폴더 밖으로 백업 이동합니다. 기존 파일이면 web_search 원래 값만 복원하거나 추가 키만 제거하고 다른 설정은 보존합니다. 재시작 후 덮어쓰기가 사라지고 note.txt가 그대로인지 확인합니다. 복원값은 남은 층에 따라 달라지며 추측한 기본값과 같다고 단정하지 않습니다.

```text 개인 검증 메모: 실제 관찰을 작성하며 명령으로 실행하지 않음
File changed: codex-config-lab/.codex/config.toml
Original state: record whether the file/key existed.
Requested change: web_search = disabled
Loaded layer: record observed path and enabled/skipped state.
Effective value: record verified value, or unverified.
Local read: record actual note.txt result.
Restoration: record the restored file/key state and fresh-session check.
```

## 문제 해결과 다음 단계

시작 실패는 지목된 TOML/줄의 따옴표, 중복 키, 테이블 소속을 확인합니다. 값이 안 바뀌면 경로/신뢰/시작 옵션/가까운 층을 봅니다. IDE와 CLI 차이는 OS/사용자/경로, 특히 별개인 Windows/WSL 홈을 비교하고 재설치 전에 출처를 진단합니다.

강제 요구는 일반 기본값과 달라 프로젝트 키로 금지값을 허용할 수 없습니다. 모델/추론은 [선택 강의](article:codex-model-selection)를 참고하고 설정 묶음 복사로 인증/공급자를 바꾸지 않습니다. 시작/활성/복원과 미확인을 기록하고 [설정 문제 해결](article:codex-config-troubleshooting)로 이어 갑니다. 문법이 맞아도 모든 클라이언트의 로드 증거는 아닙니다.
