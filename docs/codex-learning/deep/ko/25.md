## 목표와 준비

> OpenAI 읽기 전용 문서 MCP를 연결해 질문 하나를 조사하고 원문을 확인한 뒤 연습 항목을 끄거나 제거합니다. 읽기 15분, 실습 20분입니다. 인터넷에 연결된 데스크톱·CLI·IDE를 사용하며 CLI는 [설치](article:codex-cli-getting-started)를 먼저 마치세요. 비공개 문서·유료 서비스 키·외부 npm 서버 패키지는 필요하지 않습니다.

MCP는 도구 호출과 맥락 수신을 위한 프로토콜입니다. 기능은 서버에 따라 다르며 문서 연결이 GitHub나 로컬 브라우저 접근을 주지는 않습니다. Docs MCP는 문서를 검색·조회하며 대신 OpenAI API를 호출하지 않습니다. 이후 쓰기 서비스로 바꾸면 도구와 [권한 범위](article:codex-permissions)를 다시 검토하세요.

## 1단계: 연결 방식과 설정 위치 선택

| 방식 | 필요 정보 | 실행 위치 |
| --- | --- | --- |
| STDIO | 프로그램과 인수 | Codex 호스트가 로컬 프로세스 시작 |
| Streamable HTTP | MCP 주소 | 네트워크로 서비스 접속 |
| 플러그인 제공 MCP | 설치와 필요한 연결 | 플러그인과 진입점에 따름 |

이번에는 Streamable HTTP만 사용합니다. 웹사이트 첫 페이지가 MCP 주소는 아니므로 공식 주소를 사용하고 STDIO 명령을 URL 칸에 넣지 마세요.

같은 Codex 호스트의 데스크톱·CLI·IDE는 설정을 공유합니다. 기본은 ~/.codex/config.toml로 Windows 사용자 폴더와 macOS·Linux 홈의 .codex 아래입니다. 기존 사용자 지정 CODEX_HOME이 있으면 실제 위치를 확인하세요. 신뢰한 프로젝트 설정도 있지만 이번에는 사용자 설정을 씁니다. 위치는 [config.toml](article:codex-config-toml)을 참고하세요.

## 2단계: 기존 항목 확인 후 추가

```sh 터미널: 설정된 서버 목록
codex mcp list
```

Windows PowerShell, macOS 또는 Linux 터미널에서 실행하며 codex 대화 안에 들어갈 필요는 없습니다. codexLearningDocs가 있으면 덮어쓰지 말고 상세 정보를 확인하세요. 같은 공식 URL의 기존 항목은 이름을 그대로 사용하고 재사용으로 기록하며 정리할 때 보존합니다. 목록에 비공개 URL이 있을 수 있으니 전체 출력을 공개하지 마세요.

추가 전 실제 사용자 config.toml을 열고 이전 백업을 덮어쓰지 않는 날짜 사본을 저장합니다. 파일이 없으면 그 상태만 기록하세요. 한 변경의 전후 차이를 남기고 민감값이 있을 수 있는 백업은 Git 밖 로컬에 둡니다. 정리 시 새 항목만 제거하여 다른 작업이 추가한 설정을 과거 백업으로 덮어쓰지 않습니다.

```sh 세 OS 터미널: 연습 항목 추가 및 확인
codex mcp add codexLearningDocs --url https://developers.openai.com/mcp
codex mcp get codexLearningDocs
```

get에서 이름·HTTP·정확한 공식 URL을 확인합니다. 이는 설정 저장만 증명하며 연결·도구 목록·질의 성공은 아닙니다. 도구 수는 달라질 수 있으므로 고정 수치를 복사하지 않고 관리 명령 종료 0도 읽기 증거로 보지 않습니다. 명령이 없으면 codex mcp --help와 업데이트 절차를 확인하세요.

## 데스크톱과 IDE의 같은 절차

CLI 대신 데스크톱 Settings → MCP servers → Add server에서 이름, Streamable HTTP, 같은 URL을 입력하고 저장 후 Restart합니다. IDE 톱니바퀴의 같은 메뉴에서 저장 후 Restart extension을 선택하세요. 각 OS에서 사용 가능한 클라이언트를 쓰며 Linux 미리 보기 등에 UI가 없으면 CLI를 사용합니다. 버튼 없음은 서비스 장애가 아닙니다.

```toml config.toml 확인 구간: 중복 추가 금지
[mcp_servers.codexLearningDocs]
url = "https://developers.openai.com/mcp"
```

같은 설정의 파일 표현이므로 CLI·UI·직접 편집 중 하나만 선택하세요. 명령 추가 후 같은 TOML 표를 붙이면 중복 오류가 날 수 있습니다. 직접 편집은 그 구간만 합치고 재시작합니다. 웹과 모바일은 PC의 로컬 설정을 읽지 않으며 호스팅 기능은 [Plugins](article:codex-plugins)를 쓰므로 로컬 성공이 휴대폰 설정 완료는 아닙니다.

## 3단계: 도구 확인과 원문 조회

```text Codex 데스크톱·CLI·IDE 입력창: 셸 명령 아님
/mcp
```

데스크톱·CLI·IDE의 새 작업 또는 세션에서 Codex 입력창에 /mcp를 입력해 서버와 도구를 확인하세요. 셸 명령이 아닙니다. MCP servers 설정 상태와 새 작업의 실제 도구 활동도 확인할 수 있습니다. 인증을 요구하면 공개 주소부터 확인합니다. 다른 OAuth 서비스에는 Authenticate나 codex mcp login이 필요할 수 있지만 이 공개 서비스에 임의의 API key를 넣지 않습니다.

```text 새 작업: MCP로 규칙 확인
Use the codexLearningDocs MCP tools to find the official AGENTS.md instructions.
Read the relevant page and explain global versus project rules in three bullets.
Include the source URL and the section you checked.
If the MCP tools are unavailable, report that limitation instead of answering from memory.
Do not edit files or call paid APIs.
```

기존 서버를 쓰면 요청의 이름을 바꾸세요. 검색 또는 읽기 활동을 관찰하고 공식 출처를 열어 설명을 뒷받침하는 부분을 확인합니다. 고정 문장이나 도구 이름 대신 증거·URL·내용의 일치를 검증합니다. MCP를 쓰지 않은 정답은 일반 답변이며 이번 연결 연습 완료는 아닙니다.

## 4단계: 비활성화·재시험·제거

실패 대조는 자신이 추가한 항목만 바꿉니다. enabled가 이미 있으면 false로 수정하고, 없을 때만 enabled = false를 한 번 추가하세요. 키나 표를 중복하면 안 됩니다. 클라이언트 비활성화 기능도 가능합니다. 저장·재시작한 뒤 데스크톱·CLI·IDE의 새 작업 또는 세션에서 /mcp와 실제 도구 활동으로 사용 불가를 확인합니다. 이전 대화는 새 조회가 아닙니다. 이전 값을 복구하거나 이번에 추가한 키만 제거한 뒤 재시작·재조회합니다.

```sh 터미널: 이번에 추가한 항목만 제거 후 목록 확인
codex mcp remove codexLearningDocs
codex mcp list
```

제거 후 새 작업에 추가 항목이 없는지 확인합니다. 다른 서버나 문서를 지우거나 별도 OAuth를 취소하지는 않습니다. 재사용 항목은 제거를 생략하고 미변경이면 그대로 기록하세요. 인증 서비스의 remove와 logout은 목적이 다르므로 [MCP 문제 해결](article:codex-mcp-troubleshooting)을 참고합니다.

## 문제와 완료 기준

서버 없음은 설정 계층·이름·활성 상태·재시작을 확인합니다. TOML 오류는 중복 표와 따옴표를 보고 전체 초기화하지 마세요. 연결 실패는 URL·호스트 네트워크·서비스 상태와 가린 오류를 기록합니다. 출처가 없으면 원문 조회를 재요청합니다. 서로 다른 네 오류를 전부 권한 완화로 처리하지 않습니다.

실제 버전·설정 저장·출처 있는 도구 결과·추가 항목 비활성화 또는 제거를 기록합니다. Windows 격리 설정 시험과 공개 프로토콜 시험은 별도 증거이며 데스크톱 UI·macOS·Linux·사용자 모델 실행을 증명하지 않습니다. 미실행 진입점은 공식 문서 확인으로 표시하고 [연결 템플릿](article:codex-templates-cheatsheet)에 남깁니다.
