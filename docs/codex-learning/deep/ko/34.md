## 이 강의의 목표

> Windows, macOS 또는 Linux에서 터미널을 열고 현재 폴더를 확인하며 파일을 읽고 Codex 실행 전 위치를 검증합니다. 읽기 약 12분, 실습 약 20분입니다. 삭제, 설치, 관리자 작업 없이 경로와 읽기 명령만 연습합니다. 자신의 운영체제에 해당하는 부분을 따르세요.

## 창, 셸, 입력 구분하기

터미널은 텍스트 상호작용을 담는 창이고 PowerShell, Bash, zsh 같은 셸이 명령을 해석합니다. codex를 시작하면 같은 창 안에서 에이전트 대화 화면으로 들어갑니다. 하나의 창에도 입력 대상이 달라질 수 있습니다. PS와 경로는 보통 PowerShell이고 Codex 입력창은 에이전트에게 요청하는 곳입니다. 셸 명령, /plan, 자연어 요청을 구분 없이 한꺼번에 붙이지 마세요.

절대 경로는 C:\Work\demo 또는 /home/reader/demo처럼 드라이브나 루트에서 시작합니다. 상대 경로는 현재 위치를 기준으로 합니다. 점 하나는 현재 폴더, 두 개는 상위 폴더입니다. 터미널의 위치를 바꿔도 파일이 이동하거나 다른 터미널 위치까지 바뀌지 않습니다. 새 창에서는 이전 창의 기억에 의존하지 말고 위치부터 확인하세요.

## 두 단계 폴더와 텍스트 파일 준비하기

파일 관리자에서 찾기 쉬운 위치에 새 codex-terminal-lab 폴더를 만들고 그 안에 공백이 있는 lesson one 폴더를 만듭니다. 같은 이름이 있으면 다른 이름을 선택하고 이후 명령에 실제 경로를 사용하세요. lesson one 안에 note.txt를 UTF-8 일반 텍스트로 저장하고 아래 한 줄만 적습니다. 먼저 그래픽 화면에서 만들어 터미널 출력과 실제 파일 위치를 연결합니다.

```text 파일 내용: lesson one/note.txt에 붙여 넣기
Terminal practice: this is lesson one.
```

아래와 같은 구조여야 합니다. Windows에서는 note.txt.txt, macOS에서는 RTF 저장을 피하고 Linux에서는 대소문자를 유지하세요. 폴더 이름의 공백은 잘못이 아니며 따옴표 연습에 사용합니다. 코드 영역에는 입력할 명령이나 내용만 있으므로 PS C:\>나 $ 같은 프롬프트 표시를 추가하지 마세요.

```text 폴더 구조: 확인용이며 명령이 아님
codex-terminal-lab/
  lesson one/
    note.txt
```

## Windows: PowerShell 전체 절차

시작 메뉴에서 PowerShell을 열거나 탐색기의 codex-terminal-lab에서 터미널에서 열기를 선택합니다. 명령 프롬프트가 열렸다면 PowerShell로 바꾸세요. Get-Location은 cmd.exe 명령이 아닙니다. 아래 읽기 명령으로 위치와 바로 아래 항목을 확인합니다. lesson one이 없으면 파일을 읽기 전에 탐색기에서 실제 경로를 확인하세요.

```powershell PowerShell: 현재 위치와 파일 확인
Get-Location
Get-ChildItem -Name
```

직접 이동해야 한다면 탐색기에서 codex-terminal-lab의 전체 경로를 복사해 아래 따옴표 안의 예시를 바꿉니다. YOUR_NAME은 그대로 실행할 경로가 아닌 자리표시자입니다. 문서가 OneDrive나 다른 드라이브에 있을 수 있으므로 실제 위치를 사용하세요. LiteralPath는 대괄호 등이 와일드카드로 해석되지 않도록 합니다. 이동 성공 시 출력이 없을 수 있으니 위치를 다시 확인합니다.

```powershell PowerShell: 자신의 전체 경로로 바꾼 뒤 실행
Set-Location -LiteralPath 'C:\Users\YOUR_NAME\Documents\codex-terminal-lab'
Get-Location
Get-ChildItem -Name
```

실제 실습 루트에 있는지 확인한 뒤 공백이 있는 하위 폴더로 이동해 파일을 읽고 상위 폴더로 돌아옵니다. 아래 명령은 파일을 바꾸지 않습니다. 중간에 영어 문장 전체가 나오고 마지막 위치가 codex-terminal-lab이어야 합니다. 마지막 줄만 보고 전체 성공으로 판단하지 말고 중간 오류가 있으면 멈춰 확인하세요.

```powershell PowerShell: 실습 루트에서 이동, 읽기, 복귀
Set-Location -LiteralPath '.\lesson one'
Get-Content -LiteralPath '.\note.txt'
Set-Location -LiteralPath '..'
Get-Location
```

## macOS와 Linux: 터미널 전체 절차

macOS에서는 Spotlight로 Terminal을 열고 Linux에서는 앱 메뉴나 파일 관리자의 터미널 기능을 사용합니다. macOS는 주로 zsh, Linux는 주로 Bash를 사용하지만 여기서는 두 셸이 이해하는 기본 명령만 씁니다. pwd는 현재 위치를, ls -a는 숨김 항목까지 표시합니다. macOS의 /Users 경로가 Linux의 /home에도 그대로 존재한다고 가정하지 마세요.

```bash macOS/Linux 터미널: 현재 위치와 파일 확인
pwd
ls -a
```

직접 이동하려면 cd 뒤에 공백을 넣고 실제 폴더의 절대 경로를 따옴표로 감싸 입력합니다. 아래는 바꿔 쓸 예시입니다. 폴더를 터미널에 끌어 놓을 수도 있지만 공백이 자동 처리됐는지 확인하고 따옴표를 잘못 중복하지 마세요. $HOME을 쓴다면 큰따옴표에서 변수가 확장되지만 이번에는 문법을 섞지 않도록 전체 경로를 사용합니다.

```bash macOS/Linux 터미널: 자신의 전체 경로로 먼저 바꾸기
cd '/absolute/path/to/codex-terminal-lab'
pwd
ls -a
```

lesson one을 확인하면 다음 순서로 실행합니다. 같은 문장을 읽고 원래 루트로 돌아와야 합니다. 실패한 단계가 있으면 고친 후 한 줄씩 진행하세요. macOS와 Linux의 기본 절차는 같지만 대소문자 구분은 파일 시스템에 따라 다를 수 있습니다. 느슨한 일치에 기대지 말고 정확한 이름을 사용합니다.

```bash macOS/Linux 터미널: 실습 루트에서 이동, 읽기, 복귀
cd 'lesson one'
cat note.txt
cd ..
pwd
```

## 오류 동작 확인 후 Codex 시작하기

실습 루트에서 없는 missing-folder로 이동해 봅니다. PowerShell은 Set-Location -LiteralPath '.\missing-folder', macOS/Linux는 cd 'missing-folder'를 사용합니다. 경로를 찾을 수 없다는 오류가 나오고 현재 위치는 그대로여야 합니다. 오류 문구는 언어와 버전에 따라 다릅니다. 이동 실패가 폴더를 만들지는 않으며 cd 실패를 확인하지 않고 수정 명령을 실행하면 안 된다는 점을 확인합니다.

### 잘못된 위치에서 읽은 뒤 상대 경로 고치기

현재 위치가 codex-terminal-lab 루트이고 note.txt가 lesson one 안에만 있는지 확인하세요. 자신의 플랫폼에 맞는 블록을 사용합니다. 첫 줄은 note.txt를 찾을 수 없다는 오류가 나고 둘째 줄은 올바른 하위 폴더를 지정하여 Terminal practice: this is lesson one.을 읽어야 합니다. 읽기 실패로 lesson one에 자동 이동하지 않습니다. 오류를 숨기려고 루트에 note.txt를 하나 더 만들지 마세요. 읽기만 하므로 원본 내용은 그대로여야 합니다.

```powershell PowerShell: 첫 줄은 예상 실패, 둘째 줄에서 경로 수정
Get-Content -LiteralPath '.\note.txt'
Get-Content -LiteralPath '.\lesson one\note.txt'
```

```bash macOS/Linux 터미널: 첫 줄은 예상 실패, 둘째 줄에서 경로 수정
cat note.txt
cat 'lesson one/note.txt'
```

CLI가 설치되어 있으면 확인한 실습 루트에서 codex를 실행하고 아래 읽기 요청을 보냅니다. 설치 전이라면 [CLI 설정](article:codex-cli-getting-started)으로 이어 가며 이번 실습 때문에 권한을 변경하지 않습니다. 에이전트는 lesson one/note.txt와 영어 문장을 찾아 작업 위치를 보고해야 합니다. 경로가 다르면 잘못된 폴더라고 판단하기 전에 작업 복사본이 만들어졌는지 확인하세요.

```text 자연어 요청: Codex를 시작한 뒤 입력
Read lesson one/note.txt and report the current working directory.
Do not modify any files. If the file is missing, report the actual error.
```

## 문제 해결, 종료와 추가 연습

명령을 찾지 못하면 셸을 확인하세요. Get-Content는 Bash 명령이 아닙니다. 경로가 나뉘면 공백과 일반 따옴표를 확인하고 문서 프로그램의 곡선 따옴표를 피합니다. 접근 거부가 뜨면 바로 관리자로 실행하기보다 자신의 실습 폴더인지 확인하세요. 편집기에는 파일이 보이는데 터미널에는 없다면 저장 후 확장자, 위치, WSL의 다른 홈 폴더 여부를 확인합니다.

원본을 수정하지 않았으므로 터미널을 닫거나 실습 폴더에서 나오면 됩니다. 실행 중인 프로그램은 보통 Ctrl+C로 중단하지만 이미 쓴 데이터가 복원되지는 않습니다. lesson two/note.txt에 다른 문장을 만들고 루트에서 두 파일을 각각 읽어 보세요. 경로와 파일을 구분하고 공백을 처리하며 실패 후 위치를 알면 통과입니다. 그림의 1, 2, 3은 위치 확인, 읽기, 검증입니다.

PowerShell 경로는 [Microsoft Set-Location 문서](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/set-location), Codex 시작은 [공식 CLI 문서](https://learn.chatgpt.com/docs/codex/cli)로 2026-09-14에 확인했습니다. Windows 명령은 격리된 실습 폴더에서도 확인합니다. macOS/Linux 부분은 일반 셸 작업 설명이며 실제 기기 화면으로 제시하지 않습니다. 다음으로 [Markdown](article:codex-markdown-basics)과 [AGENTS.md](article:codex-agents-md)를 읽습니다.

| 목적 | PowerShell | macOS/Linux |
| --- | --- | --- |
| 현재 위치 | Get-Location | pwd |
| 파일 목록 | Get-ChildItem -Name | ls -a |
| 하위 이동 | Set-Location -LiteralPath '.\lesson one' | cd 'lesson one' |
| 파일 읽기 | Get-Content -LiteralPath '.\note.txt' | cat note.txt |
| 상위 이동 | Set-Location -LiteralPath '..' | cd .. |
