## 목표와 준비

> 올바른 CLI 세션을 재개하고 다른 프로젝트의 같은 파일명을 구분하며 최신 디스크 상태를 읽은 뒤 계속합니다. 읽기 12분, 실습 20분입니다. 세 OS의 인증된 CLI와 편집기를 사용합니다. 터미널 경로를 알아야 하며 Git/검색/실제 데이터는 필요 없습니다.

resume는 이전 대화/세션을 잇고 디스크를 되돌리지 않습니다. 자신이나 다른 작업이 편집한 파일을 다시 확인합니다. [fork](article:codex-project-management)의 새 작업 생성, [호스트 이전](article:codex-cross-device-workflow)과도 구분합니다.

## 1단계: 구별할 수 있는 실습 두 개 만들기

같은 상위 폴더에 codex-session-a와 codex-session-b를 만들고 각각의 note.txt에 다음 별도 예시를 저장합니다. 한 파일에 둘 다 넣지 않습니다. 이름은 같고 표식은 달라 파일명만으로 위치를 추측할 수 없습니다. 상위 위치를 기록하고 시작 전에 확인합니다.

```text
SESSION-A
Revision: 1
```

```text
SESSION-B
Revision: 100
```

A의 통합 터미널에서 Get-Location 또는 pwd로 codex-session-a를 확인하고 실행합니다. 다음 요청으로 A의 실제 경로, SESSION-A, Revision: 1과 무변경을 확인합니다. 목록의 제목/시간을 기록합니다.

```sh
codex --cd . --sandbox read-only
```

```text
Read note.txt from the current directory without changing files. Report the exact directory and both lines. This is a session-resume exercise. Do not search other folders or infer content from the filename.
```

/exit로 A를 종료해 셸로 돌아오고 B에서 같은 절차를 합니다. SESSION-B, Revision: 100을 확인하고 종료합니다. B가 최신이어도 다음에는 A를 찾아야 하므로 하나뿐인 최근 작업보다 선택을 확실히 검증할 수 있습니다.

## 2단계: 목록에서 A 재개

A의 셸에서 codex resume를 실행하고 경로/시간/미리 보기를 확인해 A를 선택합니다. 다른 경로는 --all로 찾되 전체 최신을 목표와 같다고 보지 않습니다. 화면 조작 안내를 따르고 Enter 전에 경로를 읽습니다.

```sh
codex resume
```

```sh
codex resume --all
```

현재/저장 경로가 다르면 CLI가 위치를 물을 수 있습니다. A를 선택하고 /status와 새 읽기로 확인합니다. tui.resume_cwd나 --cd가 있으면 동작이 달라지므로 [설정 문제 해결](article:codex-config-troubleshooting)을 참고하며 질문이 안 떴다는 이유만으로 맞다고 하지 않습니다.

| 방법 | 용도 | 먼저 확인 |
| --- | --- | --- |
| codex resume | 목록 선택 | 경로/시간/내용 |
| codex resume --last | 현재 경로의 최신 | 정확한 현재 경로 |
| codex resume --all | 다른 경로도 표시 | 최신이 목표인지 확인 |
| codex resume SESSION_ID | 알려진 ID 지정 | 실제 ID로 대체 |
| /resume | CLI 내부 목록 | 셸 아닌 Codex에 입력 |

## 3단계: 재개 후 최신 디스크 읽기

A를 종료하고 A/note.txt 둘째 줄만 Revision: 2로 바꾸며 B는 보존합니다. A에서 다음을 실행합니다. --last는 현재 경로의 최신을 대상으로 하고 --all은 범위를 넓힙니다. A에 다른 작업도 있으면 목록/알려진 ID를 쓰고 최신을 추측하지 않습니다.

```sh
codex resume --last --sandbox read-only
```

다음을 보내 이전 대화의 1과 디스크의 2, 그대로인 SESSION-A를 확인합니다. 차이는 실습이며 기억 속 숫자로 되돌려 고칠 결함이 아닙니다. 테스트 기록/미커밋 변경/인계가 현재 버전과 맞는지도 같은 방식으로 확인합니다.

```text
Resume by reading note.txt from disk again now. Compare the current revision with the earlier conversation. Report the current directory, the file marker, and any difference. Do not restore an older value or edit any file.
```

## 문제 해결, 중단, 복구

안 보이면 OS/사용자/CODEX_HOME/호스트와 --all을 확인합니다. 데스크톱/CLI의 같은 제목을 같은 세션 저장소로 가정하지 않습니다. B를 골랐으면 추가 요청을 멈추고 /exit 후 A를 고릅니다. 이미 썼다면 실제 변경 경로를 보고 종료를 취소로 취급하지 않습니다. 오래된 버전에는 새 읽기/경로 확인을 요청합니다.

지침 파일 변경 후에는 현재 작은 단계를 마치고 새 세션으로 검증합니다. resume를 이전 지침의 만능 초기화로 보지 않습니다. [규칙 범위](article:codex-agents-md-scopes)와 [문맥 인계](article:codex-context-handoff)로 결정/실제 파일/미완료를 남기고 요약을 백업으로 보지 않습니다.

A/B 식별, 재개의 새 읽기, --last/--all 차이를 남깁니다. A만 1로 복원하고 B는 100인지 확인하며 세션/인증은 삭제하지 않습니다. 명령은 공식 문서/help 확인이며 독자의 실행/자동 동기화를 보장하지 않습니다. 실제 작업도 작업/경로/버전부터 확인합니다.

그림 1은 A/B 구별, 2는 올바른 세션 선택, 3은 디스크 재읽기와 버전 확인입니다. 재개할 때 세 가지를 확인합니다.
