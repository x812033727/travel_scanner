## 목표와 준비

> 플러그인 오류를 검증 가능한 한 계층으로 좁힌 뒤 같은 문서를 다시 요청합니다. 읽기 15분, 실습 20분입니다. [설치와 연결](article:codex-plugins)의 가상 문서를 준비하고 운영 작업 공간 대신 자신의 연습 연결만 확인하세요. 사용 가능한 플러그인이 없어도 환경과 오류 기록은 만들 수 있지만 읽기 성공으로 표시할 수는 없습니다.

## 1단계: 실패 상태 기록

날짜, OS, 진입점, 버전, 플러그인 전체 이름, 출처, 로그인 방식과 실패한 단계를 기록합니다. Windows, macOS, Linux에 같은 형식을 사용하며 CLI 버전은 터미널, 데스크톱 버전은 앱 정보나 업데이트 화면에서 확인하세요. 같은 PC의 데스크톱에서 사용된다고 CLI에도 설치된 것은 아닙니다. 원격 호스트도 따로 적고 이 글의 확인 날짜를 버전으로 복사하지 마세요.

```sh 터미널: CLI 버전 확인
codex --version
```

```markdown plugin-incident.md
# Plugin incident
Date and time zone:
OS / surface / version:
Local or remote host:
Plugin name and source:
Sign-in method (no secrets):
Failing step:
Exact error (redacted):
Practice document revision:
Change attempted:
Retest result:
```

공유할 오류에서 이메일, 비공개 문서 식별자, 토큰, 쿠키를 가립니다. 인증 URL에 일회용 코드가 있을 수 있으니 자료나 문의 기록에 붙여 넣지 마세요. 오류 종류, 시각, 재현 절차를 남기고 서버 기록은 제공자의 지원 절차로 다룹니다. 한 번에 한 조건만 바꿔야 계정, 새 대화, 권한 중 무엇이 해결했는지 알 수 있습니다.

## 2단계: 증상으로 확인 계층 선택

| 증상 | 먼저 확인 | 관찰 결과 |
| --- | --- | --- |
| Plugins 없음 | 지원 진입점 | 지원 환경에서 목록 열림 |
| 목록에 있지만 설치 불가 | 출처와 작업 공간 정책 | 상세 정보 또는 관리 제한 확인 |
| 설치됐지만 도구 없음 | 활성 상태와 새 대화 | 새 작업에서 기능 선택 가능 |
| 로그인 요청 | 외부 계정 연결 | 올바른 계정 인증 |
| 특정 문서만 실패 | 문서 권한 또는 URL | 같은 계정에서 원본 열림 |
| 오래된 답변 | 도구 실행과 문서 버전 | 새 읽기에서 새 표식 확인 |

이 표는 진단 순서이며 오류 코드의 의미를 보장하지 않습니다. 401은 흔히 인증, 403은 접근 거부와 관련되지만 제공자의 응답을 해석하세요. 파일 없음, 권한 부족, 공유 변경이 비슷하게 표시될 수 있습니다. 429나 일시 장애에서는 재시도 안내를 기록하고 나중에 같은 작은 문서를 요청하세요. 반복 대량 요청이나 전체 드라이브 공개로 해결하지 않습니다.

## 3단계: 진입점·설치·활성화 확인

데스크톱 Plugins의 Installed와 상세 정보를 확인하세요. CLI는 codex 실행 후 /plugins에서 marketplace와 설치 항목을 확인하며 Space로 설치 항목을 켜거나 끕니다. 기존 작업에 이전 기능 목록이 남을 수 있으므로 설치나 재활성화 후 새 작업에서 시험하세요. 이전 결과는 보존하며 대화 삭제나 전체 설정 폴더 초기화는 필요하지 않습니다.

```text Codex CLI 대화형 슬래시 명령
/plugins
```

IDE 확장은 Plugins를 지원하지 않으므로 메뉴가 없는 것을 설치 손상으로 판단하지 말고 데스크톱이나 CLI에서 확인하세요. iOS와 Android Chat/Work는 해당 진입점에 제공되는 플러그인을 사용하며 Desktop only는 모바일에서 실행할 수 없습니다. Linux 미리 보기나 개별 요건도 확인하고 미지원으로 기록합니다. [기기 간 작업](article:codex-cross-device-workflow)을 참고하세요.

## 4단계: 계정과 문서 접근 분리

플러그인과 같은 외부 계정으로 제공자 사이트에서 연습 문서를 열고 제목과 Revision을 확인합니다. 다른 계정으로 로그인한 브라우저에서 열리는 것은 플러그인 계정의 접근 증거가 아닙니다. 불일치는 제공되는 재연결 절차로 수정하고 새 작업에서 같은 URL을 요청하세요. 특정 문서만 거부되면 소유자와 공유 대상을 확인하고 자신의 연습 파일은 필요한 계정에만 허용합니다.

ChatGPT 로그인과 OpenAI API key 로그인은 다르며 OAuth가 필요한 일부 플러그인은 API key 방식에서 사용할 수 없습니다. 상세 정보와 [계정](article:codex-account-usage)을 확인하세요. 서비스 암호를 config.toml에 넣거나 OAuth 해결을 위해 전면 허용으로 바꾸지 않습니다. 호스트 샌드박스와 외부 문서 권한은 별개라 하나를 완화해도 다른 계층의 성공이 보장되지 않습니다.

## 5단계: 실제 도구 결과로 재검증

```text 새 작업 요청: 연습 URL 교체
Use the selected plugin to read my practice document at <PRACTICE_DOCUMENT_URL>.
Return its title, source link, Revision, Document marker and task counts.
Use a fresh tool result. If access fails, report the tool error and stop.
Do not edit, share, move or delete anything. Do not infer missing contents.
```

자리 표시자를 연습 URL로 바꾸고 지원 선택기에서 플러그인이나 기능을 지정하세요. 읽었다는 문장만 보지 말고 도구 활동을 확인하여 제목, 출처, 현재 Revision, 표식, 개수를 원본과 비교합니다. 실행이 없으면 기능이 로드됐는지 확인하고 거부 응답이면 원래 오류를 남겨 이전 대화에서 답을 만들어 내지 않게 합니다.

원본 사이트에서 Revision과 확인 가능한 개수 하나를 직접 바꾸되 새 개수를 Codex에 알려주지 마세요. 다른 새 작업에서 같은 요청을 실행합니다. 오래된 값이면 복사본 URL, 저장 완료, 지원되는 새로 읽기 방법을 확인하고 지연을 기록하세요. 두 번째 정답은 이 사례의 증거이며 모든 문서와 진입점이 복구됐다는 뜻은 아닙니다.

## 판독 연습: 읽기 실패의 세 가지 경우

> 외부 계정이 없는 독자도 연습할 수 있는 가상 장애 기록입니다. Google Drive 실측 결과나 보편적인 오류 코드 규칙이 아닙니다. 증거로 다음 한 단계를 고른 뒤 해설과 비교하고, 실행하지 않은 수정을 성공으로 기록하지 않습니다.

| 사례 | 확인된 증거 | 아직 모르는 점 |
| --- | --- | --- |
| A | 데스크톱 Installed에는 있지만 같은 기기의 IDE에서 실패하며 도구 호출이 없음 | 지원되는 화면의 새 작업에서 가능한지 |
| B | 새 작업에 도구가 있지만 서비스가 접근을 거부하고 같은 외부 계정으로 원본 사이트도 열 수 없음 | 이 계정에 문서 접근 권한이 있어야 하는지 |
| C | 원본 사이트는 Revision 3을 저장했지만 실제 도구 호출은 Revision 2를 반환하며 출처 링크는 미확인 | 복사본을 읽었거나 갱신이 반영되지 않은 것인지 |

A는 Plugins를 지원하지 않는 IDE 대신 데스크톱이나 CLI의 새 작업에서 확인합니다. 연결 성공은 아직 미확인입니다. B는 URL, 계정, 공유 대상을 확인하고 권한이 있을 때만 연습 문서 접근을 수정합니다. 재설치가 문서 권한을 부여하지는 않습니다. C는 반환된 출처와 지정 URL을 비교한 뒤 재조회 시각과 버전을 기록합니다. 근거 없이 모델 기억이나 캐시로 단정하지 않습니다. 매번 같은 문서로 재검사하며 계정 전체를 공개하지 않습니다.

에이전트가 말로 ‘성공’이라고 한 것뿐이면 실제 읽기는 미확인으로 둡니다. 반대로 도구가 거부를 반환했다면 ‘호출했지만 실패’이지 ‘로드 안 됨’이 아닙니다. 이 구분을 장애 기록에 반영하면 다음 담당자가 올바른 화면이나 서비스를 점검할 수 있습니다.

## 자주 발생하는 문제와 복구

제거 버튼이 없으면 관리자 배포나 기본 항목인지 확인하고 제한을 기록합니다. 제거는 해당 환경의 묶음을 없애며 별도 MCP 연결은 남을 수 있습니다. 연습 종료 시 설치 상태와 외부 연결 관리를 각각 확인하고 필요하면 자신의 연습 인증만 취소하세요. 공유 연결을 보존하고 한 번의 연결 해제를 모든 기기 비활성화로 해석하지 않습니다.

기록을 보고 자신이 바꾼 한 조건을 복원합니다. 일시 중지 항목 활성화, 올바른 연습 계정 재연결, 문서 권한 복원 중 해당하는 작업입니다. 새 작업이 계속 실패하면 진입점, 출처, 가린 오류, 시도한 수정, 예상과 실제 결과를 유지 관리자에게 전달하세요. 무한 재설치 대신 서버 설정은 [MCP 문제 해결](article:codex-mcp-troubleshooting)로 이어갑니다.

## 검증과 다음 단계

완료 기준은 원래 실패, 원인 계층, 한 변경, 같은 문서의 새 도구 결과, 원본에 도구 쓰기 없음, 연습 연결 유지 또는 취소 상태를 재현 가능하게 남기는 것입니다. 도구 결과가 없으면 진입점 제한이나 인증 대기로 기록합니다. 이 절차는 공식 문서 확인이며 사용자 계정·OAuth·실제 휴대폰에서 시험했다고 주장하지 않습니다. 기사 표시 테스트도 연결 증거가 아닙니다.

[스킬 검증](article:codex-skill-testing)과 기록을 구분합니다. 스킬 로드가 외부 연결을 증명하지는 않습니다. [템플릿과 요약표](article:codex-templates-cheatsheet)에 항목을 모아 관찰값을 갱신하고 날짜와 미재현 사례를 남기세요.
