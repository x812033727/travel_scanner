## 목표와 두 가지 시작 경로

> Linux 또는 WSL2에서 CLI를 설치하고 호스트, 배포판, 파일 위치를 구분해 표식 파일 읽기 전용 검증과 업데이트를 진행합니다. 읽기 약 12분, 실습 약 30분이며 최초 WSL 설치, 재부팅, 다운로드는 별도입니다. 2026-09-14 공식 문서로 확인했으며 Linux/WSL 실기 실행은 하지 않았습니다. Windows 이미지를 Linux 화면으로 제시하지 않습니다.

Linux 컴퓨터에서는 터미널을 열고 2단계부터 시작합니다. Windows 사용자는 Linux 도구가 필요한지 먼저 결정하세요. 네이티브 PowerShell에서도 Codex를 실행하므로 WSL이 필수는 아닙니다. 기존 Linux 작업 흐름이나 의존성이 있을 때 WSL2를 선택합니다. [Windows CLI](article:codex-cli-windows)의 대안이며 모든 Windows 설치 오류에 자동으로 이주하는 방식은 아닙니다.

그림의 1은 명령 입력 환경 식별, 2는 설치와 Linux 프로젝트 이동, 3은 같은 환경에서 파일 검증입니다. Linux 홈, 도구, 인증 정보는 기본적으로 별도입니다. Windows의 codex --version 성공은 Ubuntu 내부 설치를 증명하지 않으며 WSL 인증만으로 Windows 데스크톱 로그인까지 확인할 수 없습니다.

## 1단계: Windows에서 WSL2 확인하기

Windows PowerShell에서 아래를 실행해 배포판과 VERSION 값이 2인지 확인합니다. Linux 셸 명령이 아닙니다. 기존 WSL2는 유지하고 재설치하거나 삭제하지 않습니다. 현재 Codex Linux 샌드박스는 WSL1을 지원하지 않습니다. 작업이 WSL1에 있으면 먼저 백업하고 Microsoft 문서로 변환을 계획하며 유일한 사본으로 실험하지 마세요.

```powershell Windows PowerShell: 설치된 WSL 배포판만 조회
wsl --list --verbose
```

먼저 winver를 확인하세요. Microsoft의 wsl --install 간편 설치에는 Windows 11 또는 Windows 10 2004(빌드 19041) 이상이 필요합니다. 이전 버전은 아래 명령을 그대로 쓰지 말고 공식 수동 설치 절차를 확인합니다. WSL이 없다면 가상화와 WSL 허용 여부를 확인하고 Microsoft 안내에 따라 관리자 PowerShell에서 wsl --install을 실행합니다. 필요한 재부팅과 Linux 사용자 생성을 마칩니다. npm 패키지 하나가 아닌 운영체제 환경을 설치하므로 다른 작업을 중단할 시간도 확보하세요. 관리 장치는 정책을 따릅니다.

```powershell 관리자 PowerShell: WSL이 없고 설치를 결정한 경우에만 실행
wsl --install
```

배포판이 여러 개라면 PowerShell에서 wsl --distribution 뒤에 목록의 전체 이름을 필요에 따라 따옴표로 넣습니다. 설치 전에 배포판을 선택하세요. A에서 codex를 찾았다고 B에서도 사용할 수 있다는 뜻은 아닙니다. 이후 PowerShell로 돌아오면 명령을 찾는 위치를 다시 확인하고 Linux 설치나 파일 해시 기록을 Windows에 그대로 적용하지 마세요.

설치 후 Terminal에서 배포판을 선택하거나 일반 PowerShell의 wsl로 기본 배포판을 엽니다. 여러 배포판이면 목록에 나온 실제 이름을 선택하고 Ubuntu가 있다고 가정하지 마세요. 들어가면 프롬프트와 경로가 Linux 형식이 됩니다. 이후 단계는 모두 이 Linux 셸에서 실행합니다.

## 2단계: 셸, CLI, 홈 폴더 식별하기

```bash Linux/WSL 셸: 시스템, 위치, 명령 출처 확인
uname -s
pwd
printf '%s\n' "$WSL_DISTRO_NAME"
command -v codex
type -a codex
```

uname은 Linux가 예상됩니다. WSL_DISTRO_NAME은 WSL 배포판을 나타내며 일반 Linux에서 비어 있어도 정상입니다. command -v와 type -a가 의도한 Linux 설치를 가리키는지 봅니다. /mnt/c 아래 Windows 래퍼는 Linux 네이티브 설치 증거가 아닙니다. 원본을 기록하고 Linux 안에 설치한 뒤 실제 선택 명령을 다시 확인합니다.

새 설치는 공식 독립 명령을 확인해 실행하고 PATH 안내를 읽은 뒤 새 Linux 터미널을 엽니다. 기존 npm 사용자는 같은 Linux 안에서 node/npm 버전을 확인하고 npm install -g @openai/codex를 쓸 수 있습니다. Windows Node.js가 Linux 설정을 대신하지 않습니다. 한 경로를 선택해 업데이트도 일치시킵니다.

```bash Linux/WSL 셸: 공식 독립 설치 경로
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

```bash Linux/WSL 셸: 설치 후 새 창에서 출처와 버전 확인
command -v codex
codex --version
codex --help
```

설치 출력, 실행 경로, 버전을 맞춥니다. curl, sh, 기본 도구가 없다면 다른 배포판 명령을 복사하지 말고 자신의 배포판 문서로 준비하세요. CLI 실행만으로 프로젝트 의존성이나 샌드박스 작동이 검증되지는 않으므로 다음 파일 작업으로 확인합니다.

## 3단계: Linux 홈에 실습 만들기

Linux 도구로 실행하는 WSL 작업은 ~/code 같은 Linux 홈을 우선합니다. /mnt/c는 Windows 파일 시스템 마운트이며 /home 프로젝트의 다른 이름이 아닙니다. 실습 때문에 실제 저장소를 이동하지 마세요. 아래는 폴더가 이미 있으면 덮지 않고 멈추므로 필요하면 새 이름을 선택합니다. 서브셸에서 실행되므로 끝난 뒤 명시적으로 이동합니다.

```bash Linux/WSL 셸: 블록 전체로 새 실습 폴더 만들기
(
  set -e
  cd ~
  mkdir 'codex linux lab'
  cd 'codex linux lab'
  printf '%s\n' 'LINUX-CLI-01' > note.txt
  cp note.txt note.original.txt
  pwd
  ls
)
```

생성 성공 후에만 다음 블록을 실행합니다. mkdir의 File exists는 기존 데이터를 보호한 결과이며 sudo를 붙일 이유가 아닙니다. 새 폴더를 선택하세요. 이동 후 두 파일, LINUX-CLI-01, 같은 SHA-256을 확인합니다. 같은 로컬 바이트를 비교하는 것이며 Windows 파일 해시와 일치할 필요는 없습니다.

```bash Linux/WSL 셸: 생성 성공 후 이동, 읽기, 확인
cd ~/"codex linux lab"
pwd
cat note.txt
sha256sum note.txt note.original.txt
```

## 4단계: 같은 Linux 환경에서 인증하고 읽기

```bash Linux/WSL 셸: 한 줄이 완료된 후 다음 줄 실행
codex login
codex login status
codex --sandbox read-only
```

각 명령을 기다리고 실제 인증 안내를 따릅니다. WSL이 호스트 브라우저를 쓰더라도 Linux 터미널에서 완료를 확인합니다. 브라우저나 로컬 콜백을 쓸 수 없으면 login --help와 공식 인증 페이지를 보세요. 계정과 조직이 허용할 때만 --device-auth를 사용하고 Windows 인증 파일을 프로젝트로 복사해 해결하지 마세요.

```text 자연어 요청: Linux의 Codex CLI 안에 입력
Read note.txt and note.original.txt in the current Linux practice directory. Report the current directory and the exact marker, and check whether both files match. Do not edit, create files, or use external services. Stop and report any missing file or access error.
```

bash 명령이 아닌 Codex 요청입니다. Linux 실습 폴더, LINUX-CLI-01, 실제 읽기 기록을 확인합니다. 이어서 같은 Codex 세션에서 없는 note-missing.txt를 요청해 생성 없이 없다고 명시하는지 확인합니다. 마친 뒤 /exit로 셸에 돌아와 sha256sum, cat, ls로 변경이 없음을 봅니다. 두 결과로 설치, 인증, 위치, 읽기를 하나의 흐름으로 검증합니다.

## 파일 위치, 업데이트, 문제 해결

| 위치나 도구 | 환경 | 확인 방법 |
| --- | --- | --- |
| C:\Users 경로 | 네이티브 Windows | PowerShell의 Get-Location |
| /home 프로젝트 | Linux / WSL 파일 시스템 | Linux의 pwd |
| /mnt/c 프로젝트 | Linux에 마운트된 Windows 드라이브 | /home 사본과 혼동하지 않기 |
| Linux codex | Linux 셸이 선택한 CLI | command -v와 버전 함께 확인 |

/mnt/c의 Linux 도구 작업이 느리면 유일한 원본을 옮기거나 지우기 전에 Linux 홈의 새 연습 사본으로 비교합니다. 탐색기에서는 공식 문서의 `\\wsl$` 입구로 실제 배포판을 선택합니다. Linux 파일 접근이며 두 사본 동기화가 아닙니다. 같은 이름만 보지 말고 표식과 pwd로 구분하세요.

업데이트 전에 CLI를 종료하고 요약을 남깁니다. 독립 버전은 Linux 공식 설치 프로그램, npm 버전은 같은 Linux의 npm을 사용하고 새 셸에서 경로와 버전을 확인합니다. wsl --update는 Codex가 아닌 WSL 업데이트입니다. wsl --shutdown은 실행 중인 WSL 작업을 중지하므로 매번 Codex 설치의 필수 단계로 쓰지 않습니다.

셸은 읽지만 Codex가 못 읽으면 샌드박스 시작/접근 오류를 기록하고 WSL2와 배포판을 확인한 뒤 [권한](article:codex-permissions)을 점검하며 일괄 해제하지 않습니다. 이전 세션이 없으면 배포판, Linux 사용자, CODEX_HOME 변경을 확인합니다. 이 글은 환경 간 인증 폴더를 공유하지 않습니다. [CLI 기초](article:codex-cli-getting-started)에서 수정과 복구를 마치고 [맥락 인계](article:codex-context-handoff)로 이어가세요.
