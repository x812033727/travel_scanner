## 목표: 기기를 바꿔도 같은 작업 확인

> 인계 기록을 만들고 다른 Remote 지원 기기에서 읽기를 이어 간 뒤 새 파일 표식으로 실행 위치를 확인합니다. 읽기 12분, 실습 25분입니다. Mac/Windows 호스트와 페어링된 iPhone/Android를 준비합니다. 지원하는 두 번째 데스크톱에서도 이어 할 수 있습니다. 뒤의 선택 Handoff 실습은 같은 Git 프로젝트를 저장한 다른 호스트가 필요합니다.

손에 든 제어 기기, 대화가 있는 작업, 파일/셸을 제공하는 호스트를 구분합니다. 휴대전화에서 노트북으로 바뀌어도 제어 기기만 바뀔 수 있습니다. Handoff는 실행 호스트를 바꾸며 클라우드는 또 다른 환경입니다. 같은 작업 제목이나 폴더명만으로 실제 자료를 식별할 수 없습니다.

흐름도 1은 호스트/경로 확인, 2는 새 읽기 요청, 3은 파일 내용과 결과 비교입니다. 순서대로 수행합니다. 목록에 호스트가 보이는 것은 1의 일부일 뿐 2와 3의 성공을 뜻하지 않습니다.

| 동작 | 실행 위치 | 파일 출처 |
| --- | --- | --- |
| 휴대전화 Remote 재개 | 원래 호스트 | 해당 호스트 파일 |
| 다른 데스크톱으로 제어 | 원래 호스트 | 같은 호스트 프로젝트 |
| 다른 호스트로 Handoff | 대상 worktree | 작업/Git 상태 이전 후 확인 |
| 새 클라우드 작업 | 클라우드 | 선택한 저장소 버전 |

## 1단계: 확인 가능한 인계 정보 기록

[Remote 설정](article:codex-remote-setup)의 codex-remote-lab에서 host-marker.txt의 REMOTE-LAB-A, Revision: 1과 원래 request.txt를 확인합니다. 호스트 편집기로 handoff.md를 만들고 관찰한 사실을 적습니다. 호스트 별칭을 써도 되며 비공개 절대 경로는 공개 이미지에 넣지 않습니다.

```markdown 호스트 파일 양식: 작성한 뒤 handoff.md로 저장
# Remote reading handoff

Goal: read this practice folder without modifying files.
Controller: record the device currently sending requests.
Execution host: record the host shown by Remote.
Project: codex-remote-lab
Working directory: record the actual directory reported by the host.
Task: record the exact task title or identifier.
Marker: REMOTE-LAB-A / Revision: 1
Git state: not initialized for this basic Remote exercise.
Verified: record only checks actually performed, with time.
Pending: fresh read from the second controller.
Next action: read host-marker.txt again and compare the revision.
```

record…를 실제 확인 정보로 바꿉니다. 제목이 겹치면 식별자, 프로젝트, 최근 메시지도 비교합니다. 내부 ID가 안 보이면 실제 제목과 시간을 적습니다. 기본 실습에는 Git이 없으므로 브랜치/커밋을 지어내지 않고 Git 프로젝트라면 이 정보와 미커밋 변경을 추가합니다.

## 2단계: 제어 기기를 바꾸고 새로 읽기

휴대전화 Remote에서 원래 호스트/작업을 선택합니다. 다른 지원 Mac/Windows는 Settings → Connections → Control other devices로 연결하고 같은 작업을 엽니다. 배포 범위에 따라 안 보이면 페어링된 휴대전화를 사용합니다. 각 제어 기기는 대상 호스트마다 연결되어야 하며 같은 로그인만으로 페어링을 확인할 수 없습니다.

수정 요청 전에 인계 기록을 읽고 새 기기에서 다음 요청을 보냅니다. REMOTE-LAB-A, Revision: 1, 작업 경로, 원래 호스트를 확인합니다. 호스트명을 얻지 못하면 미확인으로 남기고 Remote 표시와 비교합니다. 파일 표식을 측정된 컴퓨터 이름으로 제시하지 않습니다.

```text 자연어 요청: 다음 제어 장치에서 원래 작업으로 전송
Continue this exact Remote reading task. Read handoff.md and host-marker.txt from disk now, without modifying files. Report the current working directory and both marker lines. Identify the execution host if the tools expose it; otherwise state that it is unverified. Distinguish this fresh read from facts copied from earlier messages.
```

## 3단계: 버전 변경으로 오래된 내용 구별

호스트에서 host-marker.txt 둘째 줄만 Revision: 2로 저장하고 첫 줄과 request.txt는 보존합니다. handoff.md는 잠시 1로 둔 채 다른 기기에서 다시 읽게 합니다. 디스크 2와 기록 1의 차이를 지적해야 합니다. 1만 반복하면 경로, 호스트, 실제 재읽기를 확인합니다.

```text 자연어 요청: 같은 모바일 Remote 작업에 입력
Read host-marker.txt and handoff.md again from the current project. Compare their revision values. Report any disagreement; do not assume the handoff note is newer than the file. Do not edit either file.
```

차이를 확인한 뒤 handoff.md 표식을 2로 바꾸고 Verified에 기기/시간을 적습니다. 프로그램 테스트는 안 했으므로 전체 성공이라고 쓰지 않습니다. 실습을 초기화하려면 둘 다 1로 돌리고 다시 읽습니다. 이 제한된 복구는 다른 코드/작업을 취소하지 않습니다.

## 심화: 다른 호스트로 실행 Handoff

지금까지는 제어 기기만 바꿨습니다. 실행을 옮기려면 [Git 기초](article:codex-git-basics)로 독립 저장소를 준비하고 연결된 두 호스트에 같은 저장소 프로젝트를 저장합니다. 원본이 하위 폴더면 대상도 대응하는 하위 폴더여야 합니다. 일치하는 프로젝트가 없으면 설정을 보완하며 작업명 변경으로 대신하지 않습니다.

원본 실습 저장소에서 다음 읽기 명령을 실행하고 결과/중요 diff를 남깁니다. PowerShell, macOS, Linux 모두 같지만 올바른 경로가 전제입니다. not a git repository면 시작 조건이 아닙니다. 빈 브랜치는 detached HEAD일 수 있으니 커밋을 기록하고 확인합니다.

```sh 호스트 터미널: 실제 작업이 실행되는 Git 실습 저장소 조회
git rev-parse --show-toplevel
git rev-parse HEAD
git branch --show-current
git status --short
git diff --stat
git diff --cached --stat
git ls-files --others --exclude-standard
```

### 같은 커밋이라고 인계가 완전한 것은 아니에요

위 조회는 Git 루트, 커밋, 브랜치, 상태, 스테이징하지 않은 차이, 스테이징한 차이, 추적하지 않는 파일을 기록합니다. git diff --stat에는 스테이징한 변경과 미추적 파일이 포함되지 않으므로 이것만 기록하면 작업이 빠질 수 있습니다. 필요한 ignored 파일, 데이터베이스, 외부 데이터는 따로 기록하며 이 조회로 해당 자료가 전송되었다고 판단하지 않습니다.

사례: 원본 호스트에는 스테이징한 note.md, 스테이징하지 않은 core.mjs, 미추적 local-note.txt가 있습니다. 대상 호스트는 커밋이 같지만 상태가 깨끗하고 local-note.txt가 없습니다. 기준 버전은 같아도 세 작업 내용은 완전히 확인되지 않았으므로 인계 완료로 표시할 수 없습니다. 양쪽의 새 수정을 멈추고 기존 기록과 보존할 내용을 비교한 뒤 누락을 처리하세요. 휴대전화 대신 노트북으로 같은 호스트를 제어하는 경우에도 새로 읽어 확인하되 파일을 다시 옮길 필요는 없습니다.

데스크톱의 대상 작업 하단 실행 위치에서 대상 호스트/브랜치를 확인하고 Hand off를 선택합니다. 대상 worktree로 작업/Git 상태가 이전되며 실행 중 응답은 중단됩니다. 실습은 검토 가능한 지점에서 진행합니다. 다른 작업에 자연어로 요청할 때 대상과 호스트를 명시하며 요청하는 작업 자체는 옮길 수 없습니다.

성공 후에도 이 Git 실습에 필요한 파일, 경로, 커밋, diff와 새 worktree를 확인합니다. 앞의 host-marker.txt는 별도의 비 Git 실습 폴더에 있으므로 이번 이전에서 예상하는 파일이 아닙니다. 미추적 자료, DB, 환경 변수, 도구, 사이트 인증까지 옮겨졌다고 가정하지 말고 필요한 것을 확인한 뒤 재개합니다. 돌아오려면 This computer를 선택하고 재확인합니다. Codex cloud는 Handoff 대상이 아니므로 [클라우드 절차](article:codex-cloud-tasks-github)를 사용합니다.

## 문제 해결과 완료 기준

작업 누락은 호스트/워크스페이스/페어링/프로젝트를 먼저 확인합니다. 오래된 응답은 Revision: 2 재읽기, 대상 누락은 저장된 저장소/하위 폴더, 새 호스트 실행 실패는 도구/의존성을 확인합니다. 이전 성공은 테스트 성공이 아닙니다. 끊긴 뒤 상태를 먼저 보고 두 호스트에 쓰기 요청을 중복 전송하지 않습니다.

작성한 handoff.md, 두 버전의 새 읽기, 오래된 기록과의 차이, 복구 확인을 남깁니다. 실제 두 번째 호스트를 썼을 때만 Handoff 전후/도구 검사를 추가하고 안 했다면 미실측으로 적습니다. 진입점은 공식 문서로 확인했으며 단일 로컬 폴더를 실제 호스트 이전이라고 주장하지 않습니다. [긴 작업의 인계](article:codex-context-handoff)에도 적용할 수 있습니다.
