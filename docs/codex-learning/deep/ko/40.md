## 목표: 휴대전화가 연결된 작업 환경 확인하기

> Mac/Windows 호스트에서 Remote를 설정하고 자신의 iPhone/Android를 연결한 뒤 호스트, 폴더, 파일 표식을 검증합니다. 읽기 약 12분, 최초 실습 약 25분이며 업데이트와 인증은 별도입니다. 제품 경로는 2026-09-14 공식 문서로 확인했으며 실물 휴대전화 페어링, 호스트 절전, 원격 연결 실측 기록은 아닙니다.

Remote는 휴대전화에서 요청, 승인, 후속 질문을 보내고 호스트가 파일, 도구, 로그인 서비스를 제공합니다. 전화가 데스크톱 도구 실행 환경이 되거나 Codex 클라우드 업로드가 완료된다는 뜻은 아닙니다. [모바일 개요](article:codex-mobile-guide)를 확인하세요. iOS와 Android는 대안이며 둘 다 필요하지 않습니다. 기존 컴퓨터 한 대를 쓰고 서버를 빌리지 않습니다.

흐름도 1은 호스트/경로 확인, 2는 새 읽기 요청, 3은 파일 내용과 결과 비교입니다. 순서대로 수행합니다. 목록에 호스트가 보이는 것은 1의 일부일 뿐 2와 3의 성공을 뜻하지 않습니다.

## 시작 전: 양쪽 기기와 작업 위치

Codex를 쓸 수 있는 같은 계정/워크스페이스의 지원 데스크톱 호스트가 깨어 있고 온라인이며 앱이 실행 중이어야 합니다. 공식 모바일 앱을 업데이트하고 필요한 SSO, MFA, 패스키 인증을 마칩니다. 관리자가 Remote Control을 켜야 할 수도 있습니다. 단계적 제공이므로 Remote가 없으면 버전, 워크스페이스, 이용 자격부터 확인합니다.

공식 모바일 Remote 호스트는 macOS와 Windows입니다. Linux 미리 보기가 있다는 이유만으로 같은 페어링 지원을 추정하지 않습니다. 최초 설정은 데스크톱 앱에서 시작하며 CLI나 IDE 로그인으로 대신할 수 없습니다. Git, Node.js, 브라우저, Skills, MCP도 휴대전화가 보충하지 않으므로 실행 호스트에서 확인합니다.

## 1단계: 식별 가능한 호스트 프로젝트 준비하기

호스트에 새 codex-remote-lab 폴더를 만들고 첫 블록은 host-marker.txt, 둘째는 request.txt로 저장합니다. REMOTE-LAB-A는 가상 실습 표식이며 실제 호스트 이름이 아닙니다. 앱에 표시된 장치명과 실제 경로는 별도로 기록하세요. 폴더가 있으면 새 이름으로 기존 데이터를 보존합니다.

```text 호스트 파일 내용: host-marker.txt로 저장
REMOTE-LAB-A
Revision: 1
```

```text 호스트 파일 내용: request.txt로 저장하며 휴대전화에서 실행하지 않음
Read the host marker and report it. Keep both files unchanged.
```

폴더를 데스크톱 프로젝트에 추가하고 경로와 두 파일을 보고하는 읽기 전용 작업으로 호스트 접근을 확인합니다. Windows는 Get-Location/Get-Content, macOS는 pwd/cat으로도 확인합니다. 로컬 성공 기준을 먼저 확보해 원래 없는 파일을 원격 연결 실패로 오해하지 않도록 합니다.

## 2단계: 호스트에서 접근을 켜고 휴대전화 페어링하기

작업을 받을 호스트에서 Settings → Connections → Control this Mac or PC의 Set up/Add를 선택하고 접근과 인증 절차를 마칩니다. 같은 계정의 다른 빈 컴퓨터를 설정해도 이 호스트 폴더가 자동 제공되지는 않습니다. QR은 장치와 호스트 페어링용이므로 공개 자료에 넣거나 타인에게 보내지 않습니다.

자신의 iPhone/Android로 스캔해 공식 ChatGPT의 Remote 설정을 열고 같은 계정과 워크스페이스를 확인합니다. 성공하면 전화의 Remote 목록에 호스트가 보여야 합니다. 전화-호스트 쌍마다 페어링이 필요하며 양쪽 로그인만으로는 증거가 아닙니다. 링크가 브라우저에 머물면 앱 업데이트와 열기 경로를 확인합니다.

호스트에서 연결 허용과 깨어 있기 설정을 확인합니다. Mac 노트북은 전원을 연결하고 덮개를 열며 Sleep을 선택하면 연결 가용성이 멈춥니다. Windows Computer Use 작업은 잠금 해제되고 사용 가능한 세션이 필요합니다. 이 읽기 실습에 모든 브라우저나 데스크톱 제어를 켤 필요는 없습니다. 다른 사용자가 있으면 시간을 조정하세요.

## 3단계: 세 가지 증거로 확인하기

휴대전화 Remote에서 해당 호스트, codex-remote-lab, 기존 작업을 골라 아래를 보냅니다. 호스트 연결이 없는 일반 채팅은 파일 접근을 보장하지 않습니다. 새 작업을 만들면 실행 위치를 다시 확인하고 같은 작업명으로 같은 환경이라고 판단하지 마세요.

```text 자연어 요청: 같은 모바일 Remote 작업에 입력
In this host project, read host-marker.txt and request.txt without changing files. Report the host/environment name if available, the actual working directory, and both files' exact contents. Do not infer unavailable information or use other services. If either file is missing, stop and report that.
```

실제 경로, REMOTE-LAB-A와 Revision: 1, request.txt 원문이 나와야 합니다. 호스트명을 얻지 못하면 표식을 실제 장치명으로 삼지 말고 확인 불가라고 해야 합니다. 컴퓨터에서 두 파일을 독립적으로 열고 읽기 기록과 변경 없음을 확인합니다. 호스트 선택, 경로, 내용은 별도 검증이며 빠진 항목은 미확인으로 남깁니다.

작업이 끝나면 최신성도 시험합니다. 호스트 편집기에서 둘째 줄만 Revision: 2로 바꾸고 저장한 뒤 전화에서 요약이 아닌 새 파일 읽기를 요청합니다. 2가 예상되며 1이면 오래된 응답, 저장 안 됨, 다른 폴더를 점검합니다. 마지막에 호스트에서 1로 복원하고 다시 읽어 반복 가능하게 만듭니다.

## 연결 끊김과 원격 접근 중지

현재 작업이 끝난 뒤 호스트 연결 허용을 잠시 끄고 전화 접근을 확인한 다음 호스트에서 다시 켜 재연결을 확인합니다. 모든 페어링 장치에 영향을 줄 수 있어 다른 원격 작업이 없는지 먼저 확인합니다. 연결 가용성, 페어링 삭제, 작업 취소는 서로 다른 상태로 점검하세요.

공식 문서는 로그아웃이 Remote Control을 끄지만 페어링은 남고 재로그인 후 다시 켜야 할 수 있다고 설명합니다. 영구 장치 해제로 간주하지 마세요. 개별 페어링은 호스트 Connections의 현재 장치 목록과 관리 동작을 확인하고 원래 장치에서 제어가 사라졌는지 검증합니다. 모든 버전의 공통 삭제 버튼명은 문서에서 확정하지 않습니다.

### 연결, 페어링, 작업 상태를 나누어 기록하기

사례: Remote Control을 끈 후 휴대전화로 제어할 수 없지만 호스트의 작업은 실행 중으로 표시됩니다. 확인한 것은 원격 접근 중지이며 작업 취소나 기기 페어링 해제가 아닙니다. 작업을 멈추려면 해당 작업의 중지 동작과 결과를 따로 확인하세요. 기기를 해제하려면 Connections의 관리 동작과 원래 기기의 제어 가능 여부를 따로 확인합니다. 해당 버전에 명확한 제거 동작이 없으면 해제는 미확인으로 기록하며 로그아웃을 영구 해제로 대신하지 않습니다.

```text 개인 상태 메모: 관찰 결과를 작성하며 명령으로 실행하지 않음
Checked at: [time and timezone]
Controller and execution host: [your private labels]
Remote Control: [on / off / unknown]
Device pairing: [present / removed / unknown]
Task execution: [running / stopped / completed / unknown]
Last fresh file read: [time, path and revision / not verified]
Action taken: [exact control used / none]
Next verification: [what remains to check]
```

| 증상 | 먼저 확인 | 증거 |
| --- | --- | --- |
| Remote 없음 | 업데이트, 계정, 제공 범위 | 실제 입구 표시 |
| 호스트 없음 | 페어링, 앱, 연결 허용 | 올바른 호스트 표시 |
| 다른 파일 | 작업 위치, 버전, 읽기 기록 | 경로와 Revision: 2 일치 |
| 연결 끊김 | 절전, 네트워크, 앱 종료 | 복구 후 현재 파일 새로 읽기 |

## 완료 조건과 관련 강의

알림 한 번이 아닌 호스트 식별, 올바른 경로 새로 읽기, 갱신된 표식, 원격 접근 중지 방법까지 확인해야 완료입니다. 작업에서 도구와 결과를 확인하세요. 다음은 [iPhone](article:codex-mobile-ios), [Android](article:codex-mobile-android), [기기 간 인계](article:codex-cross-device-workflow)입니다. 컴퓨터가 꺼져도 별도 환경에서 실행하려면 [클라우드 작업](article:codex-cloud-tasks-github)의 환경과 결과 흐름을 배웁니다.
