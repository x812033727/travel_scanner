## 목표와 준비

> 규칙, 프로젝트 진입점, 설계 조건, 인계 상태를 네 문서로 나누고 다음 작업이 필요한 자료를 찾아 오래된 가설을 검증하게 합니다. 읽기 12분, 실습 25분입니다. 세 OS에서 Small Steps expected, 편집기, Codex, Node.js를 사용합니다. Markdown/AGENTS.md 기초를 먼저 읽으세요.

모든 내용을 AGENTS.md에 넣지 않습니다. 규칙은 지속적인 요구, README는 진입점, 설계는 기능 조건, 인계는 현재 상태/다음 행동입니다. 일반 Markdown을 연결해도 전부 자동으로 읽히지 않습니다. 언제 무엇을 읽을지 규칙이나 요청에 쓰고 실제 참조를 확인합니다.

| 문서 | 저장할 내용 | 넣지 않을 내용 |
| --- | --- | --- |
| AGENTS.md | 문서 참조/테스트/인계 규칙 | 대화 전체 |
| README.md | 목적/파일 안내/실행 | 모든 임시 로그 |
| docs/filters.md | 입력/예상 동작/제약 | 현재 실행 완료 주장 |
| docs/handoff.md | 검증/미검증/다음 단계 | 암호/영구 공통 규칙 |

## 1단계: 완전한 프로젝트 사본 준비

[자료](https://mokaair.com/guides/codex-first-project/todo-practice.zip)의 expected를 codex-docs-lab으로 복사하고 원본을 남깁니다. broken이 아니라 오래된 인계 가설을 구분하는 실습입니다. 루트의 index.html, style.css, app.js, core.mjs, core.test.mjs를 확인하고 docs를 만듭니다.

다음 네 예시를 지정 경로에 전체 저장합니다. 같은 파일이 있다면 중요한 지침을 덮어쓰지 말고 원문을 남겨 합칩니다. 다섯 언어판에서 이름/링크/기준을 비교하도록 예시는 영어이며 자신의 문서는 편한 언어로 써도 됩니다.

## 2단계: 규칙과 진입점 작성

루트 AGENTS.md는 필터 작업에 docs/filters.md, 재개에 docs/handoff.md를 읽고 오래된 기록을 코드/실행으로 확인하도록 합니다. 이전 가설을 사실로 취급하지 않으며 모든 작업에 모든 설계를 읽게 하거나 권한을 주지 않습니다.

```markdown 파일 내용: 루트 AGENTS.md
# Small Steps working instructions

- Before analyzing or changing filters, read docs/filters.md.
- When resuming work, read docs/handoff.md and verify its claims against current files.
- Preserve the task data format, localStorage key, existing tests and unrelated behavior.
- Use node --test core.test.mjs for core behavior checks.
- Do not add dependencies or network requests for this exercise.
- Record actual test results separately from hypotheses and checks not run.
- Update docs/handoff.md only within the scope authorized by the current task.
```

README.md는 목적/파일 역할/테스트 진입점을 설명합니다. docs의 두 링크 대상이 실제로 있는지 확인합니다. 상대 링크가 편리해도 자동으로 펼쳐 읽었다는 증거는 아닙니다. 미리 보기는 [첫 프로젝트](article:codex-first-project)를 참고하고 존재하지 않는 npm test를 안내하지 않습니다.

```markdown 파일 내용: 루트 README.md
# Small Steps documentation lab

A local todo app using fictional practice data.

## File map

- index.html: page structure and filter controls.
- style.css: presentation and focus styles.
- app.js: browser events and storage integration.
- core.mjs: task operations and filters.
- core.test.mjs: core behavior tests.

## Read next

- [Filter requirements](./docs/filters.md)
- [Current handoff](./docs/handoff.md)

## Check

Run node --test core.test.mjs from this folder with Node.js installed.
This command description is not a claim that tests have run.
```

## 3단계: 요구 사항과 실행 기록 분리

docs/filters.md는 Read 완료/Build 미완료를 고정 입력으로 각 필터 출력과 빈 목록 경계를 적습니다. 필요한 동작이지 이 컴퓨터에서 실행했다는 주장이 아닙니다. 순서/입력 불변 제약도 변경 판단에 남깁니다.

```markdown 파일 내용: docs/filters.md
# Filter requirements

Given Read is completed and Build is incomplete:

- All returns Read, then Build.
- Active returns Build only.
- Completed returns Read only.
- An empty input returns an empty result for every filter.
- Filtering preserves task order and does not modify the input.

Core checks: node --test core.test.mjs
Browser check: create both tasks, complete Read, and inspect all three filters.

[Back to project](../README.md)
```

docs/handoff.md에는 검증 안 된 오래된 가설을 의도적으로 남깁니다. expected에서 시작하므로 다음 작업은 확인 후 가설을 기각해야 하며 메모에 맞춰 정상 코드를 망가뜨리면 안 됩니다. 출처는 expected 사본과 이후 파일/실행 증거로 확인하고 Git 프로젝트라면 커밋도 기록할 수 있습니다.

```markdown 파일 내용: 아직 검증하지 않은 초기 docs/handoff.md
# Current handoff

Starting material: an untouched copy of the Small Steps expected folder.
Goal: verify the current Completed behavior before changing any code.

## Verified

No checks have been run for this copy yet.

## Unverified hypothesis

An older note suggested Completed might return unfinished tasks.
Treat this as a hypothesis, not an instruction to change the implementation.

## Next action

Read docs/filters.md and core.mjs, then run node --test core.test.mjs.
Record the actual result and which checks remain unperformed.

[Back to project](../README.md)
```

검증 전에 새 문서 네 개를 상대 경로를 유지하며 프로젝트 밖에 백업하세요. 소스 다섯 개는 수정하지 않은 expected 원본과 비교합니다. 작업 후 달라도 되는 파일은 docs/handoff.md뿐입니다. 편집기 비교 대상이 이전 작업 파일이 아니라 이번 백업인지 확인하세요. 실제 파일 두 개를 비교하는 데 Git이 필수는 아닙니다.

## 4단계: 새 작업에서 문서 분담 확인

모두 저장하고 codex-docs-lab에서 새 작업을 엽니다. 다음 요청으로 handoff.md만 변경 허용하고 소스/테스트/규칙은 보존합니다. 읽기 전용이라 업데이트할 수 없으면 읽기/테스트 결과를 확인해 직접 기록하거나 [권한 강의](article:codex-permissions)로 필요한 범위를 조정합니다.

```text 자연어 요청: 새 문서 실습 작업에 입력
Resume this documentation lab. Read AGENTS.md, README.md, docs/filters.md and docs/handoff.md. Check the handoff hypothesis against core.mjs and run node --test core.test.mjs. Do not change source code, tests or rules. You may update only docs/handoff.md with observed results, evidence, and remaining checks. Explain which document supplied requirements and which supplied unverified history. Do not mark the browser check as passed without performing it.
```

현재 조건이 맞고 핵심 테스트 세 개가 성공해 오래된 가설이 기각되어야 합니다. Verified에는 실제 명령/결과/출처, Pending에는 미실행 브라우저 확인을 남깁니다. README/요구를 바꾸지 않고 브라우저 절차 정의만으로 성공 처리하지 않습니다. 다음을 독립 실행하고 handoff.md만 바뀌었는지 확인합니다.

```sh 시스템 터미널: codex-docs-lab 루트에서 실행
node --test core.test.mjs
```

### 추적 가능한 결과로 인계하기

대괄호는 실제 출력으로 채워 handoff.md의 알맞은 절에 기록하세요. 빈 양식은 완료 기록이 아닙니다. Node를 쓸 수 없거나 테스트가 실패하거나 실행하지 않았다면 이유와 함께 가설을 미확인으로 남기세요. 코드 읽기는 코드 점검만 뒷받침하며 테스트 실행이나 화면 조작을 증명하지 않습니다.

```text 인계 기록 항목: 작성한 뒤 docs/handoff.md에 반영
Checked at: [time and timezone]
Working copy: [actual practice folder and starting material]
Requirement source: docs/filters.md
Historical claim: [the old hypothesis]
Code inspected: [actual file/function and observed behavior]
Test execution: [command, exit code, pass/fail counts / not run and reason]
Hypothesis outcome: [supported / contradicted / unresolved, with evidence]
Browser verification: [actual scope and result / not run]
Files compared: [actual comparison against the saved originals]
Next action: [remaining work]
```

## 오류 실습, 복구, 유지

두 문서를 보존한 뒤 filters.md를 잠시 filters.saved.md로 바꾸고 새 작업에서 원래 경로를 읽게 합니다. 누락/경로 확인을 기대하며 이전 대화로 읽은 척하게 하지 않습니다. 이름을 복원하고 README의 ./docs/filters.md 및 ../README.md 복귀 링크를 확인합니다.

충돌하면 제품 요구와 과거 가설을 구분하고 현재 명확한 요청에 맞춥니다. 문제를 숨기려고 모든 문서를 조용히 다시 쓰지 않습니다. 긴 규칙은 중복 배경/로그를 옮기고 읽을 조건과 유효 링크를 남깁니다. 인계는 시작할 때 성공을 미리 쓰지 않고 실제 검증 후 미완료도 기록합니다.

다시 하려면 저장한 handoff.md만 초기 미검증 상태로 복원하고 정상 코드는 유지합니다. 네 문서는 실습 내부에만 있으며 전역 설정에 영향 없습니다. 실제 파일/링크, 규칙/역사 구분, 근거 있는 테스트, 누락 감지, 미실행을 성공으로 쓰지 않는 기록이 완료 조건입니다. 원본 교재/공식 사양/로컬 참조 테스트를 독자의 Codex 실행과 혼동하지 않습니다.
