## 목표와 Android의 역할

> Android의 ChatGPT Remote에서 호스트 Codex 작업을 찾아 파일 읽기, 후속 질문, 앱 전환, 원래 작업 복귀를 연습합니다. 읽기 약 12분, 실습 약 25분이며 페어링 대기는 별도입니다. 제품 경로는 2026-09-14 OpenAI Remote 문서로 확인했습니다. QR은 Google이 지원하는 카메라 기능을 예로 들며 다른 브랜드는 해당 카메라를 따릅니다. 실물 Android 테스트나 제품 화면이라고 주장하지 않습니다.

Android은 요청과 결과 표시를 맡고 소스 파일, 터미널, 의존성, 로그인된 사이트는 호스트가 제공합니다. 휴대전화 ChatGPT 설치가 CLI 설치나 파일 앱 동기화를 뜻하지 않습니다. [모바일 개요](article:codex-mobile-guide)와 [호스트 설정](article:codex-remote-setup)으로 연결, 작업, 실행을 구분합니다.

## 시작 전: 호스트와 계정 준비하기

Mac/Windows 데스크톱 앱을 업데이트하고 Android과 같은 계정/워크스페이스의 Codex 접근을 확인합니다. [Small Steps](https://mokaair.com/guides/codex-first-project/todo-practice.zip)의 expected를 codex-android-lab으로 복사하고 원본을 보존합니다. 페어링 전에 호스트의 다섯 소스를 확인하며 비공개 실제 프로젝트 대신 실습 자료를 사용합니다.

Google Play에서 OpenAI를 확인하고 공식 ChatGPT를 업데이트합니다. Play 계정과 ChatGPT 로그인은 별개이므로 앱 안에서 호스트와 같은 계정/워크스페이스인지 확인합니다. 개인/업무 프로필이나 관리 앱이 있으면 어느 ChatGPT를 열었는지 봅니다. 아이콘이 같아도 인증과 정책이 같지는 않습니다. SSO, MFA, 패스키를 마친 뒤 Remote로 진행합니다.

## 1단계: 카메라로 Remote 설정 열기

호스트 Settings → Connections → Control this Mac or PC에서 Set up 또는 Add를 선택하고 인증해 QR을 표시합니다. Android의 지원 카메라·스캐너로 전체 코드를 잡아 감지한 링크를 여세요. Google Pixel 문서는 카메라·빠른 설정을 설명하지만 다른 브랜드는 각 설명을 따릅니다. 모델에 페어링을 맡기려고 QR 이미지를 대화로 보내지 않습니다.

감지하지 못하면 전체 코드·초점·반사를 확인하고 Pixel은 카메라 스캔 제안 설정도 확인합니다. 링크를 열 앱을 물으면 공식 ChatGPT와 올바른 업무 프로필을 선택하세요. 브라우저에 남으면 버전·로그인을 확인한 뒤 필요할 때 호스트에서 재설정합니다. 한 번의 연결로 모든 URL 기본값을 바꾸거나 페어링 정보·계정 화면을 공개하지 않습니다.

전화에서 계정, 워크스페이스, 호스트를 확인합니다. Remote에 대상이 보이고 codex-android-lab과 Codex 작업을 열 수 있어야 합니다. 로그인 완료 화면만으로는 부족합니다. 다른 PC라면 대상 호스트의 설정을 다시 확인합니다. 그림의 1은 전화 입구, 2는 선택한 호스트, 3은 검증 가능한 결과입니다.

## 2단계: 명확한 파일 읽기 요청하기

Remote 프로젝트 작업 입력창에 아래를 붙입니다. 키보드 자동 수정이 파일명이나 함수명을 바꾸지 않았는지 확인하세요. Android에서 터미널 명령을 실행하는 것이 아닙니다. 한 번 전송하고 응답을 보며 앱 전환 후 찾을 작업명 등을 기록합니다.

```text
Read this Small Steps project without changing files. Confirm the working directory and inspect app.js and core.mjs. Identify the localStorage key, the field that records completion, and the function that rejects blank task titles. Cite the file for each answer. If a file is unavailable, report that instead of guessing.
```

app.js의 mokaair-codex-todo-v1, core.mjs의 completed와 addTask 공백 검사, 실제 경로를 확인합니다. 일반적인 할 일 앱 설명뿐이면 읽은 파일을 묻습니다. 경로가 틀리면 멈추고 올바른 호스트/프로젝트를 선택하세요. 그럴듯한 설명만으로 파일에 연결됐다고 볼 수 없습니다.

## 3단계: 후속 질문, 승인 내용, 진행 상황 확인하기

```text
In the same project, explain what happens when I add Read and Build, complete Read, and choose Completed. Then explain an empty task title. Separate code you inspected, tests actually run, and checks still pending. Do not edit or clear stored data.
```

같은 작업 맥락을 확인합니다. Completed는 Read만 보이고 공백은 거절되어야 하며 읽은 코드, 실행한 테스트, 미검증 화면을 나눠야 합니다. 코드 분석은 예상 동작이며 전화 실측이 아닙니다. 컴퓨터 로컬 미리 보기에서 직접 조작해 검증을 보탭니다.

승인이 뜨면 동작, 폴더, 범위를 요청과 대조합니다. 읽기 실습에 외부 계정 추가, 웹사이트 공개, 삭제는 필요하지 않습니다. 긴 명령이 잘 안 보이면 호스트에서 확인하세요. 승인이 안 나타나도 새 작업을 반복 생성하지 말고 원래 Remote 작업 상태를 봅니다.

## 4단계: 나갔다 같은 작업으로 돌아오기

읽기 응답 완료 후 다른 Android 앱으로 전환했다가 최근 앱이나 홈 화면에서 ChatGPT → Remote의 같은 호스트/작업으로 돌아옵니다. 기기마다 제스처와 버튼이 달라 위치를 고정하지 않습니다. 마지막 응답을 보고 폴더를 새로 읽게 하며 캐시 글만으로 온라인이라 판단하지 않습니다. 로그인 환경이 다르면 프로필을 먼저 확인하고 같은 프로젝트를 다시 만들지 마세요.

알림은 완료나 주의 신호이며 결과 검증을 대신하지 않습니다. 알림이 없어도 작업을 열어 보세요. 호스트 절전, 연결 끊김, 앱 종료는 복구한 후 이전 요청 완료 여부를 확인합니다. 이후 쓰기 작업에서는 전화 연결이 끊겼다는 이유만으로 생성이나 제출을 다시 보내지 않습니다. 먼저 읽기로 복구를 익힙니다.

## 완료 확인과 흔한 오해

| 확인 | 충분한 증거 | 부족한 증거 |
| --- | --- | --- |
| 페어링 | 올바른 Remote 호스트 선택 가능 | 같은 계정 로그인만 |
| 읽기 | 경로, 저장 키, 함수 출처 | 일반 할 일 앱 설명 |
| 재개 | 같은 작업의 새 읽기 | 이전 알림이나 응답 |
| 검증 | 호스트 파일과 동작 확인 | 근거 없는 성공 선언 |

호스트 localhost URL을 Android 브라우저에 넣으면 전화 자신을 가리킵니다. Remote의 호스트 결과나 캡처를 보고 로컬 미리 보기는 컴퓨터에서 확인합니다. 공개 미리 보기/배포는 별도입니다. [호스트 설정](article:codex-remote-setup)으로 접근을 관리하고 작업 취소는 별도로 확인하세요. 로그아웃이 페어링을 자동 삭제하지 않습니다.

같은 작업에서 호스트/폴더, 확인 내용, 미실행 테스트, 다음 단계를 정리하고 컴퓨터에서 대조합니다. 호스트 도구를 쓰려고 Android에 Node.js를 설치할 필요가 없으며 의존성은 실행 호스트에 둡니다. [기기 간 작업](article:codex-cross-device-workflow), [맥락 인계](article:codex-context-handoff), 또는 [iPhone 강의](article:codex-mobile-ios)의 같은 검증으로 이어가며 프로젝트를 다시 쓸 필요는 없습니다.
