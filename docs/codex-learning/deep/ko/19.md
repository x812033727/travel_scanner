## 목표와 준비

> 독립 Git 실습에서 브랜치/차이/지정 파일 스테이지·commit/미커밋 복원/commit 취소를 연습합니다. 읽기 15분, 실습 30분입니다. Git 2.28 이상, 편집기, expected 실습을 씁니다. 세 OS 공통이며 로컬 기록만 만들고 GitHub/push는 필요 없습니다.

[터미널 경로](article:codex-terminal-paths)를 확인합니다. 작업 트리, 다음 commit용 index, 기록 버전은 별개입니다. 브랜치는 기록 줄이며 미커밋 사본이 아닙니다. 별도 경로는 [worktree](article:codex-worktrees)를 쓰고 브랜치를 백업 완료로 보지 않습니다.

## 1단계: 독립 기준 만들기

다른 프로젝트 밖 codex-git-lab에 expected 다섯 파일을 두고 현재 경로/git --version을 확인합니다. 없으면 공식 OS 설치 후 터미널을 다시 엽니다. 기존 작업 저장소에서 이 초기화를 하지 않습니다.

```sh
git init -b main
git config user.name "Practice Learner"
git config user.email "learner@example.invalid"
git add index.html style.css app.js core.mjs core.test.mjs
git diff --cached --name-only
git commit -m "Add practice baseline"
git status --short
```

줄별 실행해 처음 다섯 파일과 commit 후 무변경을 확인합니다. 이름/예약 도메인은 실습 내 설정이며 GitHub 인증/global이 아닙니다. 기존 서명/hooks 요구면 따르거나 장애를 기록하고 전체 정책을 바꾸지 않습니다.

## 2단계: 브랜치에서 구별할 두 변경

```sh
git switch -c codex/title-lab
git branch --show-current
```

브랜치 확인 후 h1 지정 문구만 Plan one useful step.으로 바꾸고 CSS 끝에 다음 주석으로 별도 미커밋 작업을 흉내 냅니다. 결과는 제목이며 CSS는 보존하되 제목 commit에 섞지 않습니다. 둘 다 실습입니다.

```css
/* KEEP-MY-NOTE */
```

```sh
git status --short
git diff -- index.html style.css
```

차이의 이전/새 줄과 주변을 보고 h1/CSS 주석만인지 확인합니다. 파일 수만으로 판단하지 않습니다. 다음 읽기 요청으로 기존 작업/대상을 식별하며 전체 차이 commit은 요청하지 않습니다.

```text
Inspect this lab's current branch, status and diff without editing, staging or committing. The intended change is only the h1 title in index.html. The KEEP-MY-NOTE comment in style.css represents separate work and must be preserved. Explain what belongs in the title commit and what must stay outside it.
```

## 3단계: 한 파일 스테이지 후 복원 연습

```sh
git add index.html
git diff --cached --name-only
git diff --cached -- index.html
git diff -- style.css
```

스테이지는 index.html만, 일반 차이는 CSS입니다. 다음 첫 줄은 스테이지만 해제해 편집을 남기고 둘째는 index 기준으로 파일을 복원합니다. 실습 변경을 버리려는지 확인해 실행하며 지정 밖 CSS는 보존합니다.

```sh
git restore --staged -- index.html
git restore --worktree -- index.html
git status --short
git diff -- style.css
```

CSS만 변경/h1 복원/주석 보존을 확인합니다. 자기 취소로 별도 작업을 지우지 않습니다. --staged는 실제 편집을 버리지 않고 --worktree는 지정 파일을 복원 원본으로 덮으므로 다릅니다.

## 4단계: 제한 commit과 기록을 남긴 취소

제목을 다시 바꾸고 index.html만 스테이지해 차이를 봅니다. commit은 제목만, CSS는 미커밋으로 둡니다. show로 실제 대상을 확인하며 명령 성공만으로 범위가 맞다고 보지 않습니다.

```sh
git add index.html
git diff --cached --name-only
git diff --cached -- index.html
git commit -m "Update practice title"
git show --format=short --name-only HEAD
git status --short
```

취소 전 작업 트리를 확인합니다. 남은 실습 CSS 주석 보존을 검증한 뒤 이번에는 명시적으로 연습을 끝내 첫 명령으로 그 파일만 되돌립니다. 무변경과 HEAD 제목 commit을 확인해 revert합니다. 실제 별도 변경에는 그대로 적용하지 않습니다.

```sh
git restore --worktree -- style.css
git status --short
git log -1 --oneline
git revert --no-edit HEAD
git log -3 --oneline
git status --short
```

revert는 원래 변경을 남기고 반대 commit을 추가합니다. 이전 h1/기록3개/무변경을 기대합니다. 충돌이면 상태를 읽고 강제 선택하지 않습니다. 미완료 revert 취소는 git revert --abort 절차로 하고 재확인합니다.

## 명령 비교, 문제 해결과 검수

| 목적 | 명령 | 확인 |
| --- | --- | --- |
| 미스테이지 보기 | git diff | 작업 트리/index |
| 다음 commit 보기 | git diff --cached | index/HEAD |
| 스테이지 해제 | git restore --staged -- index.html | 편집 유지 |
| 지정 미커밋 변경 버리기 | git restore --worktree -- index.html | 원본/경로 먼저 확인 |
| commit 취소 | git revert --no-edit HEAD | 대상/무변경 확인, 기록 추가 |

브랜치가 없으면 repository를 확인하고 예상 밖 파일을 add .로 묶지 않습니다. 한 파일에 변경이 섞이면 전체 스테이지에 모두 들어가므로 각 차이를 이해해 처리합니다. CSS 제외/두 restore/revert 기록이 검수 조건입니다. 그림1상태,2제한확정,3복원확인. 다음은 [테스트와 PR](article:codex-testing-review)입니다.
