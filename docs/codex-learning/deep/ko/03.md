## 이 글에서 완성할 것

> 운영체제에 맞는 앱을 설치하고 독립된 실습 폴더를 열어 Codex에 할 일 웹사이트 수정을 요청합니다. 마지막으로 파일 차이와 브라우저에서 결과를 확인합니다. 읽기 약 15분, 설치와 실습 약 25분입니다. 2026-09-14 공식 명칭에 맞춰 ChatGPT 데스크톱 앱이라고 부르며 그 안에서 Codex를 선택합니다. 예전 화면이나 바로가기는 여전히 Codex라고 표시할 수 있습니다.

데스크톱 앱은 작업, 파일, 결과물을 관리합니다. 모델은 요청을 해석하고 작업은 대화와 실행 환경을 보존합니다. 이 차이를 알면 모델 변경을 작업 폴더 변경으로 오해하지 않습니다. 진입점 비교는 [Codex 소개](article:codex-beginner-guide)를 참고하세요.

## 시작 전 준비

인터넷과 Codex를 사용할 수 있는 ChatGPT 계정을 준비하고 [계정과 사용량](article:codex-account-usage)에서 워크스페이스를 확인합니다. 요금제, 한도, 모델 메뉴는 계정마다 다르므로 고정 가격이나 특정 모델을 지정하지 않습니다. 앱이 이미 있다면 제공되는 업데이트 방식으로 갱신한 뒤 아래 진입점을 확인합니다.

[Small Steps 실습 묶음](https://mokaair.com/guides/codex-first-project/todo-practice.zip)을 풀고 expected를 자신의 codex-practice 폴더로 복사합니다. 소스 파일 다섯 개가 있으며 데이터는 가상이고 로그인이나 백엔드는 없습니다. 이번에는 제목과 스타일만 바꾸므로 운영 프로젝트보다 이 복사본을 먼저 사용하세요. 미리보기는 Python 3, 데이터 테스트는 Node.js가 필요합니다.

### 수정 전 사본 보관

expected를 압축 해제한 뒤 파일 관리자로 같은 상위 폴더에 사본 두 개를 만듭니다. codex-practice는 수정용, codex-practice-before는 비교용입니다. 두 폴더 바로 아래에 소스 파일 다섯 개가 있어야 합니다. 백업은 작업 폴더의 하위 폴더가 아닌 외부에 둡니다. Windows에서는 파일 탐색기, macOS에서는 Finder, Linux에서는 파일 관리자를 사용합니다.

Git 저장소를 만들지 않았다면 앱의 Git 차이 보기를 사용할 수 없을 수 있습니다. 이때도 텍스트 편집기에서 같은 이름의 파일을 열어 비교할 수 있습니다. 이 실습을 위해 저장소 전체를 커밋하거나 복원할 필요는 없습니다. 버전 관리가 필요하면 [Git 수업](article:codex-git-basics)으로 이어 가세요.

## 1단계: 운영체제에 맞게 설치

Windows: [ChatGPT 공식 다운로드 페이지](https://chatgpt.com/download/)에서 Windows를 선택하고 공식 설치를 완료한 다음 시작 메뉴에서 ChatGPT를 엽니다. PowerShell을 사용한다면 공식 Windows 문서의 아래 방법도 가능합니다. 바로가기가 없으면 여러 번 내려받기 전에 설치가 끝났는지 확인합니다.

```powershell Windows PowerShell, 선택 가능한 공식 설치 방법
winget install --id 9PLM9XGG6VKS -s msstore
```

macOS: 공식 페이지에서 macOS를 선택하고 내려받은 설치 파일을 열어 안내된 위치에 앱을 설치합니다. 응용 프로그램에서 ChatGPT를 엽니다. 호환되지 않는다는 메시지가 나오면 다운로드 페이지의 현재 요구사항을 확인하세요. 시스템 보호를 끈다고 지원하지 않는 버전이 지원되는 것은 아닙니다. 설치 창을 닫고 설치된 앱을 실행하는지 확인합니다.

Linux: 데스크톱 앱은 미리보기 단계입니다. 공식 대상은 Ubuntu 24.04/26.04 LTS, Debian 13, Fedora 43/44이며 x64와 ARM64 패키지를 제공합니다. 먼저 배포판과 CPU를 확인한 뒤 [Linux 공식 설치 페이지](https://learn.chatgpt.com/docs/linux/linux-app)에서 맞는 파일을 받습니다. 다른 배포판은 이 공식 지원 목록 밖에 있으며 패키지가 설치됐다고 모든 기능을 지원하는 것은 아닙니다.

```bash Linux 터미널, 배포판과 아키텍처 확인
cat /etc/os-release
uname -m
```

Ubuntu/Debian은 .deb, Fedora는 .rpm을 선택합니다. x86_64는 x64, aarch64 또는 arm64는 ARM64입니다. 다운로드 폴더에서 자신의 환경에 맞는 한 줄만 실행합니다. 브라우저가 파일 이름에 번호를 붙였다면 실제 이름을 먼저 확인하세요.

| 시스템 | 아키텍처 | 설치 명령 |
| --- | --- | --- |
| Ubuntu / Debian | x64 | sudo apt install ./chatgpt_amd64.deb |
| Ubuntu / Debian | ARM64 | sudo apt install ./chatgpt_arm64.deb |
| Fedora | x64 | sudo dnf install ./chatgpt.x86_64.rpm |
| Fedora | ARM64 | sudo dnf install ./chatgpt.aarch64.rpm |

앱 메뉴에서 ChatGPT를 열거나 터미널에서 chatgpt를 실행합니다. 이후 업데이트는 배포판 패키지 관리자를 사용합니다. Linux 미리보기는 아직 Computer Use를 지원하지 않으며 네이티브 Wayland도 실험적 제한이 있습니다. 파일 수정과 직접 하는 브라우저 확인은 연습할 수 있습니다. macOS 화면을 Linux 실화면으로 표시해서는 안 됩니다.

## 2단계: 로그인하고 실습 위치 선택

세 운영체제 모두 로그인 후 계정과 워크스페이스를 확인하고 Codex를 선택합니다. 폴더 열기 또는 프로젝트 만들기로 codex-practice를 지정합니다. ZIP이나 상위 폴더가 아닌 index.html 등이 바로 보이는 위치여야 합니다. 로컬 또는 다른 환경을 선택하라는 화면이 나오면 자신의 실습 복사본이 있는 위치를 고릅니다.

New chat을 만들고 먼저 읽기만 요청합니다. 아래는 PowerShell이나 Terminal이 아니라 Codex 작업 입력창에 붙입니다. 수정 전에 다른 프로젝트, 압축되지 않은 파일, 다른 호스트를 선택한 문제를 찾을 수 있습니다.

```text Codex 데스크톱 새 작업 입력창, 작업 위치 확인
Before editing, report the current working folder and list the exercise files.
Read index.html and explain how the page loads its JavaScript.
Do not change files. Tell me if the expected five files are missing.
```

실제 폴더 경로와 app.js, core.mjs의 관계가 나와야 합니다. 프로젝트를 이해했다는 말만 믿지 말고 파일 관리자와 경로를 비교하세요. 앱이 worktree 복사본을 만들었다면 그 위치도 확인합니다. [Worktree](article:codex-worktrees)를 참고할 수 있습니다. 이 실습은 Git 저장소 없이도 시작할 수 있습니다.

## 3단계: 확인 가능한 작은 수정 요청

```text 같은 Codex 데스크톱 작업, 전체 요청문
Update this Small Steps practice website.
Change the main heading to "Small steps, clear progress."
Use a dark blue heading color with readable contrast on the existing background.
Keep the form labels, task data format, storage key and behavior unchanged.
Do not add dependencies or external services.
Show the changed files, explain the diff and report checks actually performed.
```

결과가 나오면 파일 또는 변경 보기에서 index.html과 style.css를 엽니다. 제목과 색이 요청과 맞는지, 저장 형식 변경이나 라벨 삭제가 섞이지 않았는지 확인합니다. diff의 추가와 삭제는 비교 결과이며 배포를 뜻하지 않습니다. 처음부터 로그인, 배포, 데이터베이스를 더하기보다 직접 검증할 수 있는 범위를 완성합니다.

### 화면보다 먼저 파일 차이 확인

| 파일 | 이번 요청에서 확인할 내용 |
| --- | --- |
| index.html | 주 제목이 요청한 문자열과 같고 다른 레이블과 문구는 유지됨 |
| style.css | 제목 색상에 필요한 변경만 있음. 대비는 화면에서도 확인 |
| app.js, core.mjs, core.test.mjs | 수정 전 사본과 내용이 같음. 이번 요청은 데이터 로직이나 테스트를 변경하지 않음 |

다른 파일도 바뀌었다면 각 차이의 이유를 확인한 다음 요청 범위 밖의 변경만 되돌립니다. 원인을 가리기 위해 폴더 전체를 덮어쓰지 마세요. “두 파일만 바뀌었다”는 확인도 다음 기능 검증을 대신하지 못합니다.

## 4단계: 브라우저 결과 확인

실습 폴더에서 터미널을 열고 Windows는 아래 명령을 실행합니다. 서버가 터미널을 계속 사용하는 것은 정상입니다. 프롬프트가 돌아오지 않는다고 다시 실행하지 말고 브라우저를 따로 엽니다.

```powershell Windows PowerShell, codex-practice 폴더
py -m http.server 4173 --bind 127.0.0.1
```

```bash macOS / Linux 터미널, codex-practice 폴더
python3 -m http.server 4173 --bind 127.0.0.1
```

http://127.0.0.1:4173에서 제목을 확인하고 Read와 Build를 추가한 뒤 Read를 완료합니다. Active tasks에는 Build만, Completed tasks에는 Read만 보여야 합니다. 새로 고침 후 데이터도 남아야 합니다. 공백뿐인 항목은 추가되지 않는지 정상 흐름과 함께 확인합니다.

개발자 도구의 반응형 모드에서 390과 1280픽셀을 확인하거나 창을 좁혀 봅니다. 글자, 버튼, 폼이 가로로 넘치지 않고 Tab 포커스가 보여야 합니다. 같은 폴더의 다른 터미널에서 node --test core.test.mjs를 실행하면 참고 버전은 테스트 세 개가 통과해야 합니다. Codex에 브라우저 도구가 없으면 직접 화면을 확인하고 에이전트가 실행하지 않았다고 기록합니다.

## 문제 해결, 중지, 복원

Codex가 없으면 앱 업데이트, 계정, 워크스페이스, 사용 가능한 기능 순서로 확인합니다. 재설치를 반복해도 사용량이나 관리자 정책은 해결되지 않습니다. CLI는 별도 진입점이므로 데스크톱 앱을 설치했다고 터미널에서 codex 명령을 찾을 수 있는 것은 아닙니다.

폴더가 다르면 작업의 절대 경로와 파일 다섯 개를 대조합니다. ZIP, 빈 폴더, 다른 프로젝트라면 수정을 멈추고 다시 선택합니다. 이미 생긴 변경은 원래 위치에서 확인하세요. 프로젝트를 바꿔도 파일은 이동하지 않습니다.

빈 화면이나 작동하지 않는 JavaScript는 먼저 file URL이 아닌 http://127.0.0.1:4173인지 확인합니다. 이어 서버 터미널과 브라우저 Console을 확인합니다. 포트가 사용 중이면 자신이 이전에 실행한 서버를 멈추거나 다른 포트를 선택합니다. 포트마다 브라우저 저장 공간이 다릅니다.

Ctrl+C로 미리보기를 멈춥니다. 이번 제목과 스타일만 차이를 보고 복원하고 다른 수정은 보존합니다. Reset practice data는 실습 전용 데이터 삭제이며 코드 복원이 아닙니다. 작업 완료, 테스트 통과, 공개 배포는 각각 다른 상태입니다.

## 추가 실습과 검증 기록

모바일에서는 버튼이 한 줄 전체를 차지하고 데스크톱에서는 입력창 옆에 있도록 요청해 보세요. 수정 전에 현재 CSS를 설명하게 하고 두 너비와 원래 데이터 동작으로 확인합니다. 이미 조건을 충족한다면 변경이 필요 없다는 결과를 받아들입니다.

설치와 기능은 2026-09-14에 [데스크톱 공식 문서](https://learn.chatgpt.com/docs/app), [Windows 문서](https://learn.chatgpt.com/docs/windows/windows-app), Linux 문서로 확인했습니다. 실습 사이트는 Windows/Edge 153의 360, 390, 1280px에서 검증했습니다. 화면은 웹사이트 결과이며 제품 UI, 실제 휴대전화, macOS/Linux 설치 실측이 아닙니다. 다음은 [AGENTS.md](article:codex-agents-md), [Plan 모드](article:codex-plan-mode), [Git 차이](article:codex-git-basics)를 참고하세요.
