## 목표와 iPhone의 역할

> iPhone의 ChatGPT Remote로 호스트 Codex 작업에 들어가 검증 가능한 파일 읽기, 후속 질문, 나갔다 같은 작업으로 복귀, 컴퓨터 검증까지 진행합니다. 읽기 약 12분, 실습 약 25분이며 페어링 대기는 별도입니다. 2026-09-14 OpenAI Remote와 Apple QR 문서로 확인했으며 실물 iPhone 테스트나 iOS 제품 화면이라고 주장하지 않습니다.

iPhone은 요청과 결과 표시를 맡고 소스 파일, 터미널, 의존성, 로그인된 사이트는 호스트가 제공합니다. 휴대전화 ChatGPT 설치가 CLI 설치나 파일 앱 동기화를 뜻하지 않습니다. [모바일 개요](article:codex-mobile-guide)와 [호스트 설정](article:codex-remote-setup)으로 연결, 작업, 실행을 구분합니다.

## 시작 전: 호스트와 계정 준비하기

Mac/Windows 데스크톱 앱을 업데이트하고 iPhone과 같은 계정/워크스페이스의 Codex 접근을 확인합니다. [Small Steps](https://mokaair.com/guides/codex-first-project/todo-practice.zip)의 expected를 codex-iphone-lab으로 복사하고 원본을 보존합니다. 페어링 전에 호스트의 다섯 소스를 확인하며 비공개 실제 프로젝트 대신 실습 자료를 사용합니다.

App Store에서 OpenAI를 확인해 공식 ChatGPT를 설치하거나 업데이트합니다. SSO, MFA, 패스키 요구를 마친 뒤 Remote를 설정합니다. 관리자 활성화와 단계적 제공이 관련될 수 있습니다. Remote가 없으면 버전과 워크스페이스를 기록하고 Safari 변경이나 CLI 재설치를 기능 접근 증거로 삼지 않습니다.

이 글의 조작 예시는 iPhone입니다. iPad에서는 자신의 ChatGPT 앱에 Remote가 실제로 표시되고 호스트를 선택할 수 있는지 먼저 확인한 뒤 같은 파일 읽기 실습을 진행하세요. 공식 페이지는 iOS 접근을 설명하지만 별도의 iPad 화면 배치를 보장하지 않습니다. iPhone 화면으로 iPad 버튼 위치를 추정하거나 이 글을 iPad 실기기 검증 기록으로 보지 마세요.

### 호스트에 자신의 식별 파일 준비하기

codex-iphone-lab 루트에 remote-check.txt를 만들고 아래 줄의 01을 자신만의 표식으로 바꿔 저장합니다. 같은 이름이 있으면 먼저 읽고 다른 작업의 파일을 덮어쓰지 마세요. 다섯 웹사이트 파일에 추가하는 여섯 번째 실습 파일입니다. 사본마다 다른 표식을 쓰며 계정, 비밀번호, 페어링 코드는 넣지 않습니다. 표식과 전체 경로는 개인 메모에 남기고 나중 요청에는 표식 값을 넣지 마세요.

```text 호스트 파일 내용: remote-check.txt, 표식 끝부분을 먼저 바꾸기
IOS-PRACTICE-01
```

## 1단계: 카메라로 Remote 설정 열기

호스트 Settings → Connections → Control this Mac or PC에서 Set up/Add와 인증을 마쳐 QR을 표시합니다. iPhone 카메라 사진 모드에서 코드 전체를 잡고 감지된 링크를 누릅니다. 제어 센터 코드 스캐너도 가능합니다. QR 사진을 챗봇에 업로드하는 것이 아니라 공식 ChatGPT 설정을 여는 링크입니다.

스캔이 안 되면 코드 전체가 보이는 거리, 반사, 사진/스캔 모드를 확인합니다. Safari만 열리면 공식 앱 설치와 로그인을 확인하고 호스트에서 다시 시작합니다. 페어링 URL, QR, 인증 코드, 계정 정보는 공개 질문이나 교재 화면에 넣지 마세요.

전화에서 계정, 워크스페이스, 호스트를 확인합니다. Remote에 대상이 보이고 codex-iphone-lab과 Codex 작업을 열 수 있어야 합니다. 로그인 완료 화면만으로는 부족합니다. 다른 PC라면 대상 호스트의 설정을 다시 확인합니다. 그림의 1은 전화 입구, 2는 선택한 호스트, 3은 검증 가능한 결과입니다.

## 2단계: 명확한 파일 읽기 요청하기

Remote 프로젝트 작업 입력창에 아래를 붙입니다. 키보드 자동 수정이 파일명이나 함수명을 바꾸지 않았는지 확인하세요. iPhone에서 터미널 명령을 실행하는 것이 아닙니다. 한 번 전송하고 응답을 보며 앱 전환 후 찾을 작업명 등을 기록합니다.

```text 자연어 요청: 같은 모바일 Remote 작업에 입력
Read this Small Steps project without changing files. Confirm the working directory and inspect app.js and core.mjs. Identify the localStorage key, the field that records completion, and the function that rejects blank task titles. Cite the file for each answer. If a file is unavailable, report that instead of guessing.
```

app.js의 mokaair-codex-todo-v1, core.mjs의 completed와 addTask 공백 검사, 실제 경로를 확인합니다. 일반적인 할 일 앱 설명뿐이면 읽은 파일을 묻습니다. 경로가 틀리면 멈추고 올바른 호스트/프로젝트를 선택하세요. 그럴듯한 설명만으로 파일에 연결됐다고 볼 수 없습니다.

### 이 복사본만의 표식을 다시 읽기

```text 자연어 요청: 같은 모바일 Remote 작업에 입력
Read remote-check.txt from this task's project now.
Quote its exact content and report the absolute file path and the tool used to read it.
Do not edit files or infer the marker from earlier messages.
If the file is missing or cannot be read, report that limitation.
```

답변을 호스트에 적어 둔 표식과 경로, 도구 읽기 기록과 비교합니다. 표시된 호스트 이름과 파일 표식은 서로 다른 정보입니다. 최신 내용을 읽는지 확인하려면 작업 완료 후 호스트에서 표식만 바꾸어 저장하고 새 값을 알려 주지 않은 채 같은 읽기 요청을 보냅니다. 값이 오래되었거나 도구 증거가 없거나 경로가 다르면 미확인으로 남기고 저장 상태, 호스트, 사본부터 확인하세요.

## 3단계: 후속 질문, 승인 내용, 진행 상황 확인하기

```text 자연어 요청: 같은 모바일 Remote 작업에 입력
In the same project, explain what happens when I add Read and Build, complete Read, and choose Completed. Then explain an empty task title. Separate code you inspected, tests actually run, and checks still pending. Do not edit or clear stored data.
```

같은 작업 맥락을 확인합니다. Completed는 Read만 보이고 공백은 거절되어야 하며 읽은 코드, 실행한 테스트, 미검증 화면을 나눠야 합니다. 코드 분석은 예상 동작이며 전화 실측이 아닙니다. 컴퓨터 로컬 미리 보기에서 직접 조작해 검증을 보탭니다.

승인이 뜨면 동작, 폴더, 범위를 요청과 대조합니다. 읽기 실습에 외부 계정 추가, 웹사이트 공개, 삭제는 필요하지 않습니다. 긴 명령이 잘 안 보이면 호스트에서 확인하세요. 승인이 안 나타나도 새 작업을 반복 생성하지 말고 원래 Remote 작업 상태를 봅니다.

## 4단계: 나갔다 같은 작업으로 돌아오기

읽기 응답 완료 후 다른 앱으로 전환했다가 ChatGPT → Remote에서 같은 호스트/작업으로 돌아옵니다. 마지막 응답과 상태를 보고 현재 폴더를 새로 읽게 합니다. 이전 글이 보인다고 호스트가 지금 온라인이라는 증거는 아니며 새 읽기 성공으로 확인합니다.

알림은 완료나 주의 신호이며 결과 검증을 대신하지 않습니다. 알림이 없어도 작업을 열어 보세요. 호스트 절전, 연결 끊김, 앱 종료는 복구한 후 이전 요청 완료 여부를 확인합니다. 이후 쓰기 작업에서는 전화 연결이 끊겼다는 이유만으로 생성이나 제출을 다시 보내지 않습니다. 먼저 읽기로 복구를 익힙니다.

## 완료 확인과 흔한 오해

| 확인 | 충분한 증거 | 부족한 증거 |
| --- | --- | --- |
| 페어링 | 올바른 Remote 호스트 선택 가능 | 같은 계정 로그인만 |
| 읽기 | 경로, 저장 키, 함수 출처 | 일반 할 일 앱 설명 |
| 재개 | 같은 작업의 새 읽기 | 이전 알림이나 응답 |
| 검증 | 호스트 파일과 동작 확인 | 근거 없는 성공 선언 |

호스트 localhost URL을 iPhone Safari에 넣으면 전화 자신을 가리킵니다. Remote의 호스트 결과나 캡처를 보고 로컬 미리 보기는 컴퓨터에서 확인합니다. 공개 미리 보기/배포는 별도입니다. [호스트 설정](article:codex-remote-setup)으로 접근을 관리하고 작업 취소는 별도로 확인하세요. 로그아웃이 페어링을 자동 삭제하지 않습니다.

마지막에 인증 정보 없이 호스트/폴더, 확인한 내용, 미실행 테스트, 다음 단계를 정리하게 하고 컴퓨터에서 대조합니다. 다음 전화 진행 확인 때 완료 범위를 알 수 있습니다. [기기 간 작업](article:codex-cross-device-workflow), [맥락 인계](article:codex-context-handoff), 다른 전화는 [Android 강의](article:codex-mobile-android)로 이어갑니다.

마치면 호스트에서 이번 실습 중 자신이 만든 remote-check.txt만 제거하고 다섯 웹사이트 파일은 남깁니다. 원래 있던 파일은 삭제하거나 덮어쓰지 않습니다. 표식 검사와 코드 분석 모두 읽기만 요청하며 실제로 수행하지 않은 페어링이나 제품 조작은 미검증으로 기록합니다.
