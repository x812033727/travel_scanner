## このレッスンでできること

> iPhone または Android の ChatGPT から自分の Mac／Windows に接続し、Codex の練習タスクを開いて読み取りを依頼します。結果が正しいホストから来たか確認するまでが目標です。読む時間は約 12 分、初回接続と操作は約 20 分です。まず確認可能な Remote の一連の操作を完成させ、クラウドとの違いも説明します。

スマートフォンは依頼、返信、承認を送り、ファイル、端末、ブラウザ、ツールは接続先ホストが提供します。タスクが見えてもプロジェクトがスマートフォンに保存されたとは限らず、パソコンを切っても動き続けるわけではありません。大きな変更の前に作業場所を見分けます。

## 両方の端末を準備する

パソコンで[デスクトップ入門](article:codex-desktop-getting-started)を終え、[ToDo 教材](https://mokaair.com/guides/codex-first-project/todo-practice.zip)の expected を codex-practice にコピーして開きます。5 ファイルの存在を確認してください。GitHub や別の SSH サーバーは不要です。

iPhone は App Store、Android は Google Play から OpenAI の ChatGPT をインストールまたは更新します。両端末で Codex を利用できる同一アカウントとワークスペースを使います。組織によっては Remote Control の許可、SSO、多要素認証、パスキーが必要です。新しいタスクを増やして回避せず、先に認証要件を満たします。

2026-09-14 時点の公式 Remote 文書は、iOS／Android をモバイル入口、Mac／Windows のデスクトップアプリをホストとしています。段階的な提供であり、Linux プレビューも同じホスト機能を持つとは判断できません。初回接続のデスクトップアプリを CLI や IDE 拡張で代用することもできません。

## 段階 1：パソコンで接続を有効にする

作業するパソコンの ChatGPT デスクトップで Settings → Connections → Control this Mac or PC を開き、Set up または Add を選びます。遠隔アクセスを有効にし、認証を完了します。空のテスト機を接続してしまわないよう、コンピューター名とプロジェクトを確認します。

表示された QR code は、このホストとスマートフォンをペアリングするものです。自分の端末で読み取り、公開用スクリーンショットに入れたり他人へ送ったりしないでください。各ホストに接続設定が必要で、同一アカウントへのログインだけでは全端末が接続済みとはいえません。

Connections で他の端末の接続許可と、利用可能なスリープ防止設定を確認します。ホストはアプリを開き、オンラインで起きている必要があります。Mac ノートはまず電源をつなぎ、ふたを開けて使います。Windows の Computer Use にはデスクトップが利用可能であるなどの追加条件があります。今回はファイルを読むだけなので、すべての操作機能を有効にする必要はありません。

## 段階 2：スマートフォンで接続を完了する

iPhone ではカメラで QR code を読み、リンクを ChatGPT で開いて Remote 設定を進め、アカウントとワークスペースを確認します。ブラウザに留まる場合は最新版アプリを確認し、ホストから接続をやり直します。ウェブの会話履歴は Remote 接続成功の画面ではありません。

Android でも QR code を読み、ChatGPT で開いて認証を完了します。リンクを開くアプリの選択が出たら公式 ChatGPT を選びます。Remote がない場合は更新と再起動、機能の提供状況を確認します。別のモバイルブラウザに変えても未提供機能が使える保証はありません。

両 OS とも、Remote にホストが現れ、選択でき、そのプロジェクトやタスクが見えることが成功条件です。通知は完了や対応依頼を知らせますが、実際の結果はタスクへ戻って確認します。通知だけをファイルの検証結果にしないでください。

## 段階 3：読み取り専用タスクを実行する

Remote で接続したホストを選び、codex-practice の Codex タスクを開きます。新しく作る場合も、作業場所がホストの練習フォルダーか確認します。次は検索欄やシェルではなく、スマートフォンのタスク入力欄へ貼ります。

```text スマートフォンの ChatGPT → Remote → ホスト上の Codex 練習タスク
Read this practice project without changing files.
Report the host or environment name if available and the current working folder.
List index.html, style.css, app.js, core.mjs and core.test.mjs.
Explain how task completion is stored and name the localStorage key.
If you cannot inspect a file, report the limitation instead of guessing.
```

練習パス、保存キー mokaair-codex-todo-v1、completed フィールドの説明がソースに基づいて示されるはずです。パソコンで app.js と core.mjs を照合し、ファイルが変更されていないことも確かめます。一般的な ToDo の知識だけで、パスや根拠がなければ未完了です。

続けて、空白だけのタスクが拒否される理由を具体的なファイル付きで質問します。同じタスクと文脈を継続しているか確認できます。Node.js をスマートフォンに入れる必要はありません。ツールはホスト側のものです。後のレッスンでテストを動かす前に、そのホストに環境があるか確認します。

```text 同じモバイル Remote タスク。追加質問
In the same project, explain what happens when the new task contains only spaces.
Identify the relevant function and file. Do not edit or reset stored data.
```

core.mjs の addTask が文字列を整え、空白を拒否することと、フォームのエラー表示の説明を期待します。パソコンのプレビューで空白を入力して比べられます。正常な読み取りと、空白入力という境界例の両方に照合可能な根拠が必要です。

## 切断時の状態を判断する

読み取り完了後にホストを短時間オフラインにし、スマートフォンが接続不可になる様子を確認できます。書き込み中に意図的な切断テストはしません。ネットとデスクトップアプリを戻したら元のタスクを開きます。オフライン表示は現在接続できないという意味で、直前の処理が実行されなかった証明ではありません。

再接続したら再送前に最後の回答とファイルを確認します。作成、削除、送信を繰り返すと結果が重複する可能性があります。今回は読み取りだけで状態の見分け方を練習してから、書き込みへ進みます。

## Remote、クラウド、スマートフォンの URL

Remote は接続先のプロジェクトとツールを使い、[クラウドタスク](article:codex-cloud-tasks-github)は別に設定した環境を使います。ファイル、ブランチ、依存関係は異なる場合があります。同じようなタイトルでも同じ作業とは限りません。スマートフォンでウェブを開くだけでもパソコンのローカルプロジェクトへのアクセスにはなりません。

パソコンの http://127.0.0.1:4173 の 127.0.0.1 はそのパソコンです。同じ URL をスマートフォンに入れるとスマートフォン自身を指します。Remote タスクでホストが示すプレビューや画像を確認してください。この練習のために公開ポートを開く必要はありません。

## よくある問題と接続解除

ホストが見えない場合は、アプリ実行、接続許可、同一アカウントとワークスペース、スリープしていないことを順に確認します。原因を直してから再接続します。長く使っていない古いペアリングは、公式案内に従い更新と再設定を行います。

接続要求が出ない場合はスマートフォンの Remote を開き、ホストから設定を再開します。組織では管理者が Remote Control を許可したか確認します。ログイン成功と組織の利用許可は別です。管理者に伝えるエラーは残し、認証コードは含めません。

接続できてもファイルがない場合はホスト名と作業パスを調べ、その機械にプロジェクトがあるか確かめます。他のパソコンの同名フォルダーは自動同期されません。タスクの移動には実環境と Git 状態が関わるため、初心者は元のホストで確認を終えます。

不要になったらホストの Settings → Connections で遠隔操作を無効にするか、使わないペアリングを削除します。スマートフォンから操作できなくなったことを確認します。Remote の無効化は変更の復元や全作業の停止を保証しません。実行中のタスクは先にタスク内で停止し、状態を確認します。


| 場所 | 提供するもの | 確認方法 |
| --- | --- | --- |
| スマートフォン | 依頼、追問、承認 | Remote で選んだホストとタスク |
| Mac / Windows ホスト | ファイルとローカルツール | 実パスと内容 |
| クラウド環境 | 別設定のコードと依存関係 | クラウドタスクの環境とブランチ |

## 練習と確認記録

スマートフォンで作業場所、ファイル一覧、未実施の確認をまとめるよう依頼し、パソコンの同じタスクで照合します。同一ホストとパスを示し、確認済み結果と今後の提案を区別できれば成功です。
