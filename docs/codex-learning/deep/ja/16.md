## 目標と準備

> 独立プロジェクトで web_search を設定し、ファイルと有効な層、再起動後の状態を確認して戻します。読む時間12分、操作25分です。Codex CLI、Git、テキストエディターが必要で、各 OS の TOML 内容は同じです。IDE の設定からも開けますが検証は共通の CLI 診断を使います。

[AGENTS.md](article:codex-agents-md) は指示、config.toml はクライアントの設定です。普通の Markdown でモデル名を書いても既定設定は変わりません。TOML に注釈記号なしの説明を書くと解析できないことがあります。低影響の一項目で場所、確認、復元を覚えてから必要な設定を増やします。

## ユーザー設定とプロジェクト設定

ユーザー設定は通常ホームの .codex/config.toml で、既存 CODEX_HOME があれば場所を確認します。プロジェクト側はリポジトリ内の同名パスで、信頼された場合に読まれます。同名でも範囲が違います。本課題はプロジェクトのファイルだけを作り、認証移動や全域・環境変数変更は不要です。

| 環境 | ユーザーの既定位置 | 教材位置 |
| --- | --- | --- |
| Windows | ユーザーフォルダー内 .codex/config.toml | codex-config-lab/.codex/config.toml |
| macOS | ~/.codex/config.toml | 同じ相対パス |
| Linux/WSL | Linux ユーザーの ~/.codex/config.toml | その環境の教材パス |
| IDE | 歯車 → Codex Settings → Open config.toml | 開いた実パスを確認 |

## 手順1：元の状態を記録

新規 codex-config-lab の note.txt に次の一行を保存します。PowerShell の Get-Location、macOS / Linux の pwd で場所を確認し、新規教材で git init を実行してルートを定めます。設定はまだ作りません。同名の別プロジェクトがあればリセットせず新しい場所を使います。

```text
CONFIG-LAB-01
```

シェルで codex --cd . を起動し、信頼確認は作った教材の場所を確認して処理します。内部で次の斜線コマンドを別々に実行します。シェル命令ではありません。/debug-config で層と状態、/status で課題環境を確認し、必要情報だけ記録して私的な診断全文は公開しません。

```text
/debug-config
```

```text
/status
```

/debug-config がなければ / の一覧とシェルの codex --version を確認し、導入元の方法で更新します。同名シェル命令を作りません。版や組織環境で診断が足りなければ有効値は未確認とし、モデルの成功宣言だけで完了扱いしません。記録後 /exit で終了します。

## 手順2：復元可能な一項目を追加

プロジェクト内に .codex/config.toml を作り、ルート直下や .txt ではないことを確認します。既存なら分かる場所にバックアップし、元の値を記録して同じトップレベルキーを変更し、重複追加しません。新規なら次の全文を使えます。

```toml
# Practice setting: disable the built-in web search tool.
web_search = "disabled"
```

キーと値の綴り、半角引用符、# の注釈を守ります。トップレベルキーなので [features] などの下へ無条件に追加しません。表見出しは後続キーの所属を変えます。サイトの外側のバッククォートも入れず、UTF-8 のテキストとして保存し確認します。

## 手順3：再起動して有効な出所を確認

教材ルートから --search、-c、--profile なしで新規起動し、/debug-config のプロジェクト層と有効状態を確認します。未信頼で省略なら出所を確認して通常の信頼手順を行います。診断は低優先から表示する場合があるため、最初の行を勝者とせずラベルと状態を読みます。

有効設定や利用可能ツールの情報とファイルを比較し、次のローカル読み取りを依頼します。CONFIG-LAB-01 と検索なしを期待し、有効値が表示されれば disabled を確認します。一回検索しないだけでは設定成功の証明ではないため、層の診断根拠も残します。

```text
Read note.txt from this practice project and report its exact line. Do not edit files, browse websites or call external services. If you cannot verify an effective setting from available diagnostics, say so rather than inferring it from the file alone.
```

この設定は内蔵検索ツールを無効にするもので全通信遮断ではありません。シェル、ブラウザ、MCP、外部サービスは別の権限と設定を持ちます。[権限とサンドボックス](article:codex-permissions)を参照し、実証のために別ツールで迂回通信しません。

## 手順4：復元して結果を記録

CLI 終了後、新規ファイルなら設定ディレクトリ外へバックアップとして移します。既存なら web_search の元値だけを戻すか追加キーだけを除き、他を保持します。再起動で上書きが消え note.txt が不変か確認します。復元後の値は残る層で決まり、想像した既定値とは限りません。

```text
File changed: codex-config-lab/.codex/config.toml
Original state: record whether the file/key existed.
Requested change: web_search = disabled
Loaded layer: record observed path and enabled/skipped state.
Effective value: record verified value, or unverified.
Local read: record actual note.txt result.
Restoration: record the restored file/key state and fresh-session check.
```

## 問題の切り分けと次の手順

起動不能は指定 TOML と行の引用符、重複キー、表の所属を確認します。値が変わらなければパス、信頼、起動上書き、近い層を確認します。IDE と CLI の差は OS、ユーザー、場所、とくに別々の Windows / WSL ホームを比較し、再インストール前に出所を調べます。

強制要件は一般の既定値と異なり、プロジェクトキーで禁止値を通せません。モデルや推論は[選択記事](article:codex-model-selection)を使い、設定一式のコピーで認証や提供元を替えません。開始、有効、復元と未確認を記録し、[設定の切り分け](article:codex-config-troubleshooting)へ進みます。構文が正しくても各クライアントでの読込み証明ではありません。
