## このレッスンの到達点

> Codex、モデル、タスク、実行環境を区別し、二つのファイルだけを使って「調べる、変更する、自分で確認する」を体験します。読む時間は約 10 分、実習は約 15 分です。プログラミング経験は不要で、この実習ではサイトを公開しません。

## 四つの役割を理解する

Codex は、必要なツールと権限があればファイルを読み、変更し、コマンドを実行できるエージェントです。モデルは推論、タスクは依頼と会話、環境は利用できるファイルとツールを担います。高性能なモデルに変えても、間違ったフォルダーを選んだ問題は直りません。質問するときは入口、作業場所、使えるツールを先に整理しましょう。

ChatGPT との違いをアプリ名だけで判断しないでください。現在の公式デスクトップ文書では、ChatGPT デスクトップアプリ内の Codex 作業が説明されています。プロジェクトに接続しているか、ツールを使えるか、結果が文章だけか実ファイルの変更かを見ます。通常のチャットにツールがある場合も、Codex が分析だけに制限される場合もあります。古い画像やアイコンより、今のタスクの能力を確認します。

ローカル作業は選択したコンピューターのフォルダー、クラウド作業は別に設定した環境を使います。同名のプロジェクトでも未コミットのファイルが自動同期するとは限りません。スマートフォンのリモート作業には接続可能なホストも必要です。[入口の選び方](article:codex-platforms-guide)で比較できます。今回は成果を直接確認しやすいローカルのデスクトップか CLI を使います。

## 独立した練習フォルダーを用意する

Codex にサインインできることを確認します。未導入なら[デスクトップ版](article:codex-desktop-getting-started)か [CLI 入門](article:codex-cli-getting-started)を先に進めてください。今回はテキストエディターと端末だけでよく、GitHub、API キー、Node.js、Python は不要です。ファイル管理画面で書類フォルダー内に codex-orientation を新規作成します。同名があれば別名を選び、既存の練習を残します。

Windows は拡張子を表示し、メモ帳では「すべてのファイル」と UTF-8 で保存します。macOS は RTF ではなく標準テキストを使います。Linux もテキストエディターで、ファイル名の大文字小文字を保ちます。新しいフォルダーに次の二つの完全なファイルを作成してください。拡張子は .md と .txt です。例の外側にあるファイル名は内容に含めません。

一つ目は codex-orientation/README.md。人向けのプロジェクト説明であり、.md だから自動的にエージェントの規則になるわけではありません。

```markdown
# Orientation exercise

This folder contains a fictional packing list.
The list has exactly three items.
No website or package installation is required.
```

二つ目は codex-orientation/packing.txt。各項目を一行ずつ書き、末尾に改行があっても構いません。

```text
Notebook
Bottle
Umbrella
```

## 手順 1：場所を選んで読み取りだけを依頼する

デスクトップ版では codex-orientation をプロジェクトに追加してタスクを作成します。CLI はこのフォルダーで端末を開き、codex を実行します。書類全体を開くと無関係なファイルも対象になるため、練習フォルダーに絞ってから次の依頼を送ってください。比較しやすいよう英語の入力例は各言語で共通ですが、同じ依頼を自分の言葉で書いても構いません。

```text
Inspect this practice folder without changing files.
Report the working directory, list the files, and read README.md and packing.txt.
Explain what this project contains. Cite the filenames supporting your answer.
If a requested file is missing, say so instead of guessing.
```

二つのファイル、三つの持ち物、実行できるサイトではないことが示されるはずです。ファイル管理画面でパスと内容を照合します。表現は同じでなくてもよいですが、元データにない事実を足してはいけません。コマンドの提案だけなら、現在の入口でファイルツールが利用できるか確認してください。操作方法の説明は実行済みの証拠ではありません。

## 手順 2：確認できる変更を一つ依頼する

```text
In packing.txt, replace the line Umbrella with Raincoat.
Preserve the other two lines and leave README.md unchanged.
Do not add files, install tools, or run a website.
After editing, read packing.txt and report exactly what changed.
```

必要なファイル変更を許可した後、packing.txt を開き直します。Notebook、Bottle、Raincoat の三行になり、README.md は同じで、パッケージや余分なファイルが増えていないことを確認します。フォルダー外の権限を求められたら理由を読み、範囲を絞ってください。この実習にコンピューター全体へのアクセスは不要です。制御方法は[権限とサンドボックス](article:codex-permissions)を参照してください。

## 手順 3：失敗時の対応と復元を確認する

次に「missing.txt を読み取るだけにし、なければ説明して作成しない」と依頼します。正しい結果は不存在の報告で、元の二つのファイルがそのまま残ります。ファイルを削除せずに、情報がないときの推測を確認できます。内容を作り上げた場合は、ディレクトリを再確認し、根拠のない説明を訂正させましょう。

復元するにはエディターで Raincoat を Umbrella に戻し、保存して読み直します。プロジェクト全体のリセットや書類フォルダーの削除は不要です。実行中のタスクを中断しても、すでに書かれた内容は確認と復元が必要です。会話を閉じてもファイル変更は元に戻りません。[Git](article:codex-git-basics)に進む前にこの習慣を身につけます。

## よくある問題と追加練習

内容が異なる場合は、同名の別フォルダーやエディターの未保存状態を確認し、モデル変更を繰り返さないでください。README.md が見えなければ完全な名前を表示し、README.md.txt、リッチテキスト、大文字小文字の違いを調べます。古い会話だけが見える場合は、対応するコンピューターとプロジェクトを確認し、クラウドが新しいローカルファイルを読めると決めつけないでください。

自分で Bottle を Cup に変え、順序と行数を保ってから復元してみましょう。データの場所、変更した実ファイル、三行の内容、実施していない操作を説明できれば完了です。次は[最初の小さなプロジェクト](article:codex-first-project)と[依頼の書き方](article:codex-prompting)で、同じ確認をプレビュー可能なサイトに応用します。

入口と製品名は 2026-09-14 の[デスクトップ公式文書](https://learn.chatgpt.com/docs/app)と [CLI 公式文書](https://learn.chatgpt.com/docs/codex/cli)で確認しました。教材は独自のテキストファイル練習で、ツールや応答は環境により異なります。各 OS の編集手順を三つの OS での Codex 実機試験と称してはいません。

| 役割 | 今回の意味 |
| --- | --- |
| エージェント | ツールで作業を実施 |
| モデル | 理解と推論 |
| タスク | 今回の依頼と会話 |
| 環境 | 利用可能なファイルとツール |

図の 01 は依頼、02 は実行環境、03 は検証できるファイル成果です。三つを照合して作業場所を確認します。
