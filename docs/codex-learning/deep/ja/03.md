## このレッスンでできること

> 自分の OS に合うアプリをインストールし、独立した練習フォルダーを開いて Codex に ToDo サイトの変更を依頼します。最後に差分とブラウザで結果を確認します。読む時間は約 15 分、準備と操作は約 25 分です。2026-09-14 の公式名称に合わせて「ChatGPT デスクトップアプリ」と呼び、その中で Codex を選びます。古い画面やショートカットには Codex と表示される場合があります。

デスクトップアプリはタスク、ファイル、成果物を整理します。モデルは依頼を解釈し、タスクは今回の会話と作業環境を保持します。この違いを知ると、モデル変更と作業フォルダー変更を混同せずに済みます。入口の比較は [Codex 入門](article:codex-beginner-guide)を参照してください。

## 始める前に

ネット接続と Codex を利用できる ChatGPT アカウントを用意し、[アカウントと使用量](article:codex-account-usage)でワークスペースを確認します。プラン、上限、モデルの選択肢はアカウントによって異なるため、固定料金や特定モデルは指定しません。インストール済みなら、アプリが提供する更新方法を使ってから以下の入口を確認します。

[Small Steps 練習パッケージ](https://mokaair.com/guides/codex-first-project/todo-practice.zip)を展開し、expected を自分の codex-practice フォルダーにコピーします。5 個のソースファイルがあり、データは架空で、ログインやバックエンドはありません。今回は見出しとスタイルだけを変更します。本番プロジェクトを開く前に、このコピーで練習してください。プレビューには Python 3、データテストには Node.js が必要です。

## 手順 1：OS に合わせてインストールする

Windows：[ChatGPT 公式ダウンロードページ](https://chatgpt.com/download/)で Windows を選び、公式インストーラーを完了して、スタートメニューから ChatGPT を開きます。PowerShell を使う場合は公式 Windows 文書にある次の方法も選べます。ショートカットが見つからないときは、何度もダウンロードする前にインストールの完了を確認します。

```powershell Windows PowerShell。公式の任意のインストール方法
winget install --id 9PLM9XGG6VKS -s msstore
```

macOS：公式ページで macOS を選び、ダウンロードしたインストーラーを開き、表示に従って指定場所にアプリを置きます。「アプリケーション」から ChatGPT を開いてください。互換性エラーが出た場合は公式ページの現在の要件を確認します。システム保護を無効にしても非対応バージョンが対応になるわけではありません。インストーラーを閉じ、インストール済みのアプリを起動しているか確認します。

Linux：現在はプレビュー版です。公式の対象は Ubuntu 24.04／26.04 LTS、Debian 13、Fedora 43／44 で、x64 と ARM64 のパッケージがあります。次のコマンドで OS と CPU を確認し、[Linux 公式インストールページ](https://learn.chatgpt.com/docs/linux/linux-app)から対応するものを取得します。他のディストリビューションはこの正式対応一覧に含まれません。インストール成功だけですべての機能への対応を判断しないでください。

```bash Linux のターミナル。ディストリビューションとアーキテクチャを確認
cat /etc/os-release
uname -m
```

Ubuntu／Debian は .deb、Fedora は .rpm を選びます。x86_64 は x64、aarch64 または arm64 は ARM64 です。ダウンロード先のフォルダーで、自分の環境に合う一行だけ実行します。ブラウザがファイル名に番号を付けた場合は実際の名前を確認してください。

| システム | アーキテクチャ | インストールコマンド |
| --- | --- | --- |
| Ubuntu / Debian | x64 | sudo apt install ./chatgpt_amd64.deb |
| Ubuntu / Debian | ARM64 | sudo apt install ./chatgpt_arm64.deb |
| Fedora | x64 | sudo dnf install ./chatgpt.x86_64.rpm |
| Fedora | ARM64 | sudo dnf install ./chatgpt.aarch64.rpm |

アプリメニューから ChatGPT を開くか、端末で chatgpt を実行します。更新にはディストリビューションのパッケージ管理を使います。Linux プレビューにはまだ Computer Use がなく、ネイティブ Wayland にも実験的な制限があります。ファイル変更と自分で行うブラウザ確認は練習できます。macOS の画像を Linux の実画面として示してはいけません。

## 手順 2：ログインして練習場所を選ぶ

どの OS でもログイン後にアカウントとワークスペースを確認し、Codex を選びます。フォルダーを開く、またはプロジェクトを作る入口で codex-practice を指定します。ZIP や親フォルダーではなく、index.html などが直接見える場所です。ローカルなどの作業環境を選ぶ場合は、自分の練習コピーがある場所を指定します。

New chat を作り、最初は読み取りだけを頼みます。次は PowerShell や Terminal ではなく Codex のタスク入力欄に貼ります。編集前に、別プロジェクト、未展開の教材、別ホストを選んだ間違いを発見できます。

```text Codex デスクトップの新規タスク入力欄。作業場所を確認
Before editing, report the current working folder and list the exercise files.
Read index.html and explain how the page loads its JavaScript.
Do not change files. Tell me if the expected five files are missing.
```

実際のパスと app.js、core.mjs の関係が示されることを期待します。「理解しました」だけで済ませず、ファイルマネージャーの場所と比べます。アプリが worktree のコピーを作った場合は、その場所も確認します。[Worktree](article:codex-worktrees)も参照できます。この練習は Git リポジトリがなくても始められます。

## 手順 3：確認できる小さな変更を依頼する

```text 同じ Codex デスクトップタスク。依頼の全文
Update this Small Steps practice website.
Change the main heading to "Small steps, clear progress."
Use a dark blue heading color with readable contrast on the existing background.
Keep the form labels, task data format, storage key and behavior unchanged.
Do not add dependencies or external services.
Show the changed files, explain the diff and report checks actually performed.
```

結果が出たらファイル表示や変更表示から index.html と style.css を開きます。見出しと色が依頼に合い、保存形式の変更やラベル削除が紛れていないか確認します。差分の追加・削除行は比較結果であり、公開されたという意味ではありません。最初からログイン、デプロイ、データベースを加えず、自分で確認できる範囲を完了します。

## 手順 4：ブラウザで確認する

練習フォルダーで端末を開き、Windows では次を実行します。サーバーが端末を使い続けるのは正常です。プロンプトが戻らないからと再起動せず、別にブラウザを開きます。

```powershell Windows PowerShell、codex-practice フォルダー
py -m http.server 4173 --bind 127.0.0.1
```

```bash macOS / Linux ターミナル、codex-practice フォルダー
python3 -m http.server 4173 --bind 127.0.0.1
```

http://127.0.0.1:4173 を開き、見出しを確認します。Read と Build を追加して Read を完了にすると、Active tasks には Build だけ、Completed tasks には Read だけが表示されるはずです。再読み込み後もデータが残ることを確認します。空白だけのタスクは追加できないことも、正常操作と一緒に試します。

開発者ツールのレスポンシブ表示で 390 と 1280 ピクセルを確認するか、ウィンドウを狭くします。文字、ボタン、フォームが横にはみ出さず、Tab のフォーカスが見えることを確認します。同じ場所の別端末で node --test core.test.mjs を実行すると、参考版は 3 テスト成功のはずです。Codex にブラウザがなければ自分で表示を確認し、エージェントによる実測ではないと記録します。

## 問題解決、停止、復元

Codex が見つからない場合は、更新、アカウント、ワークスペース、利用可能機能の順に確認します。再インストールを繰り返しても使用量や管理ポリシーは解決しません。CLI は別の入口であり、デスクトップを入れても端末の codex コマンドが使えるとは限りません。

場所が違う場合は、絶対パスと 5 ファイルを照合します。ZIP、空の場所、別プロジェクトなら編集を止めて選び直します。すでに行った変更は元の場所で確認します。プロジェクトを切り替えてもファイルは移動しません。

画面が空白、または JavaScript が動かない場合は、ダブルクリックの file URL ではなく http://127.0.0.1:4173 か確認します。続いて端末と Console を調べます。ポート使用中なら自分の前のサーバーを止めるか別ポートを選びます。ポートが違うとブラウザ保存領域も別になります。

プレビューは Ctrl+C で止めます。今回の見出しとスタイルだけを差分で戻し、他の変更は残します。Reset practice data は専用データの削除であり、コードの復元ではありません。タスク完了、テスト成功、サイト公開は別の状態です。

## 練習と確認記録

「モバイルではボタンを一行全体に、デスクトップでは入力欄の隣にする」と依頼を変えてみます。変更前に現在の CSS を説明させ、二つの幅と元のデータ操作で確認します。すでに条件を満たす場合は、変更不要という結果を受け入れます。
