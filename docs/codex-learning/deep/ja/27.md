## 目標と準備

> 第二の作業目録を作り、編集の分離を確認、成果を保存して実習目録を片付けます。読む時間15分、実習20分。Git とエディターを用意し[分岐と差分](article:codex-git-basics)を読みます。遠隔なしの新規小リポジトリを使い、push や公開はしません。

Worktree は同一 Git の別 checkout で、ファイルと索引は別、提交と分岐情報は共通です。修正と調査の併行に適しても安全沙盒ではありません。同じ DB、雲文書、port は競合し得ます。フォルダー名だけでなく編集担当、外部データ、稼働サービスも分けます。

## 手順1：私的データのない実習庫を作る

自分の実習領域に空の worktree-lab を Windows Explorer、Finder、Linux のファイル管理で作り、そこで端末を開きます。現在地と正式ファイルがないことを確認します。下の命令は新規実習庫のみで実行し、作者設定は local のまま --global を加えません。

```sh 3 OS の端末：新しい worktree-lab 内
git init -b main
git config user.name "Codex Learner"
git config user.email "learner@example.test"
git status --short
```

下記全内容で notes.md を作ります。固有 marker で Codex の説明によらず比較できます。UTF-8 の標準テキストと拡張子を確認後に提交します。周辺ファイルを巻き込まないよう git add . ではなく notes.md だけを追加します。

```markdown worktree-lab/notes.md
# Worktree practice

Marker: LOCAL-A
```

```sh 実習端末：基準を提交
git add -- notes.md
git commit -m "Add worktree practice baseline"
git status --short
git branch --show-current
```

main と未提交なしを確認します。失敗はこの庫の作者設定を直し、組織の署名方針を教材のため変更しません。初回提交がなければ HEAD 基準もないため先に完了します。同名があれば未使用名に揃えて置換し、既存を強制上書きしません。

## 手順2：第二の checkout を作る

```sh worktree-lab 端末：同階層の副本を作成
git worktree add -b codex/worktree-practice ../worktree-copy
git worktree list
```

新分岐 codex/worktree-practice で同階層に worktree-copy を作ります。対象不存在を先に確認し、list の二経路が main と新分岐であること、両文書が LOCAL-A であることを見ます。Windows でも実際に worktree-lab 内なら相対パスを使えます。[端末パス](article:codex-terminal-paths)で確認できます。

別窓で worktree-copy/notes.md の LOCAL-A だけを COPY-B に変え、元窓が LOCAL-A のままか確認して両状態と差分を見ます。同じ notes.md タブだけに頼らず全パスかルート名を表示して対象を区別します。

```sh worktree-lab のまま両目録を比較
git status --short
git -C ../worktree-copy status --short
git -C ../worktree-copy diff -- notes.md
```

元の status は未変更、副本は notes.md 変更、差分は marker 一行のはずです。これはファイル分離であり main への統合ではありません。両方変われば窓の対象が同じか、手作業で両方変えたか確認し、原因が分かるまで提交しません。

## 手順3：分岐の使用制限と成果保存

```sh 失敗確認：main は元目録で使用中
git -C ../worktree-copy switch main
```

Git は同じ分岐を二箇所で使うことを拒み、main 使用中を報告します。両方とも元分岐のままなのが保護動作で、強制や制限無視を加えません。確認済み marker を副本分岐へ提交し、元から比較します。提出は本機内にあり GitHub へ自動送信されません。

```sh 元端末：副本成果を保存して分岐比較
git -C ../worktree-copy add -- notes.md
git -C ../worktree-copy commit -m "Change isolated practice marker"
git -C ../worktree-copy status --short
git diff main...codex/worktree-practice -- notes.md
```

## Codex デスクトップでの対応

Git の新規タスク下で Worktree と開始分岐を選び要求を送ります。未提交変更を含める場合は対象作業に属するか確認し、無関係の私的資料を混ぜません。管理型は当初 detached HEAD の場合があり、長期保存には標頭の Create branch here で分岐を作って検証・提交します。

同じタスクとコードを Local へ移すには Hand off を使い、移動後に場所、分岐、ファイルを確認します。移動は main 統合や公開ではありません。各 OS の利用可能な版で操作し、Linux に欄がなければ Git 手順との差を記録します。携帯 Remote でも worktree と Git は主機に残ります。

| 資源 | 自動分離 | 確認事項 |
| --- | --- | --- |
| 追跡ファイル・索引 | あり | 編集中の実経路 |
| 提交・分岐 | 共通 | 各 checkout の分岐 |
| 依存・建置快取 | 通常個別準備 | プロジェクト準備手順 |
| 本機 port | 保証なし | 各プレビューの port |
| DB・外部サービス | 保証なし | 教材とアカウント範囲 |

## 問題・片付け・検証

設定不足は .gitignore と README から実習用を準備し、正式 .env の丸ごとコピーで済ませません。管理型本機の .worktreeinclude は今回の手動 Git には適用されないため公式資料と[データ保護](article:codex-project-data-safety)を確認します。port 競合は別番号と URL を記録し、他人のサービスを止めません。

副本を使う窓・端末・プレビューを閉じ、元に戻って list の全経路と副本の未変更を確認します。成果が codex/worktree-practice に提交済みになってから除去し、未提交があれば保存、拒否には --force を加えません。元庫と提交分岐を残し、今回の副本だけを除きます。

```sh 元目録：経路照合・副本除去・成果確認
git worktree list
git -C ../worktree-copy status --short
git worktree remove ../worktree-copy
git worktree list
git show codex/worktree-practice:notes.md
```

list は元のみ、main は LOCAL-A、分岐の git show は COPY-B のままを確認します。分離状態と分岐使用拒否の記録を合わせ、作成・分離・保存・除去を検証します。Git 試験とデスクトップ Handoff は別記し、未操作 OS は公式確認とします。次は[子代理の分担](article:codex-subagents)です。
