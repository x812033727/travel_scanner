## 目標と準備

> 一つのローカルプロジェクトで二つの成果の課題を管理し、名前、切替、固定、アーカイブ、復元を練習します。一覧が別でもファイルは分離されないことを確認します。読む時間12分、操作20分。認証済みデスクトップとエディターを使い、各 OS の操作は公式確認でシステム全体実測とはしません。

[デスクトップ基礎](article:codex-desktop-getting-started)が前提です。プロジェクトは共有ファイルと課題を整理し、課題は個別成果と会話を持ちます。「教材一覧」「変更案」のように名付けます。ChatGPT プロジェクトとローカルフォルダー接続は異なり、今回は後者を確認します。

## 手順1：教材フォルダーを接続

codex-project-lab に次の別々の note.txt、request.txt を作ります。基礎手順でローカルプロジェクトへ追加し、Edit project で場所を確認します。ユーザー全体ではなく教材一つだけ接続し、主要フォルダーと実パスを確認して課題を作ります。

```text ファイル：note.txt
PROJECT-LAB
Revision: 1
Current title: Small Steps
```

```text ファイル：request.txt
Propose the title Daily Steps.
Do not edit note.txt until the proposal is reviewed.
```

主要フォルダーが起点と設定探索に使われ、追加場所も読書き可能な場合があります。分離コピーではありません。本教材は Git/worktree なしで共有を確認します。同時編集には[worktree](article:codex-worktrees)を使い、課題数で隔離を判断しません。

## 手順2：成果の異なる課題を二つ作る

最初の課題で一覧依頼を送り、2ファイル、印、版1を確認して「PROJECT-LAB — 教材一覧」と改名します。メニューで共通印と成果を残せば、印だけでも探せます。読取りのみで新文書は不要です。

```text Codex への依頼：教材の確認
Inventory this practice folder. Read note.txt and request.txt. Report their filenames, the lab marker, revision and current title. Do not edit files or search other directories. This task's outcome is a verified inventory only.
```

同じプロジェクトで次の提案課題を作り「PROJECT-LAB — タイトル案」とします。Small Steps を Daily Steps にする note.txt 一行の提案で、まだ編集しません。一覧課題へ戻るとその会話が残り、二つの履歴が混ざらないことを確認します。

```text Codex への依頼：変更案の作成
Read note.txt and request.txt. Propose the smallest title change that satisfies the request. Identify exactly which line would change and how to verify it. Do not implement yet; this task's outcome is a reviewable proposal.
```

## 手順3：課題切替時にファイルを再読

課題間に別作業をした想定で、note.txt の版だけ2へ変更し、タイトルと request.txt はそのままにします。一覧で再読依頼を送り、古い会話の1と最新2を確認します。提案側にも再読させ、同じ場所の2を見るか確認します。

```text Codex への依頼：ファイルの再読込
Read note.txt from disk again now. Compare its current revision with this task's earlier record. Report the actual directory, current revision and unchanged title. Do not repair the mismatch by restoring old contents.
```

不一致は意図的で、元へ戻す依頼ではありません。ファイル共有と会話分離は両立し、固定や改名でコピーは作られません。一方が1なら場所、ホスト、再読、別 worktree を確認します。長作業は[引継ぎ](article:codex-context-handoff)に版差を残します。

## 手順4：固定、検索、アーカイブと復元

よく使うタイトル案を固定し、別課題を開いた後も見つかるか確認します。会話やファイルは変わりません。側欄 Search chats で PROJECT-LAB を検索して完全名で区別します。版による近道キー差を避けて表示入口を使います。

一覧課題だけメニューで Archive にし、プロジェクト全体の Archive chats を選ばないよう確認します。Settings の Archived chats から復元し、会話と版2を確認します。整理操作であり、機能受入、保存、ディスク掃除ではありません。Delete は不要です。

## 発展練習：別プロジェクトに同名のタスクを作る

codex-project-lab の隣に独立した codex-project-other フォルダーを作り、次の note.txt だけを保存します。最初のプロジェクトの追加フォルダーではなく、別のローカルプロジェクトとして登録します。そこで3番目のタスクを開き、同じ「PROJECT-LAB — 教材の確認」と命名して、後述の読み取り専用の依頼を送ります。同名でも同じファイルを使うとは限りません。

```text ファイル：codex-project-other/note.txt
PROJECT-OTHER
Revision: 100
Current title: Other Steps
```

```text Codex への依頼：同名タスクを確認
Read only this project's note.txt from disk. Report the absolute path, marker, revision and current title. Do not infer content from this task's title, another task or another project. Do not edit or search outside this project.
```

3番目は PROJECT-OTHER／100／Other Steps、最初の2つは PROJECT-LAB／2／Small Steps を読むはずです。「成果、所属プロジェクト、絶対パス、最新の読み取り結果、進行中／アーカイブ」を3行で記録します。3番目が 2 を返したら、作成先のプロジェクトを確認し、期待値に合わせてファイルを書き換えないでください。その後「PROJECT-OTHER — 教材の確認」に改名し、指定した1行だけをアーカイブまたは復元します。

> このアーカイブとファイル保持の練習は通常のローカルフォルダーが対象です。[公式 worktree 文書](https://learn.chatgpt.com/docs/environments/git-worktrees)では、Codex 管理の worktree はアーカイブや整理規則で削除され、再度開くとスナップショットの復元が案内される場合があると説明しています。恒久的な worktree は扱いが異なります。種類、未コミットの内容、バックアップを確認し、[worktree のチュートリアル](article:codex-worktrees)に従ってください。このローカルの結果を全環境に一般化しません。

| 操作 | 変わるもの | 確認 |
| --- | --- | --- |
| 改名 | 表示名 | 印と成果で検索 |
| 固定 | サイドバー内の位置 | 同じ会話に戻る |
| アーカイブ/復元 | 一覧の表示状態 | 元会話が残る |
| 再読 | 最新ディスク証拠 | 両方が版2 |
| 主要フォルダー変更 | 新課題の起点 | 実パス再確認 |

## 再開・新規・停止の使い分け

同じタイトル変更の条件追加は元課題へ戻り、テスト記録整理など別成果は読取対象を示して新規にします。他会話の口頭制約を既読と仮定しません。テスト不変更など共通規則は AGENTS.md、版と残確認は引継ぎに置き、新依頼で参照します。

実行中なら表示される停止操作を先に使い、追加変更が止まったか確認して整理します。停止とアーカイブは別で、書込み済みは戻らないため再読します。主要場所の変更は旧パスを記録して新課題で確認し、既存課題の移動や追加場所をバックアップと仮定しません。

## 問題の対処と整理の習慣

見つからなければ別プロジェクト、ホスト、アーカイブ、印検索を確認し、同名を大量作成しません。両方が同じファイルを変えようとするなら一方を読取りに止め、他方の変更後に確認させます。同時機能開発は worktree と統合へ進みます。

大きくなったら「フィルター：Completed 完成」「文書：起動手順」のように成果と範囲を付けます。変更、検証、残作業を残し、未完了は会話だけでなく一覧文書へ保存します。切替ごとの全説明や、アーカイブを未完了なしとする誤解を避けます。

2つのプロジェクトにある3タスクの状態表、最初の2タスクによる版2の再読込、3番目の版100、指定タスクのアーカイブと復元結果を保存します。codex-project-lab/note.txt だけを手動で版1に戻し、Small Steps を確認します。別プロジェクトは 100／Other Steps のままにします。練習のピン留めを解除し、プロジェクトやファイルは削除しません。図1は範囲、2は成果別タスク、3は再確認と整理です。次は[既存コードを読む](article:codex-understand-codebase)に進みます。
