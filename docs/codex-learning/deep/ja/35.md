## 目標と対象環境

> Windows ネイティブの PowerShell で CLI を導入し、実行ファイルを特定してログインし、空白のあるパスの練習ファイルを読みます。読む時間約12分、操作約25分で、ダウンロードは別です。導入とサンドボックスの説明は2026-09-14の公式資料で確認しました。ローカルでの確認は版、help、ファイル操作であり、CLI の再導入や端末ポリシーの変更はしていません。

Windows ネイティブの CLI に WSL は必須ではありません。Ubuntu を開き、/home のパスが出ている場合は [Linux / WSL](article:codex-cli-linux-wsl) を使います。本記事は PowerShell 用です。[CLI 基礎](article:codex-cli-getting-started)で環境を見分け、導入後に一行変更の課題へ戻ります。図の 1 は導入、2 は場所と認証、3 は独立したファイル確認です。

導入前に winver で Windows の版を確認します。現在の公式推奨は Windows 11 で、新しいコンソール機能を備えた更新済み Windows 10 はベストエフォート対応です。古い版も同等に対応しているとは考えないでください。ネイティブサンドボックスには winget や管理者承認の設定など追加条件があり、[公式 Windows サンドボックス文書](https://learn.chatgpt.com/docs/windows/windows-sandbox)で確認します。CLI 導入とサンドボックス設定を分け、失敗した段階を記録します。

## 手順1：PowerShell と導入経路を選ぶ

スタートで PowerShell を検索するか、Windows Terminal のプロファイルから選びます。通常ユーザーのウィンドウで開始し、普段の作業すべてを管理者として実行する必要はありません。次の最初のコマンドをシェルで実行します。codex があれば版と Source を記録し、二重導入せず場所の準備へ進めます。

```powershell PowerShell：コマンドの候補と版を確認する
Get-Command codex -All | Select-Object CommandType, Name, Source
codex --version
```

未導入なら見つからないという結果で構いません。次は公式の Windows 用独立インストーラーで、スクリプトをダウンロードして実行します。公式ページの URL と照合して使ってください。ByPass はこの子プロセスの引数で、端末の実行ポリシーを永久に無効化する指示ではありません。組織の管理で止まる場合は具体的なエラーを記録し、承認済みの導入方法を使います。

```powershell PowerShell：公式の独立インストーラーを選ぶ場合に実行する
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

完了を待ち、最後に示された導入場所と PATH の案内を残します。端末を閉じて新しい PowerShell を開き、Get-Command codex -All と codex --version を再実行します。実行元と版が確認できることが必要です。ダウンロード済み、フォルダーがある、エラーが出ないというだけでは、コマンドを使える確認になりません。

### Node.js がある場合の npm 経路

npm を選んだ場合だけ次の三行を実行します。最初の二つで版が出なければ、三行目を繰り返さず Node.js を先に直します。npm.cmd は Windows のコマンドラッパーを明示し、npm.ps1 の実行ポリシー問題と Codex の導入失敗を区別します。独立インストーラーに npm は必須ではありません。

```powershell PowerShell：npm の代替経路。各行の成功を確認する
node --version
npm.cmd --version
npm.cmd install -g @openai/codex
```

## 手順2：空白のあるパスを準備して確認する

本番プロジェクト外の書き込み可能な場所を選びます。& { から最後の } まで全体を貼り付け、新しい codex windows lab を作ります。存在確認で失敗すればブロック全体が停止します。同名フォルダーがあれば内容を残して別名を選び、確認を飛ばして書き込み行だけ実行しないでください。成功すると新しい場所へ移動して一覧と note.txt を読みます。引用符は空白を保ち、LiteralPath はワイルドカード解釈を避けます。

```powershell PowerShell：全体を貼り付け、現在地に新しい練習フォルダーを作る
& {
  $cliLab = Join-Path (Get-Location) 'codex windows lab'
  if (Test-Path -LiteralPath $cliLab) { throw 'Choose a new practice folder name.' }
  New-Item -ItemType Directory -Path $cliLab -ErrorAction Stop
  Set-Location -LiteralPath $cliLab -ErrorAction Stop
  Set-Content -LiteralPath 'note.txt' -Value 'WINDOWS-CLI-01' -Encoding utf8 -ErrorAction Stop
  Get-Location
  Get-ChildItem
  Get-Content -LiteralPath 'note.txt'
}
```

現在の場所が codex windows lab で終わり、note.txt が表示され、内容が WINDOWS-CLI-01 なら準備完了です。読み取り前後の比較用にハッシュも記録します。ハッシュはバイト列の指紋で、UTF-8 BOM や改行の違いで端末ごとに変わることがあります。固定の掲載値ではなく、自分の前後を比べます。

```powershell PowerShell：練習フォルダーでファイルのハッシュを計算する
Get-FileHash -LiteralPath 'note.txt' -Algorithm SHA256
```

## 手順3：認証、サンドボックス、読み取り

練習フォルダーのまま codex login と codex login status を順に実行し、読み取り専用で開始します。ブラウザーではアカウントとワークスペースを照合します。有効なログインがあれば、ログアウトしてやり直す必要はありません。認証を共有する IDE 拡張にもログアウトが影響する場合があります。公開画面に認証情報を含めないでください。

```powershell PowerShell：一行ずつ認証、状態確認、Codex の起動を行う
codex login
codex login status
codex --sandbox read-only
```

Windows のサンドボックス設定では一度管理者の承認を求められる場合があり、普段の PowerShell を管理者として使うこととは別です。公式では強い elevated を優先し、制限付きの代替に unelevated を示していますが、組織が禁止する場合もあります。失敗時は OS の版、モード、段階を記録し、全アクセスへ切り替えず[権限とサンドボックス](article:codex-permissions)を確認します。

```text 自然言語の依頼：Codex CLI 内に入力する
Read note.txt in the current practice folder. Report the exact content and current working directory. Do not edit, create files, or use external services. If it is missing or inaccessible, report the actual error.
```

この依頼は PowerShell ではなく Codex に入力します。返答と記録で WINDOWS-CLI-01 と正しい場所を確認します。その成功を記録したら、同じ Codex セッションで missing-note.txt を要求し、作成せず欠落を報告するか試します。その後 /exit で PowerShell に戻り、再度読み取り、一覧、ハッシュを確認して、変更や余計な練習ファイルがないことを確かめます。異なる内容ならまず作業場所を直します。

## 更新と三種類の問題の切り分け

更新前に CLI を終了し、作業の要約と未コミットのファイルを残します。独立版なら同じ公式インストーラー、npm 版なら npm.cmd install -g @openai/codex を使います。新しい PowerShell で Source と版を確認します。古い版なら重複元を調べます。一つを更新しても PATH が別のものを選ぶ場合があり、実行元を見ずに更新を繰り返しても解決しません。

| 症状 | 最初の確認 | 次の操作 |
| --- | --- | --- |
| codex が不明 | 新しいシェルで Get-Command | 導入時の案内でユーザー PATH を直して開き直す |
| npm.ps1 が拒否される | npm 経路とラッパー | npm.cmd を確認し管理ポリシーは保つ |
| ログイン後に読めない | 場所、存在、サンドボックスのエラー | 場所か権限を直す。再導入で代用しない |

PATH は実行ファイルの検索先で、プロジェクト一覧ではありません。導入時の出力と Source を比較します。手動修正が必要なら Windows のアカウント用環境変数画面でユーザーの Path を編集し、既存項目を保って確認済み導入フォルダーを追加します。保存して端末を開き直します。全体を例で置き換えたり、不明なダウンロード先を追加したりしないでください。

## 完了条件と次の手順

実行中の CLI、作業場所、認証状態、ファイルの印、ハッシュが変わらないことを説明できれば完了です。経路、版、エラー、解決方法を練習ノートに記録し、認証情報そのものは保存しません。[CLI 基礎](article:codex-cli-getting-started)に戻って変更と再開を練習し、エディターなら [IDE 拡張](article:codex-ide-getting-started)へ進みます。
