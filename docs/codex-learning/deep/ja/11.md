## このレッスンでできること

> コマンドの貼り付け場所が分からない状態から、バージョン確認、セッション開始、状態確認、計画、終了、再開まで進みます。読む時間は約 12 分、操作は約 20 分です。一連の練習とよく使う索引であり、すべてのオプションを暗記する必要はありません。

対象は Codex CLI です。デスクトップや ChatGPT ウェブにもスラッシュメニューがありますが、コマンド集合は異なります。Claude Code のコマンド、古い画像、デスクトップのショートカットをそのまま CLI に使わず、現在の画面とバージョンを確認します。

## 始める前に

[CLI インストール](article:codex-cli-getting-started)とログインを終え、[ToDo 教材](https://mokaair.com/guides/codex-first-project/todo-practice.zip)の expected を codex-practice にコピーします。今回は主に読み取りと計画なので GitHub や有料の外部サービスは不要です。codex が見つからなければ先にインストールを直し、パスと認証の問題を混同しません。

Windows は PowerShell、macOS は Terminal、Linux／WSL はその環境の端末を練習フォルダーで開きます。WSL の /home と Windows の C:\Users は別のパスです。実際に CLI がある環境で実行し、場所を確認してから進みます。

## 四つの入力を区別する

| 種類 | 入力場所 | 例 | 結果 |
| --- | --- | --- | --- |
| シェルコマンド | PowerShell / Terminal / Linux shell | codex --help | CLI を起動しヘルプを表示 |
| スラッシュコマンド | Codex 起動後の入力欄 | /status | 現在の対話 UI が処理 |
| ショートカット | 文字を打たずキーを押す | Ctrl+R | プロンプト履歴を検索 |
| 自然言語の依頼 | Codex の会話入力欄 | Explain core.mjs without editing. | エージェントが依頼を解釈 |

シェルには通常パスとプロンプトがあり、Codex には専用の会話欄があります。PowerShell の /plan はシェルの命令やパスとして扱われ、Codex の Plan モードにはなりません。逆にインストール命令を会話へ貼ると、代理に実行を頼む意味になり、自分で直接実行するのとは異なります。

## 手順 1：バージョンとヘルプを見る

```text Windows PowerShell、macOS Terminal、Linux shell。Codex の会話の外
codex --version
codex --help
codex resume --help
```

一行ずつ実行します。バージョン、サブコマンドとオプション、再開専用ヘルプが表示され、新しい代理タスクは始まりません。今回の Windows では codex-cli 0.154.0-alpha.6.2 でした。これは検証記録であり、このプレビュー版のインストール指定ではありません。

角括弧は省略可能な引数、山括弧は置き換える値を表すことが一般的です。SESSION_ID などをそのまま貼ったり、全オプションを同時に付けたりしません。見つからない場合はスペル、サブコマンド、バージョンを確認してから更新を判断します。

## 手順 2：起動して状態を見る

```text 同じシステム端末、codex-practice 内
codex
```

対話画面で / を入力し、候補から status を探して /status を実行します。モデル、権限、文脈などの設定が表示されますが項目は版によって異なります。購入やリセットクレジット消費のコマンドではありません。

```text Codex CLI の対話入力欄。状態確認
/status
```

自然言語でも作業場所を読み取り確認します。違っていたらセッションを離れ、シェルで正しいフォルダーに入って再起動します。モデル変更では作業場所は直りません。

```text Codex CLI の会話。練習場所を確認
Report the current working directory and list the five Small Steps source files.
Do not edit anything. If this is not the practice folder, stop and explain.
```

## 手順 3：Plan モードで計画する

[Plan モード](article:codex-plan-mode)では実装前に要件、範囲、確認方法を調べます。次は Clear completed ボタンの計画です。未完了タスクを残し、空のリストも考慮します。今回は計画だけを作ります。

```text Codex CLI の対話入力欄。スラッシュ命令と今回の依頼
/plan Plan a Clear completed button for this todo website. Do not implement it yet. Preserve active tasks and explain how to verify an empty list, mixed completion states, and reload behavior.
```

良い計画はファイル、ボタン位置、データ操作、保存、テスト例を示します。「変更、テスト、完了」だけでは不十分です。存在しない React コンポーネントやデータベースを想定していないか確認し、成果を判断できるまで条件を補います。後で実装する際は現在の画面のモード操作に従います。計画があることはサイト変更済みの証明ではありません。

## 手順 4：終了して同じセッションを探す

タスク名やセッション情報を控え、入力欄で /quit を実行します。システム端末に戻ったら codex resume を実行し、選択画面で時刻、内容、パスを照合して選びます。初心者は「最後が目的のもの」と決めつけるより選択画面で確認する方が確実です。

```text Codex CLI の対話入力欄。画面を終了
/quit
```

```text システム端末に戻った後。セッション選択画面を開く
codex resume
```

codex resume --last は現在のディレクトリの直近セッションを再開し、--all は検索範囲を広げます。使う前に resume --help を確認します。再開後は前の計画と残作業を要約させ、パスも確認します。機能を覚えているだけではファイルの場所が正しいとは限りません。

## よく使うコマンド

| 入力 | 画面 | 用途と今回の扱い |
| --- | --- | --- |
| /model | CLI 対話 | モデルと推論設定を確認。見るだけで取り消してよい |
| /permissions | CLI 対話 | 権限確認と変更。読むだけなら権限拡大は不要 |
| /review | CLI 対話 | 変更をレビュー。指摘にも検証が必要 |
| /compact | CLI 対話 | 長い会話を要約。完全な原文記録ではない |
| /skills | CLI 対話 | 次のレッスンで使う技能を探す |
| /copy | CLI 対話 | 直近の完了回答をコピー |
| codex exec --help | システム端末 | 非対話のオプションを確認 |
| Ctrl+R | CLI キー操作 | 履歴検索。Enter で選択、Esc で取り消し |

[モデル選択](article:codex-model-selection)、[権限](article:codex-permissions)、[codex exec](article:codex-exec-scripting)に各手順があります。/compact の前に正確な再現が必要なエラーと完了条件を残し、[引き継ぎ](article:codex-context-handoff)を参照します。目次では /plan、AGENTS.md、resume などで検索できます。

## 確認、問題解決、復元

正常な確認は、バージョンとヘルプが読め、場所が正しく、計画でファイルを変えず、同じタスクを再開できることです。境界の確認では / メニューに存在しない名前を入力し、期待する機能にはならないと確かめます。取り消して文書を調べ、権限拡大や出所不明の追加ツールで解決しません。

command not found や Windows の同等エラーはシェルが codex を見つけられない状態です。インストールと新しい端末環境を確認します。codex --help が動いて /plan だけ動かないなら、入力画面の違いがよくある原因です。

引数が拒否される場合は通常の -- を使い、組版の長いダッシュを避け、空白と引用符を保ちます。メインコマンドで使えるオプションが全サブコマンドでも使えるとは限りません。

再開先がない、または違う場合は別ディレクトリ、ホスト、CLI 環境で開始したか思い出し、選択画面とヘルプを確認します。履歴削除を解決策にしないでください。今回はソースを変えないため終了すれば終わりますが、会話の終了や再開始で以前のファイル操作は戻りません。
