## 目標と準備

> 「MCP が使えない」を設定、起動、認証、ツール可視性、実行の五状態に分けます。読む時間15分、実習20分。[入門](article:codex-mcp)の codexLearningDocs を使い、削除済みなら前記事で再追加します。障害演習はこの項目だけに限り、他作業用のサービスを変更しません。

## 手順1：制限時間より先に設定を確認

```sh 各 OS の端末：読取り確認
codex --version
codex mcp get codexLearningDocs
codex mcp list
```

名前、有効状態、方式、URL と、本機・遠隔、CLI・デスクトップ、最終再起動時刻を記録します。get が見つけなければ実ファイル、綴り、利用者・プロジェクト層、独自 CODEX_HOME を確認します。同一主機だけが設定共有の対象で、Windows と WSL のホームも同じ場所とは扱いません。

解析エラーは表示行付近の引用符、重複表、値の型から直し、その後でネットを調べます。[設定](article:codex-config-toml)に従い副本を保存して実習区画だけ編集し、全設定を公開しません。名前がまだなければ信頼済みプロジェクトの読込み、現在地、保存先が副本でないかを確認します。

| 状態 | 証拠 | 次の行動 |
| --- | --- | --- |
| 保存済み | get の正しい項目 | 起動と接続 |
| 初期化済み | 接続済み表示 | ツール確認 |
| 認証済み | 必要なログイン完了 | データ権限 |
| ツール可視 | 新タスクに対象あり | 小さな読取り |
| 実行成功 | 検証可能な応答 | 原本と保全照合 |

認証不要の公開サービスは不要と記録し、ログイン忘れとは扱いません。

## 手順2：無効化状態を再現

前記事の読取りで正常結果を得て設定を保存後、既存実習区画に enabled = false を加えます。デスクトップの Restart、IDE 拡張再起動、CLI 新規セッションを使います。旧会話への再質問は過去情報を再利用し得ます。意図した本機無効化であり公式側の障害ではありません。

```toml 実習区画を置換：同名表を追記しない
[mcp_servers.codexLearningDocs]
url = "https://developers.openai.com/mcp"
enabled = false
```

```text 新 Codex セッション内：ツール確認
/mcp
```

新セッションでは無効サーバーのツールが提供されないはずです。get に設定が残るのは正常です。true または追加した false の除去で戻し、再起動・再取得・原文照合します。正常、無効、復元を全て残し、最後の成功画面だけで演習成立としません。

## 手順3：STDIO 起動と HTTP 接続を分ける

別の STDIO サーバーでは command、args、cwd を先に見ます。Windows の Get-Command、他 OS の command -v は現在の端末の解決だけを証明し、デスクトップ起動の PATH 一致は保証しません。相対パス、不存在、必要な Node 版を先に確認し、誤記のため起動時間を延ばしません。

```powershell Windows PowerShell：Node 型 STDIO のみ
Get-Command node
node --version
```

```sh macOS／Linux 端末：Node 型 STDIO のみ
command -v node
node --version
```

STDIO は標準入出力を協定に使うため挨拶やデバッグ出力が干渉し得ます。保守者なら公式実装に従い一般ログを stderr に出し、利用者なら第三者内部を書き換えず証拠を報告します。入力待ちの無表示は停止とは限らず、生存プロセスだけで初期化成功ともいえません。

HTTP は協定、主機、全パスを確認し、今回は公式 /mcp を使います。ホームページを開けても MCP、代理、認証の成功証明ではありません。TLS は時刻、組織プロキシ、証明書信頼を管理者と確認し、検証無効化を既定修正にしません。一時失敗は時刻と伏せたエラーを残して再試行します。

## 手順4：認証・ツール選別・時間制限

OAuth サービスは Authenticate または login の help を確認して対象名で認証します。アカウント、範囲、回呼は提供元の要件に従います。事前登録 ID が必要なら Codex が表示する完全 URL を登録し、ポート推測や localhost と 127.0.0.1 の置換をしません。公開 Docs MCP では不要です。

認証済みでも欠けるツールは enabled_tools、disabled_tools、插件方針を見ます。許可一覧は存在しない能力を作らず、拒否一覧は許可後に適用されます。search や read と推測せず現在の実名を確認します。插件由来の起動命令は利用者設定で置換しません。[Plugins 障害対応](article:codex-plugin-troubleshooting)を参照します。

startup_timeout_sec は初期化、tool_timeout_sec は一回の実行です。程序、URL、認証を確認後、小さな読取りで過大要求かを調べ、正常処理に時間が必要な場合だけ対象値を変えて再試験します。grace と required も起動に影響しますが全て必須にする必要はありません。不可欠なサービス不在なら依存作業を止めます。


設定を壊したら実習区画を戻して確認し、他作業中に全体を復元しません。終了は自分の追加項目を前記事通り除去します。OAuth の logout は保存認証、remove は設定を除き、外部の認可は提供者アカウントで確認します。外部へ既に書いたデータはどちらでも戻らず、そのサービスの復旧手順を使います。

失敗層を説明し、無効化・復元を再現し、新しい読取り証拠を得ることが完了条件です。プロセス、ファイル、正答だけでは不十分で、未接続ならツール未検証と残します。公式確認、本機設定、直接協定試験を分け、他 OS、IDE、OAuth、電話の実測とはしません。次は [Worktree 分離](article:codex-worktrees)です。
