## 目標と準備

> 読取り審査を独立した二作業に分け、両報告を待って親が証拠を照合します。読む時間15分、実習20分。[最初のプロジェクト](article:codex-first-project)の expected コピー、Node.js、対応 Codex を用意します。一つの回答が二節に分かれただけでは2つのエージェント実行の証明になりません。

サブエージェントは親から特定部分を任され結果を返す働き手です。独立 Git が自動で付くわけでも、二窓だけで協調するわけでもありません。並行作業は入力、範囲、成果が別で、他方の編集完了に依存しないことが条件です。今回は両者読取りのみです。

## 手順1：教材と基準の確認

完成コピーの五ファイルを開き、故障用 start・broken と混同しません。全 OS で現在地を確認し同じ命令を実行します。npm 導入や外部 DB は不要です。版と基準結果を保存して既存問題を区別します。

```sh 3 OS の端末：expected コピー内
node --version
node --test core.test.mjs
```

教材は現在三つの上位テストが通る想定ですが、他庫の数を保証しません。Node やテストがなければ[障害対応](article:codex-troubleshooting)と経路を先に直します。不足時に似たプロジェクトをエージェントに作らせると審査対象が変わります。

## 手順2：2つのエージェントを明示的に依頼

親のデスクトップ・CLI・IDE で実習ディレクトリを選び下の依頼を送ります。現行のローカル Codex は直接要求または適用規則で分担するため二つと明示します。モデル・推論は親を継承し未提供名を固定しません。各エージェントが用量を使うので、無制限追加より二つの狭い読取り範囲にします。

```text 親の入力欄：二つの読取り作業
Use exactly two subagents for a read-only review of this Small Steps reference copy.
Do not spawn additional subagents or modify files.

Agent A: Read core.mjs. Map addTask, visibleTasks and decodeTasks.
For each function, report its input, behavior, failure or boundary handling, and file/symbol evidence.

Agent B: Read core.test.mjs. Map existing test coverage to those same functions.
Distinguish covered cases from possible missing cases; do not invent a bug just because a test is absent.

Parent: Wait for both reports. Verify cited symbols and reconcile disagreements.
Run node --test core.test.mjs once in the practice directory after collecting the reports.
Return a compact evidence table, actual test result and unverified claims.
If subagents are unavailable, say so; do not present a single-agent answer as delegated work.
```

依頼に参照コピーの完全ルートと基準結果を添え、各報告に読んだパスを記載させます。同じ core.mjs 名でも別 checkout の可能性があるため、親が同じ expected コピーへ照合します。三成功の基準は親の過去記録であり、A や B の実行結果とはしません。

| 役割 | 主入力 | 成果 | 対象外 |
| --- | --- | --- | --- |
| A 動作 | core.mjs | 関数と境界 | 編集 |
| B 試験 | core.test.mjs | テスト範囲と不足証拠 | 架空の確定不具合 |
| 親 | 両報告と実体 | 統合・試験・制限 | 未検証の転送 |

両者は同時開始でき、試験は最後に親が一度行います。

## 手順3：活動確認・追加指示・停止

デスクトップでは、入力欄の上に表示される実行中のサブエージェントを展開し、状態の確認、停止、個別スレッドの表示を行います。CLI の /agent は対話内の切替で、codex agent という端末コマンドではありません。IDE でも利用可能なサブエージェント表示を確認します。表示がなければクライアントのバージョンと対応状況を確認します。

```text Codex CLI 対話内：エージェント確認
/agent
```

```text 親への追加条件
Tell Agent A to include duplicate task IDs in its analysis and keep the work read-only.
Wait for the updated evidence before the final summary.
```

親から A へ追加を渡し、更新に addTask の重複 ID があるか確認します。別窓の入力先を推測せず対象名を見ます。B の停止時は取得済み証拠を残し未完を未検証にします。停止は変更復元ではなく、読取り演習に差分が出たら別途確認します。

## 手順4：完了数だけでなく証拠を照合

参考版の addTask は空白、長さ、ID を確認して新配列を返し、visibleTasks は二条件で絞り、decodeTasks は不正形式と ID 重複を拒みます。親は実関数と試験を照合し、重複未試験という主張なら追加と保存読戻しを区別します。長い報告を優先しません。

親が基準試験を一度実行し実終了値と結果を保存します。主張、実体、試験証拠、確認状態を並べます。読解で分かってもブラウザー未操作の場合や、テスト範囲の追加提案であって不具合でない場合を分け、次の試験・再現・修正を決めます。

## 任意：狭い独自役割を保存

反復する場合は信頼済み実習プロジェクトに、同名不在を確認して .codex/agents/data-reader.toml を作れます。エージェント TOML であり AGENTS.md ではなく、存在だけで起動しません。新タスクで data_reader を明示して役割を確認します。前の二人実習の前提ではありません。

```toml 実習プロジェクト：.codex/agents/data-reader.toml
name = "data_reader"
description = "Inspect Small Steps data invariants with file and symbol evidence."
sandbox_mode = "read-only"
developer_instructions = """
Read core.mjs and report inputs, invariants and error handling.
Do not edit files, invoke external services or spawn other agents.
Cite the relevant functions and distinguish confirmed behavior from assumptions.
If the file is missing, report the missing path and stop.
"""
```

モデルを省略して利用可能設定を継承します。エージェントは親の現在権限を継承し、CLI の実行時上書きも再適用されるため、read-only ファイルが常に最優先とは保証しません。委任前に[権限](article:codex-permissions)を確認します。戻す際は追加した役割だけを除き新タスクで確認します。

## 問題・境界・次の一歩

未生成なら明示要求、対応版、既存作業による枠占有を確認し、一モデルの役割演技で代用しません。同時編集は停止・差分確認後に [Worktree](article:codex-worktrees) や順序処理へ替えます。認証・許可待ちは親が対象と停止箇所を示し、拒否行為を密かに権限拡大して再試行しません。

実在2つのエージェントの活動、証拠、一追加への応答、親の統合・試験、五ファイル未変更を残します。B 停止は別実行で停止例とし、二完了とは数えません。役割・参考コードの静的確認と利用者アカウントでの実行を混同せず、未操作環境は公式確認とします。次は[エージェント品質検証](article:codex-subagent-quality)です。
