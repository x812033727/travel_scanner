## 目標と準備

> 四つの独立した故障例で構文、キーの階層、非対応の値、上書きを分け、問題の出所だけを直します。読む時間12分、操作25分です。設定基礎と Python 3.11 以降が前提で、Windows は py -3、macOS / Linux は python3 を使います。故障例をユーザー設定へ直接貼りません。

検査器は本記事の web_search だけを扱い、Codex 全体の schema ではありません。他設定も通信も使いません。成功はそのファイルの構文と対象キーの確認で、読込み、組織許可、他ツールの動作を保証しません。成功の範囲を明確にします。

## 手順1：オフライン例と検査器を作る

codex-config-checks の check_config.py に次の全文を保存します。指定ファイルだけを開き、構文位置か対象キーだけを表示し、設定全体は出しません。画像用にはここで作る独立例を使い、認証情報入りの実ファイルを渡しません。

```python
from pathlib import Path
import sys
import tomllib

if len(sys.argv) != 2:
    raise SystemExit("Usage: check_config.py SAMPLE.toml")
path = Path(sys.argv[1])
try:
    with path.open("rb") as stream:
        data = tomllib.load(stream)
except (OSError, tomllib.TOMLDecodeError) as exc:
    print(f"FAIL: {exc}")
    raise SystemExit(1)
if "web_search" not in data:
    print("FAIL: missing top-level web_search; inspect table placement")
    raise SystemExit(1)
value = data["web_search"]
if not isinstance(value, str) or value not in {"disabled", "cached", "indexed", "live"}:
    print("FAIL: unsupported web_search value for this exercise")
    raise SystemExit(1)
print(f"PASS: sample syntax and web_search={value}; Codex loading is not verified")
```

まず good.toml を作り、Python と検査器が動く正しい基準を確認します。最初から故障例では道具の問題と題材の失敗を区別できません。両ファイルを UTF-8 と正しい拡張子で保存します。

```toml
web_search = "disabled"
```

教材内で Windows は最初、macOS / Linux は二つ目の行を実行します。PASS と読込み未検証の表示を期待します。No module named tomllib なら Python を確認します。3.11 追加の標準機能で、Codex プラグインの不足ではありません。

```powershell
py -3 check_config.py good.toml
```

```sh
python3 check_config.py good.toml
```

## 手順2：四つの異なる失敗を診断

broken-quote.toml は終端引用符がなく構文失敗します。コマンドの末尾をこの名前に替えます。位置が行末や次の文字を指す場合もあるので、その行を遡って確認し半角引用符を補って再実行します。元と修正版を残して比較します。

```toml
web_search = "disabled
```

broken-duplicate.toml は同じトップレベルキーを二回定義します。最後が勝つ仕組みではなく構文エラーです。disabled を残して重複行を除き、再確認します。複数ファイルの優先順位と単一ファイルの重複は別です。

```toml
web_search = "disabled"
web_search = "live"
```

broken-scope.toml は構文として正しくても features 内の別のキーパスです。検査器はトップレベル欠落を示します。Codex も位置や型で拒否する場合があり、解析成功だけでは対応設定としません。キーを表見出しの前へ移し、実験用 features を残しません。

```toml
[features]
web_search = "disabled"
```

broken-value.toml の off は文字列として有効でも web_search の対応値ではありません。disabled に直して再確認し、別ソフトの on/off に合わせて翻訳しません。モデルや推論は別途アカウントと版を確認し、この小さな検査器で検証しません。

```toml
web_search = "off"
```

## 手順3：構文が正しくても効かない場合

[設定基礎](article:codex-config-toml)の実際の教材へ戻り、故障例は起動設定にしません。新規 CLI の /debug-config でパス、有効層、要件を確認し、編集先と照合します。子ディレクトリや --search、-c、--profile も調べ、一項目だけ変えて再起動します。モデルや認証、権限を一度に替えません。

| 一般設定：高い順 | 確認点 |
| --- | --- |
| CLI 引数と -c | 起動命令 |
| 信頼されたプロジェクト、近い層優先 | 場所と有効状態 |
| --profile 選択ファイル | 別 profile の有無 |
| ユーザー設定 | 実際の Codex home |
| ワークスペース管理既定 | 提供元 |
| システム、内蔵既定の順 | 上書きのない場合の出所 |

表は一般値の結合であり、requirements.toml の強制制約は別途守ります。未信頼で省略なら出所と通常の信頼処理を確認し、改名や移動で迂回しません。Windows / WSL の差は実行ファイルとホームを特定します。同名でも別の設定と認証を持ちます。

## 修正、復元、記録

実修正は読込み先を確認してバックアップし、特定キーだけ変更します。認証、提供元、他の設定を例一式で置換しません。再起動後に診断とローカル印を確認し、有効値を確認できなければ理由付きで未確認とします。新問題はそのキーやファイルだけ戻し、.codex 全体を消しません。

```text
Symptom: record the actual error or unchanged setting.
File and layer: record the relevant path and whether it loaded.
Diagnosis: syntax / key scope / unsupported value / precedence / trust / policy.
Minimal change: record exactly one repaired cause.
Validation: distinguish sample parser checks from actual client diagnostics.
Restoration: record the backup or original value and the result after restarting.
```

正しい基準、説明できる四故障、修正版の成功を残します。実セッションでは未読込みと読込み後の上書きを区別し、証拠不足も認めます。Python 例はオフライン解析、Codex の層は公式診断で確認します。モデル、MCP、権限は各記事で扱い、この単一キー検査で結論を出しません。
