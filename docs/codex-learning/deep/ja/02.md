## このレッスンの到達点

> サインイン方法とワークスペースを確認し、対応する使用量ページを見つけます。個人を特定しない記録で、ログイン失敗、機能の利用不可、利用枠の消費を区別できるようになります。読む時間は約 10 分、操作は約 15 分です。プラン購入、入金、リセットの使用は不要で、自分の状態を確認するだけです。

## 二つの課金元を区別する

ChatGPT サインインと API キーによるサインインは別のアクセス方法です。前者はアカウントのプランとワークスペース権限、後者は API 組織の課金と制限に従います。同じメールアドレスでも利用枠は自動統合されません。有効なサブスクリプションが API 請求ゼロを意味するわけでも、API 残高が全クラウド機能へのアクセスを保証するわけでもありません。公式認証文書ではクラウド Codex に ChatGPT サインインが必要とされています。

価格の確認先は本記事、モデルの確認先は[モデル選択](article:codex-model-selection)にまとめ、各記事で固定価格や一日当たりの回数を繰り返しません。購入前には公式プランページと自分の表示で、通貨、税、月払いか年払いか、席数、ワークスペース条件を確認します。記事に出てきたプランや選択肢が、自分にも購入・利用可能とは限りません。

## 手順 1：アカウントとワークスペースの確認

デスクトップのプロフィールメニューで現在のアカウントとワークスペースを確認します。個人用と会社用があれば、今回使う方を選んでからプランや機能を見ます。ブラウザーとアプリのログインは一致しない場合があり、ブラウザー側を切り替えただけではアプリ側の変更を確認できません。スマートフォンでもログインを確認し、同じワークスペースの使用量を開いて別アカウントの数字を比較しないようにします。

CLI 利用者は OS の端末で次を入力します。PowerShell、macOS Terminal、Linux で同じコマンドです。Codex へのメッセージではなくシェルコマンドで、認証状態を確認します。codex が見つからなければ [CLI 導入](article:codex-cli-getting-started)に戻り、実行ファイルの不足をアカウント不良と混同しないでください。

```shell
codex login status
```

記録するのは認証方法とログイン状態だけで、認証キャッシュ、Cookie、キーはコピーしません。未ログインの場合だけ codex login でブラウザーフローを完了してください。授業のために正常なログインを解除する必要はありません。組織が認証を管理している場合は管理者設定に従います。ローカル設定を何度書き換えても組織の制限は解除できません。

## 手順 2：対応する使用量を開く

ChatGPT サインインでは公式の [Codex 使用量ページ](https://chatgpt.com/codex/settings/usage)を開きます。アカウントとワークスペースを確認してから、表示された各期間、残量、リセット時刻を読みます。CLI の対話中は /status で状態を見られますが、入力先は codex 起動後の欄であり PowerShell ではありません。API キー利用者は対応する Platform 組織の Usage と Billing を確認します。ChatGPT の使用量は API 請求の代わりにはなりません。

```text
/status
```

割合は「使用済み」か「残り」かを先に確認します。架空例で使用済み 30% なら残りは 70% ですが、最初から残り 30% と表示されていれば再計算して逆にしません。未表示や読み込み中は不明でありゼロではありません。期間ごとにリセット時刻が異なる場合があり、一つのカウントダウンから全制限の解除を判断しないでください。更新時刻の違う画面も別枠ではありません。

## 手順 3：共有できる確認記録を作る

次の書式を個人用のメモにコピーし、画面で確認できた内容だけ記入します。設定ファイルではないためプロジェクト直下に置く必要はありません。メール、会社名、キーは書かないでください。UTC と現地時刻を混同しないよう Asia/Taipei などのタイムゾーンを残し、確認できない欄は unknown とします。

```text
Checked at: YYYY-MM-DD HH:mm timezone
Interface and version: desktop / CLI / browser
Authentication: ChatGPT / API / unknown
Workspace category: personal / managed / unknown
Usage source: Codex dashboard / Platform Usage
Window label: copied without private identifiers
Metric meaning: used / remaining / unknown
Displayed value: value / unknown
Reset time and timezone: value / unknown
Feature or error being checked: short description
Next step: verify account / wait / ask workspace admin
```

必要なら練習フォルダーの一覧など小さな読み取りタスクでログインを確認します。成功しても、現在の入口でその作業ができると確認しただけで、全モデル、クラウド機能、外部サービスの利用を保証しません。利用枠を使いたくなければ状態確認で止め、タスク検証は未実施と記録します。上限確認のために大きなタスクを連投して使い切らないでください。

## 問題の切り分けと終了

ブラウザーはログイン済みなのに CLI が未認証なら、ブラウザーフローが CLI に戻って完了したか、同じシステム環境か、CODEX_HOME が異ならないかを確認します。WSL と Windows のホームは別です。エラーを記録して通常ログインをやり直し、auth.json を他人に渡さないでください。ブラウザーのない環境では公式のデバイスコード手順とワークスペースの許可を確認し、証明書検証を無効化しないでください。

ログイン後に機能がなければ、入口、バージョン、ワークスペースの役割、プラン対応の順に確認します。利用枠の問題とは限りません。使用制限が表示されたら、その名称とリセット時刻を記録し、引き継ぎを保存して待つか、アカウントで提示される選択肢を検討します。認証、利用資格、使用制限は別問題で、再インストールしても利用枠は増えません。

本実習では課金設定を変更していないため、使用量ページを閉じれば終了です。本当に CLI からログアウトする場合だけ端末で codex logout を実行します。保存された認証を消す操作で、返金やファイル復元ではありません。公式文書によると CLI と IDE は認証キャッシュを共有するため、一方のログアウトで他方にも再ログインが必要になる場合があります。画像をきれいにするために実アカウントをリセットしないでください。

## 完了条件と次の学習

追加練習では異なる時刻の記録を比較します。アカウント区分、使用量の出典、期間、タイムゾーンが同じと確認してから残量を比べます。不明な項目があれば差を推測せず証拠を補います。対応する課金元を示し、認証・利用資格・利用枠を区別できれば完了です。次は [CLI コマンド](article:codex-commands)、[コンテキストの引き継ぎ](article:codex-context-handoff)、[利用枠の活用](article:codex-usage-efficiency)に進めます。
