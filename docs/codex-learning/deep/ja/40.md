## 目標：スマートフォンの接続先を特定する

> Mac / Windows ホストで Remote を設定し、自分の iPhone / Android を接続して、ホスト、場所、印を検証します。読む時間約12分、初回操作約25分で、更新と認証は別です。2026-09-14の公式資料で入口を確認しました。実機の電話のペアリング、スリープ、遠隔接続を検証した記録ではありません。

Remote では電話から依頼、承認、追問を送り、ファイル、ツール、ログイン済みサービスはホストが提供します。電話でデスクトップツールが動くわけでも、Codex クラウドへアップロード済みになるわけでもありません。[モバイル概要](article:codex-mobile-guide)を確認します。iOS と Android は選択肢で、両方は不要です。既存の一台を使いサーバーは借りません。

手順図の 1 はホストと場所の確認、2 は新しい読み取り依頼、3 はファイル内容との照合です。順に実施します。一覧にホストがあるだけでは 1 の一部しか確認できず、2 と 3 の成功にはなりません。

## 開始前：両端末と作業場所

対応するデスクトップ版で Codex を使える同じアカウントとワークスペースに入り、オンラインかつ起動・非スリープにします。公式モバイルアプリを更新し、SSO、MFA、パスキーなどを済ませます。管理者による有効化が必要な場合もあります。段階提供のため Remote がなければ版、ワークスペース、利用資格を確認します。

公式の電話 Remote ホストは macOS と Windows です。Linux プレビューがあるだけで同じペアリング対応とは判断しません。初回はデスクトップアプリから始め、CLI や IDE の認証では代用できません。Git、Node.js、ブラウザー、Skills、MCP は電話が補うものではなく、実行ホストで確認します。

## 手順1：識別できるホスト側プロジェクトを用意する

ホストに新しい codex-remote-lab を作り、最初のブロックを host-marker.txt、次を request.txt として保存します。REMOTE-LAB-A は架空の課題用の印で、実際のホスト名ではありません。アプリの装置名と実際のパスを別に記録します。既存なら新しい名前で旧データを保ちます。

```text
REMOTE-LAB-A
Revision: 1
```

```text
Read the host marker and report it. Keep both files unchanged.
```

フォルダーをデスクトップのプロジェクトに追加し、場所と二つのファイルを報告する読み取り専用課題を作ります。Windows の Get-Location / Get-Content、macOS の pwd / cat でも確認します。先にローカルの成功基準を作り、元から存在しないファイルを接続障害と取り違えないようにします。

## 手順2：ホストで有効化して電話をペアリングする

作業を受けるホストで Settings → Connections → Control this Mac or PC の Set up / Add を選び、アクセスと認証を完了します。同じアカウントの別の空の PC を設定しても、このホストのフォルダーが自動的に使えるわけではありません。QR は装置とホストのペアリング用なので公開せず、他人に送らないでください。

自分の iPhone / Android で読み、公式 ChatGPT の Remote 設定を開いて同じアカウントとワークスペースを確認します。成功すると電話の一覧にホストが出ます。電話とホストの組ごとにペアリングが必要で、両方のログインだけでは証拠になりません。ブラウザーで止まるなら更新とアプリへの入口を確認します。

ホストで接続と起動維持設定を確認します。Mac ノートは接電して蓋を開き、Sleep を選ぶと接続は止まります。Windows の Computer Use はロック解除済みで操作できる状態が必要です。本課題の読み取りにすべてのブラウザーやデスクトップ制御を有効にする必要はありません。ほかの利用者がいれば時間を調整します。

## 手順3：三つの証拠で確認する

電話の Remote で対象ホスト、codex-remote-lab、元の課題を選んで次を送ります。ホストと関連付けのない一般チャットではファイルアクセスは確認できません。新規なら実行場所を再確認し、同名タスクだけで同じ環境と判断しません。

```text
In this host project, read host-marker.txt and request.txt without changing files. Report the host/environment name if available, the actual working directory, and both files' exact contents. Do not infer unavailable information or use other services. If either file is missing, stop and report that.
```

実際の場所、REMOTE-LAB-A と Revision: 1、request.txt の原文を確認します。ホスト名を得られなければ不明と示し、印を実名と扱わないことが必要です。PC 側で二つを独立して読み、ツール記録と不変を照合します。ホスト選択、パス、内容は別々の確認で、欠ける項目は未確認とします。

課題完了後に鮮度も試します。ホストのエディターで二行目だけ Revision: 2 にして保存し、電話から要約ではなく再読み取りを要求します。2 が必要で、1 のままなら古い返答、未保存、別フォルダーを確認します。最後にホストで 1 に戻して再読み取りし、再練習可能にします。

## 切断と遠隔アクセスの停止

作業完了後にホストの接続許可を一時無効にして電話からアクセスを確認し、ホストで再有効化して戻るか見ます。全ペアリング端末に影響する場合があるため他の遠隔作業がないことを確認します。接続可否、ペアリング削除、実行中タスクの取消は別の状態として確認します。

公式ではログアウトで Remote Control は無効になりますが、ペアリングは残り、再ログイン後に再有効化が必要な場合があります。永久取消と扱わないでください。個別管理はホストの Connections の装置一覧とその版の操作を確認し、元の装置から制御できなくなったか検証します。全版共通の削除ボタン名は資料で確立されていません。

| 症状 | 最初の確認 | 証拠 |
| --- | --- | --- |
| Remote がない | 更新、アカウント、提供範囲 | 入口が表示される |
| ホストがない | ペアリング、アプリ、接続許可 | 正しいホストが出る |
| 違うファイル | 場所、版、読み取り記録 | パスと Revision: 2 が一致 |
| 途中で切断 | スリープ、通信、アプリ終了 | 復帰後に現在のファイルを読める |

## 完了条件と関連レッスン

通知一回ではなく、ホスト特定、正しいパスの再読み取り、更新した印、接続停止を確認できれば完了です。タスクでツールと結果を見ます。次は [iPhone](article:codex-mobile-ios)、[Android](article:codex-mobile-android)、[装置間の引き継ぎ](article:codex-cross-device-workflow)です。PC 終了後も別環境で動かすなら[クラウド課題](article:codex-cloud-tasks-github)の環境と成果の流れを学びます。
