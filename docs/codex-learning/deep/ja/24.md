## 目標と準備

> 必要なプラグインを導入し、外部アカウント接続、架空教材の読取り、削除と切断の違いを確認します。読む時間15分、実習25分。対応入口とサービスアカウントを用意し、[権限とデータ範囲](article:codex-permissions)を読みます。自分の Google Drive に作る教材を使い、提供状況はアカウントの一覧で確認します。

Plugins は [Skills](article:codex-skills)、[MCP](article:codex-mcp) などをまとめて配布します。Skills は手順、MCP ツールはサービスの読取りや操作を担当します。導入済みでも認証済み、全ツール利用可能とは限りません。状態を分けると「導入済みだが読めない」原因を探せます。

## 手順1：入口を確認

デスクトップの Plugins を開き、OpenAI、作業領域、Personal、Installed など実際の分類を確認します。Windows、macOS、Linux とも版と個別要件を確認し、Linux プレビューはローカルの一覧で提供を確かめます。公開紹介ページだけで動作可能とは判断しません。導入前なら[環境選択](article:codex-platforms-guide)へ戻ります。

3つの OS の端末で実習フォルダーへ移動し codex を起動、その対話内で /plugins を入力します。前者はシェル命令、後者は対話指令なので別操作です。IDE 拡張は現時点で Plugins 非対応のため、エディターに同じ選択画面を期待せず対応デスクトップか CLI を使います。

```sh 端末：Codex 起動
codex
```

```text Codex CLI の対話入力
/plugins
```

| 入口 | 最初の確認 | 手順 |
| --- | --- | --- |
| 3 OS デスクトップ | 版、一覧、個別環境要件 | Plugins 詳細で導入・接続 |
| 3 OS CLI | 認証、/plugins、市場の出所 | 詳細、導入、新規セッション |
| iOS／Android | アカウントの Chat／Work での提供 | Desktop only でないことを確認 |
| IDE | Plugins 非対応 | デスクトップか CLI、単独 Skills と区別 |

モバイルのプラグインで PC のディスクが自動公開されるわけではありません。ローカルファイルは[端末連携](article:codex-mobile-guide)の条件に従い、本記事では選んだサービスの文書だけを読みます。Desktop only は Web で見つけても電話で直接実行できません。

## 手順2：確認できる文書を準備

自分の練習用 Google Drive で Codex Plugin Practice という文書を作り、以下を全文貼ります。非公開のままにし、読めるようにする目的で一般公開しません。URL を控えて範囲指定に使います。他サービスの場合は導入と状態記録を先に行い、同等の読取りが確認できてから例を置き換えます。

```text 練習文書の内容
Codex Plugin Practice
Revision: 1
Document marker: PLUGIN-LAB-A
Task count: 3
Completed count: 2
Pending count: 1
Scope: fictional practice data; read only.
```

標記と版は実際に読んだ文書を識別するもので、数値を当てる試験ではありません。同名文書でも URL と標記を一致させます。検索で2件なら任意に選ばず、元サービスのページを確認して同じ URL を指定し、独立した比較基準を作ります。

## 手順3：導入、接続、新規タスク

詳細で名前、提供者、市場、機能を確認して目的の Google Drive プラグインを導入します。デスクトップ文書は加号、CLI は /plugins の市場分類から詳細で導入します。名称または ID と日付を記録し、同名の別配布物と混同しません。

認証画面のサービスとアカウントが教材の所有者か確認し、要求権限を読みます。パスワード、確認コード、Token、接続戻り URL を会話へ貼りません。許容範囲を超えるなら中止して未接続と記録します。依頼に「読取りのみ」と書いても OAuth 権限は狭まりません。

元の入口へ戻り Installed と接続状態を確認して新規会話か CLI セッションを始めます。初回使用時に接続するものもあるため導入だけで省略できません。API key 認証では一部 OAuth 依存プラグインが使えません。キーを交換・表示せず、認証方式と要件を確認します。

## 手順4：実際の読取りを検収

デスクトップは @ で導入したプラグインかスキルを選び、下の依頼の指定箇所を自分の教材 URL に置き換えます。CLI は新規セッションで同じ文書への使用を依頼し、表示される選択入口を使います。全アカウント検索でなく指定文書だけを読ませ、結果と範囲を確認します。

```text Codex への依頼：先に文書 URL を置換
Use the installed Google Drive plugin to read this practice document:
<PASTE YOUR PRACTICE DOCUMENT URL HERE>
Return the document title, source link, revision, marker, and the three counts.
Use an actual read result. If access is unavailable, say which step failed.
Do not edit, share, move, delete, or search unrelated files.
```

同じ文書へのリンク、Revision 1、PLUGIN-LAB-A、3／2／1 と実読取り記録を確認します。全体、完了、未完了の項目に対応させます。自分で Revision 2、Completed 1、Pending 2 に変更し、新しい数値を依頼に書かず再読取りを求め、更新内容に基づくか確認します。

旧数値なら再取得と実際の版を求めます。接続切れ、別アカウント、更新遅延はエラーとして残し、新結果を作りません。新規タスクで旧文脈も分離できます。最後に元サービスで代理による変更、共有、移動がないか確認し、自分の改版と代理の読取りを区別します。

## 手順5：無効化、削除、切断

CLI の /plugins は表示に従い Space で切替、詳細の Uninstall plugin で削除します。デスクトップ／Web も導入済み詳細で探します。作業領域や既定プラグインは管理者が制御する場合があり、その制約を記録して内部キャッシュや導入フォルダーを壊しません。

套件削除と外部接続解除は別です。個別 MCP 接続が残る場合は ChatGPT の接続管理で切断し、必要ならサービス側の第三者認可も確認します。共有利用を確認して今回の接続だけを扱います。新規タスクでその接続から読めないことを確認し、一覧1件の削除だけで全権限撤回と主張しません。

導入、認可、初回読取り、改版再読取り、削除を別々に記録し、未操作環境は公式文書確認と記します。読者の Drive 認証や非公開文書読取りを実施したとは主張しません。図1は選択と範囲、2は接続と読取り、3は検収と終了です。[プラグイン問題対処](article:codex-plugin-troubleshooting)へ続きます。
