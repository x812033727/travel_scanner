## 目標と準備

> macOS の Terminal で導入、実行元の確認、ログイン、場所の確認、読み取り専用の検証、元の経路からの更新を行います。読む時間約12分、操作約25分で、ダウンロードは別です。2026-09-14の公式 CLI と認証資料で確認しました。macOS 実機での導入や製品画面の撮影は行っていませんが、自分の Mac で照合できるよう全手順を記載しています。

Command+Space で Spotlight を開き、Terminal を検索して起動します。導入コマンドはシェルの入力位置に入れ、ChatGPT や Codex の会話には貼りません。新しい書き込み可能な練習フォルダーと利用できるアカウントを用意します。独立版に npm は不要です。図の 1 は導入元、2 は正しい場所での開始、3 はファイル比較です。

## 手順1：既存の導入を確認する

```bash
command -v codex
type -a codex
```

Terminal で一行ずつ実行します。command -v は現在選ばれるコマンド、type -a は複数の元や同名の alias / function を調べます。未導入ならパスが出ないか見つからない表示になります。見つかれば codex --version で版と経路を記録し、記事に合わせるためだけに再導入せず練習フォルダーへ進みます。

### 公式の独立インストーラー

新規導入なら末尾の公式 CLI ページで次のコマンドを照合します。公式スクリプトを取得して sh で実行するので、取得元を確認し、完了後に導入先と PATH の案内を読みます。接続や証明書のエラーは記録してネットワークや管理証明書を直し、不明なミラーへの変更や TLS 検証の省略はしません。

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

新しい Terminal ウィンドウで command -v codex、codex --version、codex --help を実行します。導入元に一致するパスと版、説明が出れば次へ進めます。先に起動していたエディターは古い環境を保持する場合があります。IDE の端末だけ見つからなければエディターを完全に終了して開き直し、同じ確認を比べます。

### Homebrew や npm を使っている場合

Homebrew 利用者は次の cask 経路を選べます。先に brew --version を確認します。Homebrew がない初心者は Codex のためだけに管理ツールを増やさず、独立版を使えます。公式コマンドの --cask を残し、更新も同じ cask 経路で行います。

```bash
brew --version
brew install --cask codex
```

既存の Node.js / npm を使う場合は node --version と npm --version を確認してから npm install -g @openai/codex を使います。EACCES なら全コマンドに sudo を付けず、Node.js の導入方式と npm グローバルディレクトリの所有者を確認します。独立版に変えるなら元を記録して重複を調べ、意図した実行ファイルが更新されるようにします。

## 手順2：練習ファイルの準備、移動、コピー

Finder で書き込み可能な場所に新しい codex mac lab を作ります。テキストエディターで MAC-CLI-01 だけの note.txt を作り、note.original.txt も保存します。TextEdit なら標準テキストに切り替えて名前と拡張子を確認します。RTF の名前を .txt にするだけでは変換されません。同名フォルダーがあれば別の名前を使います。

Terminal に cd と空白を入力し、Finder のフォルダーをウィンドウへドラッグして、生成されたパスを確認して Return を押します。ユーザー名を推測せず実際の場所を使えます。引用符付きの完全なパスを入力しても構いません。pwd と ls の後に読み取り、RTF 制御文字や .txt.txt が見えれば先にエディターで直します。

```bash
pwd
ls
cat note.txt
shasum -a 256 note.txt note.original.txt
```

練習フォルダー、二つのテキスト、MAC-CLI-01 を確認します。二つの SHA-256 は一致するはずです。違う場合は Codex に正解を推測させず、空白、改行、文字コードを確認します。エディターの改行設定で値が変わるため、固定の掲載値ではなくローカルの値を残します。

## 手順3：ログインと読み取り専用タスク

```bash
codex login
codex login status
codex --sandbox read-only
```

一行ずつ完了を待ちます。ブラウザーのアカウントとワークスペースを確認し、Terminal で login の終了後に status を調べます。認証情報ストアの確認が出たら今回のログインか照合し、認証ファイルを依頼や画像に含めません。利用制限と API 課金は[アカウント](article:codex-account-usage)を参照します。三行目で起動後、次の依頼を Codex に入れます。

```text
Inspect note.txt and note.original.txt in the current folder. Report the current directory, exact content of each file, and whether they match. Do not edit files or use external services. If the folder or files are wrong, stop and report the mismatch.
```

MAC-CLI-01、二つの名前、正しい場所と読み取り記録を確認します。/exit 後に Terminal で cat と shasum を再実行し、内容、ハッシュ、ファイル数が不変か確かめます。Terminal では読めて Codex では読めないなら、サンドボックスのエラーを残して[権限](article:codex-permissions)を確認します。実行範囲の違いであり、消失とは限りません。

## 手順4：新しい端末でも確認する

Terminal を閉じて開き直し、command -v codex と版を確認してから練習フォルダーへ戻り、codex resume で場所と時刻を照合します。新しいシェルの開始場所は異なる場合があります。note.txt が不明なら同名を作り直す前に pwd を見ます。会話の再開は Finder、端末、ファイルをまとめて元に戻す操作ではありません。

新しいウィンドウだけ見つからない場合は、導入時の PATH 案内、command -v、シェル起動環境を比較します。実際に使う起動設定をバックアップし、既存 PATH を保ったうえで対象箇所だけ直します。/opt/homebrew や /usr/local が全 Mac に適用されるとは限りません。該当ファイルを特定せず複数へ設定をコピーしないでください。

## 更新と問題の対照

| 導入経路 | 更新 | 確認 |
| --- | --- | --- |
| 公式独立版 | 同じ公式インストーラーを再実行 | 新しい端末のパスと版 |
| Homebrew cask | brew upgrade --cask codex | brew の成功と正しい codex の元 |
| npm | npm install -g @openai/codex | 元の Node.js 環境と目的の codex |

更新前にセッションを終了して要約を保存し、完了後に再開します。版が変わらなければ type -a で重複元を見ます。help が動いて認証だけ失敗するなら、導入の基本確認はできており、ブラウザーの戻り、アカウント、通信を記録します。特定フォルダーだけなら場所とアクセスを比較します。問題の層を分けると修正の確認対象が明確になります。

[CLI 基礎](article:codex-cli-getting-started)で一行変更と復元、または[コマンド](article:codex-commands)でスラッシュ命令とセッションを学びます。Windows 編は前提ではなく、Windows パスや PowerShell で macOS 手順を代用しません。版、導入元、前後のハッシュ、エラーを残して再現できる導入記録にします。
