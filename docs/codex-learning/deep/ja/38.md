## 目標と iPhone の役割

> iPhone の ChatGPT Remote でホストの Codex 課題に入り、検証できる読み取り、追問、離れてから同じ課題への復帰、PC での確認を行います。読む時間約12分、操作約25分で、ペアリング待ちは別です。2026-09-14の OpenAI Remote と Apple QR 資料で確認しました。iPhone 実機検証や iOS 製品画像とはしていません。

iPhone は依頼と結果表示を担い、ソース、端末、依存関係、ログイン済みサイトはホストが提供します。電話に ChatGPT を入れても CLI 導入やファイル App への同期にはなりません。[モバイル概要](article:codex-mobile-guide)と[ホスト設定](article:codex-remote-setup)で接続、課題、実行を区別します。

## 開始前：ホストとアカウントを準備する

Mac / Windows のデスクトップ版を更新し、電話と同じアカウントとワークスペースで Codex を確認します。[Small Steps](https://mokaair.com/guides/codex-first-project/todo-practice.zip)の expected を codex-iphone-lab にコピーし原本を残します。ペアリング前にホストの五つのソースを確認し、私的な本番プロジェクトではなく課題を使います。

App Store で OpenAI を確認して公式 ChatGPT を更新します。SSO、MFA、パスキーなどを済ませて設定へ戻ります。組織管理者の有効化や段階提供が関係する場合があります。Remote がなければ版とワークスペースを記録し、Safari の変更や CLI 再導入を機能取得の証拠にしません。

本記事の操作例は iPhone です。iPad では自分の ChatGPT アプリに Remote が表示され、ホストを選べることを先に確認してから同じ読み取り練習を行います。公式ページは iOS の入口を説明していますが、iPad 専用レイアウトの保証ではありません。iPhone の画面位置から iPad のボタン位置を決めつけたり、この記事を iPad の実機検証記録と扱ったりしないでください。

### ホストに自分の識別ファイルを用意する

codex-iphone-lab のルートに remote-check.txt を作り、次の行の 01 を自分の識別コードに変えて保存します。同名ファイルがあれば先に読み、別作業の内容を上書きしません。これは五つのサイトファイルに追加する六つ目の練習ファイルです。コピーごとに違う識別コードを使い、アカウント、パスワード、ペアリングコードは入れません。識別コードと完全なパスは個人用メモに残し、後の依頼には識別コードを書きません。

```text ホスト上のファイル内容：remote-check.txt。先に末尾の識別コードを変える
IOS-PRACTICE-01
```

## 手順1：カメラで Remote の設定を開く

ホストの Settings → Connections → Control this Mac or PC で Set up / Add と認証を済ませ QR を表示します。iPhone カメラの写真モードで全体を写し、検出リンクを押します。コントロールセンターのコードスキャンも使えます。写真をチャットへ送る操作ではなく、公式 ChatGPT の設定へ進むリンクです。

読めなければ全体が入る距離、反射、写真かスキャンのモードを確認します。Safari だけなら公式アプリとログインを確認してホストからやり直します。ペアリング URL、QR、認証コード、アカウント情報を公開の質問や教材画像に含めないでください。

電話でアカウント、ワークスペース、ホストを確認します。Remote に対象が表示され、codex-iphone-lab と Codex 課題を開けることが必要です。認証完了画面だけでは不足します。別 PC なら対象ホストの設定に戻ります。図の 1 は電話の入口、2 は選んだホスト、3 は検証可能な成果です。

## 手順2：明確な読み取りを依頼する

Remote のプロジェクト課題入力欄に次を貼ります。キーボードの自動修正で名前が変わっていないか確認します。電話で端末コマンドを実行するものではありません。一度送って返答を見ながら、アプリ切替後も戻れる課題名などを記録します。

```text 自然言語の依頼：同じモバイル Remote タスクに入力する
Read this Small Steps project without changing files. Confirm the working directory and inspect app.js and core.mjs. Identify the localStorage key, the field that records completion, and the function that rejects blank task titles. Cite the file for each answer. If a file is unavailable, report that instead of guessing.
```

app.js の mokaair-codex-todo-v1、core.mjs の completed と addTask の空白確認、実際の場所を確認します。一般論だけなら読んだファイルを追問します。場所が違えば止めて正しいホストとプロジェクトを選びます。もっともらしい説明だけでは接続の証拠になりません。

### このコピー固有の目印を読み直す

```text 自然言語の依頼：同じモバイル Remote タスクに入力する
Read remote-check.txt from this task's project now.
Quote its exact content and report the absolute file path and the tool used to read it.
Do not edit files or infer the marker from earlier messages.
If the file is missing or cannot be read, report that limitation.
```

ホスト側のメモにある識別コードとパス、ツールの読み取り記録を返答と照合します。ホスト表示名とファイルの目印は別の情報です。新しい内容か確かめるにはタスク完了後にホストで識別コードだけ変更して保存し、新しい値を教えずに同じ読み取り依頼を送ります。古い値、ツール記録の欠落、パスの不一致は未確認のままにし、保存状態、ホスト、コピーを先に調べます。

## 手順3：追問、承認内容、進捗を確認する

```text 自然言語の依頼：同じモバイル Remote タスクに入力する
In the same project, explain what happens when I add Read and Build, complete Read, and choose Completed. Then explain an empty task title. Separate code you inspected, tests actually run, and checks still pending. Do not edit or clear stored data.
```

この例は空の一覧に Read と Build だけを追加した場合です。ローカルプレビューに他の項目があればそのデータを踏まえて判断します。この読み取り依頼でデータは消去されません。 同じ課題の文脈を確認します。Completed は Read だけ、空白は拒否を予測し、読んだコード、実行済みテスト、未操作の画面を分けることが必要です。コード分析は予測であり、電話での実測ではありません。PC のプレビューで実際に操作して補います。

承認が出たら操作、場所、範囲を依頼と照合します。読み取り課題に外部アカウント追加、公開、削除は不要です。長い命令が見えにくければホストで確認します。承認が出ない場合も新規を繰り返さず、元の Remote 課題の状態を確認します。

## 手順4：離れてから同じ課題に戻る

読み取り返答の完了後に別アプリへ切り替え、ChatGPT → Remote で同じホストと課題へ戻ります。最後の返答と状態を見て現在の場所を新たに読ませます。古い表示だけではホストの現在のオンライン状態を証明できず、新しい読み取りで確認します。

通知は完了や注意の合図で、成果確認の代わりではありません。なくても課題を開きます。ホストの睡眠、通信断、アプリ終了は復帰させ、前の要求が完了したか確認します。後の書き込み課題では、電話の切断だけで作成や提出を再送しません。まず読み取りで復帰を学びます。

## 完了確認とよくある誤解

| 確認 | 十分な証拠 | 不足する証拠 |
| --- | --- | --- |
| ペアリング | 正しいホストを選べる | 同じアカウントの認証だけ |
| 読み取り | 場所、保存キー、関数の出典 | ToDo アプリの一般論 |
| 再開 | 同じ課題で新たに読める | 古い通知や返答 |
| 検証 | ホストのファイルと操作確認 | 根拠のない成功宣言 |

ホストの localhost を iPhone Safari に入れても電話自身を指します。Remote のホスト側結果や画像を見て、ローカルプレビューは PC で確認します。公開プレビューや配備は別です。[ホスト設定](article:codex-remote-setup)で接続を管理し、タスク停止も別に確認します。ログアウトでペアリングは消えません。

最後にホストと場所、確認済み内容、未実行テスト、次の操作を認証情報なしでまとめさせ、PC で照合します。次回の進捗確認で完了範囲を判断できます。[装置間作業](article:codex-cross-device-workflow)と[文脈引き継ぎ](article:codex-context-handoff)、別の電話なら [Android 編](article:codex-mobile-android)へ進みます。

終了時は今回自分が追加した remote-check.txt だけをホストから取り除き、五つのサイトファイルは残します。元からあるファイルは削除も上書きもしません。目印確認もコード分析も読み取りだけです。実施していないペアリングや製品操作は未検証として記録します。
