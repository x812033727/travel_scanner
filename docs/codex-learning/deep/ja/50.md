## 目標と準備

> プラグイン障害を検証可能な層に絞り、修正後に同じ文書要求を再実行します。読む時間15分、実習20分。[導入と接続](article:codex-plugins)の架空文書を用意し、正式な作業領域ではなく自分の実習接続を確認します。利用できるプラグインがなければ環境とエラーの記録まで行い、読取り成功にはしません。

## 手順1：失敗時の状態を残す

日付、OS、入口、版、正式プラグイン名、配布元、ログイン方式、失敗した手順を記録します。Windows、macOS、Linux で同じ形式を使い、CLI の版は端末、デスクトップの版はアプリ情報や更新画面で確認します。同じ PC でもデスクトップで使えることは CLI の導入証明になりません。遠隔ホストも別記し、調査日を版として転記しません。

```sh 端末：CLI の版を確認
codex --version
```

```markdown plugin-incident.md
# Plugin incident
Date and time zone:
OS / surface / version:
Local or remote host:
Plugin name and source:
Sign-in method (no secrets):
Failing step:
Exact error (redacted):
Practice document revision:
Change attempted:
Retest result:
```

公開可能なエラー文からメール、非公開文書 ID、token、cookie を伏せます。認証 URL には一時コードが含まれることがあり、教材や相談メモへ貼りません。種類、時刻、再現手順を残し、サーバー記録は提供元の窓口で扱います。一度に一条件だけ変えると、アカウント、新規会話、権限のどの変更が効いたか分かります。

## 手順2：症状から確認する層を選ぶ

| 症状 | 最初の確認 | 観察できる結果 |
| --- | --- | --- |
| Plugins がない | 対応入口 | 対応入口で一覧が開く |
| 掲載済みだが導入不可 | 配布元と管理方針 | 詳細や制限を確認 |
| 導入済みだがツールなし | 有効状態と新規会話 | 新規タスクで能力を選べる |
| ログイン要求 | 外部接続 | 正しいアカウントで認証 |
| 一文書だけ失敗 | 文書権限や URL | 同じアカウントで原本を開ける |
| 古い回答 | ツール実行と版 | 新しい取得で新マーカーを確認 |

これは調査順序で、コードの意味を保証する表ではありません。401 は認証、403 は拒否に関係することが多くても、サービスの応答で判断します。不存在、権限不足、共有変更が似た表示になる場合もあります。429 や一時障害では再試行情報を記録し、後で同じ小文書を試します。大量再送やドライブ全体の公開は行いません。

## 手順3：入口・導入・有効化を確認

デスクトップでは Plugins の Installed と詳細を確認します。CLI は codex 起動後 /plugins を入力し、marketplace と導入項目を確認、導入済み項目は Space で切り替えます。導入・再有効化後は以前の能力一覧が残る可能性を避け新規タスクで検証します。旧結果を保存し、会話削除や設定フォルダー全消去は不要です。

```text Codex CLI 内の対話指令
/plugins
```

IDE 拡張は Plugins 非対応なので、メニュー不在を破損と判断せずデスクトップか CLI で確認します。iOS、Android の Chat／Work はその入口で提供されるものに限られ、Desktop only は実行できません。Linux プレビューや個別要件も確認し、非対応と記録して再導入を繰り返しません。[端末間の作業](article:codex-cross-device-workflow)も参照できます。

## 手順4：アカウントと文書アクセスを分ける

プラグインと同じ外部アカウントでサービスの原本を開き、題名と Revision を確認します。別のブラウザーアカウントで読めても証明にはなりません。不一致は用意された再接続手順で修正し、新規タスクで同じ URL を要求します。一文書だけなら所有者に共有先を確認し、自分の教材は必要なアカウントだけ許可します。

ChatGPT のログインと OpenAI API key 方式は異なり、OAuth を要する一部は API key で利用できません。詳細と[アカウント](article:codex-account-usage)を確認し、パスワードを config.toml に書いたり、OAuth のため全面許可へ変えたりしません。ホストのサンドボックスと外部文書の権限は別なので、一方を緩めても他方の成功は保証されません。

## 手順5：実際のツール結果で再検証

```text 新規タスク用：実習 URL を置換
Use the selected plugin to read my practice document at <PRACTICE_DOCUMENT_URL>.
Return its title, source link, Revision, Document marker and task counts.
Use a fresh tool result. If access fails, report the tool error and stop.
Do not edit, share, move or delete anything. Do not infer missing contents.
```

プレースホルダーを教材 URL に替え、対応選択欄で能力を指定します。「読んだ」という文だけでなくツール活動を確認し、題名、出典、現在の Revision、マーカー、件数を原本と照合します。実行がなければ能力の読み込みを調べ、拒否なら元エラーを残して過去会話から補完させません。

原サイトで Revision と確認可能な件数を手動変更し、新件数は Codex に教えません。同じ要求を別の新規タスクで実行します。古ければコピー URL、未保存、再取得手段を確認し、遅延を記録します。二回目の正解はこのケースの証拠であり、全入口・全文書の修復とはしません。

## 判読練習：「読めない」を3つに分ける

> 以下は外部アカウントがなくても練習できる架空の障害記録です。Google Drive の実測結果や普遍的なエラーコード規則ではありません。証拠から次の1手を選び、解答と比べます。未実施の処置を成功と記録しません。

| 例 | 分かっている証拠 | まだ不明なこと |
| --- | --- | --- |
| A | デスクトップの Installed にあるが、同じ端末の IDE で失敗しツール呼び出しなし | 対応入口の新規タスクで使えるか |
| B | 新規タスクにツールがあり、サービスはアクセス拒否。同じ外部アカウントで原サイトも開けない | このアカウントに閲覧権があるべきか |
| C | 原サイトは Revision 3 を保存済み。実際のツール呼び出しは Revision 2 を返し、出典リンクは未確認 | 別コピーか、更新がまだ反映されていないか |

A は Plugins 非対応の IDE ではなく、デスクトップか CLI の新規タスクで確認します。接続成功はまだ未確認です。B は URL、アカウント、共有先を確認し、権限がある場合だけ練習文書のアクセスを修正します。再インストールでは閲覧権を得られません。C は返された出典と指定 URL を比べ、再取得の時刻と版を記録します。根拠なくモデルの記憶やキャッシュと断定しません。各変更後は同じ文書を再確認し、アカウント全体を公開しません。

エージェントが自然言語で「成功」と言うだけなら、実際の読み取りは未確認にします。反対にツールが拒否を返した場合は「呼び出したが失敗」であり、「未ロード」ではありません。この区別を障害記録に反映すると、次の担当者が正しい入口やサービスを調査できます。

## よくある問題と復旧

削除ボタンがなければ管理者配布や既定項目かを確認し、制限を記録します。アンインストールはその環境のプラグインパッケージを除去しますが、別接続の MCP は残り得ます。終了時は導入状態と外部接続管理を別々に確認し、必要なら自分の実習認可だけ失効します。共有接続や全端末を一括処理したと判断しません。

記録を見て、自分が変えた一条件を戻します。一時停止の再有効化、正しい実習アカウントへの再接続、教材権限の復元です。それでも新規タスクが失敗するなら入口、配布元、伏せたエラー、試した修正、期待値と実際を担当者に渡します。再導入を繰り返さず、自作サーバー設定は [MCP の障害対応](article:codex-mcp-troubleshooting)へ進みます。

## 検証と次の一歩

完了条件は元の失敗、特定層、一変更、同文書の新ツール結果、原本への書込みなし、実習接続の維持・失効を残すことです。結果がなければ入口制限や認証待ちと書き、成功にはしません。本手順は公式資料で確認したもので、利用者アカウント、OAuth、実機電話の実測を主張しません。記事表示テストも接続の証明ではありません。

[スキル検証](article:codex-skill-testing)とは別に保存します。スキル読込みは外部接続の証明ではありません。[テンプレート](article:codex-templates-cheatsheet)に項目をまとめ、次回も観測値、日付、未再現項目を残します。
