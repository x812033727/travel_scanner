## 目標と準備

> 架空の一覧を非対話で読み、回答・診断・終了状態を別々に保存します。読む時間15分、実習20分にモデル待機時間が加わります。[CLI の導入とログイン](article:codex-cli-getting-started)を済ませ、Git と自分の空フォルダーを用意します。本実習では現在の認証方式の利用枠を使う Codex 要求を1回送信します。help と意図的に無効なフラグを使う手順ではモデルの回答は不要です。

## 手順1：実行する入口を確認する

codex exec は端末コマンドで、デスクトップ会話のスラッシュコマンドではありません。Windows は PowerShell、macOS は Terminal、Linux は端末を使います。WSL では内部で導入・認証し、Windows のログインが同期済みとは考えません。デスクトップや IDE の端末でも実行できます。携帯の会話はこのローカルプロセスではなく、CLI を実行できる PC または管理された遠隔環境が必要です。各 OS で次の2行を実行し、実版がフラグに対応するか確認します。

```sh CLI 版と exec の説明を確認
codex --version
codex exec --help
```

| 入口 | 本実習 | 用途 |
| --- | --- | --- |
| 端末 | codex exec | 非対話処理を1回開始 |
| 依頼引数 | Read tasks.md… | エージェントに目的を指定 |
| stdout | 最終回答 | テキストとして保存 |
| stderr | 進行・診断 | 文字があるだけで失敗とは限らない |
| 終了状態 | 整数 | 0 は正常終了だが回答の検証も必要 |

[JSON／JSONL](article:codex-json-output)編で stdout の形式を変えます。ここでは普通の文字列を使い、診断が空か、回答に Done とあるかだけで成功を決めません。

## 手順2：独立した入力を用意する

練習場所に新しい exec-lab を作り、エディターで開きます。同名の場所に既存データがあれば別の空フォルダーを選びます。UTF-8 の tasks.md に下記を保存します。正式プロジェクト、非公開ログ、利用者ディレクトリ全体は使わず、手で検算できる小さな一覧で十分です。そのフォルダーの端末で Git を初期化します。コミット、リモート、GitHub アカウントは不要です。

```markdown exec-lab/tasks.md
# Practice tasks
Revision: exec-practice-1

- [x] Read the guide
- [ ] Create a practice file
- [ ] Verify the result
```

```sh 全 OS で exec-lab 内から実行
git init
git status --short
```

tasks.md が未追跡と表示されるはずです。初期化は CLI の作業場所確認を満たすだけで、アップロードしません。版 exec-practice-1、総数3、完了1、未完了2を手元に控えます。次の依頼には答えを書かず、入力を読んだ結果か確認します。他のファイルが見える場合は[パスの説明](article:codex-terminal-paths)で現在地を調べます。

## 手順3：出力を保存し、直後に終了状態を記録する

自分の OS の組を選びます。report-01.md、stdout-01.txt、stderr-01.log（macOS／Linux は tasks-before.md も） が未作成か確認し、再実習では02に変えて古い回答との混同を避けます。読み取り専用サンドボックスはエージェントの編集を制限しますが、shell のリダイレクトと -o は指定した報告を書きます。--ephemeral はセッション保存を省くだけで、利用枠を消費しない、またはこの3ファイルを作らないという意味ではありません。

```powershell Windows PowerShell
$practiceBefore = (Get-FileHash -LiteralPath tasks.md -Algorithm SHA256).Hash
codex exec --sandbox read-only --ephemeral -o report-01.md 'Read tasks.md. Report its revision and the total, completed and pending checkbox counts. Do not edit input files or use external tools.' 1> stdout-01.txt 2> stderr-01.log
$practiceExit = $LASTEXITCODE
$practiceExit
Get-Content -LiteralPath report-01.md
$practiceBefore -eq (Get-FileHash -LiteralPath tasks.md -Algorithm SHA256).Hash
```

```sh macOS／Linux shell
cp tasks.md tasks-before.md
codex exec --sandbox read-only --ephemeral -o report-01.md 'Read tasks.md. Report its revision and the total, completed and pending checkbox counts. Do not edit input files or use external tools.' > stdout-01.txt 2> stderr-01.log
practice_exit=$?
printf '%s\n' "$practice_exit"
cat report-01.md
cmp tasks-before.md tasks.md
```

依頼中の external tools は外部サービスを指し、ローカルの読取りツールで tasks.md を読めます。次の外部コマンドに上書きされる前に終了状態を保存します。成功条件は0終了、正しい版と3／1／2、入力の不変です。PowerShell の最後は True、macOS／Linux の cmp は一致なら無出力で0終了です。回答の言語・表現が違っても値と根拠が正しければ合格です。

## 手順4：失敗を回答として採用しない

```sh 全 OS の無効引数実習
codex exec --sandbox invalid 'Read tasks.md'
```

引数解析で拒否され、新しいモデル回答は出ないはずです。直後に PowerShell は $LASTEXITCODE、macOS／Linux は echo $? を確認し、0以外を期待します。前回の report-01.md が残っていても今回の成功証拠にはなりません。read-only に直して再実行するなら新しい出力名で状態を保存します。権限やサンドボックスを迂回してエラーを隠さず、引数・認証・利用枠・入力欠如を分けて修正します。

結果は二行で記録します。読取り実行は実際の出力名・終了値・件数、無効フラグは「引数解析失敗、新回答なし」とします。report-01.md が残ることは旧ファイルの保存だけを示します。モデルを未実行ならその欄を未実行とし、無効フラグだけ独立して試せます。

## 問題の切り分け・復元・次の学習

codex が見つからなければ導入編で PATH を調べ、ログインを繰り返しません。Git 場所エラーでは exec-lab と git status を確認し、すぐチェックを省略しません。認証・利用枠エラーは codex login status と[アカウント・利用量](article:codex-account-usage)の入口で調べます。診断中の資格情報、利用者パス、非公開依頼は公開しません。対話承認が必要なら対話モードで必要な権限を確認し、非対話処理の範囲を小さくします。

今回の終了状態と検算結果を保存し、tasks.md を再確認します。片付けるなら自分が作った report、stdout、stderr と macOS／Linux の tasks-before.md だけをファイル管理画面で選びます。プロジェクト全体や未追跡ファイル全部を消しません。これで検証可能な読み取り専用処理を終え、次は構造化出力の検証、その後 [CI](article:codex-ci-workflows)へ進みます。フラグは公式文書と CLI help で確認しており、参考スクリプトの合格が各利用者のモデル実行成功を意味するわけではありません。
