## 目標と準備

> 環境情報付き画面で視覚要求を伝え、範囲を限定して実ページを検証します。読む時間15分、実習20分。[最初のプロジェクト](article:codex-first-project)の expected、Node.js、Python、ブラウザーを用意します。添付は変更前の Windows／Edge 参考画面で、390px は実電話や今回の変更後成果ではありません。

| 画像の種類 | 示せること | 使い方 |
| --- | --- | --- |
| 実操作画像 | 指定環境でその時見えた状態 | プラットフォーム・日付・画面幅・操作前後を明記 |
| オリジナル図解 | 概念と手順の関係 | 図解と記し実測の代用にしない |
| 生成挿絵 | 視覚方向と概念 | 製品画面や合格証拠を装わない |
| ライセンス素材 | 出典が利用を認める内容 | 作者・出典・ライセンス・署名を保存 |

## 手順1：ブラウザー入口を選ぶ

デスクトップはツールバー、URL、@Browser から内蔵ブラウザーを使えます。開く鍵は macOS の Cmd＋Shift＋B、Windows の Ctrl＋Shift＋B。Linux は実版のツールバーと提供を確認し同一鍵を仮定しません。CLI・IDE に内蔵 Browser はなく、別 [MCP](article:codex-mcp) があれば検証し、なければ自分で画面を添付します。

内蔵は独立プロフィールで通常の Chrome・Edge 分頁を自動取得しません。普段の認証を使うなら公式拡張接続を行い環境を区別します。サイト操作許可は文中指示の信頼ではなく、無関係ファイルの送信や権限変更をページの要求だけで行いません。

## 手順2：起動して正しいページを確認

expected の三試験を確認後、下記でローカル限定サーバーを起動し端末を残します。4173 使用中なら別番号と URL に揃え、他サービスを止めません。これはローカル実習で公開ではありません。

```sh 3 OS の端末：expected を確認
node --test core.test.mjs
```

```powershell Windows PowerShell：expected 内
py -m http.server 4173 --bind 127.0.0.1
```

```sh macOS／Linux 端末：expected 内
python3 -m http.server 4173 --bind 127.0.0.1
```

指定 URL で標題、フォーム、篩選を確認し、二つの指定タスクを追加して Build を完了すると 1 active／2 total です。localStorage はプロフィール別なので前後を同じ環境で比べます。既存データがあれば実習プロフィールか別 port を使い、日常の保存を全消去しません。

遠隔 Codex の 127.0.0.1 は遠隔自身で、Web 雲タスクの localhost も利用者 PC ではありません。程序とブラウザーのホストを確認して正式なプレビュー経路を使います。携帯 Remote で確認できても本教材は外部公開を行いません。[端末間作業](article:codex-cross-device-workflow)を参照します。

## 手順3：画面と文字条件を用意

レスポンシブを二寸法の CSS 像素にし、倍率と二件データを固定します。各 OS の領域撮影でページだけを before 名に保存します。装置倍率で PNG 像素は変わるため、viewport、倍率、版、日付を別記し画像寸法から推測しません。

```markdown visual-check.md：実環境を記入
# Visual check
Route: http://127.0.0.1:4173
Browser / version:
OS / date:
CSS viewport: 390 x 900, then 1280 x 900
Zoom:
State: Build complete; Read the AGENTS.md rules active
Before images:
Requested change: reduce header bottom spacing from 36px to 24px
Preserve: task data, labels, focus outline and control sizes
After images:
Behavior checks:
Unverified platforms:
```

撮影からアカウント、私的分頁、通知を外し必要なら小領域を再撮影します。他 OS の図を改題して実測とせず、個人情報は共有前に伏せます。生成・概念図は示意と明記し操作証拠にしません。他人の図は出典、作者、ライセンス、署名を保存し説明と代替文を現言語にします。

## 手順4：一変更を注釈で依頼

Annotation mode があれば標題とフォーム間を選んで間隔を記し、親へ要求を送ります。なければ二 before 図と文字で場所を示します。注釈保存だけでは編集は始まらず送信が必要です。曖昧な美観でなく値、保全、二寸法の検証を指定します。

```text Codex 入力欄：二 before 図を添付
Use the attached before screenshots and the local practice page at http://127.0.0.1:4173.
In style.css, reduce the existing header bottom margin from 36px to 24px.
Keep the task data, labels, responsive form layout, 46px controls and visible focus outline unchanged.
Verify the actual page at 390x900 and 1280x900 CSS pixels with the same two tasks.
Check no horizontal page overflow, usable filtering, keyboard focus and persistence after reload.
Report the file diff and before/after evidence. If the browser is unavailable, identify that limitation instead of claiming visual verification.
```

```css style.css の対象区画：既存規則を置換、全ファイルではない
header { margin-bottom: 24px; }
```

既存36pxを24pxへ置換し、後で上書きされ得る重複規則を足しません。差分で無関係の再構築や焦点枠除去を確認します。開発機能の computed 値は図の類似より明確な証拠です。測定不可なら制限を残して手動比較します。

## 手順5：実画面で検証・復元

同二寸法で再読込・after 保存をし、間隔、入力、Active 一件、Tab 焦点、保存を確認します。100文字近い題名でも折返しと横溢れなしを確認し、短文だけで境界合格としません。core 試験は画面確認と別欄にします。

未反映は URL、配信ディレクトリ、保存、キャッシュ、上書きを見ます。空白は HTTP の模块読込みを確認し file:// 制限を回帰と混同しません。操作不能なら画面未確認と報告し、生成 after 図で代用しません。margin だけ36pxへ戻し再確認、自己サーバーを Ctrl＋C で止めます。

実ページ、二寸法、変更ファイル、確認動作、未測 OS が分かる記録を残します。自撮影と参考図を分け日付・出典を付けます。内蔵入口・注釈・権限は公式確認で、利用者アカウントや全 OS 操作を主張しません。次は[自動化](article:codex-automations)です。
