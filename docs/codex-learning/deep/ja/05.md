## このレッスンの成果

> ファイルの準備、導入とログインの確認、正しい場所での読み取り、指定した一行の変更、終了と元のセッションへの復帰を練習します。読む時間は約12分、操作は約25分で、ダウンロードとログインの待ち時間は別です。この課題に GitHub、Node.js、有料の外部ツールは不要です。

CLI は端末から Codex を操作する入口です。シェルはプログラムを起動し、Codex の入力欄は依頼を受け取ります。どちらも文字中心ですが、入力の意味が異なります。[端末とパスの基礎](article:codex-terminal-paths)で現在のフォルダーを確認できるようにしてから進めます。図の 01 は起動前の確認、02 はセッション、03 はファイルの検証です。

## 始める前に：導入方法を一つ選ぶ

通常のユーザー権限で書き込める練習用フォルダーを、本番作業とは別に用意します。利用資格、認証方法、利用枠は[アカウントと使用量](article:codex-account-usage)で確認してください。起動できても利用枠があるとは限らず、ログインしてもすべてのフォルダーへのアクセスが許可されるわけではありません。

| 環境 | 導入方法 | 本記事に戻る目安 |
| --- | --- | --- |
| Windows | 公式 PowerShell インストーラー。npm があれば npm も選択可能 | ネイティブ PowerShell でバージョンを確認 |
| macOS | 公式インストーラー。Homebrew 利用者は cask も選択可能 | Terminal でバージョンを確認 |
| Linux / WSL2 | Linux シェル内で公式インストーラーを使用 | 同じ Linux 環境でバージョンを確認 |

詳しい手順は [Windows](article:codex-cli-windows)、[macOS](article:codex-cli-macos)、[Linux / WSL](article:codex-cli-linux-wsl) に分けています。三つを順番に導入する必要はなく、使う環境の一つを選びます。記事が未公開なら末尾の公式 CLI ページで自分の環境を選び、導入後に端末を開き直して次の確認を行います。方法を比べるためにすべての配布形式を入れる必要はありません。

```text OS の端末：タスクを始めずに版とヘルプを確認する
codex --version
codex --help
```

この二行は OS のシェルに入力します。バージョンと説明が出てシェルに戻れば確認でき、モデルのタスクはまだ始まりません。codex が見つからなければログインより先に導入を直します。記事より新しい版でも構いません。記事の検証用プレビュー版を入れ直さず、ローカルの help と公式資料でオプションを照合してください。

## 手順1：識別できる練習ファイルを用意する

テキストエディターで次の内容の greeting.txt を作り、greeting.original.txt というコピーも保存します。新しい codex-cli-lab フォルダーに二つを置きます。.txt.txt になっていないことと、ワープロ形式でないことを確認します。二行目は読み取ったファイルを識別する印で、コピーは変更前との比較用です。

```text ファイル内容：greeting.txt に貼り付け、原本コピーを保存する
Hello, traveler.
Lesson marker: CLI-START-01
```

Windows ではエクスプローラーでフォルダーを開き、ターミナルで開く操作から PowerShell を選び、Get-Location と Get-ChildItem を実行します。macOS / Linux では cd と引用符で囲んだ完全なパスを入力してから pwd と ls を実行します。二つのファイルが必要です。ホームやダウンロードのままなら先に移動し、見覚えのある名前だけで場所を判断しないでください。

## 手順2：ログインして読み取り専用で開始する

```text OS の端末：一行が完了してから次を実行する
codex login
codex login status
codex --sandbox read-only
```

前の処理が終わるごとにシェルで一行ずつ実行します。login のブラウザー案内で意図したアカウントとワークスペースを選びます。login status は認証情報の確認で、利用枠や通信、モデル要求の成功を保証しません。最後の行は読み取り専用のサンドボックスで対話画面を開きます。信頼やサンドボックスの設定が出たら、場所と説明を確認して今回の練習に合う設定を選びます。

次の /status は Codex の入力欄で実行します。表示される作業場所、モデル、権限を確認します。項目は版によって異なります。PowerShell に貼り付けないでください。read-only はサンドボックスの方針であり、ネットワークや外部ツールがすべて無効という意味ではありません。それぞれの認可も適用されます。この練習ではローカルのテキストだけを使います。

```text 対話用スラッシュコマンド：Codex CLI の入力欄で実行する
/status
```

```text 自然言語の依頼：読み取り専用の Codex セッションに入力する
Read greeting.txt in the current folder. Report the working directory and both lines exactly. Do not edit files, use external services, or infer missing content. If the file is missing, stop and report that.
```

これは Codex の会話に入れる自然言語の依頼です。二行の原文と現在の場所が一致すれば内容を確認でき、実際に読んだ証拠として読み取りツールの記録も見ます。見つからない場合は変更依頼を止めます。ファイルが存在してもアクセスできなければ、エラーと対象範囲を記録して[権限の説明](article:codex-permissions)を確認します。

## 手順3：指定した一行だけ変更する

Codex で /exit を入力し、シェルに戻ったら同じ練習フォルダーで次の書き込み可能なセッションを開始します。読み取りと変更を分け、権限の違いを確認する練習です。一行の変更にディスク全体への無制限アクセスは不要です。組織の規則で使えなければ、読み取り結果を保存して管理設定を確認します。

```text OS の端末：Codex 終了後に書き込み可能なセッションを起動する
codex --sandbox workspace-write --ask-for-approval on-request
```

```text 自然言語の依頼：書き込み可能なセッションに入力する
In greeting.txt, replace only the first line with: Hello, Codex learner.
Preserve the lesson marker and greeting.original.txt. Do not create other project files.
Read the file after editing and report the exact before/after change.
```

一つ目は起動コマンド、二つ目は Codex 内の依頼です。提示されたコマンドと変更内容を確認します。コピーが変わったり余計なファイルが増えたりしたら、範囲のずれを伝えて修正後に再確認します。一行目が Hello, Codex learner. になり、印とコピーが変わらないことが成功条件です。「完了」という返答だけで判断しません。

## 手順4：終了、検証、再開

変更後は現在の Codex セッションで欠落時も試します。greeting-missing.txt を読み、存在しなければ作成せず報告するよう依頼します。欠落が明示され、既存の二つが変わらないことを確認します。名前から内容を推測しただけの返答と区別できます。その後 /exit でシェルに戻り、エディターで二つのファイルを独立して比較します。

終了後、シェルで codex resume を実行し、時刻、内容、場所で今回のセッションを選びます。最新の一件と決めつけないでください。変更と残作業を要約させ、greeting.txt も読み直します。会話の再開はディスクを過去の版に戻しません。外部で編集した場合は現在のファイルを確認します。

```text OS の端末：練習ディレクトリで再開一覧を開く
codex resume
```

再開後は状態を確認します。会話に一行目の変更が記録されていても、greeting.txt をバックアップから戻したなら、再読込した結果は Hello, traveler. のはずです。「読み取りと比較だけを行い、以前の変更を再適用しない」と明示してください。新規会話、終了、再開は会話の管理で、ファイル復元は別途操作して確認します。分岐や別ディレクトリの検索は[セッション](article:codex-sessions-resume)へ進みます。

やり直すときは終了後、コピーの二行を greeting.txt に戻して一致を確認します。練習ファイルだけを戻せばよく、Codex の設定や全セッションを削除する必要はありません。更新は選んだ導入経路で行い、新しい端末で版を確認します。後で経路を変えるときに重複導入を調べます。

## よくある問題と完了確認

コマンド不明ならシェルを確認し、開き直して各 OS の PATH を調べます。ブラウザーで完了しても待機中なら同じログイン試行か、ローカルへの戻り処理かを確認し、URL やコードを公開しないでください。ログイン済みで送信できない場合は利用枠、組織規則、通信を分けます。変更できないなら、再インストール前に読み取り専用セッションか確認します。

版の記録、正しい場所と読み取り証拠、一行だけの変更、未変更のコピー、欠落の報告、再開可能なセッションを残します。次は[コマンド](article:codex-commands)と [AGENTS.md](article:codex-agents-md)でプロジェクト規則を追加します。ローカル Windows では版と help、練習ファイルの比較方法を確認しました。導入、認証、モデルとの対話は公式資料による確認で、macOS / Linux を実機検証したとはしていません。
