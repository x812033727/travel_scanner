## 目標と準備

> 独立した GitHub 教材リポジトリで Completed を直し、テストと差分を確認してレビュー可能な PR を準備します。読む時間15分、操作35分程度に認証や待ち時間が加わります。三つの OS ともブラウザを使い、Codex の利用資格、リポジトリを作れる GitHub アカウント、Small Steps が必要です。

クラウドは設定した環境で実行し、[Remote](article:codex-mobile-guide)は接続ホストを操作します。同名プロジェクトでも未コミットの変更、サイトのログイン状態、node_modules は自動で移りません。対象ブランチとファイル一覧を起点にして結果の出所を確認します。

## 手順1：クラウドから読める教材を用意

[教材](https://mokaair.com/guides/codex-first-project/todo-practice.zip)を展開し、broken の index.html、style.css、app.js、core.mjs、core.test.mjs を使います。expected はローカルの回答参照として残し、開始リポジトリに混ぜません。Completed が未完了を返すため一件失敗する設計です。

GitHub の New repository で自分のアカウント、codex-cloud-lab、Private、README 初期化を選びます。Add file → Upload files で五つをルートへ追加し、教材追加と分かるメッセージでこの新規教材の開始ブランチに保存します。組織規則が PR を要求するなら教材をその手順で取り込み、本番保護を変更しません。

core.mjs が broken 内ではなくルートにあり、中身があることを確認します。visibleTasks の completed 条件が逆であること、画面のブランチ名と最新コミットを記録します。main と決めつけず、教材を含むブランチを選びます。認証成功だけではこの開始状態を保証しません。

## 手順2：リポジトリと環境を接続

[Codex cloud](https://chatgpt.com/codex)で ChatGPT のアカウントとワークスペースを確認し、GitHub 接続で codex-cloud-lab を選びます。組織の承認が必要なら先に完了させて一覧を確認します。GitHub と ChatGPT の認証は別で、片方のログインだけでは接続許可になりません。

[環境設定](https://chatgpt.com/codex/settings/environments)で教材を選び、利用可能な Node.js 22 以降の互換ランタイムを指定します。外部パッケージ、API、キーは不要です。setup script には次のバージョン確認だけを入れます。意図的に失敗するテストを setup に置くとエージェント開始前に止まるため、課題内で実行します。

```sh クラウド環境設定：setup script に入れるバージョン確認
node --version
```

必要なファイルは揃っているので agent internet access は Off のままです。準備とエージェント段階の通信は別です。別の依存付きプロジェクトなら lockfile と準備ログに従いますが、この教材に不要な依存を加えたり README にトークンを書いたりしません。

## 手順3：開始版を確認して修正

教材のある環境とブランチを選び、まず次の読み取り依頼を送ります。場所、コミット、五つのソース、一件の失敗が期待値です。全成功なら expected や修正済みブランチを選んでいないか確認し、正しいコードを無理に壊しません。ルートにファイルがなければ環境や配置を先に直します。

```text 自然言語の依頼：選択した環境のクラウドタスクに入力する
Inspect this Small Steps practice repository without changing files. Report the working directory, git commit, branch if available, and the five source filenames. Run node --test core.test.mjs. Explain the failing behavior from the test and core.mjs. Keep files unchanged and do not open a pull request yet.
```

ログを確認後、同じ課題で修正を依頼します。core.mjs の completed 条件に限定し、テストと他の動作を保持します。テスト削除や期待値の緩和は修正になりません。大きな書き換えなら、条件だけでは直らない理由を確認してから範囲を広げます。

```text 自然言語の依頼：同じクラウドタスクで修正を求める
Fix only the reversed completed filter in core.mjs. Completed must return only finished tasks, Active only unfinished tasks, and All every task. Preserve order, input immutability and all existing tests. Remove any now-obsolete exercise comment. Run node --test core.test.mjs and show the final diff. Do not merge, deploy or open a PR until I review the result.
```

## 手順4：検証して PR を準備

| 条件 | 入力 | 期待表示 |
| --- | --- | --- |
| Completed | Read 完了、Build 未完了 | Read のみ |
| Active | 同じ二件 | Build のみ |
| All | 同じ二件 | 元の順の Read、Build |
| 空一覧 | 項目なし | すべてのフィルターが空 |

三件成功し、completed が真の項目を残す条件と不要な故障コメントの削除を確認します。Active、All、core.test.mjs は変わりません。以前の完了文ではなく最終差分と最新の実行を読みます。予測だけなら実出力を求めます。

### 未コミット差分だけでなく開始時のコミットと比べる

最初の読み取り確認で記録したコミットを基準にします。タスク内で変更が既にコミットされていると、git diff が空でも今回の変更がある場合があります。開始点から最終結果までの差分を確認してください。開始記録がなければログで調べ、推測したブランチ名を基準にしません。次の依頼は確認だけで、PR の作成やマージは行いません。

```text 自然言語の依頼：同じクラウドタスクで変更全体を確認する
Use the commit recorded in our initial read-only inspection as the baseline.
If you cannot identify it, stop and ask me to recover that record.
Compare the final tracked tree against that baseline, including committed, staged and unstaged changes.
List untracked files separately. Confirm whether core.test.mjs is unchanged and explain every changed file.
Report the latest actual test command and result, or say not run.
Do not modify files, open a PR, merge or deploy.
```

準備できたら課題の PR 作成から、リポジトリ、base、修正版 head を確認し、次の案を使います。PR はレビュー依頼で、マージや公開ではありません。競合、未完了チェック、無関係な差分を解決してから判断します。[レビュー記事](article:codex-testing-review)用に未マージで止めても構いません。

```markdown PR 下書き：実際の結果を記入してからレビューに出す
Title: Fix Completed filtering in Small Steps

Completed previously displayed unfinished tasks. It now displays only finished tasks while preserving Active, All, order and input data.

Baseline commit: [fill in the commit from the initial inspection]
Result checked: [fill in the final commit or task diff identifier]
Validation: [fill in command, exit code and actual pass/fail counts]
Browser verification: [performed / not run, with scope or reason]
Deployment: not performed.
```

角括弧の項目はすべて自分の実際の記録に置き換えます。三つ成功と書けるのは実行で確認した場合だけで、未実施の確認には理由を添えます。PR の題名と結果の説明も最終差分に合わせます。画面検証では PR の正確なブランチかコミットを別フォルダーに取得し、[最初のプロジェクト](article:codex-first-project)に従います。残したい練習データを保存してから About this exercise → Reset practice data を選び、All tasks で空一覧を確認します。その後 Read と Build を追加し、Read だけを完了にします。Completed は Read、Active は Build が期待値です。古いローカル版の正常画面で新しいクラウド変更を合格にしないでください。

## 問題の切り分け、停止、次の手順

一覧にない場合は所有者、接続許可、組織承認を確認します。初期化失敗は最初の setup エラーと Node、テスト欠落はブランチと配置、ローカルとの差はコミットと最新実行を確認します。アクセス、道具、配置、版を分け、同じ依頼の再送だけで済ませません。

停止操作後は状態と残った差分を確認します。停止は既存 PR や GitHub 変更を取り消しません。未マージ PR は確認して閉じ、マージ済みは対象コミットの復元を行います。チャット削除で代用しません。UI と環境は公式資料確認、教材テストはローカル確認であり、読者のクラウド課題や PR を実行済みとはしていません。
