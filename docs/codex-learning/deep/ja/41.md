## 目標：端末を替えても作業を特定する

> 引継ぎ記録を作り、別の Remote 対応端末から読み取りを続け、新しいファイル印で実行場所を確認します。読む時間12分、操作25分程度です。Mac / Windows ホストとペアリング済みの iPhone / Android を準備します。対応する二台目のデスクトップでも再開できます。後半の任意 Handoff は同じ Git プロジェクトを保存した別ホストが必要です。

手元の操作端末、会話を含む課題、ファイルと端末を提供するホストを分けます。電話からノート PC への変更は操作端末だけの変更かもしれません。Handoff は実行ホストを変え、クラウドは別の環境です。同じ題名やフォルダー名だけでは実際の資料を識別できません。

手順図の 1 はホストと場所の確認、2 は新しい読み取り依頼、3 はファイル内容との照合です。順に実施します。一覧にホストがあるだけでは 1 の一部しか確認できず、2 と 3 の成功にはなりません。

| 操作 | 実行場所 | ファイル |
| --- | --- | --- |
| 電話の Remote で再開 | 元のホスト | ホスト上の資料 |
| 別デスクトップから制御 | 元のホスト | 同じホストのプロジェクト |
| 別ホストへ Handoff | 移動先の worktree | 課題と Git 状態を移して確認 |
| 新規クラウド課題 | クラウド | 選択したリポジトリの版 |

## 手順1：検証できる引継ぎを記録

[Remote 設定](article:codex-remote-setup)の codex-remote-lab で host-marker.txt の REMOTE-LAB-A、Revision: 1 と request.txt を確認します。ホストのエディターで handoff.md を作り、観察した事実を記入します。ホスト名は別名でもよく、私的な絶対パスは公開画像に出しません。

```markdown ホスト上のファイルひな型：記入して handoff.md に保存する
# Remote reading handoff

Goal: read this practice folder without modifying files.
Controller: record the device currently sending requests.
Execution host: record the host shown by Remote.
Project: codex-remote-lab
Working directory: record the actual directory reported by the host.
Task: record the exact task title or identifier.
Marker: REMOTE-LAB-A / Revision: 1
Git state: not initialized for this basic Remote exercise.
Verified: record only checks actually performed, with time.
Pending: fresh read from the second controller.
Next action: read host-marker.txt again and compare the revision.
```

record… を実際の確認内容に置き換えます。同じ題名なら識別子、プロジェクト、最近のメッセージも照合します。内部 ID が表示されなければ実際の題名と時刻を記録します。基本課題には Git がないのでブランチやコミットを作り話にせず、Git プロジェクトではそれらと未コミット差分を追加します。

## 手順2：操作端末を替えて新たに読む

電話の Remote で元のホストと課題を選びます。別の対応 Mac / Windows なら Settings → Connections → Control other devices から接続して同じ課題を開きます。展開状況で表示されない場合はペアリング済み電話で実施します。制御する端末と各ホストの接続が必要で、同じログインだけでは確認できません。

編集を依頼する前に引継ぎを読み、別端末から次の依頼を送ります。REMOTE-LAB-A、Revision: 1、作業場所、元ホストを確認します。ホスト名を取得できなければ未確認とし、Remote の表示と照合します。ファイル内の印を実測したコンピューター名として扱いません。

```text 自然言語の依頼：次の操作端末から元のタスクに送信する
Continue this exact Remote reading task. Read handoff.md and host-marker.txt from disk now, without modifying files. Report the current working directory and both marker lines. Identify the execution host if the tools expose it; otherwise state that it is unverified. Distinguish this fresh read from facts copied from earlier messages.
```

## 手順3：版の変更で古い内容を見分ける

ホストで host-marker.txt の二行目だけ Revision: 2 にして保存します。一行目と request.txt は保持し、handoff.md は一時的に1のままにします。別端末で再読させ、ディスクの2と記録の1の差を指摘できるか確認します。1を繰り返すなら場所、ホスト、実際の再読を調べます。

```text 自然言語の依頼：同じモバイル Remote タスクに入力する
Read host-marker.txt and handoff.md again from the current project. Compare their revision values. Report any disagreement; do not assume the handoff note is newer than the file. Do not edit either file.
```

差を確認したら handoff.md の印を2にし、Verified に端末と確認時刻を記録します。プログラムテストはしていないので全成功とは書きません。課題を戻すなら両方を1にして再読します。この限定した復元は他のコードや課題を取り消しません。

## 発展：別ホストへ実行を Handoff

ここまでは操作端末の変更です。実行を移すなら[Git 基礎](article:codex-git-basics)で独立教材を準備し、接続済み両ホストに同じリポジトリのプロジェクトを保存します。元が子ディレクトリなら移動先も対応する場所です。候補がなければプロジェクト設定を直し、課題名変更で代用しません。

元の教材リポジトリで次の読み取りコマンドを使い、結果と重要な差分を残します。PowerShell、macOS、Linux で同じですが正しい場所が前提です。not a git repository なら開始条件を満たしていません。ブランチ空欄は detached HEAD の可能性があり、コミットを記録して確認します。

```sh ホストの端末：実際の作業先である練習 Git リポジトリを確認する
git rev-parse --show-toplevel
git rev-parse HEAD
git branch --show-current
git status --short
git diff --stat
git diff --cached --stat
git ls-files --others --exclude-standard
```

### 同じコミットでも引き継ぎが完全とは限りません

上の確認は Git ルート、コミット、ブランチ、状態、未ステージ差分、ステージ済み差分、未追跡ファイルを記録します。git diff --stat だけではステージ済みや未追跡の作業が漏れます。必要な ignored ファイル、データベース、外部データも別に記録してください。この確認でそれらの転送が証明されるわけではありません。

例：元ホストにステージ済み note.md、未ステージの core.mjs、未追跡の local-note.txt があり、先ホストは同じコミットでもクリーンで local-note.txt がありません。基準版は同じでも三つの作業は確認できておらず、引き継ぎ完了にはできません。両側の新規編集を止め、元の記録と必要な内容を比べて不足を解決します。電話からノート PC に替えて同じホストを操作するだけなら、新しい読み取りは必要ですが追加のファイル転送は不要です。

デスクトップで対象課題の下部実行場所から移動先を選び、ホストとブランチを確認して Hand off を実行します。移動先 worktree に課題と Git 状態が移り、実行中の返答は中断されます。課題では確認できる区切りにしておきます。別課題への自然言語依頼では対象とホストを明記し、依頼元自身は移せません。

成功後も印、場所、コミット、差分と新しい worktree を確認します。未追跡資料、DB、環境変数、ツール、サイト認証の移動を仮定せず、必要物を確かめてから再開します。戻す場合は This computer を選び再確認します。Codex cloud への Handoff は対象外なので[クラウド手順](article:codex-cloud-tasks-github)を使います。

## 問題の切り分けと完了条件

見つからない課題はホスト、ワークスペース、ペアリング、プロジェクトを調べてから新規作成を考えます。古い返答は Revision: 2 の再読、移動先欠落は保存したリポジトリと子ディレクトリ、新ホストでの実行失敗は道具と依存を確認します。移動成功はテスト成功ではありません。切断後は状態を見て二重の書込み依頼を避けます。

記入済み handoff.md、二版の新規読取り、古い記録との相違、復元確認を残します。実際に別ホストを使った場合だけ Handoff 前後と道具の確認を追加し、未実施は未実測とします。入口は公式資料で確認し、単一ローカルフォルダーを真のホスト移動とはしていません。[長い作業の引継ぎ](article:codex-context-handoff)にも応用できます。
