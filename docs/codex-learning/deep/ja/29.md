## 目標と準備

> 架空のローカル一覧を定期確認し、時刻、結果、変更、停止を追跡します。読む時間15分、実習20分で待機時間は別です。Scheduled 対応のアカウント・デスクトップで[タスク管理](article:codex-project-management)を先に読みます。記載の依頼文は教材で、利用者の予約を作成した証拠ではありません。

## 手順1：実行場所を選ぶ

ローカル文書はアクセス可能なホスト、電源、稼働中のアプリ、存在するディレクトリが必要です。Windows、macOS、Linux の実際のデスクトップ版で Scheduled の有無を確認し、入口がなければ現在のバージョンでは利用不可と記録します。CLI と IDE には管理 UI がないため、準備後に対応するデスクトップまたは Web で管理します。

| 目的 | 選択 | 確認環境 |
| --- | --- | --- |
| 同じ会話で追跡 | 会話内予約 | 文脈とデータ |
| 毎回独立報告 | 独立予約 | 保存依頼とプロジェクト |
| ローカル教材読取り | デスクトップホスト | 電源・アプリ・ディレクトリ |
| アップロードや接続情報 | 対応 Web・携帯 | プラン・ツール・権限 |

Web は PC ディレクトリを自動取得しないので、今回は同じデスクトップ会話へ戻します。

## 手順2：まず通常タスクで試す

空の practice-schedule に下記文書を UTF-8 で作り、デスクトッププロジェクトとして開きます。daily という名で毎日実行されるわけではなく、予約設定が頻度を決めます。顧客、鍵、正式パスは含みません。

```markdown practice-schedule/daily-check.md
# Practice check
Revision: 1
- [x] Read the task instructions
- [ ] Review the practice report
```

```text 通常入力欄：一度手動検証
Read daily-check.md from this practice project once now.
Report its Revision, completed count and open count, using the current file contents.
If the file is missing or unreadable, report that exact limitation and stop.
Do not edit files, create a schedule, send messages elsewhere or call external services.
```

Revision 1、完了1、未完1と読取り活動を確認し、全経路・結果・未変更を残します。通常でも読めなければ経路や権限を先に直します。動作試験だけで時刻起動、背景環境、通知を確認したことにはなりません。

## 手順3：追跡できる予約を依頼

```text デスクトップ：この実習予約を作る場合に送信
Create one recurring check named 'Practice list review' in this existing task.
Run every Monday at 09:00 in the Asia/Taipei time zone.
On each run, reread daily-check.md from this local practice project.
Report the current Revision, completed and open counts. Do not rely on an earlier report.
If the file or required access is unavailable, stop the run and report the limitation.
Keep the source file unchanged and do not contact external services.
Notify me on the first result, meaningful changes or failures; stay quiet when nothing changes.
Show the saved schedule and next run time so I can verify them.
```

Scheduled で保存項目、Active、時刻・タイムゾーン、対象プロジェクトを確認します。口頭の約束だけでは作成証拠になりません。月曜九時後なら次週の場合があるため、今日必ず実行とせず次回表示を見ます。

即時実行があれば使い、なければ観察できる近時刻へ保存して実起動を待ちます。同名をもう一つ作りません。識別情報、次回、実行履歴を残し、保存・開始・終了・結果ありを分けます。

## 手順4：毎回の原本再取得を確認

初回1／1の後、原本を手動で Revision 2・両完了へ変更します。新しい2／0を依頼文へ書かず、次実行が読取りで得ることを確認します。直前に答えを教えて復唱させる検証にはしません。

```markdown daily-check.md に手動保存する第 2 版
# Practice check
Revision: 2
- [x] Read the task instructions
- [x] Review the practice report
```

同じ状態で再実行し、変化がない場合の通知条件と履歴を確認します。プッシュ通知がないことは未実行を意味しないため、OS 通知、アプリ通知、スケジュールの報告条件を分けて調べます。毎週同じ内容でも受け取りたい場合はそう指定し、常時通知と変化なしの無通知を同時に求めません。

## 手順5：変更・一時停止・停止範囲

```text 同じ親：既存予約を更新
Update the existing 'Practice list review' schedule to Wednesday at 10:00 Asia/Taipei.
Keep its task, project, read-only prompt and notification preference unchanged.
Show the updated next run time. Do not create a second schedule.
```

同項目の新時刻と重複 Active がないことを確認します。同名はプロジェクト・依頼・識別で区別します。出所・動作変更は通常タスクで再検証してから更新し、曜日時刻だけなら無関係の再試験は不要です。

```text 実習終了：同じ予約を一時停止
Pause the existing 'Practice list review' schedule after this practice.
Confirm it is Paused and show whether any run is already in progress.
If a run is in progress, report its state before stopping anything else.
```

Paused を確認します。未来の停止と開始済み実行の中止は同じではないので最新実行も見ます。不要なら提供された削除後に一覧不在を確認し、既存報告や外部変更まで戻ったとはしません。再開は同じ一件の次時刻を確認します。

## よくある問題と失敗演習

未実行は状態・タイムゾーン・次回、電源・アプリ・プロジェクトを確認します。睡眠中の取りこぼしが必ず補完されるとはせず履歴を見ます。読取り不可は経路と[権限](article:codex-permissions)、新認可が必要ならその失敗を報告し、無人実行を全面認可としません。

失敗演習前に予定を一時停止し、読取り中の実行がないことと daily-check.saved.md の不在を確認します。既存バックアップは上書きせず別名を選びます。自分の daily-check.md を改名して元名の不在を確認し、同じ読取りを手動で試します。欠落を報告し、2／0 再利用や空一覧にしません。名前を戻して Revision 2 を確認します。背景通知の実測とは区別します。

出所、タイムゾーン、保存項目、実際のスケジュール結果、変更後の再読取り、変更時刻、Paused を残し、未提供・未起動なら部分完了とします。イベント起動には別の制限があるため、定時実行を Gmail・Slack 監視とは扱いません。公式資料による確認であり、利用者のスケジュール作成や全 OS の実測は主張しません。次は [codex exec](article:codex-exec-scripting) です。
