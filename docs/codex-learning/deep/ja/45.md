## 目標と準備

> 正しい CLI セッションを再開し、別プロジェクトの同名ファイルを区別して最新ディスク状態を読んでから続けます。読む時間12分、操作20分です。各 OS の認証済み CLI とエディターを使います。端末のパス操作が前提で、Git、検索、本番データは不要です。

resume は以前の会話とセッションを続け、ディスクを巻き戻しません。自分や別課題が編集したファイルを再確認します。[fork](article:codex-project-management)の別作業作成や[ホスト移動](article:codex-cross-device-workflow)とも区別します。

## 手順1：区別できる二つの教材を作る

同じ親に codex-session-a と codex-session-b を作り、それぞれの note.txt に次の別々の例を保存します。一つのファイルに両方は入れません。同名でも印が違うため、名前だけで場所を推測できません。親の場所を記録し、起動前に確認します。

```text ファイル内容：codex-session-a/note.txt に保存する
SESSION-A
Revision: 1
```

```text ファイル内容：codex-session-b/note.txt に保存する
SESSION-B
Revision: 100
```

A を開いた統合端末で、Windows の PowerShell は Get-Location、macOS／Linux は pwd を使い、codex-session-a を確認して起動します。次の依頼で A の実パス、SESSION-A、Revision: 1 と無変更を期待します。一覧に表示される題名と時刻を記録します。

```sh システム端末：先に本文で指定した練習ディレクトリを確認する
codex --cd . --sandbox read-only
```

```text 自然言語の依頼：この練習の Codex タスクに入力する
Read note.txt from the current directory without changing files. Report the exact directory and both lines. This is a session-resume exercise. Do not search other folders or infer content from the filename.
```

/exit で A を終了してシェルへ戻り、B から同じ手順を行います。SESSION-B、Revision: 100 を確認して終了します。B が新しくても次は A を探すため、単一の最近課題だけより正しい選択を確認できます。

## 手順2：一覧で A を再開

A のシェルで codex resume を実行し、パス、時刻、見える内容を確認して A を選びます。他の場所を探すなら --all を使い、全体の最新を目的と同一視しません。画面の操作案内に従い Enter 前に場所を読みます。

```sh システム端末：先に本文で指定した練習ディレクトリを確認する
codex resume
```

```sh システム端末：先に本文で指定した練習ディレクトリを確認する
codex resume --all
```

現在地と保存場所が違うと CLI が場所を尋ねる場合があります。A を選び、/status と新しい読取りで確認します。tui.resume_cwd や --cd があれば動作が変わるので[設定切り分け](article:codex-config-troubleshooting)を参照し、質問が出ないだけで正解としません。

| 方法 | 用途 | 先に確認 |
| --- | --- | --- |
| codex resume | 一覧選択 | パス、時刻、内容 |
| codex resume --last | 現在地の最新 | 正しい現在地 |
| codex resume --all | 他の場所も表示 | 最新が目的とは限らない |
| codex resume SESSION_ID | 既知 ID 指定 | 実在 ID に置換 |
| /resume | CLI 内で一覧 | シェルではなく Codex に入力 |

## 手順3：再開後に最新のディスクを読む

A を終了し、A/note.txt の二行目だけ Revision: 2 にして B は保持します。A から次を実行します。--last は現在地の最新が対象で、--all は範囲を広げます。他の A 課題もあれば一覧や既知 ID を使い、最新を推測しません。

```sh システム端末：先に本文で指定した練習ディレクトリを確認する
codex resume --last --sandbox read-only
```

次を送り、旧会話の1とディスクの2、変わらない SESSION-A を確認します。差は課題であり、記憶の数字に戻して直す不具合ではありません。テスト記録、未コミット変更、引継ぎが現在版を表すかの確認にも使えます。

```text 自然言語の依頼：この練習の Codex タスクに入力する
Resume by reading note.txt from disk again now. Compare the current revision with the earlier conversation. Report the current directory, the file marker, and any difference. Do not restore an older value or edit any file.
```

## 応用：会話を分岐してもファイルは確認する

別の考え方を試すには CLI を終了して A に戻り、下の fork を実行します。元の A を内容と場所で選び、新しいセッション ID を記録します。会話の分岐はファイルのバックアップではありません。この Git なしの練習では worktree を使わず、同じフォルダーを参照し得るので双方を読み取り専用にします。使えなければ codex fork --help と版を確認してください。

```sh システム端末：先に本文で指定した練習ディレクトリを確認する
codex fork --sandbox read-only
```

```text 自然言語の依頼：この練習の Codex タスクに入力する
This is a read-only alternative branch of the session exercise. Read note.txt from disk now and report its actual path, marker and revision. Describe one different way to verify the file without changing it. Do not assume that forking created a separate file copy or restored Revision: 1. Do not edit files.
```

分岐後も現在の A の Revision: 2 を読み、元の会話は残るのが期待です。完全パスが同じなら会話は別、ファイルは共有と記録します。分岐を終了し元の A を選び直して再読してください。会話の終了や削除はファイル復元ではありません。Git 作業場所の分離は [Worktree](article:codex-worktrees) で扱います。

## 問題の切り分け、停止、復元

見つからなければ OS、ユーザー、CODEX_HOME、ホストと --all を確認します。デスクトップと CLI の同名課題を同じ保存先と仮定しません。B を選んだら追加依頼を止め /exit で A を選び直します。書込み済みなら実際の変更先を確認し、退出を取消しとしません。古い版には再読と場所確認を求めます。

指示ファイル変更後は現在の小段階を区切り、新規セッションで検証します。resume を旧指示の万能リセットにしません。[規則範囲](article:codex-agents-md-scopes)と[文脈の引継ぎ](article:codex-context-handoff)で決定、実ファイル、未完了を残し、要約をバックアップとしません。

A / B の識別、新しい再読、--last と --all の違いを残します。A だけ1に戻し B は100のまま確認し、セッションや認証は削除しません。命令は公式資料と help の確認で、読者の実行や自動同期を保証しません。実作業でも課題、場所、版を先に確認します。

図1は A/B の識別、2は正しいセッション選択、3はディスク再読と版確認です。再開時にこの三点を確認します。
