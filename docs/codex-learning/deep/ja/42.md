## 目標と準備

> 三つの新規 CLI セッションでルート、子ディレクトリ、override を比べ、規則が効かない理由を切り分けます。読む時間12分、操作25分程度です。CLI と AGENTS.md の基礎、Git、エディター、Codex 認証が前提です。規則の内容は各 OS 共通で、場所を確認するコマンドだけ異なります。

[AGENTS.md](article:codex-agents-md) は作業指示、[config.toml](article:codex-config-toml) は別の優先順位を持つアプリ設定です。権限を増やさず、返答の印と共通要件を観察します。ファイルを引用できても起動時に読まれた証明にはならず、動作と作業場所も確認します。

## 読込み順を理解する

全域は通常ユーザーの .codex、CODEX_HOME があればその場所です。プロジェクトは認識したルートから現在地までを辿り、兄弟フォルダー全体は探索しません。各層で AGENTS.override.md、AGENTS.md、設定済み代替名の順に最大一つを選びます。深い層は衝突項目を上書きし、両立する要件は残ります。

| 状況 | 選択する規則 | 仮定しないこと |
| --- | --- | --- |
| ルート起動 | ルート | 全子フォルダーを読んだ |
| ui 起動 | ルート、ui | 強制ポリシーを無効化できる |
| ui に非空 override | ルート、ui override | 同層 AGENTS.md も結合する |
| 旧セッションで編集 | 以前の文脈が残る場合がある | 保存したので再読済み |

## 手順1：独立した規則の実験を作る

新しい codex-rules-lab に ui と data を作り、override はまだ置きません。エディターで開き、PowerShell は Get-Location、macOS / Linux は pwd で新規教材の場所を確認します。次の Git 初期化でルートを明確にし、コミットやリモート接続は不要です。

```sh
git init
git rev-parse --show-toplevel
```

ルート AGENTS.md に次の全文を保存します。ROOT-LAB は観察用の接頭辞、KEEP-DATA は下位でも残す共通要件です。教材の印なので、本番では実際のテスト、データ保持、交付要件に置き換えます。

```markdown
# Root practice instructions

- Start the final answer with ROOT-LAB.
- Include KEEP-DATA in the final answer.
- Do not change any files for the rule-discovery exercise.
- Report checks that were actually performed separately from unverified claims.
```

二つ目を ui/AGENTS.md、資料メモを data/README.md に保存します。README は意図的に AGENTS ではなく、該当する代替名設定がなければ Markdown だけを理由に起動指示にはなりません。大文字小文字と .txt の混入を確認します。

```markdown
# UI practice instructions

- Start the final answer with UI-LAB instead of ROOT-LAB.
- Include UI-BASE in the final answer.
```

```markdown
# Data notes

This folder describes fictional practice data.
DATA-NOTE is a document marker, not a required answer prefix.
```

## 手順2：二つの場所から起動する

教材ルートで最初の唯読起動コマンドを実行し、Codex へ次の依頼を送ります。規則の全文や期待接頭辞は貼りません。ROOT-LAB と KEEP-DATA を期待します。/exit でシェルに戻り、resume せず二つ目のコマンドで ui の新規セッションを作ります。

```sh
codex --cd . --sandbox read-only
```

```text
Without changing files, report the current working directory and the project instruction sources already available to this session. Follow the active response-format instructions. Do not search unrelated sibling folders just to collect more rules. Distinguish known loaded instructions from files you have not inspected.
```

```sh
codex --cd ui --sandbox read-only
```

ui でも同じ依頼を送り、UI-LAB、KEEP-DATA、UI-BASE を確認します。接頭辞は下位が上書きし、両立する根の要件は残ります。手動読み取りを依頼して初めて説明できたなら、起動時の発見と分けて記録します。モデルの自己申告は読込みログではなく、不十分な証拠を成功扱いしません。

## 手順3：同じ層の override と比較

ui を終了し、AGENTS.md を残して次の AGENTS.override.md を同層に追加します。教材ルートから同じ ui 起動コマンドと依頼を使います。UI-OVERRIDE と KEEP-DATA が期待値で、置き換えられた同層からの UI-BASE は入りません。override はその層の候補を替え、根や全域すべてを消すものではありません。

```markdown
# UI override practice

- Start the final answer with UI-OVERRIDE instead of ROOT-LAB.
- Include OVERRIDE-ACTIVE in the final answer.
```

境界確認ではバックアップして override を空にし、新規起動の結果を記録します。本機 codex-cli 0.154.0-alpha.6.2 の診断入力は空の本文を含まず、同層 AGENTS.md も読まず、根の規則だけでした。空ファイルを確実な無効化方法とせず、代替名にない override.saved.md へ改名して新規起動し、UI-LAB、UI-BASE、KEEP-DATA を確認します。全域や設定全体は削除しません。

## 失敗の切り分けと完了条件

印がなければ拡張子、空でない内容、Git ルート、--cd を確認します。古い印なら resume ではなく新規起動か、部分欠落なら同層 override、全域、上位指示を調べます。深い AGENTS.md は組織規則、権限、ユーザー依頼を越える許可ではありません。衝突源を特定して変更可能な指示を直します。

長い指示は既定の合計32 KiBに達する場合があり、文字数ではなくバイト数です。必要規則を残し、長い設計や例は普通の文書として必要時に読みます。兄弟フォルダーに分割しても全部自動読込みにはなりません。代替名や上限は[設定](article:codex-config-toml)で扱い、変更後に再起動検証します。

ルート、ui、override、空 override、改名復元の起動場所、ファイル状態、実際の印を残します。KEEP-DATA を維持し、override を外すと ui に戻ることを確認します。本機は debug prompt-input の実入力を確認し、モデル要求や遵守の主張はしていません。仕様と版の違いを記録し、返答動作は新規セッションで別途確認します。[規則と文書の分担](article:codex-rules-and-context-files)へ進めます。
