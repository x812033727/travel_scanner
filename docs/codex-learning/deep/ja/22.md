## 目標と準備

> 次のセッションが使える handoff.md を作り、意図的に古い記録で信頼性を試します。読む時間12分、操作22分です。デスクトップまたは CLI、エディター、対応する Node.js 22 以降、独立した Small Steps 教材を使います。3 OS 共通で、現在地の確認命令だけが異なります。

[セッション再開](article:codex-sessions-resume)は会話を残しますが、最新ディスクとは限りません。引継ぎは目的、確認済み事実、未解決点、次の操作を記録して再検証を可能にします。会話全コピーでも自動読込みの保証でもなく、新課題で読むよう明示します。

## 手順1：故障コピーと状態の印を用意

[最初の教材 ZIP](article:codex-first-project)の broken 内5ファイルを、新しい codex-handoff-lab へコピーします。start と違い Completed が未完了を返します。ルートに次の LAB_STATE.txt を作り、PowerShell の Get-Location または macOS/Linux の pwd で確認してテストします。

```text
Lab: codex-handoff-lab
Revision: BROKEN-1
```

```sh
node --test core.test.mjs
```

2成功1失敗で、失敗はフィルターです。実際に観測してから確認済みと書きます。Node 不足や場所違いなら障害と実エラーを書き、数を推測しません。アカウント、鍵、私的な全出力は残さず、架空の印と必要なテスト情報に絞ります。

## 手順2：検証可能な引継ぎを書く

ルートに handoff.md を作ります。次の完全例は上の基準結果を実測した前提です。違えば Observed を修正します。Goal は成果、Scope は許可範囲、Observed は版と命令、Not checked は未確認、Next は次の確認を示します。

```markdown
# Small Steps handoff

## Goal
Completed shows only completed tasks. Keep ordering, storage and existing UI.

## Scope
Lab: codex-handoff-lab. Only core.mjs may need a program change.
Do not change tests or add dependencies. Preserve other work.

## Observed
LAB_STATE.txt: Revision: BROKEN-1.
Command: node --test core.test.mjs
Result: 2 passed, 1 failed in the filter case.
The completed branch of visibleTasks currently selects unfinished tasks.

## Not checked
Browser interaction: NOT RUN.
Publishing and deployment: NOT PERFORMED.

## Next
1. Re-read LAB_STATE.txt, core.mjs and the test file; do not trust this record over current files.
2. Re-run the baseline before deciding whether a fix is still needed.
3. If still faulty, change only the completed predicate, then test and review the diff.
4. Manually check Read completed / Build active under all three filters.

## Stop condition
If revision, test results or files differ, report the mismatch and revise this record before editing program code.
```

「いくつか変更」では検証できません。ファイル、挙動、実行命令、未実施確認を明示します。Git ならブランチと commit も加えますが、未コミット差分も見ます。同じ commit でも作業ツリーは異なり得ます。教材に架空 ID を埋めません。

## 手順3：記録を古くして新課題へ渡す

ZIP の expected/core.mjs だけ教材へ上書きし、LAB_STATE.txt を Revision: FIXED-2 に変え、handoff.md は古いまま残します。テストは3成功になるはずです。離席中に別の人が修正し、会話と文書だけ故障状態のままという状況を再現します。他ファイルとテストは不変です。

同じ教材でデスクトップの新課題を作ります。CLI は /exit 後に場所を確認して resume なしで codex を起動します。次を送り、FIXED-2、古い BROKEN-1、3成功の不一致を認識し、正しい関数を再変更せず記録更新を提案するか確認します。

```text
Continue this lab using handoff.md, but first verify it against current files. Read LAB_STATE.txt, core.mjs and core.test.mjs. Run node --test core.test.mjs. Do not edit anything yet.
Compare the recorded revision, predicate and test result with current evidence. Report mismatches and propose the smallest next step. Browser checks must remain NOT RUN unless actually performed.
```

まだ Completed 修正を提案するなら、現在の誤った行と失敗テストを求めます。最新証拠を古い記録で上書きしません。その後 handoff.md だけ更新し、Observed は FIXED-2 と実際の3成功、Next は残る画面確認とします。古い記録を再検証した理由も短く残します。

## 長い会話、compact と文書の分担

CLI の /compact は長い会話を圧縮します。対話欄で入力し、確認があれば従い、目的・制約・残作業の再述を handoff.md と比較します。教材で無理に会話を埋める必要はありません。ファイル保存、Git 復元、全詳細保持の保証ではなく、大事な決定は読める文書に残します。

| 文書 | 保存するもの | 更新時 |
| --- | --- | --- |
| AGENTS.md | 長期ルールと命令 | 作業慣習の変更 |
| README.md | 入口と起動方法 | 使い方の変更 |
| 設計文書 | 挙動、判断、制約 | 設計決定の採用 |
| handoff.md | 最新証拠、障害、次の操作 | 中断、引継ぎ、検証後 |

[ルールと文書分担](article:codex-rules-and-context-files)も参照します。一度の障害全記録を AGENTS.md に常置して全課題へ古い情報を渡しません。引継ぎ冒頭に現在目的と確認日、解決済みは短い結果、無効パスや仮説は削除または注記します。

## 対処、復元と受入

見つからなければ場所と名前を確認し、全 PC 検索をすぐ依頼しません。未読ならパスと読んだ Revision の報告を求めます。別フォルダーの成功は教材の証拠ではありません。記録と違う失敗なら両結果と時刻を残して再読し、古い記録に合わせてテストを変えません。

不一致の説明、更新済み handoff.md、core.mjs を重複変更していない証拠が完了条件です。再実行は broken/core.mjs だけ復元し、BROKEN-1 と元の引継ぎに戻します。図1は記録、2は再検証、3は次の操作更新です。モデル会話と /compact は資料手順で、実行結果は各自記録します。参考コードの故障と修正は別途ローカルテスト済みです。
