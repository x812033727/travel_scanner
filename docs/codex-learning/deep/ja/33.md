## このレッスンの到達点

> 今回の作業に合う入口を一つ選び、ファイルの場所、コマンドの実行場所、成果の確認場所を説明し、読み取りタスクで選択を確認します。読む時間は約 10 分、操作は約 15 分です。全種類のインストールは不要で、まず一つの経路を使えるようにします。

## 入口と実行環境を分ける

入口は依頼を送る場所で、環境はエージェントが実際に作業する場所です。デスクトップ、CLI、IDE はローカル作業に使えますが、リモートプロジェクトやクラウドは別環境を扱います。画面が小さいスマートフォンでも仕事量が小さいとは限らず、同じ見た目のウィンドウでも同じ機械とは限りません。ボタン数より「依頼元 → 実行する機械 → 成果の場所」を整理します。

| 入口 | 主な操作 | 最初の確認 |
| --- | --- | --- |
| デスクトップ | プロジェクト、タスク、ファイル、差分 | 選択中のプロジェクトとホスト |
| CLI | 端末のコマンドと対話 | 現在の作業ディレクトリ |
| IDE | エディター内のファイルとコード | 開いているフォルダーとファイル |
| クラウド | 設定済みの遠隔環境とタスク | リポジトリ、ブランチ、環境 |
| モバイル Remote | 接続先ホストのタスク | ペアリング先が利用可能か |

## 手順 1：普段の作業から入口を選ぶ

GUI と複数タスクの管理を使いたいなら[デスクトップ入門](article:codex-desktop-getting-started)から始めます。Windows と macOS は各 OS の公式手順を使い、Linux はデスクトッププレビューが対応するディストリビューションと構成のパッケージを選びます。Windows 用インストーラーは流用しません。Linux デスクトップがあることと Remote ホストの対応は別に確認してください。

端末でフォルダー移動やテストを行う、またはスクリプトに接続したいなら [CLI](article:codex-cli-getting-started)を選びます。Windows ネイティブと WSL は別環境なのでインストール、ホーム、パスを分けて確認します。macOS と Linux のユーザーパスもそのまま流用しません。端末に不慣れなら[パスと端末](article:codex-terminal-paths)を先に読み、二つのシェルを同時に覚える負担を減らします。

対応エディターで作業中のファイルや選択範囲を渡したいなら [IDE 拡張](article:codex-ide-getting-started)を使います。ストアの似た名前だけで選ばず、現在のエディターに公式対応があるか確認します。デスクトップと IDE の両方を入れていても、最初の編集は一方だけで行ってください。同じファイルを同時変更すると原因の切り分けが難しくなります。

## 手順 2：クラウドとモバイルの必要性を判断する

GitHub リポジトリを設定済みの遠隔環境で作業させ、差分や PR を確認したいなら[クラウドタスク](article:codex-cloud-tasks-github)を使います。開始前にリポジトリとブランチを記録します。ローカルの未コミット変更は同名だからといってクラウドには現れません。曖昧な依頼を繰り返すより、正しい版を環境に渡します。練習用 GitHub がなければ入門はローカルで進められます。

外出先でコンピューターの作業を追跡・継続するなら[モバイル Remote](article:codex-mobile-guide)を検討します。公式文書では iOS と Android から利用可能な macOS または Windows のデスクトップホストを操作します。ホストの接続、ペアリング、ワークスペース権限が必要です。npm、プロジェクト、ローカルブラウザーを電話へ移す機能ではありません。ホストが停止・オフラインなら接続を復旧し、電話にパッケージを入れて直そうとしないでください。

## 手順 3：小さなタスクで確かめる

空の codex-platform-check フォルダーを作り、location.txt に Practice marker: local-copy-A の一行を書きます。デスクトップや IDE はそのフォルダーを開き、CLI は移動してから起動します。クラウドなら自分の練習用リポジトリに同じファイルを作ってコミットし、それを含むブランチを選びます。入口確認のために本番プロジェクトをアップロードしないでください。

```text
Read location.txt without changing files.
Report the exact marker, working directory, and where commands for this task run.
Distinguish verified facts from anything you cannot determine.
Do not install tools, create files, or change settings.
```

local-copy-A を読み、ツール結果で裏付けられた作業パスを示すことが期待されます。隔離コピーを使う入口もあるため、自分のデスクトップと同じ文字列のパスである必要はありません。ブランチ、目印、環境が一致するかを見ます。ホストを特定できなければ不明と記録し、推測を成功扱いせず接続設定を確認します。

境界の練習ではローカルだけを local-copy-B に変え、コミットしません。既存クラウドコピーで A が読めても、それは版の違いを示す証拠で、モデルが忘れたとは限りません。同じホストとフォルダーを操作する電話では、そのホストの現ファイルを基準にします。「最新ですか」より出典と目印を毎回報告する方が確実です。

## よくある問題と完了条件

入口がなければ公式対応、バージョン、ワークスペース、段階的提供を確認し、未確認を残します。ファイルがなければフォルダー、クラウドのブランチ、ホスト、コミットを見ます。コマンドがなければ実際の実行環境で調べ、手元の Node.js をクラウドにもある証拠にしません。入口、データの版、実行環境の問題をすべて再ログインで解決しようとしないでください。

終了時は目印を A に戻し、フォルダーは後の練習に残します。止めるのは今回作ったタスクだけです。「入口は＿＿、ファイルの環境は＿＿、成果確認は＿＿」と説明できれば完了です。別入口でファイルの場所が分からなければ、多重作業より読み取り確認を先にします。図の 1、2、3 は入口の選択、環境確認、成果検証です。
