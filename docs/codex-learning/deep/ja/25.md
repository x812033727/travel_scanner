## 目標と準備

> OpenAI の読取り専用文書 MCP を接続し、一問を調査、原文を照合し、実習項目を無効化・削除します。読む時間15分、実習20分。ネット接続したデスクトップ、CLI、IDE を使い、CLI は[導入](article:codex-cli-getting-started)を先に済ませます。非公開文書、有料サービス鍵、第三者 npm サーバーは使いません。

MCP はツール実行と文脈取得の協定です。能力はサーバー次第で、文書接続から GitHub やローカルブラウザーへの権限は生まれません。Docs MCP は文書検索・取得を行い、利用者の代わりに OpenAI API を実行しません。後で書込みサービスへ替える場合は[権限範囲](article:codex-permissions)を再確認します。

## 手順1：接続方式と設定場所を選ぶ

| 方式 | 必要情報 | 実行場所 |
| --- | --- | --- |
| STDIO | 程序と引数 | Codex ホストがローカルプロセスを起動 |
| Streamable HTTP | MCP 端点 URL | ネット経由のサービス |
| プラグイン由来 | 導入と必要な接続 | 個別の提供条件による |

今回は Streamable HTTP のみです。一般のホームページは MCP 端点とは限らず、公式の端点を使います。STDIO 命令を URL 欄へ貼りません。

同じ Codex ホストのデスクトップ、CLI、IDE は設定を共有します。既定は ~/.codex/config.toml で、Windows の利用者フォルダー、macOS・Linux のホーム下の .codex にあります。既存の独自 CODEX_HOME があればその場所を確認します。信頼済みプロジェクト設定もありますが、今回は利用者層を使います。[config.toml](article:codex-config-toml)で場所を確認できます。

## 手順2：既存項目を確認してから追加

```sh 端末：設定済みサーバー一覧
codex mcp list
```

Windows PowerShell、macOS・Linux の端末で実行し、codex 対話には先に入りません。codexLearningDocs があれば詳細を確認し上書きしません。同じ公式 URL の既存項目を使う場合は名称をそのまま用い、再利用と記録して終了時も残します。一覧に非公開 URL が含まれることがあるため全出力を公開しません。

追加前に実際の利用者 config.toml を開き、以前のコピーを上書きせず日付付きで保存します。存在しなければその状態を記録し空ファイルは不要です。一変更の前後差分を残し、機密を含み得るコピーは Git 外のローカルで保持します。復旧は追加区画だけを除き、他作業の新設定を古いコピーで上書きしません。

```sh 3 OS の端末：実習項目を追加・確認
codex mcp add codexLearningDocs --url https://developers.openai.com/mcp
codex mcp get codexLearningDocs
```

get で名前、HTTP、公式 URL が一致することを確認します。証明できるのは保存のみで、到達、列挙、問い合わせ成功ではありません。ツール数は変わるので固定数を写さず、管理命令の終了0も読取り証拠にはしません。命令がなければ codex mcp --help と更新手順を確認します。

## デスクトップと IDE の同等手順

CLI を使わない場合はデスクトップの Settings → MCP servers → Add server で名称、Streamable HTTP、同じ URL を入力して保存し Restart します。IDE の歯車から同じ欄を設定し Restart extension します。各 OS の利用可能なクライアントで行い、Linux プレビューなどで UI がなければ CLI を使います。ボタン不在はサービス障害とは限りません。

```toml config.toml の確認用区画：二重追加しない
[mcp_servers.codexLearningDocs]
url = "https://developers.openai.com/mcp"
```

これは同じ設定のファイル表現で、CLI、UI、直接編集の一つを選びます。命令追加後に同じ表を貼ると重複エラーになり得ます。直接編集は区画のみ統合して再起動します。Web・携帯は PC のローカル設定を読まず、ホスト側能力は [Plugins](article:codex-plugins) を使うため、ローカル成功を携帯設定済みとはしません。

## 手順3：ツールを確認して原文を取得

```text Codex 対話欄：端末命令ではない
/mcp
```

新規タスクで /mcp を入力し、実習サーバーと利用可能なツールを確認します。認証要求があれば公開端点が正しいかを先に照合します。他の OAuth サービスは Authenticate や login が必要でも、この文書サービスへ任意の API key を渡しません。別サービスの手順を写さず現在の表示で判断します。

```text 新規タスク：MCP で規則を確認
Use the codexLearningDocs MCP tools to find the official AGENTS.md instructions.
Read the relevant page and explain global versus project rules in three bullets.
Include the source URL and the section you checked.
If the MCP tools are unavailable, report that limitation instead of answering from memory.
Do not edit files or call paid APIs.
```

再利用なら要求内の名前を置き換えます。検索・取得の活動を観察し、公式ページを開いて説明を支える区画を確認します。文章形式やツール名の固定ではなく、証拠、URL、内容の一致を検証します。MCP を使わない正解は一般回答で、この接続実習の完了ではありません。

## 手順4：無効化・再試験・削除

失敗対照は自分が追加した項目だけを対象に、既存区画の enabled = false または無効化操作で保存・再起動します。新規タスクの /mcp で利用不可を確認し、旧会話の文を新取得としません。true または自分が加えた false の除去で戻し、再起動後に再取得します。

```sh 端末：今回の追加項目だけ削除して一覧を確認
codex mcp remove codexLearningDocs
codex mcp list
```

削除後は新規タスクに今回の項目が出ないことを確認します。他サーバー、文書、別 OAuth の失効は行いません。再利用項目なら削除を省略し、未変更ならそう記録します。認証ありサービスの remove と logout は別目的なので [MCP 障害対応](article:codex-mcp-troubleshooting)で確認します。

## 問題と完了条件

見えない場合は階層、名前、有効状態、再起動を確認します。TOML エラーは重複表と引用符を見て全体を初期化しません。接続失敗は URL、ホストネット、サービス状態と伏せたエラーを残します。出典なしは原文取得を再要求します。四種類の原因を全て権限緩和で扱いません。

実版、設定保存、出典付きツール結果、追加項目の無効化・削除を記録します。Windows の隔離設定試験と公開協定試験は別記できても、デスクトップ UI、macOS、Linux、利用者のモデル実行を証明しません。未操作環境は公式確認と明示し、[接続雛形](article:codex-templates-cheatsheet)へ残します。
