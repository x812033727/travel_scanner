## 目標與兩條入口

> 在 Linux 或 Windows 的 WSL2 中安裝 Codex CLI，分辨主機、發行版與檔案位置，完成標記檔唯讀驗證及更新。閱讀約 12 分鐘，操作約 30 分鐘；初次安裝 WSL、重開機與下載另計。本篇依 2026-09-14 官方檔案查證，未在 Linux／WSL 實機執行，也沒有使用 Windows 畫面冒充 Linux 截圖。

本來就在 Linux 電腦上，直接開該系統的 Terminal，從步驟二開始。Windows 使用者先決定是否真的需要 Linux 工具；原生 PowerShell 可以使用 Codex，不必為了 CLI 強制加裝 WSL。已有 Linux 開發環境或專案依賴 Linux 時才走 WSL2。兩者的選擇與[Windows CLI](article:codex-cli-windows)並列，不是 Windows 安裝失敗就無條件搬家。

圖中 1 是辨認正在輸入指令的環境，2 是安裝並進入 Linux 專案，3 是從同一環境讀檔驗收。Linux 的家目錄、工具和認證預設各自存在；在 Windows 成功執行 codex --version，不能證明 Ubuntu 裡也已安裝。反過來，WSL 的登入完成也不能單憑這點判定 Windows 桌面端已登入。

## 步驟一：Windows 使用者確認 WSL2

在 Windows PowerShell 執行下面的查詢，先看是否已有發行版，以及 VERSION 欄是否為 2。這不是 Linux shell 命令。已有 WSL2 就保留它，不重灌、不刪除發行版。官方現行 Codex Linux 沙盒不支援 WSL1；若現有專案還在 WSL1，先備份並依 Microsoft 檔案規劃轉換，不要對唯一的工作副本直接試改。

```powershell
wsl --list --verbose
```

沒有安裝 WSL 的讀者，先確認電腦政策允許啟用虛擬化與 WSL，再按 Microsoft 檔案在系統管理員 PowerShell 執行 wsl --install，依提示重開機與建立 Linux 使用者。這是安裝作業系統環境，不是只下載一個 npm 套件；需要安排中斷其他工作的時間。公司電腦依管理政策處理，不另教繞過限制。

```powershell
wsl --install
```

安裝完成後在 Terminal 選自己的 Linux 發行版，或於一般 PowerShell 執行 wsl 進入預設發行版。有多個發行版時，用 wsl --list --verbose 的真實名稱選擇，不要照抄不一定存在的 Ubuntu。進入後提示符號與路徑變成 Linux 形式；以下步驟全部在這個 Linux shell 執行。

## 步驟二：辨認 shell、CLI 和家目錄

```bash
uname -s
pwd
printf '%s
' "$WSL_DISTRO_NAME"
command -v codex
type -a codex
```

uname 預期顯示 Linux；WSL_DISTRO_NAME 在 WSL 會指出發行版，一般 Linux 留空是合理的。command -v 與 type -a 應指向你打算在 Linux 使用的安裝；若出現 /mnt/c 下的 Windows 包裝程式，不要只因命令能跑就當成 Linux 安裝。先記錄來源，後續把 CLI 安裝在 Linux 環境，並重新核對 shell 實際選到哪一份。

新裝使用官方獨立安裝命令，先核對來源，完成後閱讀 PATH 指示並開新 Linux 終端機。已用 npm 的讀者可在同一個 Linux 環境確認 node 和 npm 版本，再用 npm install -g @openai/codex；不把 Windows 的 Node.js 當作 Linux 的前置依賴。一次選一種管道，之後更新保持一致。

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

```bash
command -v codex
codex --version
codex --help
```

安裝輸出、實際路徑和版本三者要能對上。curl、sh 或系統工具本身不存在時，先依你的 Linux 發行版檔案準備工具；不要照抄另一個發行版的套件管理指令。CLI 能啟動仍不代表專案依賴或 Linux 沙盒已正常；後面的實際讀檔會檢查第二層。

## 步驟三：在 Linux 家目錄建立練習檔

WSL 專案若由 Linux 工具執行，優先放在 Linux 家目錄，例如 ~/code 下；/mnt/c 是 Windows 檔案系統的掛載入口，與 /home 不是兩個名稱指向同一份專案。不要為了本練習搬動正式專案。下面用新資料夾示範，若目錄已存在會保留內容並停止建立；換新名字再試。整個區塊在子 shell 執行，結束後依下一段明確切入。

```bash
(
  set -e
  cd ~
  mkdir 'codex linux lab'
  cd 'codex linux lab'
  printf '%s
' 'LINUX-CLI-01' > note.txt
  cp note.txt note.original.txt
  pwd
  ls
)
```

建立成功才執行下一個區塊。若 mkdir 顯示 File exists，表示它保護了原資料，並不是需要加 sudo；先選新目錄。切入後應看到兩個檔案及 LINUX-CLI-01，兩份 SHA-256 相同。這個相同是本機兩份相同位元組的比對，不要求與 Windows 的檔案雜湊一致。

```bash
cd ~/"codex linux lab"
pwd
cat note.txt
sha256sum note.txt note.original.txt
```

## 步驟四：在同一個 Linux 環境登入與讀取

```bash
codex login
codex login status
codex --sandbox read-only
```

逐行等候完成，依實際登入畫面處理；WSL 可能透過主機瀏覽器完成認證，完成頁出現後仍要回 Linux 終端機確認登入結果。沒有瀏覽器或本機回呼不可用時，先查 codex login --help 及官方認證頁；只有帳號與組織允許裝置碼流程時，才用 codex login --device-auth。不要把 Windows 認證檔複製到專案來解決登入。

```text
Read note.txt and note.original.txt in the current Linux practice directory. Report the current directory and the exact marker, and check whether both files match. Do not edit, create files, or use external services. Stop and report any missing file or access error.
```

上段是 Codex 對話，不是 bash 命令。要求的目錄應是 Linux 練習資料夾，標記 LINUX-CLI-01；同時看實際讀取記錄。/exit 回 shell 後重跑 sha256sum、cat 和 ls，核對沒有改動。再要求讀取不存在的 note-missing.txt，預期清楚回報缺檔而不新增。能完成這兩種結果，才驗證安裝、登入、定位與讀取串在一起。

## 檔案位置、更新與排錯

| 位置或工具 | 代表的環境 | 本篇怎麼判斷 |
| --- | --- | --- |
| C:\Users 路徑 | Windows 本機 | 在 PowerShell 用 Get-Location |
| /home 下的專案 | Linux／WSL 的檔案系統 | 在 Linux shell 用 pwd |
| /mnt/c 下的專案 | Linux 看到的 Windows 掛載磁碟 | 不當成 /home 的另一個副本 |
| Linux 的 codex | Linux shell 選到的 CLI | command -v 與版本一起核對 |

如果 Linux 工具專案放在 /mnt/c 而操作很慢，先用新的 Linux 家目錄練習副本比較，不要直接移動或刪除唯一原稿。需要從 Windows 檔案總管檢視 WSL，可用官方檔案說明的 `\\wsl$` 入口選實際發行版；這是存取 Linux 檔案，不是把兩份內容同步。兩個目錄都存在時，用標記與 pwd 判斷，不憑同名資料夾猜測。

更新前先退出 CLI 並記錄工作摘要。獨立版重跑 Linux 的官方安裝命令，npm 版用同一個 Linux 的 npm 更新，然後開新 shell 核對 command -v 和版本。wsl --update 更新的是 WSL，不能代替 CLI 更新；wsl --shutdown 會停止 WSL 執行中的工作，不要把它當作每次安裝 Codex 必做的步驟。

shell 能讀、Codex 不能讀時，記錄沙盒啟動或許可權錯誤，先確認 WSL2 與發行版環境，依[許可權教學](article:codex-permissions)排查，不要一律關閉沙盒。找不到舊工作階段時，核對是否換了發行版、Linux 使用者或 CODEX_HOME；本篇不設定共用認證目錄，以免把登入和工具來源混在一起。後續回[CLI 共用入門](article:codex-cli-getting-started)完成修改與還原，再接[上下文交接](article:codex-context-handoff)。
