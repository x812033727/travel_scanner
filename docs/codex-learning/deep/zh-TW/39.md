## 目標與 Android 的角色

> 用 Android 的 ChatGPT Remote 找到主機上的 Codex 任務，完成讀檔、追問、切換應用程式與回到原任務的練習。閱讀約 12 分鐘，操作約 25 分鐘，配對等待另計。產品入口依 2026-09-14 OpenAI Remote 文件查證；掃碼以 Google 官方支援的相機為例，其他品牌依自己的相機功能。未在實體 Android 手機測試，不以窄版網頁圖片冒充產品畫面。

Android 負責傳送需求與查看結果，程式檔、終端機、依賴與網站登入都由連接主機提供。手機裝了 ChatGPT，不等於手機已安裝 Codex CLI，也不會把電腦資料夾自動同步到手機檔案管理 App。先了解[手機總覽](article:codex-mobile-guide)與[Remote 主機設定](article:codex-remote-setup)，就能分開辨認連線、任務與實際工作。

## 開始之前：電腦與帳號先準備好

在自己的 Mac 或 Windows 電腦安裝或更新 ChatGPT 桌面版，登入與 Android 相同的帳號及工作區，確認能使用 Codex。將[Small Steps 練習包](https://mokaair.com/guides/codex-first-project/todo-practice.zip)解壓，以 expected 副本建立 codex-android-lab 專案。保留原 expected，並先在主機確認五個程式檔存在；不要用私人正式專案做首次配對測試。

在 Google Play 核對發行者 OpenAI，安裝或更新官方 ChatGPT。Google Play 使用的帳號與 ChatGPT 登入帳號是兩件事，請在 App 裡核對與主機相同的帳號和工作區。若手機有個人／工作設定檔，或公司分開管理應用程式，確認正在開哪一份 ChatGPT；圖示相同不表示登入與政策相同。先完成 SSO、多因素驗證或通行金鑰，再進 Remote。

### 先在主機加上自己的辨識檔

在 codex-android-lab 根目錄新增 remote-check.txt，使用下方一行，儲存前把尾端 01 改成自己選的代號。若同名檔案已存在，先讀內容，不覆寫其他工作的檔案。這是五個網站程式檔之外的第六個練習檔；每個副本用不同代號，不填帳號、密碼或配對碼。在私人筆記記下代號與完整路徑，稍後不要把代號貼進提示詞。

```text 主機檔案內容：remote-check.txt；先自行更換尾端代號
ANDROID-PRACTICE-01
```

## 步驟一：從相機掃碼進入 Remote

在主機桌面版開 Settings → Connections → Control this Mac or PC，選 Set up 或 Add，完成驗證並顯示 QR code。Android 使用自己手機支援的相機或掃碼入口，讓完整碼進入畫面並點掃出的連結。Google Pixel 官方文件以相機和快速設定掃碼為例；其他品牌按自己的說明操作，不假定按鈕相同。不要把 QR 圖片上傳到聊天讓模型代配對。

若相機沒有識別，先確認碼完整、對焦與反光；Pixel 另核對相機的掃描建議是否開啟。Android 詢問用哪個 App 開啟連結時，選官方 ChatGPT，核對沒有進到另一個工作設定檔。連結停在瀏覽器時先確認 App 版本與登入，必要時從主機重新開始設定。不要為了一次連線就修改所有網址的預設開啟方式，也不要公開配對網址、碼或帳號截圖。

在手機設定流程確認帳號、工作區與主機，成功後 Remote 中應出現該主機。只看到登入完成頁還不夠；要能選主機，找到 codex-android-lab 專案並開啟 Codex 任務。如果列表是另一臺電腦，回主機設定核對配對對象。圖的 1 是 Android 入口，2 是選中的主機，3 是可核對的專案結果。

## 步驟二：送出第一個明確讀檔要求

在手機 Remote 的專案任務輸入框貼上下面內容。先檢查檔名與函式名稱沒有被鍵盤自動修正；這是自然語言提示詞，不是要 Android 執行終端機命令。送出一次後留在該任務觀察回覆，記下任務標題或可以再次辨認的資訊，避免切換 App 後找不到原工作。

```text 自然語言提示詞：在同一個手機 Remote 任務輸入
Read this Small Steps project without changing files. Confirm the working directory and inspect app.js and core.mjs. Identify the localStorage key, the field that records completion, and the function that rejects blank task titles. Cite the file for each answer. If a file is unavailable, report that instead of guessing.
```

預期回覆會從 app.js 找到 mokaair-codex-todo-v1，從 core.mjs 指出 completed 欄位及 addTask 的空白檢查，也應提供實際工作目錄。若只有一般待辦程式知識，追問它實際讀了哪個檔案；若目錄不符，先停止本次要求、回正確主機和專案。不要把一段聽起來合理的說明當成成功連線的證據。

### 再讀一次只有這份副本才有的標記

```text 自然語言提示詞：在同一個手機 Remote 任務輸入
Read remote-check.txt from this task's project now.
Quote its exact content and report the absolute file path and the tool used to read it.
Do not edit files or infer the marker from earlier messages.
If the file is missing or cannot be read, report that limitation.
```

把回覆與你在主機筆記留下的代號、路徑及讀檔紀錄比對。主機清單中的名稱與這個檔案代號是兩種資料；不要把代號當成電腦名稱。要查是否讀到新內容，可等任務完成後只在主機改代號、存檔，再送同一個讀檔要求，不先提供新代號。結果仍舊、沒有工具紀錄或路徑不符時，保留「尚未確認」，先查儲存狀態、所選主機與副本。

## 步驟三：追問、核准與查看進度

```text 自然語言提示詞：在同一個手機 Remote 任務輸入
In the same project, explain what happens when I add Read and Build, complete Read, and choose Completed. Then explain an empty task title. Separate code you inspected, tests actually run, and checks still pending. Do not edit or clear stored data.
```

這是起初沒有待辦、只加入 Read 與 Build 的假設例；若本機預覽已有其他項目，請依現有資料判讀，不會因這段唯讀要求而清空資料。 這次追問檢查同一任務的上下文，回覆應預期 Completed 只顯示 Read，空白標題被拒絕；它也應分開列出已讀程式、真的跑過的測試與尚未操作的畫面。只分析原始碼就標成「預期行為」，不能改稱已在手機完成測試。你可在電腦的本機預覽親自做上述步驟，補上驗證。

若手機出現批准要求，先看操作內容、目錄與影響範圍，再決定是否符合你剛才的要求。本例只讀檔，無須為了前進而準許新增外部帳號、發布網站或刪除資料。若看不清楚長命令，回主機檢視完整內容再處理。批准視窗沒有出現時先回 Remote 原任務確認狀態，不用連續新建任務催它。

## 步驟四：離開後回到同一任務

唯讀回覆完成後，切到另一個 Android App，再從最近使用的應用程式或主畫面回 ChatGPT → Remote，選相同主機與任務。不同手機的手勢與導覽按鈕可能不同，本篇不固定按鍵位置。先看最後一筆回覆，再要求重新讀取目前目錄；只看見快取文字不代表主機仍在線。若回來變成另一個登入環境，先核對個人／工作設定檔，不要重建同名專案。

通知用來提醒完成或需要注意，不代替成果驗收。若未收到通知，可主動回任務查看；若主機睡眠、斷網或關閉 App，先恢復主機，再核對上次要求是否已完成。尤其有寫入的後續任務，不要因手機暫時斷線就重送同一個建立或提交要求。這次以唯讀練習學會恢復工作流程。

## 完成檢查與常見誤會

| 核對項目 | 成功證據 | 不足的證據 |
| --- | --- | --- |
| 配對 | Remote 可選正確主機 | 只有相同帳號登入 |
| 讀檔 | 正確目錄、儲存鍵與函式來源 | 泛泛解釋待辦程式 |
| 接續 | 同任務的新讀取成功 | 只看到舊通知或回覆 |
| 驗收 | 電腦端核對檔案與操作 | 模型只說測試沒問題 |

主機的 localhost 網址在 Android 瀏覽器會指向手機自己，不是那臺電腦。查看練習成果時，先從 Remote 任務看主機提供的截圖或結果，再回電腦開本機預覽；公開預覽與部署是另一個步驟。要停止手機存取，依[主機設定篇](article:codex-remote-setup)管理連線，並分開確認任務是否停止；登出不會自動刪除既有配對。

最後在同一任務整理主機與目錄、已讀取內容、尚未跑的測試及下一步，再回電腦核對。你不需要在 Android 安裝 Node.js 來執行主機工具；需要的依賴應在實際主機準備。下一步看[跨裝置工作](article:codex-cross-device-workflow)與[上下文交接](article:codex-context-handoff)。若改用 iPhone，可依[iPhone 專篇](article:codex-mobile-ios)完成同一套驗收，不需重新改寫專案檔。

練習結束，回主機只移除這次由你新增的 remote-check.txt，保留五個網站程式檔。原本就存在的檔案不刪除、不覆寫。新增的標記練習與前面的程式分析都只要求讀取；未實際配對或操作的部分，要在紀錄中保留未實測。
