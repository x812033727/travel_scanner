## 讀完能做到什麼

> 你會在自己的電腦選對安裝入口，開啟一個獨立練習資料夾，請 Codex 修改待辦網站，最後以檔案差異與瀏覽器確認成果。閱讀約 15 分鐘，安裝與操作約 25 分鐘。本文依 2026-09-14 官方名稱使用「ChatGPT 桌面應用程式」，在其中選擇 Codex；舊畫面或捷徑仍可能顯示 Codex。

桌面應用程式負責讓你管理任務、檔案與成果。模型負責理解需求；任務則保存這一次工作的對話與環境。開始之前先分清楚這三件事，才不會把「換模型」誤認成「換到另一個資料夾」。需要比較入口可先看[Codex 入門](article:codex-beginner-guide)。

## 開始之前

準備能使用 Codex 的 ChatGPT 帳號及網路，依[帳號與用量](article:codex-account-usage)確認登入的工作區。方案、額度與模型選單可能依帳號不同，本篇不硬寫固定價格或指定某個模型。若已有桌面版，先使用應用程式提供的更新方式，再核對下方入口。

下載[Small Steps 練習包](https://mokaair.com/guides/codex-first-project/todo-practice.zip)，解壓縮並複製 expected 為自己的 codex-practice。這個資料夾有五個程式檔案，使用虛構資料、沒有登入或後端。本篇只改標題與樣式，先不要把正式專案選進來。預覽需要 Python 3；資料測試需要 Node.js。

## 第一步：依作業系統安裝

Windows：從 [ChatGPT 官方下載頁](https://chatgpt.com/download/)選 Windows，依官方安裝程式完成安裝，再從開始功能表開啟 ChatGPT。若你熟悉 PowerShell，也可使用官方 Windows 文件列出的命令。安裝完成後重新開啟應用程式；看不到新捷徑時先檢查安裝是否結束，不要重複下載多份。

```powershell Windows PowerShell；選用的官方安裝方式
winget install --id 9PLM9XGG6VKS -s msstore
```

macOS：同樣從官方下載頁選 macOS，開啟下載的安裝檔，依畫面將應用程式安裝到指定位置，再從「應用程式」開啟 ChatGPT。若系統顯示不相容，回下載頁核對目前系統需求；不要用停用系統保護來處理版本不支援。安裝後關閉安裝視窗，再確認啟動的是已安裝的程式。

Linux：桌面版目前是預覽版，官方列出 Ubuntu 24.04／26.04 LTS、Debian 13、Fedora 43／44，提供 x64 與 ARM64。先在終端機確認系統與處理器，再從[Linux 官方安裝頁](https://learn.chatgpt.com/docs/linux/linux-app)下載對應套件。其他發行版不在這次正式支援清單中，不要把套件裝得進去當成全部功能受支援。

```bash Linux 終端機；確認發行版與架構
cat /etc/os-release
uname -m
```

Ubuntu／Debian 選 .deb，Fedora 選 .rpm。x86_64 代表 x64；aarch64 或 arm64 選 ARM64。在放有下載檔案的資料夾開啟終端機，只執行下表符合自己系統的一行。檔案被瀏覽器加上編號時，先核對實際檔名。

| 系統 | 架構 | 安裝命令 |
| --- | --- | --- |
| Ubuntu / Debian | x64 | sudo apt install ./chatgpt_amd64.deb |
| Ubuntu / Debian | ARM64 | sudo apt install ./chatgpt_arm64.deb |
| Fedora | x64 | sudo dnf install ./chatgpt.x86_64.rpm |
| Fedora | ARM64 | sudo dnf install ./chatgpt.aarch64.rpm |

Linux 安裝後從應用程式選單開啟 ChatGPT，或在終端機執行 chatgpt。後續更新使用發行版套件管理器。預覽版尚未支援 Computer Use，原生 Wayland 仍有實驗性限制；這不妨礙你先練习檔案修改與手動瀏覽器驗收，也不要用 macOS 截圖代表 Linux 實際畫面。

## 第二步：登入並選擇練習位置

三種系統都先在應用程式完成登入，確認帳號與工作區，選擇 Codex，再以開啟資料夾或建立專案的入口選 codex-practice。應直接看到 index.html 等檔案，而不是壓縮包或上一層資料夾。若畫面要求選本機或其他工作環境，這一篇選自己的練習副本所在位置。

建立 New chat 後先做唯讀確認。把下列文字貼在 Codex 任務輸入框，不是 PowerShell 或 Terminal。這一步能提早發現選錯專案、檔案沒解壓縮，以及任務開在另一台主機等問題。

```text Codex 桌面版，新任務輸入框；先確認工作位置
Before editing, report the current working folder and list the exercise files.
Read index.html and explain how the page loads its JavaScript.
Do not change files. Tell me if the expected five files are missing.
```

預期指出實際資料夾，並找到 app.js 及 core.mjs 的關係。與你的檔案總管比對路徑，不要只看到「我已了解專案」就跳過。若應用程式開了工作樹副本，請先核對副本位置；詳見[Worktree](article:codex-worktrees)。本例不需要 Git 倉庫也能開始。

## 第三步：交付一個可驗收的小修改

```text 同一個 Codex 桌面任務；完整需求
Update this Small Steps practice website.
Change the main heading to "Small steps, clear progress."
Use a dark blue heading color with readable contrast on the existing background.
Keep the form labels, task data format, storage key and behavior unchanged.
Do not add dependencies or external services.
Show the changed files, explain the diff and report checks actually performed.
```

等待任務提供成果後，從檔案或變更檢視開啟 index.html、style.css。檢查標題字串與顏色設定是否對應需求，是否意外修改儲存格式或刪除標籤。檔案差異中的新增與刪除只是比較結果，不表示網站已發布。第一次不用同時要求登入、雲端部署與資料庫；先完成一個可以自己驗收的小範圍。

## 第四步：在瀏覽器確認結果

在練習資料夾開終端機，Windows 使用下列命令。服務會持續占用這個終端機，這是正常狀態；另開瀏覽器，不要因為沒有回到提示符號就再次啟動。

```powershell Windows PowerShell；codex-practice 資料夾
py -m http.server 4173 --bind 127.0.0.1
```

```bash macOS / Linux 終端機；codex-practice 資料夾
python3 -m http.server 4173 --bind 127.0.0.1
```

開啟 http://127.0.0.1:4173。先看標題，再新增 Read 與 Build，完成 Read，切換 Active tasks 應只剩 Build，Completed tasks 應只剩 Read。重新整理後資料應保留。輸入只有空白的任務不得新增；這是與正常流程一起檢查的邊界案例。

用瀏覽器開發工具的響應式模式檢查 390 與 1280 像素，或縮小視窗檢查窄版；文字、按鈕與表單不應左右溢出。按 Tab 時要看得到焦點。再於另一個同目錄終端機執行 node --test core.test.mjs，參考版應為 3 個測試通過。若 Codex 沒有瀏覽器工具，就由你執行畫面驗收，並保留「未由代理實測」的紀錄。

## 常見問題、停止與還原

應用程式中沒有 Codex：先核對是否已更新、登入正確帳號與工作區，再查帳號可用功能。不要反覆重裝來處理額度或工作區管理限制。CLI 是另一個入口，安裝桌面版不代表終端機一定能找到 codex 命令。

開到錯誤資料夾：比較任務回報的絕對路徑與五個檔案。如果是解壓縮前的 ZIP、空目錄或另一個專案，停止修改，重新選擇。已發生的修改要在原位置核對，不要假設切換專案會搬移檔案。

網頁空白或 JavaScript 沒執行：確認網址是 http://127.0.0.1:4173，而不是雙擊檔案的 file URL。再檢查伺服器終端機與瀏覽器 Console。若連接埠已占用，停止自己先前啟動的服務或選另一個連接埠；不同連接埠的瀏覽器儲存空間不同。

停止預覽使用 Ctrl+C。還原時參照差異，只恢復標題與本次樣式；保留其他既有修改。練習網站的 Reset practice data 只用來清除本例專用資料，與還原程式不同。任務完成、測試通過和網站正式上線是三個不同狀態。

## 小練習與查證紀錄

把需求改成「手機上表單按鈕維持整行，桌面維持與輸入框並排」，要求 Codex 先說明目前樣式，再做必要修改。以兩個寬度及原有資料操作完成驗收；如果既有樣式已符合，就接受無須修改的結果，避免為了產生差異而改程式。
