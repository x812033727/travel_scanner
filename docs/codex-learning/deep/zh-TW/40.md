## 目標：知道手機連到哪個工作環境

> 從 Mac 或 Windows 主機開始設定 Remote，讓自己的 iPhone 或 Android 連入，再用主機、目錄、標記三項資料驗證。閱讀約 12 分鐘，首次操作約 25 分鐘，更新與帳號驗證另計。產品入口依 2026-09-14 官方文件查證；沒有實體手機配對、主機睡眠或遠端連線實測紀錄。

Remote 讓手機傳送需求、核准與追問；實際檔案、工具與登入服務來自主機。它不會把手機變成可執行桌面工具的電腦，也不代表專案已上傳到 Codex 雲端。先看[手機總覽](article:codex-mobile-guide)；iOS 和 Android 是替代入口，不必先擁有兩種手機。本篇主線只連一臺已使用中的電腦，不需要新租伺服器。

本篇流程圖的 1 代表確認主機與工作目錄，2 代表送出一次新的唯讀要求，3 代表用檔案內容核對結果。三個步驟依序完成；看到主機出現在清單，只完成第 1 步的一部分，還不能證明第 2、3 步成功。

## 開始之前：兩端條件與工作位置

電腦需有目前支援的 ChatGPT 桌面版、登入可使用 Codex 的同一帳號與工作區，並開著應用程式、連線且未睡眠。手機更新官方 ChatGPT 應用程式。若組織要求 SSO、多因素驗證或通行金鑰，先完成該流程；管理員也可能須啟用 Remote Control。功能依分階段提供，沒有 Remote 選項時先查版本、工作區與資格。

官方列出的手機 Remote 主機是 macOS 與 Windows；不能因 Linux 桌面預覽版存在，就推定它也支援同一配對流程。首次手機配對從桌面應用程式開始，CLI 或 IDE 的登入不能代替。主機上的 Git、Node.js、瀏覽器、Skills 和 MCP 可用性也不會由手機補齊；後續任務需要哪個工具，就在真正執行的主機檢查。

## 步驟一：在主機準備可辨認的專案

在主機建立新資料夾 codex-remote-lab，用純文字編輯器存兩個檔案。host-marker.txt 使用下面第一個區塊，request.txt 使用第二個。REMOTE-LAB-A 是本篇虛構練習標記，不是主機的真實名稱；你仍要另記錄桌面版顯示的裝置名稱與實際專案路徑。若資料夾已存在，就換新名稱，不覆寫舊資料。

```text
REMOTE-LAB-A
Revision: 1
```

```text
Read the host marker and report it. Keep both files unchanged.
```

在桌面版將這個資料夾加入專案，建立唯讀練習任務，要求列出路徑與兩個檔案，確認電腦端本來就能存取。Windows 可在練習資料夾用 Get-Location、Get-Content 核對；macOS 用 pwd、cat。先有本機成功基準，再做遠端；否則手機看到的失敗可能原本就是檔案不存在，而不是連線問題。

## 步驟二：在主機啟用並配對手機

在要接收工作的那臺電腦開 Settings → Connections → Control this Mac or PC，選 Set up 或 Add，依畫面啟用遠端與完成驗證。不要在另一臺同帳號的空白電腦設定後，期待自動找到這臺主機的資料夾。畫面提供的 QR code 用於配對裝置與主機，不應放進公開教學或傳給別人掃描。

用自己的 iPhone 或 Android 掃碼，確認開啟官方 ChatGPT，進入 Remote 設定。核對相同帳號與工作區並完成驗證；成功後應在手機 Remote 清單看到這臺主機。每臺手機與每臺主機需各自配對，只有「兩邊都登入同帳號」還不是配對證據。若連結只停在瀏覽器，先更新並確認應用程式入口。

回主機 Connections 檢查允許連接與保持喚醒的設定。Mac 筆電先接電、上蓋開啟；選擇 Sleep 仍會停止遠端可用性。Windows 若任務要用 Computer Use，需保持使用者工作階段解鎖且可供操作；本篇只讀檔，不需要為此開啟所有瀏覽器或桌面控制能力。其他人在用主機時，先安排好工作時段。

## 步驟三：用三項證據核對遠端結果

在手機 Remote 選這臺主機、codex-remote-lab 專案與剛才的任務，送出下列內容。不要在手機開一個沒有主機關聯的一般聊天後，就假定它能讀到電腦。若建立新任務，要再次確認執行位置；任務名稱相同不代表環境相同。

```text
In this host project, read host-marker.txt and request.txt without changing files. Report the host/environment name if available, the actual working directory, and both files' exact contents. Do not infer unavailable information or use other services. If either file is missing, stop and report that.
```

合格結果包含實際目錄、REMOTE-LAB-A 與 Revision: 1、request.txt 原文；主機名稱若工具沒有提供，應明說無法取得，不能把標記當真實裝置名稱。回電腦獨立開兩個檔案比對，確認工具記錄確實讀取這個專案，檔案未被改動。三個確認點是主機選擇、工作路徑和檔案內容，少一項就保留未確認狀態。

再做一次新鮮度測試：等任務完成後，在電腦用編輯器只把標記檔第二行改為 Revision: 2 並存檔，從手機要求重新讀取，不要只摘要上次回覆。預期看到 Revision: 2；若仍回覆 1，先查是否讀了舊訊息、未存檔或另一份資料夾。完成後在主機改回 1，重新讀取確認，讓練習可以重做。

## 連線中斷與停止遠端存取

完成目前工作再做連線測試：在主機的 Connections 暫時關閉允許其他裝置連接的開關，回手機檢查能否再存取主機，再由主機重新啟用並核對連線。這個開關可能影響所有已配對裝置，先確認沒有其他人在進行遠端工作。暫時停用連線不應當成已刪除配對或已取消正在執行的任務；這些狀態要分別查看。

官方文件明確說明：登出會關閉 Remote Control，但不移除既有配對；重新登入後可能需要再啟用。因此不要把登出當作永久撤銷裝置。要管理個別配對，回主機 Settings → Connections 檢查當版裝置清單及可用管理動作，操作後從原裝置驗證已失去控制能力。文件未固定列出所有版本的移除按鈕名稱，本篇不虛構一個通用選單。

| 現象 | 先確認 | 成功證據 |
| --- | --- | --- |
| 手機沒有 Remote | App 更新、帳號工作區與提供範圍 | 入口實際出現 |
| 有入口卻沒有主機 | 配對、主機 App、連線許可 | 清單出現正確主機 |
| 主機可見但讀錯檔 | 任務位置、檔案版本與工具記錄 | 路徑及 Revision: 2 對上 |
| 中途離線 | 睡眠、網路、App 是否關閉 | 恢復後能重新讀取目前檔案 |

## 完成條件與延伸閱讀

成功不是看到一次通知，而是能指出正確主機、重讀正確路徑的檔案、辨識更新後標記，並知道如何停止遠端存取。只收到摘要或通知時仍回任務查看工具與結果。後續看[iPhone](article:codex-mobile-ios)、[Android](article:codex-mobile-android)操作分篇，以及[跨裝置交接](article:codex-cross-device-workflow)。若需要電腦關閉後仍由獨立環境工作，再理解[雲端任務](article:codex-cloud-tasks-github)的另一套環境與成果流程。
