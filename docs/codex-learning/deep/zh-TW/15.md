## 目標與開始之前

> 在獨立 GitHub 練習儲存庫修好 Completed 篩選，取得測試與 diff，最後準備一份可審查的 PR。閱讀約 15 分鐘，操作約 35 分鐘，另加帳號設定與排隊時間。Windows、macOS、Linux 都從瀏覽器操作；需要具 Codex 資格的 ChatGPT 帳號、可建立儲存庫的 GitHub 帳號，以及 Small Steps 練習包。

Codex 雲端在它的環境執行工作；[手機 Remote](article:codex-mobile-guide)則控制已連接主機。電腦上的未提交修改、登入網站與 node_modules 不會因為選了同名專案就出現在雲端。這次用明確的 GitHub 分支和檔案清單當起點，讓每個結果都能追到同一份材料。

## 步驟一：準備雲端真正讀得到的材料

下載並解壓[Small Steps 練習包](https://mokaair.com/guides/codex-first-project/todo-practice.zip)。這次取 broken 裡的 index.html、style.css、app.js、core.mjs、core.test.mjs 五個檔案；expected 是答案參考，保留在電腦，不要混進起始儲存庫。broken 刻意讓 Completed 回傳未完成項目，所以起始測試有一項失敗，這是要修的題目。

在 GitHub 的 New repository 選自己的帳號，命名 codex-cloud-lab，選 Private，初始化 README 後建立。進入該儲存庫的 Add file → Upload files，上傳五個檔案到根目錄，寫明「Add broken Small Steps exercise」並提交到這個全新練習庫的起始分支。若帳號規則要求分支與 PR，依規則合併教材後再往下；不要更改正式儲存庫保護規則。

在檔案清單確認不是 broken/core.mjs 多包一層，也不是五個空白檔。打開 core.mjs 找 visibleTasks，核對 completed 分支有反向篩選，再記下畫面上的分支名稱與最新 commit。不要直接假設預設分支叫 main；後面選的分支必須包含剛上傳的教材。這個步驟比只確認 GitHub 登入成功更接近真正可執行的起點。

## 步驟二：連接帳號並建立環境

開啟[Codex 雲端](https://chatgpt.com/codex)，確認 ChatGPT 帳號與工作區，依 Connect GitHub 流程選擇可存取的儲存庫。首次練習只選 codex-cloud-lab；若是組織帳號需要管理員核准，先完成核準再確認清單出現。GitHub 的登入身分與 ChatGPT 身分不同，登入其中一個不代表另一個連線已授權。

到[環境設定](https://chatgpt.com/codex/settings/environments)建立練習庫環境，確認儲存庫名稱。本例沒有外部套件、API 或金鑰，只需支援 node:test 的 Node.js。使用環境的套件版本選項選擇可用的 Node.js 22 或更新相容版本，並在 setup script 只放下面的版本檢查。不要把故意失敗的測試放進 setup，否則任務可能在代理開始前就中止。

```sh
node --version
```

本例的 agent internet access 保持 Off 即可，因為需要的檔案已在儲存庫。環境安裝階段與代理工作階段的網路設定要分開看，能安裝不表示代理可任意連網。若另做有套件的專案，依 lockfile 設定安裝命令並讀取失敗紀錄；不要為了這個零依賴練習增加套件或把私人 token 寫進 README。

## 步驟三：確認版本後修正

回雲端任務頁，選練習環境及包含教材的分支，先送出下列唯讀要求。預期列出五個程式檔、目前目錄、commit 與一項失敗測試。如果顯示已全部通過，先查是否上傳 expected 或選到修好後的分支；不要為了符合文章而任意破壞已正確的程式。若根目錄沒有檔案，先修正環境或上傳位置。

```text
Inspect this Small Steps practice repository without changing files. Report the working directory, git commit, branch if available, and the five source filenames. Run node --test core.test.mjs. Explain the failing behavior from the test and core.mjs. Keep files unchanged and do not open a pull request yet.
```

核對回覆與工作紀錄後，在同一任務送出修正要求。這次限定 core.mjs 的 completed 篩選，保留既有測試與其他功能；不要用刪除失敗測試、放寬斷言或改 expected 值來換取通過。若它提出更大重構，請先說明為什麼單一條件修正不足，再決定是否擴大範圍。

```text
Fix only the reversed completed filter in core.mjs. Completed must return only finished tasks, Active only unfinished tasks, and All every task. Preserve order, input immutability and all existing tests. Remove any now-obsolete exercise comment. Run node --test core.test.mjs and show the final diff. Do not merge, deploy or open a PR until I review the result.
```

## 步驟四：驗收，再準備 PR

| 情境 | 輸入狀態 | 預期顯示 |
| --- | --- | --- |
| Completed | Read 完成、Build 未完成 | 只有 Read |
| Active | 相同兩筆資料 | 只有 Build |
| All | 相同兩筆資料 | Read、Build，原順序 |
| 空清單 | 沒有任何項目 | 三種篩選都是空清單 |

合格結果應為三項測試通過，core.mjs 的 completed 分支改為保留 completed 為真的項目，並移除過期的故障註解。Active 與 All 不變；core.test.mjs 不應被修改。檢查的是最終 diff 與最後一次測試，不是較早那段「我已完成」摘要。若回覆省略退出狀態或只說應該通過，要求補實際輸出。

準備好時使用任務的建立 PR 入口，確認目的儲存庫、base 分支與包含修正的 head，再填下面的標題和說明。PR 是提交審查，不代表已合併或網站已上線；若 GitHub 顯示衝突、檢查尚未完成或新增了其他修改，先處理再決定合併。本篇練習可以停在未合併 PR，保留成果供下一篇[測試與審查](article:codex-testing-review)使用。

```markdown
Title: Fix Completed filtering in Small Steps

Completed previously displayed unfinished tasks. It now displays only finished tasks while preserving Active, All, order and input data.

Validation: node --test core.test.mjs — 3 passed.
Browser verification: not run in this cloud exercise.
Deployment: not performed.
```

說明中的三項通過只能在你的實際結果一致時保留；若還沒測，改為未執行並說原因。需要畫面驗收時，把 PR 的確切分支或 commit 取得到另一個獨立資料夾，再按[第一個專案](article:codex-first-project)啟動預覽：加入 Read、Build，只完成 Read，Completed 只看見 Read，Active 只看見 Build。不要用電腦舊資料夾的正常畫面替雲端新修改背書。

## 常見問題、停止與下一步

看不到儲存庫時，先核對 GitHub 擁有者、連接授權範圍與組織核准；環境初始化失敗時，讀 setup 的第一個錯誤並確認 Node 版本；測試找不到檔案時，核對選定分支和根目錄；雲端結果與本機不同時，比對 commit、檔案與最後測試，而不是反覆送相同提示詞。這四種現象分別對應存取、工具、材料位置與版本問題。

要停止時，在目前任務使用可用的停止控制並確認狀態已停止，再檢查已留下的差異；停止不會撤銷先前提交的 PR 或 GitHub 變更。未合併 PR 可在核對後關閉，已合併修改要走指定提交的還原流程，不能用刪除聊天取代。本文環境與 UI 步驟依官方文件查證；故障及參考測試在本機驗證，沒有聲稱已替讀者建立雲端任務、GitHub PR 或部署。
