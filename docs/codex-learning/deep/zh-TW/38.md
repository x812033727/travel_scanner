## 目標與 iPhone 的角色

> 用 iPhone 的 ChatGPT Remote 進入主機上的 Codex 任務，送出一個可核對的讀檔要求、追問進度、離開後找回同一任務，再回電腦驗收。閱讀約 12 分鐘，操作約 25 分鐘，配對等待另計。本篇於 2026-09-14 依 OpenAI Remote 與 Apple 掃碼文件查證；未在實體 iPhone 實測，不將網站窄版截圖當成 iOS 產品畫面。

iPhone 負責傳送需求與查看結果，程式檔、終端機、依賴與網站登入都由連接主機提供。手機裝了 ChatGPT，不等於手機已安裝 Codex CLI，也不會把電腦資料夾自動同步到「檔案」App。先了解[手機總覽](article:codex-mobile-guide)與[Remote 主機設定](article:codex-remote-setup)，就能分開辨認連線、任務與實際工作。

## 開始之前：電腦與帳號先準備好

在自己的 Mac 或 Windows 電腦安裝或更新 ChatGPT 桌面版，登入與 iPhone 相同的帳號及工作區，確認能使用 Codex。將[Small Steps 練習包](https://mokaair.com/guides/codex-first-project/todo-practice.zip)解壓，以 expected 副本建立 codex-iphone-lab 專案。保留原 expected，並先在主機確認五個程式檔存在；不要用私人正式專案做首次配對測試。

在 App Store 核對發行者 OpenAI，安裝或更新官方 ChatGPT。完成 SSO、多因素驗證或通行金鑰等畫面要求，再回來設定 Remote。組織帳號可能需要管理員啟用 Remote Control；功能也可能依帳號逐步提供。沒有 Remote 時先記錄版本與工作區，不要以更換 Safari 或重裝 CLI 作為已取得入口的證據。

## 步驟一：從相機掃碼進入 Remote

在主機桌面版開 Settings → Connections → Control this Mac or PC，選 Set up 或 Add，完成要求的驗證並顯示配對 QR code。iPhone 開「相機」的拍照模式，讓完整 QR code 進入畫面，點偵測到的連結；也可使用控制中心的掃描碼工具。這不是把 QR code 拍照後上傳給聊天機器人，掃出的連結應帶你到官方 ChatGPT 設定。

若掃不到，先調整距離讓整個碼可見、減少螢幕反光，確認用的是拍照或掃碼模式。若連結只開 Safari，確認官方 App 已裝好、登入正確，再從主機重啟設定流程。不要把配對網址貼到公開討論區排錯；QR code、驗證碼與帳號資料都不應出現在公開教學圖。

在手機設定流程確認帳號、工作區與主機，成功後 Remote 中應出現該主機。只看到登入完成頁還不夠；要能選主機，找到 codex-iphone-lab 專案並開啟 Codex 任務。如果列表是另一臺電腦，回主機設定核對配對對象。圖的 1 是 iPhone 入口，2 是選中的主機，3 是可核對的專案結果。

## 步驟二：送出第一個明確讀檔要求

在手機 Remote 的專案任務輸入框貼上下面內容。先檢查檔名與函式名稱沒有被鍵盤自動修正；這是自然語言提示詞，不是要 iPhone 執行終端機命令。送出一次後留在該任務觀察回覆，記下任務標題或可以再次辨認的資訊，避免切換 App 後找不到原工作。

```text
Read this Small Steps project without changing files. Confirm the working directory and inspect app.js and core.mjs. Identify the localStorage key, the field that records completion, and the function that rejects blank task titles. Cite the file for each answer. If a file is unavailable, report that instead of guessing.
```

預期回覆會從 app.js 找到 mokaair-codex-todo-v1，從 core.mjs 指出 completed 欄位及 addTask 的空白檢查，也應提供實際工作目錄。若只有一般待辦程式知識，追問它實際讀了哪個檔案；若目錄不符，先停止本次要求、回正確主機和專案。不要把一段聽起來合理的說明當成成功連線的證據。

## 步驟三：追問、核准與查看進度

```text
In the same project, explain what happens when I add Read and Build, complete Read, and choose Completed. Then explain an empty task title. Separate code you inspected, tests actually run, and checks still pending. Do not edit or clear stored data.
```

這次追問檢查同一任務的上下文，回覆應預期 Completed 只顯示 Read，空白標題被拒絕；它也應分開列出已讀程式、真的跑過的測試與尚未操作的畫面。只分析原始碼就標成「預期行為」，不能改稱已在手機完成測試。你可在電腦的本機預覽親自做上述步驟，補上驗證。

若手機出現批准要求，先看操作內容、目錄與影響範圍，再決定是否符合你剛才的要求。本例只讀檔，無須為了前進而準許新增外部帳號、發布網站或刪除資料。若看不清楚長命令，回主機檢視完整內容再處理。批准視窗沒有出現時先回 Remote 原任務確認狀態，不用連續新建任務催它。

## 步驟四：離開後回到同一任務

等唯讀回覆完成後，暫時切到另一個 iPhone App，再回 ChatGPT → Remote，選相同主機與任務。核對最後一筆回覆及目前狀態，送出「請重新讀取目前目錄」的短追問，確認不是只在看先前快取文字。手機畫面仍保留舊回覆，不能證明主機此刻在線；只有新的讀取結果才能確認當下可工作。

通知用來提醒完成或需要注意，不代替成果驗收。若未收到通知，可主動回任務查看；若主機睡眠、斷網或關閉 App，先恢復主機，再核對上次要求是否已完成。尤其有寫入的後續任務，不要因手機暫時斷線就重送同一個建立或提交要求。這次以唯讀練習學會恢復工作流程。

## 完成檢查與常見誤會

| 核對項目 | 成功證據 | 不足的證據 |
| --- | --- | --- |
| 配對 | Remote 可選正確主機 | 只有相同帳號登入 |
| 讀檔 | 正確目錄、儲存鍵與函式來源 | 泛泛解釋待辦程式 |
| 接續 | 同任務的新讀取成功 | 只看到舊通知或回覆 |
| 驗收 | 電腦端核對檔案與操作 | 模型只說測試沒問題 |

主機的 localhost 網址在 iPhone Safari 會指向手機自己，不是那臺電腦。查看練習成果時，先從 Remote 任務看主機提供的截圖或結果，再回電腦開本機預覽；公開預覽與部署是另一個步驟。要停止手機存取，依[主機設定篇](article:codex-remote-setup)管理連線，並分開確認任務是否停止；登出不會自動刪除既有配對。

最後請 Codex 整理主機／目錄、已檢查內容、未跑測試與下一步，再回電腦逐項對照；不包含帳號或驗證碼。這份交接紀錄讓你下次用手機查進度時，能知道哪些真的完成。接著看[跨裝置工作](article:codex-cross-device-workflow)與[上下文交接](article:codex-context-handoff)；若另有 Android 手機，可用[Android 專篇](article:codex-mobile-android)完成同等驗收。
