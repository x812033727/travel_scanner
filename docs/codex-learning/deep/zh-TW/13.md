## 目標與準備

> 在一個本機專案管理兩個不同成果的任務，練習命名、切換、釘選、封存及恢復，並證明任務列表不等於檔案隔離。閱讀約 12 分鐘，操作約 20 分鐘。使用已登入的桌面版與文字編輯器；三種桌面平台使用相同練習，介面依官方文件查證，沒有冒充各 OS 的實機操作。

先完成[桌面版入門](article:codex-desktop-getting-started)。專案組織共同檔案與多個任務；任務保存自己要完成的成果及對話。這次用「清點教材」與「提出修改方案」兩個名字，避免每個都叫「繼續」。ChatGPT 專案與連接電腦資料夾的本機專案不同；要讀本機檔案，先確認所選的是連接到練習資料夾的專案。

## 步驟 1：加入練習資料夾

用文字編輯器建立 codex-project-lab，放入 note.txt 與 request.txt，分別貼上以下兩段。依桌面入門步驟加入本機專案，再打開專案選單的 Edit project 核對資料夾。這次只連接這一個資料夾，不把整個使用者目錄加入；將其設為主要資料夾後，建立任務前再次看實際路徑。

```text 檔案：note.txt
PROJECT-LAB
Revision: 1
Current title: Small Steps
```

```text 檔案：request.txt
Propose the title Daily Steps.
Do not edit note.txt until the proposal is reviewed.
```

主要資料夾決定新任務起點及一些專案設定的自動探索；其他附加資料夾也可能可讀寫，但不是隔離副本。此練習沒有 Git，也不建立 worktree，方便你清楚看到兩個任務共用同一份檔案。實際程式專案要並行修改時，另依[worktree 教學](article:codex-worktrees)建立隔離，不靠任務數量判斷是否安全。

## 步驟 2：建立兩個成果不同的任務

從這個專案開第一個新任務，送出下面的清點要求。回覆後看它是否真的指出兩個檔案、PROJECT-LAB 與 Revision: 1，再將任務改名為「PROJECT-LAB — 清點教材」。利用任務選單的重新命名功能，保留共同標記與成果詞，之後只記得 PROJECT-LAB 也能搜尋。此任務只讀，不需要新增文件。

```text Codex 提示詞：清點教材
Inventory this practice folder. Read note.txt and request.txt. Report their filenames, the lab marker, revision and current title. Do not edit files or search other directories. This task's outcome is a verified inventory only.
```

再從同一專案建立第二個新任務，使用下面的方案要求，改名為「PROJECT-LAB — 標題方案」。預期指出 Small Steps 改成 Daily Steps，只需 note.txt 的標題行；文件已要求先審閱，所以還不應改檔。切回第一個任務時，應仍看到它自己的清點對話，而不是兩段訊息混成同一份聊天。

```text Codex 提示詞：提出方案
Read note.txt and request.txt. Propose the smallest title change that satisfies the request. Identify exactly which line would change and how to verify it. Do not implement yet; this task's outcome is a reviewable proposal.
```

## 步驟 3：切換任務時重新讀檔

現在模擬你在任務之間處理了其他事：用編輯器只把 note.txt 的 Revision 改成 2，標題仍是 Small Steps，request.txt 也不動。回到「清點教材」任務，送出下列要求。它的舊對話是 1，但新讀取應是 2。接著到「標題方案」也要求重讀版本；兩個任務都應從同一資料夾看見 2。

```text Codex 提示詞：重新讀檔
Read note.txt from disk again now. Compare its current revision with this task's earlier record. Report the actual directory, current revision and unchanged title. Do not repair the mismatch by restoring old contents.
```

這個差異是刻意設計的驗收，不是叫模型把數字改回去。同一專案的兩個任務可以共用檔案，卻各有歷史對話；釘選、改名與切換都不會建立第二份磁碟。若其中一個仍是 1，先核對路徑、主機與是否真的重新讀取，再看它是否在另一個工作樹。接續長任務時用[交接文件](article:codex-context-handoff)保存這種版本差異。

## 步驟 4：釘選、尋找與封存恢復

把目前常用的「標題方案」任務釘選，確認它在側欄容易找；再開其他任務後回來核對，它的對話及檔案內容都不應因釘選改變。要找清點任務時，使用側欄 Search chats 搜尋 PROJECT-LAB，再用完整標題分辨。不同版本的搜尋快捷鍵可能不同，本篇直接使用可見入口。

完成清點後，從該任務選單選 Archive，只封存「清點教材」，不要誤選整個專案的 Archive chats。接著到 Settings 的 Archived chats 找回它並恢復，再確認原對話存在、note.txt 仍是 2。封存用來整理列表，不表示已完成程式驗收，也不是檔案備份或清理硬碟的方法。本練習不需要 Delete。

## 延伸練習：同名任務放在不同專案

在 codex-project-lab 旁建立獨立資料夾 codex-project-other，只放下面的 note.txt。將它加入另一個本機專案，不是第一個專案的附加資料夾。在新專案開第三個任務，也命名「PROJECT-LAB — 清點教材」，送出後面的唯讀要求。相同標題不能證明兩個任務使用同一份檔案。

```text 檔案：codex-project-other/note.txt
PROJECT-OTHER
Revision: 100
Current title: Other Steps
```

```text Codex 提示詞：核對同名任務
Read only this project's note.txt from disk. Report the absolute path, marker, revision and current title. Do not infer content from this task's title, another task or another project. Do not edit or search outside this project.
```

第三個任務應讀到 PROJECT-OTHER／100／Other Steps，前兩個仍是 PROJECT-LAB／2／Small Steps。用紙或筆記記下三列「任務成果、所屬專案、絕對路徑、最新讀檔結果、進行／封存狀態」。若看到 2，就先查第三個任務是否建在錯誤專案，不修改任何檔案去配合預期。確認後把它改名為「PROJECT-OTHER — 清點教材」；只封存或恢復你指定的那一列。

> 本篇的封存與檔案保留實驗限定一般本機資料夾。[官方 worktree 文件](https://learn.chatgpt.com/docs/environments/git-worktrees)另說明：受 Codex 管理的 worktree 可能因封存或清理政策被移除，重新開啟時可出現快照恢復選項；永久 worktree 的規則不同。涉及 worktree 時，先核對類型、未提交內容及備份，再依[隔離工作教學](article:codex-worktrees)處理，不把此處的本機結果推廣到所有環境。

| 操作 | 會改變什麼 | 本練習如何驗證 |
| --- | --- | --- |
| 重新命名 | 任務顯示名稱 | 用標記及成果搜尋 |
| 釘選 | 側欄位置 | 回到同一段對話 |
| 封存／恢復 | 列表中的可見狀態 | 恢復後仍可讀原對話 |
| 重新讀檔 | 取得目前磁碟證據 | 兩任務都看到 Revision: 2 |
| 編輯主要資料夾 | 新任務預設起點 | 重新核對實際路徑 |

## 什麼時候續接、另開或停止

同一個標題修改還在補條件，就回到原方案任務續接，保留先前決策；要獨立做另一個成果，例如整理測試紀錄，就建立新任務並明確指出要讀哪些檔案。新任務不應被假設已經看過前一個聊天中的口頭限制。把「不可改測試」這類共同規則放入專案 AGENTS.md，把本次版本與尚未完成的檢查放交接文件，再在新要求引用。

工作仍在執行時，先用目前任務可見的停止控制中斷，確認不再產生新修改，再整理或封存；停止與封存是不同操作。如果已經寫入 note.txt，停止不會自動撤銷，因此要讀檔與檢查差異。要更換專案主要資料夾時，先記錄舊位置，再從新任務核對起點；不要推論現有任務已被搬過去，也不要把附加資料夾當作主資料夾的備份。

## 常見問題與整理習慣

找不到任務先確認是否在其他專案、另一台主機或已封存，再用標記搜尋；不要重新建立十個同名任務。發現兩個任務都想改同一檔案，就先讓其中一個停在唯讀檢查，明確指定由另一個完成修改，之後前者再審查結果。若需要真正同時改不同功能，進入 worktree 與整合教學。

專案變大時，任務名稱加入目標與範圍，例如「篩選器：完成 Completed」或「文件：補啟動步驟」。每個任務結束留下改了什麼、如何驗證、還剩什麼；未完成工作可以存在任務清單文件，不只留在一段很久以前的聊天。這樣下次切換不用重新解釋整個專案，也不會把封存當作沒有待辦。

驗收時保存兩個專案、三個任務的狀態表，前兩個任務的 Revision: 2 重新讀取、第三個的 Revision: 100，以及指定任務的封存恢復結果。最後只把 codex-project-lab/note.txt 的 Revision 手動還原為 1，確認標題仍是 Small Steps；另一個專案保持 100／Other Steps。取消本練習的釘選，不必刪專案或檔案。圖中 1 是建立專案範圍，2 是分成果管理任務，3 是重新核對與整理。下一篇開始[閱讀既有程式](article:codex-understand-codebase)。
