## 讀完能做到什麼

> 你會分清楚 Codex、模型、任務和工作環境，並用一個只有兩個檔案的小資料夾完成「先讀取、再修改、自己驗證」。閱讀約 10 分鐘，實作約 15 分鐘；不需要先學會寫程式，也不會在這一篇部署網站。

## 先理解四個角色

Codex 是能在取得相應工具與權限後讀檔、修改及執行命令的代理。模型負責推理；任務儲存這次需求與對話；工作環境決定實際能接觸哪些檔案和工具。換一個更強的模型，不會讓選錯資料夾的任務突然找到你的專案。後續每次求助，都先記下入口、工作目錄和可用工具。

「與 ChatGPT 有什麼不同」不能只用應用程式名稱判斷：官方桌面文件現在以 ChatGPT 桌面應用程式說明 Codex 工作。實際差別要看當前對話是否連到專案、是否能執行工具，以及成果是回答文字還是落在檔案中。一般聊天也可能有工具；Codex 也可能因環境限制只能分析。請看這一次任務的能力，不要只看圖示或舊截圖。

本機工作使用你選定電腦的資料夾；雲端工作使用另外設定的環境。兩者即使叫同一個專案，也不代表未提交檔案會自動同步。手機遙控則需要可連線的主機。想先比較操作習慣，可讀[平臺選擇](article:codex-platforms-guide)；本篇採用桌面版或 CLI 的本機資料夾，讓檔案結果最容易確認。

### 先判斷：這個需求需要什麼能力？

先不執行任務，判斷三個情境。① 你貼上十行文字，請它說明意思。② 你要求把電腦中的 packing.txt 改好，關閉對話後也能打開檔案看到結果。③ 你希望它在已設定的 GitHub 儲存庫環境中修改程式，供你稍後檢查差異。各情境需要的是讀取提供的文字、存取本機檔案，還是存取指定的遠端環境？

答案依序是：① 提供的文字已足夠，不必存取你的整個資料夾。② 必須選對本機資料夾，且工具確實有讀寫能力；回覆一段新文字不代表檔案已修改。③ 必須先設定並選對遠端儲存庫與環境；本機尚未提交的檔案不能當成它已讀到的內容。第二種可接著看[桌面入門](article:codex-desktop-getting-started)，第三種看[雲端任務](article:codex-cloud-tasks-github)。這是需求判讀練習，不要求你現在開通三種入口。

## 準備獨立練習資料夾

先確認已有可用的 Codex 登入。還沒安裝時，先完成[桌面版](article:codex-desktop-getting-started)或 [CLI 入門](article:codex-cli-getting-started)。這裡只需要純文字編輯器與終端機，不需要 GitHub、API 金鑰、Node.js 或 Python。先用檔案管理員在自己的檔案資料夾建立 codex-orientation；若同名資料夾已存在，改用另一個新名稱，避免覆蓋舊練習。

Windows 開啟檔案總管的副檔名顯示，以記事本儲存時選擇所有檔案與 UTF-8；macOS 使用純文字模式的編輯器，避免儲存成 RTF；Linux 使用純文字編輯器並保留檔名大小寫。在新資料夾建立下面兩個完整檔案。副檔名分別是 .md 與 .txt，不要把顯示在文章外面的檔名也複製進內容。

檔案一：codex-orientation/README.md。這是供人閱讀的專案說明，不會因為副檔名是 .md 就自動變成代理規則。

```markdown 檔案內容：貼入 README.md
# Orientation exercise

This folder contains a fictional packing list.
The list has exactly three items.
No website or package installation is required.
```

檔案二：codex-orientation/packing.txt。每個物品各占一行，最後一行後可以有換行。

```text 檔案內容：貼入 packing.txt
Notebook
Bottle
Umbrella
```

## 第一步：選對位置，先做唯讀任務

桌面版把 codex-orientation 加入專案後建立任務。CLI 則在這個資料夾開啟終端機，再執行 codex。若你只開啟電腦的檔案總資料夾，任務可能看見許多不相關檔案；先縮小到練習資料夾，再貼下方提示詞。英文範例在五語版保持相同，方便對照結果，也可以用自己的語言提出同樣要求。

```text 自然語言提示詞：貼入 Codex 任務輸入區
Inspect this practice folder without changing files.
Report the working directory, list the files, and read README.md and packing.txt.
Explain what this project contains. Cite the filenames supporting your answer.
If a requested file is missing, say so instead of guessing.
```

預期回答指出兩個檔案、三個物品，以及這裡沒有可執行網站。開啟檔案管理員比對路徑和內容；回答格式不用逐字一致，但不能增加原文沒有的資料。若它只提供「你可以執行某命令」，先確認目前入口是否真的有檔案工具，而不是把教你做事的回答誤認成已執行。

## 第二步：只修改一個可檢查的項目

```text 自然語言提示詞：貼入同一個 Codex 任務
In packing.txt, replace the line Umbrella with Raincoat.
Preserve the other two lines and leave README.md unchanged.
Do not add files, install tools, or run a website.
After editing, read packing.txt and report exactly what changed.
```

接受相關檔案修改要求後，重新開啟 packing.txt。預期三行依序是 Notebook、Bottle、Raincoat；README.md 完全相同，沒有新套件或多餘檔案。若工具要求超出這個資料夾的授權，先看原因並縮小任務。本例不需要全面存取電腦。關於權限的實際控制，另見[權限與沙盒](article:codex-permissions)。

## 第三步：驗證失敗情況與還原

接著要求「唯讀列出 missing.txt 內容；不存在就說明，不要建立」。正常結果是明確回報檔案不存在，而且資料夾仍只有原來兩個檔案。這個邊界案例測試它會不會在缺少資料時猜測；不需要真的刪除任何檔案製造錯誤。若它捏造內容，請它重新讀取目錄，指出缺乏證據的句子並修正回答。

還原時在編輯器把 Raincoat 改回 Umbrella，儲存並再讀一次。不必執行全專案重設，也不要刪除整個檔案資料夾。中斷尚在執行的任務只能停止後續工作，已經寫入的文字仍要自行核對及還原。關閉對話也不等於把檔案恢復原狀，這是進入 [Git 教學](article:codex-git-basics)之前就應建立的習慣。

## 常見問題與自主練習

看到的內容不同，先檢查是否選到另一個同名資料夾，以及編輯器是否尚未儲存；不要連續換模型重試。無法讀到 README.md，先顯示完整檔名，排除 README.md.txt、富文字格式及大小寫差異。只能看到舊對話時，重新確認任務對應的電腦和專案，而不是假定雲端會讀到剛建立的本機檔案。

自己再做一次：把 Bottle 換成 Cup，要求保留順序與行數，再恢復原文。完成判準是能解釋資料在哪裡、指出真正修改的檔案、驗證三行內容，以及說明哪些動作沒有執行。接著讀[第一個小專案](article:codex-first-project)與[需求描述](article:codex-prompting)，把同樣的查證方法用在可預覽的網站上。

入口與產品名稱依 2026-09-14 的[桌面官方文件](https://learn.chatgpt.com/docs/app)及 [CLI 官方文件](https://learn.chatgpt.com/docs/codex/cli)核對。這是原創文字檔練習；可用工具與實際回覆依讀者環境而異。跨平臺編輯步驟未冒充三個作業系統的實機 Codex 測試。

| 角色 | 這次代表什麼 |
| --- | --- |
| 代理 | 使用工具完成工作 |
| 模型 | 理解與推理 |
| 任務 | 這次需求和對話 |
| 環境 | 可用的檔案與工具 |

圖中 01 是任務需求，02 是執行環境，03 是可驗證的檔案成果；三者對上，才能確認這次工作做在哪裡。
