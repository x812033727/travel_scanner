## 目標與準備

> 寫出能讓下一個工作階段接手的 handoff.md，並用一次刻意過期的交接測試它是否可靠。閱讀約 12 分鐘，操作約 22 分鐘。需要桌面版或 CLI、文字編輯器、Node.js 22 以上相容版本，以及獨立的 Small Steps 教材副本。Windows、macOS、Linux 步驟相同；終端機位置確認方式依平台不同。

[工作階段續接](article:codex-sessions-resume)保留對話，但對話不一定包含磁碟最新內容。交接文件的工作是保存目標、已確認的事實、未解問題與下一步，讓新任務能重新驗證。它不是把所有聊天複製成長文，也不是加入一個檔案就自動被所有工作階段讀取；應在新任務明確要求讀取。

## 步驟 1：準備故障副本與狀態標記

取得[第一個小專案](article:codex-first-project)的練習 ZIP，把 broken 中五個檔案複製到新資料夾 codex-handoff-lab。這份故障與 start 不同：Completed 誤回傳未完成任務。用編輯器開根目錄並新增 LAB_STATE.txt，內容如下。PowerShell 用 Get-Location，macOS／Linux 用 pwd，確認操作位置後執行測試。

```text 檔案內容：存入 LAB_STATE.txt
Lab: codex-handoff-lab
Revision: BROKEN-1
```

```sh 系統終端機：先核對本篇指定的練習目錄
node --test core.test.mjs
```

預期是 2 過 1 敗，失敗在篩選行為。只有真的執行得到這個結果，才能在交接寫「已確認」。沒有 Node 或路徑錯誤，就寫阻礙與實際錯誤摘要，不填預設成功數字。不要保存帳號、金鑰或完整私密工具輸出；這個教材只需要虛構標記與相關測試資訊。

## 步驟 2：寫一份可查證的交接

在根目錄建立 handoff.md。下面是完成基準測試後可使用的完整範例；如果你的結果不同，先更正 Observed 欄位。目標說明要做到什麼，Scope 指出可以改哪裡，Observed 帶上版本與命令，Not checked 保留缺少的證據，Next 讓接手者知道第一步要確認什麼。

```markdown 交接範例：基準結果相符後才存入 handoff.md
# Small Steps handoff

## Goal
Completed shows only completed tasks. Keep ordering, storage and existing UI.

## Scope
Lab: codex-handoff-lab. Only core.mjs may need a program change.
Do not change tests or add dependencies. Preserve other work.

## Observed
LAB_STATE.txt: Revision: BROKEN-1.
Command: node --test core.test.mjs
Result: 2 passed, 1 failed in the filter case.
The completed branch of visibleTasks currently selects unfinished tasks.

## Not checked
Browser interaction: NOT RUN.
Publishing and deployment: NOT PERFORMED.

## Next
1. Re-read LAB_STATE.txt, core.mjs and the test file; do not trust this record over current files.
2. Re-run the baseline before deciding whether a fix is still needed.
3. If still faulty, change only the completed predicate, then test and review the diff.
4. Manually check Read completed / Build active under all three filters.

## Stop condition
If revision, test results or files differ, report the mismatch and revise this record before editing program code.
```

不要把「已做了一些修改」當成可驗證成果。寫出檔案、具體行為、執行過的命令與未執行的檢查，才方便下一個人重做。正式 Git 專案可加分支與 commit，但未提交的變更仍需看 diff；commit 相同不能證明工作樹相同。本練習不需要為了填欄位捏造 commit ID。

## 步驟 3：讓交接刻意過期，再交給新任務

現在做一次受控改動：只把 ZIP 裡 expected/core.mjs 複製到本練習的 core.mjs，將 LAB_STATE.txt 的 Revision 改成 FIXED-2，暫時不改 handoff.md。再跑測試應 3 項全過。這模擬你離開後另一位協作者已修好程式，但聊天與文件仍記著故障。整個網站仍是同一份教材，測試檔沒有變。

桌面版在同一練習專案新建任務，CLI 則先 /exit 回系統終端機，確認目錄後重新執行 codex，這次不用 resume。把下列要求送到新任務。預期它辨識 FIXED-2、舊交接 BROKEN-1 與 3 項通過之間的差異，提出只更新交接記錄，不再改已正確的篩選函式。

```text 自然語言提示詞：在本練習的 Codex 任務輸入
Continue this lab using handoff.md, but first verify it against current files. Read LAB_STATE.txt, core.mjs and core.test.mjs. Run node --test core.test.mjs. Do not edit anything yet.
Compare the recorded revision, predicate and test result with current evidence. Report mismatches and propose the smallest next step. Browser checks must remain NOT RUN unless actually performed.
```

若它仍想修正 Completed，要求指出目前哪一行錯、哪個測試還失敗；不要用舊紀錄覆蓋剛讀到的證據。確認後只允許更新 handoff.md：Observed 改為 FIXED-2 與真正 3 項通過，Next 改為未完成的畫面驗證。保留「原交接過期，已重新核對」的短記錄，讓版本差異有原因可追。

## 長對話、compact 與文件分工

CLI 的 /compact 可壓縮長對話保留重要內容；在互動輸入框使用，若介面要求確認就依提示操作，完成後請它重述目標、限制與未完成項目並和 handoff.md 對照。本練習不需要刻意灌滿對話。壓縮不能當作檔案備份、Git 還原或一定不漏細節的保證，重要決策應保存在可重新讀取的文件。

| 文件 | 保存什麼 | 何時更新 |
| --- | --- | --- |
| AGENTS.md | 長期規則與命令 | 團隊工作方式改變 |
| README.md | 專案入口與啟動方法 | 使用方式改變 |
| 設計文件 | 行為、取捨、限制 | 接受新的設計決策 |
| handoff.md | 當前證據、阻礙、下一步 | 暫停、交接或驗證後 |

### 壓縮之後做一次唯讀交接核對

```text 互動斜線指令：在 Codex CLI 內輸入
/compact
```

只在需要整理的原 CLI 任務使用上面指令，待壓縮結束後送出下面要求；不為了練習另外灌入大量對話。合格回覆應保留只改 core.mjs 的原範圍、測試不可變，以及畫面未驗收的狀態。若摘要遺漏限制，依磁碟文件補回；不要為了讓摘要看起來一致而把 FIXED-2 改成 BROKEN-1。

```text 自然語言提示詞：在本練習的 Codex 任務輸入
After compaction, read handoff.md and LAB_STATE.txt from disk. Restate the goal, allowed changes, preserved files, actual recorded checks and remaining work. Compare the summary with the files and identify conflicts or missing constraints. Do not edit files or rerun tests in this check. Label recorded evidence separately from checks performed in this turn.
```

這些角色可參考[規則與文件分工](article:codex-rules-and-context-files)。不要把一次故障的完整記錄長期塞進 AGENTS.md，讓每個任務都帶著過期資訊。交接最上方放眼前目標與最新核對日期，已解決項目用簡短結果保留，失效的路徑及臨時猜測要刪除或註明，避免接手者把歷史假設當現況。

## 常見問題、還原與驗收

新任務說找不到文件，先核對工作目錄與檔名，不立刻讓它搜尋整台電腦；它沒讀交接，就明確附上路徑並要求回報讀到的 Revision；命令在別的目錄成功，不能當作這份程式已通過。若測試失敗與交接不同，保留兩份結果與時間，重新讀相關檔案後再決定，不先改測試來配合舊記錄。

完成時應有舊紀錄與新磁碟不一致的說明、更新的 handoff.md，以及 core.mjs 未被重複修改的證據。想重做只還原 broken/core.mjs、將 LAB_STATE.txt 改回 BROKEN-1，再用上面的原始交接；其他檔案不動。圖中 1 是記錄事實，2 是接手時重驗，3 是更新下一步。本文的模型對話與 /compact 依文件說明，實際執行要由你的結果補上；參考程式的故障與修正另有本機測試。
