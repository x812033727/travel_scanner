## 讀完能做到什麼

> 完成一個可核對的 CLI 工作迴圈：準備檔案、確認安裝與登入、讀取正確目錄、修改指定一行、退出並找到原工作階段。閱讀約 12 分鐘，操作約 25 分鐘，下載與登入等待另計。本篇不需要 GitHub、Node.js 或付費外部工具。

CLI 是在終端機操作 Codex 的入口。終端機負責啟動程式，Codex 輸入框負責接收任務；兩者外觀都像文字介面，但輸入的意思不同。先看[終端機與路徑](article:codex-terminal-paths)，能找到目前資料夾後再開始。圖中 01 是啟動前檢查，02 是工作階段，03 是檔案驗收。

## 開始之前：只選一種安裝方式

先在自己的電腦建立一般使用者可寫入的練習資料夾，不要直接用正式專案。帳號是否能使用 Codex、使用哪一種登入，以及額度資訊，先查[帳號與用量](article:codex-account-usage)。可以啟動程式不代表帳號有可用額度；登入成功也不代表已取得目標資料夾權限。

| 環境 | 安裝入口 | 完成後回到本篇 |
| --- | --- | --- |
| Windows | PowerShell 的官方獨立安裝程式；已有 npm 也可選 npm | 在原生 PowerShell 檢查版本 |
| macOS | 官方獨立安裝程式；已用 Homebrew 可選 cask | 在 Terminal 檢查版本 |
| Linux／WSL2 | 在 Linux shell 使用官方獨立安裝程式 | 在同一個 Linux 環境檢查版本 |

逐步安裝分別見[Windows](article:codex-cli-windows)、[macOS](article:codex-cli-macos)、[Linux／WSL](article:codex-cli-linux-wsl)。三篇是替代路線，不必依序安裝三套系統。若上述文章尚未公開，可直接依本篇末的官方 CLI 安裝頁，選自己的平臺分頁；完成下載、重新開啟終端機，再做下面兩項檢查。不要為了比較方法把 npm、Homebrew 與獨立版全部裝一次。

```text 系統終端機：查版本與說明，尚未啟動任務
codex --version
codex --help
```

這兩行貼在系統終端機，預期顯示版本及使用說明後回到提示符號，尚未開始模型任務。找不到 codex 就停在安裝排錯，先不要登入。實際查得的版本可能比文章新；以本機 help 和官方文件核對旗標，不要求安裝本文驗證時的預覽版。

## 步驟一：建立能辨認的練習檔

在文字編輯器建立 greeting.txt，內容如下；再另存一份 greeting.original.txt。兩個檔案放進新資料夾 codex-cli-lab。確認副檔名沒有變成 .txt.txt，內容不是 Word 檔案。第二行是固定版本標記，用來分辨讀到的是否真是你的練習檔；備份則能核對修改前後。

```text 檔案內容：貼入 greeting.txt，另存原始副本
Hello, traveler.
Lesson marker: CLI-START-01
```

Windows 在檔案總管開啟這個資料夾，使用「在終端機中開啟」並選 PowerShell，執行 Get-Location 和 Get-ChildItem。macOS／Linux 在終端機輸入 cd 加上這個資料夾的完整路徑，再執行 pwd 和 ls；路徑有空格就加引號。清單必須包含剛才的兩個檔案。若還顯示家目錄或下載目錄，先定位，不能只因看見檔案名稱就猜已在對的地方。

## 步驟二：登入並啟動唯讀工作階段

```text 系統終端機：每行完成後才執行下一行
codex login
codex login status
codex --sandbox read-only
```

在系統終端機逐行執行，前一行完成才繼續。login 依畫面完成瀏覽器登入；選你預期的帳號及工作區。login status 用來確認已有憑證，不證明額度、網路或模型請求一定成功。第三行開啟互動介面並指定唯讀沙盒；若出現資料夾信任或沙盒設定，先核對路徑和畫面說明，再選符合本次練習的設定。

進入 Codex 輸入框後才執行下面的 /status。檢視目前目錄、模型及權限資訊，欄位依版本而異。不要把它貼回 PowerShell，也不要把「read-only」理解成完全沒有網路或所有外部工具都被禁用；它設定的是沙盒範圍，外部工具仍受各自授權控制。本練習只使用本機文字檔。

```text 互動斜線指令：在 Codex CLI 輸入區執行
/status
```

```text 自然語言提示詞：在唯讀 Codex 工作階段輸入
Read greeting.txt in the current folder. Report the working directory and both lines exactly. Do not edit files, use external services, or infer missing content. If the file is missing, stop and report that.
```

這一段是自然語言任務，貼在 Codex 對話。合格回覆必須對得上兩行原文與目前目錄；同時檢視讀檔工具記錄，確認有實際讀取，不只照抄提示詞。如果它說找不到檔案，先停止後續修改；若檔案存在但沙盒讀不到，記錄錯誤與範圍，接著查[權限教學](article:codex-permissions)。

## 步驟三：只修改指定的一行

在 Codex 輸入 /exit，看到系統終端機提示符號後，於同一個練習資料夾重新啟動下列寫入工作階段。這個練習刻意分開讀取和寫入，讓你看到授權範圍的差異；不必為了改一行開啟全磁碟存取。若組織政策不允許這個模式，保留唯讀練習結果並確認管理設定。

```text 系統終端機：退出 Codex 後啟動寫入工作階段
codex --sandbox workspace-write --ask-for-approval on-request
```

```text 自然語言提示詞：在寫入工作階段輸入
In greeting.txt, replace only the first line with: Hello, Codex learner.
Preserve the lesson marker and greeting.original.txt. Do not create other project files.
Read the file after editing and report the exact before/after change.
```

第一個區塊是啟動命令，第二個才是進入 Codex 後送出的要求。審核提出的命令與差異；如果改到備份或多出專案檔，先指出偏離範圍，要求修正後重新讀檔。合格結果是第一行變成 Hello, Codex learner.，第二行仍是原標記，備份完全不變。不要只以回覆中的「完成」作為驗收。

## 步驟四：退出、驗證與接續

修改完成後，先在目前的 Codex 工作階段做一次缺檔測試：要求讀取 greeting-missing.txt，並明說檔案不存在就回報、不要建立。預期是清楚指出缺檔，原檔和備份不受影響。這能分辨有查檔案與憑名稱猜測內容的回覆。接著輸入 /exit 回到系統終端機，再使用文字編輯器獨立開啟兩個檔案比對。

退出後在系統終端機執行 codex resume，從清單依時間、內容和目錄找回這次工作，不要假定最近一筆就是它。接續後要求摘要已做修改與剩餘工作，再讀 greeting.txt 核對實際狀態。接續儲存的對話不會把硬碟還原成當時版本；如果你在外部編輯過檔案，應以目前檔案為準。

```text 系統終端機：在練習目錄開啟接續選單
codex resume
```

接續後先做一個狀態判讀：對話若記著「已把第一行改好」，但你剛從備份還原 greeting.txt，Codex 應重新讀檔後說明目前是 Hello, traveler.。請明確要求「只讀取並比較，不要再次套用上次修改」。新任務、退出與接續是管理對話的動作；真正的恢復仍靠你核對與還原檔案。需要分岔或跨目錄查找時，再看[工作階段教學](article:codex-sessions-resume)。

要重做練習，退出後將 greeting.original.txt 的兩行內容複製回 greeting.txt，再核對兩份一致。只還原這個練習檔，不用刪除整個 Codex 設定或所有工作階段。更新 CLI 時也使用原本的安裝管道，重新開啟終端機核對版本；日後更換管道才另外檢查重複安裝。

## 常見問題與完成檢查

命令找不到：確認是在系統 shell、重新開啟視窗，依平臺篇查 PATH。登入頁完成但 CLI 等待：核對是否為同一筆登入、瀏覽器是否回到本機流程；不要在公開貼文貼登入網址或程式碼。狀態有登入卻無法送出任務：分開記錄額度、組織政策或網路錯誤，再查帳號篇。唯讀不能修改：先核對本次是否仍在 read-only 工作階段，不要反覆重灌 CLI。

完成時應保有：安裝版本、正確目錄與兩行讀取證據、只改第一行的檔案、未變的備份、缺檔回報、可接續的工作階段。接著閱讀[常用指令](article:codex-commands)及[AGENTS.md](article:codex-agents-md)，把專案規則補進後續練習。本文 Windows 本機只驗證版本與 help，以及練習檔比較方法；安裝、帳號與互動模型流程依官方查證，macOS／Linux 未宣稱已親自操作。
