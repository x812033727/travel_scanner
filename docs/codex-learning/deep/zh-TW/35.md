## 目標與適用環境

> 在 Windows 原生 PowerShell 安裝 Codex CLI、確認實際執行的程式、登入並讀取一個含空格路徑的練習檔。閱讀約 12 分鐘，操作約 25 分鐘，下載時間另計。以下安裝與沙盒步驟依 2026-09-14 官方檔案查證；本機驗證僅涵蓋版本、help 與檔案操作，沒有重灌使用者的 CLI 或變更電腦政策。

Windows 原生 CLI 不要求先裝 WSL。若開啟的是 Ubuntu、路徑以 /home 開頭，請改看[Linux／WSL](article:codex-cli-linux-wsl)；本篇在 PowerShell 進行。先完成[CLI 共用入門](article:codex-cli-getting-started)的環境判讀，安裝後再回去做單行修改練習。圖的 1 是安裝入口，2 是定位與登入，3 是獨立讀檔驗證。

## 步驟一：開對 PowerShell，選定安裝管道

按開始選單搜尋 PowerShell，或在 Windows Terminal 的分頁選單選 PowerShell。先用一般使用者視窗，不需要把所有日常工作都以系統管理員執行。在系統終端機輸入下面第一行；若能找到 codex，先記錄其版本與 Source，通常可直接跳到定位步驟，避免新增第二份安裝。

```powershell
Get-Command codex -All | Select-Object CommandType, Name, Source
codex --version
```

尚未安裝時，第一行可能回報找不到命令，這是合理起點。官方目前提供下列 Windows 獨立安裝命令；它會下載並執行安裝指令碼，應從官方頁面核對網址後才貼上。ByPass 是這次子程式的引數，不是要求你永久關閉電腦的執行政策；若公司管理政策阻擋，先記錄具體訊息並使用管理員核准的安裝方式。

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

等待安裝完成，保留最後顯示的安裝位置與 PATH 提示。關閉這個終端機，開一個新的 PowerShell，再跑 Get-Command codex -All 與 codex --version。預期至少有一個可執行來源及版本。不要把下載完成、資料夾存在或沒有跳出錯誤視為命令已能使用；新的 shell 必須真的找得到它。

### 已有 Node.js 時的 npm 替代路線

只有選擇 npm 管道時才執行下面三行；第一、二行都應顯示版本，否則先解決 Node.js 安裝，不要連續重試第三行。本例使用 npm.cmd 直接選 Windows 命令包裝檔，能避免把 npm.ps1 的執行政策問題誤認成 Codex 安裝失敗。npm 不是獨立安裝版的必要前置工具。

```powershell
node --version
npm.cmd --version
npm.cmd install -g @openai/codex
```

## 步驟二：建立有空格的路徑並確認內容

選一個不在正式專案內、可寫入的新練習目錄。下列命令建立 codex windows lab；如果已存在就停止並保留原內容，請換一個新的資料夾名稱。New-Item 和 Set-Content 只用於這次新資料夾。接著切進資料夾，列檔並讀取 note.txt；路徑加引號，LiteralPath 避免把路徑字元當成萬用字元。

```powershell
$cliLab = Join-Path (Get-Location) 'codex windows lab'
if (Test-Path -LiteralPath $cliLab) { throw 'Choose a new practice folder name.' }
New-Item -ItemType Directory -Path $cliLab -ErrorAction Stop
Set-Location -LiteralPath $cliLab
Set-Content -LiteralPath 'note.txt' -Value 'WINDOWS-CLI-01' -Encoding utf8
Get-Location
Get-ChildItem
Get-Content -LiteralPath 'note.txt'
```

成功時目前路徑最後一段是 codex windows lab，清單有 note.txt，讀取結果為 WINDOWS-CLI-01。另記錄雜湊作為唯讀前後的比較。雜湊表示檔案位元組的指紋；不同電腦因 UTF-8 BOM 或換行差異可能不同，不要拿本文的數字當標準。本機前後應相同。

```powershell
Get-FileHash -LiteralPath 'note.txt' -Algorithm SHA256
```

## 步驟三：登入、沙盒與實際讀取

仍在練習資料夾，逐行執行 codex login、codex login status，再啟動唯讀工作階段。瀏覽器登入時核對帳號與工作區；已登入不代表需要登出重來。若另一個 IDE 擴充套件共用認證，登出也可能影響它。看見登入程式碼或憑證路徑時不要放進公開截圖。

```powershell
codex login
codex login status
codex --sandbox read-only
```

Windows 沙盒設定可能需要一次管理員核准；這和把日常 PowerShell 視窗長期以管理員執行不同。官方以 elevated 為較強的原生選項，unelevated 是受限制的替代方式，組織可禁止替代。若初始化失敗，先記錄 Windows 版本、沙盒模式及錯誤階段；不要直接把教學改成全存取模式。需要調整時先看[許可權與沙盒](article:codex-permissions)。

```text
Read note.txt in the current practice folder. Report the exact content and current working directory. Do not edit, create files, or use external services. If it is missing or inaccessible, report the actual error.
```

上段貼進 Codex 對話，不是 PowerShell。回覆和讀取記錄應包含 WINDOWS-CLI-01 及正確目錄。用 /exit 回到 PowerShell，再執行讀檔、列檔和雜湊，確認內容未變、沒有新增練習檔。先記錄這個成功基準，再刻意要求讀取 missing-note.txt，預期回報不存在而不建立。若讀到其他內容，先處理工作目錄錯誤。

## 更新與三類排錯

更新前先退出 CLI、保留工作摘要和未提交檔案。獨立版重跑同一個官方安裝命令；npm 版再執行 npm.cmd install -g @openai/codex。開新 PowerShell，核對 Get-Command 的來源和版本。若顯示舊版，先找重複來源；更新成功的是其中一份，PATH 仍可能先選另一份。不要只重複更新卻不查實際執行檔。

| 現象 | 先查什麼 | 下一步 |
| --- | --- | --- |
| 找不到 codex | 新 shell 的 Get-Command 結果 | 依安裝輸出修正使用者 PATH，再開視窗 |
| npm.ps1 不允許執行 | 是否用 npm 管道及指令碼包裝檔 | 用 npm.cmd 查版本；保留公司政策 |
| 登入後讀檔失敗 | 目錄、檔案是否存在、沙盒錯誤 | 修正目錄或授權範圍，不能以重灌代替 |

PATH 是 shell 搜尋程式的目錄清單，不是專案清單。先對照安裝輸出與 Get-Command Source；需要手動修改時，在 Windows 搜尋「編輯帳戶的環境變數」，編輯使用者 Path，新增已確認的安裝資料夾，保留現有專案，儲存後開新終端機。不要把整段 PATH 替換成教學範例，也不要新增來路不明的下載資料夾。

## 完成條件與下一步

你應能指出正在執行哪一份 CLI、從哪個資料夾啟動、登入狀態如何、讀到的標記為何，以及唯讀前後雜湊是否相同。把安裝管道、版本、錯誤和解法記在自己的練習筆記即可，不需儲存憑證內容。接著回[CLI 共用入門](article:codex-cli-getting-started)完成小幅修改與接續；若要在編輯器工作，再看[IDE 擴充套件](article:codex-ide-getting-started)。
