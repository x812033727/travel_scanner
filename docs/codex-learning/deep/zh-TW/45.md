## 目標與準備

> 找回正確的 CLI 工作階段，辨認同名檔案屬於哪個專案，讀取磁碟最新版本後再繼續。閱讀約 12 分鐘，操作約 20 分鐘。需要已登入的 Codex CLI 與純文字編輯器；Windows、macOS、Linux 都能做本練習。先熟悉終端機路徑，這次不用 Git、網路搜尋或正式資料。

resume 接續的是先前工作階段的對話與狀態，不是把整個磁碟還原到當時。你在編輯器改了檔案，或其他任務做了修改，重新接續時都要確認。也不要把接續與 [fork](article:codex-project-management)、[跨主機 Handoff](article:codex-cross-device-workflow)混成一件事：一個是回到既有任務，一個建立另一條工作線，另一個移動執行位置。

## 步驟一：建立容易辨認的兩個練習

在同一個練習父資料夾建立 codex-session-a 與 codex-session-b，各自新增 note.txt。A 放第一段，B 放第二段，不要把兩段放進同一個檔案。兩個檔名都叫 note.txt，但內容標記不同；這讓你不能只靠檔名猜測目前工作位置。記下父資料夾在哪裡，後續每次啟動前都先核對目錄。

```text
SESSION-A
Revision: 1
```

```text
SESSION-B
Revision: 100
```

用編輯器開 A 資料夾，再開整合終端機。PowerShell 用 Get-Location，macOS／Linux 用 pwd，確認末端是 codex-session-a；從該處執行下列命令。進入 CLI 後送出再下一段要求。預期回覆 A 的實際路徑、SESSION-A、Revision: 1，且檔案沒有修改。記錄這次任務在清單中顯示的標題與時間。

```sh
codex --cd . --sandbox read-only
```

```text
Read note.txt from the current directory without changing files. Report the exact directory and both lines. This is a session-resume exercise. Do not search other folders or infer content from the filename.
```

用 /exit 退出 A，看到系統終端機提示符號後，改從 B 資料夾開相同的唯讀工作階段並送出相同要求。這次應是 SESSION-B 與 Revision: 100。退出後你有兩個可辨識的工作階段；B 較新，但接下來要找回的是 A。這比只有一個任務時按「最近」更能測出選擇是否正確。

## 步驟二：用清單找回 A

回到 A 資料夾的系統終端機執行 codex resume。用畫面清單確認專案路徑、時間與可看到的內容，再選 A。若目前清單不含想找的目錄，可以用 --all 列出其他目錄的工作階段，但必須重新核對選擇，不把全域最新項目直接當目標。清單操作鍵以當前畫面提示為準，按 Enter 確認前先看清楚目錄。

```sh
codex resume
```

```sh
codex resume --all
```

若啟動目錄和任務儲存的目錄不同，CLI 可能詢問要用哪個位置；不要為了快點進去隨便選。這次要繼續 A 就選 A 所在位置，接著用 /status 與新的讀檔要求確認。已設定 tui.resume_cwd 或明確 --cd 時，行為可能不同；需要理解它們時看[設定排錯](article:codex-config-troubleshooting)，不要把沒有跳詢問框當作一定選對。

| 方式 | 用途 | 使用前的確認 |
| --- | --- | --- |
| codex resume | 開啟選擇清單 | 路徑、時間、任務內容 |
| codex resume --last | 接續目前目錄最近任務 | 已在正確目錄 |
| codex resume --all | 顯示跨目錄任務 | 不把最新項目誤當目標 |
| codex resume SESSION_ID | 用已知 ID 指定任務 | ID 來自真正任務，不是範例字樣 |
| /resume | 在互動 CLI 開選擇清單 | 指令輸入於 Codex，而非系統 shell |

## 步驟三：證明接續會讀到新磁碟內容

再次退出 A，使用文字編輯器只將 A/note.txt 第二行改為 Revision: 2，B 的檔案完全不動。回 A 的系統終端機執行下面命令，這裡 --last 依官方規則限定目前目錄的最近工作階段；不要加 --all，因為它會改變搜尋範圍。如果該目錄還有其他任務，改用清單或已知 ID，不要盲猜最近一筆就是練習。

```sh
codex resume --last --sandbox read-only
```

進入後送出下列要求。預期指出舊對話是 Revision: 1，但目前磁碟是 Revision: 2，且 SESSION-A 沒變。這個差異是題目，不是要修復的錯誤；不要叫它把檔案改回聊天記憶中的數字。對正式工作而言，相同方法可用來確認測試紀錄、未提交修改與交接筆記是否仍符合現在版本。

```text
Resume by reading note.txt from disk again now. Compare the current revision with the earlier conversation. Report the current directory, the file marker, and any difference. Do not restore an older value or edit any file.
```

## 常見錯誤、停止與還原

找不到工作階段時，先查是否換了 OS、使用者、CODEX_HOME 或主機，再用 --all 核對其他目錄；桌面與 CLI 的工作階段不應只靠標題相同就推定可互換。選錯 B 時，先停止送出後續要求，/exit 回終端機重選 A；如果已經有寫入，就到被修改的真正目錄檢查差異，退出對話不會撤銷檔案。回覆仍是 1 時則要求新讀取並確認路徑，而不是重複同一句「繼續」。

如果規則檔剛更新，也應先完成目前小步驟並開新的工作階段驗證，不把 resume 當成清空所有舊指示的方法；[規則層級篇](article:codex-agents-md-scopes)有專門對照。長對話需要整理時看[上下文交接](article:codex-context-handoff)，保留關鍵決策、真實檔案與未完成事項，而不是把摘要當作檔案備份。

完成時應保存 A／B 的辨識紀錄、A 接續後的新讀取，以及為何 --last 和 --all 不能隨便互換的說明。還原練習時只把 A 的 Revision 改回 1，再確認 B 仍是 100；不需要刪除工作階段或登入資料。本篇命令依官方文件與本機 help 查證，沒有替讀者執行互動工作階段或保證舊任務跨平台自動同步。下一次正式接續也先確認「哪個任務、哪個目錄、哪個版本」，再開始修改。

圖中 1 是先辨認 A 與 B，2 是選擇正確的工作階段，3 是重新讀取磁碟並核對版本。每次續接都保留這三個檢查點。
