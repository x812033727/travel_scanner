## 讀完能做到什麼

> 這篇讓你從「看到指令卻不知道貼哪裡」，走到能查版本、進入工作階段、查看狀態、要求計畫、退出並接續任務。閱讀約 12 分鐘，操作約 20 分鐘。它是一條完整練習路線加上常用索引，不要求一次背下所有選項。

本篇以 Codex CLI 為範圍。桌面版和 ChatGPT 網頁也可能有斜線選單，但命令集合不相同。不要把 Claude Code 的命令、網路上的舊截圖，或桌面快捷鍵直接當成 CLI 語法；先查你正在使用的介面與版本。

## 開始之前

先完成[CLI 安裝](article:codex-cli-getting-started)及登入，下載[待辦練習材料](https://mokaair.com/guides/codex-first-project/todo-practice.zip)，用 expected 副本建立 codex-practice。這一篇主要讀取檔案和規劃，不需要 GitHub 或付費外部服務。若 codex 命令找不到，先完成安裝排錯，不要把登入問題和路徑問題混在一起。

Windows 在練習資料夾開 PowerShell；macOS 開 Terminal；Linux／WSL 開該環境自己的終端機。WSL 中的 /home 路徑與 Windows 的 C:\Users 路徑不同，命令要在真的裝有 CLI 的環境執行。確認完位置，再開始以下步驟。

## 四種輸入要分清楚

| 類型 | 貼在哪裡 | 範例 | 會發生什麼 |
| --- | --- | --- | --- |
| 終端機命令 | PowerShell／Terminal／Linux shell | codex --help | 執行 CLI 程式並顯示說明 |
| 互動斜線指令 | 已啟動 Codex 的輸入框 | /status | 由目前互動介面處理 |
| 快捷鍵 | 按鍵，不是輸入文字 | Ctrl+R | 搜尋提示詞歷史 |
| 自然語言提示詞 | Codex 對話輸入框 | Explain core.mjs without editing. | 交給代理理解並完成要求 |

終端機通常顯示路徑與提示符號；Codex 互動介面則有自己的對話輸入區。在 PowerShell 輸入 /plan 會被 shell 當成命令或路徑，不能開啟 Codex 的 Plan 模式。反過來，把多行安裝命令貼進 Codex 對話，也可能變成請代理執行的要求，與你直接執行不同。

## 第一步：查版本與說明

```text Windows PowerShell、macOS Terminal 或 Linux shell；尚未進入 Codex 對話
codex --version
codex --help
codex resume --help
```

三行可以逐行執行。第一行顯示版本，第二行列出此版本的子命令與選項，第三行只看接續工作階段的說明。它們不會開始新的代理工作。本次 Windows 實際查得 codex-cli 0.154.0-alpha.6.2；這是驗證環境紀錄，不是要求你安裝這個預覽版本。

說明中的方括號表示選用內容，角括號通常代表要替換的值。不要照抄 SESSION_ID 之類的占位文字，也不要把文件展示的所有旗標一起加上。查不到選項時，先確認拼字、子命令與版本，再判斷是否需要更新。

## 第二步：啟動並檢查狀態

```text 同一個系統終端機；目前目錄為 codex-practice
codex
```

進入互動介面後，在輸入框打 /，使用彈出的清單搜尋 status，再執行 /status。應看到目前工作階段的設定資訊，例如模型、權限與上下文狀態；顯示欄位依版本而異。它不是購買額度或兌換重置信用的指令。

```text Codex CLI 互動輸入框；執行狀態檢查
/status
```

請同時用唯讀自然語言核對工作位置。若路徑不符，離開這個工作階段，回終端機進入正確資料夾再啟動。不要試圖用切換模型來修正工作目錄。

```text Codex CLI 對話；讀取練習位置
Report the current working directory and list the five Small Steps source files.
Do not edit anything. If this is not the practice folder, stop and explain.
```

## 第三步：使用 Plan 模式做一次規劃

[Plan 模式](article:codex-plan-mode)適合在實作前檢查需求、影響範圍與驗收方式。在互動輸入框執行下面的內容，要求設計一個「清除已完成」功能。這個功能不在初始需求中，所以要保留未完成資料並考慮空清單；本篇只產生計畫。

```text Codex CLI 互動輸入框；斜線命令與本次需求
/plan Plan a Clear completed button for this todo website. Do not implement it yet. Preserve active tasks and explain how to verify an empty list, mixed completion states, and reload behavior.
```

合格計畫應指出相關檔案、按鈕位置、資料操作、儲存方式與測試案例，不能只有「修改、測試、完成」三個空泛步驟。檢查是否誤提不存在的 React 元件或資料庫。發現不符就補充限制，直到你能用計畫判斷成果。之後要實作，依目前介面的模式控制與提示交付；計畫本身不代表已改好網站。

## 第四步：退出並找到同一個工作階段

完成計畫後，先記下任務名稱或工作階段識別資訊，再在互動輸入框執行 /quit。回到系統終端機後，執行 codex resume，從選擇器核對時間、內容與路徑，選回剛才的任務。剛入門先用選擇器，比直接假定最後一個就是目標更容易核對。

```text Codex CLI 互動輸入框；退出當前介面
/quit
```

```text 回到系統終端機後；開啟工作階段選擇器
codex resume
```

官方文件也提供 codex resume --last 接續目前目錄最近的工作階段；加 --all 會擴大搜尋範圍。這些選項先查 resume --help 再使用。接續後請它摘要剛才的計畫和未完成事項，並核對路徑。能說出功能不表示檔案就在正確位置，兩項都要查。

## 驗收、常見問題與還原

正常驗收：版本與說明可讀、工作位置正確、計畫沒有修改檔案、退出後能接續同一任務。邊界驗收：在 / 選單輸入不存在的名稱，確認它沒有變成你以為的功能；取消輸入並回文件查證，不要因此提高權限或安裝來路不明的補充工具。

「不是內部或外部命令」或 command not found：這是 shell 找不到 codex，先檢查安裝位置與新的終端機環境。若 codex --help 能跑而 /plan 不能，通常是輸入介面不對，不是 CLI 沒裝好。

參數不接受：確認一般半形連字號 --，不要使用文章排版的長破折號；空格與引號也要保留。不同子命令支援的旗標可能不同，主程式接受不表示每一個子命令都接受。

resume 找不到或接錯：回想是否在不同目錄、主機或 CLI 環境啟動，先看選擇器與說明。不要用刪除歷史來處理找不到的任務。這篇沒有修改原始碼，退出即可結束；退出或重開對話不會撤銷先前已經完成的檔案操作。
