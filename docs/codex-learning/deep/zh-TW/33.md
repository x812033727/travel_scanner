## 讀完能做到什麼

> 你會選出一個適合目前工作的主要入口，說明檔案在哪裡、命令在哪裡執行、要去哪裡看結果，並用唯讀任務確認選擇。閱讀約 10 分鐘、操作約 15 分鐘。這篇不要求把所有版本都安裝一次；先讓一條完整路線可用，再擴充其他入口。

## 把入口與執行環境分開

入口是你送出需求的地方，環境才是代理實際工作的地方。桌面、CLI 與 IDE 都可能操作本機專案；遠端專案與雲端任務則涉及另一個環境。手機畫面小，不代表任務比較小；桌面視窗看起來一樣，也不代表背後使用相同電腦。先畫出「我從哪裡送出 → 哪臺機器做事 → 哪裡檢查成果」，比先比較按鈕多寡有用。

| 入口 | 主要操作方式 | 第一個確認點 |
| --- | --- | --- |
| 桌面 | 專案、任務、檔案與差異畫面 | 選到哪個專案與主機 |
| CLI | 終端機的文字指令與對話 | 目前工作目錄 |
| IDE | 編輯器旁的檔案與程式上下文 | 開啟哪個資料夾與檔案 |
| 雲端 | 設定好的遠端環境與任務 | 儲存庫、分支及環境設定 |
| 手機 Remote | 控制已連線主機的任務 | 配對的主機是否可用 |

## 第一步：從現有工作選入口

主要用圖形介面、希望直接管理多個任務，可先走[桌面版入門](article:codex-desktop-getting-started)。Windows 與 macOS 依各自官方安裝流程；Linux 依官方桌面預覽支援的發行版與架構挑套件，不把 Windows 安裝檔搬過去執行。Linux 桌面預覽的存在也不代表 Remote 主機支援完全相同，兩個功能要分別查證。

平常會在在終端機切換資料夾、執行測試，或準備把工作接到指令碼，就選 [CLI](article:codex-cli-getting-started)。Windows 原生與 WSL 是不同環境，工具安裝、家目錄與路徑要分別確認；macOS 與 Linux 也不能把使用者路徑直接互貼。還不熟終端機，可先讀[路徑與終端機](article:codex-terminal-paths)，這比一次學兩種殼層更容易找到錯誤。

已經在官方支援的編輯器內寫程式，希望把目前檔案或選取區段帶入，就讀 [IDE 擴充](article:codex-ide-getting-started)。先用目前的編輯器核對官方可用入口，不要只根據商店裡相似的名稱安裝。即使同時安裝桌面與 IDE，第一次仍只用一個入口改檔；兩個任務一起改同一檔案，很難判斷是哪次修改造成結果。

## 第二步：判斷是否需要雲端或手機

需要把 GitHub 儲存庫的工作交給配置好的遠端環境，再回來看差異或 PR，可走[雲端任務](article:codex-cloud-tasks-github)。開始前記下儲存庫與分支；只在自己電腦修改但尚未提交的檔案，不會因名稱一樣就出現在雲端。你需要的是把正確版本提供給環境，而不是重新貼一次模糊需求。沒有 GitHub 練習庫時，先用本機路線也能完成入門。

外出時追蹤或接續電腦工作，可以考慮[手機 Remote](article:codex-mobile-guide)。官方文件列出 iOS、Android 控制可用的 macOS 或 Windows 桌面主機；主機需要保持可連線，配對與工作區權限也要成立。手機不是把 npm、專案與本機瀏覽器搬到自己儲存空間。若電腦關機或離線，先恢復主機，不要改成在手機終端機亂裝套件來修復連線。

## 第三步：用同一個小任務驗證

建立一個空白 codex-platform-check 資料夾，以純文字檔 location.txt 寫下唯一一行 Practice marker: local-copy-A。桌面或 IDE 開啟該資料夾，CLI 先移入資料夾再啟動；選擇雲端者則在自己的練習儲存庫建立同一檔案並提交，確認雲端選到包含它的分支。不要為了驗證入口而上傳正式專案。

```text 自然語言提示詞：在選定環境的 Codex 任務輸入
Read location.txt without changing files.
Report the exact marker, working directory, and where commands for this task run.
Distinguish verified facts from anything you cannot determine.
Do not install tools, create files, or change settings.
```

預期讀到 local-copy-A，並能以工具結果支援工作路徑。平臺可能使用隔離工作副本，因此不要求路徑和自己桌面文字完全相同；重點是所選分支、檔案標記和工作環境能對上。若它無法證實是哪臺主機，就把主機身份列為未知，再回連線設定核對，而不是把推測當作成功。

邊界練習：只在本機把標記改成 local-copy-B，但不要提交。詢問既有雲端副本時，它仍可能讀到 A；這正是不同版本的可觀察證據，不是模型忘記。手機連到同一主機且同一資料夾則應以主機目前檔案為準。每次都報出來源與標記，比問「是不是最新」更容易判斷。

### 只有一台電腦時，怎麼完成這個練習？

若尚未設定雲端或 Remote，完成所選本機入口的讀取測試就足夠，不必為這一課新增帳號連線。想練習分辨副本，可另外建立兩個互不包含的資料夾 copy-a、copy-b，各放一份 location.txt；只把 copy-b 的標記改為 local-copy-B，再分別開啟兩個資料夾執行上面的唯讀提示詞。預期 A 讀到 local-copy-A，B 讀到 local-copy-B；先看工作目錄，再比對標記。這只驗證本機有兩份不同檔案，不能當成雲端同步或手機連線已成功的證據。

## 常見問題與完成判準

入口看不到：先核對官方支援、程式版本、帳號工作區及逐步開放狀態，沒有按鈕時保留未確認結果。檔案看不到：核對資料夾、雲端分支或連線主機，再檢查提交狀態。命令找不到：到實際執行的環境檢查工具，不能用自己筆電裝過 Node.js 證明雲端也有。這三種問題分別是入口、版本資料與執行環境，不要全部用重新登入處理。

結束時把標記恢復成 A，保留練習資料夾供後續課程使用；只停止自己這次建立的任務。你應能完成一句話：「我使用＿＿入口，檔案在＿＿環境，以＿＿檢查成果」。若改換入口仍不知道檔案去哪裡，先完成這個唯讀測試，不急著開始多工。圖中的 1、2、3 分別代表選入口、確認環境、驗證成果。
