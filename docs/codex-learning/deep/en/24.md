## Goal and preparation

> Install a plugin you need, connect its external account, read a fictional practice document and distinguish uninstalling from disconnecting. Allow 15 minutes to read and 25 to practice. Use a supported surface and a service account; read [Permissions and data scope](article:codex-permissions). The example uses a practice document you create in Google Drive; available plugins and options depend on your account.

Plugins distribute capabilities and can bundle [Skills](article:codex-skills), [MCP](article:codex-mcp) and supporting components. Skills describe a workflow; MCP tools read or operate services. Installation does not establish service authentication or immediate availability of every tool. Separating these states helps diagnose an installed plugin that cannot read a document.

## Step 1: Confirm your surface

Open Plugins on desktop and inspect the available OpenAI, workspace, Personal or Installed categories. On Windows, macOS and Linux, check the desktop version and plugin-specific requirements; verify actual availability in a Linux preview's local directory. A public description page does not establish executable support in the current environment. See [Platform selection](article:codex-platforms-guide) if you need a desktop entry point.

In a terminal on any of the three operating systems, enter your practice folder, start codex, then type /plugins inside its interactive session. codex is a shell command; /plugins is an interactive slash command, so perform them separately. The IDE extension currently does not support Plugins. Use a supported desktop or CLI surface instead of expecting the CLI menu inside the editor.

```sh Terminal: start Codex
codex
```

```text Inside interactive Codex CLI
/plugins
```

| Surface | Confirm first | Practice route |
| --- | --- | --- |
| Windows/macOS/Linux desktop | Version, directory, plugin platform requirements | Install and connect through Plugins details |
| CLI on all three | Login, /plugins, marketplace source | Inspect, install, then start a fresh session |
| iOS/Android | Plugins available in account Chat/Work | Check it is not Desktop only; use a supported surface |
| IDE | Plugins unsupported | Use desktop/CLI; standalone Skills are separate |

A mobile plugin does not automatically expose a computer's disk. Tasks needing local computer files still follow [Mobile and cross-device](article:codex-mobile-guide) connection requirements; this exercise reads only the chosen service document. A Desktop only plugin cannot run directly on a phone merely because its listing is discoverable on the web.

## Step 2: Prepare a verifiable document

In your practice Google Drive, create a document titled Codex Plugin Practice and paste the full text below. Keep it private; do not enable public access merely to make a plugin read it. Retain its URL to specify scope. If using another service, first complete installation and state recording, then adapt the example only after confirming equivalent read tools.

```text Practice document content
Codex Plugin Practice
Revision: 1
Document marker: PLUGIN-LAB-A
Task count: 3
Completed count: 2
Pending count: 1
Scope: fictional practice data; read only.
```

The marker and revision identify what the tool actually read, rather than testing whether a model can guess three counts. Titles can repeat; the URL and marker must match. If search finds two documents with the same name, do not choose arbitrarily. Inspect the original service page first, then request that exact URL for an independent comparison.

## Step 3: Install, connect and start a fresh task

Open plugin details and verify the name, provider, marketplace source and capabilities before installing the intended Google Drive plugin. Desktop documentation describes a plus button; CLI installation is available from details under /plugins marketplace categories. Record the name or ID and date so a similarly named package is not mistaken for the same installation.

When sign-in is required, verify the service and account own the practice document, then read the requested permissions. Do not paste passwords, verification codes, tokens or connection callback URLs into chat. If the requested access exceeds your acceptable purpose, cancel and record not connected. A read-only prompt does not narrow OAuth permissions.

Return to the original surface, inspect Installed and connection state, then start a new chat or CLI session. Some plugins connect only on first use, so installation alone cannot skip this check. API-key Codex authentication does not support every OAuth-dependent plugin. Check authentication mode and plugin requirements rather than repeatedly replacing or printing keys.

## Step 4: Verify an actual read

On desktop, use @ to select the installed plugin or bundled skill and paste the request, replacing the marked position with your practice document URL. In a new CLI session, request the installed plugin for the same document and use the skill-selection entry if shown. Read only the specified document, making both results and scope easy to verify.

```text Request to Codex; replace the document URL first
Use the installed Google Drive plugin to read this practice document:
<PASTE YOUR PRACTICE DOCUMENT URL HERE>
Return the document title, source link, revision, marker, and the three counts.
Use an actual read result. If access is unavailable, say which step failed.
Do not edit, share, move, delete, or search unrelated files.
```

The reply should link the same document and report Revision 1, PLUGIN-LAB-A and 3/2/1 with actual read evidence. Match values to total, completed and pending fields rather than merely checking the numbers. Then manually change Revision to 2, Completed to 1 and Pending to 2. Request a fresh read without supplying the new values and verify it reports the updated document.

If it returns old counts, request a fresh source read and observed revision. Record connection, account-access or update-delay errors instead of fabricating new results. A fresh task can help separate old conversation context. Finally inspect the service to confirm the agent did not edit, share or move the document, distinguishing your manual revision from the agent's read.

## Step 5: Disable, uninstall and disconnect

In CLI /plugins, use Space on an installed entry to toggle it when supported; use Uninstall plugin in details to remove it. On desktop/web, open installed plugin details for the uninstall action. Workspace or default plugins may be administrator-controlled. Record that restriction rather than deleting application caches or installation folders.

Uninstalling a bundle and disconnecting an external account are separate. Independently connected MCP integrations may remain; disconnect the service in ChatGPT connection management and inspect the provider's third-party authorization page if needed. Check shared use before removing only the practice connection. In a fresh task verify that connection can no longer read, rather than treating a removed Installed entry as proof all access was revoked.

Record installation, authorization, first read, revised read and removal separately. Mark unoperated platforms/services as documentation-checked. This lesson does not claim to have authenticated your Drive or read private documents. Diagram 1 selects capability/scope, 2 connects and reads, and 3 verifies and closes.
