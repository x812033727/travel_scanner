## Goal and environment

> Install Codex CLI in native Windows PowerShell, identify the executable, sign in and read a practice file in a path containing spaces. Allow 12 minutes to read and 25 minutes to practice, excluding downloads. Installation and sandbox steps were checked against official documentation on 2026-09-14. Local checks cover version, help and file operations; they did not reinstall the user's CLI or change machine policy.

Native Windows CLI does not require WSL. If your terminal is Ubuntu with /home paths, use [Linux / WSL](article:codex-cli-linux-wsl). This lesson uses PowerShell. Review environment selection in [CLI basics](article:codex-cli-getting-started), then return there for the one-line edit after setup. Diagram 1 is installation, 2 location and authentication, and 3 independent file verification.

Before installation, check your Windows version with winver. Current documentation recommends Windows 11 and provides best-effort support for recent, fully updated Windows 10 with modern console support; older versions are not equally supported. Native sandbox setup has additional prerequisites including winget and administrator-approved setup; consult the [official Windows sandbox documentation](https://learn.chatgpt.com/docs/windows/windows-sandbox). Treat CLI installation and sandbox setup as separate stages, and record which stage failed.

## Step 1: open PowerShell and choose a channel

Search Start for PowerShell, or select its profile in Windows Terminal. Begin with an ordinary user window; routine work does not require an administrator terminal. Run the first command below in the shell. If codex is found, record its version and Source and usually proceed directly to folder setup instead of adding another installation.

```powershell PowerShell: inspect command sources and version
Get-Command codex -All | Select-Object CommandType, Name, Source
codex --version
```

A command-not-found result is expected before installation. The official standalone Windows command below downloads and executes an installer; verify its URL on the official page before using it. ByPass is an argument for this child process, not an instruction to permanently disable machine execution policy. If organization policy blocks it, record the specific error and use an administrator-approved installation route.

```powershell PowerShell: run only when choosing the official standalone installer
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

Wait for completion and retain the reported installation path and PATH instructions. Close that terminal, open a fresh PowerShell and rerun Get-Command codex -All and codex --version. Expect a discoverable executable and version. A completed download, existing folder or absence of an error is not enough; the new shell must resolve the command.

### npm alternative when Node.js is already present

Use these three lines only if choosing npm. ## Step 2: prepare and verify a path with spaces

Choose a writable location outside production projects. Paste the whole block, including & { and the final }, to create a new codex windows lab; a failed existence check then stops the block. If that name already exists, preserve its contents and choose a new name rather than skipping the check and running the write lines. On success, the commands enter the new folder, list files and read note.txt. Quotes preserve spaces; LiteralPath avoids wildcard interpretation.

```powershell PowerShell: paste the whole block to create a new practice folder here
& {
  $cliLab = Join-Path (Get-Location) 'codex windows lab'
  if (Test-Path -LiteralPath $cliLab) { throw 'Choose a new practice folder name.' }
  New-Item -ItemType Directory -Path $cliLab -ErrorAction Stop
  Set-Location -LiteralPath $cliLab -ErrorAction Stop
  Set-Content -LiteralPath 'note.txt' -Value 'WINDOWS-CLI-01' -Encoding utf8 -ErrorAction Stop
  Get-Location
  Get-ChildItem
  Get-Content -LiteralPath 'note.txt'
}
```

Success means the current path ends in codex windows lab, note.txt appears and its content is WINDOWS-CLI-01. Record the hash for comparison before and after the read-only task. A hash fingerprints file bytes; UTF-8 BOM and newline differences can vary across machines, so compare your own before and after values rather than a published fixed value.

```powershell PowerShell: hash the file in the practice folder
Get-FileHash -LiteralPath 'note.txt' -Algorithm SHA256
```

## Step 3: authentication, sandbox and reading

Stay in the practice folder. Run codex login and codex login status, then start a read-only session. Confirm the account and workspace in the browser; existing valid sign-in does not need a logout/reset. Logging out can also affect an IDE extension sharing the credentials. Keep login codes and credential information out of public screenshots.

```powershell PowerShell: sign in, check status, then start Codex one line at a time
codex login
codex login status
codex --sandbox read-only
```

Windows sandbox setup may request one-time administrator approval; this is distinct from running everyday PowerShell as administrator. Official guidance prefers the stronger elevated native sandbox and provides unelevated as a restricted fallback that organizations may prohibit. On setup failure, record Windows version, sandbox mode and failure stage rather than switching the exercise to full access. See [permissions and sandboxing](article:codex-permissions) before adjusting it.

```text Natural-language prompt: enter inside Codex CLI
Read note.txt in the current practice folder. Report the exact content and current working directory. Do not edit, create files, or use external services. If it is missing or inaccessible, report the actual error.
```

Paste that prompt into Codex, not PowerShell. The response and read record should identify WINDOWS-CLI-01 and the correct directory. Use /exit, then read, list and hash again in PowerShell to confirm unchanged content and no extra practice files. After establishing success, request missing-note.txt and expect absence without creation. Unexpected content points first to a working-directory problem.

## Updating and three troubleshooting branches

Before updating, exit CLI and preserve the work summary and uncommitted files. Rerun the official installer for standalone installations, or npm.cmd install -g @openai/codex for npm. In fresh PowerShell, check command Source and version. If the old version remains, inspect duplicate sources: one installation may have updated while PATH selects another. Repeated updates without checking the executable will not resolve that ambiguity.

| Symptom | First check | Next step |
| --- | --- | --- |
| codex not found | Get-Command in a fresh shell | Follow installer instructions for user PATH, then reopen |
| npm.ps1 execution blocked | npm channel and script wrapper | Check npm.cmd; preserve managed policy |
| Reading fails after login | Directory, file existence and sandbox error | Correct location or access; reinstalling is not a substitute |

PATH is the shell's executable-search list, not a project list. Compare installer output with Get-Command Source. If manual correction is necessary, open Windows' environment-variable editor for your account, edit the user Path, add the confirmed installation directory while retaining existing entries, save and reopen the terminal. Do not replace the entire PATH with an example or add an unverified downloads folder.
