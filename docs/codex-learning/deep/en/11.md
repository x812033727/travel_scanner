## What you will accomplish

> Move from recognizing a command without knowing where to paste it to checking versions, entering a session, inspecting status, requesting a plan, exiting and resuming. Allow 12 minutes to read and 20 minutes to practice. This is a complete workflow with a compact index, not a requirement to memorize every option.

The scope is Codex CLI. The desktop app and ChatGPT web can also have slash menus, but their commands differ. Do not treat Claude Code commands, older screenshots or desktop shortcuts as CLI syntax. Check the interface and version you are actually using.

## Before you begin

Complete [CLI installation](article:codex-cli-getting-started) and sign-in. Download the [todo materials](https://mokaair.com/guides/codex-first-project/todo-practice.zip) and copy expected into codex-practice. This lesson primarily reads files and produces a plan; GitHub and paid external services are unnecessary. If codex is not found, resolve installation first instead of confusing path discovery with authentication.

Open PowerShell on Windows, Terminal on macOS, or a shell in the relevant Linux/WSL environment at the practice folder. WSL /home paths differ from Windows C:\Users paths. Run commands where the CLI is installed and verify the location before proceeding.

## Distinguish four kinds of input

| Type | Where it goes | Example | Effect |
| --- | --- | --- | --- |
| Shell command | PowerShell / Terminal / Linux shell | codex --help | Runs the CLI and prints help |
| Interactive slash command | Composer after Codex starts | /status | Handled by the current interactive UI |
| Shortcut | Press keys, do not type their names | Ctrl+R | Searches prompt history |
| Natural-language prompt | Codex conversation composer | Explain core.mjs without editing. | Gives the agent a task to interpret |

A shell usually displays a path and prompt; Codex has its own conversation input. Typing /plan in PowerShell is interpreted as a shell command or path, not Codex Plan mode. Conversely, pasting installation commands into a Codex conversation may ask the agent to execute them, which differs from running them yourself.

## Step 1: inspect version and help

```text Windows PowerShell, macOS Terminal or Linux shell; outside a Codex conversation
codex --version
codex --help
codex resume --help
```

Run these one line at a time. They show the version, available subcommands and flags, and resume-specific help. They do not start a new agent task. The Windows environment checked for this lesson reported codex-cli 0.154.0-alpha.6.2; that is an evidence record, not an instruction to install this preview build.

Square brackets in help indicate optional arguments; angle brackets usually identify a value to replace. Do not copy placeholders such as SESSION_ID literally or combine every documented flag. If an option is missing, check spelling, subcommand and version before deciding to update.

## Step 2: start a session and inspect status

```text The same system terminal, in codex-practice
codex
```

Inside the interactive interface, type /, search for status in the popup and run /status. Expect session configuration such as the model, permissions and context state, with fields varying by version. This is not a purchase or reset-credit redemption command.

```text Codex CLI interactive composer; inspect status
/status
```

Also ask for the working directory in a read-only prompt. If it is wrong, leave the session, enter the correct folder in the shell and restart. Switching models does not correct a directory mistake.

```text Codex CLI conversation; inspect the practice location
Report the current working directory and list the five Small Steps source files.
Do not edit anything. If this is not the practice folder, stop and explain.
```

## Step 3: request a plan

[Plan mode](article:codex-plan-mode) helps inspect requirements, scope and verification before implementation. Run the following in the interactive composer to design a Clear completed feature. It must preserve active tasks and handle an empty list. This lesson produces only the plan.

```text Codex CLI interactive composer; slash command with this request
/plan Plan a Clear completed button for this todo website. Do not implement it yet. Preserve active tasks and explain how to verify an empty list, mixed completion states, and reload behavior.
```

A useful plan identifies files, button placement, data operations, persistence and test cases. “Edit, test, finish” is insufficient. Check for invented React components or a database that this project does not have. Add constraints until you can use the plan to judge results. When ready to implement later, follow the current interface's mode controls and prompts. A plan does not establish that the website has changed.

## Step 4: exit and locate the same session

Record the task name or session identifier after planning, then enter /quit in the interactive composer. Back in the system terminal, run codex resume. Check time, content and location in the picker before selecting the task. For beginners, choosing explicitly is easier to verify than assuming the latest session is the intended one.

```text Codex CLI interactive composer; leave the interface
/quit
```

```text Back in the system terminal; open the session picker
codex resume
```

The documentation also provides codex resume --last for the latest session in the current directory; --all broadens the search. Check resume --help before using these options. After resuming, ask for the previous plan and outstanding work, then verify the path. Remembering the feature does not prove the files are in the right location.

## Verification, troubleshooting and restoring

Normal verification: version and help work, the directory is correct, planning did not edit files, and the same task can be resumed. Boundary verification: type a nonexistent name in the slash menu and observe that it does not become the function you expected. Cancel and check documentation rather than increasing permissions or installing an unknown add-on.

“Command not found” or the Windows equivalent means the shell cannot find codex. Check installation and open a fresh terminal environment. If codex --help works but /plan does not, the input surface is often wrong; that is not a missing CLI installation.

Rejected argument: use ordinary -- hyphens, not a typographic dash, and preserve spaces and quotes. Different subcommands accept different flags; a flag on the main command does not necessarily work everywhere.

Missing or wrong resumed task: consider whether it started in another directory, host or CLI environment. Inspect the picker and help. Do not delete history as a fix. This lesson does not modify source code, so exiting ends it; leaving or restarting a conversation does not undo earlier file operations.
