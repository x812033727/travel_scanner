## Goal and preparation

> In an isolated Git lab, create a branch, inspect diffs, stage/commit only selected files, restore uncommitted changes and revert a commit. Allow 15 minutes to read and 30 to practice. Use Git 2.28 or later, an editor and the expected fixture. Git commands are shared across OSes. This creates local history only; no GitHub, remote account or push is needed.

Know [terminal paths](article:codex-terminal-paths). The working tree is current files, the index is the next commit's staged content, and commits record versions; these can differ. A branch identifies a history line, not an automatic copy of uncommitted files. For separate directories, use [worktrees](article:codex-worktrees); creating a branch is not a backup.

## Step 1: Create an isolated baseline

Place the five expected files in new codex-git-lab outside any other project. Open its editor terminal, verify Get-Location or pwd and run git --version. If Git is missing, use its official platform installation guidance and reopen the terminal. Do not initialize your existing work repository for this exercise.

```sh
git init -b main
git config user.name "Practice Learner"
git config user.email "learner@example.invalid"
git add index.html style.css app.js core.mjs core.test.mjs
git diff --cached --name-only
git commit -m "Add practice baseline"
git status --short
```

Run line by line. Initial staging should contain exactly five files and status should be clean after committing. Identity values are local to this practice repository, not GitHub login or global configuration. If existing signing/hooks requirements prevent a commit, follow your setup or record the blocker instead of changing global policy.

## Step 3: Stage one file, then practice restoration

```sh
git add index.html
git diff --cached --name-only
git diff --cached -- index.html
git diff -- style.css
```

The staged list must contain only index.html while ordinary diff still shows CSS. The first command below unstages the title but keeps the edit in the editor. The second restores index.html from the index, now the original baseline. Confirm you intend to discard this practice edit before the second command. CSS is outside its path and must remain.

```sh
git restore --staged -- index.html
git restore --worktree -- index.html
git status --short
git diff -- style.css
```

Now only style.css should be modified, h1 restored and the note preserved. Undoing your change must not clear separate work. restore --staged does not discard the working-file edit; restore --worktree overwrites the specified file from its restore source. They are not interchangeable.

## Step 4: Commit the scoped edit and revert with history

Reapply Plan one useful step. in the editor, stage only index.html and inspect cached diff again. The commit below should contain only the title while CSS remains uncommitted. Verify committed paths with show; command success alone does not prove correct scope.

```sh
git add index.html
git diff --cached --name-only
git diff --cached -- index.html
git commit -m "Update practice title"
git show --format=short --name-only HEAD
git status --short
```

Before reverting, resolve working-tree changes. Here the only remaining change is your fictional CSS note. After verifying its preservation, explicitly finish that exercise and discard only it with the first command below. Require clean status and confirm HEAD is Update practice title before reverting HEAD. Do not apply this cleanup to real work with unrelated changes.

```sh
git restore --worktree -- style.css
git status --short
git log -1 --oneline
git revert --no-edit HEAD
git log -3 --oneline
git status --short
```

revert adds a reversing commit while preserving the original title commit. Expect original h1, three history entries and clean status. On conflict, inspect actual state instead of forcing options. To cancel an unfinished revert, use Git's git revert --abort workflow and recheck files.

## Command comparison, troubleshooting and acceptance

| Goal | Command | Check |
| --- | --- | --- |
| Inspect unstaged content | git diff | Working tree versus index |
| Inspect next commit | git diff --cached | Index versus HEAD |
| Unstage | git restore --staged -- index.html | Edit remains |
| Discard selected uncommitted edit | git restore --worktree -- index.html | Verify source and path first |
| Reverse a commit | git revert --no-edit HEAD | New history; verify target and clean state |

For a missing branch, verify the repository. Inspect unexpected files instead of staging every file at once. If one file mixes edits, whole-file staging includes all of them; review hunks before selective handling. Acceptance proves CSS exclusion, distinct restore effects and preserved revert history.
