## 每篇必須教到的程度

採用 [深入文章模板](article-template.md)。一般操作篇以繁中約 1,800–3,000 字為規劃尺度；純索引依用途縮短，實戰可超出。任何篇幅例外都要寫明原因與涵蓋成果，不能只把字數警告忽略後標為完整教學。英文、日文、韓文採相同操作與限制，不硬套中文字数；簡中除文字轉換外也需逐項校對。

每篇必須包含：

1. 一個主要學習目標、可觀察的完成結果、閱讀與操作時間分列。
2. 適用平台、帳號及工具前提、工作目錄；先備教學與可獨立開始的材料。
3. 最少必要概念，清楚區分「指引文件」「應用程式設定」「授權」「Git 狀態」。
4. 每一步的操作位置、輸入、預期回應與下一個判斷。不能只寫「安裝後登入」「設定 MCP」而省略中間動作。
5. 至少一個完整可複製範例；檔名、目錄樹、必要輸入資料及預期產物均齊全。節錄必須標示，不能讓讀者以為是完整檔案。
6. 成功驗證，包括至少一個正常案例及一個失敗／邊界案例；不需要執行工作的概念篇，改用具體選擇情境及判讀答案。
7. 通常至少三個與該功能直接相關的錯誤，逐一寫出症狀、可能原因、檢查方法與修正。若實際不適用，記錄例外原因。
8. 會改動設定、檔案或排程的教學附停止、停用或還原方法，說明恢復範圍；外部操作不能以回復對話冒充撤銷。
9. 一個小練習、明確完成判準、先備／相關／下一步分開的連結，以及實際查證的官方來源。

每份指令範例除語法語言外，必須標明「貼在哪裡」：PowerShell、macOS 終端機、Linux／WSL 終端機、Codex CLI 對話、桌面任務輸入框，或寫入哪個檔案。程式碼本體不得翻譯變形。

對齊的是教學深度及閱讀體驗。Claude Code 的 `CLAUDE.md`、`settings.json`、Dispatch、Hooks、Agent Teams、`/rewind` 等名稱和機制不能直接改名移植到 Codex。Codex 各篇仍以實作當下官方支援為依據；沒有對應功能時，明確說明差異或教導已查證的替代流程。

## 推薦路線與共用練習

路線保存穩定 ID；頁面依清單產生，先備依賴與上一篇／下一篇分開。未通過目前語言公開檢查的目標只顯示計畫狀態，不放空連結。

- 桌面新手：01 → 33 → 03 → 06 → 07 → 08 → 10 → 19 → 21。
- CLI 新手：34 → 05 → 35／36／37（按系統選一篇）→ 06 → 11 → 45 → 10 → 12。
- 手機與跨裝置：33 → 04 → 38／39 → 40 → 41；雲端工作再讀 15。
- MD 與可重用流程：09 → 10 → 42 → 43 → 16 → 44 → 23 → 48 → 49 → 51。
- 日常開發：46 → 07 → 08 → 47 → 20 → 19 → 21 → 22。
- 進階自動化：18 → 25 → 52 → 30 → 55 → 29 → 57 → 56；需要平行工作再讀 27 → 28 → 53 → 54。

待辦網站統一使用無資料庫的 HTML／CSS／JavaScript。材料需要有 `start`、`expected`、受控缺陷案例、測試與 README；每一篇列出從哪個狀態開始，不依賴讀者碰巧完成上一章。必要功能包括新增、完成、刪除、篩選、儲存、空值處理及鍵盤操作。教學自動化測試使用乾淨儲存環境與虛構待辦，避免前一次測試影響結果。

目前的 Small steps 靜態網站可保留為畫面修改練習，不能用它替代完整待辦功能實戰。既有 CSV 範例與測試保留，補上操作解說與可下載的每步材料。兩個品牌教學可共享練習成果標準；尚未協調共用原始檔前，各自在自己的目錄維護，不直接改動另一個任務的材料。

| 範圍 | Codex 現有版本 | Claude Code 當時可見版本 | 後續整合要求 |
| --- | --- | --- | --- |
| 富文字 | `rich_paragraph.spans`，text／link | `rich_paragraph.inlines`，text／code／link／article | 定義單一新版格式及舊 spans 轉接，覆蓋讀取、儲存、匯入與預覽；不直接改型別造成舊稿失效 |
| 程式碼 | language／code，語言可自由標記 | language 列舉＋必填 label＋code | 保留 TOML、CSV、Shell 等已有語言；替舊區塊補預設用途標籤，不能無損遷移的要報告 |
| 站內引用 | 含語系的絕對 URL，渲染時判斷發布 | kind／slug 引用，伺服器解析 | 遷移前後比對每個目標與文字、保持目前語言與同分頁；撤回／隱藏／缺語系皆不可點 |
| 系列清單 | 前端 32 筆 catalog，分頁讀一般文章清單 | 後端 series_data 與 series API | 整合成同一系列機制；支援 Codex 五語、規劃項目、穩定 ID、閱讀順序及推薦路線 |
| 搜尋導覽 | state 內篩選，沒有 URL 保存 | URL q／group／level／platform／path | 加入重新整理、返回上一頁、分享網址後保留篩選條件的驗證 |
| 文章目錄 | 一般內文章節目錄 | 計畫要求桌面側欄／手機可展開 | 補上桌面定位、手機展開與明顯返回總目錄入口，不影響舊文章 |
| SEO | 沿用 Article | 計畫要求目錄集合頁 | 目錄使用適當的 CollectionPage／ItemList，僅列符合公開條件的項目；分篇保留 Article |

共用重疊檔案包括 API `schemas.py`、`pack_ingest.py`，前端 `content-blocks`、`guides`、文章頁、後台編輯及生活分享入口。2026-09-14 唯讀核對 Claude Code 已結案，PR #485 的共用功能已合併；此工作目錄仍需接入主分支及轉換 Codex 格式。未改動對方工作目錄或傳送任務指令。進入整合實作前，先核對當時任務持有人與最終介面，劃定唯一整合負責範圍，保留兩邊測試。

## 製作順序與驗收門檻

1. **規格與整合契約**：確認本表的 60 個穩定 ID、slug、先備、路線、五語資料及共用區塊格式，形成不破壞舊稿的遷移範例。
2. **五篇代表篇**：深化原 ID 03／10／04／11／23，使用同一模板及待辦網站材料。每篇先核對繁中操作，再完成四語等義內容與圖片驗收。這五篇仍算在 60 篇內。
3. **第一大批**：按閱讀次序 01–20 完成；第 10／20 篇分別檢查。
4. **第二大批**：閱讀次序 21–40；第 30／40 篇分別檢查。
5. **第三大批**：閱讀次序 41–60；第 50／60 篇分別檢查。
6. **整套驗收**：60 篇＋總目錄的五語內容、練習檔、圖片、引用、目錄、舊稿相容及公開狀態測試均有紀錄，才列為可發布。

每篇依序記錄 `planned → drafted → depth-reviewed → example-verified → five-locales-reviewed → preview-accepted`；官方查證與實機驗證另外標記，不能合併。`published` 只能來自正式發布結果。舊 `ready` 不能作為新流程的完成旗標；目前 32 篇一律從 drafted 開始接受新標準審核。

每十篇檢查以下項目，任何一項未過即留在待辦，不以完成檔案數代替品質：

- 讀者能從指定材料獨立完成，概念、命令位置、預期結果、成功與失敗案例齊全。
- 五語步驟、版本／帳號限制、命令與範例產物一致；沒有把日韓文縮成摘要。
- 每篇有先備連結、篇首篇尾返回、正確的閱讀次序及 2–3 篇相關教學；同一節不反覆連同一目標。
- 來源核對與實測分列；操作截圖有環境、版本、日期、替代文字與五語圖說。無法實測的平台用完整官方查證步驟說明，不能以另一平台截圖冒充；缺少關鍵畫面時仍標記待補。
- 360px、390px 與桌面尺寸均可閱讀；程式碼與表格只在自己的容器捲動。
- 搜尋功能名、英文別名、指令、MD 檔名、用途可找到正確專篇；分享／重新整理／返回保留條件。
- 公開、未公開、隱藏、撤回、缺語系與讀取失敗皆有測試；不洩漏未公開正文或產生可點擊空頁。
- 複製保留空白、縮排、引號與特殊字元；後台修改並儲存後仍與公開頁呈現一致。
- API、前端、內容包、範例、圖片及相容性測試通過，保留未執行項目與原因。
