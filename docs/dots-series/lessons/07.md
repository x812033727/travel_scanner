# 第 07 課｜從 Activity 檢視委派：進度、成果與原始環境

這堂課練習從 dot 的主對話走到委派工作，找到結果、等候輸入的要求與實際執行位置。你會用一個虛構場地比較工作，分別在 dot 與工作對話補充資料，最後確認成果真的符合要求，而不只看執行狀態。

:::summary
- 桌面 profile 的 Activity 可開啟委派工作與輸入請求。
- 新工作有自己的背景，接續使用原電腦或雲端環境。
- 開啟成果核對來源，完成狀態不能代替內容驗收。
:::

## 先修條件與可用條件

先完成第 03 課，知道如何說清成果、來源、限制與完成條件。準備下方三個虛構場地資料，這次不查真實訂位、不付款、不寄信。新雲端工作可在桌面、網頁與手機 App 檢視；本機 Codex 工作在已連線的電腦上使用。需要本機資源時須上線並開啟 ChatGPT App。

如果要委派與程式庫相關的雲端 coding 工作，須先在 Codex 建立含程式庫及設定的環境，dot 不會因一句要求就取得任意專案。本課只測比較檔案，不必配置程式環境。Work、Codex 的用量依對應產品規則計算。

## 跟著做：建立並檢視一份比較工作

1. **準備來源與決策條件。** 示範場地甲容納八人、費用五百元；乙容納十二人、費用九百元；丙容納十人、費用七百元，但無障礙動線待確認。活動十人，場地費上限八百元。這些純屬練習資料，不能當成真實場所建議。
2. **要求可見委派工作。** 在 dot 明確說「請建立一個新的雲端 Work 工作」，取名「讀書會場地比較」，附完整來源與限制。dot 可用背景代理或獨立工作處理；這次指定可見工作是為練習 Activity，若環境未提供，應說明而不捏造卡片。
3. **開啟 Activity。** 在桌面 App 開 dot 的 profile，選 Activity，找到相應工作。開啟後看進度、檔案、結果與需要輸入的請求。名字相似時，比對任務描述與來源，別把另一個工作當成此次結果。
4. **檢查委派收到的背景。** 新工作有自己的對話，會收到 dot 為任務提供的指示與背景，但不自動取得你和 dot 的每則歷史。確認它知道十人、八百元與三個場地資料；缺漏時補明確摘要，不要只說「你都知道」。
5. **處理真正的輸入請求。** 如果它問無障礙需求，回答本次需要無障礙動線；如果丙仍待確認，就維持待確認而不猜可用。登入、連線或批准請求要開啟辨認，與本課無關的外部動作不擴大範圍。
6. **直接在工作裡補一個條件。** 把場地預算上限改成一千元，要求工作產出更新版比較表，並說明是否影響推薦。這是在原工作接續，不代表更換執行電腦。保留初版，方便對照。
7. **回 dot 要求協調摘要。** 說明你已在「讀書會場地比較」更新預算，請 dot 檢視該工作結果，列出下一步決定。dot 可檢查與接續它建立的工作，但工作仍使用原始電腦或雲端環境。
8. **開啟成果做驗收。** 比較表需列人數、費用、待確認項與推薦理由。如果產出檔案，實際開啟確認內容；完成 run 不能證明結果已達標，也不表示通知或預約已經完成。

```text 在 dots 對話輸入
請建立新的雲端Work工作，名稱「讀書會場地比較」，用以下虛構資料製作繁中比較表。
活動十人，場地費上限800元，需要無障礙動線。
甲：容納八人，500元，無障礙動線已確認。
乙：容納十二人，900元，無障礙動線已確認。
丙：容納十人，700元，無障礙動線待確認。
只用以上資料，列符合條件、限制、待決問題與建議。
不要查詢訂位、聯絡場地或付款；成果供我審閱。
請告訴我工作連結與執行環境。若無法建立可見工作，請說明原因。
```

## 教學期待結果：看清楚「完成」還缺什麼

第一版期待指出甲人數不足、乙超出預算、丙動線待確認，所以沒有全部條件均已確認的選項。建議可以是先人工確認丙，不能宣稱它已取得場地回覆。預算改為一千元後，乙在示範條件下可以符合需求，丙仍需要動線確認。

這是依虛構來源推導的驗收標準，真實工作卡片、進度、檔案與結果還要由帳號取得。若它推薦甲，表示忽略十人的限制；若它說丙全部符合，表示把未知當成已確認。請針對錯誤欄位修正，不需要重建整個系列。

## 接續練習：在原環境更新同一份成果

```text 在委派工作對話接續更新
接續同一份場地比較：場地費上限改成1000元，其他條件維持。
請儲存第一版，交出新版與差異說明。
不要把丙的無障礙動線改成已確認；仍不聯絡或預約。
若你缺少原始三個場地資料，請告訴我，我會補上摘要。
```

完成後在 dot 再問目前需要我決定什麼，核對它是否引用新預算與原工作。若切換 dot 的選定電腦，已有工作不會自動搬過去。需要換環境時要另行處理，不要把看得到聊天誤認為本機檔案已同步。

## 失敗恢復與停止

找不到工作時，確認是在 dot profile 的 Activity，看名稱與建立時間；如果它只用背景代理，要求說明沒有可見工作。手機看不到本機 Codex 工作，回已連線電腦檢視。原電腦 Offline，恢復網路與 App 後再檢查本機步驟；雲端工作也不能憑空取得未上線的本機檔案。

工作等待輸入，開該工作直接回答；內容方向變了，在原工作說清楚新值。想停止委派，在 Activity 開該工作個別停止；Pause dot 的主工作不等於所有委派停止，Scheduled 的未來排程也要分別處理。停止不回復已完成動作，保留版本與來源便能核對。

## 完成檢查

- [ ] 我能從桌面 Activity 找到指定工作，或明確記錄不可建立。
- [ ] 委派收到完整來源與限制，沒有推定全部歷史可見。
- [ ] 初版與千元新版都有可開啟的成果。
- [ ] dot 協調摘要使用最新條件，待確認項目未被補造成已確認。
- [ ] 我知道原始環境與停止範圍要分別檢查。

## 委派工作位置對照

| 工作型別 | 前提 | 檢視與接續位置 |
| --- | --- | --- |
| 新雲端工作 | 帳號與工具可用 | 桌面、網頁、手機 App |
| 本機 Work 或 Codex | 電腦已連線且線上 | 對應本機工作 |
| 既有本機 Codex | 指定正確工作與目標 | 原已連線電腦 |
| 雲端 coding | 先配置 Codex 環境 | 原程式庫與雲端環境 |

> 操作提醒：改選 dot 的電腦不會搬移已存在的工作；先確認原環境，才能判斷缺資料還是缺連線。
