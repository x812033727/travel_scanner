# 第 08 課｜排程與事件：時區、通知、期限和取消

這堂課建立一個有明確期限的定時檢查，再分清固定時間與事件觸發。你會練習讓 dot 回述儲存內容，在 Scheduled 核對，等待至少一次實際執行，最後修改及取消。成果是可驗證的追蹤，不只是聊天中的承諾。

:::summary
- 定時工作寫清來源、時區、期限、通知條件與目的地。
- 在 Scheduled 核對儲存內容，再以一次實際執行驗收。
- 修改與取消同一項排程；已啟動委派和主工作另行檢查。
:::

## 先修條件與使用條件

先完成第 03 課；若來源使用 Google Drive 或 Slack，先按第 05 課確認連線、資料權限與指定來源。練習使用虛構讀書會，不寄信、不付款、不發團隊訊息。事件監看取決於連線服務支援，須請 dot 確認能監看哪些事件，不能假設 Slack 加入頻道後就已啟動。

示範正式練習期間是 2026-10-05 至 2026-10-09，每個工作日上午九點，Asia/Taipei。若你跟做時日期已過，先換成未來五個工作日，寫明完整日期與時區。實際首次執行驗證可另選帳號允許的近期時間，結束後取消，不能以預估時間或已儲存狀態冒充執行證據。

## 跟著做：建立並驗證定時檢查

1. **先定義檢查來源與動作。** 指定一份已連線的示範準備清單，讓 dot 檢查是否有期限變動或待決問題。首次練習可只讀取與回述；不要混入對外傳送。若來源只能靠手動貼上，就說明排程屆時可用的是哪份資料，而非假設它能自行更新信箱。
2. **寫完整時間與期限。** 指定每天何時、哪些日子、開始與結束日期，以及 Asia/Taipei。不要只說明天早上，因為帳號所在地區、你的意圖與執行環境可能不同。把結束日寫入責任，避免練習永遠繼續。
3. **設定通知條件與目的地。** 指定只有截止日風險、來源不可用或需要你決定時纔在 ChatGPT 通知；沒有變化不傳例行訊息。若要每天收到摘要，也要明確說明，別讓「每天檢查」自動被理解成「每天通知」。
4. **請它確認已儲存內容。** 提交下方提示後，檢查 dot 回述的工作名稱、來源、時間、時區、結束日與通知範圍。若它只是回答可以做，還沒有儲存排程，請它說明實際狀態，不能自行勾完成。
5. **開啟 Scheduled 檢查。** 在 dot 的排程檢視找出對應任務，核對指示、時間與結果目的地。聊天回述與排程資訊若不同，先修正後再驗證，保留變更紀錄。
6. **等待一次真正執行。** 記錄實際執行時間、可取得的來源與成果。若平常沒有變化保持安靜，驗證時請它列出這項排程最近一次實際執行狀態與結果；如果賬戶未提供證據，保留待驗，不把安靜當成功。
7. **修改一次，再重新核對。** 將上午九點改成九點半，通知條件維持。請它確認修改的是同一項排程，Scheduled 中再看時區與結束日是否保留，避免建立重複工作。
8. **取消練習並確認。** 請它取消指定排程，並在 Scheduled 檢視已停用或刪除的狀態。這只處理未來執行；如果已啟動委派，還要到 Activity 檢查與停止，主工作則按其控制處理。

```text 在 dots 對話建立排程
請為「虛構讀書會期限檢查」儲存一項排程。
從2026-10-05到2026-10-09，每個工作日上午09:00，時區Asia/Taipei。
來源只使用：[貼上已驗證可讀取的示範清單連結]。
檢查截止日變更、逾期風險、需要我決定的問題。
只有風險、來源不可用或需要決定時，在ChatGPT通知我；無變化保持安靜。
不寄信、不聯絡其他人、不付款。不要建立重複排程。
請確認實際儲存的時間、時區、結束日期、來源、通知條件與目的地。
若無法建立，請說明原因與哪些內容仍未設定。
```

## 教學期待結果：儲存和執行分開驗收

設定驗收期待排程名稱、來源、工作日上午九點、臺北時區與結束日期都能核對。執行驗收則必須有一次真實執行及可檢查結果；如果來源未連線，應顯示或報告缺少條件，不能用舊摘要說成剛剛讀取。兩種驗收都通過，才把這次練習寫成已驗證。

為了測通知，你可以在實際下次執行前人工調整虛構清單，讓一項練習截止日出現需要決定的變動。記錄修改時間，核對後續結果是從來源取得。沒有收到通知時，檢查通知條件、結果目的地和排程是否真的執行，不要馬上重複建立。

## 接續練習：事件監看與固定排程

```text 在 dots 對話確認事件支援
我想監看已連線的Slack測試頻道：[貼上指定頻道]。
只關注帶有「練習期限變更」的測試訊息，整理變動供我審閱。
先確認這個來源支援哪些事件，以及目前是否能夠建立事件監看。
未確認支援前不要建立；不要對頻道其他人回覆或轉貼私人資訊。
若只能定時檢查，請說明這個差別，再讓我選擇時間與結束日。
```

事件是有新情況時觸發，定時是按儲存的時間檢查，不能把同一個結果當作兩者都已測通。真正支援時，再指定事件範圍、通知對象與結束條件；用一則虛構測試訊息驗證。沒有支援時保留缺口，不聲稱即時。

## 失敗恢復與完成檢查

時間不符，重新寫完整時區並核對儲存值。來源過期，開啟重連請求；本機來源需要電腦線上，不適合假設關機後仍能讀。未收到訊息時，先檢查無變化是否本來應安靜。結束對話、通話或按 Pause，不會取消所有未來排程。取消後確認對應名稱與指示，不停用其他人的任務。

- [ ] 時間、時區、開始與結束日期在回述和Scheduled一致。
- [ ] 通知條件與目的地明確，來源有實際讀取能力。
- [ ] 至少一次執行有記錄與可核對結果。
- [ ] 修改沒有產生重複排程，取消後的未來狀態已確認。
- [ ] 主工作、委派與排程的停止效果分開檢查。

## 追蹤方式與停止對照

| 方式 | 何時繼續 | 如何驗收與結束 |
| --- | --- | --- |
| 已交辦的持續責任 | dot 協調跟進 | 檢查主工作與委派 |
| 固定排程 | 儲存的時間與時區 | Scheduled 核對、修改、取消 |
| 支援事件監看 | 指定來源的事件 | 確認支援、測觸發、結束監看 |
| 已啟動委派 | 原工作繼續 | Activity 個別檢視與停止 |

> 操作提醒：取消未來排程後，還要檢視目前已啟動的工作；「已取消」不能回復先前完成的動作。
