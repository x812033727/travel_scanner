# 第 01 課｜dots 完整介紹：從提問到持續交辦

這堂課先建立產品分工，再讓你挑一件適合交給 dot 的工作。學完後，你應能說明 Chat、ChatGPT Work、Codex 與 dots 各自在什麼情況派上用場，也能寫出一個有來源、有更新條件的持續責任。你不用寫程式，但仍需要確認資料與成果。

:::summary
- Chat 適合討論，Work 與 Codex 提供可檢查的工作成果，能力有重疊。
- dot 協調持續責任，更新時仍要說清新資訊與保留條件。
- 雲端、本機與外掛的來源和權限分別確認。
:::

## 先修條件與使用條件

準備一份不含個資的練習筆記即可；尚未取得 dots 入口也可以先做選題與交辦草稿。實際建立須用桌面 App 或桌面瀏覽器。dots 目前逐步向符合方案、地區、年齡與工作區設定的帳號推出，資格細節在第 02 課核對。功能可見與帳號能做的操作，以目前環境為準。

## 先理解四種使用方式

Chat 適合提問、解釋、比較與短稿；Work 適合完成可以檢查的檔案、分析或工作流程；Codex 提供開發視角與技術細節，常用於程式修改、測試與檢視差異。Work 和 Codex 有重疊能力，所以不能把它們理解成一個只能寫文章、一個只能寫程式。

dot 則著重持續責任：你交辦一件需要追蹤的工作，之後補上新資料與優先順序，它會接續協調。它能使用背景代理、建立可見工作，或把部分工作交給 Work、Codex。你仍可以同時和它談事情，也需要回應重要決定與授權要求。

用讀書會來比較：問「如何主持討論」可以先用 Chat；想把材料做成一頁議程，可用 Work；報名網站的表單壞了，開發者會用 Codex 查問題；想持續追蹤準備、期限與參與人數，則可把這份責任交給 dot。這是編輯上的選用例子，不是四個產品互斥的功能表。

## 跟著做：找出第一份持續責任

1. **挑一件會變動的工作。** 寫下你每週要重新確認的事情，例如讀書會準備、課程進度或專案待辦。選你能提供資料、也能判斷好壞的範圍，第一次先避開付款、公開發布與跨多人帳號的複雜流程。
2. **把責任說成結果。** 「幫我留意活動」太模糊；改成「維持一份準備清單，列截止日、未確認專案與需要我決定的事」。結果應能開啟、逐項核對，也能在資料變化後重新檢查。
3. **列出允許使用的來源。** 可以是貼上的虛構摘要、上傳檔案或已連線外掛。來源不在同一個地方時，給出確切檔案與範圍。不要假設說出「信箱」兩個字就已取得郵件存取。
4. **決定何時需要你。** 例行整理可以留在清單；預算超出、截止日改變或缺少決定時才通知。第一次先寫通知條件，尚不建立排程。固定時間和支援的事件監看會在第 08 課設定。
5. **辨認工作環境。** dot 有自己的雲端電腦和瀏覽器，本機離線仍可做不依賴本機資源的雲端工作。如果需要電腦上的檔案，必須另行連線並保持電腦上線、ChatGPT App 開啟。你個人瀏覽器登入，不代表雲端也登入。
6. **準備驗收方式。** 列出原始資料的三個關鍵值，例如日期、人數、預算；再列成果必須包含的欄位。收到結果後逐條比對。工作完成狀態、回覆流暢或漂亮圖表，都不能代替內容核對。
7. **寫下接續更新指令。** 讓新資料明確指向既有責任：「接續讀書會準備，人數改成八人，預算維持原定。」這樣你能保留原目標，逐次修正受影響部分。

```text 在 dots 對話輸入
我想把「每週整理虛構讀書會準備事項」交給你持續協助。
目前先幫我界定工作，不要建立排程或連線新工具。
成果是一份繁中清單：事項、截止日、狀態、待決問題。
來源先以我貼上的資料為準，未知事項請標示待確認。
當預算或期限需要我決定時，請在ChatGPT問我；例行整理保留在清單。
請回述這份責任，列出開始前缺少的資料，以及我應如何驗收結果。
```

## 教學期待結果：一份可交辦的責任說明

期待 dot 回述成果、來源、更新範圍與需要你介入的條件，並列出尚缺活動日期、參與人數或負責人等資料。它應清楚說目前只是界定工作，不把排程或外部連線說成已完成。這裡描述的是教學期待，真正回覆與紀錄要由帳號操作取得。

你可以自己先寫一張責任卡：追蹤什麼、用哪些資料、什麼改變需要通知、誰決定對外動作。每項用一句話，便能檢查工作是否太大。若一張卡同時要求訂票、付款、寫網站與管理信箱，就拆成可分別驗收的責任；關聯資料仍可以告訴同一個 dot。

## 接續練習：換資料而保留目標

把「讀書會」換成你的七日學習計畫，但只修改來源與成果欄位。你是否仍能說清每天完成什麼、哪些進度變更要通知、何時結束追蹤？再挑一個一次性任務，例如解釋一個術語，思考它是否只需要 Chat 就足夠。這能幫你按工作需求選工具。

下一步若真的建立 dot，先在第 02 課確認入口與連線，再在第 03 課提交小範圍工作。重要資料變動時，以明確版本或日期說清楚，避免只寫「用最新的」而沒有指定來源。

## 常見誤解與恢復方法

「一直線上」不代表所有工具都不需要你的電腦；本機步驟仍需要可用連線。「記得我的背景」不代表記錄每句話，也不代表能讀所有聊天。「已連線 Slack」不代表已啟動頻道監看，更不代表可以把私人資訊分享給團隊。遇到不清楚的宣稱，請它列出可用來源與缺口。

dot 對話與它啟動的 Work、Codex 工作，使用限制計算方式不同，不能把對話額度說明延伸成所有深度工作無限。離開聊天或結束通話，也不一定終止已交辦的工作。需要停止時，要分別檢查主工作、委派與排程；第 10 課會用三個控制示範。

## 選用方式對照

| 工作需要 | 優先使用方式 | 你仍要檢查 |
| --- | --- | --- |
| 解釋術語、討論主持方式 | Chat | 說明是否符合情境 |
| 做成議程或比較檔案 | ChatGPT Work | 檔案內容與來源 |
| 查程式問題與測試修改 | Codex | 差異、測試與風險 |
| 接續追蹤準備與新決定 | dot | 責任範圍與更新成果 |

> 操作提醒：第一份責任先選你能提供完整來源的小工作；收到回述後，先補缺少資料，再擴大範圍。
