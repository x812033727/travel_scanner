# 第 03 課｜第一次交辦：讓 dot 交出可以檢查的成果

這堂課把「幫我準備一下」改寫成能交付、能修正的工作。你會用虛構讀書會資料交辦一份準備清單，檢查資料是否忠實，再加入人數變動接續更新。練習重點是把目標、來源、限制與完成條件說完整，並能回到工作裡檢視結果。

:::summary
- 第一次交辦寫完整成果、來源、限制與完成條件。
- 用日期、人數與預算核對清單，再加入一次資料更新。
- 執行結束、草稿正確與正式傳送分別驗收。
:::

## 先修條件與使用條件

先完成第 02 課，能在桌面開啟自己的 dot。準備下面的虛構資料；不需要郵件外掛、付款、對外傳送或本機存取。若 dot 分派 Work 或 Codex 工作，那些工作仍計入對應產品的使用限制。是否分派、使用何種工具與執行速度，須看帳號能力與當下任務，這堂課不保證每次產生獨立聊天。

第一次交辦建議用小範圍成果：一頁清單、三個待決事項、來源可以逐條核對。不要直接要求它整理整間公司的所有檔案，因為你很難判斷漏掉的是資料、授權，還是理解差異。先用可驗收的範圍建立合作方式，再擴大工作。

## 跟著做：交辦讀書會準備清單

1. **把成果寫成可檢查的清單。** 開啟同一個 dot 的對話，指定「一份繁中準備清單」，而不是只寫「協助活動」。清單至少包含事項、負責人、截止日、狀態與仍需決定的問題。這些是你提出的欄位需求，不是產品的固定資料格式。
2. **提供完整示範資料。** 貼上日期、人數、預算、場地與各人的責任。虛構資料寫明是練習；未知的事情寫「待確認」，不要留一個空白讓它猜。這次不連線其他工具，要求只用貼上的內容，方便驗證來源。
3. **界定動作範圍。** 清楚寫目前要整理與擬稿，通知他人、訂場地與付款都留待你決定。交辦草稿不等於授權傳送；日後若真的要送出，需提供具體收件對象與內容，並依權限和審核處理。這樣 dot 就知道成果應停在什麼階段。
4. **加入完成條件。** 要求缺資料時標示、日期寫完整、預算不得自行增加，最後提供核對清單。你不用替它指定每個內部步驟，但要讓它知道什麼結果纔算可交付。貼上下方完整提示詞，送出後讀它的理解與追問。
5. **只補真正缺少的決定。** 如果它問活動時間，補「晚上七點到九點，Asia/Taipei」。如果它提出場地未知，確認原資料已寫校園討論室，請它修正。追問中若包含你未要求的外部動作，回覆維持草稿範圍；不要因為要快速完成而放寬全部權限。
6. **檢視進度與成果。** 桌面 App 開啟 dot 的 profile，再選 Activity。若有委派工作，開啟該工作檢視進度、檔案、結果或請求輸入。如果結果直接留在對話，仍要逐欄檢查。工作執行結束只是狀態，不代表清單正確或已交付給參與人。
7. **用新資訊接續更新。** 保留第一版，再送出人數由六人改為八人的更新指示。請它只調整受影響部分並列差異；觀察它是否延續原本預算上限、截止日與草稿範圍。最後請它提供新版與尚未解決的問題。

```text 在 dots 對話輸入
請協助我追蹤一場虛構讀書會，先交出準備清單供我審閱。
資料如下：2026-10-17 19:00–21:00，時區 Asia/Taipei。
六名參與人，地點為校園討論室，總預算上限新臺幣1200元。
小安負責選讀內容，截止2026-10-10；小晴負責茶水，截止2026-10-15。
我負責確認場地，截止2026-10-09。目前場地預約狀態待確認。
只使用以上資料。清單列事項、負責人、截止日、狀態、待決問題。
另外擬一段100字內的活動提醒，留在這裡供我修改。
不要聯絡其他人、訂位、付款或建立排程。
缺少資料請標示待確認，不能自行推定已完成。
完成時列出你採用的限制及我下一步需要決定的事。
```

## 教學期待結果：用來源驗收第一版

期待清單忠實列出三個責任與截止日，場地狀態維持待確認。茶水經費若未分配，就應列待決事項；不能假設六人每人兩百元已付清。提醒草稿應含正確日期與地點，也應說明場地尚在確認。這些是教學驗收標準，並非我們已在真實帳號取得的結果。

檢查時先看是否漏項，再看有沒有增添不存在的事實。你可以用三個問題驗收：資料從哪裡來？目前做了什麼？哪個動作仍需要我決定？若產出檔案，實際開啟檔案確認文字；不要只看到檔名就勾完成。如果出現錯誤報告，先讀原因，必要時縮小範圍重做受影響部分。

## 接續練習：人數增加時保留原限制

```text 在 dots 對話接續更新
接續剛才的讀書會準備工作：參與人數改成八人，預算仍是1200元。
場地已由我人工確認可容納八人，請把場地狀態改成已確認。
日期與各人的截止日維持原定。茶水分配仍待我決定。
更新清單與提醒草稿，列出本次改變的欄位。
先不要傳送或建立排程，請提醒我哪些待決事項尚未完成。
```

期待新版把人數與場地狀態改對，不把預算提高，也不宣稱它親自查到場地確認。來源是你提供的人工確認，這個差別應留在工作說明中。若新版本連前次日期也改了，要求它依原始資料回復並再列一次差異。

## 卡住時怎麼恢復

它讀不到資料時，先確認你確實貼進同一段工作；外掛未連線時則改用練習摘要。出現登入或批准請求，開啟請求判斷是否屬於此課，無關動作就改寫範圍。Activity 中的工作等候輸入，開工作補資料，比在另一段聊天只說「繼續」更容易指向正確任務。

想中止時，Pause 處理 dot 的主工作；已委派的工作要在 Activity 個別停止，排程在 Scheduled 個別取消。這堂課刻意沒建立排程，但你仍要知道三種停止效果不同。已完成的動作不會因停止而回復，整理清單時保留版本便能追查改動。

## 完成檢查

- [ ] 提示詞同時寫出成果、來源、限制與完成條件。
- [ ] 第一版三個責任、日期與待確認事項都能對回原資料。
- [ ] 我能找到結果或委派工作的 Activity 記錄。
- [ ] 八人版本保留1200元上限，並列出更新差異。
- [ ] 草稿仍在審閱階段，沒有把 run completed 當成已傳送。
