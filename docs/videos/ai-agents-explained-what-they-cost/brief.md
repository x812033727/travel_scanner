# AI 代理到底是什麼、跑一次要花多少錢，以及那個能阻止它亂花錢的設定

## 觀眾

每天聽到「AI 代理」「agent」「自動化」，但分不清它跟一般聊天差在哪、為什麼有人說它很貴、要委託工程師或外包時該問什麼的人。搜尋「what is an AI agent」「AI agent cost」「OpenAI Agents API pricing」「how much does an AI agent cost to run」。英文市場為主。

## 觀眾看完能做到的事

1. 用一句話分辨眼前的東西是「聊天回答」「固定流程」還是「真正的代理」：代理是模型自己決定下一步、自己選工具，不是照寫死的步驟走。
2. 估一個代理任務的花費：知道它會為一件工作呼叫模型好幾次、每次都把整段歷史重新讀一遍，所以帳單不是「一次的價錢」；委託前先問清楚權限、紀錄、怎麼喊停、預算上限。

## 站主觀點

套用立場：1、5、6
代理不是越自主越好，是越能被你驗收越好。我的做法是把兩件事分開：模型決定它多聰明，框架決定它怎麼保存進度、用工具、分工，兩者都不等於「可以安全交給它」。花錢那一段要老實講：OpenAI 自己的文件都寫「一件任務會呼叫模型好幾次、重複處理很長的歷史」，所以總價很難只看任務名稱估，先用真實資料試跑一週、記下實際費用，再決定要不要放大。每支影片都給觀眾一個能當場做的動作：這支是「先從唯讀、能回查的工作開始，會改資料的動作留人工確認」。

## 示範或實算

第 4 章的 `table` 用 2026-09-28 的 GPT-6 Sol 短脈絡牌價（輸入每百萬 2 美元、輸出每百萬 10 美元），實算一個代理任務為什麼比一次問答貴。假設一個「整理本週客戶意見並產出報告」的代理跑 5 輪，每一輪都把先前的對話與工具結果重新讀進去（數字為示意，用來說明結構，不是任一產品的實測）：

| 輪次 | 這一輪的輸入 token（累積歷史） | 這一輪的輸出 token | 這一輪費用（美元） |
| --- | --- | --- | --- |
| 1 | 20,000 | 2,000 | 0.06 |
| 2 | 45,000 | 2,500 | 0.115 |
| 3 | 75,000 | 3,000 | 0.18 |
| 4 | 110,000 | 3,000 | 0.25 |
| 5 | 150,000 | 4,000 | 0.34 |
| 合計 | 400,000 | 14,500 | 0.945 |

同一份工作用「一次問答」只算一輪，大約 0.06 美元；做成會自己接續、會呼叫工具的代理，因為每輪重讀歷史，變成約 0.95 美元，差約 16 倍。第 4 章的 `big` 放「0.06 → 0.95」，sub「同一件事，一次問答 vs 五輪代理」。再放一張 `bullets`：如果它還開了子代理，子代理各自也會這樣算一遍。這說明的是 OpenAI 文件講的「呼叫好幾次、重複處理很長歷史」，不是宣稱任何產品的真實帳單。

## 大綱

### 選項 A：三分鐘看懂代理，順便算清楚它多貴（推薦）
一行說明：先用一個生活例子分出聊天、固定流程、代理，再實算費用結構，最後給委託時的四個問題；和 B 的差別是以「花多少錢」為主線，和 C 的差別是不談你要不要自己寫。
開場鉤子：「大家都在說 AI 代理。但同一件事，做成代理可能比你直接問，貴上十幾倍。這支影片告訴你貴在哪，還有哪個設定能讓它不亂花你的錢。」
章節（估計秒數，合計約 560 秒）：
1. 代理跟聊天差在哪（80 秒）
   - title: 「AI 代理是什麼、跑一次多少錢？」，副標「模型決定下一步，就是代理」
   - compare: 左「聊天回答／固定流程」，右「代理：自己決定先做什麼、用哪個工具」
   - chat: 觀眾問「幫我整理報名資料」，示意代理先讀欄位、發現同名不一定同人、改用允許的欄位比對
2. 一個代理是哪些東西組成的（90 秒）
   - steps: 模型 → 指示 → 工具 → 執行環境（沙箱）
   - bullets: 說「我已更新」不等於真的做了，要看實際結果；沒有工具或授權，它什麼都改不了
3. 為什麼會這麼貴：每輪都重讀歷史（120 秒）
   - bullets: 一件任務呼叫模型好幾次；每次輸入含指示、工具定義、對話紀錄、工具結果
   - big: 「0.06 → 0.95」，sub「同一件事，一次問答 vs 五輪代理（示意）」
   - stats: 子代理各自再算一遍；工作階段的用量數字是盡力記錄、可能是空值、不是最後帳單
4. 實算：五輪代理的帳單（150 秒）
   - table: 上面的五輪表，逐列出現
   - quote: OpenAI 文件「代理完成一個任務時可能呼叫模型好幾次」與翻譯
   - cta: 說明欄第一行的站內文章
5. 委託前先問的四件事＋一個能救命的設定（80 秒）
   - steps: 權限（能讀寫什麼）→ 紀錄（誰能看、留多久）→ 停止（誰能喊停、怎麼喊）→ 預算（試跑費用、每月上限）
   - big: 「預算上限」，kicker「跑錯時唯一能自動擋住費用的東西」
6. 一句話答案（40 秒）
   - outro: 「先從唯讀、能回查的工作開始」；下一步：站內文章
實算放第 4 章。結尾的下一步：站內文章〈AI 代理（AI Agent）是什麼：從回答問題到完成任務〉。

### 選項 B：委託工程師做自動化前，先看懂這四個問題
一行說明：以「要外包一個自動化」為情境，用 OpenAI Agents API 文件的原則講權限、紀錄、停止、預算，資料落地與零資料保留當合規提醒；和 A 的差別是給決策者，不解釋 token。
開場鉤子：「有人要幫你做一個 AI 代理，自動處理工作。簽約前，這四個問題能幫你省下開發到一半才發現不能上線的錢。」
章節（估計秒數，合計約 555 秒）：
1. 你買的到底是什麼（70 秒）：title；compare 模型 vs 框架
2. 權限：它能碰哪些資料（100 秒）：bullets 唯讀分析代理 vs 會改資料先請求核准的代理；steps 從唯讀開始

### 選項 C：代理做錯事的三種樣子，以及怎麼驗收
一行說明：以「代理不可靠」為主線，用報名資料的例子講錯誤怎麼一步步傳下去、外部文字為什麼要當資料不是指令、停在待確認為什麼是對的；和 A、B 的差別是重點在驗收而非費用。
開場鉤子：「AI 代理最危險的地方，不是它很笨，是它把第一步的錯，當成後面每一步的根據。」
章節（估計秒數，合計約 550 秒）：
1. 自主程度不等於可靠程度（70 秒）：title；big 多步驟會放大錯誤
2. 錯誤怎麼傳（110 秒）：steps 誤讀欄位 → 去重 → 統計全錯；chat 示意
3. 外部文字是資料，不是指令（100 秒）：bullets 報名備註裡的文字不能改變它的權限；quote
4. 把交辦寫成可驗收的任務（150 秒）：steps 目標、輸入範圍、交付形式、完成標準；table 驗收抽查
5. 停在待確認是對的（80 秒）：compare 擅自合併 vs 交出疑點清單
6. 答案（40 秒）：outro
驗收示範放第 4 章。結尾的下一步：站內文章〈AI 代理（AI Agent）是什麼：從回答問題到完成任務〉。
