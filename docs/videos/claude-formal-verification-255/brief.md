## 示範或實算

製作路線：教學卡片。**概念實算，非AI產品安裝／付費服務教學。** 核心主角是一份逐步寫完整的「程式保證紀錄」；兩個獨立程式用同一n=0..255域，255是共同反例。主要成果是寫規格、改程式、看完整結果；不能把我們自己設計的教學碼當成Claude受測輸出或真實漏洞發現。

### 前提先上卡

1. 第一程式的**輸入型別8bit**與**資料容量8byte**分開：n是0..255的payload長度；容量為8byte，還需1byte結尾。8bit不是8byte。
2. 第一程式只執行guard，不寫buffer；本地結果只支持guard行為符合契約，沒有實際越界寫入或完整應用安全認證。
3. 第二程式重新開始，以固定n與本地計數器i檢查返回。**不是**修好guard仍放行255再卡迴圈：正確guard原本就會拒絕255。
4. 本地方法各自標名：GCC實際執行、SymPy命題SAT、有限控制狀態探索。沒有SMT、Rocq／Lean checker，也沒有vendor proof reproduction。

### 不用這個方法：簡單做法的同輸入對照

普通計算機可算出255+1=256；一般測試也能完整列舉本片這個小域。**在這裡，命題SAT沒有提供完整枚舉做不到的答案，本片不販售它比計算機更聰明。** 真正已觀察的差異，是原先五個小樣例都過，而同一程式的完整域暴露255；再把應接受條件加進去，一律拒絕也會失敗。

觀眾寫出條件、修改兩個型別位置並對回完整輸出，才是教學成果；拿現成包只按一次run不是全部成果。官方大規模研究如何處理遠大於此小域的命題，是CITED背景，不能借本地小例子宣稱我們量到研究的成本或覆蓋率。
