## 觀眾看完能做到的事

1. **用一句講清目的的要求，讓 Claude Code 在講座資料夾裡把亂掉的報名表整理成「可以直接寄確認信的名單」「要補資料的名單」和一份處理日誌，原始檔一個字都沒動。** 對象：`講座籌備/報名表.csv`（24 列，有缺 Email、同名不同人、同一人填兩次、取消、測試資料、部門寫法五花八門）。怎麼知道做對了：照日誌與輸出逐項對十項檢查（兩個不同的王志明都在、陳怡君只出現一次、取消的張書豪與「測試」不在、補上 Email 的林佳蓉在、三個缺資料的人另外列出、部門統一、寄信名單 16 人、有日誌、原檔雜湊不變）；同一份資料貼進只有文字的對話，拿不到任何一個檔。證明：示範 R4（p1）對 R2（c2）、R3（n1）。級別：跑過（待第 R2–R4 項，各 1 次）。更高一級（看過）是桌面版 Code 分頁裡的同一件事，這裡不能登入，不列。
2. **自己寫一份十二行的 CLAUDE.md，放進講座資料夾，之後只說「幫我整理報名名單」它也照你的規矩做；再把其中一條改成自己的情況、重跑一次確認。** 對象：`講座籌備/CLAUDE.md`（全文上卡片，見「示範或實算」）。怎麼知道做對了：同一句只有八個字的要求，在沒有 CLAUDE.md、規則只寫一句「名單要整理乾淨」、規則寫清楚的三個資料夾各跑一次，用同一支計分腳本比十項檢查過了幾項；寫清楚的那一份要比沒有的多過三項以上。改一行：觀眾把「同名不一定同一人：Email 不同就是兩個人」換成自己名單的判斷方式；片中改的是把模糊的那一句換成具體的那幾句（v1 → s1），兩次都跑。證明：示範 R3（n1）、R6（s1）、R7（v1）。級別：跑過（待第 R3、R6、R7 項，各 1 次）。
3. **改檔名、搬檔案之前，先用規劃模式讓它說出打算怎麼做，看過沒問題再切到「自動接受編輯」放手。** 對象：資料夾裡的「最終版／真的最終版／這次絕對最終版」三份簡報大綱。怎麼知道做對了：規劃模式那一次，資料夾每個檔的雜湊前後一樣，回覆裡寫出它認為哪一份最新、為什麼；手動模式那一次，每個要動檔案的動作都停在等人同意（片中說成「需要人點頭幾次」）；自動接受編輯那一次，檔案真的搬了，`versions.mjs` 從內容認出它改名的是哪一份，跟規劃裡說的一致。證明：示範 R8（pl1）、R9（m1）、R10（a1）。級別：跑過（待第 R8–R10 項，各 1 次）。
4. **把每週都要做的「新報名表檢查」寫成一個 Skill，用 `/signup-check` 叫它處理第二批報名表。** 對象：`.claude/skills/signup-check/SKILL.md`（十八行，全文上兩張卡）與 `報名表_第二批.csv`（6 列）。怎麼知道做對了：session 開頭的技能清單裡有 `signup-check`；第二批的兩個新人加進寄信名單、重填一次的王志明沒有重複、測試資料不在、缺 Email 的宋柏均列進要補資料，寄信名單共 18 個不同的 Email（`batch2.mjs` 六項）。證明：示範 R11（k1）；R12（k2）看不打斜線、只說「照平常的方式檢查」時它會不會自己挑這個 Skill。級別：跑過（待第 R11、R12 項，各 1 次）。

這四件以外：上下文那一章的「寫進度檔、開新對話接著做」有一組實跑（R13–R14c），是基本功的一部分、不單列成果；連接器（MCP）與排程只引官方頁，是「留下來」的步驟，卡片標明；排程要跑的那一句指令本身實跑一次（R15）。

## 站主觀點

（提案，待站主選大綱時確認或改寫。這次的發動訊息沒有附頻道立場的原文，所以不寫「套用立場」那一行，也不沿用舊企劃的點號。）

1. 讓 AI 動我的檔案之前，我要先看它打算怎麼做。新的資料夾、新的要求，我先用規劃模式；看過一次、知道它會怎麼做，再切到自動接受編輯。
2. 交代目的比交代動作有用。「幫我整理名單」跟「幫我整理一份等一下要寄確認信的名單」是兩件事，後面那句它才知道哪些人不該寄。
3. 原始檔只讀不改，成果另放一個資料夾，每做一件事留一份處理日誌。我驗收的是日誌和檔案，不是它在對話裡說「已完成」。
4. 每次都要講的規矩寫進 CLAUDE.md，偶爾才做的整套步驟寫成 Skill；兩邊都寫短，寫具體，寫得出「怎麼算做對」的才寫。

依據：官方 permission-modes 頁（規劃模式「edits stay blocked until you approve the plan」；acceptEdits 自動放行 `mkdir`、`mv`、`cp` 等）、desktop 頁（Best practice：複雜的工作先開 Plan，核准後再切 Accept edits 或 Manual）、memory 頁（CLAUDE.md 每次 session 都載入、建議每份 200 行以內、寫得越具體越短越照做）、skills 頁（Skill 的內文用到才載入；一直重貼同一段指示就做成 Skill）。第 3 點的「驗收看檔案不看它說的」是這支片的計分方法本身（`score.mjs`、`versions.mjs` 從檔案判定，不讀回覆）。

### 不用這個方法：…

- **名單**：不用 Claude Code，觀眾今天的做法是**一句普通的提示**：把 `報名表.csv` 的內容貼進 ChatGPT 或 Claude 網頁版，請它整理。網頁版本身這裡不能登入、不能跑，是引用；這支片用「同一個模型、只給貼上的文字、不給任何工具、在空資料夾裡」跑兩次代替（R1 c1 用模糊的那句、R2 c2 用講清目的的那句，`--tools ""`），卡片標「同一模型、只有貼上的文字（不是網頁版本身）」。預期差別（等紀錄確認）：只有文字的那一邊拿不到任何檔案（寄信名單、要補資料、日誌都要觀眾自己複製、存檔、命名），而且看不到活動說明，所以不知道「取消的不寄」「11/01 前要給場地餐點數」這兩件寫在另一個檔裡的事；資料夾那一邊三個檔直接寫進 `輸出/`，原檔雜湊不變。量得出來的是：檔案數、十項檢查過幾項、它有沒有提到 11/01 的期限。網頁版的「專案」功能可以放常駐指示、也可以上傳多個檔，這一點在片中照實說一句，差別仍是「寫不回你的資料夾、看不到修改時間、改不了檔名」。
- **三份最終版**：觀眾今天的做法是**看一眼資料夾**，照修改時間排，最新的就是最終版。這個做法在這個資料夾會選錯：修改時間最新的是「這次絕對最終版」，內容卻是舊的（16:00、講者待確認、沒有 Q&A）；跟活動說明對得上的是 10/18 的「真的最終版」。M3 用 `ls -lt` 把這個排序記進紀錄（不呼叫模型）。Claude Code 那一邊（R8、R10）讀內容、對活動說明，它選哪一份照紀錄講；選錯了，那就是規劃模式抓到的那一刻，CLAUDE.md 的第七、八行就是為它寫的（R10b a2 驗證）。
- **CLAUDE.md**：觀眾今天的做法是每次把規矩重打一遍（R4 p1 那句講清目的的長要求）。比較的是同一句八個字的短要求，有沒有 CLAUDE.md（R3 對 R6），不是跟「什麼都沒做」比；R4 是「每次都打長要求」那一臂，R6 要接近它才算 CLAUDE.md 省下了那段話。
- **Skill**：觀眾今天的做法是把同一段步驟留在 CLAUDE.md，或每次貼一遍。這支片不量兩者的脈絡成本（〈Skills 對 CLAUDE.md〉那支量過），只示範「寫一份、用斜線叫、第二批照樣做對」；選擇規則引 skills 頁：「一直重貼同一段指示、或 CLAUDE.md 的一段已經長成一套流程，就做成 Skill」。

### 猜不到的結果（企劃時的候選，照紀錄定案）

1. **看一眼資料夾就會選錯最終版**（M3，不呼叫模型，一定成立）：名字最「最終」、修改時間最新的那一份，是舊的。這是例子自己的狀態，不是操作的人手滑。
2. **同一句「幫我整理報名名單」**（R3 n1，沒有 CLAUDE.md）：預期至少有一項觀眾沒想到的處理，例如把兩個不同的王志明當成一個人刪掉、直接改寫原始的 `報名表.csv`、把取消的人留在名單裡、沒有任何日誌。哪一項，照紀錄。
3. **規則只寫一句「名單要整理乾淨」**（R7 v1）跟沒有規則（R3 n1）分數差不多。
4. **Claude Code 自己挑最終版**（R8、R10）：照修改時間挑（錯）或照內容挑（對），兩種都能教；前者是規劃模式的用處，後者是「它讀了內容」的證據。
開場或主例的轉折用證據最強的那一個：R3 有失敗就用 R3（選項 B 的開場），沒有就用第 1 項＋R8／R10 當實戰章的轉折（選項 A）。R3、R7、R8、R10 全部「照預期做對」時，第 1 項仍成立（簡單做法失敗、主題做對），但要在報告裡寫明主題那一邊沒有意外。

## 大綱

三個選項的例子、執行與四件成果都一樣，差在順序與開場。長度以每分鐘 250 字估；三個都在 14–16 分鐘之間，超過 12 分鐘的目標上緣是因為四個基本功加實戰加進階，一章都不能拿掉（發動訊息允許）。三個的卡片順序都跟前六支不同：前六支多從 `terminal`、`code` 或 `stats` 開場，這一支從 `chat` 的那個天真問題開場，`terminal` 卡一張都不用（觀眾不開終端機；實跑的出處寫在卡片的來源欄：「實跑 2026-10-2x｜Claude Code 2.1.295，無介面 session」）。

### 選項 A：照新手會問的順序，四個基本功每一個都在講座資料夾裡發生，再實戰、進階、家教（推薦）
