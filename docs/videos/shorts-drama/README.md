# Shorts 零台詞短劇的共用區

這整個資料夾與 [`../lessons/shorts.md`](../lessons/shorts.md) 會由 [`../rules-sync/`](../rules-sync/README.md) 每小時自動同步到雲端硬碟 `AI/備份/AI劇/_共用規則/`、`AI劇/Shorts/_規則與教訓/` 與各系列的 `_規則與教訓/`。**正本只有這份 repo**，改規則或補教訓一律改在 repo。

## 所有零台詞 Shorts 統一的規格（站主定案）

四個系列與未來新增的無語音 Shorts 系列，一律遵守以下統一規格。個別系列有特殊例外時，寫在該系列的 `series/<slug>.md`。

| 項目 | 統一規格 | 為什麼（實戰依據） |
| --- | --- | --- |
| **零台詞、零字卡** | 整集沒有任何角色對白、旁白、內心獨白或畫面文字卡；只有背景配樂與物理音效，**關靜音也 100% 看得懂** | 2026-11-03 試做有內心獨白的職場短劇時，評審與站主都覺得靠台詞撐笑點太慢且有語言門檻；改成純視覺因果＋物理音效後，1 支成片可直接配 8 語系標題說明吃全球流量 |
| **片長與鏡數** | 成片 **11–16 秒**（硬範圍 **9–20 秒**），每集 **5–7 鏡**；每鏡買 5 秒 H3 片段，剪進成片取 **0.6–3.0 秒**最穩的段落 | 2025–2026 Shorts 完播與重播數據顯示 11–16 秒最容易在觀眾看懂結尾反轉時自動重播回第 1 格（衝出 >100% 留存）；超過 20 秒單一視覺梗會疲乏 |
| **畫幅與音畫技術** | `1080×1920`（9:16 直式，Colab H3 以 `736×1312` 生成後放大）、`30 fps`、`48 kHz` 雙聲道、整體響度 **`-14 ± 1 LUFS`**（真峰值 `≤ -0.8 dBTP`） | 對齊 `qa_check.py` 與後台 Shorts 品管 `profile`／`loudness` 標準 |
| **畫風與世界觀** | 寫實 AI（真實毛髮與動物外觀），動物像人一樣雙足站立、穿固定服裝過日子；**世界裡完全沒有人類**（包含背景路人、人類手指與手臂） | 角色一旦混入人手或背景人影，一般觀眾第一眼就會覺得怪異出戲（2026-11-04 第一輪審片抓出最多的高嚴重度問題） |
| **鏡位鐵律** | **一鏡一主角（單人框）**、**80% 鎖定機位（`locked`）**。對手戲一律拆正反打；需要交代同場時，另一人只露畫面邊緣的一隻毛爪、一角衣服或背影 | 9:16 橫向窄，雙人同框或「畫外一隻手伸進來」極易讓 H3 畫出多一隻手或角色分身；固定機位最能凸顯前後狀態的喜劇反差 |
| **五拍節奏鐵律** | ① 鉤子 `≤ 1.2s`（第一格已在事件中）→ ② 停頓反應 `0.6–1.5s` → ③ **跳過過程，硬切給誇張結果** `2.2–3.0s` → ④ 升級／破綻 `1.5–2.2s` → ⑤ 結尾反轉＋定格 `hold: 0.5–0.9s` | 2026-11-04 第一版有 10 集笑點盲審沒過，全是因為開頭鋪陳太長（4.6 秒）、反應呆滯（3 秒）、揭曉後沒停頓；按五拍重剪後 20 集全數過關 |
| **聲音與留白** | 轉折與結尾打點處必設 **`music_off: True`（瞬間抽掉背景音樂）**，搭配具體物理音效；**收尾音效必須排在最後一鏡結束前** | 第一版有 4 支片的收尾音效排在最後一鏡結束後，成片直接被切掉沒播出；抽掉 BGM 加定格能讓笑點力道翻倍 |
| **八語上架** | 零台詞無需配音與翻譯字幕；`youtube-meta` 一次產出繁中＋8 語系（`en,ja,ko,es,pt,id,vi,th`）標題與說明欄；皆標示 AI 生成（`synthetic_media: true`） | 標題寫「情境鉤子」不寫「結局答案」；封面選反轉前或誇張結果最強的那一格 |

## 一集零台詞 Shorts 從頭到尾：每一關看哪份文件

| 階段 | 做什麼 | 看哪裡 | 過關條件 |
| --- | --- | --- | --- |
| **1. 企劃與選題** | 寫一句話前提（誰、在哪、做什麼、出什麼錯、最後怎麼反轉）與五拍節拍表；新系列先做 3 支試片 | [`WRITING.md` §一](WRITING.md)、`.agents/skills/producer/references/micro-drama.md` | 一句話說得清楚、關靜音看得懂、符合系列固定笑點機制 |
| **2. 審劇本與分鏡（三道檢查）** | 把點子寫成 5–7 鏡分鏡表與英文 `ff`（首格）／`clip`（片段）提示詞；跑寫稿自檢與**獨立審稿代理**檢查 | [`WRITING.md` §二～§六](WRITING.md) | 零雙人碰觸、零人手陷阱、鉤子 `≤ 1.2s`、結果用 `himself/herself` 靜態造型描述、獨立審稿零高風險項 |
| **3. 角色定妝照與首格** | 沿用系列鎖定的定妝照（平靜、閉嘴、無道具）當參考圖，畫每一鏡首格（`colab/ff/`） | 各系列 [`series/<slug>.md`](series/)、[`REVIEW.md` §1](REVIEW.md) | 首格先驗有沒有人手、背景人影、文字 logo 或多出真物件；首格不對當場重畫，不送 H3 |
| **4. 片段生成與剪接** | Colab H3 生 5 秒直式片段（`736×1312`），用 `edit.py`／`recut.py` 剪取精華段、加音效、`hold` 定格與 `music_off` | [`WRITING.md` §三](WRITING.md)、[`REVIEW.md` §2](REVIEW.md) | 避開 5 秒片段後半的硬切與變臉；收尾音效落在鏡內 |
| **5. 成片四道品管與笑點審核** | 跑 `qa_check.py` 出檢查圖 → 獨立審片人查畫面破綻 → **兩位不同觀眾角色盲審笑點** → 沒過就修（剪接優先，必要才重畫）並複審 | [`REVIEW.md` §2～§4](REVIEW.md) | 規格全過、無高／必修改中度畫面瑕疵、兩位審片人都判「笑點有畫出來」且好笑平均 `≥ 3/5` |
| **6. 雲端備份與後台匯入** | 完整製作檔備份到雲端硬碟 `AI/備份/Shorts/<系列名>/`，再用 `node tools/video/shorts/cli.mjs import` 送後台 | [`REVIEW.md` §5](REVIEW.md) | 雲端備份完整（含 `edit/plan.json`、`colab/`、`qa/`、八語 meta）；後台匯入成功 |
