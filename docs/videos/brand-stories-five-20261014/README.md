建立日期：2026-10-14。**目前是五集的編輯企劃，不是已配音、成片、上傳或發布的影片。** 站主要求從品牌故事選五個有機會吸引廣泛觀眾的主題，形式依奇聞檔案局新版：第一秒先進故事、30–60 秒濃縮開場、5 秒動畫片頭、連貫正文、21 秒動畫片尾與 YouTube 可點的片尾元素。五題都從[已由站主核准、另經查核的 100 題題庫](../story-plans/brand-stories-100/README.md)選出；A01/B18 原有試作另循其票，不算進這五支。

## 五集共同的觀看時間軸

| 時間軸 | 觀眾看到與聽到的事 | 製作及驗收 |
| --- | --- | --- |
| `0:00` 起、30–60 秒 | 一個具體場景先落地。前約 20 秒有標題承諾的名字、年份或數字。後面預告三至四個按發生順序排列的事件，各停在結果之前，最後一問接正文。 | 旁白第一句不打招呼、不唸目錄。每個預告在正文有真正的新事實回收；開場說過的事實不重講。Treatment 中的 45 秒只是文字估算，TTS 後量實際時間。 |
| 濃縮開場後 | 全頻道 5 秒／150 格動畫片頭。 | 依[頻道品牌素材規格](../BRANDING.md)在第一章與第二章之間插入。當前本機 `_branding/current.json` 讀到 `mokaair-brand-package-v4-endscreen`、hash `416c8768d4d29f2e746a0c019d2d598ec367cbb66b0ff996841c523651a63e88`、片頭 150 格、片尾 630 格；實際合成前再次回讀並鎖 pin。 |
| 正文約 13 分鐘目標 | 台灣口音單人旁白、六個事件章，約 85–100 張一致的平面卡通插畫與緩慢運鏡，繁中字幕跟著音訊。每約 5–8 秒畫面狀態更新；圖片要說出故事的下一步，不只換背景。 | 後五章一條因果主線；每 60–90 秒埋一個可回收的疑問。章名指向事件，不是「背景／結論」。最後一章來源不足時就縮短，不能靠重複、停頓或放慢旁白灌長。品牌故事原路線為 `series.kind=story`、`format=drama`、`visual_tier=stills`；其他語言字幕與配音依本集實際設定及另行核定。 |
| 正文最後三句 | 回答開場、給一個與故事相連的留言題、說一個有理由的訂閱邀請。 | 正文不口播「下一支是什麼」；這件事交給結束畫面。 |
| 正文後 21 秒／630 格 | 1 秒停頓與配樂淡入、3 秒動畫、17 秒留兩個影片卡位與一個訂閱位置。 | 最後 16 秒在 YouTube Studio 放「最符合觀眾喜好」、訂閱、「最新上傳」三個**真正可點**的元素；MP4 畫出的外框本身不能點，YouTube Data API 也不能替代 Studio 編排。未上傳前只能準備 `endscreen-setup`，不能宣稱連結已啟用。 |

現用 v4 片尾在動畫之後還有約 1 秒 CTA 淡出，因此可點元素依[時間修正票](../../../tasks/open/2026-10-12-correct-v4-youtube-end-screen-timing.md)與[奇聞檔案局重製片規格](../curio-five-recuts-20261012/README.md)放**最後 16 秒**。`BRANDING.md` 仍寫「片尾第 4 秒／最後 17 秒」，該行尚待修正；實際上傳時以 v4 畫面與 Studio 預覽再核對。

正文和成片各自要量到至少 8 分鐘；品牌故事以約 13 分鐘為製作目標，實際聲畫時間由 `ffprobe`、TTS timeline 與 QA 驗證，片頭片尾不能湊正文門檻。五集都保留母企劃的**非虛構、只用旁白**邊界。任何真實人物、商標或受版權保護角色，生成畫面用一般化人物與通用物件；必要的名稱與數字在後製文字層呈現。

## 編輯查核與製作順序

1. 先把 Treatment 的六章推進成每章帶來源的逐字稿與畫面句，逐句標明主張。重要數字、時間、因果、法律裁決與企業自述要有頁面證據；爭議說法保留歸屬。開場四個懸念在正文各有 setup/payoff，全文不重播已揭曉的答案。
2. 逐章查核、逐章聽眾審稿，再做完整敘事盲評。`youtube-video` 的[故事主線與開場規格](../../../.agents/skills/youtube-video/references/script-writing.md)及 `node tools/video/cli.mjs narrative --slug ...` 的說故事關卡要在逐字稿後跑；本階段的短企劃不能冒充通過該關。
3. 五集由來源題庫抽出時，不覆寫現有 100 集的已核准順序，也不直接把本 README 交給 worker。若更動原 `chapters`、標題或任何事實欄位，必須重新獨立查核並更新相符的 `reviews/<id>.json`，再執行 `node tools/video/story-plans/validate.mjs --write`。匯入前核對正式站是否已有相同 slug、集數或進行中工作，先做唯讀 dry-run。
4. 媒體購買前核對該集畫風、品牌素材、旁白聲音、實際模型單價、帳號餘額與每支花費上限；先做最少的連續鏡頭 pilot，確認人物／圖像一致和故事可看，再整批產圖。完成後聽全片、看全片，檢查字幕、章節、音量、來源、縮圖與 `qa`，五支分別保存 hash 和費用收據。
5. 待站主看過成片後，才進入上架確認。私密上傳、Studio 結束畫面實際可點、公開發布及站主接受，各記不同證據；不可因為生成 MP4 或 YouTube private ID 就寫成公開完成。

截至本稿，repo 的[品牌故事試作票](../../../tasks/open/2026-09-28-video-story-pilot.md)仍指定先做 A01/B18、量成本與清晰度。這五支另需新的工作安排，不暗改既有試作或 100 集每天兩支的排程。`docs/videos/STORY.md` 的 2026-09-28 試算為選定模型 1K 圖 US$0.067／張；[Google 官方價格表](https://ai.google.dev/gemini-api/docs/pricing)於本次檢查仍列相同數字。若以 89 張有效圖估計，五支的**圖像輸出基本費約 US$29.82**；若各生成約 120 張（含重做）則約 US$40.20。這不包含輸入 token、judge、語音、配樂、重試及匯率；真正費用與上限以製作時預算 dry-run 和收據為準。試作票的每支 US$25 上限不能只靠圖片估價證明。
