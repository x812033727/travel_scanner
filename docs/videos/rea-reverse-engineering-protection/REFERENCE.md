## 2. 它比我們強在哪（對照 `travel-scanner-video-teaching-value`、`narrative-flow` 兩份紀錄量到的我們的毛病）

1. **字數**：13 分鐘約 4,800 字。我們同長度的舊片約 2,500 字，空的部分是出處交代與比喻。
2. **一個主角**：Apple 備忘錄從 4:16 的例子、5:23 的實測、7:45 的邊界、10:06 的需求寫法、11:27 的護城河都在用。我們舊片一支換 8 個比喻。
3. **實測是畫面主體**：5:09–7:09 整整兩分鐘是螢幕錄影實際操作，觀眾看到「做得出來」。我們很多片只有字卡寫「預期・未實測」。

5. **一個可以帶走的方法**：「拿參考物對齊，而不是用形容詞描述需求」，連不寫程式的人都用得到。
6. **意見是意見**：「我覺得」「老實說」「我認為」，給立場也給理由。
7. **結尾**：一個具體行動（挑熟悉的產品做雙胞胎）＋按讚訂閱。不講下一支。

## 3. 它自己也有的缺口（我們能贏的地方）

- 實測很淺：自己說「可能是逆向失敗，或這東西太簡單」——**沒給觀眾看 REA 到底挖出了什麼證據**，只看到成品。
- 「裝不裝 REA 差多少」是轉述別人的對照，沒自己跑。
- 安裝只說「丟 repo 給 Agent」，沒有能照打的指令（官方是 `npx rea-agents setup`）。
- 完全沒談**被逆向的那一方**：開發者該怎麼保護自己的軟體。這正是站主給的標題。

## 4. 我們這支的角度與證據

標題問的是防守方：程式編譯、混淆過「看不懂」，在 AI Agent 加 Ghidra 的時代還擋得住嗎？跟 Gary 的「我可以複製別人」正好是反面，題目不撞。

**主角**：我們自己的網站 Mokaair。用 REA 逆向**自己**的正式站前端（Next.js 打包過、壓縮過的 JavaScript）與一支我們自己編譯的小程式，看它能挖出什麼。這是我們有權分析的目標（REA 的 DISCLAIMER 也只允許分析自己擁有或被授權的軟體），也是 Gary 沒有的「猜不到的實測結果」。

觀眾看完能做到的事（含金量六條的草案）：
1. 用一行指令裝好 REA，對自己的網站或 Electron App 跑一次靜態分析，看出被打包的程式裡露了什麼（路由、API 位址、內部旗標、source map）。
2. 分得清哪些東西放前端就等於公開（金鑰、付費判斷、隱藏功能開關），哪些只要放伺服器就看不到（REA 自己的邊界：伺服器端邏輯拿不到）。
3. 知道混淆與編譯只是拉高成本、不是鎖：用實測對照「混淆前後 Agent 花的步數與找到的東西」。
4. 拿到一份照做的上線前檢查清單：關 source map、秘密不進 bundle、授權與計費判斷放伺服器、對前端只回需要的欄位。

故事線（事件型，草案）：
1. 開場場景：10-06 不到一萬星、10-12 破十萬、今天 27 萬；別人十分鐘把一個老遊戲拆出來 → 「那我們自己網站打包過的程式，它要多久？」（停在結果之前）
2. 以前為什麼覺得編譯就安全：編譯丟掉名字與註解、工具倒出幾萬個函式不知道追哪條（借 Gary 的「難在哪」結構，用我們的例子）。
3. REA 補上的那一塊：Agent 決定追哪條線，三層架構一句講完。
4. 實測一：對 Mokaair 正式站的前端跑 REA —— 它找到什麼、花多少步、哪些是我們以為藏起來的。
5. 實測二：同一支小程式，混淆前、混淆後各跑一次，比較。
6. 邊界：它拿不到的東西（伺服器上的程式、資料庫）＝真正的保護在哪裡。
7. 帶得走的清單，結尾一個行動：「今晚對你自己的網站跑一次」。
