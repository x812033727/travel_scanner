# REA 一週破十萬星：程式「看不懂」，還保護得了你的軟體嗎？

## 觀眾

會自己寫網站、桌面 App 或小工具的開發者，以及想知道「我付錢的軟體／我做的軟體，秘密到底藏不藏得住」的進階使用者。他們聽過 REA 爆紅、看過「用 AI 復刻某某 App」的 Demo，搜尋的是「REA 是什麼」「程式碼混淆有用嗎」「前端的 API key 會被看到嗎」。他們已經會用 Claude Code／Codex 這類 agent，也大概知道「編譯過就看不懂了」這個直覺。

## 觀眾看完能做到的事

- 用一行 `npx rea-agents setup` 把 REA 接上自己的 agent，再用一個指令對自己的 .NET／Electron 程式或自己的網站跑一次靜態分析，親眼看到被打包的程式裡**露出了哪些字串與 API 介面**（證據：RUN，執行紀錄裡原版 NoteVault 一個指令倒出全部 23 個字串常數；網站 `analyze-web-bundle` 解析 20 支 script、判出框架與兩個 API 端點）。
- 分辨「放進前端／二進位就等於公開」的東西（金鑰、付費判斷、隱藏旗標）和「只要放伺服器就看不到」的東西，並說得出為什麼（證據：RUN，REA 對正式站明確回報 source map 不可得、server-side behavior 拿不到）。
- 判斷程式碼混淆**到底擋住了什麼**：自己做一個混淆前後的對照，看出混淆改的是「可讀性」而非「可繞過性」（證據：RUN，同一支程式 const 版混淆後密鑰仍以明文殘留、readonly 版才真的藏掉；三種繞過在混淆版照樣成功）。
- 照一份清單改掉自己程式裡的用戶端授權漏洞：把判斷與秘密搬到伺服器、關掉 source map、拔掉除錯後門（證據：RUN，清單每一條都對應一個實測到的失敗）。

## 站主觀點

我覺得 REA 這波最被誤讀的地方，是大家都在看「它能複製誰」，很少人問「那被複製的那一方該怎麼辦」。我自己做 Mokaair，第一個反應不是興奮，是緊張：我到底在前端漏了什麼？所以我乾脆拿自己的網站跟一支自己寫的小程式開刀，用 REA 照一次鏡子。我的立場是：**混淆和編譯從來不是鎖，只是提高一點門檻；真正的保護只有一種，就是把判斷和秘密放到使用者碰不到的伺服器上。** REA 爆紅只是把這件一直成立的事，變成一行指令就能示範給你看。

## 示範或實算

製作路線：教學卡片。

貫穿例子：一支我自己寫、自己編譯的約 80 行小程式 **NoteVault**（模擬「有 Pro 付費功能的筆記 App」，所有秘密都是假的測試值）。它故意犯三個常見錯誤：授權檢查用寫死的密鑰在用戶端算、一個 `NV_INTERNAL_DEBUG=letmein` 除錯後門、一個 region=EDU 的隱藏折扣。原始碼與混淆設定收在 `test-target/`，執行紀錄在 `RUNLOG.md`。

- 有用的產出：對自己擁有的程式跑一次 REA，看到它會被怎麼讀。
- 信任／風險（排在安裝之前）：REA 的分析在**本機**跑，不上傳程式；官方提醒只能從 `morluto/rea`、`rea.tools`、npm 套件 `rea-agents` 取得，名字相近的 repo 不算官方（搜尋結果裡就有一個抄 README 的假 repo）；DISCLAIMER 只允許分析自己擁有或被授權的軟體——這支影片分析的全是我們自己的東西。
- 步驟：`npx rea-agents setup` → 對 `NoteVault.dll` 跑 `rea inspect-managed-members` → 對混淆版再跑一次 → 對 `https://mokaair.com` 跑 `analyze-web-bundle`。
- 預期 vs 實測：都在 RUNLOG.md，下面「會過期的事實」與各大綱標了用哪張卡呈現。

**不用這個方法：** 看一個 .NET DLL 裡的明文字串，最簡單的方法是 `strings` 指令或直接用文字檢視器打開——原版 NoteVault 這樣就能看到密鑰了。所以 REA 的價值**不在**「看到明文字串」，而在兩件 `strings` 做不到的事，影片就把例子放在這裡：(1) 讓 agent **順著授權邏輯**算出一把合法 key、實際解鎖 Pro（`strings` 只給你一堆字串、不會幫你繞過）；(2) 面對**混淆版**——`strings` 掃不到結構、人也讀不懂，REA／agent 仍能從 metadata 與 CIL 把判斷還原出來。兩邊我都跑了：純位元組掃描（簡單法）對上 REA，差別是「找到字串」對「繞過付費閘門」。

**不可預測的結果（開場就放）：** 直覺是「混淆過＝看不懂＝安全」。實測打臉：同一支程式混淆後，我用的三種繞過（偽造 key、除錯後門、隱藏折扣）**一字不差地照樣成功**——因為判斷還是跑在使用者的機器上。而且混淆連「藏字串」都做得不一致：秘密寫成 `const` 時混淆後還以明文躺在檔案裡，改成 `readonly` 才真的消失。

**觀眾自己動手寫的那一項：** NoteVault 的授權檢查整段會上卡（三張卡放得下 `License.Check`），影片示範把它從「用戶端算 HMAC」改成「只收伺服器回傳的已批准結果」，改動的那幾行與呼叫伺服器的那一行都在卡上，並重跑一次確認偽造 key 失效。這是觀眾照著能改自己程式的那一行。

## 大綱

### 選項 A：照一次鏡子（我對自己的軟體開刀）

一句話角度：以「被逆向的那一方」為主角，從站主拿自己的網站與小程式實測出發，結論落在一份可照做的防守清單；跟市面上「用 REA 複製別人」的片正好相反。相對 B，A 更貼個人、敘事感強，開場就是站主的緊張。

開場鉤子（20 秒內落地）：「REA 這個工具，十天從不到一萬顆星衝到約二十八萬。大家都在用它複製別人的 App——那我做的網站呢？我把自己的程式丟給它，結果最讓我意外的不是它挖出了什麼，而是：我把程式碼混淆到人根本看不懂之後，付費鎖還是被同一招打開了。」

案例與結果：「NoteVault（自己寫的付費筆記 App）＋ Mokaair 正式站；一個指令倒出全部 23 個字串、混淆後付費閘門照樣被繞過、網站 source map 已關但 API 介面仍可讀。證據狀態：RUN。」

卡片與步驟：

1. **為什麼我會緊張**（約 60 秒）：REA 是什麼、為什麼一週爆紅（星數卡，標錄製日）；別人拿它複製 App 的熱度；站主的問題「那被複製的一方呢」。`stat`：星數與時間軸。`quote`：站主觀點一句。
2. **以前我以為編譯就安全**（約 70 秒）：編譯／混淆會把變數名、註解丟掉，直覺上「看不懂＝安全」。用 NoteVault 介紹三個故意的錯。`code`：授權檢查那段。`compare`：原始碼 vs 編譯後「應該看不懂」。
3. **第一次照鏡子：原版**（約 90 秒）：`inspect-managed-members` 一個指令，23 個字串全出來，密鑰、後門、隱藏折扣全中。但先說清楚——**這招 `strings` 也做得到**。`screencast`／`code`：REA 指令與輸出。`compare`：`strings` 簡單法 vs REA。
4. **REA 真正多做的一件事**（約 90 秒）：讓 agent 順著邏輯算出合法 key、實際解鎖 Pro——`strings` 給不了這個。`steps`：從密鑰到偽造 key 到 `Pro activated.`。
5. **混淆之後呢？**（約 100 秒）：做混淆版，人與 `strings`都讀不懂了；但同三招繞過照樣成功，而且 const 版密鑰還殘留。開場那個意外在這裡解開。`compare`：混淆前後 × 可讀性／可繞過性 四格。
6. **換網站：我漏了什麼**（約 80 秒）：`analyze-web-bundle` 跑正式站，20 支 script、判出 Next.js、兩個 API 端點；但 source map 不可得、沒有金鑰、伺服器邏輯拿不到。這是「做對了」的對照。`screencast`：REA 網站報告重點。
7. **把判斷搬回伺服器（動手改）＋清單**（約 110 秒）：示範把授權檢查改成只收伺服器結果、重跑確認偽造 key 失效；收尾給六條上線前檢查清單。`code`：改動的那幾行。`checklist`：六條清單。
8. 結尾（約 30 秒）：回答開場——混淆擋不住繞過，真正的鎖在伺服器；留言題「你最想保護自己程式裡的哪一塊？」；請訂閱。（不講下一支。）

### 選項 B：三個等級的「其實都看得到」（以攻帶守）

一句話角度：不走個人敘事，改成以「資訊外洩的三個等級」為骨架——明文字串／用戶端邏輯／伺服器秘密——每一級用一個實測示範「看得到或看不到」，最後反推防守。相對 A，B 更像系統性教學、結構先行，適合想要「一張表帶走」的觀眾。

開場鉤子：「你的程式有三種秘密：寫在畫面上的、算在使用者電腦裡的、鎖在伺服器上的。前兩種，一行指令就能被讀出來或繞過——我用自己的程式跑給你看，連混淆都救不了。只有第三種，REA 自己都說它拿不到。」

案例與結果：同 A 的 NoteVault＋Mokaair，但以「三個等級」重新切分；證據狀態：RUN。

卡片與步驟：

1. **三個等級是什麼**（約 70 秒）：先給整張地圖（明文／用戶端／伺服器），這支要逐級驗證。`diagram`／`compare`：三級對照表。
2. **第一級：明文字串**（約 90 秒）：原版 NoteVault 一個指令 23 個字串全出；但標明 `strings` 也行，所以這級的教訓是「別放就對了」。`screencast`：REA 輸出。
3. **第二級：用戶端邏輯**（約 110 秒）：REA 比 `strings` 多做的——順邏輯算出合法 key 解鎖 Pro；這是 `strings` 到不了的一級。`steps`：偽造 key 流程。
4. **混淆能升級幾級？**（約 90 秒）：做混淆版測一次——第一級的字串「看起來」藏了（還不一致），第二級完全沒變，照樣繞過。`compare`：混淆前後四格。
5. **第三級：伺服器（REA 的邊界）**（約 90 秒）：跑 Mokaair，看得到 API 介面、框架，但 source map 與伺服器邏輯拿不到。`screencast`：網站報告。
6. **把第一、二級的東西搬到第三級（動手改）＋清單**（約 110 秒）：示範改授權檢查、重跑確認失效；六條清單。`code`＋`checklist`。
7. 結尾（約 30 秒）：回答開場——第三級才是真的鎖；留言題；訂閱。（不講下一支。）
