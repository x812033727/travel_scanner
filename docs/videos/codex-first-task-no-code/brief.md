## 觀眾

- 誰：有 ChatGPT Plus（或 Pro、Business）帳號、每天用 ChatGPT 聊天、不會寫程式、聽過 Codex 但沒開過的人。
- 已經知道：怎麼在 ChatGPT 貼文字、問問題；電腦上怎麼建資料夾、用記事本或文字編輯器存檔。
- 還不會：Codex 跟平常的聊天差在哪（不是「比較聰明」，是它能碰你電腦裡的檔案）；要在哪裡打開它、要選哪個資料夾；怎麼下第一個要求讓它只看不改；怎麼確認它真的改了檔案、而不是只回了一段漂亮的文字；它說「檔案不存在」時怎麼知道它沒有瞎編。

## 觀眾看完能做到的事

每一件寫成：動作／對象／怎麼知道做對了／畫面上的證明與證據級別。證據級別：看過（在產品自己的介面上看到）、跑過（留了輸入、動作、結果、日期、版本的執行）、引用（附出處的官方範例或實算）。這支企劃時什麼都還沒跑，所以每件先寫「跑過（待第 N 項）」；跑完之後哪一件沒成立，那一件拿掉。

1. **在 ChatGPT 桌面版打開 Codex、指定一個只有兩個檔案的資料夾，下一個「只看不改」的要求，並從回覆裡核對它真的讀了那兩個檔。** 動作：建 `codex-orientation/`，放 `README.md` 與 `packing.txt`；在桌面版的 ChatGPT 下拉選 Codex、開這個資料夾；貼 R1 的四行要求。對象：練習資料夾。怎麼知道做對了：回覆點名兩個檔名、說出三個物品、說這裡沒有可執行的網站；資料夾的兩個檔沒有變（比對修改時間與內容）。證明：R1 的畫面（看過）與 R1 前後的檔案內容（跑過）。級別：看過（待第 1 項）。
2. **叫它只改一行，然後不靠它的回覆、自己打開檔案確認那一行真的換了、其他都沒動。** 動作：貼 R2 的四行要求（把 `packing.txt` 的 Umbrella 換成 Raincoat，其餘不動，不加檔、不裝東西）；接受它的修改；用編輯器重開 `packing.txt`。對象：同一個資料夾。怎麼知道做對了：三行依序是 Notebook、Bottle、Raincoat；`README.md` 一個字都沒變；資料夾沒有多出任何檔案。證明：R2 前後兩次 `packing.txt` 的內容並排（跑過）、Codex 要求核准修改的那一格畫面（看過）。級別：看過（待第 2 項）。
3. **分辨「它改了檔案」和「它只是把答案打給你看」。** 動作：同一句 R2 的要求，連同 `packing.txt` 的三行，貼進平常的 ChatGPT 聊天（不是 Codex）；再打開電腦裡的 `packing.txt`。對象：同一份文字。怎麼知道做對了：聊天回了一份改好的三行文字，電腦裡的檔案還是 Umbrella。證明：R4 的回覆與 R4 之後的檔案內容（跑過）。級別：跑過（待第 4 項）。這一件是「不用這個方法」那一邊的執行（見下面）。
4. **用一個不存在的檔案測它會不會瞎編，看到它老實說「沒有」才繼續交更大的事給它。** 動作：貼 R3 的要求（唯讀列出 `missing.txt` 的內容，不存在就說明、不要建立）。對象：同一個資料夾。怎麼知道做對了：回覆說檔案不存在；資料夾仍然只有兩個檔。證明：R3 的回覆與之後的檔案清單（跑過）。級別：跑過（待第 3 項）。如果它編出內容或建了檔案：照實記，這一件改成「它編了，怎麼抓到」，證據反而更強。

不是成果、片中照樣會講的步驟（靠官方頁，卡片上標明）：Codex 在哪些方案裡（官方定價頁：Free 與 Go 是桌面版的 GPT-6 Luna、依推出進度；Plus 20 美元有網頁、CLI、IDE、iOS；Pro 100 起；Business 每人 20 美元）；桌面版的三種入口（ChatGPT 的 Chat、Work，與下拉選單的 Codex）；本機資料夾與雲端環境是兩回事；三種內建的權限範圍（`:read-only`、`:workspace`、`:danger-full-access`）與「改檔要你按核准」；關閉對話不會把檔案改回來。

## 示範或實算

製作路線：教學卡片。`format: "slides"`，沒有 `shot`；畫面是 `steps`、`chat`、`code`、`compare`、`table` 與公開官方頁的 `screencast`（quickstart 頁的「Select where ChatGPT should work」那一段、pricing 頁的方案卡）。站主自己電腦上的畫面不錄：規矩 4（不露帳號、email、瀏覽器分頁）；需要「看過」的成果，用卡片照抄站主在執行紀錄裡抄下來的回覆文字，出處標那一次執行。

給誰、解決什麼：給不寫程式、只用過聊天的人。看完能在自己的電腦上讓 Codex 讀一個資料夾、改一行、並自己核對；也能分辨「它改了」和「它只是打給你看」。

主線：一個人（站主）在自己的電腦上，從「建兩個檔」那一刻開始，到「第三個要求它老實說沒有那個檔」為止，一路核對。轉折（照順序）：第 2 章它讀對了兩個檔；第 3 章同一句話貼進聊天只得到文字、檔案沒變；第 4 章它要求核准才改、改完檔案真的變了；第 5 章缺檔測試它怎麼答（跑之前不知道）。故事線：實測型。主角：`packing.txt` 這個三行的檔案。

**不用這個方法**：把 `packing.txt` 的三行貼進平常的 ChatGPT 聊天，叫它把 Umbrella 換成 Raincoat。它會回一份改好的文字；電腦裡的檔案不會變，要自己複製貼回去存檔。Codex 做得到、聊天做不到的事：檔案在磁碟上直接變了，而且改之前要你按一次核准。這是觀眾接下來做得到、簡單做法完全做不到的事（簡單做法連「改檔案」這個動作都沒有）。兩邊用同一句要求、同一份三行文字，R2 與 R4 並排。

**主例要有的意外**：跑之前不知道的有兩處。一是 R3 缺檔測試：它說沒有、還是編一段內容出來；二是 R2 改檔時要你核准的那一格長什麼樣、核准之後它有沒有順手做要求以外的事（多建檔、改 README）。哪一個真的意外，開場就放哪一個；兩個都照預期，就把「貼進聊天檔案沒變」當開場的轉折（這件事對聊天用戶來說是意外，對開發者不是；這支的觀眾是前者）。

### 要先實作（站主照做，結果填進「執行紀錄」）

機器與版本先記下來：作業系統與版本、ChatGPT 桌面版的版本（設定裡看）、方案（Plus／Pro／Business）、日期。每一次執行都抄下：貼進去的原文、它回的全文（或截圖存在 repo 外，回覆文字抄進紀錄）、執行前後 `packing.txt` 與 `README.md` 的內容、資料夾的檔案清單。不露帳號名稱、email。

- 準備：在「文件」底下建 `codex-orientation/`，用純文字編輯器存兩個檔（Windows 記事本存成「所有檔案」、UTF-8；macOS 用純文字模式）。內容逐字用站內文章的：

      README.md：
      # Orientation exercise
      
      This folder contains a fictional packing list.
      The list has exactly three items.
      No website or package installation is required.

      packing.txt：
      Notebook
      Bottle
      Umbrella

- R1（只看不改）：桌面版 ChatGPT → 左上下拉選 Codex → 新對話 → 選這個資料夾 → 貼：

      Inspect this practice folder without changing files.
      Report the working directory, list the files, and read README.md and packing.txt.
      Explain what this project contains. Cite the filenames supporting your answer.
      If a requested file is missing, say so instead of guessing.

  預期：點名兩個檔、三個物品、沒有網站；兩個檔不變。怎麼認：比對內容與修改時間。
- R2（只改一行）：同一個對話貼：

      In packing.txt, replace the line Umbrella with Raincoat.
      Preserve the other two lines and leave README.md unchanged.
      Do not add files, install tools, or run a website.
      After editing, read packing.txt and report exactly what changed.

  預期：它要求核准修改；核准後 `packing.txt` 三行是 Notebook、Bottle、Raincoat；`README.md` 不變；沒有新檔。怎麼認：重開兩個檔、看資料夾。核准那一格的字抄下來。
- R3（缺檔測試）：同一個對話貼：

      Read-only: list the contents of missing.txt. If it does not exist, say so and do not create it.

  預期：說檔案不存在；資料夾仍兩個檔。它編了內容或建了檔：照實記，並貼「請重新讀取目錄，指出你剛才哪一句沒有證據」看它改不改。
- R4（簡單做法那一邊）：把 `packing.txt` 還原成 Umbrella 存檔。在平常的 ChatGPT 聊天（Chat，不是 Codex）貼 R2 那四行加上三行的檔案內容。預期：回一份改好的文字；電腦裡的檔案仍是 Umbrella。怎麼認：重開檔案。
- 各跑兩次（第二次換一個新的對話，資料夾還原到兩個原檔），寫成 R1a／R1b…。兩次不一樣就兩次都記，片中講「兩次裡有一次」。
- 另外看一眼、不當成果：Codex 對話裡有沒有哪裡看得到「權限範圍」或「只讀／可寫」的設定（官方 permissions 頁寫的三個內建範圍），看得到就截下那一格的文字；看不到就只引用官方頁。

### 選項 A：三個要求、一次反查，從只看不改到它老實說沒有（推薦）

故事線：實測型。主角：`packing.txt`。

角度：照站內文章的順序做，每章一個要求，核對的動作放在它的結果旁邊；聊天那一邊在第 3 章並排。跟 B 的差別是把「聊天 vs Codex」放在中段當轉折，不當開場。

開場（≤60 秒，`title`）：「我把三行字貼給 ChatGPT，它改好了，我電腦裡的檔案一個字都沒變。換成 Codex，它先問我一句『可以改嗎』，我按了，再打開檔案，第三行變了。」接著丟三個後面的時刻：它讀資料夾的時候點名了哪兩個檔；核准那一格寫了什麼；我叫它讀一個不存在的檔，它怎麼回。最後一句：「不會寫程式的人，第一次用 Codex 要怎麼下要求，才能一路核對它？」

1. 開場：它改了，我打開檔案看到了（45 秒）：`title`；`compare`：聊天回的文字 vs Codex 之後的檔案（R4 對 R2 的結果）。
2. Codex 是什麼：它能碰你選的那個資料夾（90 秒）：`chapter`；`table` 四個角色（代理、模型、任務、環境，文章）；`screencast` quickstart 頁「Select where ChatGPT should work」；`table` 方案（pricing 頁，標日期）；`steps` 打開的三步（桌面版 → 下拉選 Codex → 開資料夾）。收尾問題：「那第一個要求要怎麼下，才不會一開始就讓它亂改？」
3. 第一個要求：只看不改（100 秒）：`code` README.md 與 packing.txt 全文；`code` R1 四行；`quote` 它的回覆（R1，跑過）；`steps` 怎麼核對（檔名、三物品、沒網站、檔沒變）。收尾：「同一句話，貼進平常的聊天會怎樣？」
4. 同一句話貼進聊天：文字來了，檔案沒變（70 秒）：`chat` R4 的要求與回覆；`compare` 檔案前後（沒變）；一句選擇規則：只要文字就用聊天，要檔案變就用 Codex。
5. 第二個要求：只改一行，自己打開檔案看（110 秒）：`code` R2 四行；`quote` 核准那一格（看過）；`compare` packing.txt 改前改後；`bullets` 核對三件事（三行、README 沒變、沒新檔）。收尾：「它會不會在沒有的時候編一個給你？」
6. 第三個要求：讀一個不存在的檔（80 秒）：`code` R3；`quote` 它的回覆（R3，跑過）；`big` 結果一句話。
7. 常見失敗與練習；關閉對話不會還原（70 秒）：`table` 三個失敗與查法（文章）；`steps` 練習（Bottle → Cup → 換回）；`quote` 官方 permissions 頁的三個範圍（引用）。
8. 結尾（≤45 秒，`outro`）：回答開場的問題（三個要求的順序：只看、改一行、測缺檔；每一步自己打開檔案核對）；留言題「你第一個想交給它改的檔案是什麼？」；訂閱邀請。

主例在第 3、5、6 章；對照在第 4 章；練習在第 7 章。長度估 610 秒加開場，約 11 分鐘。

### 選項 B：先把「聊天」和「動手」分開，再做三個要求

故事線：抉擇型。主角：站主自己（同一個人、同一句要求，兩邊都試）。

角度：開場就是 R4 對 R2 的並排，第 2 章講四個角色與方案，第 3 到 5 章做三個要求，第 6 章常見失敗與練習。跟 A 的差別是對照放最前面、中段不再回頭講聊天。

開場：「同一句話，我貼了兩次。一次它回我一段文字，一次我的檔案真的變了。差別不在它多聰明，在它能不能碰我選的那個資料夾。」丟三個時刻：它點名兩個檔；核准那一格；缺檔那一句。問題：「不會寫程式的人，怎麼安全地讓它第一次碰自己的檔案？」

1. 開場（50 秒）：`title`、`compare`。
2. 四個角色與你的方案（100 秒）：`table`、`screencast`、`table`、`steps`。收尾：「所以第一個要求要怎麼下？」
3. 只看不改（100 秒）：同 A 第 3 章。
4. 只改一行、自己看（110 秒）：同 A 第 5 章。
5. 缺檔測試（80 秒）：同 A 第 6 章。
6. 常見失敗、練習、權限範圍（90 秒）：同 A 第 7 章。
7. 結尾（45 秒）：`outro`。
