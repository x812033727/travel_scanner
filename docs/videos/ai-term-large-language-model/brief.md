# 大型語言模型：它會接話，哪一段有證據？

企劃與來源重查日期：2026-10-04。文字草稿；尚未大綱核准、獨立查核、合成或上架。

## 觀眾

把問題和資料貼進聊天工具的一般使用者，不需要懂程式。觀眾常把「回答很完整」理解成「已經找到資料」，或以為模型提出計算要求就代表工具已執行。

## 觀眾看完能做到的事

拿一份回答，用三欄卡核對「文字生成」「有來源的資料查找」「工具已完成的計數」各自的依據與執行紀錄，圈出不能確認的句子。一份回答可以同時含三種工作；即使有資料或工具回傳，最後文字也可能由模型生成。三欄不是互斥能力分類。

## 站主觀點

套用立場：4、6、7

4：AI 整理要點開來源核對，我們自己的影片也一樣。6：實測就是實測，沒測過不說測過，示意標示意。7：每支給觀眾一個能做的動作。本集先區分文字生成、資料查找與工具計數，最後用三欄卡分類一份回答。失物故事、對話、錯誤答案都明示為編輯自製的虛構示意；離線程式的輸出只證明資料與計數，不測任何模型能力。

## 示範或實算

`demo.py` 只用 Python 標準函式庫，沒有網路、模型呼叫或帳號。六筆虛構失物紀錄，物件代號 L001 至 L006。三種情況：

1. **有據**：查 L001，回傳「雨傘、北側櫃台、未領」及紀錄代號；無資料支持所有權認定。
2. **缺資料**：詢問 L001 的失主電話；資料沒有 `owner_phone` 欄位，輸出 `UNKNOWN`，不可補造電話或失主。
3. **工具計數**：依 `status == unclaimed` 篩選四筆未領物件，再依 `item == umbrella` 篩選兩把雨傘，列實際參與計數的代號。不是六件全算成未領。

另示範同一個總數如何因「已領／未領」條件不同而不同，以及錯誤文字草稿如何添上資料不存在的失主姓名。這個錯誤草稿是編輯自製，畫面與說明欄標「錯誤示意，非模型輸出」。完整原始資料與輸出存 `demo-log.md`，terminal 字卡只抄真實執行輸出，附日期與 Python 版本。

### 選項 C：先場景，交接前先問三個問題（配方 B）

從值班員把櫃台交給下一班開始，觀眾幫他檢查三句交接文字。優點是一般觀眾容易代入；缺點是名詞機制較分散，需要章節卡保持脈絡。以下同樣是 10 分鐘候選估計。

| 章節 | 估計起訖／秒數 | shot 與必要卡 | 收尾問題 |
| --- | --- | --- | --- |
| 三句交接，有幾句能核對 | 0:00–1:30／90 秒 | 櫃台換班交籃 shot；chat 三句編輯示意；虛構標記 | 說得完整的人，怎麼產生這份回答？ |
| 接話的模型，與眼前材料 | 1:30–3:20／110 秒 | 麵團接續和新黏土 shot；diagram 模型／上下文／工具，compare 參數與材料 | 清單沒有的欄位，它應該怎麼處理？ |
| 有據、缺欄位、工具數字 | 3:20–6:30／190 秒 | 櫃台雨傘／空抽屜／分籃 shot；六列 table、三組真實 terminal | 為什麼工具說四，文字還可能說六？ |
| 哪一步把條件換掉了 | 6:30–8:10／100 秒 | 廚房六盤／四盤 shot；6/4/2 stats、工具回傳 steps | 下一班怎麼把同樣錯誤擋下來？ |
| 交出去之前的三欄卡 | 8:10–10:00／110 秒 | 庭院手上物件交接 shot；三欄 table 和缺資料保留未知卡 | 回答開場：三句交接要逐句找支持紀錄與條件，不能因為都很通順就全部接受。 |

三個方案都以同一份虛構六筆資料為證據，不把生成、查找與計數當互斥分類。鏡頭換地點是機制映射：櫃台＝資料需要可查；麵團分塊／接續＝token 與常見生成；陶藝手藝／當次黏土＝訓練能力與材料；多功能室＝真正離線查表；集市多人＝產品與工具分工；廚房分食＝條件與核對；庭院交接＝觀眾的下一步。參數不與單筆資料一一對應，不把比喻當真實模型內部。

## 會過期的事實

不講價格、方案、特定產品功能、模型排名、參數數量或性能分數。來源於 2026-10-04 重開官方頁；Google 教材說的完整編碼器／解碼器架構只作背景，不說所有 LLM 都有兩者。因果語言模型只能看到目前已有的 token，不能把示意說成看見未來的答案。這集不給 token／中文字固定換算值，也不測任何特定模型。

## 不做的事

不把離線程式說成語言模型，不把虛構錯誤示意說成實測，不讓六筆資料證明整類模型可靠或不可靠。不聲稱模型只能背誦或永遠不能推理；把逐步生成機制與實際能力評估分開。不列各家模型、不做跑分、不論證人類與模型的心智等同，不替站主編使用經驗。不補造失主、電話或已成功執行的工具；這份包不代表任何關卡核准。
