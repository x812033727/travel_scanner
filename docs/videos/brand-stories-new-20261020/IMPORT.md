# 正式站匯入交接

截至 2026-10-20，五集已完成企劃、逐來源重查、獨立雜湊收據與正式編譯。匯入檔是本目錄的 `stories.json`（約 68 KB），不是 `stories.draft.json`。目前沒有任何一集匯入或製作成片。

## 正式工人開始前的前置

已將企劃包與 `tools/video/automation/story.mjs` 修正推送到 Git 分支 `codex/brand-stories-20261020`，**尚未合併或部署**。此系列的精確 `cute-mystery` 外觀會用奇聞檔案局的 `CURIO_MUSIC`，且新系列在付費畫圖前檢查插圖至少 70%、連續卡片最多三張；既有系列的配樂設定不受影響。**先將分支修正部署到正式故事工人，再匯入企劃清單**。若先匯入，正式工人可能使用舊配樂與舊畫面檢查開始製作。

本系列 `hands_off: true` 且每日可開工一集；正式匯入後工人可能啟動付費步驟。按「確認寫入」前須以正式站版本、帳本與供應商價格估出首批張數和全項費用，確認每片 US$25 上限涵蓋文字、語音、圖像、評審與重試，並取得整批一次性核准。現在只有企劃和旁白參考稿，尚無 TTS／逐鏡張數與可靠總額，不能把本機匯入乾跑當成費用核准。

## 需要後台帳號完成的匯入操作

1. 程式變更部署後，使用有 `content.manage` 的帳號登入正式站 [影片後台的故事分類](https://mokaair.com/zh-TW/admin/videos?tab=reviews&category=story)，找到「匯入企劃清單」。這項權限來自後台匯入 API；已配對的影片工具權杖沒有管理員匯入權限。
2. 選擇本目錄的 `stories.json`，或貼上完整內容。畫面應解析為 **5 個故事，作品 `brand-stories-new-20261020`、預留總數 100 集**。先把「只匯入前幾個故事」設為 **1**，以 B10 做首支；「建立作品時的每日支數」選「照檔案」（檔案設定為每天 1 支）。
3. 按「試跑」。首支預期 `accepted=true`、新增 1、更新 0、拒絕 0，且作品會按檔案建立。「檔案有 5 個故事、系列預計 100 集」是預期提示，並非匯入失敗。這裡必須看**正式站**的報告；它能檢查 slug 衝突與既有同系列狀態，**不能判斷跨系列語意同題**。另以正式站已做影片及待做企劃人工核對五題品牌與主線。若報告有拒絕或非預期更新，或人工核對發現同題，暫勿寫入，保留紀錄以便換題及重查。
4. 只有正式站試跑、人工同題核對和上述付費前檢都通過，才用**相同的限額 1**按「確認寫入（新增 1、更新 0）」。待首支真實劇本、來源、畫面、配樂、成本與成片 QA 通過，再用完整的同一份 `stories.json` 清空限額試跑；預期新增其餘 4，首支只列 `started` 或 `unchanged`，拒絕 0 且沒有非預期更新。核對新四支的成本護欄後才確認寫入，依正式工人的排程與關卡逐集製作。

正式站上次成功唯讀預查已列出 54 支漫劇影片，沒有這五集的新影片 slug；指定系列回 404。此查詢不會列出其他系列尚未開工的企劃，所以第 3 步仍必須執行。正式站唯讀設定顯示自動化與故事配樂已啟用；實際工人是否開始仍受每日限額、同時製作上限與待上架緩衝限制。此後雲端環境對 `mokaair.com` 的 CONNECT 回 403；已保存網路設定草稿但尚待發布，代理暫時不能再讀正式站狀態。

匯入成功後，再以已配對影片工具唯讀核對系列與首集狀態，依真實工人產物核對劇本、事實、插圖比例、配樂、時長與成片。每集標題應以 ` | 品牌故事` 結尾。五集排完後要繼續做新的題目，仍需先完成新批次查核與匯入；不能把這五集的查核直接套用到新片。系列預留 100 集，但不產生空白集；若五集已做完、後續尚未匯入，工人安全等待。追加時檔案必須包含原五集與新集，集數連續；詳見 `CONTINUATION.md`。
