# Claude Code Mods：一個計數器的完整教學

錄製／查核規劃日期：2026-10-09。狀態：完整改寫稿；未合成旁白、未製作成片、未載入本機 Mod。

預計 8–12 分鐘；這是撰稿目標，不是媒體實測。語音樣式保留原版，字幕為可關閉 CC。

## 一個計數器，讓工具呼叫次數看得見

### r2-result

畫面：diagram；示意計數｜依官方 first-mod 範例重畫，非本機實測

[mc001] Claude Code 忙了半天，到底用了幾次工具？
[mc002] 右邊多了計數，你就不用往上翻。

### r2-what-changed

畫面：big；多一行**工具計數**

[mc003] 這一行，是今天這個擴充模組加出來的。
[mc004] 它能修改 Claude Code 的介面或行為。

### r2-illustrative-count

畫面：stats；讀一次，加一筆

[mc005] 收到一次工具事件，計數從零加到一。
[mc006] 第二次再加一；這些數字都是示意。

## 工具、模型與 Mod 各做什麼

### r2-not-model-upgrade

畫面：big；**看得更清楚**

[mc007] 你以為加了功能，就是換了更強的模型。
[mc008] 其實，這個例子只把已有的動作數出來。

### r2-example-task

畫面：chat；固定用這個小工作

[mc009] 我們把工作固定成讀一個示範資料夾。
[mc010] 請它讀示範資料，觀察計數如何增加。

### r2-scope

畫面：big；官方範例，逐步拆解

[mc011] 這個官方範例，加上一個工具計數器。
[mc012] 從記錄事件，到顯示數字，都在這份程式裡。

### r2-question-mechanism

畫面：big；它怎麼知道**工具被呼叫了**？

[mc014] 那計數器從哪裡知道有動作發生？

### r2-flow

畫面：diagram；固定角色：使用者、模型、Claude Code、Mod、工具

[mc015] 看這張圖，先把幾個角色分清楚。
[mc016] 你輸入要求，Claude 模型負責理解和回應。

### r2-model

畫面：diagram；模型提出工具需求；Claude Code 負責協調執行

[mc017] 需要讀檔時，模型提出一個工具呼叫。
[mc018] Claude Code 接手，處理執行和結果。

### r2-tool-example

畫面：big；讀檔，也是一次**工具呼叫**

[mc019] 工具，就是讀檔或執行指令這些功能。
[mc020] 模型說想讀檔，跟檔案真的讀到了，要分開看。

### r2-event

畫面：diagram；tool.call → 計數加一 → next(e)

[mc021] Claude Code 收到工具呼叫，會觸發事件。
[mc022] 計數器就在這個時間點，把數字加一。

### r2-hook-term

畫面：big；事件發生，就執行這段程式

[mc023] 這段接住事件的程式，叫做掛鉤。
[mc024] 你可以理解成，事情發生時要做的動作。

### r2-continue

畫面：diagram；本例只記錄，再把原事件交回

[mc025] 記完之後，它把原本的要求交回去。
[mc026] 所以讀檔這件事，仍由原來的流程處理。

### r2-redraw

畫面：diagram；計數變動 → 重畫介面 → 顯示新數字

[mc027] 另一段掛鉤，負責把數字放到介面上。
[mc028] 一次記錄，一次顯示，畫面就接起來了。

### r2-separate-counts

畫面：compare；這個數字沒有告訴你的事

[mc029] 它累積的是模組載入後的工具呼叫事件。
[mc030] 它不保證工作完成，也不是你的帳單。

### r2-failure-count

畫面：big；失敗的呼叫，也可能被數進去

[mc031] 例如讀檔失敗，事件仍然已經發生。
[mc032] 看到兩次，要回到執行結果判斷成敗。

### r2-result-matters

畫面：big；數字是線索，**結果才是答案**

[mc033] 數字可以幫你找到要看的紀錄。
[mc034] 你要核對的，是那次呼叫實際做了什麼。

### r2-question-hooks

畫面：big；同一個事件，還能怎麼處理？

[mc036] 如果它選擇不放行，會發生什麼事？

## 同一個掛鉤，三種處理方式

### r2-observe

畫面：bullets；選擇一：只觀察

[mc037] 只觀察，就是記下事情，讓它照常繼續。
[mc038] 計數器對工具呼叫，採用的就是這種做法。

### r2-next

畫面：code；程式片段｜next(e) 交回原事件

[mc039] 畫面這兩行，一行加一，另一行交回。
[mc040] 交回的意思，是讓後面的處理繼續跑。

### r2-rewrite

畫面：bullets；選擇二：改寫

[mc041] 改寫，則是把內容改過，再往後傳。
[mc042] 計數器畫介面時，就替狀態文字加上數字。

### r2-same-spinner

畫面：big；原有狀態，**加上次數**

[mc043] 所以你還看得見原來的工作狀態。
[mc044] 它只是多了一段，告訴你目前數到幾次。

### r2-answer

畫面：bullets；選擇三：自己回覆

[mc045] 還有一種，是自己回答這個事件。
[mc046] 計數器的查詢指令，就直接回傳目前數字。

### r2-tally

畫面：code；使用者查次數｜官方範例指令，不是模型提示詞

[mc047] 你輸入畫面這條指令，就能查目前次數。
[mc048] 這個回覆由程式產生，不需要請模型猜。

### r2-choices

畫面：compare；記錄動作，與決定動作

[mc049] 同樣叫做擴充模組，做的事可以差很多。
[mc050] 因此，不能只看名字就決定要不要裝。

### r2-question-trust

畫面：big；載入前，先看它會做什麼

[mc052] 載入之前，究竟要先看哪裡？

## 載入以前，先確認權限與來源

### r2-privileges

畫面：big；Mod 會用**你的權限**執行

[mc053] 這種模組，會用你的使用者權限執行。
[mc054] 所以來源和程式內容，都要在載入前確認。

### r2-what-reach

畫面：bullets；它可能碰得到什麼

[mc055] 有的程式會讀檔，有的會啟動其他程式。
[mc056] 也可能連網，或另外發出模型請求。
[mc057] 小小一行介面，不表示背後只做一件事。

### r2-sandbox

畫面：compare；兩種「沙盒」別混在一起

[mc058] 模組本身的執行環境，會限制直接使用的能力。
[mc059] 但這跟執行系統指令的隔離，是兩回事。

### r2-sandbox-consequence

畫面：big；Mod 自行啟動的程序

[mc060] 模組自己啟動的程式，在 Claude Code 的指令執行沙盒之外。
[mc061] 所以，開了指令沙盒也不能省略來源檢查。

### r2-review-checks

畫面：bullets；對這個計數器，先核對三件事

[mc062] 先找到作者提供的原始碼。
[mc063] 再看它掛了哪些事件。
[mc064] 最後看它透過介面要求了哪些能力。

### r2-validate

畫面：code；靜態檢查｜讀檔分析，不執行這個 Mod

[mc065] 畫面這條檢查指令，可以列出掛鉤和呼叫。
[mc066] 它讀程式做分析，還沒有執行你的擴充程式。

### r2-validation-limit

畫面：big；檢查通過，**不等於安全認證**

[mc067] 如果看到讀檔、連網等能力，就追進去看原因。
[mc068] 程式能通過檢查，跟你能信任作者是兩回事。

### r2-question-files

畫面：big；只加計數，要準備什麼？

[mc069] 這個入門例子不需要讀你的專案內容。
[mc070] 那它實際由哪幾個檔案組成？

## 三個檔案，組成一個計數器

### r2-official-page

畫面：screencast；官方文件｜Write a mod yourself｜查核 2026-10-09

[mc071] 打開官方的建立教學，找到手寫範例這一段。
[mc072] 同一頁就有完整程式，不必從零猜格式。

### r2-version-command

畫面：code；版本檢查指令｜官方門檻查核 2026-10-09

[mc073] 先用版本指令，檢查目前的終端機版本。
[mc074] 這份教學要求二點一點二八七以上。

### r2-our-version

畫面：big；低於 2.1.287？**先更新**

[mc075] 如果你的版本低於門檻，先停下來更新。
[mc076] 更新後再查一次，確認版本符合要求。

### r2-clean-folder

畫面：big；用乾淨的**示範資料夾**

[mc077] 你動手時，可以先準備一個示範資料夾。
[mc078] 用自己寫的短文字，比拿工作資料測試清楚。

### r2-file-tree

畫面：code；檔案結構｜三個角色，各有一份檔案

[mc079] 範例有三份檔案，每一份各做一件事。
[mc080] 先看外掛說明，再看入口，最後才看程式。

### r2-manifest

畫面：code；plugin.json｜外掛的名字與版本

[mc081] 第一份，是外掛的基本資料。
[mc082] 名字用來辨認它，版本用來記錄哪一版。

### r2-module-pointer

畫面：code；hooks.json｜找到真正要執行的模組

[mc083] 第二份，告訴 Claude Code 程式放在哪裡。
[mc084] 這個路徑，是相對於它所在的掛鉤資料夾。

### r2-four-hooks

畫面：bullets；register.js 裡的四個動作

[mc085] 第三份才是真正的程式。
[mc086] 它把四個時間點，接到四個小動作。
[mc087] 四個動作合起來，才是剛才那個計數器。

### r2-question-load

畫面：big；檔案齊了，怎麼核對它有載入？

[mc089] 要怎麼確認，這次對話真的載入它了？

## 載入與核對，每一步看什麼

### r2-local-check

畫面：code；操作步驟 1｜在範例上層執行靜態檢查

[mc090] 在範例資料夾的上一層，先跑剛才的檢查。
[mc091] 路徑要指向整個外掛資料夾。

### r2-check-output

畫面：bullets；檢查結果，應該對得上原始碼

[mc092] 核對事件清單，有沒有程式裡那四個掛鉤。
[mc093] 核對能力清單，有沒有不明的額外呼叫。
[mc094] 如果有錯誤，先停下來把錯誤修好。

### r2-load-session

畫面：code；操作步驟 2｜官方單次 session 載入指令

[mc095] 確認內容後，用畫面這條指令開始對話。
[mc096] 它把資料夾載入這次對話，沒有做永久安裝。

### r2-loaded-check

畫面：code；操作步驟 3｜在 Claude Code 裡檢查外掛

[mc097] 進入對話後，打開外掛清單。
[mc098] 在已安裝分頁，核對名稱和啟用狀態。

### r2-zero-check

畫面：code；操作步驟 4｜先查次數，再叫模型做事

[mc099] 還沒叫模型做事，先用查詢指令看次數。
[mc100] 剛載入且沒有工具事件時，應該是零。

### r2-command-missing

畫面：big；指令在哪？**先查載入**

[mc101] 如果指令不存在，就先回頭檢查載入。
[mc102] 不要把沒出現功能，誤認成模型不夠聰明。

### r2-real-task

畫面：chat；操作步驟 5：執行小工作

[mc103] 功能已載入，才請模型讀示範說明檔。
[mc104] 這一步會使用你的模型額度或用量。

### r2-expected-visible

畫面：diagram；核對方法示意｜累計自模組載入起；本例從 0 開始

[mc105] 工作進行時，看旁邊的計數有沒有增加。
[mc106] 完成後再查一次，用前後差值核對這次呼叫。

### r2-not-always-two

畫面：big；不必剛好等於**二**

[mc107] 同一個要求，模型可能用不同的方式處理。
[mc108] 要對得起來的，是新增次數和這次的事件。

### r2-question-edit

畫面：big；只改顯示文字，要重開嗎？

[mc110] 那把旁邊的文字改掉，需要重開一切嗎？

## 改字、歸零與停止使用

### r2-edit-label

畫面：code；改的是介面文字｜原英文 → 自訂中文

[mc111] 把顯示文字改成你看得懂的說法。
[mc112] 只改標籤，不動計數和工具執行流程。

### r2-reload

畫面：big；保存後，**重新載入**

[mc113] 用資料夾載入時，程式會監看檔案變更。
[mc114] 保存之後，新的介面文字就能在後續顯示。

### r2-reset

畫面：stats；入門範例的計數會重設

[mc115] 不過這個入門例子，把數字存在模組變數。
[mc116] 重新載入時，數字也會從零開始。

### r2-state-choice

畫面：big；需要保留？再加入狀態管理

[mc117] 如果你需要保存紀錄，就要另外管理狀態。
[mc118] 不要把入門例子，直接當成永久的統計報表。

### r2-stop-session

畫面：bullets；只載入這次對話，怎麼停用

[mc119] 這次是單次載入，結束對話就結束這次使用。
[mc120] 下次不帶那個載入參數，就不靠這個方式載入。
[mc121] 如果另做過常駐安裝，則要去外掛管理停用。

### r2-not-working

畫面：bullets；沒有反應，照這個順序查

[mc122] 排查時，先看版本，再看資料夾路徑。
[mc123] 接著看檔案名稱，有沒有打錯或放錯層。
[mc124] 最後看外掛或掛鉤，是不是被設定停用了。

### r2-surface

畫面：compare；指令能跑，畫面不一定會畫

[mc125] 你使用的入口，也會影響介面能不能出現。
[mc126] 非互動列印模式，沒有這種互動畫面。

### r2-no-cost-test

畫面：big；不想先跑模型？**先做離線測試**

[mc127] 如果只是核對加一的邏輯，可以先做離線測試。
[mc128] 用兩個假的工具事件，檢查回覆是不是兩次。

### r2-test-command

畫面：code；進階核對｜新版官方測試工具，非本機已跑結果

[mc129] 這種測試不需要登入，也不需要模型回合。
[mc130] 但測試過了，還是要實際看一次介面。

### r2-question-useful

畫面：big；知道怎麼改，還要知道何時值得改

[mc131] 計數器能幫你觀察流程，卻不會替你完成工作。
[mc132] 那你自己的工作，最缺哪一個看得見的資訊？
