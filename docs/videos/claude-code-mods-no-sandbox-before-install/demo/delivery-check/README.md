# 交稿檢查 Mod 原始碼

狀態：2026-10-09，站主親自執行 `plugin validate` 並貼回結果：**原生靜態驗證通過，只有缺少作者資訊的警告。** 事件與 API 清單符合候選程式；尚未驗證載入後的指令、面板、按鈕或錄製操作畫面。詳見 [驗證紀錄](../delivery-verification.md)。

這個範例將一套固定交付清單放進面板。它只在使用者開啟或按「重新檢查」時，查詢明確指定資料夾與以下三個路徑的狀態：

| 檔名 | 用途 |
| --- | --- |
| `article.md` | 文章 |
| `sources.md` | 資料依據 |
| `cover-brief.md` | 封面需求 |

## 查詢結果

- **路徑存在，內容待審閱**：狀態查詢回傳存在的路徑，可能是檔案、資料夾或其他種類。這個版本不判斷內容、檔案種類是否合適或能否交稿。
- **缺少**：只有可讀到明確 `ENOENT` 錯誤碼時才使用。
- **無法檢查**：包含存取遭拒、路徑中某段不是資料夾、回傳格式不明，以及無法辨認的錯誤。

原生錯誤的資料形狀仍待驗證。官方型別描述狀態查詢會帶 errno 拒絕，但沒有承諾 JavaScript 捕捉的錯誤一定保留 `code`。若目前主機只傳回錯誤訊息，本版會保守顯示「無法檢查」，**不能用猜測訊息或把所有失敗當缺少，掩蓋這個未完成的相容性檢查**。

## 原始碼分工

- `.claude-plugin/plugin.json`：套件名稱、版本及用途。
- `hooks/hooks.json`：指向唯一入口。
- `hooks/register.mjs`：官方 API 的接線，包含指令、手動狀態查詢及面板。
- `hooks/delivery-logic.mjs`：純資料函式，解析路徑、組合三個目標、區分結果、格式化時間。沒有主機 API 或檔案存取。
- `API-EVIDENCE.md`：官方來源、選用方法與尚未驗證的部分。

普通 Node 測試可以檢查純資料函式；這不是 Claude Code 的 `plugin validate`、`plugin test`，也不證明面板、回呼、錯誤傳遞或真實 Mod 已工作。入口程式不匯入 Node、第三方套件或外部檔案。

## 準備資料與未來試用步驟

完整起始內容與教學提示位於 `../../teaching-rewrite.md`。目錄安排如下；複製整個 Mod 目錄，不只複製入口檔。

```text
mods-lesson/
  delivery-practice/          起初只有 article.md 和 sources.md
  delivery-check/             這份完整程式目錄
```

先複製 `delivery-practice` 的絕對路徑。這個候選版本接受本機 Windows 磁碟路徑或 POSIX 絕對路徑；反斜線不做 shell 跳脫。相對路徑、`~` 展開、UNC 網路位置與 Windows 裝置路徑不在範例範圍。路徑必須對執行 Claude Code 的電腦有效。

**靜態驗證已有站主手動回報；以下單次載入與操作仍待執行。** 先前代理的 CLI 呼叫遭自動審查拒絕，站主手動驗證不代表代理的執行限制已解除。需在適用且允許的環境確認版本、原始碼及能力，再於 `mods-lesson` 單次載入；新副本須與已驗證原始碼相同：

```text
claude plugin validate ./delivery-check
claude --plugin-dir ./delivery-check
```

在該互動對話輸入下列指令，把欄位換成真正路徑並保留雙引號：

```text
/deliverables "<delivery-practice 的完整路徑>"
```

第一次未指定路徑，面板會要求提供，不猜預設位置。重新執行無參數的 `/deliverables`，會再查本次記住的資料夾；明確提供新路徑則換成新資料夾。記憶僅在目前模組生命週期，不保存到磁碟；重載或結束對話後需要重新指定。

面板位置由 Claude Code 決定，不保證固定右側。按「重新檢查」才更新狀態和 UTC 時間；重新繪圖本身不查檔，也沒有背景定時器。時間取得失敗會明說，不自行生成時間。關閉用面板按鈕或 Esc；關閉面板不等於卸載。結束這個單次載入的對話，之後不帶 `--plugin-dir` 啟動，才是不再以這種方式載入。

## 原生驗收進度

1. 已有站主手動回報：原生靜態驗證通過，辨識入口／相對匯入結構、四個事件及預期 API；只有 author 資訊警告。沒有附 exit code，不推算執行時間。
2. 指令實際接到含空格的 Windows／POSIX 路徑；無參數、引號不完整和換資料夾能清楚處理。
3. 真正缺檔時，確認捕捉錯誤的 errno 形狀。若沒有 `code`，先保存證據，再調整適用版本的辨識方式，不能把「無法檢查」剪成「缺少」。
4. 兩份起始材料 → 顯示第三份缺少 → 新增第三份 → 手動刷新後出現；過程保留實際路徑與時間。
5. 空白檔只顯示路徑存在；錯檔名仍指出約定路徑缺少；權限／主機錯誤維持無法檢查。
6. 開啟、刷新、換資料夾、關閉、重載與結束對話的真正畫面及狀態符合說明；其他面板仍由原處理程序呈現。
7. 純邏輯、原生靜態驗證與互動實測分開記錄。目前僅第 1 項有站主回報的通過結果，第 2–6 項仍待實測。

## 實作能力範圍

呼叫 `$.command.register`、`$.fs.stat`、`$.clock.now` 與 `$.ui.open/close/resolve/invalidate`。先檢查使用者指定的資料夾是否可查且為資料夾，再核對三個固定子路徑；不讀內容、不列目錄、不遞迴、不補檔、不寫檔。

程式沒有模型、提示提交、網路、程序、環境變數或持久儲存呼叫，也不修改或攔截其他工具。這只描述本程式；不表示 Claude Code 整個對話離線、免費或受同一層沙盒保護。
