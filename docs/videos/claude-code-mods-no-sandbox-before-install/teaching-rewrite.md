# Claude Code Mods：交稿前，先看缺了哪一份

2026-10-09｜原創教學段落草稿，供內容審查。未同步至 `video.json`／`script.md`，未製作旁白或成片，未核准發布。

主角是要交文章、資料依據和封面需求的一般使用者，不要求他理解 JavaScript。看完應能寫出自己的交付檢查需求、辨識缺件與內容品質的差別，並判斷一次提示、固定面板或修改回顧哪一種更適合。

**剪輯目標：** 正文約 8–10 分鐘；主案例與排錯占約一半，兩個短對照與變式練習占其餘篇幅。這是編排目標，尚無音訊或操作錄影可量測。完整提示詞提供複製版，口播解釋選擇，不逐字唸規則或指令；實際不足 8 分鐘時補有用的示範，不慢播或延長空畫面。

**示範狀態：** `delivery-check` 的候選原始碼已放在 [範例套件](demo/delivery-check/README.md)，完整起始材料在 [練習材料](demo/delivery-fixtures/README.md)。普通 Node 驗證已通過，站主另已貼回原生 `plugin validate` 通過結果，只有 author 資訊警告，詳見 [驗證範圍](demo/delivery-verification.md)。尚未驗證互動載入或錄製面板，不能宣稱 Mod 已跑通。先前代理 CLI 被拒的紀錄仍有效；站主手動回報不代表代理的執行限制解除。下列未執行步驟仍需未來實錄。

畫面標記：`【素材】` 是本稿原創文字；`【設計示意，未實測】` 是要驗收的介面；`【待實錄】` 必須取得真實操作才可替換。不得把示意改成假的終端輸出。未補證據前，這份稿子不是「實測完成版」。

## 2．先準備能核對的材料

**畫面｜【素材】** 新建專用的 `delivery-practice` 資料夾。三個英文檔名旁持續標中文用途；展示副檔名，避免存成 `.md.txt`。這裡使用純文字練習檔，不放私人稿件。

錄製時展示：在檔案管理器建立資料夾，用純文字編輯器存入下列兩份檔案，再從檔案管理器複製資料夾完整路徑。後續每個 `<貼上同一路徑>` 都換成這個實際路徑，不能連尖括號一起送出。

```text
mods-lesson/                 ← 建立及試用 Mod 時的終端機所在資料夾
  delivery-practice/        ← 先建立；存放本次文章練習檔
  delivery-check/           ← 候選 Mod 程式；可複製本稿附的完整範例目錄
  lesson-practice/          ← 最後變式練習才建立
```

Windows 在檔案總管打開 `delivery-practice`，點位址列、複製完整路徑。讓終端機位於其上一層 `mods-lesson`；鏡頭同時顯示資料夾結構和終端機目前路徑，不要求觀眾猜工作目錄。其他系統錄製時改用該系統的實際操作。

先建立 `article.md`：

```markdown

活動內容：每人帶一本最近讀過的書，分享其中一個觀點。

這是教學自製情境，不是真實活動公告。
```

此時**不建立** `cover-brief.md`。後面要用這個缺件驗證功能。

## 3．把想要的功能，說成可以驗收的要求

**畫面｜【素材】** 以下為完整原創提示詞；影片逐段說明重點，說明欄提供可複製全文。

```text
請幫我設計並建立一個 Claude Code Mod，名稱為 delivery-check。
我不會寫程式。我的需求是交稿前找出缺件，不是判斷文章品質。
練習資料夾的絕對路徑：<貼上同一路徑>
請把 Mod 程式放在目前 mods-lesson 下的 delivery-check 資料夾，
與存放練習檔的 delivery-practice 分開。

先產生程式與使用說明，列出使用到的能力；先不要載入或安裝。
依目前版本的官方文件和型別確認可行性。不支援的功能請明說，別用假資料補上。

功能：
1. 提供 /deliverables 指令，開啟「交稿檢查」畫面。
2. 第一次用 /deliverables "資料夾完整路徑" 指定要查的資料夾。
   正確處理路徑中的空格；把實際使用的絕對路徑顯示在畫面上。
   只在本次對話記住這個選擇；重載或結束對話會清除，需要重新指定。
   未指定時要求我提供，不猜其他資料夾。
   如果這種參數方式在目前版本不受支援，先說明，不自行換成默認目錄。
3. 先核對指定路徑是可檢查的資料夾，再查該資料夾下
   article.md、sources.md、cover-brief.md 這三個精確路徑。
   不遞迴掃描，不讀檔案內容，不修改或補建檔案。
4. 我開啟畫面或按「重新檢查」時才重新查詢。
   顯示本次檢查時間，沒有刷新時不可假裝資料是最新的。
5. 路徑存在，寫「路徑存在，內容待審閱」；不存在，寫「缺少」。
   權限或讀取環境出錯，寫「無法檢查」並顯示可理解的原因，不可當成缺少。
6. 不顯示完成百分比、不推算剩餘時間、不把三個路徑都存在寫成「可以交稿」。
7. 這個檢查功能不呼叫模型、不連網、不啟動其他程式。
   如果你認為需要上述能力，先說明原因，不要自行加入。

請附驗證步驟：
- 只有前兩個路徑時，第三項必須顯示缺少。
- 補上第三個後重新檢查，三項改成存在、內容待審閱。
- 即使第三個是空白檔，也不能判成內容合格。
- 換錯資料夾、改錯檔名，以及無法檢查時，要能辨識原因。

最後用一般使用者看得懂的方式，說明怎麼開啟、關閉和停止載入。
不要把還沒執行的測試寫成已通過。
```

**旁白**

這段比較長，但重點只有四件事：查哪裡、查哪三個名字、什麼時候重查，以及每個結果代表什麼。

只說「幫我檢查交稿」，它可能自己加一個品質評分，也可能直接替你補檔。我們現在只需要找缺件，所以把範圍寫明白。

還有一行很關鍵：出錯時，要說無法檢查。程式沒有權限看到檔案，不代表檔案不存在。

生成程式這一步可能使用模型用量。提示詞要求的是檢查功能本身不要再叫模型；不能因此說整個製作過程免費。

## 4．載入前，先看能力是否符合這件小事

Mod 會在你的電腦上執行。載入前先看來源和能力：只是找三份檔案，為什麼要連網或啟動其他程式？

Claude Code 的指令沙盒，不會自動套在 Mod 自行啟動的程序上。先核對程式，再用練習資料試。[來源 S1]

**畫面｜【待實錄 A】** 站主已提供 validate 通過的文字輸出，尚無錄影。下面三條不是全部已執行的紀錄；需分別記錄版本、驗證及互動載入。先確認終端機版本符合當時官方門檻；本次文件查核門檻為 2.1.287。再於 Mod 上層資料夾核對：

```text

claude plugin validate ./delivery-check
claude --plugin-dir ./delivery-check
```

本稿已附候選程式，validate 有站主手動通過的文字紀錄；互動載入尚無成功紀錄。正式教學仍需實際路徑、版本、檢查輸出及單次載入畫面。[來源 S2]

製作註：候選版只在錯誤物件明確帶有 `code: ENOENT` 時顯示缺少；未辨識的錯誤顯示無法檢查。官方型別沒有承諾捕捉到的錯誤形狀，必須在原生實測確認；若真缺檔卻顯示無法檢查，先修相容性，不能剪成成功。

## 8．兩個短對照：先選對需求，再選功能

### 對照一：今天只查一次，直接問就夠了

**畫面｜【素材】** 同樣三份交付，完整一次性提示：

```text
練習資料夾：<貼上同一路徑>
請只檢查該資料夾下 article.md、sources.md、cover-brief.md
這三個精確路徑是否存在。逐項列出存在、缺少或無法檢查。
不要讀內容、不要建立或修改檔案，也不要評分完成度。
```

**旁白**

如果今天只做這一次，直接問 Claude 查清單就夠了。我們換回最初只有兩份文件的練習副本，貼上同樣三個名字。

這次要拿到的是逐項檢查結果：文章有、資料依據有、封面需求缺少。回答的措辭可以不同，但三個名字與查詢的資料夾必須對得上。

如果它只有重述你的清單，卻沒有真的檢查資料夾，那還沒有回答問題。如果它沒辦法存取，就請它說清楚，改由你開資料夾核對；不要把一段肯定的文字當成檢查證據。

確認缺件後，就用剛才的提示詞補封面需求，再查一次。你完成的是同一件工作，只是結果出現在對話裡。

只有當這件事反覆發生，而你希望每次都用同一套規則、同一個按鈕和固定畫面，這個 Mod 的價值才更清楚。

不要先想要裝什麼。先問自己：我是在做一次工作，還是在改每天工作的介面？

**畫面｜【待實錄 G】** 一次性檢查同樣用缺第三份的副本。保留實際工具使用紀錄與查詢路徑，核對回答中的三項狀態，再補件與重查。畫面用對話和實際資料夾，不畫成 Mod。若檢查需要權限，展示適用環境的實際結果；尚未取得紀錄，不得標為已示範成功。

```text
其他內容保持不變。改完後列出修改前後的文字，並指出檔名。
```

**旁白**

如果你要查的是日期有沒有改對，剛才的缺件面板幫不上忙。兩次檢查都會說路徑存在，可是檔案裡的字已經變了。

這次我們先約定：練習裡把活動改到十月三十一日。送出提示後，打開真正的文章，找到日期那一行；再看地點、分享方式和待確認的報名方式，有沒有被順手改掉。

這個例子的合格結果很具體：日期改了，其他內容留下來。只收到「已完成」不算核對；只看到一段修改紀錄也不夠，因為那可能是失敗的嘗試。

只改一處，可以直接對照前後文字。經常一次改很多份，才值得考慮把變更回顧放進介面。

Anthropic 的公開範例 Replay Theater，展示的就是這種用途：把觀察到的編輯逐步攤開，方便回頭檢查。[來源 S3]

但記錄到編輯事件，不等於修改成功。這個範例也會記到後來被拒絕或失敗的呼叫，所以最後仍要打開真正的檔案核對。[來源 S3]

如果它連活動地點也改了，你就能指出具體差異：我只要求改日期，請把地點還原為里民活動中心。比起說「你又改錯了」，給出原值和改動範圍，才有下一次可驗收的結果。

**畫面｜【待實錄 F／或明標公開來源】** 若未取得本機回顧錄影，只能展示標明來源的官方文件，不能把上述日期練習合成為官方已跑過的案例。驗收需看日期是否改成 10 月 31 日，以及其他內容是否保留。

核對卡使用本稿的原始材料，標成「預期對照」：日期 `10 月 24 日 → 10 月 31 日`；地點保持 `里民活動中心`；活動內容和待確認的報名方式保持原文。實際結果欄等錄製後填，不預先打勾。

## 9．換成你自己的交付，規則怎麼改？

**畫面｜【素材】** 練習題：你要交的是課程大綱、練習題、答案。先列出三個確切名稱，再用下列提示修改既有需求。

另建 `lesson-practice` 資料夾，準備以下完整起始素材，先不建 `answer.md`。

`outline.md`：

```markdown
# 讀書會海報小練習
目標：分清標題、時間、地點三種資訊。
步驟：讀公告、找三項資訊、檢查缺了什麼。
```

`exercise.md`：

```markdown
# 練習題
公告：社區讀書會，10 月 24 日，在里民活動中心。
請寫出活動標題、時間和地點。
```

```text
請把交稿檢查的三個目標改為 outline.md、exercise.md、answer.md。
中文用途分別是課程大綱、練習題、參考答案。
新的練習資料夾：<貼上 lesson-practice 的完整路徑>
其他規則保留：指定資料夾、手動重新檢查、顯示實際檢查時間、
存在只代表路徑存在；無法檢查不算缺少，不顯示完成百分比。
先列出要改動的地方與驗證方式，不要自行載入。
```

取得修改方案後，以「請依剛才方案產生修改後的程式，列出改動，先不要載入」進行下一步。錄製者先核對修改與支援版本，再依第 4 節的單次載入流程試用；以新資料夾完整路徑開啟面板。這段修改、核對和重新載入同樣尚未執行，不可剪成提示詞送出就自動完成。

**旁白**

現在換你自己的工作。這次要交課程大綱、練習題和答案，你會改什麼？

主要改的是三個目標名稱和中文用途。存在、缺少、無法檢查的區分要留下來，檢查時間也要留下來。

做練習時，先只放大綱和題目，看看它能不能指出答案缺少。再補一份空白答案，確認它沒有跳成「課程完成」。最後放入真正答案，自己核對題目和答案能不能對上。

核對答案也放在這裡：活動標題是社區讀書會，時間是十月二十四日，地點是里民活動中心。如果你把答案寫成另一個地點，檢查面板仍會找到這個檔案；真正的內容核對會指出錯誤。

你也可以選自己的工作，例如報價單、品項表、交貨說明。先寫下確切檔名，再想一個缺件和一個內容錯誤。能分別查出這兩種問題，才知道自己的流程查到了哪裡。

你現在帶走的，不只是一個面板。你知道怎麼把工作需求寫成可檢查的條件，也知道檢查結果能回答什麼、還不能回答什麼。

**畫面｜【素材】** 最後使用的 `answer.md`：

```markdown
# 參考答案
活動標題：社區讀書會
時間：10 月 24 日
地點：里民活動中心
```
