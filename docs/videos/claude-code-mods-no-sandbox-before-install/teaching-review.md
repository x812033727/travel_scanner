## 我自己做錯的地方

1. **案例目的太弱。** `mc001–034` 讓觀眾知道次數不是完成度或帳單，卻沒有接到一個值得他使用的工作。主利益只剩「不用往上翻」。計數器適合短小的觀察練習，不足以獨占整支實用入門片。
2. **開始操作太晚。** 68 場裡，第 46 場才載入、第 50 場才做小工作。初學者先聽了大量機制，還沒有親眼看到解決的問題。
3. **例子沒有完整起點和終點。** 「讀示範資料」沒有配好資料內容、實際輸入、結果和核對紀錄。`demo/` 的 stub 測試範本不能證明真實讀檔或畫面。
4. **講過原因，不等於教會判斷。** 失敗仍可能計數、重載會歸零，都是值得學的差異，但目前只口述結論，沒有讓觀眾先預測、看結果、解釋差異。
5. **檢查了作品，沒有檢查學習。** 139 句、93 個畫面狀態、預計十分鐘、零裁切和通過測試，只證明製作的一部分。不能用這些數字回答使用者的批評。

## 示範完成的判準

每個核心例子須能在同一段找到：使用情境、完整輸入或準備資料、實際操作、可觀察結果、解釋、失敗檢查。至少再有一個對照例和一個可換成自己需求的練習；數量服務於學習，不是片長配額。

觀看者完成後須能：

- 說明這個功能解決哪件事，以及何時不需要它。
- 用提供的起始材料完成核心操作，核對結果，而非只抄一條命令。
- 辨識一個常見失敗，根據畫面或紀錄決定下一個檢查步驟。
- 換一個需求修改範例，並說明哪些條件應保留。

作者自行跑通只能證明操作可重現。還需由未參與撰稿者只憑教材重做並回報卡點；若執行環境尚未允許，就如實保持待驗，不把讀稿審查當成實作通過。
