# X11 FedEx｜製作、連結與上架交接

**交付級別：離線前製。** 目前沒有音檔、MiniMax 插圖、合成 MP4、正式 5 秒片頭或 21 秒片尾工作檔，也沒有可驗證的 YouTube 長片／Shorts ID；`youtube.video_id` 維持 `null`。草稿或 PR 是製作包，不是已上架影片。

1. 以 `video.json`、`shorts.json` 的確切 SHA，完成逐句一手來源覆核和**兩位獨立盲讀**；要檢查旁白、資料卡、縮圖文字、兩支 Shorts 的時間與主詞。改稿後重編並重審。正文需用正式 Sulafat 聲音量到 ≥8 分鐘；扣除 30–60 秒濃縮開場、結尾三句、5 秒片頭、21 秒片尾，不以卡片停留或靜音補時。
2. 在正式媒體工作區重新取本集 ledger、配額與乾跑價；滿足 [整片 US$25 硬上限](production-quote.md)才付款。TTS 後逐句對稿聽核、複查數字／財年／人名讀法及停頓。經人眼審可用的小批量圖片後才擴到 99 張；所有字由後製卡製作。配樂設定已在 `video.json`，不得把無音樂片說成正式版。
3. 取得**頻道選定**的 5 秒片頭與 21 秒 v4 片尾；片頭接在濃縮開場後，三句結尾後接片尾。按[畫面計畫](visual-plan.md)將 Express／Ground 與加拿大／美國的名稱和符號用後製角標標在已口播的關鍵鏡頭；確認 `x11-b06-s12` 不像同一市場兩種司機同站作業。輸出可關閉的繁中 CC，不燒字幕；兩支 25–55 秒 Shorts 從主片重用音訊與鏡頭。完成逐幀、畫面語意、字幕同步、響度及整檔 QA，再由站主看片。
4. 長片說明欄使用 `video.json` 的五份 **SEC 原始網址**；Shorts 各用 `shorts.json.links` 的相應原件。先取得真實長片 URL，再把該 URL 放入兩支 Shorts 的說明及 YouTube「相關影片」功能。不得用占位 `youtube.com/watch` 或猜測 ID 冒充可點連結。正式長片的 21 秒結束畫面在 YouTube Studio 設真實可點的訂閱與推薦影片元件，發布後逐一核對。
5. 最後回填公開長片、兩支 Shorts 真實 URL、可點片尾元件、CC、實際時長、媒體檔 SHA、來源網址和結算 ledger。站主看過成片後才依偏好選其他語言版本；沒有主機工作檔或 Studio 接入前，保持本機概念／前製狀態。

目前的 `youtube.description` 與兩支 Shorts 說明有直接 SEC 連結；「長片正式網址待發布後填入」只表示待辦，不是連結。畫面中的 FedEx 名稱只能用本機排字卡、縮圖文字和可查來源出現，匿名 AI 圖像不畫品牌商標或員工制服。
