## 站主觀點

同一題的輸出要和起點、驗收條件一起公開。這次只描述眼前實測，不把單次速度、訂閱制估值或登入障礙寫成產品排名；站主若有不同的頻道立場，以後台最新立場為準。

## 觀眾看完能做到的事

拿同一個小型任務，替候選工具固定起始程式與驗收測試，檢查能不能啟動、看差異與測試，再決定要不要交給真實專案。

## 觀眾與問題

已會看 Git 差異、會跑 Node 測試的開發者。問題是「Claude Code、Codex、Gemini CLI 怎麼選？」；本片回答「先看帳戶可用性，再看同題差異與驗收」。長度目標 8–12 分鐘，觀點解說加實作紀錄，不是完整安裝教學。

## 30 秒開場

三支工具接到同一題，兩支修好，一支連題目都讀不到。這不是誰最聰明的排行榜，而是你選工具前該做的三個檢查：能啟動、改了什麼、你的驗收過了嗎？

## 大綱 A（採用）

1. 題目與兩個起始測試：綠燈卻少一分。
2. 三支 CLI 的同題流程與原始差異：一支登入失敗，兩支修好。
3. 事後四個驗收測試：資料契約、極端案例、測試證據。
4. 怎麼選：可用性、變更品質、使用成本欄位分開記；只做自己的小型試驗。
