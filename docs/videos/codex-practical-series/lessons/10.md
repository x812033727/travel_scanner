# 10．用畫面條件改 UI：手機寬度與鍵盤操作都能驗收

狀態：教案與製作規格已撰寫；本頁沒有宣稱原生示範、模型實作或媒體已完成。題型：ui。兩支獨立影片：`codex-practical-10-app`、`codex-practical-10-cli`，各目標 12–18 分鐘，正文至少 8 分鐘，以例子、排錯與變式補內容。

## 觀眾、問題與成果

桌機看起來正常，style.css 的 min-width:900px 卻把手機撐寬。本集只改這個真實可測的版面問題，讓視覺改善也有驗收。

觀眾是會使用電腦、希望用 Codex 完成自己的小工作，但還不會可靠驗收的人。先備課程：09；先備是概念，不要求拿前集生成的成品。

1. 把『手機能用』拆成窄屏不溢位、長標題換行與控制項可觸及三項條件。
2. 用390px寬度與Tab/Enter完成一次任務操作，不只看桌機截圖。
3. 修CSS的固定最小寬度，保留資料邏輯與週報結果。

- 讀這些關鍵檔案：`index.html`、`style.css`、`app.mjs`。資料和介面以當集的 `lesson.json`、`acceptance.md` 與原始程式為準。

- App／CLI 各複製一份當集 start，使用不同目錄、新對話與證據。不匯入另一入口的聊天或修改；只看其中一支影片也有完整起點、需求、操作和驗收。

先將 `codex-practical-10-materials.zip` 解壓到新的資料夾；把 `$lessonRoot` 換成直接包含 `README.md`、`start`、`reference`、`challenge` 的本課解壓根目錄。下方從根目錄的 `start` 複製新工作副本，保留原始教材。每課 ZIP 已是完整一課，不需再接 `lessons/10`。

$lessonRoot = '<本課 ZIP 解壓目錄>'

if (-not (Test-Path -LiteralPath $lessonSource -PathType Container) -or -not (Test-Path -LiteralPath (Join-Path -Path $lessonRoot -ChildPath 'README.md') -PathType Leaf)) { throw '把 lessonRoot 換成本課 ZIP 解壓後直接含 README.md 和 start 的根目錄。' }

CLI 那份把副本尾碼改成 `10-cli`，從同一個未改的 start 再複製。已存在的副本不覆蓋、不刪除；停止後保留，重做用新名字。

## 主案例：完整輸入、操作與結果

這是要送出的任務文字，**尚不是已執行的聊天紀錄**。

```text
只改善UI，不更改core.mjs、儲存鍵、報表或資料格式。移除造成390px橫向頁面滾動的min-width:900px，讓長中文標題換行、輸入與按鈕適應窄屏。保留label、鍵盤操作及可見焦點。用390px與1280px檢查；不能截圖時明確寫未驗證，先給我完整操作清單。
```

1. 在瀏覽器開發工具設390px，記錄整頁橫向滾動與fixed min-width，不靠截圖縮小掩蓋。
2. 讓Codex把視覺要求落實到CSS；逐項看diff是否只影響UI，測試資料邏輯與週報不變。
3. 輸入長中文標題，用Tab移動到新增/完成/刪除，用Enter或Space操作，觀察焦點能否看見。
4. 回1280px核對layout，再重新整理確認持久化；同樣命令核對週報四個固定數字。

驗收命令由讀者在真實工作目錄自己執行：

```powershell
node --test
$LASTEXITCODE
node report.mjs fixtures/tasks.json --from 2026-10-05 --to 2026-10-11
```

預覽：

```powershell
py -m http.server 4173 --bind 127.0.0.1
```

另開瀏覽器至 `http://127.0.0.1:4173/`。這是本機練習，先開乾淨的瀏覽器 profile／該來源的練習資料；不要清除其他網站的資料。服務所在目錄必須是這個入口的工作副本。用 Ctrl+C 停服務後，才換另一份副本佔用相同 port。

應核對的外部行為：

- 390px不出現整頁橫向滾動，長標題可讀，按鈕不被裁切。
- Tab焦點可見；輸入標記與按鈕名稱清楚；鍵盤能新增、完成與刪除。

**預期和目前狀態：** 390px、1280px、Tab焦點與持久化畫面待真實瀏覽器驗收；CSS reference為作者示範。 執行前不填「實際」欄，沒有執行紀錄就保留未驗證；不能編成功的終端輸出、截圖或代理對話。

## App 與 CLI 各自怎麼完成

App：

在原生桌面 App 加入這份本機資料夾 `C:\codex-practice\10-app`，新開屬於此專案的 Local 聊天。先請模型回報 cwd 和當集檔案，再貼本集完整任務。讀工具紀錄、開啟實際修改檔與 diff；自行執行驗收，在瀏覽器操作，而不是用模型的完成文字替代。

CLI：

在 `C:\codex-practice\10-cli` 的 PowerShell 開互動 TUI，命令為 `codex -C . --sandbox workspace-write`；先貼要求確認 cwd，再送本集完整任務。退出 TUI 後自己跑驗收，將實際 exit code 與輸出和來源檔核對。保留原本的核準規則，不使用繞過核准或沙盒的捷徑。

CLI 錄製前先執行 `codex --version`、`codex --help`，必要時查子命令 `--help`。官方頁與本機版本可能不同；可用帳號／模型照使用者當前設定，錄製時記實際 model，不預先編費用、時間或成功率。功能不存在就修訂對應入口的教案，不拿另一入口的畫面補位。

## 常見失敗、修復與變式

只縮小字型使全部擠進去，或移除outline讓截圖變整潔；回到觸達和可讀條件。若只改螢幕截圖沒有程式碼diff，不能寫成UI實現。

遇到這個失敗時可送：

```text
請保留字型可讀與鍵盤焦點；只修造成390px整頁溢位的寬度與換行，逐項說明我應檢查哪個CSS和哪個操作，不使用隱藏overflow遮蔽控制項。
```

變式練習：加入100字以內的長中文標題，在360px與390px各核對；同時用鍵盤完成並刪除篩選內的任務。

答案與核對：answers.md 的第 10 集；答案含可重做的窄屏與鍵盤檢查，不以靜態截圖推斷資料或焦點行為。 看答案前先寫預測；回答須能指出輸入、操作、結果與原因。若以自己的需求替換資料，要同時重寫真相與驗收，不再套示範數字。
