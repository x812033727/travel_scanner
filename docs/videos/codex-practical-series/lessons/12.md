# 12．換一段對話也能接著做：用檔案交接，先驗過期說法

狀態：教案與製作規格已撰寫；本頁沒有宣稱原生示範、模型實作或媒體已完成。題型：handoff。兩支獨立影片：`codex-practical-12-app`、`codex-practical-12-cli`，各目標 12–18 分鐘，正文至少 8 分鐘，以例子、排錯與變式補內容。

## 觀眾、問題與成果

上個對話寫『週報全部完成』，新對話沒有那些細節。本集的handoff故意含過期宣告，教你以現有檔案和真相接手。

觀眾是會使用電腦、希望用 Codex 完成自己的小工作，但還不會可靠驗收的人。先備課程：11；先備是概念，不要求拿前集生成的成品。

1. 寫出含來源版本、實際狀態、未完成項與下一步的handoff。
2. 讓新對話先核對程式和測試，識別教材故意過期的完成宣告。
3. 把接手的第一個任務限制為可驗收的小步，不依賴上一段對話記憶。

## 材料、起點與介面

- 當集完整教材：[README](../materials/lessons/12/README.md)、[完整提示](../materials/lessons/12/prompts.md)、[驗收](../materials/lessons/12/acceptance.md)、[答案](../materials/lessons/12/answers.md)。
- 起點：`start/`（本課 ZIP 根目錄），比較答案：`reference/`（本課 ZIP 根目錄），變式：`challenge/`（本課 ZIP 根目錄）；reference 是作者實作，不是模型執行成果。
- 讀這些關鍵檔案：`docs/handoff.md`、`core.mjs`、`report.mjs`、`fixtures/tasks.json`、`core.test.mjs`。資料和介面以當集的 `lesson.json`、`acceptance.md` 與原始程式為準。
- 09–18 使用 `mokaair-codex-practical-v2`。v2 不存在才讀經驗證的 v1 轉移，保留原 v1 鍵；`completedAt` 為 canonical UTC 字串或 null，未知時間不能補今天。
- Node.js 22 以上相容版本，Python 3 預覽、Git；沒有 npm dependencies，不需要新增套件。記錄實際版本；只驗 Windows 的結果不能寫成跨平臺已通過。
- App／CLI 各複製一份當集 start，使用不同目錄、新對話與證據。不匯入另一入口的聊天或修改；只看其中一支影片也有完整起點、需求、操作和驗收。

先將 `codex-practical-12-materials.zip` 解壓到新的資料夾；把 `$lessonRoot` 換成直接包含 `README.md`、`start`、`reference`、`challenge` 的本課解壓根目錄。下方從根目錄的 `start` 複製新工作副本，保留原始教材。每課 ZIP 已是完整一課，不需再接 `lessons/12`。

```powershell
$lessonRoot = '<本課 ZIP 解壓目錄>'
$lessonSource = Join-Path -Path $lessonRoot -ChildPath 'start'
if (-not (Test-Path -LiteralPath $lessonSource -PathType Container) -or -not (Test-Path -LiteralPath (Join-Path -Path $lessonRoot -ChildPath 'README.md') -PathType Leaf)) { throw '把 lessonRoot 換成本課 ZIP 解壓後直接含 README.md 和 start 的根目錄。' }
$lessonWork = 'C:\codex-practice\12-app'
if (Test-Path -LiteralPath $lessonWork) { throw '這個副本已存在；保留它，選一個新的工作路徑。' }
New-Item -ItemType Directory -Path $lessonWork | Out-Null
Get-ChildItem -LiteralPath $lessonSource -Force | Copy-Item -Destination $lessonWork -Recurse
Set-Location -LiteralPath $lessonWork
Get-Location
node --version
git --version
node --test
$LASTEXITCODE
```

CLI 那份把副本尾碼改成 `12-cli`，從同一個未改的 start 再複製。已存在的副本不覆蓋、不刪除；停止後保留，重做用新名字。

## 主案例：完整輸入、操作與結果

這是要送出的任務文字，**尚不是已執行的聊天紀錄**。

```text
你是新的接手對話。先讀docs/handoff.md，再自行核對node --test與固定週報命令。不把檔案中的『已完成』當成事實；逐條標記已驗證、過期、未驗證，並附檔案或輸出。先修正交接狀態，再提出一個最小下一步；不得重新搭建專案或補造舊任務時間。
```

1. 在第一段對話整理任務、範圍、實際測試、尚未做的UI與來源，寫入docs/handoff.md；保留日期與當前本機commit（若有）。
2. 結束這一段工作，開本入口的新對話，明確只從檔案接手，不貼上整份舊聊天。
3. 新對話讀現有handoff、跑測試和報表；對照固定真相找出過期宣告，列清何者有證據。
4. 把核對後的狀態寫回handoff，附可複製的下一步與未完成項；另一入口仍用自己的副本。

驗收命令由讀者在真實工作目錄自己執行：

```powershell
node --test
$LASTEXITCODE
node report.mjs fixtures/tasks.json --from 2026-10-05 --to 2026-10-11
```

預覽：

```powershell
py -m http.server 4173 --bind 127.0.0.1
```

另開瀏覽器至 `http://127.0.0.1:4173/`。這是本機練習，先開乾淨的瀏覽器 profile／該來源的練習資料；不要清除其他網站的資料。服務所在目錄必須是這個入口的工作副本。用 Ctrl+C 停服務後，才換另一份副本佔用相同 port。

應核對的外部行為：

- handoff不把作者reference、檔案預期、測試綠與原生UI驗收混在一起。
- 新對話能指出過期項並根據實際原始檔繼續，不依賴口頭宣稱。

**預期和目前狀態：** 新對話接手與過期偵測未實跑；docs/handoff.md只是作者用於演練的輸入。 執行前不填「實際」欄，沒有執行紀錄就保留未驗證；不能編成功的終端輸出、截圖或代理對話。

## App 與 CLI 各自怎麼完成

App：

在同一個當集本機專案新開聊天，只提供 docs/handoff.md 路徑。讓新聊天自行讀現有檔案與測試，畫面取證要顯示新的聊天及來源，不把 CLI resume 或舊聊天答覆當成 App 接手。

CLI：

關閉舊 TUI，從同一個當集工作目錄以 codex -C . --sandbox workspace-write 新開對話，只貼交接 prompt 與檔案路徑。也能使用 codex resume 接續原對話，但那是另一種測試；本集驗收採新對話從檔案接手。

CLI 錄製前先執行 `codex --version`、`codex --help`，必要時查子命令 `--help`。官方頁與本機版本可能不同；可用帳號／模型照使用者當前設定，錄製時記實際 model，不預先編費用、時間或成功率。功能不存在就修訂對應入口的教案，不拿另一入口的畫面補位。

## 常見失敗、修復與變式

新模型重複『前一位已驗證』卻沒跑；要求引用當前命令與輸出。若無法執行，標未驗證並保留下一步，不把讀稿當驗收。

遇到這個失敗時可送：

```text
你沿用了handoff中的過期『全部通過』。請重新按現有core、fixture、node --test與報告輸出核對，修訂狀態；沒有執行證據就寫未驗證，保持其他專案內容不動。
```

變式練習：故意把handoff中的一個區間或檔名改成舊值，新開對話核對它是否發現，並記錄修正前後文字。

答案與核對：answers.md 的第 12 集；答案含來源、狀態、驗證命令、未完成項與下一步，過期說明必須以現存證據修正。 看答案前先寫預測；回答須能指出輸入、操作、結果與原因。若以自己的需求替換資料，要同時重寫真相與驗收，不再套示範數字。

| CLI 原生 | 真實 TUI/exec/review 紀錄、輸入輸出與 exit/status | pending_run |
| 學習 | 未參與撰稿者只憑教材重做、解釋、排錯及變式 | 待獨立重做 |
| 媒體 | 查核、旁白、畫面、字幕、成片與站主觀看 | 未開始 |

每支影片以「有用的結果」開場，再問與原做法怎麼選、完整操作、怎麼知道做對、失敗與變式。未實跑時先用明標的作者材料講預期，不在正式成片冒充模型成果；核心入口示範與學習檢查缺證據就退回。原生 App 不可存取時保持 pending_capture，公開官方頁截圖不能替代。

製作前由未撰稿者使用當集新副本重做，必須完成本頁成果、指出一個失敗原因、完成變式並核對答案。只有讀稿／程式檢查時如實記錄，不能寫「新手學會」。來源逐項查核；之後才配音、渲染、QA、站主觀看與上架，狀態分開。
