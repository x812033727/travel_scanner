# 16．把獨立檢查交給代理：回報要核對，主對話要負責

狀態：教案與製作規格已撰寫；本頁沒有宣稱原生示範、模型實作或媒體已完成。題型：subagents。兩支獨立影片：`codex-practical-16-app`、`codex-practical-16-cli`，各目標 12–18 分鐘，正文至少 8 分鐘，以例子、排錯與變式補內容。

## 觀眾、問題與成果

另一個模型說沒問題，也不等於你可以交。這裡讓兩位代理獨立讀不同方面，再由主對話負責確認，而不是增加兩份肯定的文字。

觀眾是會使用電腦、希望用 Codex 完成自己的小工作，但還不會可靠驗收的人。先備課程：15；先備是概念，不要求拿前集生成的成品。

1. 把資料/測試和鍵盤/UI審查拆成兩個不重疊的只讀子任務。
2. 檢視真實代理活動與回報，區分已啟動、已完成和已採納。
3. 用主對話複驗代理發現，合併成帶來源與待驗證項的交付結論。

## 材料、起點與介面

- 起點：`start/`（本課 ZIP 根目錄），比較答案：`reference/`（本課 ZIP 根目錄），變式：`challenge/`（本課 ZIP 根目錄）；reference 是作者實作，不是模型執行成果。
- 讀這些關鍵檔案：`docs/subagent-lab.md`、`core.mjs`、`core.test.mjs`、`app.mjs`、`style.css`、`core.test.mjs`。資料和介面以當集的 `lesson.json`、`acceptance.md` 與原始程式為準。
- 09–18 使用 `mokaair-codex-practical-v2`。v2 不存在才讀經驗證的 v1 轉移，保留原 v1 鍵；`completedAt` 為 canonical UTC 字串或 null，未知時間不能補今天。

## 主案例：完整輸入、操作與結果

這是要送出的任務文字，**尚不是已執行的聊天紀錄**。

```text
請使用恰好兩位只讀子代理：A 審 core.mjs、core.test.mjs、fixtures/tasks.json 與週報資料邊界，核對 5/2/1/1 並指出舊說明 completedInWeek=3 的錯誤；B 審 index.html、app.mjs、style.css 與 localStorage 的鍵盤及窄屏條件，實際操作才寫觀察，未操作寫 NOT RUN。兩位都不得改檔或呼叫付費外部工具，發現須附檔案/函式、觸發條件和核對方式。主對話收齊後自行復驗可跑專案，合併重複發現；沒有瀏覽器證據的UI寫未驗證。
```

1. 讀docs/subagent-lab.md，寫清任務A/B的輸入、範圍、輸出與完成條件，先說明為什麼兩項可獨立。
2. 明確要求恰好兩位代理，觀察本入口的真實活動，不把普通兩個回答段落當代理。
3. 分別核對代理回報的檔案位置、斷言與證據；主對話自己跑測試/報告，UI須實際操作或留待驗證。
4. 整理共同結論與下一步，附是否實際啟動/結束/複驗；一次沒發現不推論所有情境安全。

驗收命令由讀者在真實工作目錄自己執行：

```powershell
node --test
$LASTEXITCODE
node report.mjs fixtures/tasks.json --from 2026-10-05 --to 2026-10-11
```

預覽：

```powershell
py -m http.server 4173 --bind 127.0.0.1
```

另開瀏覽器至 `http://127.0.0.1:4173/`。這是本機練習，先開乾淨的瀏覽器 profile／該來源的練習資料；不要清除其他網站的資料。服務所在目錄必須是這個入口的工作副本。用 Ctrl+C 停服務後，才換另一份副本佔用相同 port。

應核對的外部行為：

- 有真實代理活動與不同任務，兩個回報保持只讀範圍。
- 結論能回溯原始檔與主對話複驗，代理意見、作者真相、使用者UI確認分別標記。

**預期和目前狀態：** 兩位代理的啟動、輸出、完成與主對話複驗皆未實跑；模板只是計畫輸入；reference 的分析是作者撰寫範例，沒有宣稱代理曾執行。 執行前不填「實際」欄，沒有執行紀錄就保留未驗證；不能編成功的終端輸出、截圖或代理對話。

## App 與 CLI 各自怎麼完成

App：

在主聊天貼恰好兩位代理的分工要求，展開真正的代理活動／對話，保留 A/B 的開始、來源範圍、完成與回報。主聊天最後自行驗證；代理活動尚未錄到時不能畫成兩位已完成。

CLI：

在互動 TUI 明確要求恰好兩個只讀子代理，使用 /agent 檢視／切換真實代理對話；儲存每位的範圍與結果，回主TUI做複驗。不要把shell兩個程序或列印兩段文字冒充原生子代理。

CLI 錄製前先執行 `codex --version`、`codex --help`，必要時查子命令 `--help`。官方頁與本機版本可能不同；可用帳號／模型照使用者當前設定，錄製時記實際 model，不預先編費用、時間或成功率。功能不存在就修訂對應入口的教案，不拿另一入口的畫面補位。

## 常見失敗、修復與變式

模型自行做完並沒啟動代理，或代理寫了同一檔案；如實記入口/策略結果，不偽造排程。發現不可重現先讓提供固定輸入，不因多人一致就採納。

遇到這個失敗時可送：

```text
目前沒有可驗證的兩位代理活動。請按A/B獨立只讀任務實際委派（入口不可用則明說），完成後給每位的範圍與原始發現；主對話複驗再下結論，不補造代理對話。
```

變式練習：故意給其中一位過期說明，讓它以源程式核對；主對話辨認未執行的畫面結論並要求進一步證據。

答案與核對：answers.md 的第 16 集；答案看委派範圍、真實活動、來源與複驗，不看代理人數或報告長度。 看答案前先寫預測；回答須能指出輸入、操作、結果與原因。若以自己的需求替換資料，要同時重寫真相與驗收，不再套示範數字。

## 證據與製作驗收

| 項目 | 必須儲存的證據 | 本頁狀態 |
| --- | --- | --- |
| 作者教材 | 起始與參考檔、來源雜湊、確定性測試 | 有規格；實際結果引用教材驗證收據 |
| 本入口模型 | 完整 prompt、版本/model、工具與修改、測試原文 | pending_run |
| App 原生 | 專案／模式／操作／結果的真實畫面與對應時間 | pending_capture |
| CLI 原生 | 真實 TUI/exec/review 紀錄、輸入輸出與 exit/status | pending_run |
| 學習 | 未參與撰稿者只憑教材重做、解釋、排錯及變式 | 待獨立重做 |
| 媒體 | 查核、旁白、畫面、字幕、成片與站主觀看 | 未開始 |

每支影片以「有用的結果」開場，再問與原做法怎麼選、完整操作、怎麼知道做對、失敗與變式。未實跑時先用明標的作者材料講預期，不在正式成片冒充模型成果；核心入口示範與學習檢查缺證據就退回。原生 App 不可存取時保持 pending_capture，公開官方頁截圖不能替代。

製作前由未撰稿者使用當集新副本重做，必須完成本頁成果、指出一個失敗原因、完成變式並核對答案。只有讀稿／程式檢查時如實記錄，不能寫「新手學會」。來源逐項查核；之後才配音、渲染、QA、站主觀看與上架，狀態分開。
