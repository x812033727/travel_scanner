# 02．先把需求講清楚：用 Plan 寫出能開工的計畫

狀態：教案與製作規格已撰寫；本頁沒有宣稱原生示範、模型實作或媒體已完成。題型：plan。兩支獨立影片：`codex-practical-02-app`、`codex-practical-02-cli`，各目標 12–18 分鐘，正文至少 8 分鐘，以例子、排錯與變式補內容。

## 觀眾、問題與成果

上一個任務能跑了，下一個需求是『加搜尋』。如果不先決定搜尋物件與它和篩選的關係，模型可以做好另一個功能，卻沒有做好你的功能。

觀眾是會使用電腦、希望用 Codex 完成自己的小工作，但還不會可靠驗收的人。先備課程：01；先備是概念，不要求拿前集生成的成品。

1. 把搜尋與篩選需求寫成範圍、輸入、可觀察結果，去掉『做漂亮一點』這種不可驗收的要求。
2. 在真正的 Plan 模式先讀專案，再得到可執行的步驟與待確認事項。
3. 用不改產品程式的差異檢查，區分計畫、實作與驗收。

## 材料、起點與介面

- 當集完整教材：[README](../materials/lessons/02/README.md)、[完整提示](../materials/lessons/02/prompts.md)、[驗收](../materials/lessons/02/acceptance.md)、[答案](../materials/lessons/02/answers.md)。
- 起點：`start/`（本課 ZIP 根目錄），比較答案：`reference/`（本課 ZIP 根目錄），變式：`challenge/`（本課 ZIP 根目錄）；reference 是作者實作，不是模型執行成果。
- 讀這些關鍵檔案：`docs/task-brief.md`、`docs/plan.md`、`app.mjs`、`core.mjs`、`core.test.mjs`。資料和介面以當集的 `lesson.json`、`acceptance.md` 與原始程式為準。
- 02–08 使用獨立練習鍵 `mokaair-codex-practical-v1`，資料為 `id/title/completed`。
- Node.js 22 以上相容版本，Python 3 預覽、Git；沒有 npm dependencies，不需要新增套件。記錄實際版本；只驗 Windows 的結果不能寫成跨平臺已通過。
- App／CLI 各複製一份當集 start，使用不同目錄、新對話與證據。不匯入另一入口的聊天或修改；只看其中一支影片也有完整起點、需求、操作和驗收。

先將 `codex-practical-02-materials.zip` 解壓到新的資料夾；把 `$lessonRoot` 換成直接包含 `README.md`、`start`、`reference`、`challenge` 的本課解壓根目錄。下方從根目錄的 `start` 複製新工作副本，保留原始教材。每課 ZIP 已是完整一課，不需再接 `lessons/02`。

## 主案例：完整輸入、操作與結果

這是要送出的任務文字，**尚不是已執行的聊天紀錄**。

```text
這一回合只規劃，不修改任何檔案。讀 docs/task-brief.md 與 app.mjs、core.mjs、core.test.mjs。目標：標題搜尋 trim 後不分大小寫，和 All/Active/Completed 取交集；空搜尋保留現有篩選，無結果顯示空狀態。列出要改的範圍、測試與瀏覽器驗收；明說目前哪些步驟尚未執行，不加入後端、登入或新套件。
```

1. 先讀 docs/task-brief.md，寫下搜尋範圍與三個篩選的交集；使用三筆固定任務 Read、Build、Review 作輸入。
2. 進入本入口的 Plan 模式，核對模式提示，再送完整規劃要求；單寫『先規劃』不是切換模式的證據。
3. 把回覆依需求、檔案、步驟、測試四欄核對；若漏空字串或 Completed 交集，在同一規劃對話補問。
4. 將採用的計畫文字記入教材的 docs/plan.md，註明由讀者記錄；核對產品程式沒有變更，後續實作放到第 03 集。

驗收命令由讀者在真實工作目錄自己執行：

```powershell
node --test
$LASTEXITCODE
```

預覽：

```powershell
py -m http.server 4173 --bind 127.0.0.1
```

另開瀏覽器至 `http://127.0.0.1:4173/`。這是本機練習，先開乾淨的瀏覽器 profile／該來源的練習資料；不要清除其他網站的資料。服務所在目錄必須是這個入口的工作副本。用 Ctrl+C 停服務後，才換另一份副本佔用相同 port。

應核對的外部行為：

- Read 未完成、Build 未完成、Review 完成；搜尋 re 配 Completed 預期只剩 Review。
- 本集只產生計畫與讀者的記錄；沒有聲稱搜尋已實作或瀏覽器已驗收。

**預期和目前狀態：** 預期得到決策完整的計畫；模型文字、模式畫面與產品差異皆待本入口實跑，reference 計畫是作者範本。 執行前不填「實際」欄，沒有執行紀錄就保留未驗證；不能編成功的終端輸出、截圖或代理對話。

## App 與 CLI 各自怎麼完成

App：

在原生聊天的新增選單選 Plan mode，確認畫面已有模式提示後才送規劃要求。先看計畫、未決項與產品 diff；模式畫面尚未取證就保持 pending_capture。讀者把採用文字存入 docs/plan.md 時另記為教材筆記，不宣稱 Plan 自動建立檔案。

CLI：

先啟動互動 TUI：codex -C . --sandbox read-only，再輸入 /plan 並確認模式。貼規劃 prompt；產品程式不得變更。/plan 是 TUI 控制，不放到 codex exec 的 prompt 裡當成切換模式。

CLI 錄製前先執行 `codex --version`、`codex --help`，必要時查子命令 `--help`。官方頁與本機版本可能不同；可用帳號／模型照使用者當前設定，錄製時記實際 model，不預先編費用、時間或成功率。功能不存在就修訂對應入口的教案，不拿另一入口的畫面補位。

## 常見失敗、修復與變式

模型在 Plan 回合提出執行或程式已變更；先確認實際模式與變更範圍，將計畫記錄與產品變更分開。漏規格時回到完整輸入補條件，不只要求『更仔細』。

遇到這個失敗時可送：

```text
請修訂計畫：目前漏了空搜尋、無結果與搜尋加 Completed 的交集。仍只規劃；逐條對應驗收案例，最後列出尚未執行的工作。
```

變式練習：把需求改成只搜尋 title，保留大小寫不敏感，但關鍵字為空時不過濾；自行給兩個正例、一個反例，判斷計畫是否包含它們。

答案與核對：answers.md 的第 02 集；核對搜尋不讀 id、trim 空白與交集，不以計畫篇幅評分。 看答案前先寫預測；回答須能指出輸入、操作、結果與原因。若以自己的需求替換資料，要同時重寫真相與驗收，不再套示範數字。

## 證據與製作驗收

| 項目 | 必須儲存的證據 | 本頁狀態 |
| --- | --- | --- |
| 作者教材 | 起始與參考檔、來源雜湊、確定性測試 | 有規格；實際結果引用教材驗證收據 |
| 本入口模型 | 完整 prompt、版本/model、工具與修改、測試原文 | pending_run |
| App 原生 | 專案／模式／操作／結果的真實畫面與對應時間 | pending_capture |
| CLI 原生 | 真實 TUI/exec/review 紀錄、輸入輸出與 exit/status | pending_run |
| 學習 | 未參與撰稿者只憑教材重做、解釋、排錯及變式 | 待獨立重做 |
| 媒體 | 查核、旁白、畫面、字幕、成片與站主觀看 | 未開始 |

每支影片以「有用的結果」開場，再問與原做法怎麼選、完整操作、怎麼知道做對、失敗與變式。未實跑時先用明標的作者材料講預期，不在正式成片冒充模型成果；核心入口示範與學習檢查缺證據就退回。原生 App 不可存取時保持 pending_capture，公開官方頁截圖不能替代。

製作前由未撰稿者使用當集新副本重做，必須完成本頁成果、指出一個失敗原因、完成變式並核對答案。只有讀稿／程式檢查時如實記錄，不能寫「新手學會」。來源逐項查核；之後才配音、渲染、QA、站主觀看與上架，狀態分開。
