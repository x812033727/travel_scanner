# 04．寫一份有用的 AGENTS.md：每次都能照規矩交付

狀態：教案與製作規格已撰寫；本頁沒有宣稱原生示範、模型實作或媒體已完成。題型：agents-md。兩支獨立影片：`codex-practical-04-app`、`codex-practical-04-cli`，各目標 12–18 分鐘，正文至少 8 分鐘，以例子、排錯與變式補內容。

## 觀眾、問題與成果

每次都要重說『不要加套件、保留儲存資料、列出測試』。本集只寫這個小專案真正需要的規則，再用一次變更驗證效果。

觀眾是會使用電腦、希望用 Codex 完成自己的小工作，但還不會可靠驗收的人。先備課程：03；先備是概念，不要求拿前集生成的成品。

1. 把經常重貼的範圍、測試與回報要求寫成當集專案的 AGENTS.md。
2. 在新對話只讀驗收，核對規則是否被讀取、資料真相與實際回報是否相符。
3. 區分當次需求、專案指示與強制測試，避免把 Markdown 當成硬性阻擋。

## 材料、起點與介面

- 當集完整教材：[README](../materials/lessons/04/README.md)、[完整提示](../materials/lessons/04/prompts.md)、[驗收](../materials/lessons/04/acceptance.md)、[答案](../materials/lessons/04/answers.md)。
- 起點：`start/`（本課 ZIP 根目錄），比較答案：`reference/`（本課 ZIP 根目錄），變式：`challenge/`（本課 ZIP 根目錄）；reference 是作者實作，不是模型執行成果。
- 讀這些關鍵檔案：`AGENTS.md`、`docs/data-contract.md`、`app.mjs`、`core.mjs`、`core.test.mjs`。資料和介面以當集的 `lesson.json`、`acceptance.md` 與原始程式為準。
- 02–08 使用獨立練習鍵 `mokaair-codex-practical-v1`，資料為 `id/title/completed`。
- Node.js 22 以上相容版本，Python 3 預覽、Git；沒有 npm dependencies，不需要新增套件。記錄實際版本；只驗 Windows 的結果不能寫成跨平臺已通過。
- App／CLI 各複製一份當集 start，使用不同目錄、新對話與證據。不匯入另一入口的聊天或修改；只看其中一支影片也有完整起點、需求、操作和驗收。

先將 `codex-practical-04-materials.zip` 解壓到新的資料夾；把 `$lessonRoot` 換成直接包含 `README.md`、`start`、`reference`、`challenge` 的本課解壓根目錄。下方從根目錄的 `start` 複製新工作副本，保留原始教材。每課 ZIP 已是完整一課，不需再接 `lessons/04`。

```powershell
$lessonRoot = '<本課 ZIP 解壓目錄>'
$lessonSource = Join-Path -Path $lessonRoot -ChildPath 'start'
if (-not (Test-Path -LiteralPath $lessonSource -PathType Container) -or -not (Test-Path -LiteralPath (Join-Path -Path $lessonRoot -ChildPath 'README.md') -PathType Leaf)) { throw '把 lessonRoot 換成本課 ZIP 解壓後直接含 README.md 和 start 的根目錄。' }
$lessonWork = 'C:\codex-practice\04-app'
if (Test-Path -LiteralPath $lessonWork) { throw '這個副本已存在；保留它，選一個新的工作路徑。' }
New-Item -ItemType Directory -Path $lessonWork | Out-Null
Get-ChildItem -LiteralPath $lessonSource -Force | Copy-Item -Destination $lessonWork -Recurse
Set-Location -LiteralPath $lessonWork
Get-Location
node --version
git --version
node --test
$LASTEXITCODE
```

CLI 那份把副本尾碼改成 `04-cli`，從同一個未改的 start 再複製。已存在的副本不覆蓋、不刪除；停止後保留，重做用新名字。

## 主案例：完整輸入、操作與結果

這是要送出的任務文字，**尚不是已執行的聊天紀錄**。

```text
只改 AGENTS.md 和 docs/data-contract.md。把目前 v1 的 id/title/completed、同名可用但 ID 唯一、篩選不改來源、儲存鍵、node --test 與瀏覽器 PASS/FAIL/NOT RUN 回報寫成可核對規則；先讀 core.mjs/app.mjs，不能憑空添加已實作功能。完成文件後新開對話，只讀驗收：列出實際讀取的規則、執行測試、解釋同名 ID 刪除與篩選真相，不改產品或測試。
```

1. 讀 AGENTS.md、docs/data-contract.md 與現有 core/app，把範圍、資料不變條件、檢查命令和未跑回報寫清楚；只修改這兩份文件。
2. 在同一副本的新對話送唯讀驗收要求；保留規則真正載入/讀取和測試的紀錄，不靠『我讀了』文字判定。
3. 比較 diff 只含 AGENTS.md/docs/data-contract.md；自己重跑 node --test，確認產品、既有測試和資料都沒有變更，未操作的瀏覽器條件保持 NOT RUN。
4. 在 challenge 副本讀 docs/rules-review.md，指出 title 當 ID 的規則與源程式/測試衝突，修文件規則並重新核對；不改產品去迎合錯誤規則。

驗收命令由讀者在真實工作目錄自己執行：

```powershell
node --test
$LASTEXITCODE
```

預覽：

```powershell
py -m http.server 4173 --bind 127.0.0.1
```

另開瀏覽器至 `http://127.0.0.1:4173/`。這是本機練習，先開乾淨的瀏覽器 profile／該來源的練習資料；不要清除其他網站的資料。服務所在目錄必須是這個入口的工作副本。用 Ctrl+C 停服務後，才換另一份副本佔用相同 port。

應核對的外部行為：

- 只更新文件規則；產品、任務資料、localStorage 鍵與既有測試保持一致。
- 規則讀取、差異範圍、實際測試三種證據分開記錄。

**預期和目前狀態：** 指示發現規則已由官方文件查核；當集的載入、遵循與對照結果未實跑。 執行前不填「實際」欄，沒有執行紀錄就保留未驗證；不能編成功的終端輸出、截圖或代理對話。

## App 與 CLI 各自怎麼完成

App：

在原生桌面 App 加入這份本機資料夾 `C:\codex-practice\04-app`，新開屬於此專案的 Local 聊天。先請模型回報 cwd 和當集檔案，再貼本集完整任務。讀工具紀錄、開啟實際修改檔與 diff；自行執行驗收，在瀏覽器操作，而不是用模型的完成文字替代。

CLI：

在 `C:\codex-practice\04-cli` 的 PowerShell 開互動 TUI，命令為 `codex -C . --sandbox workspace-write`；先貼要求確認 cwd，再送本集完整任務。退出 TUI 後自己跑驗收，將實際 exit code 與輸出和來源檔核對。保留原本的核準規則，不使用繞過核准或沙盒的捷徑。

CLI 錄製前先執行 `codex --version`、`codex --help`，必要時查子命令 `--help`。官方頁與本機版本可能不同；可用帳號／模型照使用者當前設定，錄製時記實際 model，不預先編費用、時間或成功率。功能不存在就修訂對應入口的教案，不拿另一入口的畫面補位。

## 常見失敗、修復與變式

新對話沒有反映規則；查工作目錄及祖先目錄的指示、是否使用當集副本、是否已開新工作階段。檔案有要求但沒有執行，只能算遵循失敗，不能改口成強制關卡成功。

遇到這個失敗時可送：

```text
請先停止新增變更。列出本次實際讀到的專案指示與來源路徑，再核對 diff、node --test 和未跑的瀏覽器檢查；有偏離範圍就只修偏離部分。
```

變式練習：讀 challenge 的 docs/rules-review.md 候選規則，指出以 title 當識別與穩定 ID/允許同名的衝突；只修 AGENTS.md/docs/data-contract.md，再用同名不同 ID 案例說明正確規則，不改產品。

答案與核對：answers.md 的第 04 集；答案含可操作的規則、一次小任務和成果核對，不用複製個人的全域設定。 看答案前先寫預測；回答須能指出輸入、操作、結果與原因。若以自己的需求替換資料，要同時重寫真相與驗收，不再套示範數字。

## 證據與製作驗收

| 項目 | 必須儲存的證據 | 本頁狀態 |
| --- | --- | --- |
| 作者教材 | 起始與參考檔、來源雜湊、確定性測試 | 有規格；實際結果引用教材驗證收據 |
| 本入口模型 | 完整 prompt、版本/model、工具與修改、測試原文 | pending_run |
| App 原生 | 專案／模式／操作／結果的真實畫面與對應時間 | pending_capture |
| CLI 原生 | 真實 TUI/exec/review 紀錄、輸入輸出與 exit/status | pending_run |
| 學習 | 未參與撰稿者只憑教材重做、解釋、排錯及變式 | 待獨立重做 |
| 媒體 | 查核、旁白、畫面、字幕、成片與站主觀看 | 未開始 |

每支影片以「有用的結果」開場，再問與原做法怎麼選、完整操作、怎麼知道做對、失敗與變式。未實跑時先用明標的作者材料講預期，不在正式成片冒充模型成果；核心入口示範與學習檢查缺證據就退回。原生 App 不可存取時保持 pending_capture，公開官方頁截圖不能替代。

製作前由未撰稿者使用當集新副本重做，必須完成本頁成果、指出一個失敗原因、完成變式並核對答案。只有讀稿／程式檢查時如實記錄，不能寫「新手學會」。來源逐項查核；之後才配音、渲染、QA、站主觀看與上架，狀態分開。
