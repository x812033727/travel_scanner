# 14．讓 Codex 查本地任務資料：接一個只讀 MCP

狀態：教案與製作規格已撰寫；本頁沒有宣稱原生示範、模型實作或媒體已完成。題型：mcp。兩支獨立影片：`codex-practical-14-app`、`codex-practical-14-cli`，各目標 12–18 分鐘，正文至少 8 分鐘，以例子、排錯與變式補內容。

## 觀眾、問題與成果

模型需要查固定任務資料，但不能把每次回答都當成它真的讀了檔案。本集用一個只讀本地工具，把查詢與來源證據接起來。

觀眾是會使用電腦、希望用 Codex 完成自己的小工作，但還不會可靠驗收的人。先備課程：13；先備是概念，不要求拿前集生成的成品。

1. 先測試本機stdio MCP服務，再在當前入口配置與核對連線。
2. 區分伺服器連上、工具被呼叫、來源結果被採用三種證據。
3. 用拒絕寫入與工具故障案例確認只讀邊界，不用外部帳號演練。

## 材料、起點與介面

- 當集完整教材：[README](../materials/lessons/14/README.md)、[完整提示](../materials/lessons/14/prompts.md)、[驗收](../materials/lessons/14/acceptance.md)、[答案](../materials/lessons/14/answers.md)。
- 起點：`start/`（本課 ZIP 根目錄），比較答案：`reference/`（本課 ZIP 根目錄），變式：`challenge/`（本課 ZIP 根目錄）；reference 是作者實作，不是模型執行成果。
- 讀這些關鍵檔案：`mcp-server.mjs`、`fixtures/tasks.json`、`tests/`、`docs/mcp-lab.md`。資料和介面以當集的 `lesson.json`、`acceptance.md` 與原始程式為準。
- 09–18 使用 `mokaair-codex-practical-v2`。v2 不存在才讀經驗證的 v1 轉移，保留原 v1 鍵；`completedAt` 為 canonical UTC 字串或 null，未知時間不能補今天。
- Node.js 22 以上相容版本，Python 3 預覽、Git；沒有 npm dependencies，不需要新增套件。記錄實際版本；只驗 Windows 的結果不能寫成跨平臺已通過。
- App／CLI 各複製一份當集 start，使用不同目錄、新對話與證據。不匯入另一入口的聊天或修改；只看其中一支影片也有完整起點、需求、操作和驗收。

先將 `codex-practical-14-materials.zip` 解壓到新的資料夾；把 `$lessonRoot` 換成直接包含 `README.md`、`start`、`reference`、`challenge` 的本課解壓根目錄。下方從根目錄的 `start` 複製新工作副本，保留原始教材。每課 ZIP 已是完整一課，不需再接 `lessons/14`。

## 主案例：完整輸入、操作與結果

這是要送出的任務文字，**尚不是已執行的聊天紀錄**。

```text
透過本集只讀MCP讀取練習任務，回答2026-10-05到2026-10-11的Asia/Taipei週報。列出你實際呼叫的工具/資源與來源資料，核對total5、completedInWeek2、pending1、unknownCompleted1。不得新增、修改或歸檔任務；工具不可用就回報錯誤，不猜數值，不把普通讀檔案結果說成MCP呼叫。
```

1. 先跑node --test，核對stdio協議、讀取fixture與拒絕寫入案例；原始stdout僅用於協議，日誌與說明不能汙染它。
2. 配置本入口的本地server；連線後先檢視它真實公佈的tools/resources與schema，再使用對應讀介面，不猜工具名。
3. 傳送固定查詢，儲存連線、呼叫、源fixture與最終四個數值證據；使用普通檔案讀取時明確區分。
4. 另用故障副本或停止server演練一次失敗，再恢復；工具失敗時沒有真實結果就不填成功答案。

驗收命令由讀者在真實工作目錄自己執行：

```powershell
node --test
$LASTEXITCODE
node --test tests/mcp.test.mjs
```

預覽：

```powershell
py -m http.server 4173 --bind 127.0.0.1
```

另開瀏覽器至 `http://127.0.0.1:4173/`。這是本機練習，先開乾淨的瀏覽器 profile／該來源的練習資料；不要清除其他網站的資料。服務所在目錄必須是這個入口的工作副本。用 Ctrl+C 停服務後，才換另一份副本佔用相同 port。

應核對的外部行為：

- 服務只讀取教材fixture；沒有修改、刪除、歸檔動作；未知完成時間仍單列。
- 有真正MCP呼叫與源資料對應，只有伺服器配置或最終答案都不夠。

**預期和目前狀態：** 本地server與協議測試為作者教材；原生MCP連線、工具呼叫和故障處理待當集實跑。 執行前不填「實際」欄，沒有執行紀錄就保留未驗證；不能編成功的終端輸出、截圖或代理對話。

## App 與 CLI 各自怎麼完成

App：

在這個練習專案的 .codex/config.toml 設定 practice_tasks，指向 C:/codex-practice/14-app/mcp-server.mjs；設定來源與可用工具需在原生 App 核對，仍未錄製。重開聊天後先檢視公佈的 list_tasks／read_weekly_report 與 practice://tasks／practice://weekly-report，再送固定查詢。使用專案設定，不改讀者的全域 MCP 清單。

CLI：

先 node --test tests/mcp.test.mjs。使用專案 .codex/config.toml，內容：[mcp_servers.practice_tasks]、command="node"、args=["C:/codex-practice/14-cli/mcp-server.mjs"]。重開 TUI 用 /mcp 核對，並用 codex mcp list 查設定；只有清單不代表連線成功。查詢透過 read_weekly_report 的 from/to 引數；stdio stdout 僅保留協議。

CLI 錄製前先執行 `codex --version`、`codex --help`，必要時查子命令 `--help`。官方頁與本機版本可能不同；可用帳號／模型照使用者當前設定，錄製時記實際 model，不預先編費用、時間或成功率。功能不存在就修訂對應入口的教案，不拿另一入口的畫面補位。

## 常見失敗、修復與變式

配置存在但沒有連線；先檢查node路徑、server絕對路徑與stdout是否夾入日誌。連上未呼叫或呼叫報錯分別記錄，不能合稱MCP正常。

遇到這個失敗時可送：

```text
MCP查詢失敗。先核對server命令和絕對路徑、stdio輸出與當前連線狀態，再手動跑已有協議測試；不要換成猜答案或增加寫許可權。修好後只重做固定只讀查詢。
```

變式練習：以 read_weekly_report 查 from=2026-10-12、to=2026-10-18，預測本週已知完成 0；再要求讀取不存在資源 practice://missing 及呼叫 write_task，核對真實拒絕，區分有效的零筆統計、資源錯誤與未提供的寫入工具。

答案與核對：answers.md 的第 14 集；以server實際tool/resource schema與拒寫測試為準，空查詢不編造任務。 看答案前先寫預測；回答須能指出輸入、操作、結果與原因。若以自己的需求替換資料，要同時重寫真相與驗收，不再套示範數字。
