# 11．重構不要順手改行為：把重複週報邏輯收回核心

狀態：教案與製作規格已撰寫；本頁沒有宣稱原生示範、模型實作或媒體已完成。題型：refactor。兩支獨立影片：`codex-practical-11-app`、`codex-practical-11-cli`，各目標 12–18 分鐘，正文至少 8 分鐘，以例子、排錯與變式補內容。

## 觀眾、問題與成果

頁面和命令列各算一次完成數，遲早會修好一邊忘了另一邊。本集把重複邏輯收回核心，教你在行為不變的條件下重構。

觀眾是會使用電腦、希望用 Codex 完成自己的小工作，但還不會可靠驗收的人。先備課程：09、10；先備是概念，不要求拿前集生成的成品。

1. 找到UI與CLI重複計算週報的位置，說明一個權威邏輯來源的用途。
2. 重構後以相同fixture證明欄位、區間與結果保持一致。
3. 用未知時間、區間邊界與輸入不變的測試守住外部行為。

## 材料、起點與介面

- 當集完整教材：[README](../materials/lessons/11/README.md)、[完整提示](../materials/lessons/11/prompts.md)、[驗收](../materials/lessons/11/acceptance.md)、[答案](../materials/lessons/11/answers.md)。
- 起點：`start/`（本課 ZIP 根目錄），比較答案：`reference/`（本課 ZIP 根目錄），變式：`challenge/`（本課 ZIP 根目錄）；reference 是作者實作，不是模型執行成果。
- 讀這些關鍵檔案：`core.mjs`、`report.mjs`、`app.mjs`、`core.test.mjs`。資料和介面以當集的 `lesson.json`、`acceptance.md` 與原始程式為準。
- 09–18 使用 `mokaair-codex-practical-v2`。v2 不存在才讀經驗證的 v1 轉移，保留原 v1 鍵；`completedAt` 為 canonical UTC 字串或 null，未知時間不能補今天。
- Node.js 22 以上相容版本，Python 3 預覽、Git；沒有 npm dependencies，不需要新增套件。記錄實際版本；只驗 Windows 的結果不能寫成跨平臺已通過。
- App／CLI 各複製一份當集 start，使用不同目錄、新對話與證據。不匯入另一入口的聊天或修改；只看其中一支影片也有完整起點、需求、操作和驗收。

先將 `codex-practical-11-materials.zip` 解壓到新的資料夾；把 `$lessonRoot` 換成直接包含 `README.md`、`start`、`reference`、`challenge` 的本課解壓根目錄。下方從根目錄的 `start` 複製新工作副本，保留原始教材。每課 ZIP 已是完整一課，不需再接 `lessons/11`。

## 主案例：完整輸入、操作與結果

這是要送出的任務文字，**尚不是已執行的聊天紀錄**。

```text
這是行為不變的重構。report.mjs 有重複週報計算，改成呼叫 core.mjs 的 weeklyReport，讓UI與CLI共用。保留 CLI 引數、輸出欄位、timezone、含首尾規則與嚴格日曆錯誤行為；重構前後 2026-02-30 都須拒絕，不能順便放寬或加改行為；不得改fixture來通過。先記錄固定命令的before，再改、跑node --test與同命令after，逐欄位比對並確認原資料不變。
```

1. 先跑固定報告儲存before，並把日期/未知分類對到程式碼位置。
2. 找出report.mjs內的重複計算與core.weeklyReport邊界，確定抽取後誰負責解析引數、誰負責業務計算。
3. 讓Codex窄重構；對照diff確認沒有改輸出契約或新增套件。
4. 跑完整測試和同一報告儲存after，比較關鍵欄位與錯誤情況，UI再檢視相同周區間。

驗收命令由讀者在真實工作目錄自己執行：

```powershell
node --test
$LASTEXITCODE
node report.mjs fixtures/tasks.json --from 2026-10-05 --to 2026-10-11
node report.mjs fixtures/tasks.json --from 2026-02-30 --to 2026-03-01
$LASTEXITCODE
```

預覽：

```powershell
py -m http.server 4173 --bind 127.0.0.1
```

另開瀏覽器至 `http://127.0.0.1:4173/`。這是本機練習，先開乾淨的瀏覽器 profile／該來源的練習資料；不要清除其他網站的資料。服務所在目錄必須是這個入口的工作副本。用 Ctrl+C 停服務後，才換另一份副本佔用相同 port。

應核對的外部行為：

- 非法日曆日期 2026-02-30 在重構前後皆非零退出；錯誤行為與合法報表一起比對。

- before/after同fixture仍total5、completedInWeek2、pending1、unknownCompleted1、timezone一致。
- CLI仍能讀取同路徑與引數，輸入資料沒有被寫回或排序。

**預期和目前狀態：** 作者reference展示共用函式，Codex重構、before/after與相容驗收皆待實跑。 執行前不填「實際」欄，沒有執行紀錄就保留未驗證；不能編成功的終端輸出、截圖或代理對話。

## App 與 CLI 各自怎麼完成

App：

在原生桌面 App 加入這份本機資料夾 `C:\codex-practice\11-app`，新開屬於此專案的 Local 聊天。先請模型回報 cwd 和當集檔案，再貼本集完整任務。讀工具紀錄、開啟實際修改檔與 diff；自行執行驗收，在瀏覽器操作，而不是用模型的完成文字替代。

CLI：

在 `C:\codex-practice\11-cli` 的 PowerShell 開互動 TUI，命令為 `codex -C . --sandbox workspace-write`；先貼要求確認 cwd，再送本集完整任務。退出 TUI 後自己跑驗收，將實際 exit code 與輸出和來源檔核對。保留原本的核準規則，不使用繞過核准或沙盒的捷徑。

CLI 錄製前先執行 `codex --version`、`codex --help`，必要時查子命令 `--help`。官方頁與本機版本可能不同；可用帳號／模型照使用者當前設定，錄製時記實際 model，不預先編費用、時間或成功率。功能不存在就修訂對應入口的教案，不拿另一入口的畫面補位。

## 常見失敗、修復與變式

模型順手升級schema或換欄位名；用before/after與原引數揭露相容性變化。測試綠但舊CLI指令碼不能用也是失敗，須恢復契約。

遇到這個失敗時可送：

```text
這次是重構，不接受欄位/引數變化。恢復原CLI介面，只抽業務計算到weeklyReport；用原fixture與相同命令證明before/after一致，再列出真正減少的重複部分。
```

變式練習：加入「全部任務待辦」與「全部完成但時間未知」兩份小輸入，確認UI與CLI共用函式不會憑空算出本週完成。

答案與核對：answers.md 的第 11 集；對照weeklyReport與report入口職責、零完成情況和輸入不變。 看答案前先寫預測；回答須能指出輸入、操作、結果與原因。若以自己的需求替換資料，要同時重寫真相與驗收，不再套示範數字。
