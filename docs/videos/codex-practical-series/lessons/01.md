# 01．接手專案先建立基準：知道哪裡能跑、哪裡還沒做

狀態：教案與製作規格已撰寫；本頁沒有宣稱原生示範、模型實作或媒體已完成。題型：baseline。兩支獨立影片：`codex-practical-01-app`、`codex-practical-01-cli`，各目標 12–18 分鐘，正文至少 8 分鐘，以例子、排錯與變式補內容。

## 觀眾、問題與成果

第一次請 AI 做網站，回覆說完成，卻不知道應該先看什麼。本集從五個檔案與一個有理由的紅燈開始，讓第一項工作有起點、差異與終點。

觀眾是會使用電腦、希望用 Codex 完成自己的小工作，但還不會可靠驗收的人。先備課程：無；只需能開資料夾與照打命令。

1. 建立只含本集起始五檔的工作副本，跑出並解讀教材基準 2 通過／1 失敗。
2. 分辨起始版刻意未完成的篩選、作者參考版 3 通過與模型實作成果三種狀態。
3. 用本機 HTTP 預覽驗證已存在的新增、完成與儲存，寫出第 03 集要接手的範圍。

## 材料、起點與介面

- 當集完整教材：[README](../materials/lessons/01/README.md)、[完整提示](../materials/lessons/01/prompts.md)、[驗收](../materials/lessons/01/acceptance.md)、[答案](../materials/lessons/01/answers.md)。
- 起點：`start/`（本課 ZIP 根目錄），比較答案：`reference/`（本課 ZIP 根目錄），變式：`challenge/`（本課 ZIP 根目錄）；reference 是作者實作，不是模型執行成果。
- 讀這些關鍵檔案：`index.html`、`style.css`、`app.js`、`core.mjs`、`core.test.mjs`。資料和介面以當集的 `lesson.json`、`acceptance.md` 與原始程式為準。
- 01 使用原 Small Steps 的 `mokaair-codex-todo-v1`。
- Node.js 22 以上相容版本，Python 3 預覽、Git；沒有 npm dependencies，不需要新增套件。記錄實際版本；只驗 Windows 的結果不能寫成跨平臺已通過。
- App／CLI 各複製一份當集 start，使用不同目錄、新對話與證據。不匯入另一入口的聊天或修改；只看其中一支影片也有完整起點、需求、操作和驗收。

先將 `codex-practical-01-materials.zip` 解壓到新的資料夾；把 `$lessonRoot` 換成直接包含 `README.md`、`start`、`reference`、`challenge` 的本課解壓根目錄。下方從根目錄的 `start` 複製新工作副本，保留原始教材。每課 ZIP 已是完整一課，不需再接 `lessons/01`。

```powershell
$lessonRoot = '<本課 ZIP 解壓目錄>'
$lessonSource = Join-Path -Path $lessonRoot -ChildPath 'start'
if (-not (Test-Path -LiteralPath $lessonSource -PathType Container) -or -not (Test-Path -LiteralPath (Join-Path -Path $lessonRoot -ChildPath 'README.md') -PathType Leaf)) { throw '把 lessonRoot 換成本課 ZIP 解壓後直接含 README.md 和 start 的根目錄。' }
$lessonWork = 'C:\codex-practice\01-app'
if (Test-Path -LiteralPath $lessonWork) { throw '這個副本已存在；保留它，選一個新的工作路徑。' }
New-Item -ItemType Directory -Path $lessonWork | Out-Null
Get-ChildItem -LiteralPath $lessonSource -Force | Copy-Item -Destination $lessonWork -Recurse
Set-Location -LiteralPath $lessonWork
Get-Location
node --version
git --version
node --test core.test.mjs
$LASTEXITCODE
```

CLI 那份把副本尾碼改成 `01-cli`，從同一個未改的 start 再複製。已存在的副本不覆蓋、不刪除；停止後保留，重做用新名字。

## 主案例：完整輸入、操作與結果

這是要送出的任務文字，**尚不是已執行的聊天紀錄**。

```text
先只讀，不修改任何檔案。讀 index.html、style.css、app.js、core.mjs、core.test.mjs，指出畫面、資料邏輯與測試分工。執行 node --test core.test.mjs，列出實際通過、失敗與退出碼，確認 visibleTasks 的篩選是教材刻意留給第03集的工作。不要修復或修改測試。最後交出當前基準、尚未完成項及我應操作的瀏覽器清單。
```

1. 在 start 工作副本跑 node --test core.test.mjs；教材預期 2 通過、1 失敗與非零退出碼，照實記錄，沒有修程式。
2. 讀 core.test.mjs 的 filters 斷言與 core.mjs 的 visibleTasks，說明失敗對應尚未完成的功能，不把刻意紅燈當環境壞掉。
3. 啟動 start 的 HTTP 預覽，新增 Read/Build、完成 Read、重新整理；Active/Completed 尚未正確過濾是起始限制，記到待做。
4. 另複製 reference 到不同資料夾，跑相同測試作作者答案對照：預期3通過。記下第03集只補篩選與搜尋的下一步，不把reference當模型成果。

驗收命令由讀者在真實工作目錄自己執行：

```powershell
node --test core.test.mjs
$LASTEXITCODE
```

預覽：

```powershell
py -m http.server 4173 --bind 127.0.0.1
```

另開瀏覽器至 `http://127.0.0.1:4173/`。這是本機練習，先開乾淨的瀏覽器 profile／該來源的練習資料；不要清除其他網站的資料。服務所在目錄必須是這個入口的工作副本。用 Ctrl+C 停服務後，才換另一份副本佔用相同 port。

應核對的外部行為：

- start 已有新增、完成、刪除及儲存；篩選尚未完成，切Active/Completed仍會顯示全部是要交接的缺口。
- reference 預期3通過；它是作者寫好的比較材料，沒有在本集請Codex實作。

**預期和目前狀態：** start 核心測試預期2通過/1失敗，作者reference預期3通過；本集不實作篩選。模型的只讀基準核對與本入口畫面仍待實跑。 執行前不填「實際」欄，沒有執行紀錄就保留未驗證；不能編成功的終端輸出、截圖或代理對話。

## App 與 CLI 各自怎麼完成

App：

先在原生 App 的本機專案確認五個檔案，送出只讀要求。開啟它真正讀檔與執行測試的紀錄；在內建終端機或附屬終端機自行重跑。主畫面要能看到 start 的 2 通過／1 失敗，並把 reference 的 3 通過標成作者比較；沒有任何實作完成的宣稱。

CLI：

在終端機執行 codex -C . --sandbox read-only。把只讀 prompt 貼進 TUI；用真實工具紀錄核對五個檔案及 2 通過／1 失敗。退出後自己重跑測試；reference 對照在另一個副本，不能由複製答案冒充模型修復。首次登入由讀者完成，不將驗證碼或金鑰放進教材。

CLI 錄製前先執行 `codex --version`、`codex --help`，必要時查子命令 `--help`。官方頁與本機版本可能不同；可用帳號／模型照使用者當前設定，錄製時記實際 model，不預先編費用、時間或成功率。功能不存在就修訂對應入口的教案，不拿另一入口的畫面補位。

## 常見失敗、修復與變式

找不到檔案或測試不是 2/1；先用 Get-Location 與 Get-ChildItem 查根目錄，不為了湊結果改測試。若瀏覽器看得到網站卻不載入模組，確認使用 http://127.0.0.1:4173 而不是 file://。

遇到這個失敗時可送：

```text
我的工作目錄或HTTP預覽不對。先不要改程式；核對Get-Location、五份起始檔、node --version和啟動命令，指出應重做哪一步。測試2通過1失敗是本集預期，不要為它改測試。
```

變式練習：在兩份全新副本分別執行 start 與 reference 的同一測試，說明為什麼只有起始版紅燈，再寫一段給第03集的窄範圍交接。

答案與核對：answers.md 的第 01 集；核對 start=2通過/1失敗、reference=3通過、兩份目錄及第03集待做scope，不修改產品程式碼。 看答案前先寫預測；回答須能指出輸入、操作、結果與原因。若以自己的需求替換資料，要同時重寫真相與驗收，不再套示範數字。

## 證據與製作驗收

| 項目 | 必須儲存的證據 | 本頁狀態 |
| --- | --- | --- |
| 作者教材 | 起始與參考檔、來源雜湊、確定性測試 | 有規格；實際結果引用教材驗證收據 |
| 本入口模型 | 完整 prompt、版本/model、工具與修改、測試原文 | pending_run |
| App 原生 | 專案／模式／操作／結果的真實畫面與對應時間 | pending_capture |
| CLI 原生 | 真實 TUI/exec/review 紀錄、輸入輸出與 exit/status | pending_run |
| 學習 | 未參與撰稿者只憑教材重做、解釋、排錯及變式 | 待獨立重做 |
| 媒體 | 查核、旁白、畫面、字幕、成片與站主觀看 | 未開始 |

每支影片以「有用的結果」開場，再問與原做法怎麼選、完整操作、怎麼知道做對、失敗與變式。未實跑時先用明標的作者材料講預期，不在正式成片冒充模型成果；核心入口示範與學習檢查缺證據就退回。原生 App 不可存取時保持 pending_capture，公開官方頁截圖不能替代。

製作前由未撰稿者使用當集新副本重做，必須完成本頁成果、指出一個失敗原因、完成變式並核對答案。只有讀稿／程式檢查時如實記錄，不能寫「新手學會」。來源逐項查核；之後才配音、渲染、QA、站主觀看與上架，狀態分開。
