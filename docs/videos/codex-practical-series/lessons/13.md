# 13．把驗收流程做成 Skill：能被找到，也真的做完檢查

狀態：教案與製作規格已撰寫；本頁沒有宣稱原生示範、模型實作或媒體已完成。題型：skill。兩支獨立影片：`codex-practical-13-app`、`codex-practical-13-cli`，各目標 12–18 分鐘，正文至少 8 分鐘，以例子、排錯與變式補內容。

## 觀眾、問題與成果

每次交付都重貼三段檢查。這裡用一份小Skill儲存驗收流程，教你先看它有沒有被使用，再看檢查有沒有完成。

觀眾是會使用電腦、希望用 Codex 完成自己的小工作，但還不會可靠驗收的人。先備課程：12；先備是概念，不要求拿前集生成的成品。

1. 將重複的測試、週報真相與UI清單寫成專案範圍的verify-delivery技能。
2. 分別確認檔案有效、被發現、被選擇與檢查完成四種狀態。
3. 用一個失敗案例驗證技能會保留問題與待驗證項，不把提醒寫成強制關卡。

## 材料、起點與介面

- 當集完整教材：[README](../materials/lessons/13/README.md)、[完整提示](../materials/lessons/13/prompts.md)、[驗收](../materials/lessons/13/acceptance.md)、[答案](../materials/lessons/13/answers.md)。
- 起點：`start/`（本課 ZIP 根目錄），比較答案：`reference/`（本課 ZIP 根目錄），變式：`challenge/`（本課 ZIP 根目錄）；reference 是作者實作，不是模型執行成果。
- 讀這些關鍵檔案：`.agents/skills/verify-delivery/SKILL.md`、`core.test.mjs`、`fixtures/tasks.json`、`report.mjs`。資料和介面以當集的 `lesson.json`、`acceptance.md` 與原始程式為準。
- 09–18 使用 `mokaair-codex-practical-v2`。v2 不存在才讀經驗證的 v1 轉移，保留原 v1 鍵；`completedAt` 為 canonical UTC 字串或 null，未知時間不能補今天。
- Node.js 22 以上相容版本，Python 3 預覽、Git；沒有 npm dependencies，不需要新增套件。記錄實際版本；只驗 Windows 的結果不能寫成跨平臺已通過。
- App／CLI 各複製一份當集 start，使用不同目錄、新對話與證據。不匯入另一入口的聊天或修改；只看其中一支影片也有完整起點、需求、操作和驗收。

## 主案例：完整輸入、操作與結果

這是要送出的任務文字，**尚不是已執行的聊天紀錄**。

```text
請使用本專案的 $verify-delivery，驗證當前任務與週報工具。遵照技能中的node --test、固定報告真相與瀏覽器檢查；逐項記錄實際、失敗與未驗證。如果無法操作瀏覽器，不寫UI通過。只驗收與回報，不修改程式、資料或使用者全域設定。
```

1. 先讀SKILL.md frontmatter的name/description與步驟，核對它只用於當前專案交付，並指向真實命令與fixture。
2. 在本入口重新整理發現技能（若未出現則重啟），顯式選verify-delivery並送完整要求；保留髮現與選擇紀錄。
3. 核對實際工具執行與結果表，不能只憑『已呼叫技能』確認完成；UI看不到就留待驗證。
4. 在全新challenge副本再驗證一項錯誤；觀察技能是否記失敗，而不是改測試或替你靜默修好。

驗收命令由讀者在真實工作目錄自己執行：

```powershell
node --test
$LASTEXITCODE
node report.mjs fixtures/tasks.json --from 2026-10-05 --to 2026-10-11
```

預覽：

```powershell
py -m http.server 4173 --bind 127.0.0.1
```

另開瀏覽器至 `http://127.0.0.1:4173/`。這是本機練習，先開乾淨的瀏覽器 profile／該來源的練習資料；不要清除其他網站的資料。服務所在目錄必須是這個入口的工作副本。用 Ctrl+C 停服務後，才換另一份副本佔用相同 port。

應核對的外部行為：

- 技能包含name/description，清楚說明何時用；專案目錄是.agents/skills/verify-delivery。
- 結果分別列測試、報告數值、UI；未知、失敗與未驗證不會合併成通過。

**預期和目前狀態：** 技能檔案由作者提供；在App或CLI出現、被選擇、完成驗收與失敗案例均待該入口實跑。 執行前不填「實際」欄，沒有執行紀錄就保留未驗證；不能編成功的終端輸出、截圖或代理對話。

## App 與 CLI 各自怎麼完成

App：

在本機專案檢視 verify-delivery 的技能清單或選擇器，再於聊天明確送出 $verify-delivery。若沒出現，先核對 .agents/skills 路徑並重啟／重開；清單、被選擇、實際執行檢查要分三段取證。

CLI：

在互動 TUI 用 /skills 檢視，輸入 $verify-delivery 明確叫技能；若用 / 互動選單，核對選中的真實名稱。執行紀錄要包含 node --test 與固定報告，單一『已使用』答覆不算驗收。

CLI 錄製前先執行 `codex --version`、`codex --help`，必要時查子命令 `--help`。官方頁與本機版本可能不同；可用帳號／模型照使用者當前設定，錄製時記實際 model，不預先編費用、時間或成功率。功能不存在就修訂對應入口的教案，不拿另一入口的畫面補位。

## 常見失敗、修復與變式

技能看不到；核對目錄層級、frontmatter和當前repo範圍，按官方文件重啟再看。看得到但沒執行檢查，屬於使用或遵循失敗，不是安裝問題。

遇到這個失敗時可送：

```text
verify-delivery已被選擇，但結果沒有實際測試/報告命令。請只執行技能中已有的可用檢查，逐項給實際輸出；無法驗證的UI保留未驗證，不改產品程式碼。
```

變式練習：把某一項固定報告預期寫錯，執行技能並要求以fixtures真相定位差異，再修技能說明而不是改fixture。

答案與核對：answers.md 的第 13 集；核對發現/選擇/執行分開，以及錯誤預期需回到源資料的處理。 看答案前先寫預測；回答須能指出輸入、操作、結果與原因。若以自己的需求替換資料，要同時重寫真相與驗收，不再套示範數字。

## 證據與製作驗收

| 項目 | 必須儲存的證據 | 本頁狀態 |
| --- | --- | --- |

| 本入口模型 | 完整 prompt、版本/model、工具與修改、測試原文 | pending_run |

| CLI 原生 | 真實 TUI/exec/review 紀錄、輸入輸出與 exit/status | pending_run |
| 學習 | 未參與撰稿者只憑教材重做、解釋、排錯及變式 | 待獨立重做 |
| 媒體 | 查核、旁白、畫面、字幕、成片與站主觀看 | 未開始 |

每支影片以「有用的結果」開場，再問與原做法怎麼選、完整操作、怎麼知道做對、失敗與變式。未實跑時先用明標的作者材料講預期，不在正式成片冒充模型成果；核心入口示範與學習檢查缺證據就退回。原生 App 不可存取時保持 pending_capture，公開官方頁截圖不能替代。

製作前由未撰稿者使用當集新副本重做，必須完成本頁成果、指出一個失敗原因、完成變式並核對答案。只有讀稿／程式檢查時如實記錄，不能寫「新手學會」。來源逐項查核；之後才配音、渲染、QA、站主觀看與上架，狀態分開。
