## 兩支共同的做法（我的讀法；盲評讀者的量測在下一節）

1. **第一個主角是一個會問天真問題的人。** Gary 是「完全不寫程式的運營夥伴」，俗說是「還有人不會嗎？」的那個你。問題用觀眾自己的話問（「這不就是桌面版 ChatGPT 嗎？」），答案用動詞清單答。
2. **一個承諾句，點名東西和數字，不排目錄。**「四個基本功：專案、權限、上下文、AGENTS.md」「用一個比喻搞懂，最後自己加一本」。它跟目錄的差別：講的是觀眾看完會拿到的東西，不是這支片分幾段。
3. **一條利害關係句，讓後面不能跳。**「一個能動你整台電腦的東西，你得先學會駕馭它」；「出來滿一年了」。
4. **同一個例子從頭帶到尾。** 講座籌備（資料夾→權限→壓縮上下文→AGENTS.md 四條→改檔名→名單→簡報→Skill→自動化）；說明書（封面→內文→附件→書櫃→翻開）。新概念永遠先在例子裡發生，才有名字。
5. **每個概念同一個小結構**：它是什麼（一句白話）→ 在例子裡長什麼樣（具體到選單名、檔名、那四條規則）→ 大部分人怎麼用／我怎麼用（帶一個數字）→ 一條怎麼選的規則 → 一個新手常踩的坑。順序可以換，五樣缺一就薄。
6. **觀眾的下一個疑問由旁白先講出來。**「你第一次看到可能會想，怎麼又要寫一個 markdown」「到這裡你可能會有個疑惑」「那你可能會問」「看到這邊可能覺得很難，其實沒有」。這是教學片的鉤子：不是懸疑，是**觀眾心裡正要冒出來的那句話**。
7. **術語在例子後面出現，用「聽起來很 X，其實…」卸掉。** context engineering、漸進式載入、MD、YOLO 模式都是這樣進來的，各一句。
8. **教的東西整份唸出來。** AGENTS.md 的四條、find-restaurant 的介紹句和四條內文、講座籌備 Skill 的五條。觀眾聽完就能照寫。
9. **「我」在場，而且帶數字或帶不確定。**「我 80% 的時間用語音」「我的習慣是 80% 就手動壓」「我個人覺得 Codex 比 Claude 順手」「我不建議新手亂開」「我自己用 Plus 也看到了，免費版就還不確定」「說實話我也不知道會有多少人喜歡」。
10. **比喻一句就走，不鋪場景。** 特斯拉聽廣播、存檔點、助理十份文件、員工守則對觀察筆記、雙面刃——每個一句；只有俗說的「說明書」是撐全片的那一個，而且每個部位都對得上機制。
11. **共同經驗的玩笑一兩個。**「最終版、真的最終版、這次絕對最終版」「反正你只活一次」「還沒開始做事就先累死了，對吧？」。
12. **章節銜接是例子的進度，不是結構標籤。**「名單整理完，活動頁也做好了，我會讓它先總結」「這四個基本功都搞定了，現在來看它實際能把這場講座做出什麼」「好，那到底要怎麼用？」。
13. **風險一段，一個檢查，放在步驟之後。** 兩支都是。
14. **片尾：一句話的答案或一份照順序做的行動清單、一個問觀眾自己情況的留言題、承認一件不確定的事。**

## 我們現行規則會誤擋的地方

這兩支片拿我們的十三題盲評去讀，會在第 4 題（宣告接下來要怎麼講）、第 5 題（章首標籤句）、
第 8 題（事實講超過一次：承諾句點名的東西後面又講）被擋；`lint` 會在前 60 秒對「帶你」
「我會告訴你…四個」警告，對「接下來」開頭的章首句警告。它們寫這些規則的理由是「拼湊感」
「像上課」「公式」——而這兩支片讀起來都不像。差別在句子**帶不帶例子的狀態**：
「接下來我們來看第二點」是標籤；「這四個基本功都搞定了，現在來看它實際能把這場講座做出什麼」
帶著例子走到哪裡了。規則要改的是辨認方式，不是放棄原則。細節與新規則見
`teaching-flow.md`。
