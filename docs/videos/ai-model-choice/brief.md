# AI 模型這麼多，到底該怎麼挑？

## 觀眾

用 ChatGPT、Claude、Gemini 這類現成工具或 API 做產品功能的個人開發者與小型團隊：他們已經會在聊天視窗的下拉選單裡換模型，也知道「LLM 有很多家、很多版本」，但不清楚換一個型號、換一種串接方式（單一模型、先便宜後升級的級聯、多模型互審）實際上會差多少錢、多少時間。他們搜尋的問題接近「AI 模型怎麼選」「Claude Opus 和 Sonnet 差在哪」「API 費用怎麼算比較划算」；也有一部分人是看到新模型上架的新聞後，想知道「要不要馬上換」。他們不需要會寫路由程式，只需要會做加減乘除。

## 觀眾看完能做到的事

1. 能照自己的實際用量（輸入、輸出各要幾個 token，一天呼叫幾次），套進官方定價頁「每百萬 token」的單價，自己算出單一模型、先便宜後升級的級聯、多模型並行互審三種串接方式各要花多少錢，而不是只比較「哪一家最便宜」這種表面標語。
2. 能分辨自己真正卡住的是成本、品質還是延遲這三個量的哪一個，決定要不要為了追新模型或新排行榜換掉現在的做法，而不是每次看到新聞就跟著換。

## 站主觀點

我的看法是：排行榜每週換一次第一名，這件事本身不該是你換模型的理由。大部分人的工作用得到的其實是「先便宜後升級」的級聯——先讓便宜、快的小模型答，答不出來或沒把握才升級到貴的旗艦模型；以本片的假設試算，平均成本可以比一路用旗艦省六成以上。把兩個模型同時問、再找第三個模型當評審這種並行互審做法，呼叫次數是單一旗艦的三倍以上，換到的是多一份校對，不是省錢，我只會留給真的輸不起的決定，例如要發出去的對外文件。比起追每週的第一名，我更在意把成本、品質、延遲這三個量分開算一次——算完會發現，平均最省的做法，最慢的那百分之五（p95）不一定比較快；這是本片的推論、不是官方數字，但這筆帳值得先攤開來看一次，才知道自己在乎的到底是哪一個量。新模型也不一定比較貴：現在官方定價頁上，比較新的旗艦等級模型單價反而比舊的低，所以「新的一定要多付錢」這個直覺也該重新算，不是照單全收。

## 示範或實算

固定一組共同假設（與來源文章一致）：一次請求平均送出 3,000 個輸入 token、平均收到 600 個輸出 token；金額一律用官方定價頁「標準價」，不算批次、快取與加速模式的折扣，取到小數點後四位。以下每個單價都在 2026-09-24（本片查證當天）重新打開官方定價頁核對過，全部與來源文章 2026-09-18 查到的數字相同：

- Claude Opus 5：輸入每百萬 token 5 美元、輸出 25 美元（`platform.claude.com/docs/en/about-claude/pricing`）。
- Claude Sonnet 5：輸入 2 美元、輸出 10 美元（同上）。
- Gemini 3.5 Flash-Lite：輸入 0.30 美元、輸出 2.50 美元（`ai.google.dev/gemini-api/docs/pricing`）。
- gpt-6-astra：輸入 10 美元、輸出 50 美元，標準價、短上下文（`platform.openai.com/docs/pricing`）。

算出來的三種流程成本（單一旗艦、級聯、並行互審）：

| 流程 | 呼叫組成 | 一次請求 | 每萬次 |
| --- | --- | --- | --- |
| 單一旗艦 | 1 次 Claude Opus 5 | 0.03 美元 | 300 美元 |
| 級聯（先便宜後升級，30% 升級） | 1 次 Gemini 3.5 Flash-Lite，其中 30% 再加 1 次 Claude Opus 5 | 平均 0.0114 美元 | 平均 114 美元 |
| 並行互審 | Claude Opus 5 與 gpt-6-astra 同時作答，Claude Sonnet 5 評審 | 0.1004 美元 | 1,004 美元 |

30% 升級比例與 3,000/600 個 token 是示範用的假設，不是量到的真實流量，字卡與口播都要說清楚。

本片查證時另外發現一個來源文章沒有的事實，適合當「新模型不一定比較貴」的額外例證（只在選項 C 用到，不影響上面主表）：Anthropic 定價頁把 Claude Opus 5.5 標成「For long-running agentic coding and knowledge work」，標準價輸入 4 美元、輸出 20 美元，比 Claude Opus 5 的 5／25 美元便宜；換算同一組假設，單一旗艦用 Opus 5.5 是 0.024 美元（比 Opus 5 省 20%），級聯改用 Opus 5.5 兜底是平均 0.0096 美元。

畫面：主表和算式在「付多少（實算）」那一章，用 `table` 場景放三種流程的成本比較（表格數字同上）、`code` 場景放級聯那一步怎麼算出來的算式（0.30×3,000/1,000,000 + 2.50×600/1,000,000 = 0.0024，加上 30%×0.03＝0.0090，合計 0.0114）、`diagram` 場景放來源文章已有的 `apps/web/public/guides/ai-workflow-cost-quality-latency/diagram-1.svg`（圖上的數字沒有變，可以直接沿用）。選項 C 額外用一張 `table` 場景放 Opus 5.5 前後對照。
