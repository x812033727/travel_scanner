# AI 劇的備份分支：分集與共用各放什麼

適用：在雲端 session 製作的 AI 劇。先統一《種田娶妻打天下》（`zt`）與《恁祖媽今年18》（`tn`）兩個系列（站主 2026-11-08：「我想要先統一種田跟祖媽」），之後新的 AI 劇照這份做。

這份管的是 GitHub 上的 `transfer/*` 備份分支。雲端 session 的容器隨時會被收掉，本機檔案只在 GitHub 上留一份才算安全。主機上影片的雲端硬碟備份是另一條路線，見 [`BACKUP.md`](../BACKUP.md)；它今天跟分支差在哪裡，見本文最後的〈雲端硬碟〉。

## 站主定下的原則

這幾條是站主說過的話，本文其他規則都從這裡來：

- **所有檔案都要備份**：「不要漏備份某個你覺得沒用的檔案」（2026-11-07）。
- **一集一條分支，跨集共用的放一條**：「跨集共用可以共同放一個：音效庫、配樂、試鏡、參考圖各輪、我寫的腳本；其他每一集的全部放每一集的分支」（2026-11-07）。
- **分集只留重剪需要的，但不能漏**（2026-11-08）。可能還會用到的也要留：沒選中的草稿；縮圖、log、進度檔、清單副本；被換掉的舊精修。
- **舊畫風的檔案另開分支，不跟新的混在一起**：「3D CG 時期的全部檔案就另外開分支吧 不要跟真人的混再一起」（2026-11-08）。
- **刪本機檔案的條件**（2026-11-07）：要備份核對過，**而且**這集已送上後台，並確認成片、字幕、封面都在。兩件都成立才刪，而且只刪那一集。

## 備份放在哪個 repo（站主 2026-11-09）

`travel_scanner` 快到 GitHub 的容量上限，站主為每個系列各開了一個私人備份 repo。之後的備份分支一律推到該系列的 repo；分支命名照下面〈分支怎麼命名〉不變。

| 系列 | 備份 repo |
| --- | --- |
| 種田（`zt`） | `x812033727/drama-backup-zt` |
| 祖媽（`tn`） | `x812033727/drama-backup-tn` |
| 奇聞檔案局 | `x812033727/mokaair-video-backup` |
| 原來如此 | `x812033727/mokaair-video-backup-sothatswhy` |

- 雲端 session 要先把 repo 接進來（`add_repo`，要 push 權限），才能推。
- `travel_scanner` 裡舊的 `transfer/*` 分支，要等新 repo 的分支由另一個代理逐檔核對完、站主同意後才刪。刪分支之後 GitHub 不會馬上釋放空間。
- 祖媽的備份工具（scratchpad 的 `tn-bk.py`）預設推到 `drama-backup-tn`，也可以用環境變數 `TN_BACKUP_REMOTE` 指定別的 repo。

## 分支怎麼命名

| 分支 | 放什麼 |
| --- | --- |
| `transfer/<系列>-e<NNN>` | 一集的檔案，一集一條 |
| `transfer/<系列>-shared` | 這個系列跨集共用的檔案 |
| `transfer/<系列>-<舊版>-e<NNN>`、`transfer/<系列>-<舊版>-shared` | 系列換過畫風時，舊畫風的分集與共用檔 |

規則：

- `<系列>` 用短代號：種田 `zt`、祖媽 `tn`。
- 換畫風的系列，新畫風的分集也加上版本，免得跟舊版混淆。種田現在的分支是：
  - 真人版的分集：`zt-live-e<NNN>`
  - CG 版：`zt-cg-e<NNN>`、`zt-cg-shared`
  - 真人版與兩版都用的共用檔：`zt-shared`
- 一集一條分支，每次備份都在同一條上加一個 commit，只能 fast-forward，**不強推、不另開 `-v2`**。
- 舊的 commit 留在分支歷史裡，舊版本的檔案一個都不會丟。

## 分支裡的路徑

- 路徑一律相對於 `~/mokaair-work/videos/`。例如：
  - `zhong-tian-qu-qi-e901-dh/audio/zq901a01.wav`
  - `_live-e901/zhong-tian-qu-qi-e901-dh/picks.json`
  - `tai-nainai-import/tai-nainai-e001/meta.json`
- Claude 的 scratchpad 放在 `_scratchpad/` 底下，不要存成 `tmp/claude-0/<session id>/scratchpad/…`。session id 每次都不一樣，換一個 session 就還原不回同一個位置。
- 超過 95 MB 的檔案切成 90 MiB 的 `X.part00`、`X.part01`…，用 `cat X.part* > X` 接回。
- 每個 commit 都附 `README-backup.md`，寫清楚三件事：
  - 這一版放了什麼、沒放什麼，以及沒放的在哪裡；
  - 怎麼還原；
  - 檔案數與大小。

## 分集分支放什麼

一集重剪、重拍某一鏡、回頭查決定時需要的東西，都放在這一集的分支。

| 類別 | 內容 | 為什麼 |
| --- | --- | --- |
| 草稿 | 每一支草稿，**包括沒選中的**，以及每一輪重拍的提示詞、manifest、spec、log、進度檔 | 想換另一個版本時，不用花錢重拍 |
| 挑片 | 挑片清單（`picks.json`、`review-picks.tsv`）、剪點、裁切、挑片理由 | 重剪要照同樣的選擇與剪點 |
| 精修 | 目前用的每一鏡精修，**加上被換掉的舊精修**，以及精修的提示詞與 manifest | 重剪的畫面來源；舊版留著可以換回 |
| 剪進成片的片段 | 每一鏡最後剪進去的片段（接好聲音、剪好頭尾的，**帶模型原聲**；種田真人版是 `_live-e90N/zhong-tian-qu-qi-e90N-dh/clips/`）。送上架包時 `--clips` 指的也是這一份 | 有些是手工剪過的，工具重建不出來（祖媽第 1 集 c27）；原聲只在這裡與選中的草稿裡 |
| 剪接表 | 這一集的剪接表（種田 `hailuo/edit-dh-eNNN-live.json` 之類），repo 裡已經有也放一份 | 重剪要照同一份；種田第 1 集的剪接表原本只在工作分支（PR #2047 才帶進 main） |
| 錄音 | 這一集全部台詞的錄音（系統聲、畫外音、心裡話），連同原始 TTS | 重剪的聲音來源 |
| 發布包與外語錄音 | `<slug>/review/`（匯入工具的預覽、`publish-import-*.json`、打包好的錄音 `review/recordings`）、`audio-<語言>/`、匯入資料夾的 `dub.*.m4a` | 以前漏備份的就是這幾個位置（種田第 53、54 集的八語錄音約 1 GB，runpod〈備份要跟著每一批走〉） |
| 語言批次的檔 | 匯入資料夾或工作資料夾裡的外語字幕、說明、各語縮圖 | 雲端硬碟從語言批次拿得到，分支也要有，兩邊才一樣 |
| 該集配樂 | 只給這一集用的配樂（`<集>/music/`）。種田 2026-11-08 以前把它放在 `zt-shared`，之後放分集分支 | 重剪要用 |
| 成片 | 交給站主看、送上後台的那一份 mp4，加上字幕、`lines.json`、`final.log`、手機版與預覽版 | 能確定之後拿到的就是站主核准的那一份；重跑合成未必逐位元相同 |
| 後台匯入資料夾 | `final.mp4`、`meta.json`、字幕、封面 | 送上後台的原樣 |
| 審片紀錄 | 連戲表、挑片與審片截圖 | 當時判斷的依據（審片報告本身在 repo 裡） |
| 交接 | 這一集的 `RESUME.md`、交接筆記（要寫什麼見 [`README.md`](README.md)〈交接〉） | 下一個接手的人從這裡開始 |

**不放進最新一版的**（較早的 commit 裡如果有，就留在那裡）：

- 工具每次都會重建的中間檔：`segments-v4/`、已被取代的試剪與舊版成片、`first-frames/`。
- 已經不用的舊版配音（`audio-old/` 之類）。
- 舊畫風的檔案：放進 `<系列>-<舊版>-e<NNN>`。
- 參考圖、音效、系列配樂：放共用分支；已經進 repo 的參考圖不重複放。

**換成精簡版之前要先證明沒漏**：

1. 只用分集分支加上共用分支的檔案，還原到一個空資料夾。
2. 重新剪一次這一集。
3. 跟交出去的成片比：畫面與聲音解碼後的 MD5 要完全相同。

種田第 1 集 2026-11-08 做過這個比對，結果相同。當時用到的剪接表與 `live-action/stage.py` 只在種田的工作分支，配樂取自 `zt-shared`；之後剪接表、剪進成片的片段與該集配樂都放分集分支，工具在 main 上，只靠分支與 main 就能重剪。

## 共用分支放什麼

不屬於某一集、而是整個系列都會用到的東西。

| 類別 | 內容 |
| --- | --- |
| 音效庫 | `_series/<系列>/sfx/` |
| 配樂庫 | `_series/<系列>/music/`；各集共用的配樂 |
| 試鏡與參考圖 | 試鏡、定妝照、角度圖、場景圖，**每一輪都放，包括沒選中的**；試鏡的聲音樣本（`_audition/`，容器一收就沒了） |
| 小樣 | pilot 的草稿、精修、試剪 |
| 腳本與工具 | 自己寫的腳本（scratchpad 的 `.py`、`.sh`、`.mjs`、`.md`），以及系列共用的工作腳本 |
| 不屬於單一集的 scratchpad | 聲音測試、跨集的審片抽格、給站主看的預覽、交接與規劃筆記 |
| 系列層級的匯入與合輯 | 合輯、季封面 |

**不放的**：

- 別的系列的東西。一個系列借用另一個系列的音效時，在 README 寫明出處就好，不重複備份。祖媽的 `tn-series-assets` 目前放了一份種田的音效庫，可以拿掉。
- 只屬於某一集的東西：放那一集的分支。
- 兩樣站主同意不放的：
  - pod 的登入憑證（`h3r-state`，是密碼）；
  - 可以重新安裝的程式套件（例如 faster-whisper 的 Python 環境）。

分不清屬於哪一集、哪個畫風的檔案，就兩邊都放。同一個檔放兩條分支，GitHub 只存一次，不多佔空間。

## 什麼時候備份

- 每次付費產出之後：草稿、重拍、精修跑完。
- 交給站主或送上後台的檔案，交出去之前就先進分支。
- 一集做完時。
- 一集的檔案之後又有變動時，在同一條分支上再加一個 commit。
- 備份之後才產生的檔案，補進同一條分支。

## 怎麼確認備份完整

三道檢查都要過：

1. **逐檔核對**：清單上的每個檔案，跟分支裡的版本雜湊相同；切塊的檔案每一塊都比。結果要是 0。
2. **涵蓋檢查**：工作區與 scratchpad 的**每一個**檔案，都在某一條分支的清單裡。結果要是 0；正在拍的那一集，以及只是捷徑的連結除外。
   - 只做逐檔核對不夠。種田第 1 集曾經漏掉另開的精修工作資料夾 `_live-e901`，逐檔核對是 0，是靠涵蓋檢查才抓到的。
   - 另開工作資料夾時，要當下就把它加進備份清單。
3. **刪本機檔案前**：另找一個沒參與製作的代理到 GitHub 逐檔核對，並確認後台成片、字幕、封面都在。

## 雲端硬碟

站主 2026-11-08：「備份到雲端的內容應該也要跟備份到分支的一樣」。

今天兩條路線是分開的：分支由雲端 session 自己推；雲端硬碟由主機的 worker 從**後台審核區**取回再複製（[`BACKUP.md`](../BACKUP.md)〈匯入的影片〉）。
所以雲端硬碟只拿得到送上後台的東西，而且要照 [`REVIEW.md`](REVIEW.md) 第 8 節送 `import --publish --clips … --edit …` 才拿得到片段、錄音與剪接資料。

### 要一樣的做法（還沒做）

**主機 worker 把 `transfer/*` 分支鏡像到雲端硬碟**（缺口檢查的方案一）：

1. worker 每輪 `git fetch` 這個系列的 `transfer/<代號>-*` 分支（主機放一把唯讀的 deploy key）。
2. 分支最新的 commit 跟上次不同時，解到主機的暫存資料夾，把 `.partNN` 接回原檔。
3. `rclone copy --checksum` 到 `AI/備份/drama/<劇>/_分支/<分支名>/`，被覆蓋的舊檔進 `_舊版/<時間>/`。
4. `rclone check` 核對，回報網站，後台備份卡多一列「分支」。

這樣分支有的雲端硬碟就有，審核區的上限都不用改。**這要改程式、要站主同意才做**，票是
[`2026-11-08-drive-mirrors-transfer-branches`](../../../tasks/open/2026-11-08-drive-mirrors-transfer-branches.md)。

在那之前：

- 每集照 `REVIEW.md` 第 8 節送 `--publish --clips … --edit …`，把今天就送得上去的送齊。
- 刪本機的條件仍是上面的兩件（分支核對、後台確認）。要不要再加「雲端硬碟核對完成」由站主決定：鏡像做好以前，雲端硬碟本來就收不齊，加了會讓本機永遠刪不掉。
