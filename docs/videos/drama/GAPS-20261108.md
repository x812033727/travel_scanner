## C. 雲端硬碟（主機 worker）對分支

### 一集匯入的劇，今天怎麼進雲端硬碟

雲端硬碟只拿得到審核區裡的東西。worker 取回來的是 `review_package`，也就是上架確認那一關的檔案。來源：`BACKUP.md`〈匯入的影片〉第 1–7 步、`build.mjs`、`review-package.mjs`、`clips.py`。

- 用 `import` 送：成片、字幕、封面、`metadata.json`。
- 用 `import --publish` 送：上面這些，加上
  - `--clips DIR` 裡的每支 `<鏡>.mp4`，角色是 `clip_`，最多 120 支；
  - `--clips` 上一層的 `audio/`、`audio-<語言>/`，打包成每種語言一個 `recording_<語言>` 加 `recordings_manifest`，這類「其他」最多 24 個；
  - 同一層的 `cut/*.log`、`music/*.mp3|wav`、`edit*.json` 或 `--edit` 指定的檔，角色是 `build_`，最多 40 個，每個名稱最多 28 字，只收 text、json、mp3、wav；
  - 同一層的 `first-frames/*`，角色是 `kf_`，最多 400 個。
- 語言批次：上架後核准的字幕、說明、配音、各語縮圖。

其他限制：
- 每個檔最多 1.5 GB（`video_review_max_file_bytes`）。
- 審核區總容量 20 GB（`video_review_max_total_bytes`）。
- worker 每輪下載 40 個檔。
- 完整層級才收 `clips/`、`recordings/`、`recut/`、`keyframes/`。
- 系列共用的檔：上傳包不帶。只能在**掛著雲端硬碟（G:）的電腦**上跑 `series-backup.mjs`，雲端 session 沒有這條路。

種田第 1 集真人版的匯入資料夾（`zhong-tian-qu-qi-import/zhong-tian-qu-qi-e001-r2/`）裡只有 `final.mp4`、`meta.json`、`thumbnail.png`、`zh-TW.srt`，沒有 `clips/`。`REVIEW.md` 第 8 節與 route-a 第 320 行都只寫 `import --from … --force`。所以照文件做的話，這一集進雲端硬碟的只有上傳包。這份檢查沒查後台這一集有沒有送過 `--publish`，所以「今天」那一欄寫的是照文件做的結果。

### 要讓雲端硬碟跟分支一樣，兩條路

**方案一（建議）：主機 worker 直接把 `transfer/*` 分支鏡像到雲端硬碟。**

- 怎麼做：worker 每輪 `git fetch` 一個系列的 `transfer/<代號>-*` 分支（主機放一把唯讀的 deploy key）。分支最新的 commit 跟上次不同時：
  1. 用 `git archive` 或稀疏 checkout 解到 `_backup-stage/`；
  2. 把 `.partNN` 接回原檔；
  3. 用 `rclone copy --checksum` 複製到 `AI/備份/drama/<劇>/_分支/<分支名>/`，被覆蓋的舊檔進 `--backup-dir _舊版/<時間>/`；
  4. 用 `rclone check` 核對；
  5. 回報網站。
