# C01 Crocs｜首集取證與六章敘事草案

狀態：**來源未查核，禁止當成旁白事實或正式匯入列。** 工作標題「洞洞鞋紅遍世界，Crocs 為何在 2008 年反而大虧？」。這個問句本身的年份、損益與矛盾仍待美國證管會原始申報證實；如果資料不支持，改題，不為標題硬湊故事。

一條主線：同一雙洞洞鞋如何推動 Crocs 擴張，以及公司在需求變化時如何調整。觀眾沿著鞋、庫存、通路和公司決策往前走，不插入無關品牌通史。每章結尾留下下一個具體問題；正式 8–10 分鐘稿須至少八組有 setup／payoff 的鉤子、每 30–45 秒有進展。

| 章 | 目前可用的敘事問題 | 入稿前必須核對 |
| --- | --- | --- |
| hook | 在一個普通鞋店的購物場景先看到洞洞鞋與公司財報之間的反差。實際場景要標成示意，不能冒充 2008 年某家店的紀實畫面。 | 2008 年是否及如何虧損；熱賣到底是哪幾年；開場只預告問題，不先揭曉答案。 |
| origin | 這雙鞋如何進入市場？ | 官方年表、創立者與產品來源，不採流傳的創業軼事。 |
| idea | 商品為何迅速被市場看見？ | 公司自己的產品與通路紀錄；對「舒適」「醜」等主觀評價要有歸屬。 |
| engine | 公司如何擴張？收入、庫存和其他產品各占多少？ | 2006–2008 年 10-K 的年度數字；區分總收入、銷量、存貨、利潤和現金。 |
| turn | 虧損如何發生，哪些因素有直接證據？ | 2008–2009 年 10-K 對需求、跌價、庫存、減值、店面或收購的披露；不能把宏觀危機當唯一原因。 |
| now | 公司後來如何調整，今天靠什麼生意？ | 後續年報與當期營運狀態；避開過期數字，區分品牌本身與集團其他業務。 |

## 官方來源入口（尚未讀取）

以下是要打開的入口，**不是已核對的引用**。雲端代理在 2026-10-20 對這些網域回傳網路政策阻擋，沒有取得正文或 PDF；`checked` 日期和結論均不得填寫。

1. Crocs 投資人財報：<https://investors.crocs.com/>；先找 2006–2009、後續年度的年報及投資人公告，記錄原件 URL、頁碼和公開日期。
2. SEC 公司申報入口：<https://www.sec.gov/edgar/search/>；以公司名查 CIK，再核對 10-K。候選 CIK `1334036` 未在本輪讀到官方資料，不直接當已驗證 ID。
3. SEC 結構化申報：<https://data.sec.gov/>；只在核對 CIK 與欄位定義後用於交叉檢查數字，不把 API 數字代替 10-K 敘述。
4. Crocs 企業網站：<https://www.crocs.com/>；供當期產品、品牌與公司敘述的核對，歷史財務仍以申報為主。

逐條要確認：產品與公司創立年份；2006–2009 年營收、淨利／淨損及存貨的同幣別數字；年度末與全年不能混寫；虧損原因在公司申報中的原句與其限制；後續調整的年份、執行主體與結果；有沒有不同來源不一致的數字。獨立審稿人必須看原件並把每個核心說法連到可讀的一手頁面，才可產生 `episodes/C01.json` 和正式 `stories.json`。

## 畫面與製作邊界

構圖只寫匿名旅客／店員在普通場景做一件事，以及一雙**無商標的普通泡棉鞋**、鞋架或庫存箱等焦點。不能仿畫品牌標誌、型號標記、真人、競品商標或讓模型生成字。財報數字及年份由後製字卡呈現；插畫不是歷史現場照片。先有查核稿和實測 TTS，再決定 5–8 秒一鏡的實際張數；現在沒有精確圖片批次與全片報價。
