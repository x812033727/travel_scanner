# 已上架影片的標題與縮圖重做規則（2026-11-11）

站主 2026-11-11：頻道只留三個系列（奇聞檔案局、原來如此事務所、AI 劇），已經上架的影片先換標題和縮圖，不重做內容。這份是給接手重做的對話照做的規則：做什麼、每個系列怎麼寫、哪些檔案不要碰、做完交什麼給站主。

為什麼先做這件：2026-11-03 的判讀（`.agents/skills/producer/SKILL.md`「不能讓步的事」第 2 條）是 28 天 3.1 萬觀看裡，抽查的兩支有 98–99% 來自 YouTube 廣告，自然點閱率只有 0.7–0.8%。觀眾自己滑到的時候不點，問題出在點進來之前；換包裝不用重拍，是成本最低的一步。

## 一、範圍與順序

1. 先列清單：從站台的 YouTube 報表（`.agents/skills/youtube-channel-reports/SKILL.md`）拉每支公開影片近 28 天的曝光數與縮圖點閱率，**只看自然流量**，`ADVERTISING` 另列。
2. 照「曝光多、點閱率低」排序，先做前 10 支。曝光很少的片換了也看不出差別，排後面。
3. 奇聞檔案局 10 月那批（`docs/videos/channel-review-20261025-story-series/README.md` §2.1 的 14 支）還是舊的深青底小字縮圖和平靜的閱讀題標題，優先做。
4. 一支影片只改標題和縮圖。說明欄、章節、字幕、成片都不動。

## 二、各系列的規則

### 奇聞檔案局（`curio-`）

- **縮圖沿用現行版型 layout e**：左邊深藍字區、右邊放圖，字不壓圖。這是 11-10 定的預設，不用換。舊縮圖只是沒用到它，重畫就好。
- **標題**照 `.agents/skills/curio-episode/SKILL.md` §標題與縮圖：
  - 大家認得的名字放在前 6 個字（船、地方、人、事件、品牌）。
  - 接一個利害或反常的詞（消失、不敢、騙過、差點、全部、真相、憑什麼），再加一個數字或年份，最後是問號。
  - 後綴「｜奇聞檔案局」，後綴前最多 30 字。
  - 不要平靜的閱讀題：「燈塔的故事改了哪裡？」→「三個守燈人一夜消失，1900 年的燈塔日誌寫了什麼？」。
- **縮圖文字**：
  - `headline` 最多 6 字。第一行寫名字，第二行用 `**…**` 標出反轉並帶問號，例如「周瑜\n**早死了？**」。
  - `sub` 寫標題和 headline 都沒說的硬事實，例如「2000 打 25000」。
  - `shot` 選一張大臉、表情明顯，或那件東西本身，不選空景。用 `focus` 讓主體落在右框中間。
  - 這幾條跟開著的 [x812033727/travel_scanner#2004](https://github.com/x812033727/travel_scanner/pull/2004) 一致；#2004 合併後以 skill 為準。

### 原來如此事務所（`sothatswhy-`）

- **縮圖用 #2078 的亮底版**（站主 2026-11-11 定案，見 `docs/videos/thumbnail-looks-20261111/README.md`）：天藍到夕陽橘的底或奶油色遮罩、墨藍白邊大字、芥末黃強調、一行墨藍副標，紅印章在左下系列字樣旁邊。
- **標題**照 `docs/videos/so-thats-why/refresh-20261101/SPEC.md`：熟悉的物件放前面，接真實的反差和問題，後綴「｜原來如此事務所」，後綴前盡量 30 字內。數字和年份只在有用、有出處時才加，不要為了套公式硬塞。
- **縮圖文字**：
  - 主標最多 6 字，副標最多 12 字。
  - 主標不重複標題，補一句反常識的結論或數字，例如標題「為什麼天空是藍的？」配縮圖「藍天是**彈**的」。
  - 關鍵影格的人物在畫面中間時，寫 `"subject": "right"`，讓圖縮到右側，字跟人分開。

### AI 劇（種田娶妻打天下、恁祖媽今年18，以及之後的劇）

- **縮圖用 #2078 的 layout f**：
  - 滿版關鍵影格。
  - 下方一行黃字黑邊大字，放不下就縮小字，不換行。
  - 左上是劇名色條，種田橘、祖媽紅。
- **標題**照 `.agents/skills/youtube-video/references/drama-craft.md` §六：處境的鉤子＋主角的反轉＋《劇名》，不提前講出排定的答案。
- **縮圖文字**：
  - `headline` 寫 4–8 字，寫這一集的衝突（「我不念了」「人不能押」），不寫劇名，劇名在色條上。
  - `shot` 選**情緒最強的臉**（哭、怒、驚），不選場景、不選平靜的臉。種田 e003 原本選的 s33 就太平靜。
- 有些集的縮圖是在產線外另外做的，例如雲端硬碟裡種田第 6 集那張「劇照＋劇名＋集數」。重做時一律改用產線出的 layout f，或請站主決定保留哪一種。

## 三、不要碰的東西（會花錢或讓核准失效）

- **不要改已上架集數 `video.json` 的 `thumbnail` 文字或鏡頭**：`headline`、`sub`、`tag`、`shot` 都算在 `visualHash` 裡（`tools/video/core/timeline.mjs`）。一改，分鏡核准就失效，judge 要全部重付；有角色的漫劇代價最大。只有 `brand`、`focus` 和 `"layout": "e"` 不算（`thumbnailOnly`）。
- 新縮圖另外畫：用 `tools/video/templates/templates.mjs` 的 `thumbnailHtml` 加 `tools/video/render/browser.mjs` 的 `openRenderer`，在暫存目錄出圖。`docs/videos/thumbnail-looks-20261111/` 的樣張就是這樣畫的。每個語言各出一張，八語都要逐張看。
- **不要用 `review-push --gate publish` 送新縮圖**：上架包核准的雜湊不含縮圖檔，站上會默默留著舊檔（票 `2026-11-10-review-push-a-changed-thumbnail-never`，在 [x812033727/travel_scanner#2060](https://github.com/x812033727/travel_scanner/pull/2060)）。新縮圖直接交給站主。
- **不要自己改公開影片**：標題和縮圖由站主在 Studio 換。主機上有 `python -m app.cli video-youtube-caption-titles --set-title …` 可以批次改標題（`apps/api/app/video_youtube/retitle.py`；每支 50 配額單位，預設只報告不送出），要站主在對話裡明確同意才能加 `--apply`。

## 四、標題的語言版本

- zh-TW 標題改了，八個語言（en、ja、ko、es、pt、id、vi、th）的在地化標題也要跟著改，用同一套公式翻，不要逐字翻。
- 每個標題結尾保留該語言的字幕標記（`apps/api/app/video_youtube/requests.py` 的 `CAPTION_TAGS`，例如「｜CC字幕」），而且不能超過 YouTube 的 100 字元上限。
- 系列名的譯名每次都要一樣。目前還沒有定版譯名，第一批做的對話把譯名寫進這份檔案的〈譯名〉一節，之後照用。

## 五、交付與量成效

每一批寫一份 `docs/videos/packaging-refresh-20261111/<系列>-<批次>.md`，一支影片一列：

| 欄位 | 內容 |
| --- | --- |
| slug、YouTube ID | |
| 舊標題 → 新標題 | zh-TW，八語另附 |
| 縮圖 | `headline`、`sub`、`shot`（或 `focus`／`subject`），新縮圖檔放在哪裡 |
| 換之前 28 天 | 自然曝光、自然點閱率 |
| 換上去的日期 | 站主換完回填 |
| 換之後 14 天 | 自然曝光、自然點閱率 |

- 縮圖優先用 Studio 的「測試與比較」，一次放新舊或兩張新的，讓 YouTube 比，不要直接覆蓋。
- 同一支影片 14 天內不要改第二次，不然量不出是哪一次改動的效果。
- 新縮圖檔交給站主，不要提交進 repo：每支八語就是九張圖，repo 會膨脹。依 `docs/videos/AI-DRAMA-DRIVE.md` 放到雲端硬碟該集的 `製作檔/`。
