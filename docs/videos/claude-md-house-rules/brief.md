## 觀眾看完能做到的事

1. **寫一份八條的 CLAUDE.md 放在資料夾最上層，之後每次新對話只說八個字「幫我整理報名名單」，整理出來的檔案就進 `輸出/`、附一份處理日誌、寄不出去的人另外列一張表。** 對象：`講座籌備/CLAUDE.md`（12 行、8 條，全文上卡片）。怎麼知道做對了：資料夾裡多了 `輸出/`，裡面有 `處理日誌.md` 與 `要補資料.csv`；沒有這份檔時，同一句八個字只得到資料夾根目錄一個 `報名名單_整理後.csv`，寄不出去的三個人混在名單裡、沒有日誌。證明：示範 s1 對 n1（跑過，2026-10-21，2.1.295）；終端機畫面用「要先實作」第 N1、N2 項重跑的同一組。級別：跑過。更高一級（在桌面 app 的 Code 分頁看到）這台機器不能登入 app，不列。
2. **把一條含糊的規矩改成一句看得出做對沒的規矩。** 對象：模糊版 CLAUDE.md 的那一句「名單要整理乾淨。」→ 具體版的「沒有 Email 或格式不對的，列進要補資料，不要猜。」「做完在 輸出/處理日誌.md 寫下：做了什麼、動了幾筆、哪裡沒把握。」怎麼知道做對了：含糊的那一句跑出來跟沒有 CLAUDE.md 一模一樣（同一個檔名、同樣把三個缺資料的人留在名單裡、同樣沒有日誌）；換成具體的那幾句，`要補資料.csv` 與 `處理日誌.md` 就出現。證明：示範 v1 對 n1 對 s1（跑過）。這是全片唯一一句量測句「只寫一句的規矩，跟沒寫一樣」的依據（§九）。級別：跑過。
3. **請 Claude 先生一份守則草稿，再拿資料夾逐條對，把會害它選錯的那一條改掉。** 對象：Claude 自己寫的六條（g1）第 3 條「簡報大綱有多個『最終版』時，以檔案修改時間最新的為準」→ 觀眾的第 7 條「哪一版最新，看內容對不對得上 活動說明.md，不看檔名，也不看修改時間」。怎麼知道做對了：這個資料夾修改時間最新的「這次絕對最終版」內容是舊的（16:00、講者待確認）；照它寫的第 3 條會挑到舊稿，照第 7 條它在日誌裡寫「判斷依據（看內容，不看檔名與修改時間）」並留下對的那一份。證明：示範 g1（跑過：它只看了一次檔案清單、一個檔都沒打開就寫了）、M3（`ls -lt`）、a2（跑過）。級別：跑過。

這三件以外：「CLAUDE.md 跟 Skill 差在哪」一句話、「怎麼確認它讀到了」（`/context` 看 Memory files）、「寫多少」（200 行以內）都引官方頁，卡片標「引用」，不算成果。「輪到你改一行」是練習，給核對方法（看 `處理日誌.md`），卡片不宣稱結果。

## 站主觀點

（提案，待站主選大綱時確認或改寫。發動訊息說明站主的十點立場在後台設定分頁、原文沒有附來，所以不寫「套用立場」那一行，也不沿用舊企劃的點號。最多三點。）

1. 每次新對話都要講的那一段，我寫進 CLAUDE.md；用到才翻的整套步驟，我做成 Skill。守則短，手冊長。
2. 規矩要寫到看得出它做對了沒：「名單要整理乾淨」我不寫，「寄不出去的另外列一張表」才寫。
3. 它幫我生的草稿，我逐條對著資料夾看過才留；它在資料夾裡看得到的事，不等於它寫的規矩是對的。

依據：memory 頁（CLAUDE.md 每次對話開始載入；「越具體越簡潔，它越照做」；每份 200 行以內；它是脈絡不是強制設定）、skills 頁（Skill 的內文用到才載入；一直重貼同一段指示、或 CLAUDE.md 的一段長成流程，就做成 Skill）；第 3 點是 g1 那次執行本身（看了檔案清單、沒開檔，第 3 條寫錯）。

## 示範或實算

製作路線：教學卡片

`category: "tutorial"`、`format: "slides"`、沒有 `shot`、`theme: "paper"`。畫面是 `big`（帶 `numeral` 與 `icon`）、`terminal`（`data.typing: "human"`，指令與輸出逐字取自執行紀錄）、`code`（只放觀眾要照抄的檔）、`steps`、`compare`、`chat`、`quote`、`stats` 與公開官方頁的 `screencast`。沒有登入畫面、沒有 OBS；桌面 app 只出現在官方頁的截圖與文字裡。每個狀態一句 `keys`（≤ 24 字），執行代號與來源戳只進 `source` 欄與說明欄，旁白一個都不唸。

### 一個對照撐全片：CLAUDE.md＝釘在門口的員工守則（teaching-flow §六）

| 守則的部位 | 機制 | 出處 |
| --- | --- | --- |
| 釘在門口 | 檔案放在你打開的那個資料夾最上層（或它上層的資料夾） | memory 頁：工作目錄與它上層目錄的 CLAUDE.md 在啟動時載入；子資料夾的用到才載 |
| 每天上班前讀一遍 | 每次新對話開始就載入，不用你提 | memory 頁：「Both are loaded at the start of every conversation」 |
| 守則不是鎖 | 它是脈絡不是強制設定；要硬擋一個動作得用 hook（片中只說「那是另一種東西，這支不講」） | memory 頁：「Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead.」 |
| 守則短、手冊長 | 一直重貼的整套步驟做成 Skill，內文用到才載入 | skills 頁：「Create a skill when you keep pasting the same instructions… Unlike CLAUDE.md content, a skill's body loads only when it's used」 |
| 比喻停在哪裡 | 新同事會記得昨天的事，它不會：每次對話都是第一天上班；守則也不保證它照做（上面那條） | memory 頁同上；本片不講自動記憶（auto memory），那是另一個檔 |

手冊（Skill）只在第 1 章用一句帶過，不展開，不在後面的章節再提（§六：一個對照撐全片；局部對照一句就走）。

### 主例子：講座籌備資料夾（沿用，同一份種子）

`講座籌備/` 是上一支企劃為影片做的虛構資料夾（`<work-prev>/_tools/make-seed.mjs`，`<work-prev>` 是 `claude-code-beginner-event-folder` 的工作區；種子的文字檔在 `docs/videos/claude-code-beginner-event-folder/demo/seed/`）：報名表 24 列（缺 Email 3 列、少了 `.com` 1 列、同名不同人 1 組、同一人填兩次 1 組、先報名後取消 1 組、一筆「測試」、部門寫法五花八門）、`活動說明.md`（11/01 前給場地飲食需求、11/07 前寄確認信、「取消」的不寄）、三份「最終版」簡報大綱（修改時間最新的「這次絕對最終版」內容是舊的；跟活動說明對得上的是「真的最終版」）。人名、Email（全在 `example.com`）、地點都是虛構。

觀眾要寫的那個檔（全文，一張 `code` 卡放得下：12 行、最寬 29 字；`sha256` 前 16 碼 `8e865483370aa2d4`）：

```
# 講座籌備資料夾的規矩

- 報名表.csv、活動說明.md 只讀不改。
- 整理出來的檔案一律放到 輸出/。
- 同名不一定同一人：Email 不同就是兩個人。
- 同一個 Email 填了兩次，以最後一次為準。

八條各自的理由（第 2 章一條一個狀態、`numeral` 01–08；理由來自這個資料夾裡真的有的狀況，括號是證據）：01 原始檔只讀（沒有這條時它也沒動原檔，但你每次都得交代；n1、v1、s1 的 `報名表.csv` 雜湊都不變）；02 放 `輸出/`（沒有這條，檔案落在根目錄：n1、v1 的 `報名名單_整理後.csv`）；03 同名不同人（報名表裡兩個王志明，Email、部門都不同）；04 同 Email 以最後一次為準（陳怡君填兩次，第二次 Email 大小寫不同、前面多空白）；05 取消與測試不寄（張書豪、「測試」那一列）；06 缺 Email 不要猜（洪子晴少了 `.com`；n1 把三個缺資料的人留在名單裡、標 ⚠️）；07 哪一版最新看內容（三份最終版；M3 的 `ls -lt` 最上面是舊的那份）；08 留日誌（沒有這條就沒有日誌：n1、v1 都沒有）。

Claude 自己寫的那份（g1，6 條；全文在 `demo/g1/CLAUDE.md`；卡片放第 3 條整句、其餘以條號帶過）：

```
3. 簡報大綱有多個「最終版」時，以檔案修改時間最新的為準，
   並在整理時告訴我你採用哪一份；不要自行合併內容。

### 不用這個方法：每次把規矩重打一遍

觀眾今天的做法是一句普通的提示：每開一次新對話，把規矩連著要求一起打一遍（p1 那句 118 字的要求：「我要在 11/7 前寄講座確認信。用這個資料夾的 報名表.csv 和 活動說明.md，整理一份可以直接寄確認信的名單，存成 輸出/確認信名單.csv；沒辦法寄的人另外列在 輸出/要補資料.csv。原始檔不要改。做完把你做了什麼、動了哪幾筆、哪裡沒把握，寫進 輸出/處理日誌.md…」）。兩邊同一份資料夾都跑過：

- 打長要求（p1）跟八個字加 CLAUDE.md（s1）做出來的東西一樣多：都有寄信名單、要補資料、處理日誌，原檔都沒動（兩次的十項檢查都是 9/10，差的同一項是部門沒統一，兩邊都沒交代）。
- 差別一：長要求只管那一件事。同一個資料夾換一件事（整理三份最終版，versions 那句要求沒有提日誌），沒有 CLAUDE.md 的 a1 做完沒有日誌；有 CLAUDE.md 的 a2 做完多了 `輸出/處理日誌.md`，裡面寫「判斷依據（看內容，不看檔名與修改時間）」。守則管每一件事，不只管你這次講的那件。
- 差別二：量得出的成本是那 118 個字，每一次新對話都要再打一遍；守則寫一次，之後只打 8 個字。
- 網頁版 Claude 的「專案」也能放常駐指示；片中照實說一句，差別是它寫不回你的資料夾（第 1 章，引用）。

### 猜不到的結果（主例自己的，不是操作的人手滑）

1. **請它替資料夾寫守則，它第三條就寫錯**（g1）：它只跑了一次 `ls -la`、一個檔都沒打開，就寫下「以檔案修改時間最新的為準」；這個資料夾修改時間最新的那份是舊稿（M3）。而它自己真的去做那件事時（a1，沒有任何 CLAUDE.md），讀了內容、選對了，回覆第一句就是「整理完了，但我選的不是修改時間最新的那份」。它寫的規矩比它自己的做法差。開場放這個。
2. **只寫一句的規矩，跟沒寫一樣**（v1 對 n1）：同一個檔名、同樣的兩個漏洞。第 3 章的那一句量測句。
3. 有 CLAUDE.md 之後它仍然沒統一部門寫法（s1 的回覆：「部門寫法…我沒有統一」），因為八條裡沒有這一條：守則沒寫的它不會自己補。第 5 章「輪到你改一行」的引子（引用那次執行，不另跑）。
