# 上下文視窗（Context Window）是什麼？塞得進去，不等於讀得懂

2026-09-30 撰稿封包（AI 名詞十分鐘，前三集試片）。影片代號 `ai-term-context-window`，文章 `ai-context-window-explained`，目標 10 分鐘（`target_minutes: [9, 11]`），卡片配方 B 先場景。

## 觀眾

每天跟 AI 聊很長、常常要換新對話的人；把一批文件（會議紀錄、報告、合約）丟給 AI 整理的社團幹部、小編、專案助理；看過「一百萬 token」這種數字、以為視窗越大就越不會忘的人。他們已經會用聊天工具、知道可以貼附件，但不知道模型每一次到底拿到什麼。搜尋的問題是「AI 為什麼忘記」「context window 是什麼」「上下文長度」「AI 記憶」「AI 對話太長怎麼辦」。不用懂 API，也不用知道模型名稱。

## 觀眾看完能做到的事

1. 遇到 AI「忘了」，先分出是哪一種：服務回報輸入太長（沒送進去）、對話被壓成摘要後條件不見了（摘要漏掉）、原文明明在卻答錯（看了卻答錯），各做一個對應的動作：縮小工作集、補上核對過的原文、把相關段落拉到一起要求指出依據。
2. 換新對話之前寫一張五格交接單（目標、已確認的事實、原文位置、不能違反的限制、下一步），先自己核對數字、日期和決議狀態，再交給下一輪。
3. 拿自己的文件算一次「這一輪放得下幾份」：視窗大小除以每份的 token 數，知道容量只是資源檢查，不是理解測驗。

## 站主觀點

提案，待站主確認（對應頻道立場草稿第 1、3、6 條與系列立場提案第 8、9 條）：以我的用法，換新對話之前，我先看這一輪桌上有什麼、少了什麼，再決定要補哪一段原文，不靠換更大的視窗解決忘記的問題；AI 壓出來的摘要我一定拿去對原文，特別是「尚未核准」「不得發包」這種否定條件。這個名詞改變的決定有兩個：要不要為更大的視窗付錢或換工具（先分清楚是沒送進去、摘要漏掉還是看了卻答錯，再說），還有信不信一句看起來很完整的摘要（先對原文再信）。失敗的樣子是這集的示範：一句六十二字元的摘要，把「尚未核准」壓掉了。

放得下多少：一份紀錄平均約 178 個 token；二十萬 token 的視窗放得下 1,121 份（每月開會約 93 年），一百萬 token 放得下 5,607 份（約 467 年）；算式是視窗 ÷ 平均每份 token。二十萬與一百萬是官方文件列出的兩個級距，字卡標「以官網為準」，旁白不唸模型名稱。

在哪張卡：第二章的 `stats` 卡（535 token｜1,121 份｜5,607 份）；第四章的 `code` 卡（壞摘要與好交接兩段文字並排，字元數一樣、token 差五個、差在「尚未核准」）與 `compare` 卡（三種忘記各自先查什麼、怎麼處理）。「換新對話只帶這句摘要，模型手上就沒有任何一個字說不能發包」是從摘要內容推得的，不是跑過模型的實測；旁白只說交接單沒有那個字，不說「模型會寫成即將施工」是測出來的。

## 大綱

### 選項 A：先場景（採用）

角度：從觀眾每天看到的畫面（往上滑，舊對話都還在）切進去，先建立「這一輪的桌面」這個比喻，再用會議紀錄示範三種忘記；跟選項 B 的差別是示範放在中段，前面先把容量講清楚。

開場（如實唸出）：「上個月的對話還在畫面裡，模型這一次卻可能一個字都沒看到。」（停 900）「十分鐘，你會分得出它是沒收到、被摘掉，還是看了卻答錯。」

你以為／其實：「你以為聊天紀錄都在模型的腦子裡，它記得你們聊過的每一句 → 其實模型每一次只拿到應用程式放上桌面的東西；三份會議紀錄六百零四個字元、五百三十五個 token，桌面多大就是上下文視窗。」

1. **留著，不等於讀到**（鉤子，約 19 秒）：`title: 塞得進去，不等於讀得懂` → `shot: 手機聊天畫面往上滑的長長卷軸，旁邊一張小小的桌子` → `shot: 無臉人物坐在小桌前只拿到一張紙，背後玻璃牆後是整面檔案架`。收尾問題：「那它這一次，到底拿到了什麼？」
2. **這一輪的桌面有多大**（約 100 秒）：`shot: 巨大的腦形雲裡塞滿對話泡泡（你以為）` → `shot: 一張桌子，桌上只有幾張紙（其實）` → `shot: 一隻手把選好的紙放上桌，其他紙留在架上` → `shot: 三種放法：整本、篩過的幾頁、一張縮小的紙` → `shot: 桌上的問題卡與規則卡` → `shot: 一疊歷史訊息，只有最上面幾張在桌上` → `shot: 迴紋針夾著的附件與查回來的資料` → `shot: 桌角空著一塊，畫著虛線` → `big: 桌面多大，就是上下文視窗` → `shot: 一把量尺靠在桌邊` → `shot: 三份會議紀錄疊在桌上` → `stats: 535 token｜1,121 份（二十萬 token）｜5,607 份（一百萬 token），以官網為準` → `shot: 一張永遠放不滿的長桌延伸到天邊` → `shot: 攤開的長桌，一個無臉人物站在中間看不清兩端`。示範的第一段（放得下幾份）在 `stats`。收尾問題：「可是桌面這麼大，放得下，就等於讀得懂嗎？」
3. **放得下，不等於讀得懂**（約 110 秒）：`chapter` → `shot: 長桌上三個月的紀錄攤開` → `shot: 無臉人物雙手一攤，紙自己會翻的想像` → `shot: 最前面一份寫著舊方案的紙、最後面一份撤回單` → `shot: 中間夾著一張報價單草稿` → `diagram: 文章圖解（外部紀錄經選取進入本輪工作集；容量與事實狀態分開驗證）` → `shot: 無臉人物讀著長桌，頭上兩個一樣的問號` → `shot: 書架上一本二零二三年的研究，攤開一頁` → `shot: 同一張關鍵紙在長條裡從開頭滑到中間再到結尾` → `quote: Lost in the Middle 原句與翻譯` → `shot: 長長的走廊，中段最暗，像迷宮` → `shot: 一張告示牌上畫著驚嘆號，不是鐵律但要留意` → `shot: 兩張檢查表：一張量尺、一張考卷` → `shot: 換了一張更大的桌子，舊方案與撤回單還是各在一頭` → `shot: 每張紙貼上不同顏色的標籤：提案、決議、撤回、待查證` → `shot: 貼好標籤的紙排成一列，狀態一眼清楚`。收尾問題：「那它忘了，到底是沒送進去，還是送進去了卻沒看到？」
4. **三種忘記：沒送進去、摘要漏掉、看了卻答錯**（約 155 秒，示範）：`shot: 三份會議紀錄，每一份都蓋著同一個尚未核准的印` → `shot: 一張議程草稿，最上面一格空著等狀態` → `shot: 三個月份的日曆與三次會議的圈` → `shot: 一疊紙卡在門口，門框太小（沒送進去）` → `shot: 紙分成幾疊，中間用線連起來（分批後合併檢查）` → `shot: 只留幾張相關的紙，其他紙上貼著位置標籤` → `shot: 影印機吐出一張變薄變小的紙（摘要漏掉）` → `shot: 摘要留住大標題，小字狀態被擦掉` → `shot: 一張只有一行字的紙，看起來很完整` → `code: 壞摘要 62 字元 55 token 沒有「尚未核准」｜好交接 62 字元 60 token 有` → `shot: 便利貼上的四個字掉到地上` → `shot: 新的空桌上只放著那一張摘要` → `shot: 工地起重機與一張蓋著問號的施工單` → `shot: 一疊核對過的原文被放回桌上` → `shot: 原文明明在桌上，無臉人物還是答錯（看了卻答錯）` → `shot: 舊方案、撤回、報價草稿混在一疊裡` → `shot: 相關的段落被抽出來並排，旁邊一支放大鏡` → `shot: 一盞剛亮的訊號燈，不是永久的證明` → `shot: 一個小盒子裡留著幾張容易混淆的例子` → `compare: 先查什麼｜怎麼處理` → `cta: 完整的整理步驟與檢查表在說明欄第一行的文章` → `shot: 空桌與一張等著填的交接單`。收尾問題：「那換新對話之前，到底該帶什麼過去？」
5. **換新對話前，怎麼交接**（約 100 秒）：`chapter` → `shot: 一張五格的交接單` → `shot: 交接單遞給下一個無臉人物，後面是三個月的紀錄` → `bullets: 目標／已確認的事實／原文位置／不能違反的限制／下一步` → `shot: 無臉人物拿著筆逐格核對數字與日期` → `shot: 兩個印章：同意研究、正式通過，被誤合成一個` → `shot: 一枚正在討論的印章與一枚已經決定的印章，中間畫著禁止` → `shot: 三個抽屜：專案、附件、記憶，看起來無限大` → `shot: 倉庫與桌子並排，倉庫很大，桌子很小` → `shot: 手推車從倉庫把一箱紙推到桌邊` → `shot: 倉庫裡的文件是縮小的卡片，不是逐字的原文` → `shot: 整理好的檔案櫃，每格有標籤，抽出一格` → `shot: 長文件分成幾段逐段處理，最後一張總校對表` → `shot: 三樣東西並排：量尺、桌子、倉庫`。收尾問題：「那上下文視窗、token 跟記憶，到底差在哪？」
6. **上下文視窗跟 token、記憶差在哪**（約 90 秒）：`shot: 一張桌子，旁邊一把尺、一間倉庫、一顆腦` → `table: token 刻度／上下文視窗 桌面／記憶 倉庫／模型參數 訓練來的本事` → `shot: 用尺量一疊紙的高度，再看桌面放不放得下` → `shot: 貼上桌的決議並沒有流進腦子` → `shot: 全新的空桌，剛才的紙不在` → `shot: 無臉人物在桌前先盤點桌上有什麼（站主觀點）` → `shot: 一張更大的桌子被推到一旁，人先拿摘要對原文` → `shot: 三個問題卡：沒放上去、放了沒讀到、讀了答錯` → `shot: 三個檢查點：收到什麼、限制留住沒、追得到證據嗎` → `shot: 說明欄的文章打開在桌上，旁邊三個步驟` → `outro: 留著，不等於讀到；下一步是說明欄第一行的文章`。最後一句回答開場：「留在畫面裡的訊息，模型不一定讀到；先看桌上有什麼。」

下一步只有一個：說明欄第一行的文章（把會議紀錄整理成可查核的工作集的三個步驟與檢查表）。token 那一集還沒上架，片尾不指它。

### 選項 B：先示範（未採用）

角度：開場就把失敗放在觀眾眼前，先看一句摘要怎麼把「尚未核准」壓掉，再回頭解釋桌面與容量；順序跟 A 相反（先果後因），適合已經被 AI 忘記過、想直接看解法的人。

開場（如實唸出）：「同樣六十二個字元，一句摘要把『尚未核准』壓掉了，另一句留住了。」（停 900）「十分鐘，你會知道模型這一次到底拿到什麼，還有換新對話前該帶什麼。」

你以為／其實：「你以為摘要只是把前面聊過的縮短一遍，資訊都還在 → 其實摘要留得住主題，留不住狀態；同樣六十二個字元、五十五對六十個 token，差的只是那四個字。」

1. **一句摘要，掉了四個字**（鉤子，約 18 秒）：`title` → `shot: 影印機吐出一張變薄的紙` → `shot: 便利貼上的四個字掉到地上`。收尾問題：「它為什麼會掉？」
2. **摘要為什麼會掉字**（約 90 秒）：`code: 兩段文字並排` → `shot: 摘要留住標題、擦掉狀態` → `chat: 右邊「請把前三次會議整理成一句」、左邊示意的摘要` → `shot: 新對話的空桌上只放著摘要`。收尾問題：「那模型這一次桌上到底有什麼？」
3. **這一輪的桌面有多大**（約 120 秒）：`shot` ×4（桌面、放什麼、留回答的位子、量尺） → `big: 桌面多大，就是上下文視窗` → `stats: 535 token｜1,121 份｜5,607 份`。收尾問題：「放得下就等於讀得懂嗎？」
4. **放得下，不等於讀得懂**（約 110 秒）：`chapter` → `diagram` → `shot` ×3（長桌、舊方案與撤回、報價草稿） → `quote: Lost in the Middle` → `shot` ×2。收尾問題：「那它忘了，是哪一種忘？」
5. **三種忘記怎麼分**（約 130 秒）：`steps: 沒送進去→縮小工作集／摘要漏掉→補原文／看了卻答錯→重組比對` → `shot` ×5 → `cta`。收尾問題：「換新對話前該帶什麼？」
6. **交接單與鄰近名詞**（約 130 秒）：`bullets: 交接單五格` → `shot` ×3 → `table: token／視窗／記憶／參數` → `shot` ×2 → `outro`。最後一句回答開場：「掉字的不是模型，是交接；先看桌上有什麼。」

## 會過期的事實

- 視窗大小的級距「二十萬」「一百萬」：Anthropic 的 Context windows 文件（https://platform.claude.com/docs/en/build-with-claude/context-windows，2026-09-30 開啟，原網址 docs.anthropic.com 轉址）寫「up to 1M tokens, depending on the model」與「a 200k-token context window」；Google 的 Long context（https://ai.google.dev/gemini-api/docs/long-context，2026-09-30）寫「large context windows of 1 million or more tokens」。只放在 `stats` 卡並標「以官網為準」，旁白不唸模型名稱、不講價格與方案。
- 輸入超過視窗時服務會明確回報（Anthropic 文件：「the API returns a 400 invalid_request_error ("prompt is too long")」）：措辭與錯誤碼可能改，影片只說「服務會直接告訴你輸入太長」。
- 官方對上下文視窗的定義句：Google 的 tokens 文件（https://ai.google.dev/gemini-api/docs/tokens）「The context window defines the combined limit of input and output tokens」；Anthropic「holds the conversation history plus the new output」。文件改版就重讀。
- 示範工具：tiktoken 0.14.0（https://pypi.org/project/tiktoken/，2026-09-30）與 `o200k_base` 編碼；換版本或編碼，數字要重算。
- Lost in the Middle（https://arxiv.org/abs/2307.03172，v3，2023-11-20）本身不會過期，但「這不是所有模型在所有問題上的鐵律」這句要維持。

## 不做的事

- 不比較哪家模型的視窗大，不排名；視窗大小只在 `stats` 卡放兩個官方級距並標「以官網為準」，旁白不唸模型名稱。
- 不講價格、方案、快取計費。
