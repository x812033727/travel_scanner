# 零台詞短劇：成片品管機制

站主 2026-11-04 定的規矩：**每一集成片都要過審核才能上架；有問題就修，修完再審。**
這份是成片的關卡；故事企劃在畫圖之前另有一道評分審核（`.agents/skills/animation-preproduction/references/comedy-review.md`）。

## 為什麼需要

2026-11-03／04 做的 20 集，第一版逐格掃描後抓到約 15 個嚴重、40 多個中等問題；沒有審核就直接交出去的那一版，站主自己看出「有些地方怪怪的」。
圖片與影片模型的錯是**系統性的**，不是偶發：

| 錯誤 | 出現在 | 原因 |
| --- | --- | --- |
| 人類手指、手臂（還有指甲油） | 角色手上拿東西的鏡頭；黃金獵犬、小豬最常見 | 模型把「拿」畫成人手 |
| 背景有人影 | 辦公室、街道、後巷 | 這類場景在訓練資料裡都有人 |
| 多一隻手、分身 | 插入特寫（「一隻手伸進來」）、兩個角色同框 | 模型同時畫了完整角色和伸進來的手 |
| 片段中途換景、換角色 | 5 秒片段的後半 | H3 自己剪接 |
| 不該有的物件仍在畫面 | 寫「原本掛時鐘的地方」→ 畫出時鐘 | 提示詞裡出現的名詞會被畫出來 |
| 假刊名、logo、浮水印 | 寫「像雜誌封面」、筆電、零食袋、成品照角落 | 同上；筆電會長出蘋果 logo |

## 四道關卡

### 第 0 關：寫 spec 時就避開（`make_episode.py` 的 spec）

- 一鏡一個主角；第二個角色用背影、反應鏡或下一鏡交代，不要「一隻手伸進來」。
- 角色要拿東西時，寫成東西**放在胸口／桌上／肚子上**，爪子放旁邊；必要時寫「two furry front paws」。
- 辦公室、街道直接寫「**身後就是一面牆**、沒有隔間、沒有窗戶通往別的房間」；不要只寫「沒有人」。
- 不想出現的物件**不要寫出它的名字**（不要寫「原本的時鐘不見了」）。
- 不要寫「像雜誌封面」；電子產品寫 plain、unbranded。
- 偽裝、被掛起來這種笑點，寫成角色 **himself／herself** 在做。

### 第 1 關：自動檢查（免費）

```bash
python3 docs/videos/zero-dialogue-series-ideas/production/qa_check.py <slug>
```

規格（1080×1920、30 fps、48 kHz、9–20 秒、−15～−13 LUFS）不過 = 結束碼 1，修完才往下。它也列出**鏡頭中間的硬切換景**（模型自己切走），
並產生每秒 3 格、帶時間碼的檢查圖 `<VIDEO_WORKDIR>/<slug>/qa/<slug>.jpg`，給第 2 關用。
剪接腳本 `edit.py` 會在片段中途的硬切換景之前自動剪掉，但「鏡頭慢慢移到別處」的那種抓不到，要靠第 2 關。

### 第 2 關：獨立審片

- **每一批開一個新的審片人**（另開的代理），沒看過前面的審核紀錄、也不是剪這一集的人。提示詞用 `review-prompt.md`，換掉系列設定與 slug。
- 審片人讀檢查圖，有疑點就從 `final.mp4` 抽大格確認；用「一般觀眾第一次在手機上滑到」的眼光。
- 嚴重度：**高**＝一眼看出很怪；**中**＝注意看會發現；**低**＝挑剔。每支一句「能不能上架」。

**笑點審核**（站主 2026-11-04：「笑點也要夠」）：成片看得到畫面，是判斷好不好笑最準的時候（企劃階段的文字評審看不到畫面）。
每支由**兩位**不同觀眾角色的審片人各自看檢查圖、必要時抽格，回答：

| 項目 | 怎麼評 |
| --- | --- |
| 鉤子 | 1–5：前 2 秒有沒有怪事或衝突，讓人不想滑走 |
| 笑點有畫出來 | 是／否：這集的核心笑點（偽裝那一格、被掛起來、成品照破綻、老闆的貓動作……）在畫面上看得懂嗎？只靠想像補的算「否」 |
| 收尾 | 1–5：最後一拍有沒有補刀、結得有力 |
| 好笑 | 1–5：1 不好笑、3 會心一笑、5 笑出聲；附一句理由 |
| 會轉傳 | 是／否：會不會丟給某個具體的人 |

**上架門檻**：兩位都判「笑點有畫出來」，而且「好笑」平均 ≥ 3；沒過就照審片人的建議修
（換剪接順序或時機、加停頓與音效、重畫笑點那一鏡、補一個反應鏡），修完再評。

**畫面上架門檻**：沒有「高」；下面這幾類就算只是「中」也要修——人類（含背景人影、人手）、多出的肢體或分身、看得懂的文字、品牌 logo、浮水印、
片段中途換角色、讓笑點看不懂的劇情矛盾。其他「中」（例如道具前後款式不同）可以在紀錄裡寫明「接受」後上架。

### 第 3 關：修正與複審

修法由便宜到貴：剪短 → 整鏡拿掉（音效併到前一鏡）→ 首格做慢推靜止 → 裁切／`delogo` → 重畫那一鏡（`redo.py` 的寫法：
新提示詞加上動物爪與空背景的限制、舊檔改名保留、`run_episode.sh` 只會重做缺的那幾鏡）。

修完重剪、重跑第 1 關，交回**同一位審片人**複審（他知道上一次指出了什麼），直到每支都是「可以上架」。
同一鏡重畫兩次還是同樣的錯，就換寫法（改構圖、拿掉那個動作）或整鏡拿掉，不要一直抽卡。

## 紀錄

每一批在這個資料夾寫一份 `QA-<日期>.md`：每集的最終判定、接受的已知問題、做過的修正。2026-11-04 的 20 集在 `QA-2026-11-04.md`。
