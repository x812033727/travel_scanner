## 為什麼選 P29

- 每個人都看過網址開頭的 https 和那個小鎖頭，也都被叮嚀過「有 https 才能打密碼」；小問的疑問（「不就多一個 S？」）就是觀眾的疑問。
- 它有一個真的會改結論的轉折：鎖頭和 https 不代表網站可信，詐騙網站一樣有（Chromium 2023：幾乎所有釣魚網站都用 HTTPS），因為發證只查「你管不管得了這個網址」。
- 素材審視第三輪補上了規格原文（RFC 8446、RFC 5280、RFC 9849、Let's Encrypt、CT），兩個規格自己承認的界線（不隱藏長度、搶先送出的信可能被重送）讓「保護到哪裡為止」有一手來源，不用靠資安新聞。

## 問題

小問在咖啡店，要用店裡的免費網路登入遊戲。媽媽叫她先看網址，開頭要是 https 才能打密碼。可是不就多一個 S？密碼還不是一樣要傳出去——多一個 S，密碼在路上到底差了什麼？

## 一句答案

你的密碼要經過咖啡店的機器、網路公司好幾站，每一站都不是你的；多一個 S（HTTPS，用 TLS 加密的 HTTP），代表三件事：
先確定對面真的是那個網站（它出示一張綁著網址名字的憑證，一層一層接到瀏覽器內建的根憑證，還要當場用只有它有的私鑰簽整段對話）；
兩邊在大家眼前算出只有彼此知道的秘密，之後每一筆都加密、有隱藏的編號，被改、被重送、被調換順序都會失敗。
可是它只保護路上：資料有多長、什麼時候傳、要找哪個網站的名字，路上還可能看得到；它也不管對方是不是好人——騙子替自己的相似網址一樣領得到憑證，所以還是要看清楚網址列上的名字。

我的看法是：這一集真正要留下的有兩句：「多一個 S，路上的人讀不到、改不掉、也冒充不了那個網址」和「它只保護路上，不保證對方是好人」（片尾小問只說讀不到與冒充不了那個網址，改不掉在 p122 講過）。
所以全片只用**一個比喻**（上課傳信給教室另一頭的好朋友）跑完：同學幫忙傳＝咖啡店與網路公司的機器；沒封的信誰都能看能改；

調顏料只借來想像「在大家眼前算出只有彼此知道的秘密」，片中明說真的做法是數學，不講數學。
鎖頭只借來回收開場的預告與說明「鎖頭不代表網站可信」：Chrome 2023 年宣布換掉鎖頭圖示的理由，片中照實說；不說哪個瀏覽器現在一定畫鎖頭。
「搶先送出」（0-RTT）只借來修正小問「每一封都不能重寄」的結論：規格自己用重要提醒標出來，不說哪些網站有開。
「寄完說我講完了」（close_notify）只借來兩句，不展開。
「把收件人的名字也封起來」（ECH）只借來說「有新規格在做，但它自己說不夠」：只說 2026 年 3 月發布，不說普及到什麼程度。
所長的「最妙的是，這個封條你每天都在用，卻從來沒有看清楚它」標成她的看法。插圖是示意，不畫真的瀏覽器、網址或任何字。

## 畫什麼（每張都是人看得到大小的日常物件，不畫網址、瀏覽器畫面上的字、箭頭、數量或方向）

- 平板一律寫成「a small tablet showing a plain pale grey bar along the top with one tiny padlock icon and soft pastel colour blocks below」：只有一個小鎖頭和色塊，沒有字。
- 傳信：陽光教室與木頭課桌（`classroom-pass`）、紅蠟封口的奶油色信封（`sealed-letter`、`letter-row`、`envelope-front`）、厚薄不同與一樣厚的信封（`thick-thin`、`padded-letters`）、
  信封正面畫一棟小紅屋代表收件人（`envelope-house`）、搶先滑出去的一封（`early-letter`）。
- 證件：一張只有卡通小臉和金色圓徽的學生證（`card-close`）、三張像樓梯排的卡片最高的是金色（`cards-stairs`）、抽屜裡一張金色小卡（`desk-drawer`）、走廊玻璃櫃裡整排一樣的卡片（`glass-case`，公開帳本）。
- 調顏料：三杯黃紅藍顏料（`paint-cups`）、兩杯一樣的深棕色（`two-cups`）。
- 網路與城市：咖啡店架上的白色無線路由器（`router-shelf`）、路口問路的郵差（`street-ask`、`street-ask-2`）、一個放著一疊灰色伺服器盒的奶油色櫃子（`server-cabinet`，網站的機器）、所長手捧一個灰色小盒（`chief-same-machine`，很多網站共用同一台）。

## 查核清單（結果在 `claims.md`）

- 資料經過路由器與網路公司的路由器（MDN）；沒有私人連線時別人可能看到與改掉（Chrome 說明）。
- TLS 假設攻擊者完全控制網路、三個性質、不隱藏長度（RFC 8446 §1）；HTTPS 的 S 與 TLS（MDN）；https 的意思（RFC 9110 §4.2.2）。
- 憑證驗證防冒充與名稱解析被控制、要有信任錨、身分要符合網址（RFC 9110 §4.3.4）；憑證綁網域與公鑰（CT、RFC 5280 §6.1）。
- 網域驗證：DNS 記錄或固定路徑的檔案、多個網路視角（Let's Encrypt How It Works）；鎖頭不代表可信、幾乎所有釣魚網站用 HTTPS、11%、換成 tune 圖示（Chromium 2023）。
- 信任鏈條件與信任錨是輸入（RFC 5280 §6.1）；根憑證由 user agent 散布、中繼簽發網站憑證（CT）；根金鑰離線、信任庫決定（Let's Encrypt Chains of Trust）。
- CT：只增不刪、誰都能查、Chrome 與 Safari 要求至少兩張 SCT、訂閱監測者（certificate.transparency.dev）。
- Chrome 整頁「Your connection is not private」與三種可能原因、要看網址列上的名字（Chrome 說明）；釣魚偵測與「Dangerous site」警告是封條以外的功能（Chrome 說明 answer/99020，p179）。
- 握手三階段、金鑰交換後全部加密、CertificateVerify、Finished、Application Data 不早於 Finished（RFC 8446 §2、§1.2）；前向保密（E.1）。
- additional_data 是紀錄標頭、沒有另外的完整性檢查、解密失敗必須中止（§5.2）；序號與 nonce（§5.3）；順序保護（E.2）；填充（§5.4）；流量分析（E.3）。
- 0-RTT 的重要提醒、重放與購買重複、伺服器的限制方法（§1.2、§2.3、E.5、§8）；close_notify 與截斷（§6.1）。
- SNI 明文、ECH、DNS 與 IP 仍可能露出、同一 IP 多網域（RFC 9849 §1，2026 年 3 月）；server_name（RFC 8446 §9.2）。
