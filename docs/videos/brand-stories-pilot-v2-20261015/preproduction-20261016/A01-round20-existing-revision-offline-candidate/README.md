# A01 round20 existing-story 81→82 revision — offline fixture, HOLD

This is a **new isolated model** for adopting the frozen [round20 candidate](../A01-round20-i17-fact-index-candidate/README.md) into an A01 story that already has six worker chapters and a continuous audit chain. It does not use the draft #1518 author package, which is only valid before the first writer. It does not change any existing candidate, historical audit event, `tools/video`, production host, database or provider. There is **no CLI or production installer**. The only write function refuses roots outside a marked directory under the OS temporary directory. Every successful result still says `production_status: HOLD`, `installation_allowed: false`, `paid_work_allowed: false`.

## Exact offline transition

`planOfflineRevision()` first runs the existing `verifyProposedTransition()` against **separate** immutable 80- and 81-event snapshots. Thus the 81st event must be the exact lexicon-only proposal, with the original 80 events, their historical installation receipts, original tip and new shared-lexicon bytes independently intact. A row added to the 81-event snapshot by hand, or a repinned old inspector, is rejected. The round20 `manifest.json` SHA-256 is fixed at `4d701779891e1076c3729788cc82165901d71140bfbd77c07fa9b1c060b32549`; all six chapter files, series, source map and validation bytes are checked against it. The 27 active source-map rows must resolve to the exact line, claim when present, series source URL and fact index. Split `o2` lines, two source-bound questions and unsourced general-physics `n14` retain their distinct documented relationships; this check is a binding check, **not** an independent fact verdict.

The proposed **82nd** event changes only `auto.json`, `series.json` and six `story/chapters/*.json` files. In `auto.json`, all six chapter `checked`/`listened` flags and aggregate `verified`/`listener_done` become false; each revised chapter's `check_rounds` and `lint_fixes` restart at zero, and its old `changed` tally is removed. The blocked state, `narrative_fixes=2` and genuine failed panel remain. Old counters and tallies remain in the immutable 81 snapshot, the transaction's exact `before/auto.json` backup and the 82nd `author-manifest.json` audit field. This matters because the current worker increments `check_rounds` before each check: retaining round 2 would let four `CHANGED` rows hit its round-3 cap and mark the chapter checked without another check. The proposal keeps existing `video.json`, `script.md`, `claims.md` and `verify-1.md` as **stale historical output** until the actual worker rechecks a chapter and calls `relint()`. It refuses a pre-existing pilot `script-review.json`. No panel PASS, fact PASS, script receipt, speech or media is synthesized by this transaction. The worker must be tested against the exact revised `auto.json` before any operational adoption: its first step has to be a chapter verifier and relint, with no downstream stage using stale generated documents.

The worker's configured maximum can still set `checked=true` on a later round with unresolved `CHANGED`, `ATTRIBUTED` or `NOT FOUND` rows. Neither that chapter flag nor aggregate `verified=true` is a factual PASS. An independent reviewer must inspect the exact verdicts and claim/source bindings before accepting the revised story. This fixture changes only the starting counters; it does not change the worker's cap policy.

`prepareOfflineRevision()` requires external raw independent-review and record-receipt bytes bound to the proposed plan, current source composite, round20 manifest and event ID. Their reviewer/operator/owner-reference strings are **not authentication**. It returns four proposed files: one receipt and an `index.json`, `author-manifest.json` and independent-review file for `story/recheck-audit/<event>`. The index links the exact 81st tip to the proposed 82nd source composite. `verify82Fixture()` requires precisely the original 81 event IDs plus that one event, the original 81 file bytes and revision receipts, the exact four new files, exact target chapter/series/state bytes and no other source-map field change. The historical 80 and 81 pins remain separately verifiable and are never rewritten.

## Synthetic transaction and crash boundary

`applyOfflineFixture()` requires an OS-Temp root containing `A01-ROUND20-82-OFFLINE-FIXTURE.json` and the existing exact 81 source copied from its immutable snapshot. It checks supplied synthetic STOP, LEASE, job, retry, budget, release and review fields, then stages an intent, original-source backups and proposed event bytes. It rechecks its pinned plan, STOP bytes and history immediately before writing. It atomically replaces only the eight source files, publishes the new receipt directory, and publishes the audit directory **last**; exact readback then verifies the 82nd transition. An ordinary error rolls back only exact new bytes and keeps transaction evidence. A simulated process death after source files or receipt leaves a partial HOLD and forbids blind retry. A death after the complete event can be recognized only by full exact 82-event readback. A concurrent edit blocks destructive rollback.

The fixture does **not** establish a production lock. A per-video `LEASE` cannot exclude another video's shared-lexicon write, and the repo does not define one lock honored by every manual audit writer. The host docs/work mounts are separate; this Temp transaction's file operations are not a reviewed two-mount host adapter. The synthetic safety object does not prove current DB, provider cost, STOP, worker process or operator exclusivity. There is no fresh host-origin 81-event snapshot or real round20 reviewer/receipt, and the 2026-10-16 live observation remains historical. Production remains HOLD until a separately reviewed host capture, coordinated writer window, actual human review/owner-approved exact paths, host implementation, crash exercise and post-write readback exist. A different lexicon SHA, extra audit event, changed round20 bytes or altered live A01 state requires a new proposal.
