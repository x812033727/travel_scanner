## P2：row 的 `attributed:true` 與部分實際口播未對齊

本候選 `B18.json` 的 `must_verify[3]` 把轉角壅塞與掉盤、約十年、兩種扇形靈感和板片結果合為一筆，整筆標 `attributed: true`。品牌故事規則 [story.md 的「查核怎麼做」](../../../../../.agents/skills/youtube-video/references/story.md)寫明：`attributed: true` 時旁白要說是誰的說法（例如「照某某的說法」），不能當成無歸屬的定論。

- `hook-s004`／`h5` 實際第一句是「他把點子帶回小店，輸送帶卻在轉角堵住，盤子掉下來」；這是直接陳述。該景是 `shot`，沒有來源字卡；相鄰 `hook-s003` 與 `hook-s005` 也未說「據 J-Net21」。
- `idea-s024`／`i1` 實際句是「一到轉角，帶子擠在一起，盤子就可能掉下來」；`idea-s023`／`s025` 也未為此句標來源。`idea-s027` 才開始說兩份資料不同，明確歸屬的是後面的撲克牌／名片靈感，不會倒回去替 `i1` 做口播歸屬。
- 同一 row fact 綁到的 `i5`／`i6`／`i7`／`n7` 也以無歸屬的工程結果或時長口播；這些有官方來源支持，但在目前**整筆** `attributed:true` 下，形式與規則仍衝突。`i3`、`i4` 已各自有可聽見的來源歸屬，不是這項缺口。

這是規則與稿件的對齊問題，並非「轉角壅塞、盤子掉落」查無來源。**最小修正範圍**限於 `must_verify[3]` 的歸屬設計及它直接綁定的場景：可把可直接確認的工程事實與有版本分歧的靈感拆成兩筆，只把後者標 `attributed:true`；或在相關口播明講 J-Net21／其他來源。若採語義例外而讓 `attributed:true` 只管靈感兩版本，須在新 row 的審稿收據明記例外的精確子句與 65 筆映射，不能默認。任何改動都要重算 canonical hash、重做 row／逐景映射與獨立審稿，並確認新旁白與 fullscript 一致。
