**Local review package only. It has not been installed or run on production. No model or media call was made by this package.** The pilot ticket owns these files. Independent code review and an exact site-owner host-write approval are required before installation, validation or a production phase.

## Proven live facts and boundary

- `video-worker` normally runs `worker.sh` with auto and Shorts loops. Owner Retry can make blocked A01 runnable while STOP is absent. `video-ai-worker` handles durable model jobs independently. The release hold blocks deployment, not owner Retry or manual Docker commands.

The actual phase acquires A01 LEASE, temporarily removes STOP around reviewed work, then restores it in `finally` if the process survives.

## Fence used by this package

1. Keep A01 STOP present. Pin both original video container IDs, site Retry IDs, active job counts, budget and exact staged files. The `validate` service performs a no-model preflight **only inside** an inert one-off container. It **writes** a private `/tmp` capture, Docker container metadata and a one-off marker; it is not read-only. It never copies into or runs the old driver in the original worker's private `/tmp`.
2. For one phase, acquire all four deploy locks and the round-specific release hold. Change **both original video containers** to Docker `restart=no` and read it back. Create a temporary **global** STOP while A01's project STOP remains present; wait for queued/running jobs and project LEASEs to be absent and for the worker process tree to contain **no auto Node process**, Shorts tick, renderer or other unrecognized child. Only the worker shell, Docker init and sleep are quiet. If auto has not exited within 120 seconds, fail closed with the global STOP still present; do not interrupt it by stopping the container. Once quiet, stop the original `video-worker`, verify it stopped, and remove only the exact global STOP bytes written by this runner. Its auto and Shorts loops are now absent. Keep the original `video-ai-worker` running with `restart=no` so a reviewed stage can complete. No unrelated video work may be active when this begins. On an error during this drain, the global STOP intentionally remains until manual reconciliation.
3. Resolve the original worker's exact image reference and ID; the 2026-10-17 read-only observation was `travel-scanner-video-worker:local` with image ID `sha256:9255d808f59ea07f5626ddc360836a75fd35f11f51e2396859b78a581b8c139b`. `container_id()` queries Docker with exact Compose project/service/`oneoff=False` labels and requires one full 64-character original ID; `docker compose ps --all` can include a later `compose run` one-off and is not used to identify the original. Require both image pins to match the original container and Docker's tag resolution, and `docker compose --profile video config --images` to include the reference. HEAD is pinned separately; the local Docker tag is **not** a Git SHA. The runner sets `RELEASE_SHA=local` before Compose commands, preventing `${RELEASE_SHA:-local}` from selecting a different image. Create a `docker compose --profile video run --rm --detach --no-deps --pull never` one-off using the `video-worker` service, with command `sleep infinity`. The disposable Compose 2.40 test returned a full ID on stdout, but the runner independently resolves its full ID by the exact phase label, requires one match, and reads back the fixed name plus project/service/`oneoff=True` labels before writing the durable ID marker. This avoids relying on CLI output capture; if it crashes before that marker, `ExecStopPost` still finds the fixed label. The one-off inherits the worker's named volumes, site network, environment and hostname. The original same-hostname worker is already stopped for a paid phase, so there is no concurrent auto process or LEASE contender. For `validate`, original worker remains running but A01 STOP remains present and no direct phase runs. Pin the one-off's exact image ID, named volumes, network, `AutoRemove=true`, `restart=no` and `VIDEO_INTERNAL_SITE=http://web:3000`. Persist its ID in the A01 volume before the direct phase can start. Every direct Node invocation explicitly sets `MOKAAIR_SITE=http://web:3000`, matching `worker.sh` rather than falling back to the public endpoint.
4. The service's `/tmp` is a private tmpfs. Before `validate` or any phase, copy the independently reviewed `round12-r4-full-payload.tar.gz` archive to the **host** pinned release directory and run `a01_stage_payload.py --check`, then `--stage` under exact host-write approval. The archive has SHA-256 `ae7483b2867bd0dd479fe6177c7261be2e7abb47d6fe53c3c21bb89943833792`, top-level `payload/`, 979 files, 372 directories and no links. The stage helper rejects unsafe paths, links, special files, count or hash drift and an existing destination; it extracts into a new private directory and atomically renames it to `/root/mokaair-a01-round12-20261017-fe35369c/payload`. The runner derives all 979 file hashes from the pinned archive and compares every host extracted file, directory and extra entry. It repeats this check immediately before copying into the one-off's `/tmp/a01-round12-20261017-fe35369c/payload`, makes only that private tmpfs payload readable to `pwuser`, and compares its entire tree and 979 hashes there. The manifest separately pins the phase-critical files. The old original worker's `/tmp` is never a staging source. Run no-model preflight only in the one-off and require exact source/link evidence. Only then hardlink the original STOP to `STOP.a01-round12-held`, fsync the release marker, and write the phase driver's required pending sentinel. Recheck stopped original auto, live AI worker, policy `no`, Retry IDs and job quiet state. Then run the **one** exact phase by `docker exec` into this pinned one-off.
5. The systemd phase service's `ExecStopPost` runs on exit or host runner SIGKILL. It first finds A01 one-offs by both durable ID marker and fixed Docker label, kills any still-running one-off, verifies each stopped or removed, and only then restores the project STOP. If Docker cannot prove the one-off stopped, it still attempts STOP restoration but reports failure; the original auto remains stopped with restart=no and the release hold stays. This is important because killing a host `docker exec` CLI does not prove the Node process inside its container died.
6. After a normal phase, require no queued/running stage or media job, no uncertain budget operation, stable Retry IDs, and the exact next audit link. Restart the original `video-worker` only **after** STOP was read back and inspect it. Restore both original `unless-stopped` policies and read them back. Disarm the STOP marker and clear the phase sentinels. Keep the release hold until all four phases and final audit are reconciled.

The unit is bounded by `RuntimeMaxSec=90min` and does not retry. The sole paid `docker exec` has a 60-minute subprocess timeout; other runner commands have 120 seconds and recovery Docker commands have 10 seconds each. A timeout makes the result uncertain, triggers `ExecStopPost`, and retains the hold/restart=no until reconciliation. `TimeoutStopSec=90s` bounds systemd recovery; a disposable fault run must prove it finishes inside that limit. The gated `fault-test` mode deliberately waits for MainPID SIGKILL but is subject to the same 90-minute unit cap.

Docker's official [restart policy](https://docs.docker.com/engine/containers/start-containers-automatically/) says `no` does not automatically restart a container; [container update](https://docs.docker.com/reference/cli/docker/container/update/) says a new policy takes effect immediately. [Compose run](https://docs.docker.com/reference/cli/docker/compose/run/) documents `--rm` overriding the service's restart policy and `--no-deps` avoiding linked-service startup. The runner nevertheless reads back each actual container policy and ID. This design has **no `RequiredBy=docker.service` hook**: a broken A01 volume will not prevent the rest of the site starting. A provider-free Docker 29.1.3 daemon-restart test with STOP lifted confirmed both originals stayed stopped at `restart=no`, the AutoRemove one-off disappeared, and the original STOP inode could be restored before any video restart. A full production-like VM reboot is untested; the distinct risk is a boot unit, timer, cron or cloud-init hook that starts video Compose manually. Refresh the production boot-start inventory before host writes. After any actual host reboot, restore/read back STOP and reconcile jobs before starting any video container. An out-of-band root start remains a bypass.

## Fault behavior and rollback

| Fault | Required result and receipt |
| --- | --- |
| Host runner SIGKILL or Docker CLI lost | `ExecStopPost` finds the one-off by ID or label, kills it, verifies no running process, then restores STOP. Keep hold and restart=no until stage/budget receipt is reconciled. |
| One-off container killed | Its AutoRemove/restart=no prevents recreation. `ExecStopPost` restores STOP. A dispatched AI job can still finish or become uncertain; never resubmit with a fresh key by assumption. |
| Original auto or AI container killed | Both have restart=no for the window. No automatic A01 retry; reconcile existing jobs before starting either. |
| Host reboot | Original auto, AI and one-off are expected stopped/removed. STOP or held hardlink and markers persist in the named volume. Restore STOP manually and read back it, jobs, leases and budget **before** starting any video container. Do not clear the release hold on reboot alone. |
| Missing, truncated or invalid one-off marker | `ExecStopPost` still scans the fixed Docker label and kills any matching one-off before restoring STOP. A malformed marker makes the service fail after recovery and retains the hold for reconciliation. If Docker or the volume is unreadable, retain hold and stopped auto; do not start video containers. |

Normal rollback before the phase: leave project STOP present, kill the sleep-only one-off and prove stopped, start original auto under STOP, restore both original restart policies, clear only this round's release hold after no active jobs/leases, and retain a receipt. After any possible dispatch: kill/prove one-off stopped first, restore STOP from held link, retain marker/hold and restart=no, reconcile stage and media jobs plus budget uncertainty; only then restart auto and restore policies. A stopped container does not start merely because its policy changed. The `--rm` one-off may already have disappeared; validate `No such object` rather than treating a Docker daemon error as proof.

On host reboot, the A01 one-off marker may point to an auto-removed container. An operator must compare it with `docker ps -a --no-trunc --filter label=mokaair.a01.round12`, restore STOP, verify job and budget evidence, then clear the marker under the round's locks. Do not rerun a phase merely because its one-off is gone. To uninstall the helper/unit after the complete round, prove STOP is present, no one-off/hold/pending phase remains, both original policies are restored, and the unit inactive; remove only the exact installed three helper files and unit, `systemctl daemon-reload`, then read back their absence. Uninstall is a separate host write.

## Residual risks and required approval

An out-of-band root `docker compose up/start/restart`, manual new worker container or direct script call can bypass this host-only fence. The release hold/locks cover the normal deployment path; use one host operator and do not press A01 Retry during the review. The runner checks Retry IDs at checkpoints, but a concurrent click can still change the site row while a reviewed call is in flight; if it does, the phase remains held for reconciliation. Stopping original `video-worker` also pauses all ordinary video auto and Shorts during each window; `video-ai-worker` loses crash auto-restart for the window. The existing AI job can continue after its caller dies, so job and budget receipts determine whether another phase is allowed.

`prod-host-ops`, `deploy` and `ops/release/README.md` require exact site-owner approval for installation, `validate`'s bounded host writes, both Docker policy changes and original worker stop/start, one-off create/copy/kill, release hold, temporary project STOP lift and direct phase calls. One approval may cover that concrete setup and the four guarded editorial phases if it names the scope, US$25 total cap and stop-on-drift conditions; it does not remove per-phase readback gates. The existing A01 spending cap alone does not approve new host service changes. An independent reviewer must accept the frozen package and disposable Linux/systemd/Docker fault receipts before requesting owner approval.
