The unit is bounded by `RuntimeMaxSec=90min` and does not retry. The sole paid `docker exec` has a 60-minute subprocess timeout; other runner commands have 120 seconds and recovery Docker commands have 10 seconds each. A timeout makes the result uncertain, triggers `ExecStopPost`, and retains the hold/restart=no until reconciliation. `TimeoutStopSec=90s` bounds systemd recovery; a disposable fault run must prove it finishes inside that limit. The gated `fault-test` mode deliberately waits for MainPID SIGKILL but is subject to the same 90-minute unit cap.

Docker's official [restart policy](https://docs.docker.com/engine/containers/start-containers-automatically/) says `no` does not automatically restart a container; [container update](https://docs.docker.com/reference/cli/docker/container/update/) says a new policy takes effect immediately. [Compose run](https://docs.docker.com/reference/cli/docker/compose/run/) documents `--rm` overriding the service's restart policy and `--no-deps` avoiding linked-service startup. The runner nevertheless reads back each actual container policy and ID. This design has **no `RequiredBy=docker.service` hook**: a broken A01 volume will not prevent the rest of the site starting. A provider-free Docker 29.1.3 daemon-restart test with STOP lifted confirmed both originals stayed stopped at `restart=no`, the AutoRemove one-off disappeared, and the original STOP inode could be restored before any video restart. A full production-like VM reboot is untested; the distinct risk is a boot unit, timer, cron or cloud-init hook that starts video Compose manually. Refresh the production boot-start inventory before host writes. After any actual host reboot, restore/read back STOP and reconcile jobs before starting any video container. An out-of-band root start remains a bypass.

## Fault behavior and rollback

| Fault | Required result and receipt |
| --- | --- |
| Host runner SIGKILL or Docker CLI lost | `ExecStopPost` finds the one-off by ID or label, kills it, verifies no running process, then restores STOP. Keep hold and restart=no until stage/budget receipt is reconciled. |
| One-off container killed | Its AutoRemove/restart=no prevents recreation. `ExecStopPost` restores STOP. A dispatched AI job can still finish or become uncertain; never resubmit with a fresh key by assumption. |
| Original auto or AI container killed | Both have restart=no for the window. No automatic A01 retry; reconcile existing jobs before starting either. |
| Host reboot | Original auto, AI and one-off are expected stopped/removed. STOP or held hardlink and markers persist in the named volume. Restore STOP manually and read back it, jobs, leases and budget **before** starting any video container. Do not clear the release hold on reboot alone. |
| Missing, truncated or invalid one-off marker | `ExecStopPost` still scans the fixed Docker label and kills any matching one-off before restoring STOP. A malformed marker makes the service fail after recovery and retains the hold for reconciliation. If Docker or the volume is unreadable, retain hold and stopped auto; do not start video containers. |

Normal rollback before the phase: leave project STOP present, kill the sleep-only one-off and prove stopped, start original auto under STOP, restore both original restart policies and retain a receipt. In the zero-media route, clear only this round's release hold after no active jobs/leases. In the fenced route, **keep the cutover hold and nonce** even if the A01 phase never dispatched. After any possible dispatch: kill/prove one-off stopped first, restore STOP from held link, retain marker/hold and restart=no, reconcile stage and media jobs plus budget uncertainty; only then restart auto and restore policies. A stopped container does not start merely because its policy changed. The `--rm` one-off may already have disappeared; validate `No such object` rather than treating a Docker daemon error as proof.

On host reboot, the A01 one-off marker may point to an auto-removed container. An operator must compare it with `docker ps -a --no-trunc --filter label=mokaair.a01.round12`, restore STOP, verify job and budget evidence, then clear the marker under the round's locks. Do not rerun a phase merely because its one-off is gone. To uninstall the helper/unit after the complete round, prove STOP is present, no one-off/hold/pending phase remains, both original policies are restored, and the unit inactive; remove only the exact installed three helper files and unit, `systemctl daemon-reload`, then read back their absence. Uninstall is a separate host write.

## Residual risks and required approval

An out-of-band root `docker compose up/start/restart`, manual new worker container or direct script call can bypass this host-only fence. The release hold/locks cover the normal deployment path; use one host operator and do not press A01 Retry during the review. The runner checks Retry IDs at checkpoints, but a concurrent click can still change the site row while a reviewed call is in flight; if it does, the phase remains held for reconciliation. Stopping original `video-worker` also pauses all ordinary video auto and Shorts during each window; `video-ai-worker` loses crash auto-restart for the window. The existing AI job can continue after its caller dies, so job and budget receipts determine whether another phase is allowed.

`prod-host-ops`, `deploy` and `ops/release/README.md` require exact site-owner approval for installation, `validate`'s bounded host writes, both Docker policy changes and original worker stop/start, one-off create/copy/kill, release hold, temporary project STOP lift and direct phase calls. With the queued-media exception, approval must also name the API dispatch-fence release, exact marker/nonce/watcher installation and their retention. One approval may cover that concrete setup and the four guarded editorial phases if it names the scope, US$25 total cap and stop-on-drift conditions; it does not remove per-phase readback gates. The existing A01 spending cap alone does not approve new host service changes. An independent reviewer must accept the frozen R9 package, API fence, host cutover and disposable Linux/systemd/Docker fault receipts before requesting owner approval.
