### wrong-name-diagnosis

**畫面｜steps**

排錯依序看，不靠猜

- 核對完整路徑：是不是這份練習副本

**旁白**

先確定面板查的是這份副本，再把完整檔名逐字比對。

連字號、底線和副檔名都算名字的一部分，不能只看開頭。

### wrong-name-fix

**畫面｜steps**

- 改回 cover-brief.md：保留原有內容

**旁白**

把名字改回約定的寫法，內容不用重做。

換副本，也要換查詢路徑

### one-time-prompt

**旁白**

每週都用相同規則，你才更需要固定按鈕和一致畫面。

### not-every-task-panel

**畫面｜big**

先寫需求，再決定工具

**旁白**

### history-not-success

**畫面｜big**

有編輯事件，不等於最終內容正確

**旁白**

### date-repair

**畫面｜code**

不小心改到地點，就精確指出範圍

**旁白**

如果它連地點都改了，就給出原值和需要保留的日期。

比起只說改錯了，明確指出範圍，才有下一次可核對的結果。

### change-review-use

**畫面｜big**

單一改動直接對照；大量修改分段檢查

**旁白**

只改一處，直接看前後文字最清楚。

經常一次改很多份，才值得把變更回顧也放進工作介面。

## 附件：完整可複製需求

這是文字教材，不逐字口播。主案例先用隨附且已驗證的完整模組；這段生成提示是理解與改寫需求的可選路線，生成結果不會自動等同站主試過的版本。

```text
請幫我設計並建立一個 Claude Code Mod，名稱為 delivery-check。
我不會寫程式，目的是交稿前找缺件，不是判斷文章品質。
練習資料夾的完整路徑：<貼上自己的 delivery-practice 完整路徑>
程式放在 mods-lesson 下的 delivery-check，與練習材料分開。
先產生程式、使用說明與能力清單，先不要載入或安裝。
依適用版本的官方文件和型別確認可行性；不支援就明說，不用假資料補上。

1. 提供 /deliverables 指令，開啟交稿檢查面板。
2. 第一次以 /deliverables "資料夾完整路徑" 指定目錄，正確處理空格。
   在畫面顯示實際使用的絕對路徑，只在本次對話記住它。
   重載或結束對話會清除，要重新指定；未指定就詢問，不猜其他目錄。
   如果參數方式不受支援，先說明，不自行換成默認資料夾。
3. 先確認指定目錄可檢查，再核對 article.md、sources.md、cover-brief.md。
   只核對這三個約定名稱；不遞迴、不讀內容、不修改或補建檔案。
4. 開啟或按重新檢查時才查詢，顯示本次時間，不把舊結果當最新。
5. 存在就寫「路徑存在，內容待審閱」；不存在寫「缺少」。
   權限或環境出錯，寫「無法檢查」，並顯示可理解的原因。
6. 不顯示完成百分比、不估剩餘時間，三項存在也不寫可以交稿。
7. 檢查功能不呼叫模型、不連網、不啟動其他程式。
   如果認為需要，先說明原因，不自行加入。

驗證方式：
- 只有前兩份時，第三項缺少。
- 補上第三份並手動刷新後，三項存在，內容仍待審閱。
- 第三份是空白檔時，仍不能說內容合格。
- 換錯目錄、改錯檔名，以及不能存取時，能區分原因。

請附開啟、關閉與停止載入說明，不把沒執行的測試寫成已通過。
```

補件、一次性查件、內容審閱、單改日期與課程變式的完整提示已在各對應畫面；起始材料與答案也可直接複製。課程版模組是延伸需求設計，未宣稱已完成第二個模組。
