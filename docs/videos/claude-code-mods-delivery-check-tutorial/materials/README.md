# 交稿檢查面板：Windows 跟做教材

這份教材讓你用現成的 Claude Code Mod，核對文章、資料依據與封面需求有沒有放齊。你會完成「找出缺件 → 補入材料 → 手動重新檢查」，再用空白檔與錯檔名練習判斷結果。

影片後段的完整生成需求、內容審閱、日期修改提示，以及課程大綱／題目／答案，請看 [可複製提示與練習](EXERCISES.md)。課程材料已附在 lesson-fixtures；起始練習只複製大綱與題目，答案留到後面再補。本包沒有第二個課程版 Mod。

本例只核對約定檔名，不讀文章內容、不補建檔案，也不會替你評分。三份都存在，仍要閱讀內容才能決定是否能交付。

## 1. 準備程式與材料

需要 Windows 電腦，以及已能正常開啟、使用的 Claude Code。Mods 的版本門檻為 **2.1.287 以上**，這次主案例使用 **2.1.293**；版本資料確認日為 2026-10-09。安裝與帳號設定請依 [Claude Code 官方建立指南](https://code.claude.com/docs/en/plugins/mods/create)。

先取得隨片教材並解壓縮，不要直接在 ZIP 預覽內操作。本說明使用 `C:\mods-lesson` 作為練習位置：把包含本 README、`delivery-check` 與 `delivery-fixtures` 的資料夾命名為 `mods-lesson`，放到 C 槽根目錄。如果那裡已有你的資料，不要覆蓋；選另一個自己的本機資料夾，後面所有路徑一起換成實際位置即可。

完整模組至少要有以下四個程式檔。**整個 `delivery-check` 資料夾一起複製**，包括名稱以點開頭的 `.claude-plugin`，不要只拿一支程式。

```text
C:\mods-lesson\
  README.md                         ← 從這份開始
  delivery-check\
    .claude-plugin\
      plugin.json
    hooks\
      hooks.json
      register.mjs
      delivery-logic.mjs
  delivery-fixtures\                ← 保留完整範本，不在這裡改
    article.md
    sources.md
    cover-brief.md
  delivery-practice\                ← 本次工作副本
    article.md
    sources.md
                                    ← 起初不要有 cover-brief.md
```

如果教材尚未附上 `delivery-practice`，在檔案總管建立它，然後**只從 `delivery-fixtures` 複製 `article.md` 和 `sources.md`** 進去。若已附上，就先核對裡面只有這兩份練習檔。不要把整個範本資料夾的三份檔案全複製進起始副本，否則第一次就沒有缺件可找。

在檔案總管開啟「檢視 → 顯示 → 副檔名」（不同 Windows 版本可能直接叫「副檔名」）。完整名字要是 `article.md`、`sources.md`，不是 `article.md.txt`。

先分別打開兩份檔案閱讀：公告日期為 10 月 24 日、地點為里民活動中心；報名方式待主辦人確認。這是自製教學情境，不是真實活動通知。

## 2. 分清兩個輸入位置

| 在哪裡輸入 | 外觀與用途 | 本教材的例子 |
| --- | --- | --- |
| Windows PowerShell／終端機 | 啟動程式前的命令列，常見提示開頭為 `PS` | `claude --version`、`claude --plugin-dir ...` |
| Claude Code 互動對話框 | 執行載入命令後進入的 Claude 對話 | `/deliverables "C:\mods-lesson\delivery-practice"` |

**`/deliverables` 要輸入 Claude Code 對話框，不是 PowerShell。** 後面若要整理檔案，使用檔案總管即可，不要把檔案操作命令當成 Claude 對話送出。

## 3. 載入前，確認版本與程式來源

模組以你的使用者權限執行。先確認取得的是完整隨片範例；不明來源或被改過的程式，先找能看程式的人核對。這份範例讀指定資料夾的一層檔名清單，沒有讀文章內容、網路、模型、其他程序或寫檔呼叫。這不表示整個 Claude Code 對話離線或免費。模組自行啟動的程序，也不自動受 Claude 指令沙盒保護；參考 [官方安全說明](https://code.claude.com/docs/en/plugins/security)。

打開一個專供這次練習使用的 PowerShell 視窗或終端機分頁，依序輸入以下命令。這是你要執行的指令，不是本教材偽造的成功輸出。

```powershell
Set-Location -LiteralPath 'C:\mods-lesson'
Get-Location
claude --version
```

核對 `Get-Location` 顯示 `C:\mods-lesson`，版本符合上面的門檻。若出現找不到 `claude`，先完成官方安裝或在安裝後重新開終端機；不要繼續猜其他命令。

接著驗證完整模組目錄：

```powershell
claude plugin validate .\delivery-check
```

閱讀實際結果；若有錯誤，先處理，不直接跳到載入。常見原因是目前位置不對，或解壓縮時漏了 `.claude-plugin`、`hooks` 內的檔案。驗證通過也只代表程式結構等檢查通過，不能代替接下來的缺件測試。

## 4. 單次載入，指定要檢查的資料夾

仍在同一個 PowerShell 視窗／分頁執行：

```powershell
claude --plugin-dir .\delivery-check
```

這會以此目錄為這次對話載入模組，不需要先發布到 marketplace。若程式詢問是否信任或允許存取，先確認顯示的是你自己的練習目錄，依你使用環境的規則處理；不要為了跟做關掉原有保護。

進入 **Claude Code 互動對話** 後，在它的對話輸入框送出：

```text
/deliverables "C:\mods-lesson\delivery-practice"
```

使用自己的實際完整路徑，保留雙引號。單一反斜線就可以，不用寫成兩條。這份範例接受本機完整路徑；不要改用相對路徑、網路共享路徑或把占位用的尖括號原樣貼入。

面板位置由 Claude Code 決定。先找到「交稿檢查 v2」，核對頂端的「檢查資料夾」確實是 `C:\mods-lesson\delivery-practice`。預期看到：

| 名稱 | 起始預期結果 |
| --- | --- |
| `article.md` | 路徑存在，內容待審閱 |
| `sources.md` | 路徑存在，內容待審閱 |
| `cover-brief.md` | 缺少 |

同時記下「上次檢查（UTC）」顯示的時間。UTC 與台灣時間差 8 小時；你的時間不需要與影片一樣，重點是有本次完成查詢的時間。

如果結果不同，先核對面板完整路徑、資料夾裡的完整檔名，以及是否已完成查詢；不要手動改狀態文字來配合預期。

## 5. 補入封面材料，再按重新檢查

保留 Claude Code 開著。回到**檔案總管**：

1. 開啟 `C:\mods-lesson\delivery-fixtures`。
2. 複製 `cover-brief.md`。
3. 貼到 `C:\mods-lesson\delivery-practice`。此處先前應沒有同名檔；如果要求覆蓋，先回頭核對你是否用錯副本。
4. 打開剛貼上的檔案，確認有下列內容；`article.md` 和 `sources.md` 不要改。

```markdown
# 封面需求

主標：社區讀書會
副標：帶一本書，分享一個觀點
版面：白色背景、深藍標題，預留一個書本插圖位置。
本文件只描述需求，不代表圖片已製作完成。
```

回到交稿檢查面板，按 **「重新檢查」**。核對兩件事：

- 「上次檢查（UTC）」已更新。
- `cover-brief.md` 從「缺少」變成「路徑存在，內容待審閱」，原先兩份仍存在。

這次做的是複製提供的封面材料，不需要請模型生成，也沒有製作封面圖片。面板不持續監看資料夾：檔案改了、畫面重繪了，都不表示已重新查詢。按鈕會重新讀取當下的檔名清單、對照約定的三個名字，再更新狀態與時間。

主案例已有站主原生操作的文字回報，支持缺件、補件與按鈕刷新；影片把它做成結果整理卡，沒有把它當成操作錄影。

## 6. 有三份檔案，仍不能直接交

打開三份文件閱讀。這份公告的報名方式還待主辦人確認，資料依據也寫聯絡窗口未確認。即使面板全部顯示存在，也不會替你解決這兩件事。

只偶爾檢查一次，可以直接用一次性提示；常常重複同一套清單，希望有一致的按鈕與畫面，才更適合固定 Mod。內容審閱是另一個工作，可以使用下列提示，但這會是模型閱讀文件的請求，與本模組的路徑查詢不同：

```text
請閱讀這個練習資料夾的三份文件，先不要修改：
C:\mods-lesson\delivery-practice
逐份列出內容、缺少的資訊，以及需要人工確認的地方。
每個問題附檔名和對應原文。
不要把檔案存在當成內容合格，不自行補造報名方式。
```

## 7. 空白檔練習：名字在，內容也可能沒寫

以下是供你跟做的案例與預期判讀，沒有宣稱已取得這些案例的原生成功紀錄。都在新副本做，保留已補完整的 `delivery-practice` 和原始範本。

1. 在檔案總管複製整個 `delivery-practice`，把副本命名為 `delivery-practice-blank`，放在 `C:\mods-lesson` 下。
2. 用純文字編輯器打開**副本裡**的 `cover-brief.md`，選取全部文字、清空並儲存。只清這份副本，不改完整材料。
3. 回 Claude Code 對話輸入框，送出新的查詢位置：

```text
/deliverables "C:\mods-lesson\delivery-practice-blank"
```

4. 核對面板頂端已換成 `delivery-practice-blank`。預期封面仍顯示「路徑存在，內容待審閱」。
5. 再打開副本的空白封面需求：它沒有主標、副標或版面資訊，所以不能交給設計師。

如果你已開啟面板後才清空檔案，做完仍按一次「重新檢查」。存在與空白不矛盾，因為本模組不讀內容。連同名項目是不是一般檔案，也不在這版的內容驗收範圍。

## 8. 錯名練習：看得到檔案，約定路徑仍缺少

1. 從已補完整的 `delivery-practice` 再複製一份，命名為 `delivery-practice-wrong-name`。
2. 在新副本裡把 `cover-brief.md` 重新命名成 `cover_brief.md`。只把中間的連字號 `-` 改成底線 `_`，保留內容。
3. 在 Claude Code 對話框重新指定這份副本：

```text
/deliverables "C:\mods-lesson\delivery-practice-wrong-name"
```

4. 核對頂端路徑後，預期 `cover-brief.md` 顯示缺少。它要求連字號名字，資料夾內卻是底線名字。
5. 回檔案總管，把副本內的 `cover_brief.md` 改回 `cover-brief.md`。
6. 回同一個面板按「重新檢查」，核對新時間，以及封面指定路徑恢復存在。

每換一份副本，就重新指定其完整路徑。否則你在副本改名，面板仍查原目錄，結果自然對不上。

## 9. 結果不對時，照這個順序排查

| 現象 | 先核對什麼 | 採取的動作 |
| --- | --- | --- |
| 找不到模組目錄 | PowerShell 是否位於 `C:\mods-lesson`；四個程式檔是否齊全 | 回正確目錄，重新解壓縮完整範例後再驗證 |
| 找不到 `/deliverables` | 是否進入帶 `--plugin-dir` 啟動的 Claude 對話；是否輸入錯視窗 | 回到那次 Claude 互動對話，不在 PowerShell 輸入斜線指令 |
| 一直顯示缺少 | 面板完整路徑、連字號／底線、副檔名、是否按過刷新 | 修正實際檔案位置或名稱，再重新檢查 |
| 已改檔案，時間沒更新 | 是否仍是上次查詢結果 | 按「重新檢查」，看新的時間與結果 |
| 「無法檢查」 | 顯示的原因、資料夾存取權限、適用版本 | 先查清楚原因，不把它當成缺件補檔 |
| 找到大小寫不同的檔名 | 是否用了 `Cover-Brief.md` 等不同大小寫 | 改成約定的精確名字；本例遇到大小寫差異會顯示無法檢查 |
| 沒有取得檢查時間 | 面板對時間的提示 | 不宣稱是即時狀態，保留結果並處理環境問題 |

若你的版本仍無法工作，保留版本號、完整錯誤文字和使用的相對步驟即可。分享問題時不要附私人文章或帳號資訊。不要把無效清單或讀取錯誤改成空清單，來製造缺件結果。

## 10. 收起面板，以及停止下次載入

兩個動作不同：

- **只收起面板：** 試「關閉面板」按鈕或 Esc。模組仍在這次對話中；再次送出 `/deliverables "C:\mods-lesson\delivery-practice"` 可以要求重開並檢查指定目錄。
- **停止這次單次載入：** 結束這個 Claude Code 對話。這次若使用獨立終端機分頁，可以關閉該專用分頁，再開一個新的 PowerShell 分頁。不要關閉存著其他工作的分頁。

在新 PowerShell 分頁中，正常啟動，不附上載入參數：

```powershell
Set-Location -LiteralPath 'C:\mods-lesson'
claude
```

這個新對話不再透過本教材的 `--plugin-dir` 方式載入模組；確認交稿檢查不再出現，也不要再沿用前一次對話記住的路徑。本教材沒有指示永久安裝；若你另外設定過其他載入方式，需按自己的設定處理。

關閉、重啟與停止載入是依程式及官方單次載入語意提供的操作步驟，仍待補齊本例的原生驗收紀錄。如果實際行為不同，保留情況，不把「收起面板」寫成已卸載。

**練習檔案留著就好。** 停止載入不需要刪程式、刪文章或清空硬碟。

## 完成後，自己回答這三題

1. 初次缺的是哪一份？補件後為什麼還要按重新檢查？
2. 三項全部存在，為什麼空白封面和待確認的報名方式仍不能交？
3. 檔案名稱是 `cover_brief.md`，為什麼清單要求的 `cover-brief.md` 仍然缺少？

答案：封面需求；按鈕才重新查詢當下的清單；存在只證明有約定名稱，不代表內容完整；底線與連字號是不同的檔名。能指出資料夾、實際檔案和內容中的依據，才算把流程重做了一次。
