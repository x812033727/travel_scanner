# 可複製提示與影片後段練習

配合《Claude Code Mods：交稿檢查面板》。主案例的 Windows 操作流程見 [跟做教材](README.md)。以下提示與材料逐字取自隨片影片稿，不是已執行的對話紀錄。

教材已附的是 **delivery-check 交稿檢查模組**。課程三檔是檔案練習與延伸需求設計，**沒有附第二個課程版 Mod，也沒有宣稱課程版已原生測通**。貼提示前，把所有 `<...>` 換成自己的實際完整路徑，不要保留尖括號。

## 1. 完整模組生成需求

先跟做主案例時，直接使用已附的完整模組即可。下面保留影片的完整生成需求，供你理解或修改需求；新生成的程式不會自動等同已測過的範例。請模型生成程式可能使用模型額度。

```text
請幫我設計並建立一個 Claude Code Mod，名稱為 delivery-check。
我不會寫程式，目的是交稿前找缺件，不是判斷文章品質。
練習資料夾的完整路徑：<貼上自己的 delivery-practice 完整路徑>
程式放在 mods-lesson 下的 delivery-check，與練習材料分開。
先產生程式、使用說明與能力清單，先不要載入或安裝。
依適用版本的官方文件和型別確認可行性；不支援就明說，不用假資料補上。

1. 提供 /deliverables 指令，開啟交稿檢查面板。
2. 第一次以 /deliverables "資料夾完整路徑" 指定目錄，正確處理空格。
   在畫面顯示實際使用的絕對路徑，只在本次對話記住它。
   重載或結束對話會清除，要重新指定；未指定就詢問，不猜其他目錄。
   如果參數方式不受支援，先說明，不自行換成默認資料夾。
3. 先確認指定目錄可檢查，再核對 article.md、sources.md、cover-brief.md。
   只核對這三個約定名稱；不遞迴、不讀內容、不修改或補建檔案。
4. 開啟或按重新檢查時才查詢，顯示本次時間，不把舊結果當最新。
5. 存在就寫「路徑存在，內容待審閱」；不存在寫「缺少」。
   權限或環境出錯，寫「無法檢查」，並顯示可理解的原因。
6. 不顯示完成百分比、不估剩餘時間，三項存在也不寫可以交稿。
7. 檢查功能不呼叫模型、不連網、不啟動其他程式。
   如果認為需要，先說明原因，不自行加入。

驗證方式：
- 只有前兩份時，第三項缺少。
- 補上第三份並手動刷新後，三項存在，內容仍待審閱。
- 第三份是空白檔時，仍不能說內容合格。
- 換錯目錄、改錯檔名，以及不能存取時，能區分原因。

請附開啟、關閉與停止載入說明，不把沒執行的測試寫成已通過。
```

## 2. 補件提示

主案例是複製提供的封面材料；若另選模型補寫，可以使用影片這段提示。完成後仍要核對真正的檔案與路徑。

```text
在這個練習資料夾新增 cover-brief.md：<完整路徑>
主標「社區讀書會」，副標「帶一本書，分享一個觀點」。
白色背景、深藍標題，預留書本插圖位置。
只寫文字需求，不生成圖片，不加已確認的報名資訊。
article.md 和 sources.md 保持原樣。
完成後回報新增檔案的實際路徑。
```

## 3. 一次性查件

只檢查一次時，可使用這段提示。結果需要來自實際存取；不能只因回覆肯定，就視為已檢查。

```text
練習資料夾：<貼上完整路徑>
只檢查 article.md、sources.md、cover-brief.md
這三個精確路徑是否存在。
逐項列出存在、缺少或無法檢查。
不要讀內容、不要建立或修改，也不要評分完成度。
```

## 4. 內容審閱

路徑存在與內容合格是兩種問題。下面會要求閱讀內容、附問題原文，先不改檔案。

```text
請閱讀這個練習資料夾的三份文件，先不要修改：
<貼上完整路徑>
逐份列出內容、缺少資訊、需要人工確認的地方。
每個問題附檔名與對應原文。
不要把存在當成合格，不自行補造報名方式。
```

## 5. 日期修改與驗收

使用主案例的 `article.md`。這是影片的日期練習提示，沒有聲稱 Claude 已執行過這次修改：

```text
練習資料夾：<貼上完整路徑>
只把 article.md 的活動日期
由「10 月 24 日」改成「10 月 31 日」。
其他內容保持不變。
改完列出前後文字，並指出檔名。
```

合格結果：真正的 `article.md` 日期由 **10 月 24 日** 改為 **10 月 31 日**；地點保持「里民活動中心」，活動內容與待確認的報名方式保持原文。打開實際檔案核對，不只看「已完成」回覆或編輯紀錄。

如果連地點也被改了，影片提供的修正提示是：

```text
我只要求改日期。
請將活動地點還原為「里民活動中心」。
保留已改成「10 月 31 日」的日期。
其他內容不變，完成後列出實際內容。
```

## 6. 課程交付：先建立缺答案的起點

在 `C:\mods-lesson` 下另建 `lesson-practice`。若你的主教材放在其他地方，所有路徑也一起換成那個實際位置。

本教材的 [lesson-fixtures](lesson-fixtures) 有三份完整材料。**先只複製 [outline.md](lesson-fixtures/outline.md) 和 [exercise.md](lesson-fixtures/exercise.md) 到 lesson-practice；不要先複製 answer.md。** 保留 lesson-fixtures 原樣作為範本。

```text
C:\mods-lesson\
  lesson-fixtures\
    outline.md
    exercise.md
    answer.md               ← 保留在範本，起初不複製
  lesson-practice\
    outline.md
    exercise.md
                            ← 先不建立 answer.md
```

### 課程大綱 outline.md

```text
# 讀書會海報小練習
目標：分清標題、時間、地點三種資訊。
步驟：讀公告、找三項資訊、檢查缺了什麼。
```

### 練習題 exercise.md

```text
# 練習題
公告：社區讀書會，10 月 24 日，在里民活動中心。
請寫出活動標題、時間和地點。
```

這是新的練習題，日期是 **10 月 24 日**，不要沿用上一個日期修改例的 10 月 31 日。

## 7. 課程材料的三輪檢查

1. **缺答案：** `lesson-practice` 只有大綱與題目。用檔案總管確認 `answer.md` 不在這份工作副本。
2. **空白答案：** 在這份工作副本建立空白的 `answer.md`，顯示完整副檔名，避免存成 `answer.md.txt`。檔名存在，但沒有作答內容，不能說課程交付完成。
3. **真正答案：** 閱讀題目，在 `answer.md` 填入下面的參考答案，或將範本中的 [answer.md](lesson-fixtures/answer.md) 複製到工作副本。若系統詢問覆蓋，先確認是剛建立的空白答案，再替換；不要改到其他工作。

### 參考答案 answer.md

```text
# 參考答案
活動標題：社區讀書會
時間：10 月 24 日
地點：里民活動中心
```

核對方法：把活動標題、時間、地點逐項對回題目。答案應為「社區讀書會、10 月 24 日、里民活動中心」。假如把地點寫成「圖書館」，即使檔名正確，內容仍然錯誤。

**這三輪可以直接用檔案總管和文字編輯器完成。** 現有交稿模組仍固定查 `article.md`、`sources.md`、`cover-brief.md`；把它指向課程資料夾，不會自動改成課程清單。不要把材料練習當作已完成另一個模組的操作測試。

## 8. 課程版 Mod 的延伸需求設計

先列出希望改動的三個目標名稱、中文用途與新路徑，保留狀態和刷新規則。這是影片的需求提示：

```text
把三個目標改為 outline.md、exercise.md、answer.md。
中文用途：課程大綱、練習題、參考答案。
新的練習資料夾：<lesson-practice 完整路徑>
保留指定路徑、手動刷新、實際時間與三種狀態。
存在不等於完成，不顯示完成百分比。
先列出改動與驗證方式，不自行載入。
```

看過方案後，影片的下一步是要求按方案修改程式、列出改動，**先不要載入**；核對後才重新試用，並指定新的練習資料夾。課程版程式和原生驗收並未包含在本教材中，不能只換檔名就當成實作完成。

需要保留的規則是：指定資料夾、手動重新檢查、顯示實際查詢時間；存在只代表路徑存在，無法檢查不算缺少，不顯示工作完成百分比。最後仍需自行閱讀題目與答案，判斷是否能交付。
