查核對象：`video.json`，SHA-256 `b01691ff827cd86d37710066eb521ac8ed6ee58af7b607d07e317ed82e50c90f`。共 87 景、101 句、2,588 個旁白字元；字數與企劃長度都不是實際媒體時長。

## 已核對的主張

- 兩顆公平且互不影響的六面骰，形成 36 個等機率有序結果。旁白 `21c1bc` 已明說互不影響；`8f5f2e` 說明第一顆與第二顆標記的差異。
- 目標總和七、十二、六分別有六、一、五個有利結果。除了檢查原作者的枚舉程式，本代理另將每個合法總和二至十二的結果與閉式計數 `6 - abs(7 - target)` 比較，全部一致。這是模型計算，不是擲骰實驗。
- 本代理在獨立資料夾複製教材核心檔案，實際輸出總和六的 MP4：H.264、1280×720、24 fps、1,296 影格、54 秒，無音軌。這證明教材的可重做核心，不能延伸成任意 AI 的成片保證。
- 核對 `summary-check.log` 與 `summary-render.log`：終端卡命令與短摘要取自實際輸出，沒有把 JSON 中間硬插換行當成原始終端輸出。
- 非法目標十三以錯誤結束；合法變式六對應五格。檢查器不讀取畫面自報的答案；它也不能判斷解釋是否好懂。
- `locale` 只支援 `zh-TW`；旁白 `b13c3e`、教材與主張表均有交代。沒有宣稱只改語言代碼就得到外語動畫。
- 無聲教材的 `.srt`／時間軸是設計時間；`52cf29`、`ba0179` 與教材均要求完成語音後另行量測及對齊。
- 沒有把本次 Codex 協作冒稱 Claude 或 Claude Motion 實測。精確圖解採程式動畫屬本片編輯選擇，未宣稱其他路線必然做不到。

## 查核中發現並已修正

1. 舊稿只說公平，缺少互相獨立的前提，已改為 `21c1bc` 的完整條件。
2. 初版總和六影片仍以一加六及「七或十二」開場，與資料參數不一致。原作者已將開場骰子改成目前目標的實際配對，文字跟隨 `target_sum`；本代理以修正版另跑影格預覽，確認總和六開場顯示一加五及「六或十二」。最後固定總和六的場景是明示練習，不宣稱所有段落都由目標參數控制。
3. 初稿終端卡把長 JSON 在字詞中間人工斷行。現版改用真正執行過的 `--summary` 輸出。
4. 跨平台字型原為固定 Linux 路徑；現教材附字型選擇參數、不同作業系統說明與找不到字型的錯誤訊息。已在目前 Linux 環境重做，尚未在全新 Windows／macOS 實機安裝。

## 教學與畫面檢視

同一骰子專案貫穿需求、資料檔、預覽、輸出和改值練習；完整提示詞、起始資料與指令均在教材內。縮圖與圖解為原創。獨立輸出的六張聯絡表已看過，修正後開場影格也已另開圖確認，未見先前的標籤截斷或軸標重疊。主影片的完整字卡、配音時窗與手機可讀性仍須在實際 `render`／`qa` 檢查。

正文的聲畫同步段落是製作方法與交付說明；不得把它說成這份無聲教材已完成配音對齊。八種外語為 `en`、`ja`、`ko`、`es`、`pt`、`id`、`vi`、`th`，繁中主版另計，沒有德文或法文。
