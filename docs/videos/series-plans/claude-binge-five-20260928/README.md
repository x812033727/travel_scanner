## 五部共同的緊湊規格

這批把「鋪陳好、看起來緊湊」寫成可以檢查的規則，`validate.mjs` 每一條都擋：

- **第一句就是鉤子**：每集 `hook` 是能直接說出口的一句話，≤ 28 字（產線量到 8 秒就退件，28 字約 6 秒，留餘裕），40 句不重複；沒有片頭卡、沒有前情。
- **10 秒衝突、30 秒第一個爽點、每集至少兩個爽點**，第一個在前半；爽點寫成觀眾看得到的畫面或聽得到的那句話，不寫「她很厲害」。
- **爽完就來更大的麻煩**：主角不能連兩集只挨打；三集連贏會被警告。
- **最後一句就是懸念**：懸念分五型，相鄰兩集不同型（跨篇也算）；第 10／20／30／40 集必須是揭露或反轉，改變觀眾對本篇某件事的理解。
- **第 18–22 集之間正好一次翻轉世界觀**（五部都放在第 20 集，約 60 分鐘處），讓前一小時的畫面換一種意思。
- **每條謎團都有帳**：8–12 條長線謎團，埋下、推進、揭曉的集數寫在設定集，細綱的 `setups`／`payoffs` 必須對上；任何連續四集至少收一條。全部在第 40 集前收完（`open_ended: false`，不留續作懸案）。
- **第 1 集的動作在第 40 集倒過來演一次**（倒茶揭假→倒茶喝真；只准報毒名→自己吃第一口並廢除嘗使；掌心寫「走」→寫「留」；忘掉的生日→記回來；血寫的符→燒掉的符）。
- **每部一個會自己製造爽點的機制**（讀檔、釐光、三針、舌頭、借命符），規則在第一篇立好，結局用它翻盤，不靠新設定救場。
- **人物與場景逐字沿用**：角色外觀是 ≤ 800 字元的英文提示詞、每集逐字複製；聲音是 Gemini 內建聲音的擬定 casting（旁白 Sulafat），開拍前先試聽；場景有固定辨識物，讓關鍵影格跨集一致。

## 獨立審稿

每部寫完後，由另一個沒寫過它的代理完整讀四十集，只找程式抓不到、觀眾會抓到的問題，列出必修與可改；必修的全部改掉，再重建、重驗。修掉的問題分六類：

- **撞到真實世界**：藥號「濟安堂」是台中的真實藥局而劇情指控它賣假藥、「回春散」是註冊成藥、第三部男主原名和熱門遊戲角色同名、「一眼千年」是真實節目主題曲的名字、「蕭太后」是遼代真實人物的通稱，全部改名。
- **和知名作品太近**：試毒少女加鉛毒加隱藏身世接近《藥師少女的獨語》，毒改成虛構礦物，外戚與公主改名。
- **規則自相矛盾**：第九層的唯一命、錯序的藥先好三天、誰看得見鬼、魂怎麼回到身體、讀檔的代價記在誰身上，都改成在前半就立好、後面照用，結局不靠新設定。
- **翻轉被提前說破**：第 20 集的揭露在前面先講白的，改成只留線索。
- **年份、物件、場景接不上**：誰手上有什麼、第幾天、在哪一樓，逐一對齊。
- **醫療與自傷的誤導畫面**：急救不等針灸、急診不寫成輸給三針、不寫沒有外敵的墜樓、不拍傷口。

另外有六個角色改名，避免和 Codex 版的角色同名或同音；兩批會在同一個頻道播。

## 怎麼餵進產線

1. **以已審企劃匯入流程預載文件**：`<slug>/series-request.json` 是 `SeriesIn`，但直接 `POST /api/v1/admin/video-automation/series` 建立空作品，仍可能讓工人啟動付費設定集企劃。`hands_off: false` 只關閉自動核准，不是停止生成或花費的開關。這批應沿用 [PR #929 的 reviewed-plan importer 與匯入紀錄](https://github.com/x812033727/travel_scanner/pull/929)：`ops/video/import_drama_plans.py` 的離線準備、dry-run、審核 bundle 雜湊後才套用的流程，原子建立作品與六份待審文件；它不核准審稿、不產生媒體。正式套用需另經站主授權；本次本機修正沒有執行它。完整作業說明在該 PR 的 `docs/videos/series-plans/binge-five-20260928/IMPORT.md`，應使用經審核的工具版本，勿把本段當成可直接執行的正式站指令。
2. **逐份更新與審核**：`<slug>/documents.json` 的六份（設定集、總綱、四篇細綱）各是 `{kind, chapter_number, body_md, body_json}`。作品頁「自己改」的 `PUT …/series/<slug>/docs/<kind>[/<n>]` 只修改已存在的文件，不能用來建立空作品缺少的文件；修改與核准是不同步驟，不能把匯入一律設為 `approve: true`。目前十部已存在，更新時先比對既有狀態與版本，再依設定集→總綱→篇章的相依順序審核。`body_json` 含 `answer`、`carry`、`world_flip` 等撰稿與查核資料；來源的 `continuity_notes` 也會進入設定集 Markdown、JSON 與 `documents.json`，不能只帶走獨立的 `continuity.md`。
3. **先做前三集校準**：任何一部都先做第 1–3 集（約九分鐘），用 `retentionNumbers` 量鉤子與第一個爽點的實際秒數、看重做率與花費，再決定五部的順序；不要五部同時送進付費生成。
4. **合集**：40 集完成後由產線接成 `<slug>-full`；合集 `video.json` 的 `compilation` 把 `chapter_cards` 與 `outro` 關掉，一口氣看到底，YouTube 章節照實際時間軸；`packaging.md` 的三組標題與三組縮圖給 YouTube 的標題／縮圖測試用。
