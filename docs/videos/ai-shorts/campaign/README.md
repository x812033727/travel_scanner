# AI 真的可以？90 天 Shorts 執行手冊

本企劃在既有 Mokaair 頻道，製作繁中、不出鏡、台灣口音旁白的 25–55 秒真實 AI 小測試。挑戰目標是第一支公開起 90 天、120 支、累積 1,000 萬公開觀看，平均約每支 83,333 次。這是實驗目標，不是流量承諾，也不代表已具備營利資格。先用觀眾能參與的題目吸引注意，再讓可查證的結果建立信任。

本目錄已備妥 15 支可執行 brief、共同實驗規範、90 天排程與來源登記。brief 的 `planned` 是企劃版本狀態；各次實驗證據與實際試片狀態另看 `../experiments`、`../pilots` 及本機產物紀錄。未拍完的題目不寫成已驗證成果。

## 90 天節奏與選題

90 天從首支公開日開始，企劃日期不是開始日。前 30 天每天一支，共 30 支；第 31–60 天與第 61–90 天各 45 支。後兩階段各以階段內奇數日雙片、偶數日單片安排，恰好各 15 個雙片日和 15 個單片日。單片 19:30，雙片另加 12:30，均為台灣時間。前 15 支三系列各五支，後 15 支根據已滿七天的樣本逐步調整。

每週一完成一次盤點，確定下一週題目、素材、成本預估及負責人。後續採 60% 已驗證題型、30% 新角度、10% 當週話題；用每十支 6/3/1 的滾動配額避免每週四捨五入失真。沒有可核實且適合觀眾的當週話題時，該格改做有明確答案的觀眾挑戰。留言僅取題目，不展示帳號或私人資料。

每週研究十支英文原片，以近 30 天作品為主，記錄原片 URL、發布日、查閱日、搜尋快照或實看區別、當時觀看數、影片長度、開場方式、揭曉方式及台灣可重做的角度。至少看過開場、測試與結論才可記剪輯手法；只讀搜尋摘要不能填成已觀看。片量不足時如實記不足，不把較舊片補成當週熱點。

已查到的英文題型先例有 [Sambucha 的 AI life hacks](https://www.youtube.com/watch?v=01HhLdDmz7g)、[其續集](https://www.youtube.com/watch?v=BKTj5pCdbqM)、[zi8gzag 的 AI 猜地點對照](https://www.youtube.com/watch?v=EhHBnBPLVlg)及[另一支同類題目](https://www.youtube.com/watch?v=uWOUh4u1T-I)。它們都超過 30 天，這輪只取得 YouTube 搜尋快照，未看片；不能拿來宣稱現在正在爆紅。完整來源、快照數字與原提案未重新驗證的三個連結見 [sources.json](sources.json)，數字不要移植成影片內的當前觀看數。

YouTube 官方列出的訊號包含是否選擇觀看、平均觀看時間與平均觀看百分比，也明說沒有最低發片頻率要求。因此本排程是製作管理決定，四週後依頻道受眾數據調整，不能把時段或頻率宣稱為流量公式。[官方 Shorts 推薦說明](https://support.google.com/youtube/answer/11914225?co=YOUTUBE._YTVideoType%3Dshorts&hl=en)（查閱：2026-09-28）

## 製作、證據與成本

每支在 repo 外建立以 slug 命名的工作目錄，保存素材與影音；公開 repo 只放不含個資的企劃、規格及可公開實驗文字。開始前先凍結輸入、答案、評分、兩組限制與重試額度；完成後把實際模型標籤、時間、原始輸出、核對、授權、費用及獨立審稿連在一起。測試照片未備妥、工具不可用或權利不明時，該題保持待製作，用已備料題目遞補，不能演出假的模型操作。

每支先給 0–2 秒題目或實際結果鉤子，2–7 秒規則，中段是原始輸出、操作與局部放大，最後 5–10 秒揭曉並說一個與這次實驗有關的限制。A/B 海報與網頁輪流全幅展示，避免手機上只剩小到看不清的分屏；字幕和重要數字要避開 Shorts 右側按鈕及底部介面。固定 1080×1920、30 fps；畫面上的生成等待若加速，標明實際等待時間。

首三支新增費用合計最多 NT$300；每個 30 天區間最多 NT$3,000，90 天最多 NT$9,000。月內新增付費實驗到 NT$2,400 停止，保留 NT$600 完成已開始作品。成本包含測試、生成、旁白與失敗重做；既有訂閱固定費不算新增費用，仍記使用的額度。工具未回報費用時填「未知」，不能填零。任何新訂閱或超出上限的用量，先改用已付費或免費可用資源；不為維持片量默默超支。

每支交付 `final.mp4`、繁中 SRT、實際封面影格、兩個標題備案、說明文字、原始實驗紀錄及查核報告。前三支先通過真值核對、手機尺寸視覺檢查、旁白試聽及獨立審稿，再擴大批量。實際發布一律由站主透過 YouTube Studio 審片及設定；本站 YouTube API 額度用盡不阻擋本機上傳包製作，也不自動改頻道配額。

## 匯入基準與每支成效

上線前由站主在 YouTube Studio → Analytics → Advanced mode／See more，選近 90 天、Shorts 類型並按影片拆分，匯出目前檢視。記錄匯出時間、日期範圍、時區和篩選條件；原始 CSV／ZIP 放 repo 外的 `analytics/baseline/`，不改寫原檔。若沒有 Shorts，基準記「無歷史 Shorts」，不要拿長片與 Shorts 的觀看百分比混算。[官方匯出步驟](https://support.google.com/youtube/answer/9717005?hl=en)（查閱：2026-09-28）

映射欄位時以影片 ID 為鍵，再連到 campaign slug；缺 ID 或同 ID 多個狀態先查清，不能靠可能重複的標題合併。保留匯出原始欄位名與單位：影片長度秒、公開日、公開觀看、engaged views、選擇觀看百分比、平均觀看時間秒、平均觀看百分比、分享、訂閱增加。成本來自製作帳，不能從 Studio 推估。百分比統一使用 0–100 的數值；沒有資料留空，零只表示已觀察為零。

每支公開後約 24 小時、72 小時、7 天各存一份快照；以實際觀察時間記錄，不用後來的累積觀看回填成早期數字。每份快照都記公開時間、觀察時間、影片年齡與口徑。觀看可因重播增加，公開觀看與 engaged views 要分開；營利與資格依 YouTube 自身規則，不拿本計畫的千萬公開觀看目標等同門檻。[官方指標說明](https://blog.youtube/inside-youtube/engaged-views-youtube-explained/)（查閱：2026-09-28）

本機追蹤工具從 repo 根目錄執行。`--start` 必須換成站主實際決定的首支公開日，下例日期只示範參數；初始化目錄必須在 repo 外且為空（`<VIDEO_WORKDIR>` 是你自己選的 repo 外持久工作區）：

```powershell
node tools/video/shorts/cli.mjs track-init --dir <VIDEO_WORKDIR>/ai-shorts-tracking --start 2026-10-01
node tools/video/shorts/cli.mjs report --dir <VIDEO_WORKDIR>/ai-shorts-tracking
```

`track-init` 產生 120 格 `calendar.csv`、空白 `metrics.csv` 與 `costs.csv`；只有首 15 格已有題目，後 105 格留給每週依數據選題，空格不算製作完成。`report` 讀取 CSV，產生 `report.json`／`report.md`，不登入頻道、不發布影片。需要重現過去報告時，附 `--now 2026-10-08T19:30:00+08:00`，時間不可拿來回填不存在的觀察。

| CSV | 欄位與填寫方式 |
| --- | --- |
| `metrics.csv` | `slug,video_id,published_at,captured_at,views,engaged_views,stayed_pct,avg_pct,shares,subscribers,series`；`series` 用 `daily`／`blind`／`prompts`。時間包含時區；觀看、互動與新增訂閱為累計數，`stayed_pct` 是選擇觀看比例，`avg_pct` 是平均觀看百分比，可因重播大於100。 |
| `costs.csv` | `occurred_at,slug,category,amount_ntd,status`；`status` 用 `confirmed`（已確認）、`reserved`（預留）或 `unknown`（費用未知，可空金額）。預留款與已確認款會一併占用預算；結算時更新同一筆狀態，避免重複計入。 |

工具的每筆成效紀錄要求全部指標完整；有缺值的原始資料保留在 repo 外 `analytics/pending/`，先不加入 `metrics.csv`，待資料齊全才匯入。這是完整快照的驗證條件，不能靠補零通過。`subscribers` 使用新增訂閱數，不能用可能為負的淨增減替代。工具尚未存影片長度、素材來源或公開狀態變更，這些資料仍須在原始匯出及交接表保留；轉私密或刪除後要調整可計入的影片集合再產報告，不把舊快照當現況。

工具取 24–48 小時、72–96 小時、7–9 天區間內最早的實際快照，區間外的資料不補成該節點；24h／72h 上界不含端點，7d含第9天端點。手動決策時也檢查影片年齡與片長，避免 7 天和 9 天累積的差異被誤解為題材優勢。

每週用已成熟的七日樣本判斷。比較集合限定本系列企劃、相近片長、同樣七日口徑；只有累積28天數字的舊片不能拿來壓過新片。每個系列至少五支，各滿七天，才判斷題型去留；不足 1,000 engaged views 的單支只作初步觀察，資料不足時保留現行題型，不把缺值當失敗。

| 動作 | 條件與下週工作 |
| --- | --- |
| 擴大 | 同系列至少兩支七日觀看超過同期合格影片中位數兩倍，且平均觀看百分比不低於同期中位數；下週做三支不同內容的延伸 |
| 修改開場 | 中段留存相對好、選擇觀看比例相對低；下一支換開場或首個畫面，保持核心題材 |
| 縮短鋪陳 | 選擇觀看比例相對好、中段留存相對低；下一支把測試結果提前，刪不必要背景 |
| 暫停 | 同系列連續五支合格七日樣本在觀看和平均觀看百分比都低於同期中位數；暫停兩週換角度 |
| 資料不足 | 不滿五支、未滿七天或 engaged views 太少；記下觀察但不宣判題材有效／無效 |

這些是本企劃的實驗規則，不是 YouTube 推薦門檻。每週另算 `max(0, 10,000,000 − 已觀察系列公開觀看) ÷ 剩餘天數`，說明達標仍需要的日均觀看；第 90 天後不除以零，改報最終累積值。未發布影片不計入已發布數；私密、取消公開或刪除的影片與改版紀錄要保留狀態，避免將它們當作仍在公開累積。

## 交接與完成標準

本輪可驗收的交付是直式製作能力、三支有真實測試依據的試片，以及 15 題首批企劃與後續實驗流程。90 天成效只能在實際發布及觀察後驗證；現階段沒有頻道私有分析資料，不會填造觀眾數或留存。

每週交接包含：已產出／已審核／站主已發布的三種數量、實際費用與未知費用、影片 ID 對照、下一批備料狀態、24h／72h／7d缺件與下一步。若已知問題未能修正，放回任務看板，不只留在聊天。站主決定的發布欄位包含公開時間、兒童設定、付費宣傳與適用的合成內容揭露；這些選擇不能從虛構範例推定。
