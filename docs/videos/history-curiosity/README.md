## 兩個參考頻道，各學什麼

### 馬臉姐（內容）

2026-10-10 看頻道「影片」分頁的最新 30 支：

- **題材**：預言與末日（2027、2030、500 年輪迴、江教授）、外星與 UFO（1956 年的訪客、月球被佔領、UFO 檔案、金星女人）、靈異與因果（借命、招鬼）、歷史與政治的「真相」（美國 53 年不敢改的數字、頂新案的證據）、科學奇觀（黃金來自宇宙、世界不是真實的）、宗教（佛陀成佛前一晚）。約三分之一是台灣時事的「陰謀」角度。
- **長度** 15–37 分鐘；標題一律「反常識的斷言＋問號」加「| 馬臉姐」，常帶年份與數字（「1991 年她自稱來自金星，說出 6 個禁忌預言！35 年後…其中 4 個正在成真」）。
- **畫面**：她本人出鏡，旁邊「貼」進去的東西一直換：手機截圖、新聞截圖、去背的物件（戒指、隕石）、歷史照片。觀眾盯著的是她的表情和貼圖。
- **我們學的**：選題的「檔案感」（一個年份、一份文件、一個名字）、鉤子寫法（先丟斷言再問為什麼）、貼圖式的照片呈現。
- **我們不學的**：把預言與陰謀論講成事實、推薦理財商品、靈異儀式的教學。我們沒有出鏡的主持人，貼圖要貼在插畫與卡片上（§照片）。

### cheap（畫面）

- **畫面**：全彩可愛卡通——大頭、大眼、誇張表情、粗而乾淨的描邊、飽和的平塗加柔和陰影、背景簡單；歷史人物畫成漫畫化的角色（史達林、山姆大叔），縮圖常用動物角色代人（熊、浣熊、牛）。字幕燒在畫面下方。
- **長度** 12–23 分鐘；標題「斷言【問題】補充」三段式，用【】框住問題。
- **我們學的**：畫風（§畫面）、一個畫面一個笑點或一個情緒、縮圖的大字加角色。
- **我們不學的**：在世人物的漫畫像、燒錄字幕（頻道規格是可開關的 CC）。

## 一集長什麼樣（10 分鐘）

| 段落 | 長度 | 做什麼 | 場景 |
| --- | --- | --- | --- |
| 鉤子 | 0:00–0:20 | 檔案裡最反常識的一句（年份、數字、名字），承諾「這集打開這份檔案」 | `shot` → `big` |
| 開檔 | 3 秒 | 系列片頭：檔案櫃拉開、一份牛皮紙檔案夾被抽出來蓋上「開檔」章（每集相同，做一次重用；[`look.md`](look.md)） | 片頭 |
| 流傳的版本 | 1–1.5 分鐘 | 大家聽過的說法，講得像故事；這一段最多照片 | `shot`、照片卡 |
| 檔案裡有什麼 | 5–6 分鐘 | 3–4 章，每章一份證據（當年的報告、後來的研究、關鍵人物說了什麼）；時間軸、地圖、數字用卡片 | `shot`、`stats`、`compare`、`steps` |
| 目前最站得住的解釋 | 1–1.5 分鐘 | 把證據收攏成一句話；沒有定論就說「目前主流解釋是…，還沒解釋的是…」 | `shot` → `big` |
| 結檔 | 20 秒 | 檔案夾蓋上「存檔」或「未結」章（有定論／沒定論兩種）、下一份檔案預告、訂閱 | `outro` |

- 每 4–6 秒換一張圖，約 100–150 張插圖加 5–10 張照片；每張插圖一個主體一個動作（MiniMax 聽不懂多人互動，[`look.md`](look.md)）。
- 單一旁白：頻道聲音 Gemini `Sulafat`、說書口吻（`style` 寫法照 `docs/videos/ai-term-token/video.json`，「標準國語、咬字清楚」）；每句壓在 24 個單位以內（實測每秒約 3.4 個單位）。
- 章節名寫觀眾會搜尋的說法（「1994 年空軍怎麼解釋」「DNA 比對的結果」），不寫「背景」「結論」。
- 歷史與奇異的檔案很少過期，但「最新研究」會：每集的 `## 來源` 寫確認日期，說明欄寫「資料截至」。

## 內容守則（跟馬臉姐不一樣的地方）

1. **講的是檔案，不是結論**：預言、陰謀論、靈異事件一律用「當年流傳的說法 → 留下的證據 → 目前的解釋」三段講，不把預言講成「正在成真」，不把陰謀論講成事實。沒有定論就說沒有定論，不講「據說」「有人說」當證據。
2. **每個數字、年份、名字、引言有來源**（頻道規矩 2）：一手文件（解密檔案、調查報告、期刊論文、官方新聞稿）優先；維基百科只當索引，順著它找原始來源。`topics.json` 的 `facts_to_verify` 是最容易錯的點。
3. **YouTube 政策**：不講醫療與選舉相關的陰謀論；不教靈異儀式（招鬼、借命）；不把宗教信仰當事實或當笑話；在世人物不做漫畫像、不評論私德；血腥與遺體不畫、不貼照片。這些題目在題庫裡直接不收。
4. **真實人物**：過世超過 70 年的歷史人物可以畫成可愛卡通（提案，等站主決定）；在世或近代人物用有授權的照片或剪影。公司 logo、產品外觀照舊不畫（截圖走 `screenshot`）。
5. **意見標成意見**：「我們覺得最可能的是…」可以講；排名、機率要有出處。
6. **說明欄**：資料截至日、來源清單、「📷 圖片來源」區塊（照片逐張標示）、合成內容揭露照頻道規格。

## 畫面

畫風規格、四種候選的樣張與 MiniMax 的限制在 [`look.md`](look.md)。摘要：

- **可愛卡通**：大頭、大眼、誇張表情、粗而乾淨的描邊、亮色平塗加柔和陰影、背景簡單、一個主體在畫面中間三分之一。
- **MiniMax `image-01` 的事實**（2026-10-04 實測，[`../ai-terms/README.md`](../ai-terms/README.md) 那條線先踩過）：不吃參考圖與畫風樣張、`negative` 會被接成正向文字（系列的 `look.negative` 留空）、提示詞含畫風上限 1,500 字、只出 1K（1280×720），每張 US$0.0035、審圖 US$0.01。一致性全靠 `look.style` 的文字，所以畫風文字要寫得具體、每張 prompt 不重寫風格。
- **跟原來如此事務所的關係**：同一個「可愛插畫」家族、不同色盤。原來如此保留奶油紙底、墨藍、印章紅、芥末黃；這個系列用夜空藍、牛皮紙黃、褪色青與一個警示紅（樣張 C）。兩個系列從 2026-10-10 起都用 MiniMax 畫（原來如此的 T26、T27 是 Claude／Codex 手繪 SVG，之後不再這樣做）。
- **數字、年份、地圖、時間軸**：卡片場景（`big`、`stats`、`compare`、`steps`、`table`），插圖裡不畫字。
- **縮圖**：`thumb` 版型，左 40% 大字（≤6 字）＋標籤（主軸名），右 60% 一張最有衝擊的插圖；cheap 式的角色臉部特寫優先。

## 照片（貼圖方式）

馬臉姐的貼圖是「主持人旁邊彈出一張去背的照片或截圖」。我們沒有主持人，對應的做法：

| 照片來源 | 授權 | 用在 |
| --- | --- | --- |
| 維基共享資源的公有領域檔案照（1929 年前的作品、美國聯邦政府作品）、NASA、美國國家檔案館、FBI Vault、各國國家圖書館 | 公有領域；CC BY／BY-SA 的要標作者與授權 | 事件現場、當年的報紙版面、文件原件、歷史人物 |
| Pexels、Pixabay（[`../ILLUSTRATED.md`](../ILLUSTRATED.md) §圖庫照片，`stock search`／`stock fetch`） | 可商用、免標示但我們照標 | 今天的地點、泛用的物件（雷達、望遠鏡、麥田） |
| 自己截的官方頁（解密文件 PDF、研究論文的圖） | 合理引用、標出處 | `screenshot` 版型，框出關鍵段落 |

- **貼圖式照片卡**（要補的版型，票 `2026-10-10-photo-paste-card`）：照片像印出來的相片貼在系列色的底上——白邊、微傾、投影、右下角出處膠囊；一張卡一張照片，可以疊在同章的插圖上方三分之二。現有的 `screenshot` 版型是滿版截圖加框線，先用它頂著，版型做好再換。
- 每張照片寫進 `assets[]`（`path`、`source`、`license`、`author`、`url`），說明欄自動長出「📷 圖片來源」；`render` 會擋沒登記的照片。
- 不用：來源不明的網路圖、新聞媒體的照片（除非該媒體明確授權）、在世人物的肖像照用在負面情境、遺體與血腥照片。

## 怎麼做（產線）

先本機、再主機，跟 AI 名詞那條線一樣（[`../ai-terms/README.md`](../ai-terms/README.md)）。

### 第 1 期：本機試片 2 集（插圖投影片路線）

1. `docs/videos/curio-<id>/`：`brief.md`（企劃代理，`prompts/planner.md` 的 8 節；「站主觀點」依後台立場）、`video.json`（`format: "slides"`、`category: "explainer"`、`look` 照 [`look.md`](look.md) 選定的那一種、`shot` 與卡片交錯、照片卡）、`claims.md`、`verify-1.md`。
2. 查核：換人查一輪，改超過 3 個事實再換人查第二輪；每個待查核事實寫來源與確認日期。
3. `tts` → `check-audio`（帶 Whisper 第二轉寫）→ `pace.mjs` 量實際節奏 → `keyframes`（`--dry-run` 必須印出 `minimax image-01`）→ `render` → `assemble` → `captions` → `qa` → `package` → `review-push`。
4. 每集記：插圖張數與重做次數、照片張數、媒體花費、token、審圖分數分布、站主審片分鐘數。
5. 兩集做完後把 §成本 改成實測，站主看成片決定畫風要不要調、長度要不要拉長。

含金量六條（頻道規矩 11）是教學投影片的規則，這個系列跟原來如此一樣是說書，不套；但 lint 的出處用語上限（「文件寫」「官方說」最多幾次）照常。

### 第 2 期：主機自動產線

主機現有的解說路線（`flat-explainer`：站主在 `/admin/videos` 填前提 → 故事聖經 → 劇本 → 查核 → 靜圖 → 合成）寫死了原來如此的四個主軸與畫風，而且畫圖用漫劇設定的 Gemini Pro。要補的事在 §票：新畫風預設、解說路線吃系列自己的主軸與畫風、單集請求可以指定 MiniMax、照片卡。補好之後站主在後台一次填一份檔案，工人做到上架確認。

每集的媒體花費約 **US$1.4–2.1**，比起草時估的 US$5 低（審圖費比預期少）。一集從研究到上架確認，機器時間約 5–6 小時：研究約 15–30 分鐘、撰稿約 30 分鐘、查核兩輪約 35–45 分鐘、插圖 55–70 分鐘、合成 15–45 分鐘，其餘是旁白檢查與重跑。模型 token 沒有逐項量。

每月上限是張數：後台 `/admin/videos?tab=drama` 的 `monthly_images_budget` 與 `monthly_judge_calls_budget`（2026-10-10 起草時各用了 6,072／10,000 與 6,930／10,000）。一集約 100–140 次生成與同數量的審圖，每週 2 集一個月約 1,000 次，跟原來如此、AI 名詞一起算仍要看站主的上限。
