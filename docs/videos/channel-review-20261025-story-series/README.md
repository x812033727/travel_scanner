**三句話**：

1. **最大的差距不在鉤子密度，在「說話的對象」與「密度」。** 10-19 以來我們把鉤子壓到每 45 秒一個，但 Seiko 一支 20 分鐘講了 6,224 字、每秒 5 個字、全片沒有一個 1.5 秒以上的空檔，而且 26 次「你」、18 次「我」：它是一個人在跟你講故事。我們 11 分鐘 2,178 字、每秒 3.3 個字、「你」1 次：是一份檔案被唸出來。
2. **開場寫法剛好相反。** Seiko 前 26 秒先講這件事差點改變什麼（對觀眾說），40 秒給數字，66 秒一句「今天我們就來聊聊 Seiko 當年到底有多瘋狂」，一個後面的時刻都不預告。我們照 10-13 定的「一個場景＋三到四個預告句」寫，H01 v2 開場 30 秒連丟劍、酒精、小說、礁石四個線索，觀眾沒有脈絡。
3. **點進來之前就輸了。** 參考頻道的標題是「大家認得的名字＋利害動詞＋問號」，縮圖是亮底、黃字黑邊兩行大字、東西本身或一張有表情的臉；我們是平靜的閱讀題（「燈塔的故事改了哪裡？」）配深青底小字。而且品牌故事一支都還沒公開，奇聞檔案局跟 AI 新聞、教學、漫劇擠在同一個頻道，演算法找不到該推給誰。

## 3. 六個差距（依影響排序）

### 3.1 說話的對象：一個人對你講，還是一份檔案被唸出來

Seiko（a7NlBfRCgqI，zh-TW 上傳字幕）與我們兩支（上傳的 CC）的時間軸：

| | 黑猫 Seiko 20:32 | 我們 H01 v2 11:33 | 我們 S01 赤壁 9:45 |
| --- | ---: | ---: | ---: |
| 字數（正文） | 6,224 | 2,178 | 1,849 |
| 字／秒（全片） | 5.06 | 3.25 | 3.29 |
| 字／秒（講話中） | 5.08 | 3.69 | 3.69 |
| 超過 1.5 秒的空檔 | 0 | 1 | 1 |
| 「你」 | 26 | 1 | 4 |
| 「我」／「我們」 | 18／4 | 2／0 | 10／6 |
| 「大家」 | 5 | 1 | 1 |
| 問號 | 16 | 11 | 16 |
| 驚嘆號 | 11 | 0 | 0 |

他的句子：「甚至連很多**你**今天耳熟能詳的百年名錶，當年都一度陷入生死危機？」「這聽起來像科幻小說，但在現實中真實發生過」
「如果**你**今天出門有戴手錶，不妨留言告訴我，你手上戴的是什麼錶呢？」。我們的：「大副德沃划小艇過去，甲板上、舵邊都沒有人。」
「還記得那段空白的九天嗎？」——句句是事實，但沒有一句是對著觀眾講的，旁白沒有反應、沒有觀點、不開玩笑。
C01 Crocs 全片 2,618 字，「你」「我」各 0 次。

**改了**：`register.mjs` 的 `TOLD_TO_ONE_VIEWER`（每章至少一句「你」、一句旁白自己的反應、意見標成意見、一集一兩次共同經驗的玩笑、
正文 4.5 字／秒）接進品牌故事與奇聞檔案局的撰稿提示；`narrative.mjs` 的 `viewerAddressProblems` 在每千字少於 2 個「你」時警告
（只對這兩個系列）；盲評的 `chapters_link` 系列版接受「轉向觀眾」當銜接。

**沒改、要站主決定**：語速。Gemini 沒有 rate 參數，速度只能寫在 `voice.style`；那段文字在 `speechHash` 裡，改了整支重錄，
而且主機用的是站主貼在後台的那一份。建議照 `voice-audition.md` 先用同一段稿試聽「語速像平常聊天，一秒四到五個字，句與句之間不拖」
這句加不加的差別，站主選了再貼到後台並改 `STORY_VOICE_STYLE`。

### 3.2 開場：利害與承諾句，不是線索清單

Seiko 前 75 秒（字幕時間軸）：

| 秒 | 內容 |
| ---: | --- |
| 0–26 | 「大家有沒有想過，如果今天有一家亞洲公司…差點把稱霸世界幾百年的瑞士鐘錶業直接逼到崩潰…甚至連很多你今天耳熟能詳的百年名錶，當年都一度陷入生死危機？」——利害，對觀眾說 |
| 26–30 | 「這聽起來像科幻小說，但在現實中真實發生過」——旁白的反應 |
| 30–47 | 1970–80 年代、「石英危機」、九萬人跌到三萬人——數字 |
| 50–66 | 這家公司是 Seiko；起點是 21 歲年輕人在銀座的小店——場景 |
| 66–75 | 「今天我們就來聊聊 Seiko 這個品牌當年到底有多瘋狂，以及他們是如何一步步把石英腕錶…塞進人的手腕」——承諾句 |

沒有一句預告後面的時刻。我們 H01 v2 前 57 秒：場景（0–27 秒，寫得好）→「而這，只是第一天」→ 劍（30 秒）→ 酒精被數（36 秒）→ 小說作者是誰（43 秒）→ 礁石（50 秒）→ 問題（57 秒）。
四個預告在 27 秒內連著丟，每個都是觀眾還不認識的東西；這是 10-13「開場要有很多鉤子」那條規則的直接產物，也是我提的。
10-07 的診斷已經量到 Gary Chen 與可波都有一句承諾句（39 秒、53 秒），當時只落到教學片的規則裡。

**改了**：`register.mjs` 的 `STORY_OPENING_RULE`（利害 → 場景 → 最多兩個預告 → 一句承諾句 → 問題）取代這兩個系列的「三到四個預告句」；
主機奇聞檔案局的 `shape` 第 1 步同步；盲評 `scene_first`、`opening_hooks`、`no_toc` 換成系列版（`STORY_SERIES_PANEL_QUESTIONS`），
否則照舊題目讀 Seiko 這種開場會被判「少於三個預告」「介紹主題」而退稿。其他旁白影片（AI 名詞、原來如此）維持原規則。

### 3.3 密度與長度

同樣 10 分鐘，他講 3,000 字，我們講 2,100 字。他 13 分鐘中位、Seiko 20 分鐘；馬臉姐 31 分鐘中位。我們的目標 10 分鐘、正文 8 分鐘是 10-10
定的，當時寫「等前三集的留存數據再決定要不要拉到 15 分鐘」——現在沒有留存數據（觀看太少），但並排看得出：**他們一集的資訊量是我們的 2–3 倍**，
不是因為講得慢，是因為講得多。

**沒改、要站主決定**：`target_minutes` 10 → 13（品牌故事的 `series.json`、主機奇聞檔案局的長度、skill 定案表）。在拍板前，兩個 skill 已寫「字數照 4.5 字／秒算」，
10 分鐘正文約 2,700 字起算（原本 2,100–2,600）。

### 3.6 字幕、畫面與頻道

- **畫面**：10-07 量過黑猫每 4.9–6.7 秒換一張、每張都有運鏡與字幕；我們 5 秒一張但運鏡幅度小（10-24 對漫劇量到鏡內動量 1.2 對參考 8–12）。奇聞檔案局用的是同一套 `assemble` 運鏡常數，沒有重新量；列為下一步。

## 6. 量法

```bash
# 清單（標題要 UTF-8，否則中文變 ?）
PYTHONUTF8=1 python -m yt_dlp --flat-playlist --playlist-end 120 \
  --print "%(id)s	%(view_count)s	%(duration)s	%(title)s" https://www.youtube.com/@qiqiqushi0/videos
# 字幕時間軸（黑猫有上傳 zh-TW 字幕；我們的 CC 同樣抓得到）
python -m yt_dlp --skip-download --write-subs --write-auto-subs --sub-langs zh-TW --sub-format json3 -o "%(id)s" https://www.youtube.com/watch?v=a7NlBfRCgqI
# 沒字幕的片（馬臉姐、cheap）：抓音訊 → 16k wav → faster-whisper small
python -m yt_dlp -f "ba[ext=m4a]/ba" -o "%(id)s.%(ext)s" https://www.youtube.com/watch?v=cbTaGjK-YQE
ffmpeg -i cbTaGjK-YQE.m4a -ac 1 -ar 16000 cbTaGjK-YQE.wav
```

- 這台機器的 PyAV 19 跟 faster-whisper 1.2.1 不合（`av.open(... metadata_errors=)`），要先用 `wave`＋numpy 讀成陣列再給 `transcribe()`；faster-whisper 裝在 user site，不能用 `python -I`。
- 字／秒＝去掉標點後的字數 ÷ 最後一句結束秒數；空檔＝相鄰字幕段的間隔 >1.5 秒；「你」「我」用字串計數。
- 縮圖：`https://i.ytimg.com/vi/<id>/hqdefault.jpg` 十二張用 PIL 拼成一張看，不重用圖片。
- 10-07 的畫面節奏量法（故事板格差）與 10-24 的幀差量法（內建瀏覽器 `<video>` seek）這次沒重跑。
