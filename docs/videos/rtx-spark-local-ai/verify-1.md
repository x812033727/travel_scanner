## The four questions the writer flagged

1. **GB units: settled; the table was already consistent, no cell changes.** Files are decimal on both sites the table uses. The Hugging Face tree of gpt-oss-120b prints the 4,625,017,896-byte shard as 「4.63 GB」. Ollama's registry manifests give 42,520,398,528 / 74,975,054,528 / 39,969,737,408 / 141,117,917,888 bytes for the llama3.3 tags ollama.com prints as 43 / 75 / 40 / 141 GB (÷10⁹ matches each; ÷2³⁰ would print 40 / 70 / 37 / 131). Memory capacity is binary: JEDEC Standard No. 21-C §2.5.4–2.5.5 (HTTP 200): "When describing the storage capacity of a memory device the quantity K=1024 is used", "M=2exp20 or 1024K". JEDEC's dictionary entry that spells out giga = 2³⁰ exists but answered 403 (Cloudflare). NVIDIA's pages do not define GB; its "128 GB / 64 GB LPDDR5X" and Windows 11's "4 GB" RAM are memory capacities, so they are 2³⁰-byte GB. With files in 10⁹ bytes and memory in 2³⁰ bytes, every cell holds (arith.py). gpt-oss-120b is 65,248,893,184 B = 60.77 GiB; 64 GiB minus Windows' 4 GiB leaves 60 GiB, and 64 GiB is 68.72×10⁹ B, so the cell is **太擠**. It would be 放不下 only if memory GB were decimal, which JEDEC rules out. The convention is on screen in a few characters: the fit-rule slide's note 「記憶體的 GB 以 1024³ 計：128 GB ＝ 檔案算法的 137.4 GB」, narrated in i55z. The table template has no note field, so the fit-table slide itself carries none (see "suspected"). JEDEC 21-C was added to `sources`.
2. **OpenAI's 16 GB is GPU-usable memory: a card's VRAM or unified memory, not plain system RAM.** The model card and the openai/gpt-oss README say only "the gpt-oss-20b model run within 16GB of memory". OpenAI's own Cookbook page on running gpt-oss with Ollama says gpt-oss-20b is "Best with ≥16GB VRAM or unified memory ... Perfect for higher-end consumer GPUs or Apple Silicon Macs", and adds "You can offload to CPU if you're short on VRAM, but expect it to run slower". openai.com itself answered 403. The video's line 「OpenAI 說，gpt-oss-20b 在 16 GB 記憶體內就能跑」 is faithful, so no change. Its 太擠 verdict for 16 GB is about system or unified memory, and holds for the unified case OpenAI names. It does not describe a 16 GB graphics card (see "suspected").
3. **「專用 GPU 記憶體」: not confirmed, so the exact label was dropped.** No support.microsoft.com zh-TW page shows it: not the Task Manager/cores article, not 「關於圖形處理單元 (GPU)」, not 「關於電腦記憶體」, and not the two searches. The only zh-TW Microsoft page that has it is Learn's troubleshooting article, whose `<meta name="ms.translationtype" content="MT">` marks it machine-translated. That page also writes 任務管理員／任務管理器 and 詳細數據, which are not zh-TW Windows strings, so its bracketed labels are not evidence of the UI. Line sji9 and the outro's `cta` now say 「顯示卡自己的記憶體」. Microsoft's DirectX blog defines dedicated memory on discrete GPUs as "your VRAM, the memory that sits on your graphics card". 「工作管理員 → 效能」 is confirmed on Microsoft's zh-TW support page.
4. **NVIDIA publishes no RTX Spark price, memory bandwidth or tokens-per-second figure today: confirmed.** I checked the product page's raw HTML: no bandwidth, GB/s, tokens-per-second, price or $ figure, and its spec table has no Memory Bandwidth row, unlike the GeForce laptop page's. The same holds for the press release, the IFA blog, and every later post under NVIDIA's RTX Spark blog tag (08-11, 08-25, 09-14). The only speed figures on those pages are for the GeForce RTX 5090 (IFA "1.9x"; Aug 11 "131 tokens per second"). A search surfaces "300 GB/s" from a user thread on NVIDIA's developer forums (2026-06-06, no staff post). The same thread withdraws it as a misread of the 600 GB/s C2C link, so it is not NVIDIA's figure.
