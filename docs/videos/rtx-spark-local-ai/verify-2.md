## Also found: NVIDIA published the memory bandwidth (two sampled rows were false)

Sampled rows L242 (「九月底未公布：**記憶體頻寬**、token 速度」) and L350 (「九月底頻寬未公布」) are contradicted by an official NVIDIA page that round 1 did not reach. The page is NVIDIA's developer documentation, NVIDIA Windows on Arm Porting Guide → System Overview → Key Specifications, https://docs.nvidia.com/rtx-spark/rtx-spark-porting-guide/latest/overview.html (HTTP 200, "Last updated on Sep 10, 2026"). It says: "Memory: Up to 128 GB of LPDDR5, shared by the CPU and iGPU. The interface is 256 bits wide, with a bandwidth of 300 GB/s. The memory is fully coherent." The guide's Unified Memory Architecture page points there: "Memory capacity, interface width, and bandwidth are listed in System Overview". The product page, the press release, the IFA blog and the RTX Spark tag's other posts still show no bandwidth. No NVIDIA page gives an RTX Spark tokens-per-second figure: the 131 and "over 200" tokens per second in the Aug 11 post are GeForce RTX 5090 figures. Round 1's reading, that the only "300 GB/s" was a withdrawn forum guess, is superseded by NVIDIA's own document.

Applied as a fact fix with its dependants. Line ids, order and reveals are kept, and no line or scene was added. The brief's own rule for this case (「NVIDIA 若公布了 RTX Spark 的記憶體頻寬…第 5 章改放 NVIDIA 的數字並標明是廠商公布的」) is met under the slide title 「NVIDIA 公布了什麼？」:
- published item 1 「有公布：算力、記憶體容量、功耗」 → 「有公布：算力、記憶體容量、功耗、頻寬 300 GB/s」. Line 3xvu (it reveals item 1) → 「有公布的：算力、記憶體容量、功耗，還有記憶體頻寬，每秒 300 GB。」
- published item 2 → 「九月底未公布：**token 速度**」. Line 6jug → 「九月底還沒公布的：每秒能產生幾個 token。」
- priorities row 4, reason cell → 「九月底 token 速度未公布」.
- youtube.description p1 → 「當天 NVIDIA 的 RTX Spark 產品頁沒有列價格，價格以官網為準；記憶體頻寬 300 GB/s 出自 NVIDIA 的開發者文件。」 The old sentence was literally true of the product page.
- `sources`: the porting guide was added. claims.md c4, c24 and c36 were updated.

The same guide (Unified Memory Architecture page, 2026-09-10) also describes how much memory the GPU can use. A dedicated carveout is "reported by Windows as dedicated GPU memory". Shared system memory is sized at "the post-carveout capacity minus 16 GB", "clamped to a minimum of 50% and a maximum of 80% of the post-carveout capacity". The rest is CPU-only memory that "cannot be used for GPU allocations". The carveout size is not given. By that rule the GPU can use about 48 GB of 64 GB (for any carveout under 32 GB) and 102.4 GB plus a fifth of the carveout of 128 GB. No fit-table cell changes, because every 放得下 cell is under those figures. Lines L081 and L084 (「五月的公告沒寫數字」) speak only of the May announcement and stay true, so they were not changed. They are flagged below for the owner.
