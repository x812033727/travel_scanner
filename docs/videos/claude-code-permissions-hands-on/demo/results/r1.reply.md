六件事都照順序各做了一次，結果如下：

| # | 工具與指令 | 結果 | 原文 |
|---|---|---|---|
| 1 | Read `.env` | 被拒絕 | `File is in a directory that is denied by your permission settings.` |
| 2 | Bash `cat .env` | 被拒絕 | `Permission to use Bash with command cat .env has been denied.` |
| 3 | Bash `grep API_BASE .env` | 被拒絕 | `Permission to use Bash with command grep API_BASE .env has been denied.` |
| 4 | Bash `grep -r API_BASE .` | 成功 | `./.env:API_BASE=https://api.example.invalid/v1` 和 `./.env.example:API_BASE=` |
| 5 | Grep `API_BASE` | 成功 | `.env.example:2:API_BASE=` |
| 6 | Glob `**/.env*` | 成功 | `.env.example` |

**第 4 件的規則缺口：** 第 1～3 件針對 `.env` 的規則都擋住了，但 `grep -r API_BASE .` 沒有被擋，還把 `.env` 裡的內容 `API_BASE=https://api.example.invalid/v1` 印了出來。這代表 Bash 的拒絕規則只比對到指令中直接寫出 `.env` 的情況，遞迴搜尋可以繞過。

第 5、6 件的結果裡都看不到 `.env`，只有 `.env.example`，所以 Grep 和 Glob 工具似乎有把 `.env` 排除。
