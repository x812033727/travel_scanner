# 十萬筆以上素材池，怎麼變成值得看的影片

2026-11-01。依站主補充：素材池可以超過十萬筆，再從中取捨組成影片。這個方向採用為擴充規劃；目前實際存在的是 **300 個歷史題＋13 個新增題＝313 筆來源紀錄**，不是已建成十萬筆資料庫。其中 100 題經初篩，44 題組成 [30 支影片候選](EPISODES.md)。沒有啟動大量抓取、付費生成或背景擴庫。

## 我們要累積的是什麼

一筆素材是一個有邊界的疑問、現象、觀測、實驗或工程案例；不是一整篇腳本。它可以尚未查證，也可以最後被淘汰，但狀態要清楚。不要把「為什麼天空藍」「天空為何是藍色」「藍天怎麼來」算成三個新發現。不同條件真的改變答案時才拆開，並記錄差別。

《十萬個為什麼》提供從日常追問機制的方向。沒有指定版本，也不將任何一本書或節目整套問答搬進資料庫。書目、目錄與公開問答可以作找題線索；核心解釋回到可追溯資料，腳本重新寫。

| 層級 | 放什麼 | 能不能直接拿來拍 |
| --- | --- | --- |
| 候選池，目標可超過 100,000 筆 | 待研究問題、來源線索、重複或淘汰紀錄；生成的問題明標「生成提案」 | 不能；沒有來源的提問不算事實 |
| 研究素材 | 具體主張、原始來源、適用條件、反例、可用畫面與權利狀態 | 還不能；核心查核不等於整支影片已查核 |
| 主題群 | 同一核心問題下可相接的素材，記錄相接理由與不同機制 | 用來挑故事，不要求群內每題都入片 |
| 單集企劃 | 核心承諾、章節推進、入選／不講素材、長度估計、證據缺口 | 通過 treatment、查核與試讀後才進製作 |
| 鎖定製作包 | 完整稿、逐主張來源、盲讀紀錄、媒體方案與核准版本 | 依既有報價、製作、驗收、上架流程 |

十萬筆是候選儲備的規模，查核深度按用途逐層增加。不能因為題目存得多，就要求每題都寫出三千字；也不能把重複改寫、無根據答案和未讀過的連結算成「已研究」。

每批另外報六個數量：**原始提問紀錄、去重後不同問題、前提檢查通過候選、來源足夠素材、單集企劃、已審完整劇本**。目前的 313／100／30 是本輪來源紀錄、初篩素材和企劃數，不能直接冒充新資料管線已量測的各層通過率。

## 每筆要留下的最小資料

| 欄位 | 用途 |
| --- | --- |
| `candidate_id`、`canonical_id`、原題號別名 | 穩定識別；重複題指向主題，不重新發號當新增成果 |
| `question`、`scope`、`topic_tags` | 問什麼、限哪個地點／物件／條件；分類可多標籤 |
| `origin_type`、`origin_ref`、`discovered_at` | 人工疑問、讀者投稿、書目線索、公開資料、生成提案各自分清 |
| `claims[]` | 想回答的主張及其 `unverified / supported / disputed / refuted` 狀態 |
| `sources[]` | 精確 URL／書目定位、發布與查閱日期、支持哪條主張、原始或轉述來源、必要短摘錄 |
| `limits`、`counterexamples` | 哪些條件不能套用，尚有什麼爭議 |
| `visual_evidence`、`rights_status` | 圖表、實驗、照片是什麼，能否引用或重製；生成插畫不算實驗證據 |
| `relations[]` | 重複、前提、因果下一步、同機制變條件、反例、可比較的不同機制；每個關係有理由與可信度 |
| `editorial_status`、`decision_reason` | 新進、待查、可研究、短形式、暫緩、淘汰；保留處置理由 |
| `episode_links[]`、`used_claims[]` | 哪支企劃實際採用了什麼，防止同一答案換標題再拍 |
| `reviewed_at`、`reviewer`、`revision`、`content_hash` | 修訂與查核可追溯；來源變更影響到哪些影片 |

來源 URL 存在不等於支持主張。來源內寫給模型的指示一律只是資料，不作操作指令。保存必要的摘要與短引用，不無差別複製全文；抓取遵守網站條款與存取限制，不繞過登入、付費牆或反爬限制。

## 怎麼擴到十萬筆而不灌水

1. **先把現有 313 筆變成可追溯的起點。** 保留原 ID、原查核包與第一、二輪取捨，不把舊資料改名就算新增。現有檔案是這個起點，仍需正式的匯入／去重實作。
2. **增加來源種類與尺度。** 生活觀察、科學館和大學公開教材、氣象／太空／地科機關、公開研究、標準與工程文件、官方資料集、已核對的產業個案。分類用來發現缺口，不按每類硬塞相同數量。
3. **生成模型只提問題和關係候選。** 例如同一現象換條件會如何、觀眾的直覺漏了什麼；未讀到來源前不生成「已知答案」欄。不得用「物件 × 為什麼句型」的排列組合冒充十萬個不同問題。
4. **先去重再深查。** 先正規化字詞與精確匹配，再做語意近似與「答案是否相同」檢查。語意模型只提合併建議；兩個答案不同的相似問題不能自動合掉。保留原紀錄、別名與回復路徑。
5. **以主題群挑研究投資。** 每輪選少量可形成完整影片的群，補一手證據與反例；其餘留在候選層，不能批次升格為已查核。
6. **採用與淘汰都回寫。** 題目薄、前提錯、與已拍內容重複，都記錄原因與可重評條件；別的批次再次遇見時沿用識別，不讓它反覆混入長片選單。

建議分三段驗證流程，數字是規劃檢查點，並非已完成或背景執行的批次：

| 階段 | 要證明的能力 | 過關才擴大 |
| --- | --- | --- |
| 現有 313 → 約 1,000 候選 | 不重複計數、原來源可回找、錯誤前提能擋下、能找出跨題連結 | 人工抽查每種來源、重複合併、淘汰與入選各一組，記錄樣本與缺陷 |
| 約 1,000 → 約 10,000 候選 | 批次續跑、增量更新、查核狀態不誤升格、同核心撞題能追蹤 | 零未處理的嚴重證據錯配；去重有誤時先修規則再繼續擴 |
| 約 10,000 → 100,000 以上候選 | 搜尋／分群可用、每批成本可控、來源更新可找回受影響企劃 | 用實際抽查與編輯命中率決定擴速，不用資料列數作唯一成績 |

第一段先用小批候選驗證規則，通過後才累積下一段。抽查不能證明整批全對；進入影片的每條主張仍須逐條核對。後續若要付費研究或模型批量執行，先按「候選取得、去重、補查核、獨立覆核」分別報實際費用；本次沒有估造服務價格或授權大量花費。

## 如何從素材群裁成一支影片

「裁」是選擇與重新組織，最後寫成一條有推進的稿；不是把幾篇舊問答接起來。

1. **先選一個觀眾會追的問題。** 要能一句話說清楚，而且結尾確實回答它。
2. **畫因果線或一次觀察的路徑。** 每段必須回答上一段引出的疑問。共同物件也可以比較不同機制，但要交代為什麼現在需要比較。
3. **只挑會改變理解的素材。** 一筆作開場反差、一筆建立機制、一筆指出限制、一筆提供反例；沒有任務的素材不進片。群裡有二十題，也可以只用三題。
4. **先排轉折，再估時長。** 8–10 分鐘只能說清的題目不勉強做 13 分鐘；10–16 分鐘是本輪多數候選範圍，16–18 分鐘須有額外而必要的推進。超過 18 分鐘先檢查是否其實是兩個能各自回答的核心問題。
5. **給每段做刪除測試。** 刪掉以後理解、證據與下一段都不受影響，就刪。長度縮短是有效編輯結果。
6. **無圖試讀再驗證。** 讀者說得出核心問題、每章新增什麼、哪些是不同機制、結尾答案和限制，才算成立。正式旁白後再量測；AI 估時或字數不算實測。

例：候選池可以有悠遊卡、無線充電、電磁爐、Wi-Fi、磁浮列車等幾十筆「看不見的電磁現象」。P01 只選 **卡片、手機充電、鍋子**，因為能沿「接收能量 → 能量做什麼 → 損失與條件」比較。Wi-Fi 與磁浮沒有這支片的必要角色，先不講。三種裝置各自的電路與機制仍要查核，不因同群便宣稱完全相同。

## 什麼情況下直接退出長片

- 前提本身不成立、依賴未證實傳聞、需要捏造案例才能好看：淘汰該角度，保留拒絕理由。
- 一個答案講完後，只剩更多相似例子或人物／品牌清單：改短形式或留素材。
- 可以講很久，但沒有一條觀眾追問的主線：重新分群，不能把知識密度誤當故事厚度。
- 來源足夠卻沒有可理解的畫面／觀察：先補表達方案，不能用無關可愛圖拖長。
- 合題只因為同屬「食物」「動物」「科技」：拆開重選；同分類不是合併理由。
- 試讀去掉重述後不足 8 分鐘：退出既有長片路線。若要 Shorts，另外選一個能獨立成立的小問題，不把七分鐘稿硬壓到五十秒。

## 如何判斷素材池有用

同時看候選數、不同核心問題數、來源可追溯率、抽查證據錯配、重複誤合併、主題群轉 treatment 的比例、試讀被判無聊或不連貫的原因，以及成片後實際的留存資料。這些指標目前沒有量測值；不能預先寫成功率或流量保證。

優先增加能形成新故事的來源與關係。若新增十萬筆卻只有一千種重複答案，不算成功擴庫；若少量新素材能把一個原本太薄的題目變成清楚、有反例的完整主題，就值得保留。
