# 原來如此事務所：大素材池，依故事厚度組成影片

2026-11-01。採奇聞檔案局新版開場、鉤子、插畫、字幕與包裝，再依站主補充調整：**素材可以累積到十萬筆以上，每支影片的長度由內容決定，太薄就移出長片，相關題目能串起來才合成主題。**

先讀 [十萬筆素材池規劃](POOL-STRATEGY.md) 與 [30 支逐集企劃](EPISODES.md)。前者是可擴充方向，目前沒有十萬筆資料庫；後者有核心問題、素材組合、片長範圍、章節預算、無聊風險與刪減條件，目前沒有完整稿或成片。共用產線尚未同步，也沒有讀取正式站／YouTube 的當前片單，故正式開寫前仍須核對既有製作狀態。

## 前六支：先做 treatment 與試讀

| 順序 | 核心主題 | 合入素材 | 估計正文 |
| --- | --- | --- | --- |
| P01 | 卡片不燙、鍋子卻熱：電怎麼隔空過去？ | 卡片供電＋無線充電＋電磁爐 | 14–16 分鐘 |
| P02 | 一朵雲，怎麼變成午後大雨？ | 雲中水滴＋午後對流降雨＋雨滴觀測 | 14–16 分鐘 |
| P03 | 檔案存好、刪掉，真的照畫面發生嗎？ | 寫入／退出＋刪除與儲存狀態 | 12–14 分鐘 |
| P04 | 太空人一直在掉，火焰為什麼也變了？ | 軌道自由落體＋微重力下的火焰 | 14–16 分鐘 |
| P05 | 羽絨衣不發熱，為什麼穿上就暖？ | 材料摸起來冷暖＋羽絨隔熱＋保溫瓶 | 14–16 分鐘 |
| P06 | 泡泡的形狀與顏色，藏在哪一層？ | 泡膜形狀＋干涉與觀測變化 | 10–12 分鐘 |

是建議試寫順序，沒有開播日或付費製作排程。P06 若缺同一顆泡泡的變化序列，就繼續縮短；排名不能保住片長。獨立審閱也將 P02 從 16–18 分鐘下修，避免雷達支線佔滿尾段；P22 肥皂改成先補對照、再判斷能否成立的 8–10 分鐘條件題。

本輪多數候選估 10–16 分鐘；有厚度才能更長。所有時間是正文估計，片頭片尾另計。以試讀及實際旁白重算，不把字數、章節表或「13 分鐘」當成好看的證據。

## 哪些拿掉，哪些合起來

- **薄題移出長片：** 自己的錄音聲 S26、鏡子顛倒 S27、洋蔥流淚 S03、吐司冰後變硬 S54、跑道數字 T54 等。好疑問仍可留在素材池，但不靠反覆舉例加長。
- **有缺口就暫緩：** 百圓商店 B45、吃到飽 B72 缺可追溯經營個案；騎樓 T73 沒限定制度與地點；運河屋 T44 不把窄與傾斜硬說成同因。B26 有既有製作紀錄與新角度證據缺口，不預設重做。
- **錯前提或過時角度剔除：** AI 數 strawberry A08、AI 手指 A16、密碼必須混大小寫 A09、民族偏好或身高單因故事、百事「海軍排名」噱頭等。理由留在初篩表，避免換標題復活。
- **企業興衰轉線：** Nokia、Blockbuster、柯達等仍可當品牌故事候選；沒有自動匯入別的系列。
- **合題有共同追問：** 泡泡形狀＋顏色追同一薄膜；檔案寫入＋刪除追同一檔案。藍天＋彩虹、洗油＋泡泡、壁虎＋蟑螂等只因分類相近，不硬合。

## 本機入口

```powershell
node tools/video/so-thats-why/cli.mjs check
node tools/video/so-thats-why/cli.mjs list
node tools/video/so-thats-why/cli.mjs brief P01
node tools/video/so-thats-why/cli.mjs brief A68
node tools/video/so-thats-why/cli.mjs show S26
node tools/video/so-thats-why/cli.mjs topics
```

`list` 現在列 30 支單集候選；`topics` 才是 100 題初篩素材。`brief A68` 會導向整支 P01 並帶三題來源，不再替 A68 固定套一支 13 分鐘影片。`brief S26` 因第二輪已改短片而拒絕；`show S26` 會顯示初篩及本輪理由。所有 brief 都是 `EDITORIAL_BRIEF_NOT_IMPORT_READY`，不能直接匯入、核准或付費開拍。

`catalog.json` 保存第一輪來源與處置，`episodes.json` 保存第二輪單集計畫與完整 100 題對應。雜湊綁來源檔、舊查核包、規格與企劃定義；來源或生成文件漂移時拒絕使用，重新審閱才執行 `build`。初篩 24 題舊排序僅存於 `historical_first_pass_order`，已由上述單集順序取代。

## 製作規則與後續交接

[SPEC.md](SPEC.md) 是本輪規格：五步開場、最多兩個預告、30–45 秒內有內容推進、依每集長度規劃伏筆回收、MiniMax `image-01` 可愛插圖、七成插圖、最多三張連續字卡、配樂、繁中燒錄字幕、濃縮後品牌片頭與 v4 片尾。

共用工人、後台題庫、舊 `long-form inputs` 與縮圖預設仍是原程式；[產線同步票](../../../../tasks/open/2026-11-01-sothatswhy-production-rules-sync.md) 執行時必須以 **CURRENT → 本版 SPEC／episodes.json** 為準，採每集片長和素材組合，不能照舊票的固定 13 分鐘文字擴批。相關共用檔仍有其他任務持有，本次沒有改動。

大型候選池需要另外實作匯入、持久索引、去重與來源更新；[素材池規劃](POOL-STRATEGY.md) 明列資料欄位、313→約 1,000→約 10,000→100,000 以上的檢查點與品質門檻，沒有啟動批量研究。題目數與影片數分開計，生成提案不能升格為來源。

開拍前逐集補完整稿、claims、分鏡與當期來源，獨立查核及聽稿後再按實際片長報整集費用。舊 T26／T27／B26 的影片、核准與付費紀錄維持原狀；重製須另綁版本。未合併、未部署、未生成或上傳媒體。
