## 2. 兩個角色怎麼分工

| | 所長（主持人） | 小問（小孩） |
| --- | --- | --- |
| 是誰 | 事務所的所長，原本那個說故事的聲音，現在有了樣子 | 約 8–9 歲，每集帶一個生活裡看到的問題來事務所「報案」 |
| 台詞比例 | 約 75% 字數：講機制、講證據、轉向觀眾說「你」 | 約 25% 字數：發問、說出直覺答案（常常是錯的）、反應、追問、最後說「原來如此！」 |
| 句長 | 照奇聞旁白，一句 ≤ 25 字為主 | 短，一句 ≤ 15 字；不講術語，所長講了術語小問就問「那是什麼？」 |
| 職責 | 回答；不搶答小問還沒問的；意見標成意見 | **代替觀眾**：觀眾在這裡會冒出的疑問由她問出來。這也是兌現「每 30–45 秒一個鉤子」最自然的方式 |
| 不做 | 不對小孩說教、不嘲笑錯的直覺 | 不當可愛擔當亂插話；不知道答案時不裝懂；不講超齡的知識 |

規則：
- **小問的錯誤直覺是主線的引擎**。每章開頭由她說出一個合理但錯的猜法（「雲是棉花做的吧？」「水滴太小所以沒有重量？」），
  所長用觀察或證據推翻，這就是 SPEC 的「直覺碰壁 → 新觀察 → 機制」。
- **每章結尾的懸念由小問問出口**，下一章第一句由所長接住。
- 片尾的「原來如此！」由小問說，同時答案卡蓋印章（look.md 的結尾蓋章）。
- 「說給一個人聽」照舊：所長每章至少一句轉向觀眾的「你」，不只對小問講。

## 3. 畫面：兩個角色怎麼進插圖

MiniMax `image-01` 讀得懂**一個**角色參考圖，讀不懂多人互動（奇聞 skill：「兩三個人同框互動 → 試圖被退」）。所以：

1. **兩個角色一律分鏡，不同框**。對話用正反打：小問發問的鏡頭、所長回答的鏡頭，各自「一個人做一件事、臉朝鏡頭」。
   需要交代兩人在同一個空間時，用一張沒有人的事務所空景，或卡片。
2. **小問就是內容插圖裡的那「一個人」**。奇聞要求插圖是「一個人在那個地方做一件事」；這集由小問來做：
   她在陽台抬頭看積雲、手貼冰杯看水珠、在騎樓下看雨打在地上。這樣內容插圖和角色是同一條線，不會變成「角色鏡頭 vs 內容鏡頭」兩套畫面。
3. 所長多半在事務所（白板、放大鏡、檔案夾、印章），少數到現場；所長鏡頭佔全片約 15–20%。
4. 純機制畫面（一滴水的放大、上升氣流箭頭、雲滴 vs 雨滴大小比例）不放人，寫成卡通裡會有的樣子；數字與比例畫成圖，不用卡片（§1「畫面上的字」）。
5. 2026-11-05 起正文不用卡片；只有片尾訂閱卡還有字（見 §3.2 待決）。

### 3.1 插圖提示詞怎麼寫（2026-11-06，借自 PR #2027 奇聞的 W03 實測，加上 P02／P05 自己的教訓）

- **短、動作在前、角色描述在後**：景別 → 地點 → 一個角色做一個動作 → 一兩個道具；角色外觀（`KIDDESC`、`CHIEFDESC`）接在最後。
  動作越簡單越容易過：P05 第一輪 113 張裡 24 張三次不過，幾乎都是複雜的手部動作或一手一物的對照。
- **白天、明亮**：檯燈、夜晚、`soft lamp light` 常被畫成 3D 公仔（P05 重畫時「3D CGI」「clay figurine」是最常見的退件原因）。新集光線寫 bright morning、daylight。
- **不寫 no、not、without、text、blank**：模型沒有反向提示詞，寫了反而畫出來。P02 的 `BLANK`（「every sign … is plain and blank」）新集不要再用。
- **會冒字的道具換掉**：日曆、招牌、報紙、白板上的字、筆記本都會長出亂碼。**小問的設定寫著拿筆記本**，兩集都一直冒出筆記本與假字（見 §3.2）。
- **螢幕寫出畫面內容**：「a phone showing a simple map with a blue route line」，不寫空白螢幕。
- **數字畫成圖**：「一滴雨要一百萬顆雲滴」畫成一顆大雨滴被無數小點圍住（P02 `kid-million`）。
- **眼睛**：關鍵影格評審 2026-11-05 起問眼睛（`tools/video/media/keyframes.mjs` 的 anatomy 題），但輕微的鬥雞眼它仍會放過，
  分鏡給站主前另外請一個代理逐張放大看眼睛。三次都畫不好的臉，改成閉眼笑（「her eyes closed as two happy curved lines」）、
  背影，或沒有人的物件特寫——這三種畫法沒有瞳孔可以歪。
- **改評審題目會讓整集重評**：評審的題目是每張圖評分紀錄的一部分，題目一改，已核准的圖下次跑 `keyframes` 會全部重評、
  不過的重畫（P05 因此被換掉 49 張已核准的圖，救回花了半天）。已核准分鏡的集數要重畫少數幾張時，只讓那幾張用新題目
  （做法記在任務票 `2026-11-05-keyframe-judge-checks-the-eyes-mismatched`）。
- 已付錢的圖提示詞逐字不動（吃快取）；這一節只管新畫的景。
- **英文名稱照原文念**（借自 PR #2027）：台詞裡的品牌、產品、單位照英文原文念，不寫中文音譯的 `say`；台灣慣用的正式中文名例外（例如維基百科）。新詞記進 `docs/videos/lexicon.json`。

## 5. 為什麼選 P02（雲 → 午後大雨）

候選看了 #1971 標「優先試做」的 P01–P06：

| 企劃 | 對話版適不適合 |
| --- | --- |
| **P02 雲變午後大雨** | **選這個**。小孩最自然會問（「雲裡有水，為什麼不掉下來？」），錯的直覺很多又很好推翻（棉花、沒重量、整朵掉下來），每一步都畫得出來，小問可以真的站在陽台看雲、在騎樓下躲雨；台灣夏天的午後雷陣雨人人有經驗；來源可以全用氣象署、NOAA、UCAR 這種官方或教學單位，不靠單一論文 |
| P05 羽絨衣 | 也很適合小孩，但「空氣不導熱」的機制較抽象，第二梯 |
| P06 泡泡 | 只有 11 分鐘、偏光學，對話容易變成名詞解釋 |
| P01、P03、P04 | P01 三種裝置要合併、P03 偏電腦、P04 要先講微重力；都比較適合大人提問 |

## 6. P02 試做 treatment（13 分鐘版）

#1971 估 15 分鐘，但它的刪減條件已經說「雷達、閃電、雨味不展開」；對話版拿掉開場濃縮後，先以 **13 分鐘正文**（約 3,500 字，4.5 字／秒）寫，試讀後照實際長度決定，不硬拉。

| 段落 | 約略 | 主線推進 | 小問的直覺／問題（鉤子） |
| --- | --- | --- | --- |
| 片頭 | 11.9 秒 | 系列片頭動畫 | — |
| 開場 | 40 秒 | 午後兩點還大太陽，三點就下大雨；小問在陽台看著一朵白雲變灰變高 | 「雲裡面真的有水嗎？那它為什麼不會掉下來？」承諾句：今天從一朵雲裡的一滴水開始，看它怎麼留在天上、又怎麼變成打在你身上的大雨 |
| 1 晴天怎麼長出一朵雲 | 2.5 分 | 地面曬熱 → 暖濕空氣上升 → 上升變冷 → 水氣在微小顆粒上凝結成雲滴；雲是很多很小的水滴，不是水蒸氣 | 「雲是水蒸氣吧？」（錯：水蒸氣看不見）→ 章尾：「那一朵雲有多少水？」 |
| 2 有重量，為什麼還在天上 | 3 分 | 一朵積雲的水量（待查核的官方估值）；雲滴極小，落得極慢；上升氣流比它掉得快，所以整體留在天上 | 「它太小所以沒有重量？」（錯：有重量，只是落得慢）→ 章尾：「那要多大才會掉下來？」 |
| 3 水滴長大以後 | 3 分 | 一顆雨滴要很多雲滴合起來（碰撞合併；溫度低的高處還有冰晶長大再融化的途徑，只帶到一句）；大的落得快，開始往下穿過雲 | 「是不是整朵雲撐不住就一起掉下來？」（錯：是一顆一顆長大的水滴先落）→ 章尾：「那為什麼不是每朵雲都會下雨？」 |
| 4 為什麼偏偏是午後 | 2.5 分 | 一天裡地面加熱的時間差 → 對流在午後最旺；雲頂長得夠高、上升夠強才下大雨；雨帶下冷空氣，雨常常下一陣就停（邊界：不是所有雲都會發展成雷雨） | 「所以每天下午都會下雨嗎？」（錯，回到條件）→ 鋪雨滴形狀 |
| 5 地上看到的雨告訴你什麼 | 1.5 分 | 短對照（SPEC 上限 60–90 秒）：雨滴不是淚滴形；用一場有官方觀測的午後雷陣雨回收前面所有條件 | 「雨滴不是尖尖的嗎？」 |
| 收尾 | 35 秒 | 回答片頭問題；留言題：「你那邊午後雷陣雨通常幾點開始？」；訂閱理由 | 小問：「原來如此！」＋印章 |

`loops`（13 分鐘至少 11 個，每個都要回收）先列 11 個：雲裡真的有水嗎、有水為什麼不掉、一朵雲多重、雲是不是水蒸氣、要多大才會掉、
一滴雨要多少雲滴、整朵雲會不會一起掉、為什麼不是每朵都下雨、為什麼是下午、為什麼下一陣就停、雨滴的形狀。

**開場對話草稿**（口吻示範，數字都還沒查核，不可錄音）：

> 小問：所長！我剛剛在陽台看到一朵雲，越長越高，現在變成灰色的了。
> 所長：那你等一下可能要收衣服了。
> 小問：可是我想不通。雲裡面真的有水嗎？
> 所長：有，而且很多。你抬頭看到的那一大片白色，裡面全是水。
> 小問：水不是比空氣重嗎？那它為什麼沒有整團掉下來？
> 所長：這個問題很好。你每年夏天都見過答案，只是沒人跟你說。今天我們就從那朵雲裡的一滴水開始，看它怎麼留在天上，又怎麼在一個小時以後，變成打在你身上的大雨。

## 7. 查核清單（撰稿時逐條找一手或官方來源，寫進 `## 來源`）

- 雲是液態小水滴或冰晶，不是水蒸氣；凝結需要凝結核（氣象署、NOAA JetStream）。
- 一朵典型積雲的含水量估值（常見說法約 50 萬公斤，出自 NCAR／UCAR 的估算；要找到原出處，找不到就不講數字）。
- 典型雲滴與雨滴的直徑、落速；一顆雨滴約需多少雲滴（數量級，教科書或 UCAR／NOAA 教材）。
- 積雲中上升氣流的速度範圍。
- 暖雨（碰撞合併）與冷雨（冰晶）兩種途徑；台灣午後雷陣雨以哪種為主——查不到定論就兩種都說「都可能」。
- 台灣午後對流的日變化（氣象署的氣候統計或說明頁）。
- 雨滴形狀（小雨滴近球形、大雨滴底部扁平；USGS／NASA GPM）。
- 第 5 章若找不到一場可引用的官方觀測，整章縮成 30 秒，不用別的題目補分鐘數。

### 10.1 插圖

- **嚴格的評審會讓大半鏡頭「不過」，但它不準。** #2028 的角色一致題目上線後，P14 畫了 139 張有 101 張三次都不過、P07 122 張有 66 張；很多好圖被打掉，有些假字、3D 圖卻過了。`--accept-best` 這個系列不能用（只給插畫型影片）。做法：三次都不過的鏡頭，`manifest` 本來就指向分數最高的那張；交給**另一個代理逐張放大看**，只挑嚴重的（眼睛、假字、多出來的人或物件上的臉、角色走樣、3D／黏土／照片風），其他的用 `repin` 固定。P07 66 張挑出 24 張、P14 101 張挑出 23 張要重畫。

- **所長一直被畫成灰髮老太太，根源是基本描述裡的「a streak of grey」。** 在後面補「jet-black hair」蓋不過它，要整句換掉：`build_scenes.py` 的 `CHIEFFIX2` 這組鏡頭改用不帶灰髮的 `CHIEFFIX_DESC`。P14 的評分者指出設定圖上看不出灰髮，下一集可考慮整個系列拿掉這句（會重畫所有所長鏡頭，先跟站主說）。

### 10.5 借自奇聞 W03 的教訓（PR #2037），原來如此也用得到

奇聞是不同系列（cute-mystery、只有 Ada 一個角色），下面只挑對話版也碰到的；其餘（Ada 設定圖、螢幕安全圖案、年報畫成書、片頭位置）不適用。

- **數字畫成感覺，不畫比例**：模型數不準「兩顆加一顆」「七成」，箭頭方向也常畫反（P07 `two-plus-one` 就是這樣）。改用鼓或扁的東西、升起或洩氣的氣球、多一顆發亮的球；同一集的比喻前後一致。
- **方向與位置靠不住**：「往下」「偏掉」「快掉下去」「拼在一起」常畫成相反。挑意思不靠方向的畫面。
- **畫完自己先放大看**：交評分前用 PIL 把每張切四格 2x 看（眼睛、假字、物件上的臉），比交出去被退省一輪。PR #2033 的放大評審只在問「有沒有字」「不該有人」時附四格放大；原來如此現在也算不放字的畫風，這兩題會一起帶放大圖。
- **評分員每輪不同人，分數會差 3–4 分**：分數卡在門檻附近時，不要一直重跑評分；硬規則（眼睛、假字、多出來的人、3D）清乾淨，角色鏡頭一次修完，再評一次就決定。
- **背景工作會在對話閒置或容器重開時被收掉**：`keyframes`、`assemble`、`dub` 跑在背景時，回來先 `pgrep` 確認還活著；死了就重跑，已畫、已錄的會沿用。
