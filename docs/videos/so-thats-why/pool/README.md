# 原來如此事務所：第一批 1,000 筆素材池

已建立 **1,000 個去重後的候選核心問題**，並挑出 **12 組影片主題**。這一批供研究與編輯選材；不是 1,000 份已查核答案，也不表示每題都能獨立拍成長片。

先開 [可搜尋素材池](index.html)，可依關鍵字、分類、影片主題篩選，展開每題查看來源小節、適用範圍及待查事項。也可看 [完整題目](QUESTIONS.md)、[影片組合與片長](THEMES.md)、[去重紀錄](DEDUP.md)、[來源索引](SOURCES.md)。

## 怎麼判重與選入

完整問題經字元、標點正規化後相同，才可自動合併。其餘用題名、研究目標和機制關鍵字提出相似對，再讀核心答案與條件；相似分數不會自動決定合併。相同完整機制鍵不受熱門詞過濾影響。此法及人工審閱仍不能證明所有語意重複都已找完。

例如蒸散的兩種問法、鹽降低凝固點、催化的不同生物例子已合併；衛星為地球自轉換接收站，與因局部天氣換光學接收站，則保留為不同問題。合併後只算一筆，變體及全部來源仍保留。歷史剔除／轉線／暫緩題不會因換標題重新入選。

911 筆新題已由非原作者逐題做編輯審閱；外站獨立覆核是風險抽查，沒有逐條重核全部事實。查閱範圍、抽查頁、問題和修正都在 [審閱紀錄](reviews/)。新題的生活情境有些是根據來源機制推導，notes 會標明，進稿需補直接案例與條件。

入選先採本輪來源研究且交叉審閱後可用的新核心，再從歷史可研究題中依既有單集組合、候補與短形式處置排序，優先科學／科技。來源有多少不當成品質分數；一頁有多題也不代表多份獨立證據。少數定義辨析只適合影片中的一小段，未承諾獨立長片。

## 影片怎麼從素材長出來

[12 組候選](THEMES.md) 都寫明共同追問、前後相接理由、每章新增理解、秒數預算、可能無聊的位置、應刪條件與待補證據。優先六組供 treatment：

1. 看起來混勻了，杯子裡真的一樣嗎？9–11 分鐘。
2. 一個字，電腦怎麼算出好幾個？8–10 分鐘。
3. 地底明明有水，為什麼不能一直抽？12–15 分鐘。
4. 工具幫你省力，代價藏在哪裡？9–11 分鐘。
5. 全家共用一個 IP，資料怎麼不送錯？9–11 分鐘。
6. 土裡有水，盆栽為什麼還會垂頭？9–11 分鐘。

沿用本次 [新版規格](../refresh-20261101/SPEC.md) 的敘事要求：開場有具體疑問、章節接得上、每 30–45 秒有實際資訊推進與追問；刪掉一段不影響理解就刪。章節預算還不是節拍表，也沒有用字數冒充實測片長。刪重述後不足 8 分鐘，就退出長片或改短形式；不為湊 13 分鐘塞同義例子。

用 `theme G01` 可輸出該集候選、來源與缺口，交給既有單集 treatment、逐主張查核、獨立盲讀和試讀流程。這些指令沒有製作、上架或付費 API。

## 本機使用與重建

需要 Node 24。Windows 本輪驗證使用 Codex 附帶的 Node 24.19.0；沒有新增 npm 相依。

```powershell
node tools/video/so-thats-why/pool/cli.mjs check
node tools/video/so-thats-why/pool/cli.mjs index
node tools/video/so-thats-why/pool/cli.mjs search 地下水
node tools/video/so-thats-why/pool/cli.mjs show N098
node tools/video/so-thats-why/pool/cli.mjs search 咖啡 --all
node tools/video/so-thats-why/pool/cli.mjs theme G03
node --test tools/video/so-thats-why/pool/pool.test.mjs tools/video/so-thats-why/catalog.test.mjs
```

- `index` 寫入忽略版控的 `.cache/pool.sqlite`，相同快照再次匯入寫入 0 筆。交易中斷時保留上一版；問題、來源修訂和原 ID 保留歷史。
- `search` 預設只查入選題，`--all` 可含未入選／暫緩紀錄；`show` 可按原 ID 找回合併主題。歷史查詢會明標是否仍在當期索引。
- 搜尋頁可找合併原題的字詞；CLI 以核心題名、研究目標、範圍為主要索引，已知原 ID 使用 `show`。
- 新批次先放 `batches/*.json`，執行 `preview`，再編輯 `dedup-decisions.json` 與 `selection.json`。不得僅執行生成就升格為已審稿。
- 重新審閱後跑 `build`、`check`、`index`。來源包、處置或程式變動會使舊輸出／舊索引失效，不能靜默沿用。
- 解除誤合併時修改處置、重新審閱選入數量再重建，原始批次與修訂仍在，不需重新編造題號。

`pool.json` 是可重建的資料快照，`manifest.json` 保存輸入與輸出雜湊；`selection.json` 明列本輪 1,000 個主題 ID 和 46 個候補。驗證證據見 [VALIDATION.md](VALIDATION.md)。

## 來源與使用界線

《十萬個為什麼》作為從生活追問機制的方向；這批沒有複製某一版本的目錄或整本問答。新題以 NASA、NOAA、USGS、ESA、科學教材及 IETF／Unicode 等公開原始資料研究，保留原創提問與短摘要，未搬入全文、插圖或實驗圖表。

連結存在不代表支持影片每一條主張，公開可讀也不等於圖文可商用。OpenStax 現行授權須依個別版本與頁面核對，本輪沒有把它概括當作可直接搬用的 CC BY 素材。生成插畫只能幫助解說，不能冒充研究證據。

## 後續擴到十萬筆

先維持這 1,000 筆作基準，再分小批累積到 10,000，最後才驗證 100,000 以上。下一階段要補來源更新追蹤、語意檢索、編輯採用回饋及實際規模測試。現在的精確索引／交易續跑已驗證；**十萬筆的效能、語意去重召回率與成片命中率尚未量測**，不宣稱已達標。

每批都同時報不同核心數、來源缺口、誤合／漏合、能轉 treatment 的組合與實際成本。沒有新理解的變體不加數量；本輪沒有採購付費媒體、修改正式資料庫、發布影片或啟動持續擴庫。
