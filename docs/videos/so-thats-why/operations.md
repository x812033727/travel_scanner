# 原來如此事務所：每日工作流

每天發 1 支長片、2 支 Shorts。一集從開工到公開至少要 4 天，所以任何一天都同時有 4 集在不同階段。

## 一集的時間線

| 相對公開日 | 誰 | 做什麼 |
| --- | --- | --- |
| D−4 | 代理 | 從 `episodes.json` 生成 brief；查 `facts_to_verify` 與所有數字，寫 `## 來源`；查不到就改題目 |
| D−3 | 代理 | 劇本與分鏡（每鏡的插圖提示詞、運鏡、卡片場景）；查核模型與聽眾審稿 |
| D−3 | 站主 | 看劇本（可帶備註退回） |
| D−2 | 工具 | 旁白 → 關鍵影格（judge 分數不過就重做）→ 合成長片 → 五語字幕 → 切兩支 Shorts |
| D−2 | 工具 | 站主勾選的語言做配音 |
| D−1 | 站主 | 看長片與兩支 Shorts；上傳到 Studio（私人），上傳配音音軌，排程公開時間 |
| D 20:00 | YouTube | 長片公開 |
| D+1 12:00 | YouTube | Shorts 1 公開，說明欄連回長片 |
| D+2 18:00 | YouTube | Shorts 2 公開 |
| D+7 | 代理 | 把 7 日數據（從 Studio 匯出）記到該集，缺值寫「未取得」 |

## 每天的站主清單

1. 審一份劇本（D−3 的那集）。
2. 看一支長片＋兩支 Shorts（D−1 的那集），上傳、上配音、排程。
3. 有空時看前一天長片的留言，把好問題加進題庫。

## 庫存規則

- 開播前做好 14 集。
- 庫存（已完成、未公開）少於 7 集：改成隔日更，直到回到 14 集。
- 任一集查核沒過：換 `schedule.csv` 下一集上，不趕工。

## 發布表

`schedule.csv` 是提案日期（D1 暫定 2026-11-02，所有列 `PROPOSED_NOT_SCHEDULED`）。首集真的公開那天，以那天為 D1 重排所有日期；每支公開後填 `actual_video_id` 與 `actual_published_at`。

順序：第一週是最強的七題（B08、S01、T01、A08、B06、S09、T05），之後照 S → T → A → B 輪替，同一主軸不連續兩天。
