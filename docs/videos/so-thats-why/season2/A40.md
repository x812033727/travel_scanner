# A40 網址為什麼常有 www？一定要打嗎？

文字製作包；作者 `write_t26`，製作查核日期2026-10-01（Asia/Taipei）。審稿狀態以 [獨立審稿](reviews/batch05/A40.md) 與同名 JSON 雜湊收據為準。以下是六章480秒製作企劃，尚非完整八分鐘逐字稿；兩支Shorts的35–55秒是估計。未生成音訊、圖片或成片，未匯入、核准、排程或公開。

本集區分「全球資訊網的名稱」與「主機名稱中的 www 標籤」。www 是網頁服務常見的命名慣例，不是URL必要前綴；能否刪去，取決於站方對不同名稱的解析與服務安排。以CERN第一網站作具體反例，不把歷史個案推成所有網站的操作保證。

## 後台發起用

故事前提：

```text
網址為什麼常有www？一定要打嗎？
以空白網址卡開場，將完整https網址拆成scheme、主機名稱與路徑。www在主機名稱裡，是網頁服務常用的標籤，不是所有URL的必填前綴。RFC1912在1996年就以www作Web server命名例子，但這不證明誰發明或首次使用；RFC1034不強制選這個標籤。
用www.example.com與example.com比較：兩個不同名稱，可由站方安排到同一網站或轉到其中一個；解析與伺服器必須有相應設定，不是刪三個字母就必定連得上，不代表兩台實體機器。DNS提供名稱資料，HTTP轉址是伺服器回應，兩者不要混講。MDN只作技術條件來源，不是全網兩種都可用的普查。
再講CERN第一網站：info.cern.ch介紹全球資訊網計畫，主機名稱沒有www。CERN記錄2013年啟動重建計畫，今日能讀到相關頁面，不代表原網站從誕生從未中斷。全球資訊網名稱和主機標籤要分開。六章480秒企劃，結尾回答：www不是網址必填前綴，但對某個網站能否省略，要看站方提供的正式地址與設定。本片沒有瀏覽器或DNS實測，不教改DNS、Cookie或SEO操作。
```

## 不做事項與下一關

- 不稱www為URL必要前綴、傳輸協定或網際網路本身；不把Web名稱與主機標籤混用。
- 不說現在多數／所有網站兩種地址都可用，不保證隨意刪www；不把兩個名稱說成必有兩台實體電腦或DNS會自動轉址。
- 不從1996RFC例子推造www標籤發明者／首次使用年，不將CERN第一網站推成所有早期網站的命名規則。
- 不宣稱第一網站原頁從誕生一直不中斷；保留2013重建計畫與今日讀取的區別。不把路徑WWW當主機www。
- 不講CNAME、apex、ALIAS／flattening、Cookie、SEO排名保證或DNS改法，不生成可執行設定與假實測成功畫面。
