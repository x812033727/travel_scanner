# 原來如此事務所：播放清單與 Shorts 導流

2026-09-28 起草。第一季 100 集（[`episodes.json`](episodes.json)）分成 12 份播放清單，目的是讓看完一支的人直接接下一支。路線圖第 21–60 集要「找出能連看的題組」（[README](README.md)），這份是起點：第 20 集後依 Studio 的「播放清單連看數」調整，改動寫回這份。

## 規則

- 每個 id 至少在一份清單、最多兩份。檢查表的第一欄是**主清單**：結束畫面、Shorts 置頂留言都指向它。
- 清單內的順序是發布順序（`schedule.csv` 的 D 值），新集數加在最後，觀眾照順序看不會跳到還沒發的集。
- 清單只放已公開的影片；還沒發布的 id 在該集公開當天由站主加入。清單在第一支影片公開時建立，先公開、有 1 集就建。
- 清單標題與說明用五語：Studio 清單的「翻譯」填 en、ja、ko、zh-CN（下表）。說明第一行是下表的一句話，第二行固定「每集一個為什麼，看完就知道原來如此。」
- 清單標題不放系列名（清單頁已經顯示頻道名），也不放 emoji。

## Shorts 導流設定

每集的兩支 Shorts（[README 的 Shorts 一節](README.md#shorts)）都要把人送回同一集長片。YouTube 可用的路徑與限制：

| 路徑 | 在哪設 | 做法 | 備註 |
| --- | --- | --- | --- |
| 相關影片（Related video） | Studio → 該支 Shorts → 詳細資料 → 相關影片 | 選**同一集長片** | Shorts 播放頁上唯一能點的導流連結。只能在 Studio 設、要頻道有進階功能，Data API 沒有這個欄位（[`../SHORTS.md`](../SHORTS.md)）。長片要先是公開或不公開 |
| 說明欄第一行 | 上架包自動寫入 | 「完整版：https://youtu.be/…」 | 工具已處理（長片有 id 才有）。Shorts 說明與留言裡的連結目前不可點擊（YouTube 2023 年起的防垃圾措施，上架前再到 YouTube 說明中心確認），所以它是備援，不是主要路徑 |
| 置頂留言 | Shorts 公開後由站主留言並置頂 | 下方範本 | 告訴觀眾去哪裡點，並丟一個問題引留言 |
| 畫面每張卡片 | 工具已做 | 底下「完整版在長片 ▶」（`cut:sothatswhy` 主題） | 口頭提示要和相關影片的位置一致 |

**Shorts 本身不能設結束畫面**，所以結束畫面只設在長片上。

### 長片的結束畫面（最後 20 秒）

片尾 20 秒（README「一集長什麼樣」）剛好是 YouTube 結束畫面的上限。構圖：左半留給答案卡與蓋章，右半與下緣空出來放元素，旁白在元素出現後才說「下一集……」。

| 元素 | 設定 | 位置（1920×1080） | 出現時間 |
| --- | --- | --- | --- |
| 影片 | 指定影片：`schedule.csv` 的下一集（旁白預告的那一集）。下一集還沒公開時，改成「最新上傳」 | 右上，大格 | 最後 20 秒 |
| 播放清單 | 本集的**主清單**（檢查表第一欄） | 右下，大格 | 最後 20 秒 |
| 訂閱 | 頻道頭像訂閱鈕 | 左下，答案卡下方 | 最後 15 秒 |
| （選用）影片 | 「最適合觀眾的影片」 | 只在沒有下一集時補 | — |

- 最多 4 個元素，這裡用 3 個；不放連結元素（要 YPP 資格，也會把人帶離 YouTube）。
- 同一集的兩支 Shorts 公開前，長片的結束畫面要先設好：Shorts 導來的觀眾看完長片，才會被送進清單。
- 下一集公開當天回頭把前一集的「最新上傳」改成指定影片（建議寫進 [`operations.md`](operations.md) 的每日工作流）。
