# X09 BlackBerry｜成片與發布交接

**交付級別：離線前製。** 這個資料夾沒有聲音、MiniMax 插畫、合成影片或已上架網址；`youtube.video_id` 必須維持 `null`。審核合格只能表示稿件可進下一段製作，不能說本集「已完成影片」。

1. 鎖 `video.json`、`shorts.json` 的 SHA，確認逐句來源審查和兩位獨立盲讀綁**相同**版本；稿件任何修改都重編重審。`lint`、文件測試和任務檢查需通過。
2. 在正式工人的固定工作區執行乾跑、預算核對和專集發音字典讀回。TTS 後逐句聽、量 30–60 秒濃縮開場與**扣除首段、三句 CTA、片頭片尾**後的 ≥8 分鐘實質正文；若不足，補的是經來源審核的事件與因果，重做受影響的審查。
3. 生成、評審並人工複查圖像；以原生文字卡呈現財報數字，保持插圖占比 ≥70% 且最多連續三卡。合成 Sulafat 聲音、正文音樂，繁中 CC 可開關、不燒錄；做逐幀、音量、畫面語意與字幕同步 QA。兩支 Shorts 必須沿用主片語音及素材，剪後實測各 25–55 秒。
4. 取得頻道**選定的 5 秒片頭、21 秒 v4 片尾**工作檔：片頭安在 30–60 秒濃縮開場之後，三句結語後接片尾。若做本機概念試看片，可用**明確標示的替代卡**並附雜湊與來源；不得把替代卡稱正式動畫。
5. 正式成片經站主與工具 QA 通過後，繁中標題、說明、來源直接網址、縮圖與 CC 一起進上架包。兩支 Shorts 先取得真實長片網址，再在 Shorts 說明與 YouTube 相關影片功能填**真實可點的長片連結**。正式長片片尾在 YouTube Studio 裝實際可點的訂閱、推薦影片元素；將 Studio 畫面／清單與每個真實 URL 回填交接。沒有真實 ID 時不要造 `youtu.be` 或 `youtube.com/watch` 網址。
6. 發布後再核對長片、兩 Shorts 的公開播放、來源網址、CC、片尾點擊元素與 US$25 整集 ledger；依站主規則辦理可選語言。對使用者回報的是可驗證的 URL 與檔案雜湊，不以 PR 取代影片。

發佈文案在 [video.json](video.json) 的 `youtube.description`，SEC 原始連結已逐條直接列出；[shorts.json](shorts.json) 的兩支說明也各有直接來源連結。尚缺的正式品牌動畫、YouTube Studio 接入與任何媒體階段保留為後續工作，不能讓此 PR 暗示已上架。
