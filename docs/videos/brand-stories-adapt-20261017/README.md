## 他的做法（從標題、說明欄、長度歸納）

- **標題**：一個反常問題，常帶誇張動詞（摧毀、統治、死活不用）。
- **結構**：說明欄明寫「上半集／下半集」：上半是創辦人與起家的傳記，下半是高潮與現在。長度 11–20 分鐘，Seiko 那支從 1881 年講到 Spring Drive。
- **結尾**：一句情感或哲理（「功能不再稀缺，人願意為什麼付錢」「忒修斯之船」），再問一個留言題。
- **畫面**：卡通插畫約每 9 秒一張，燒錄字幕。

## 我們贏在哪

逐支的對照寫在每份 Treatment 的〈對照參考影片〉。五支共同的三件事：

1. **一條主線、一個問題**：標題問什麼，第一章就開始推進那件事，與它無關的年代整段砍掉。他用傳記從頭講到尾，我們從一個具體場景開場、照因果講，每 60–90 秒留一個後面會回收的問題，約 10 分鐘講完（Seiko 他講 20 分鐘）。
2. **他沒有的轉折**：每支都找到一個他沒講、有一手來源的轉折，多數是台灣觀眾的切身角度：

   | 集 | 他沒有的轉折 |
   | --- | --- |
   | B25 Seiko | 瑞士其實先做出石英錶（Beta 21 只晚 Astron 不到四個月上市）；學者與評論者認為壓垮瑞士的主因是瑞郎大漲與被法規凍住的產業，石英只是加重；最後救瑞士的 Swatch 也是石英錶。 |
   | A41 米其林 | 他當尾巴帶過的商業模式成為主線：錢一百年換了三種人付（輪胎公司、讀者、觀光單位）；台灣 2018 年起由觀光局簽約、首年投入上千萬元，之後擴到六個縣市。 |
   | A42 A4 紙 | 台灣考卷的 B4、筆記本的 B5 是日本 JIS 的 B，比 ISO 的 B 大；1929 年日本為了不浪費印刷廠手上的四六判紙，另訂了一套 B。 |
   | C21 杜比 | 用 2025 財年年報一手數字講授權生意（授權占營收約 93%）；1996 年 FCC 把杜比 AC-3 寫進美國數位電視標準；錢正從電視移到手機。 |
   | B26 哆啦A夢 | 台灣「小叮噹」是 1976 年底起的未授權版，1992 年著作權法修正後退場，1997 年改名「哆啦A夢」；作者過世後新故事由藤子プロ、助手、編輯與導演的製作體制接手。 |

3. **查核比他嚴**：他的說明欄裡至少有這些說法被我們的查核修正或改成有歸屬的說法：Seiko 一手摧毀瑞士（學者不同意）、瑞士從業「近 9 萬人」只是兩組數字之一；庫柏力克讓杜比立體聲成名（《發條橘子》發行拷貝仍是單聲道，第一部杜比立體聲是 1976 年的《星夢淚痕》）、杜比「不造硬體」（2025 年仍有 7% 收入來自設備與服務）、Ray Dolby「16 歲參與發明錄影機」（16 歲進 Ampex，做錄影機是之後的事）；Lichtenberg「發現」根號 2 比例（他是在信裡說明好處，當時已有這種紙）；哆啦A夢像「開源系統」（新故事靠的是授權公司與製作委員會）。

**觀看次數是目標，不是承諾。** 題目已被他驗證過有人要看；我們能控制的是標題與縮圖的問題更準、開場更快進故事、畫面更新更密、沒有錯，這些都要等成片與上架後的 CTR、平均觀看時間才知道效果。

## 規格與檔案

規格照[品牌故事新版](../brand-stories-five-20261014/README.md)：作品 `kind: "story"`、`format: drama`、MiniMax `image-01`、`look: {"preset":"cute-mystery"}`、旁白正文目標約 10 分鐘（至少 8 分鐘）、台灣口音單人旁白、繁中 CC、首章後 5 秒片頭、21 秒片尾與 Studio 可點的結束畫面。本包是獨立的五集作品 `brand-stories-adapt`，不動既有 100 題的排程與審稿。

| 檔案 | 內容 |
| --- | --- |
| `<ID>-*.md` | 給站主看的 Treatment：對照參考影片、觀眾與包裝、一條主線、開場濃縮旁白草稿、六章預算 |
| `episodes/<ID>.json` | 匯入用的故事列（六章 `beats`、必查事實、來源、畫面禁忌、撰稿注意事項） |
| `episodes/reviews/<ID>.json` | 另一個代理逐來源查核的紀錄，綁故事內容的雜湊；故事改一個字就要重查 |
| `series.json` | 作品列 |
| `build.mjs` | 從五份故事與查核編出 `stories.json`；`--draft` 只做結構檢查 |
| `stories.json` | 產生的匯入檔，不要手改 |

```bash
node docs/videos/brand-stories-adapt-20261017/build.mjs           # 重新編出 stories.json
node docs/videos/brand-stories-adapt-20261017/build.mjs --draft   # 查核前只檢查結構
```

## 製作前要站主決定的事

1. **要不要開拍、先做哪一支。** [A01／B18 新版試作](../brand-stories-pilot-v2-20261015/README.md)與[已選的五支](../brand-stories-five-20261014/README.md)都還沒有成片；這五支要插隊到它們前面，還是排在後面。
2. **預算。** 每支照新版品牌故事的 US$25 整片上限估；匯入、工人與付費生成都要在主機唯讀試跑、核對帳本與 MiniMax 餘額後，由站主一次核准。
3. **上架包裝。** 標題三案與縮圖假設在各 Treatment；最後由站主在成片後選定。

匯入照新版品牌故事的做法：先 `python -m app.cli video-story-import --series brand-stories-adapt --limit 1 < stories.json` 唯讀試跑，確認只建第一列、沒有 slug 衝突，才以完全相同的參數加 `--apply`。工人產出的逐字稿仍要逐章查核、聽眾審稿與說故事關卡；本包的查核只核准企劃裡的事實，不核准之後的逐字稿。

- **B26 不能畫任何藤子角色**，連剪影、藍色圓形機器貓、鈴鐺、口袋、竹蜻蜓、任意門都不行；系列畫風的負面提示本來就擋受版權保護的角色。畫面用書桌、原稿紙、無字書背、台灣租書店、電視的光與人物背影。
