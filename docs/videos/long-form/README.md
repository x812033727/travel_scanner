# 知識科普與非虛構故事：長片時長新版

依站主確認的範圍，2026-10-02修訂原來如此事務所第一、二、三季、品牌故事與AI名詞的長片時長。所有這些長片的**實際正文及成片都至少8分鐘（480秒）**；原來較短的企劃改用10分鐘（600秒）製作目標，留出合成語速與剪輯餘裕。品牌故事保留13分鐘，AI名詞保留9–11分鐘成片區間。Shorts仍為原短片規格。

**後續製作以[新版企劃資料](plans.json)及[時長規格](policy.json)為準。** 舊查核包保留原稿與原SHA256，其中的8分鐘／480秒大綱是歷史版本；不得再直接照舊備註發起長片。新版從原檔產生有效後台輸入與章節預算，另外核對原檔雜湊，不改舊查核收據或宣稱舊收據審過新版完整稿。

| 類別 | 項目 | 製作目標 | 原有長度與進度 |
| --- | ---: | --- | --- |
| 第一季 | 100 | 10分鐘 | 已查核的大綱；新版後台備註覆蓋原8分鐘要求 |
| 第二季 | 92 | 10分鐘、六章合計600秒 | 92個採用包；8個同核心判重題仍不採用 |
| 第三季 | 100 | 10分鐘 | 已查核候選題，完整製作大綱仍須逐集編寫 |
| 品牌故事 | 100 | 保留13分鐘 | 保留原12–15分鐘規格及逐故事查核 |
| AI名詞 | 81 | 10分鐘 | 保留9–11分鐘區間；其中1項已覆蓋，免重做 |

合計473個企劃項目，包括1個已覆蓋名詞；這不是473支新成片、匯入或排程紀錄。新版不變更原有題目、查核事實、Shorts、發布表、核准或正式站設定。

## 怎麼使用

先核對所有來源與新版資料：

```bash
node tools/video/long-form/cli.mjs check
```

查看一個企劃的完整時長修訂與來源，例如第二季B26：

```bash
node tools/video/long-form/cli.mjs plan --catalog season2 --id B26
```

第一、二季發起時，使用新版可貼用輸入（包含`target_minutes: 10`、原前提與修訂備註），不要複製舊包的8分鐘要求：

```bash
node tools/video/long-form/cli.mjs inputs --catalog season1 --id B08
node tools/video/long-form/cli.mjs inputs --catalog season2 --id B26
```

這些指令只讀本機檔案並印出資料，不會送出請求或產片。第三季仍須先完成製作大綱；品牌故事走原故事匯入流程；AI名詞走原逐集流程，三者都用`plan`查新版長度，不冒充可直接送出的單集請求。`ai-agent`保留`covered`，`inputs`會拒絕替它重排一支片。

第二季新版的`proposed_chapters`是600秒**大綱預算**；保留原六章內容、主張界線及主場景，只加長中間四章的解釋。撰寫完整逐字稿時，沿既有已查核內容補具體案例、因果步驟、比較及適用界線，新的事實仍須另行查核。不得靠停頓、重複旁白、拉慢語速或延長片頭片尾湊秒數。每5–8秒仍須變換原創畫面狀態；六張圖不等於完成十分鐘畫面。

## 成片如何驗收

後台扁平插畫解說（`flat-explainer`單集）支援8–20分鐘、預設10分鐘；普通漫劇維持原1–8分鐘限制。既有較短解說可修訂長度，並仍可暫停或編輯標題。

`node tools/video/cli.mjs qa --slug <slug>`在原11項QA的`assemble`項重新驗證相關長片：當前旁白正文時間軸至少14,400個30fps影格（480秒），實際成片影格也至少14,400，且稿件／旁白雜湊與正文、片頭片尾、成片影格數都必須一致。479.966秒會退回，片頭片尾不能補足正文不足；舊`checks.json`曾通過也不能略過新門檻。Shorts、普通漫劇與合集各用原規格。

企劃秒數與字數估算不代表實際合成長度。旁白、圖片、完整逐字稿及成片仍照原製作／查核／審聽流程完成；改稿須重新綁定核准。這次沒有生成或修改媒體，沒有量測正式站成片，也沒有匯入、啟用工人、核准、排程或發布。

## 重建與覆核

```bash
node tools/video/long-form/cli.mjs build
node tools/video/long-form/cli.mjs check
node --test tools/video/long-form/plans.test.mjs tools/video/long-form/review.test.mjs tools/video/core/duration.test.mjs tools/video/qa/duration.test.mjs
```

`build`只重建`plans.json`。來源變動或新版資料少一集、目標下降、章節預算不符、已覆蓋狀態被抹除時，`check`會失敗；重建後須重新覆核，不沿用本次修訂的審稿雜湊。

[本次獨立時長覆核](review.md)及[雜湊收據](review.json)只確認本次企劃修訂與產線規則；不替代原事實查核或實際媒體驗收。`check`與逐集輸出也會核對這份獨立報告及全部受審檔案SHA，任何後續改動都須重新覆核才能使用。
