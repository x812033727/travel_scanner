站主 2026-10-26 問：「幫我評估 YT 的說書人系列影片，可能說三國系列故事，或是國外的格林童話，或是國外的其他故事系列，
這樣會有市場嗎？還有可以做哪些題材？」接著追加「也加入外星人系列與靈異的系列吧」「還有其他系列嗎？或是有哪些點閱率會比較高的？」，
看完評估後說「好，照計畫開始做」。這份是那次評估量到的數字；做成什麼決定寫在
[`../history-curiosity/README.md`](../history-curiosity/README.md) §F 軸與 G 軸。

**三句話**：

## 2. 怎麼讀這些數字

- 這是**搜尋結果**的觀看數，不是隨機抽樣：YouTube 搜尋會把熱門的片排前面，所以中位數比整個類別的真實中位數高。它適合拿來**比較類別之間**，不適合拿來估一支新片會有幾次觀看。
- 長尾很重：前 25% 的門檻是中位數的 3 倍（童話神話）到 40 多倍（騙局），少數百萬片把平均拉得很高，所以只看中位數與前 25%，不看平均。
- **粗體的類別，結果被關鍵字左右**：老刑案第一輪用「開膛手傑克」「十二宮殺手」抓到很多小頻道的案件解說，第二輪用「未解之謎 懸案」抓到大頻道；神秘生物、中國志怪、騙局也一樣。這幾類的排名信心低。
- 類別之間會互相滲：靈異的前五名裡有一支是韓國的真實命案，災難的前五名裡有一支是馬臉姐的 2027 預言。沒有逐支重新分類。
- 沒有量時事與政治（站主定不碰爭議）。10-25 量到 cheap 最高的一支是大罷免（270 萬），這一類應該在最前面，但我們不做。
- 我們自己的頻道還太小（奇聞檔案局 14 支約 44 次觀看），差距主要在觸及與包裝（[`../channel-review-20261025-story-series/README.md`](../channel-review-20261025-story-series/README.md)），題材選對只是條件之一。

## 3. 每一類量到的特徵

- **童話、神話原版**：大爆款是老高的日本神話（927 萬）、希臘神話「27 分鐘講完十二泰坦與眾神」（816 萬）、北歐神話（669 萬）；格林原版類（「原版《格林童話》堪比變態案件？」「格林童話中的這 14 個暗黑情節」）多在 8–25 萬。題目長青、可以成套看，**一集講完一個故事或一個神話體系**是共通形狀。
- **靈異與怪談**：前幾名是「真實事件」「驅邪」「在地怪談」（台中、香港新娘潭），125–186 萬。中位與前 25% 門檻都高，百萬片少：穩，但不容易爆；在地（台灣、香港）的題目表現好。
- **外星與 UFO**：中文由老高主導（宇宙文明、費米悖論、51 區、納斯卡線，600–870 萬）。我們 U 軸的題目夠，缺的是說書版（[`../history-curiosity/README.md`](../history-curiosity/README.md) §U 軸說書版）。
- **三國**：人物一生（正史上的呂布、諸葛亮、劉備、馬超）與「一口氣看完」兩種形狀都有百萬片；兩輪結果幾乎一樣。
- **災難與生還**：中文前幾名是鐵達尼號的「恐怖真相」（315 萬）、九一一最後 100 分鐘（227 萬）、巴西戈亞尼亞核事故（150 萬）。題目本身強，但很多涉及近代死者，我們的守則會擋掉一大半。
- **品牌故事**：搜尋中位只有 2,421，跟 10-25 量到黑猫研究院的頻道中位 3.75 萬對照，代表這一類靠頻道本身的訂閱觀眾，不太靠搜尋。

## 4. 量法

```bash
pip install yt-dlp     # 2026.10.21
cd docs/videos/storyteller-genres-20261026
PYTHONUTF8=1 python3 measure.py round-a.json      # 第一輪關鍵字
PYTHONUTF8=1 python3 measure_b.py round-b.json    # 第二輪關鍵字
python3 summarize.py round-a.json round-b.json results.json
```

- 每組關鍵字 `ytsearch40:`，`--flat-playlist` 拿 id、觀看、長度、頻道、標題；長度 < 240 秒丟掉（Shorts 的觀看數是另一個尺度）。
- 過濾（`results.json` 的 `filters`）：中文標題（至少 6 個漢字、沒有假名與韓文）；標題有主題曲、MV、歌詞、預告、翻唱，或頻道名有唱片、Music、電影、華納兄弟的丟掉。第一版沒有這一步，「鐵達尼號 最後」抓到伍佰〈挪威的森林〉（1 億）與〈My Heart Will Go On〉，災難類被灌高；加了之後排序沒變，數字是加了之後的。
- 兩輪用影片 id 合併去重再算一次中位數（表的「中位觀看」），兩輪各自的在 `round_a`、`round_b`；`union_without_laogao` 是拿掉頻道名含「老高」的片再算。
- 原始清單（兩輪共 3,109 列）沒有進 repo；每輪幾分鐘就跑完。
