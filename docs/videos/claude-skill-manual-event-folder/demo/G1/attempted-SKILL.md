# 報名表檢查

每次新報名表進來（例如 `報名表.csv`、`報名表_第二批.csv`），照下面的方式處理。做法是從第一批的產出歸納來的，沿用即可，不要自創新格式。

## 開始前先讀

1. `活動說明.md`：名額、時程、備註規則（目前是「備註寫取消的不寄確認信」）。規則若有更新，以它為準。
2. `輸出/` 底下三個現有檔案：確認信名單.csv、要補資料.csv、處理日誌.md。新的一批是**接在後面**，不是重做。
3. 日誌裡已經有哪幾批，避免同一份報名表處理兩次。若這份已在日誌裡，先問使用者要不要重跑。

只動 `輸出/` 底下這三個檔案。報名表原檔、簡報、講者介紹等其他檔案一律不改。

## 報名表欄位

`填表時間,姓名,Email,部門,飲食需求,備註`

## 判斷順序

對新報名表的每一筆，依序判斷：

### 1. 先整理格式
- 姓名、Email 去掉前後空白；Email 轉小寫。
- 部門統一成「○○部」寫法：行銷／Marketing／mkt → 行銷部；業務 → 業務部；研發／R&D → 研發部；人資 → 人資部；財務 → 財務部。遇到沒見過的寫法，不要硬猜，照原樣寫入並在日誌提醒。

### 2. 不處理的（不進任何名單）
- **測試資料**：姓名或備註帶「測試」、「請刪除」之類（例如姓名「測試」、`test@example.com`）。
- **取消**：備註寫「取消」或表達不來了（例如「不能去了，請幫我取消」）。同一個人如果取消在後，整個人都不寄；已經在確認信名單裡的，從名單移除，並在日誌註明。

### 3. 合併重複報名
- 同一個 Email 視為同一人，**以填表時間最晚的一筆為準**（例如陳怡君先填「無」、後來改「素食」，就用「素食」）。
- 其中一筆沒有 Email、另一筆補上（備註常寫「補上 email」）的，同名同部門視為同一人，合併成一筆。
- **同名但 Email 不同、部門也不同**（例如兩個王志明）視為不同人，各自保留，並在日誌提一句，請使用者自己確認是不是真的兩個人。
- 跟 `輸出/` 裡已有的人重複（同 Email）：不重複新增，有更新內容才更新那一列，並記在日誌。

### 4. 分流
- **缺資料**：沒有 Email，或 Email 格式不對（例如 `zihching.hung@example` 缺網域尾巴）→ 加進 `要補資料.csv`。
- 其他 → 加進 `確認信名單.csv`。
- 之前在 `要補資料.csv` 的人，這次補齊了 → 移到確認信名單，並從要補資料刪掉。
- 飲食需求空白**不算缺資料**，照樣進確認信名單，欄位留空。

## 輸出格式

**輸出/確認信名單.csv**：`姓名,Email,部門,飲食需求`
- 新的人接在現有列後面，順序依各人「第一次有有效 Email 的那筆報名」的先後。

**輸出/要補資料.csv**：`姓名,原因`
- 原因用簡短固定說法：`沒有 Email`、`Email 格式不對`。

兩個檔案都沿用現有檔案的編碼與換行方式，不要改成別的。

## 處理日誌

在 `輸出/處理日誌.md` **結尾追加**一段，不改動前面已有的批次：

```
## 第N批（檔名）
- 寄信名單 X 人，要補資料 Y 人，不寄 Z 筆（取消 a、測試 b）。
- 素食類 ○ 位、海鮮過敏 ○ 位。
```

- 「寄信名單／要補資料」寫**這一批新增的人數**，並另加一行累計：`目前累計：寄信名單 X 人、要補資料 Y 人。`
- 素食類（素食、蛋奶素、全素等）和過敏人數，算「這批所有沒被取消、不是測試的人」，包含還缺 Email 的，因為備餐要用。其他忌口（不吃牛、不吃辣等）若有也一併列出。
- 再依情況追加「需要人工確認」的條目，例如：
  - 同名但 Email 不同的人
  - 備註裡有需要回覆的問題（例如有人問能不能改線上參加）。這種**不算取消**，照常放進名單，只在日誌提出來。
  - 沒見過的部門寫法
  - 累計寄信名單加要補資料已超過活動名額（30 人，以活動說明.md 為準）

## 做完之後

用幾行話向使用者回報：這批新增幾人、要補幾人、不寄幾筆，以及「需要人工確認」的項目。不要自己寄信，也不要自己去聯絡要補資料的人。
