# 第 54 篇：Gmail 到 Docs／Sheets 交接流程實測

[返回實測總表](../README.md) · [作者交付目錄](../../../README.md)

2026-09-15 在 Windows Chrome、既有 Google Pro 個人帳號完成合成資料流程：Gmail 側邊欄整理五封教材信件文字，建立 Google 文件與試算表，再於 Docs 修正佔位文字、接受修改、重開核對，並在 Sheets 操作篩選。四次 Gemini 生成、兩份雲端成品；Gemini API 呼叫 0、額外購買 0、額外花費 NT$0。

這是實際 Workspace 介面操作，但輸入是貼入的合成信件文字，沒有測試 Gmail 從真實收件匣擷取郵件。模型介面只顯示 Gemini，未提供可核對的後端版本。成品只供帳號本人存取；沒有更改分享設定或測試其他收件者帳號。

## 輸入與可重做步驟

來源是 [五封合成信](../../../examples/54/mail-samples.md)，包含日期尚未確認、數量由 10 改為 12，以及未指派負責人。原作者參考 CSV 僅供獨立比對，沒有上傳當成 Gemini 的答案。

1. 在 Gmail 搜尋本次專用標記，確認沒有結果，再開啟右上角「向 Gemini 提問」。貼入 [第一輪提示詞](prompt-gmail-v1.txt)，要求只根據貼上的五封信整理待辦、保留來源與未決事項。這一步沒有開啟任何真實郵件。
2. 檢查四筆待辦，核對兩個場地候選日、印刷稿的時區、樣品更正為 12 組、報名表負責人未知。[原始回答](gmail-v1.json) 中的「（留空）」是文字標記，不能當成真正空白欄位。
3. 貼入 [建立 Docs 的提示詞](prompt-gmail-doc.txt)，從 Gemini 回答開啟新文件，核對四筆待辦、兩個追問以及五份來源全文和時間。原始文件把報名表負責人顯示為灰色 `Person` 人員佔位晶片，問題保留於 [首版匯出](docs-v1-export.md)。
4. 在同一個 Gmail 側邊欄貼入 [建立 Sheets 的提示詞](prompt-gmail-sheet.txt)。開啟新試算表，檢查 A1:F5 表格與 A7 合成資料註記，確認 B5 是真正空白。
5. 在 Docs 自己的 Gemini 側邊欄貼入 [修正提示詞](prompt-docs-fix.txt)，限定把該佔位晶片換成純文字「尚未指派」。查看修改預覽，按「接受」，等候儲存後重新開啟文件。Gemini 回覆「已完成」時仍有接受／拒絕介面，因此不能只憑回覆認定已寫入。
6. 在 Sheets 的「狀態」篩選器取消「已確認」，保留「日期衝突」與「負責人待定」。確認顯示 4 筆中的 2 筆，再選取全部 3 個狀態、按確定並重載。重新複製 A1:F7 核對內容，B5 的值及公式列都須空白。

四個提示詞都可複製；重做時可替換專用測試標記與成品名稱，但保留來源文字及驗收條件，並記錄自己的日期與環境。再次執行會建立新的文件，不應把新結果覆寫到本輪原始證據。

## 故障練習與檢查器的界線

[candidate-normalized.csv](candidate-normalized.csv) 是 Codex 把 Gmail 首輪回答轉成作者檢查器欄位的衍生資料，明確把「（留空）」轉為空值；它不是模型的原始 CSV，也不是 Sheets 下載成品。轉換方式與結果見 [candidate-review.json](candidate-review.json)。

在這份衍生資料上套用原作者 `check_handoff.py`，四筆資料通過。另注入三個故障：把日期衝突改成已確認、替未知負責人填入名字、捏造來源引文；檢查器都拒絕。另一次故意把工作文字寫成「場地已確認改到九月二十一日」，並保留真實引用、單一期限與已確認狀態，語法檢查卻通過。

最後一例說明引用存在不等於推論成立：M4 只是可能改期，M5 仍待確認。[故障紀錄](fault-checks.json) 保留這個漏檢案例；AI 語意初查判定有問題，沒有把腳本成功當成人工核准。

## 擷取方式與限制

- 首版 Docs 透過瀏覽器匯出 Markdown，保存原始位元組及 [下載收據](docs-v1-export-receipt.json)。修正後三次匯出逾時；另一次原生下載未確認產生檔案，均不列為成功。
- 最終文件改用重新開啟後的可見編輯介面全選、複製文字；原文及 checksum 保存於 JSON。截圖曾逐段檢視，但未保存或公開，不能宣稱交付了截圖證據。
- 雲端成品的私人網址只在 git 忽略的本機暫存；追蹤檔使用網址雜湊。兩份成品皆觀察到 Only me，沒有測試對方收到連結後能否開啟。
- 未測試真實收件匣擷取、寄送信件、日曆事件、實體手機或其他帳號。沒有完成獨立人工語意核准、完整樣式比對及公開網站整合。
- 此次四輪生成只有既有 Pro 的網頁操作；沒有呼叫 Gemini API，沒有以訂閱推定 API 免費。
