# 第 51 篇：AI 初查，尚非人工評分

檢查者：Codex；2026-09-15。資料只來自本目錄二十份真實回答及凍結題庫。
未填 0–2 分，未計算 A/B 勝負；`human-review.csv` 保留獨立的 `capture_status=captured` 與 `review_status=pending`。

| 題目 | 觀察與交給人工核對的重點 |
| --- | --- |
| C01 | 兩版保留缺夾子與希望補寄。A 的日期沒有加「回覆日」標籤；B 明確標承諾回覆日，並把是否補寄列待確認。 |
| C02 | 兩版沒有捏造回覆日期。B 補列「是否有庫存」是待確認事項，不應誤讀為已知庫存資訊。 |
| C03 | A 把 09-18 放日期主欄，09-21 放待確認；B 在日期欄同列兩日並標衝突／未定。核對是否充分表達第二封未取代第一封。 |
| C04 | 兩版都保留尚未指派及 09-17 截止日。A 的「預計」與原文「討論」有措辭差別，可由人工判斷嚴重性。 |
| C05 | 兩版都列操作說明、不退貨、負責人與日期；「已取消退貨」可能被理解成作業已取消，原文只明確說客戶改變需求，應核對措辭。 |
| C06 | 兩版保留更正為兩枚及僅承諾回覆。A 在待確認列「是否已完成補寄」；B 明列「是否確定補寄」。兩版需求欄都使用「補寄」而原文沒有明示補寄要求，應核對推論是否過度。 |
| C07 | 兩版都沒有把「明天」換算為特定日期或承諾；負責人與寄信時間保留未知。 |
| C08 | 兩版都保留照片未收到及兩日期。B 明列條件式承諾；A 的日期欄用「回覆日」，須配合需求與待確認欄閱讀。畫面表格有儲存格內換行，raw 不是平面 CSV。 |
| C09 | 兩版都沒有保證免費換新。B 把客戶附註與手冊描述為「衝突」，可進一步檢查是否過度提升客戶指令的地位；A 較簡短。 |
| C10 | 兩版都分兩列，責任人、不同截止日與未完成狀態可對應。 |

這是單一帳號、單次每題樣本。未控制既有個人化，UI 只顯示 Flash；不能推廣成模型排行榜或宣稱改寫必定有效。時間戳是開始送出與擷取時間，不是精確推論延遲。

人工核對時逐列對照 `../../../examples/51/cases.csv` 與 `../../../examples/51/rubric.csv`，填四項分數及原文證據。原 `score.py` 的 `complete` 表示人工評分齊備，因此在目前階段不使用它宣告完成。待人工填妥後，才能轉成該工具支援的 `status=complete` 格式。
