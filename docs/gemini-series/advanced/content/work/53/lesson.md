活動預算工具看起來能按，不代表每筆金額都算對。本篇把人數、單價、場地費與備用金寫成明確需求，再用 Gemini Canvas 製作單頁工具。你會學到怎樣描述計算規則、用人工答案驗收、回報錯誤，以及把完整程式保存成可在電腦開啟的 HTML 檔。

## 第一階段：先決定怎麼算，才要求畫面

本工具只計四個輸入：參加人數、每人單價、場地費與備用金百分比。基本費用等於人數乘單價，再加場地費；備用金以基本費用計算，先四捨五入到分，再加回總額。平均每人等於總額除人數，另外四捨五入到分，不反過來改變總額。

人數只接受一至一萬的整數；金額零至一千萬元，最多兩位小數；備用金零至百分之一百，最多兩位小數。空白不是零，負值不是折扣，科學記號與超出小數位數都要顯示可理解的錯誤。先把這些限制寫清楚，避免模型替你決定業務規則。

## 第二階段：在 Canvas 產生第一版

登入 Gemini，從提示區的新增功能入口選 Canvas，貼入需求並要求單一完整 HTML。請它把樣式與程式放在同一檔案，避免載入外部套件、儲存輸入或加入雲端資料庫。這樣你才能下載程式文字後，以同一組資料在本機核對。

```text 可複製提示詞：接在需求檔後
請做單一完整 HTML 的活動預算計算器，介面使用繁體中文。
依上述公式、輸入界線與四捨五入順序實作，不自行增加費用。
顯示基本費用、備用金、總額及平均每人；提供計算與重設。
修改任一欄位後清除舊結果，錯誤時不要顯示上一筆金額。
360 像素寬度採單欄，標籤可讀、按鈕可用鍵盤操作。
```

收到成果先檢查它對公式的理解，再看預覽。若理解就已經錯誤，例如把百分之十寫成乘十，先修需求解讀，不必急著調整顏色。保存這次提示詞與第一版完整程式，檔名可用 budget-v1.html，記錄畫面模型名稱與生成日期。

Canvas 的 Code 程式碼檢視與 Show Console 主控台可協助看錯誤；是否出現相同文字依介面為準。若需要保存檔案，複製完整 HTML 到文字編輯器，以 UTF-8 儲存為 .html，再用瀏覽器開啟。不要假設一定有「下載 HTML」按鈕，也不要把某段 JavaScript 存成完整網頁。

## 第三階段：核對正常與錯誤輸入

先依 B01、B02、B03 逐一輸入，核對四個輸出，不只看醒目的總額。以 B02 為例，總額偶然正確但備用金欄錯誤，也不算通過。把預期值、實際值、是否符合與檔案版本寫到同一份紀錄，避免後續改過程式卻仍沿用舊版測試結果。

接著清空人數、輸入零、小數人數、負單價、文字、過多小數與百分之一百零一。每次錯誤都應顯示原因，結果區不能留著上一組正確金額。改動任何欄位但未按計算時，也要提示重新計算；否則使用者容易把新輸入與舊答案當成同一筆。

最後按重設，確認四欄回到初始值、錯誤清除、結果不顯示。用 Tab 從人數移動至其他欄位及按鈕，按 Enter 應能計算。在手機寬度上下捲動確認標籤完整、按鈕不重疊、整頁沒有左右捲動；放大字體後也要能讀清楚金額與單位。

作者參考版使用整數「分」運算，避免十進位金額直接用浮點數相加產生細微誤差。你不需要先學完整數值程式設計，但應要求結果符合人工作業規則。完整可執行碼放在下載包，網站只把範例顯示成文字，不會直接執行文章內程式。

## 第四階段：帶著證據除錯與交付

若模型第一版沒有錯，也要做故障練習：在副本把備用金改成以人數乘單價計算，故意漏掉場地費，再跑 B01。此時會得到 9700 元，應被 9900 元的人工答案抓出。原版保留，故障副本另命名，避免下一次誤用。

回報錯誤時貼最小重現資料：「二十人、單價三百五、場地兩千、備用金百分之十，預期總額九千九百，實際九千七百」。要求只修備用金基礎，不改輸入範圍與版面。修好後重跑三組正常案例與錯誤輸入，因為一處修正也可能影響重設或小數處理。

交付資料包含最後版 HTML、需求、測試表、修正前後差異與已知限制。作者版本在 360 與 1440 像素測了三組正常案例、十種錯誤輸入，以及重設、鍵盤順序和水平溢出，共二十八筆觀察；測試期間沒有網路請求。這份紀錄只涵蓋本機參考程式，Canvas 生成與帳號操作仍需另留證據。

## 常見問題

### 畫面漂亮但金額不對，先改哪個？

先修公式與輸入驗證。保留一個能重現的錯誤案例，確認修正後數字符合需求，再調整配色與留白，避免版面變動掩蓋計算差異。

### 每人金額乘人數與總額差幾分是錯嗎？

可能是平均值的四捨五入。本篇把平均每人標成參考；若要真正分攤付款，需另寫尾差分配規則並增加測試，不能用這個平均欄直接收款。

### 可以直接公開 Canvas 分享連結嗎？

先確認分享內容與資料範圍。本篇以本機檔案交付；若新增登入、儲存或公開分享，需重新檢查資料行為。接著可用 [[54|會議信件交接流程]]，把活動決議與待辦一起整理。
