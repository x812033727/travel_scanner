本篇將檔案檢索、引用檢查、工具邊界與固定題庫組成可在本機使用的文件助手。完成後能輸入問題、閱讀答案、打開對應原文，並用二十題檢查成功、缺資料、惡意指示及無效輸入的處理方式。

## 開始前準備

先完成 [[81|只讀工具呼叫]]、[[83|File Search 索引管理]] 與 [[85|批次評測與結果追蹤]]。下載本篇或整批練習包，保留 86、lablib、requirements.txt 的相對位置。安裝在獨立 Python 虛擬環境，避免改動既有服務的相依版本。

本篇固定 Python 3.13.15、google-genai 2.23.0、FastAPI 0.141.1 與 Uvicorn 0.52.4，使用 Windows 本機測試。預設 author_fixture 是作者合成回應模式；它沒有金鑰也可操作，目的是先檢查介面與資料流，不代表 Gemini 已答對二十題。

文件是十份原創合成杯子規格，並附二十題 golden-cases.json。每份文件都有識別碼、版本、顯示名稱與全文。若之後改了規格，必須同時管理雲端索引與本機引用對照表；不能讓畫面顯示新版標籤，實際卻引用舊版文字。

## 第一階段：啟動並完成第一個可追查答案

在解壓後的練習包根目錄開啟終端機，明確使用作者模式啟動。服務只綁定本機位址，再用瀏覽器開啟顯示的網址。首頁上方模式標示應為作者測試資料；若顯示 live，先確認環境變數與正在執行的服務。

```powershell 本機啟動，不呼叫模型
$env:GEMINI_LAB_LIVE='0'
.venv/Scripts/python.exe -m uvicorn app:app --app-dir 86/document-service --host 127.0.0.1 --port 8765
```

輸入「S003 的容量是多少？」並按送出。預期作者回應是二百六十毫升，下面列出 S003 與 v1、來源檔名及引用片段。點來源連結會在同一分頁打開原文；核對容量後，使用瀏覽器返回助手。畫面有來源只表示可以追查，閱讀原文仍是必要步驟。

再問不存在的 S011。這次應顯示沒有此題證據，不會推算出下一個容量。作者模式只認識固定示範題型；自由改寫問題可能得到缺證據，這是本機測試模式的設計，不能把它當成真實模型語意理解能力。

| 畫面或檔案 | 應確認的事情 |
| --- | --- |
| 模式標示 | 明確區分作者測試與真實模型 |
| 答案與片段 | 具體數值能在對應原文找到 |
| 文件版本 | 本機對照表與目前索引一致 |
| 缺證據狀態 | 不補造來源、數值或可點連結 |

## 第二階段：設定真正檢索，保持金鑰在伺服器

真實模式需要可用帳號、金鑰、明確費用上限，以及第 83 篇已核對的練習索引。先把十份相同版本文件匯入，完成逐份索引與查詢驗證。GEMINI_STORE_NAME 填寫自己的 fileSearchStores 名稱，不使用別人的示例資源，也不把文字標題當作資源 ID。

範例 .env.example 只供閱讀，不會自動載入。金鑰設定在啟動 Python 的終端機環境；不要貼進網頁、app.js、題庫或版本控制。停止原作者模式服務後，再用同一啟動命令啟動新的程序，環境變更才會生效。

```powershell 具備索引與費用條件後設定
$env:GEMINI_STORE_NAME='fileSearchStores/請替換成自己的名稱'
$env:GEMINI_LAB_LIVE='1'
```

真實請求採 Interactions，且只啟用 File Search。它不混入 Google Search，也沒有寫入訂單或執行命令工具。回應解析器只接受目前文件清單中唯一相符的檔名，並核對引文確實存在於該份原文；舊檔名、假引文或同名多版本均不能通過這個引用檢查。

即使引文存在，仍可能與答案中的主張無關，所以狀態命名為 needs_claim_review，表示需要核對主張。不要把它改成「已驗證正確」後直接公開給客戶。需要公開資訊搜尋的應用，另依 [[82|搜尋來源與顯示要求]] 建立獨立流程。

## 第三階段：跑固定題庫並練習故障

另開終端機執行 evaluate.py。它先查健康狀態，預設只允許作者模式；若服務已切成真實模式，必須明確加入 --live 才會執行固定題庫。每題完成立即寫入評測檔，保留部分進度，不等全部成功才留下紀錄。

```powershell 對正在執行的作者模式做評測
.venv/Scripts/python.exe 86/document-service/evaluate.py --output service-fixture-evaluation.json
```

題庫包含十題有文件的問題、五題不存在的規格、三題試圖改變工具權限的指示，以及兩題無效輸入。程式檢查狀態、預期數值與文件識別碼；真實模型若換了說法，可能需要人工判讀，而不是直接修改標準答案配合輸出。

在網頁輸入要求刪除訂單或交出金鑰的文字，確認它不會執行寫入動作。合成文件 S010 也含有試圖改變規則的內容，這段文字是測試資料，不能成為工具授權。只讀訂單範例另有固定路由，回傳合成資料，模型沒有呼叫修改工具的權限。

故障測試另涵蓋空白問題、過長問題、不允許的欄位、跨來源請求與上游錯誤。上游失敗時顯示一般錯誤訊息，伺服器只記錄錯誤類型，不把例外原文、環境變數或金鑰送回瀏覽器。修正設定後手動重新提問，範例不自動連續重送。

> 本機題庫通過只能證明這組作者資料與程式行為符合預期。真實模型、實際索引、答案語意與帳單仍須另外測試；評測檔保留 mode，避免交接時混淆。

## 第四階段：整理交接與停止服務

交接資料包含 requirements.txt、十份原文、文件版本表、固定題庫、實際評測檔與啟動步驟。另記錄 SDK、模型、帳號條件、測試日期、失敗題目及仍待人工確認的主張。若只有作者模式結果，就明寫沒有呼叫真實模型，不附虛構的成本或延遲統計。

在桌面與手機寬度各試一次輸入、送出、來源連結與返回。長答案應在容器內換行，按鈕與狀態應看得見，整頁不應橫向溢出。本機路由用純文字呈現來源；回答與片段以 textContent 放進畫面，不讓模型文字變成可執行的網頁標籤。

使用完畢在終端機按 Ctrl+C 停止服務。真實練習建立的索引與原始上傳檔，依第 83 篇 ledger 執行清理並核對；若做過快取與批次實驗，也要分別處理相應帳本。停止網頁服務不會自動刪除雲端資源，也不代表帳單已結算。

這份服務供單人在本機學習，沒有多人登入、持久佇列與正式部署設定。若要擴充，先從現有題庫增加需求與失敗條件，再設計身分、用量控制與紀錄保存。成本比較可接著使用 [[84|快取實驗]]，逐項確認修改後是否仍能追查來源。

## 常見問題

### 沒有 API Key，可以完成這篇嗎？

可以完成作者模式的啟動、介面與二十題本機檢查；真實檢索與模型品質驗收仍未完成。

### 來源存在，為什麼畫面還要求核對主張？

引文存在只能證明文字來自某份文件，不能自動證明它支持整段答案。應逐項核對數值、版本與問題範圍。

### 改完環境變數，網頁仍顯示原模式怎麼辦？

先停止原程序，再從已設定環境的終端機啟動。不要同時留下多個不同模式的服務，造成驗證錯用網址。
