Gemini API 的費用取決於模型、輸入輸出、服務模式及使用的工具；速率限制則決定你的專案在一段時間內能送出多少工作。本篇教你找到真正對應的用量頁面、估算一次檔案處理成本、分類錯誤，並設計有限重試與停止條件，避免把每個失敗都當成多按一次就能解決。

## 開始前：先確認計費物件

先完成[[47|AI Studio 入門]]，記下金鑰所屬專案與模型識別字。Gemini 消費者方案的月費不等於 API 儲值或用量，CLI 也會因[[30|認證方式]]使用不同服務。你應在 AI Studio 的專案與用量頁核對，而不是從 Gemini 網頁的訂閱圖示推論程式已包含免費使用。

本文於二〇二六年九月十四日核對官方價格、額度與錯誤文件。Python 範例使用 google-genai 2.23.0；計算器是本地算術，沒有呼叫模型。正式支出仍以 Google 計費記錄為準，因為額外工具、快取、服務模式與適用期間都可能改變結果。

## 讀價格表：先找模型與服務模式

以 Gemini 3.8 Flash 的 Standard 為例，官方當前標示到二〇二六年十二月三十一日，付費輸入每百萬 token 為美元 0.75，輸出每百萬 token 為美元 3.75，輸出包含思考 token。頁面也列出二〇二七年起的不同價格，因此紀錄單價時必須同時儲存生效日期，不能只抄一個數字長期沿用。

假設一次處理使用兩千個輸入 token、五百個計費輸出 token，在上述單價且沒有其他費用時，估算為美元 0.003375。這是教學算例，不是每篇檔案的固定價格；繁體中文一個字也不等於一個 token。你需要讀取實際用量，再把它代入價格表。

## 查額度：速率、每日限制與預算分開看

官方說明速率限制會依專案層級、模型與帳號狀態變動，實際限制應在 AI Studio 檢視。每分鐘請求數、每分鐘 token 與每日使用限制不是同一件事；小請求很多次和大檔案少量呼叫，可能碰到不同限制。換一把同專案金鑰，也不應被當成繞過專案限制的方法。

1. 到 AI Studio 選擇正確專案，檢視目前模型的可用限制。
2. 在用量頁確認時間範圍、模型與請求量，對照自己的執行紀錄。
3. 在計費頁確認是否已啟用付費、可用餘額及通知設定。
4. 在應用程式設定每批檔案數、單份大小與同時執行數，先用小批次觀察。
5. 為預算或錯誤率達門檻時設計停止機制，確認真的不再送出新請求。

帳單通知與程式停止是兩種不同機制。你的程式應有自己的操作上限，例如每次只處理指定清單、輸出已存在就先核對、錯誤超過門檻就停止。這些限制要能在測試中觸發，不能只寫在專案說明檔案裡。

## 錯誤分類：先修正原因，再決定是否重試

無效請求通常應檢查模型名稱、引數與檔案格式；認證或權限錯誤要檢查金鑰與專案資格；找不到資源則檢查檔案識別與儲存期限。這些情況不能靠快速重送相同內容修好。保留 HTTP 狀態與服務錯誤碼，不在記錄中輸出金鑰或整份私人檔案。

暫時性服務錯誤或速率限制，可依官方建議採指數退避並加入隨機延遲，但要有最大次數與總等待上限。SDK 本身可能已經自動重試，你再包一層重試會增加總次數；先確認目前 SDK 的行為，再決定應用層是否需要額外處理。對有外部副作用的動作，也要防止重複提交。

```text 重試流程範例：設計規則，不是 CLI 指令
取得錯誤碼與請求編號
若為無效輸入、認證或權限問題：停止並回報
若為暫時性錯誤：先確認 SDK 已重試幾次
尚在總次數與等待上限內：等待後重試
超出上限：儲存失敗狀態，不產生成功結果
```

這份流程的預期結果是：錯誤不會被轉成空白摘要，重試用完也不會無限等待。你可以用模擬服務依序回傳暫時錯誤與成功，確認程式只建立一次正式結果；另用權限拒絕測試，確認它立即停止，而不是持續消耗請求。

## 成本控制：先減少不必要的工作

對檔案摘要而言，先排除重複資料，限制輸出長度，使用能達成品質要求的模型，再衡量快取或 Batch 是否適合。不同 API 路線的功能不一定完全一致；目前官方 Interactions 說明仍列有與 generateContent 的功能差異，不要直接把 Batch 範例的引數塞進 Interactions 呼叫。

每次模型或提示詞更新，都以固定檔案比較正確率、缺漏判斷與實際用量。最便宜的一次呼叫若常需要人工重做，未必是整體成本最低的流程。用[[48|結構與來源驗證]]降低不合格結果流入後續工作的機會，通常比只追求短回覆更有意義。

## 常見問題與檢查清單

「有免費層為什麼還會失敗」免費可用不表示無限制，也不表示每個模型與工具都支援。先看目前專案限制及錯誤碼，確認是否已用盡、功能不支援或資格不符，再決定下一步。

「我只看到很短的回答，為什麼輸出用量較多」部分模型的思考 token 也列入計費輸出；工具、歷史內容與檔案輸入也可能增加用量。以回傳使用統計與官方計費定義為準，不以畫面上看得到的字數估算全部工作。

「發生逾時代表沒有計費嗎」不能這樣推論。客戶端沒收到完整回覆時，服務端可能已處理部分或全部工作。記下請求時間與識別資訊，核對用量，再判斷是否重送。[[50|完整檔案工具]]會保留模型與來源指紋，讓結果更容易追蹤。
