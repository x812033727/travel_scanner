Gemini CLI 的登入方式會影響可使用的服務、額度與計費歸屬。本篇帶你比較 Google 帳號登入、Gemini API Key 與 Vertex AI，完成適合自己的認證，並用最小對話驗證。重點是知道目前到底使用哪個帳號與專案，而不是只看到登入成功就假設所有功能都包含在訂閱裡。

## 開始前：先確認使用目的

先完成[[29|CLI 安裝]]，在空白練習資料夾啟動 Gemini CLI。本篇指令以 0.59.0 為基準，認證條件依查證日官方文件整理。你需要一般 Google 帳號，或已建立 Gemini API 專案；若使用公司 Workspace 或 Google Cloud，還可能需要管理者配置權限與專案。

如果你只是個人互動使用，先看 Google 帳號登入是否符合資格；已有程式開發專案與金鑰的人，可選 API Key。Vertex AI 適合已使用 Google Cloud 身分、專案與計費管理的環境，第一次使用 CLI 不必為了選項較多而額外建立整套雲端設定。

認證選擇與[[2|Gemini 消費者方案]]不是一張通行證。Google AI 訂閱、Code Assist 權益及 API 計費要分別看官方條件。不要把某個方案的月費直接當成 API 儲值，也不要將一般網頁登入會話當成程式金鑰。

## 路線一：使用 Google 帳號登入

1. 在練習資料夾執行 gemini，依登入介面選擇 Google 帳號方式。
2. 在開啟的瀏覽器確認帳號電子郵件，閱讀同意畫面所列的權限。
3. 完成流程後回到終端機，等待 CLI 顯示可使用的狀態。
4. 輸入不需檔案與工具的短提示詞，確認模型能回答。
5. 記錄帳號型別與 CLI 版本，之後檢視額度時使用對應服務的資訊。

```text Gemini CLI 內輸入
請用繁體中文回覆一句「連線測試完成」，不要使用工具。
```

預期看到一段正常文字回覆；若顯示資格或地區錯誤，先保留錯誤碼。個人帳號與組織帳號的需求可能不同，後者可能需要指定專案或管理者授權。不能只因為瀏覽器能使用 Gemini 網頁，就判定 CLI 的服務資格也完全相同。

當電腦同時登入多個 Google 帳號，最常見的混淆是瀏覽器選了私人帳號，但你以為使用公司帳號。回到認證介面核對身份，再做同一個最小測試。不要用模型自我介紹來判斷目前帳號；應看登入流程與服務回傳資訊。

## 路線二：使用 Gemini API Key

到[[47|AI Studio]]建立或選取金鑰，確認所屬專案，將金鑰放入目前終端機的 GEMINI_API_KEY 環境變數，再依 CLI 介面選擇 API Key 認證。金鑰不是提示詞，不應貼進普通聊天輸入框，也不應放進 GEMINI.md。

```powershell PowerShell 7：隱藏金鑰輸入
$env:GEMINI_API_KEY = Read-Host "貼上 AI Studio 金鑰" -MaskInput
gemini
```

這個環境變數會讓此終端機啟動的程式讀取金鑰。若改用另一個終端機或排程環境，必須在那邊正確提供認證；不要假設設定一次便影響整臺電腦所有工作。關閉視窗後，工作階段層級的設定也可能不再存在，長期自動化應使用適當的秘密管理方式。

使用 API Key 的請求與 API 專案額度相關，請到 AI Studio 用量與計費頁核對。先確認是否為免費或付費層、使用什麼模型，再開始大量工作。[[49|API 成本與錯誤處理]]提供估算與停止條件，避免把重試或長對話當成沒有成本。

## 路線三：使用 Vertex AI

Vertex AI 認證建立在 Google Cloud 的專案、位置與身分權限上。依官方 CLI 認證檔案設定所需環境與憑證，使用組織已核准的專案；不同組織可能使用應用程式預設憑證或其他方式。你不應把網路上的服務帳戶 JSON 任意下載後直接放進專案。

開始前先確認誰負責計費、哪個身分有呼叫權限、資料將使用哪個位置與政策。完成後仍以短提示詞測試，再到對應雲端用量頁核對。遇到專案不存在或權限不足，應修正專案與身分，而不是一直更換模型名稱。

本系列主要 API 範例採 Gemini Developer API，因此不把 Vertex AI 引數混進相同範例。若你的工作必須走 Vertex AI，先把認證與模型可用性驗證完成，再依官方 SDK 檔案改寫。兩者雖然都能使用 Gemini 模型，服務管理與計費邊界仍需各自確認。

## 切換認證與排查混用

0.59.0 的認證指令提供 signin 與 signout；在 CLI 內用 /auth 檢視目前可用操作。要切換方式，先結束原先認證流程，檢查目前終端機是否留有另一套 API 或 Cloud 環境變數，再重新登入。保留設定用途，不要一口氣清除公司既有的雲端配置。

```text Gemini CLI 內輸入
/auth
/auth signin
```

若個人帳號出現組織訂閱資格提示，官方疑難排解檔案提到，GOOGLE_CLOUD_PROJECT 等環境變數可能影響服務檢查。先確認它們是否為本次工作需要，再在目前環境調整。修正後重跑相同提示詞，並記錄哪個變數造成差異，詳見[[46|排解流程]]。

## 常見問題與安全交接

「有 Google AI Pro 就一定不用管 API 費用嗎」不能這樣推論。你選的認證路線決定請求走哪個服務，應對照該服務的當前權益與計費頁。方案名稱相似，不代表用量可以互相抵扣。

「金鑰可以放在 settings.json 嗎」優先採環境變數或受控秘密管理，不把真實金鑰放在可分享的專案設定。[[38|設定檔教學]]會區分普通程式設定與認證資料，分享範例時只保留變數名稱。

「換電腦後為什麼不能直接用」新環境可能沒有登入憑證、相同 PATH 或必要專案設定。重新確認認證流程，再測試短對話，最後才搬入[[45|批次腳本]]。交接檔案應記錄所需帳號型別與變數名稱，不包含任何真實金鑰。
