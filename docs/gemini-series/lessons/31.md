這份指令總表整理 Gemini CLI 0.59.0 的內建操作，讓你先找到用途，再跳到負責講解的文章。清單由本機已安裝版本的指令載入器核對，並對照官方文件；自訂命令、MCP 提示詞與開發版專用命令不混入固定內建清單。部分專案必須先開啟功能或符合登入條件。

## 開始前：辨識三種輸入位置

先完成[[29|安裝]]與[[30|認證]]。gemini --version 是在 PowerShell 或 shell 執行的終端機命令；/memory list 是在 Gemini CLI 裡輸入的斜線指令；「幫我摘要這份公告」則是交給模型的提示詞。若放錯位置，即使文字完全正確，也不會得到同樣結果。

本文核對時，將可選的使用者功能開啟以取得完整清單，但沒有執行每個指令的動作，也沒有替讀者安裝服務或更改帳號。你的 /help 若少了某一項，先檢查版本、功能開關與管理者政策，不要直接認定安裝損壞。詳細差異請回到對應教學檢視。

## 常用操作：先學會看狀態

先輸入 /help 與 /about，確認可用命令和版本。接著用 /tools desc 看工具說明；這可以告訴你 CLI 現在有哪些能力，但不代表所有工具都已獲得外部服務授權。要確認專案指示，用 /memory list、/memory show；改檔後再 reload，詳見[[37|記憶載入]]。

```text Gemini CLI 內輸入
/help
/about
/tools desc
/memory list
/memory show
/memory reload
```

0.59.0 的 /memory reload 保留 refresh 別名；/compress 也有 compact 與 summarize 別名。這些別名都指向同一類操作，不需要建立多份設定。官方不同頁面可能尚未使用相同名稱，本篇以實際版本清單為準，升級後再重新核對。

## 模型與對話：操作後確認影響

模型選擇可從 /model manage 開啟介面，或用 /model set 加上你帳號可用的模型識別字；需要持續儲存時，先檢視該版本提供的 persist 行為。不要把網頁版模式名稱當成 API 或 CLI 模型識別字，也不要把切換成功當成所有工具都已支援新模型。

對話太長時用 /compress 整理上下文，但重要需求仍應儲存在你可查閱的檔案。要找舊工作用 /resume，要另開新工作階段用 /clear；這些操作與清除本機檔案不同。完整恢復、匯出與還原範例見[[33|對話管理]]，執行還原前先讀清楚會影響對話、檔案或兩者。

## 終端機引數與語法速查

終端機命令以 gemini 開頭。單次非互動提問使用 -p，選輸出格式用 -o；恢復最近工作階段可用 --resume latest。先用 --help 檢視當前版本，再把需要的引數放入腳本，不要從不同年代文章各抄一段組合。

```bash 終端機命令
gemini --version
gemini --help
gemini --resume latest
gemini -p "請列出公告摘要應核對的欄位，不使用工具。" -o json
```

@ 是檔案與資源引用入口，! 是 shell 命令入口；兩者都不是一般的文字裝飾。需要路徑、引號與背景工作說明時閱讀[[32|檔案與 shell]]。要把短提示詞存成自己的 /summary，閱讀[[40|TOML 自訂指令]]，不要把自訂名稱誤列為所有讀者都有的內建命令。

## 常見問題與版本更新

「官方文件有 /shells，我卻找不到」這份 0.59.0 載入器清單提供 /tasks，另有 bg 與 background 別名。遇到檔案差異時，以本機 help 與版本化清單交叉核對。不要為了讓舊指令可用，就任意安裝不明套件。

「/extensions install 能不能在 CLI 裡用」0.59.0 在啟用對應功能時提供互動子指令，但部分官方文件仍以終端機管理為主。本系列完整安裝範例採 gemini extensions，讀者比較容易辨識輸入位置；[[41|擴充教學]]會帶你完成安裝、重啟與連線驗證。

「/bug-memory 可以當一般記憶功能嗎」不適合，它是寫出程式記憶體快照供除錯的功能，可能包含工作資料。專案規則請使用 GEMINI.md 與 /memory；需要回報問題時先檢查資料內容與儲存位置，不把診斷檔直接當作普通教學附件公開。

新增命令前，先記錄來源屬於內建、專案 TOML、擴充套件或 MCP。把這四種來源分清楚，才知道更新或停用應到哪裡操作。若清單與預期不同，依[[46|疑難排解]]從版本、目錄與功能狀態開始查。
