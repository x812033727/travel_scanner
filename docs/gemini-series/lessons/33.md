長對話、工作中斷與切換任務，是使用 Gemini CLI 時常見的情況。本篇教你找回工作階段、儲存命名檢查點、壓縮上下文與匯出資料，並分清楚清除畫面、恢復對話和還原檔案的效果。目標是保留能繼續工作的資訊，也知道哪些狀態必須重新確認。

## 開始前：先儲存可辨識的工作內容

準備已安裝並登入的 Gemini CLI，本篇以 0.59.0 與官方工作階段檔案為基準。在獨立練習資料夾進行一段虛構公告整理，讓工作階段有清楚主題。不要第一次練習還原就使用正在修改的重要專案，因為不同操作可能影響對話或檔案。

先理解[[37|專案記憶]]與對話歷史不同。GEMINI.md 儲存持續使用的指示，工作階段歷史則包含這次提問與工具結果。找回對話不能保證磁碟檔案仍和當時一致，也不能代表外部服務狀態沒有改變；繼續前要重新核對重要來源。

你可以先要求 CLI 列出目前目標、已完成專案、尚待確認事項與下一步，將這段交接摘要存成自己的筆記。即使之後無法恢復完整工作階段，也能從清楚的狀態繼續。這份筆記應記錄具體檔案與驗收結果，不只寫「進度八成」。

## 恢復工作：從清單選對一個會話

在 CLI 輸入 /resume，會開啟先前工作階段的瀏覽介面。利用時間與開頭訊息辨識主題，選取後先檢視最後的工作內容。若你只想恢復最近一次，可在終端機使用 gemini --resume latest；不要把終端機引數直接貼成普通聊天內容。

恢復後，先要求它整理已知狀態，再核對磁碟與外部資料。先前模型說某個測試通過，只代表當時記錄中的那一次結果；如果檔案後來被你或同事修改，應重跑相關檢查。這個習慣能避免把舊對話的結論當成目前專案的事實。

## 實作：儲存檢查點並恢復

1. 在練習對話整理一段公告，要求列出日期缺漏，確認結果可用。
2. 執行 /resume save before-format，儲存目前決策點。
3. 接著要求把摘要改成表格，觀察另一種輸出格式。
4. 使用 /resume resume before-format，回到命名檢查點的對話分支。
5. 核對回復的內容，再選擇另一種格式繼續，不把對話分支與 Git 分支混為一談。

```text Gemini CLI 內輸入
/resume save before-format
/resume
/resume resume before-format
```

預期可以在命名檢查點附近重新開始另一條對話。官方文件也保留 /chat 相容操作；0.59.0 的兩組指令都有檢查點相關子命令。這個練習只改變對話內容，沒有示範還原磁碟檔案；要驗證檔案回復，必須另外檢視實際差異與還原選項。

## 壓縮、清除與匯出：用途分開記

/compress 會用摘要取代部分上下文，適合對話變長後保留重點。壓縮可能省略細節，因此操作後先問它目前理解的限制與下一步，再與你的交接筆記比對。固定不能遺失的規則應儲存在[[36|GEMINI.md]]或專案檔案，不依賴模型摘要每次都記得。

/clear 會清除畫面並開始新工作階段，它不是刪除專案檔案的命令，也不應被當成抹除所有歷史或登入資料。若要處理儲存資料，先檢視對應工作階段管理與隱私說明，再決定是否刪除。清楚區分效果，能避免以為資料已刪除卻其實仍存在。

0.59.0 提供 /export-session 將目前工作階段輸出為 JSON，另可用 /copy 複製最近結果。匯出前確認檔案位置與內容，因為對話可能包含原文、工具輸出及私人路徑。分享前檢查必要資料，不把完整工作階段當作一般公開文章附件。

```text Gemini CLI 內輸入
/stats session
/compress
/export-session
```

執行匯出後，依畫面回報確認實際檔案存在且可開啟。只看到「準備匯出」不能算完成；如果目標檔名已存在，也要先了解覆寫行為。需要把工作結果交給腳本處理，可閱讀[[45|Headless 模式]]，使用明確的輸出與退出狀態。

## 還原操作：先確認要退回什麼

/rewind 可以選擇較早訊息，依介面決定處理對話、程式變更或兩者。這些選項的影響不同，執行前先看當下檔案差異。對話回到較早時間，不代表寄出的信件、外部服務變更或所有 shell 副作用也會被撤銷。

/restore 與工具檢查點有關，必須有可用的記錄與設定。它不能取代 Git 或你自己的備份。當專案另有未提交修改，先儲存差異與來源，再考慮還原；不要為了讓畫面回到熟悉位置就覆蓋其他人剛完成的工作。

## 常見問題與下一次開工

「恢復後怎麼找不到之前的檔案」可能啟動於另一個資料夾，或檔案已移動。先用[[32|目錄與檔案工具]]確認現況，再重新提供來源。工作階段儲存的是歷史，不會替你保證所有檔案永久存在。

「壓縮後漏掉要求怎麼辦」把仍有效的要求重新整理成一份明確清單，並指出哪些內容是最新指示。不要只說「照之前的做」，因為被摘要的細節未必還在上下文中。必要時從交接筆記開始新工作階段，減少混雜的舊要求。

「刪除工作階段能取消已做的事情嗎」不能。刪除歷史與撤銷外部行為是不同操作；刪除前先確認是否需要保留稽核或交接資料。要撤回檔案修改或外部更新，應依該系統的流程處理，而不是單純刪聊天。

每次暫停前留下已完成、未完成、驗證結果與下一步；重新開始時先對照現況。配合[[34|程式修改流程]]與[[46|疑難排解]]，你就能把中斷與恢復變成可檢查的工作步驟，而不是靠回憶猜進度。
