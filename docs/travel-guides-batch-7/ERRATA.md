## 字數：README 的上限比站上實際出貨嚴

普吉跳島篇的撰稿者用 `pack_ingest._body_length` 量了 main 上 88 篇 zh-TW `howto`：**中位數 3,183 字、最長 4,178 字**，而 `pack_cli lint` 的機械區間是 1,500 到 6,000。
README 寫的 1,800 到 3,000（沿用第六批）比實際出貨的分布嚴，本批前三篇寫完都落在 3,000 到 4,050 之間，
每一篇都刪過兩到三輪，再刪就要砍規格點名的事實。

**協調者 2026-09-17 的決定：上限放到 4,200 字**（站上既有文章的最長值），不要為了湊 3,000 砍掉查證過的資訊，
但也不要超過站上既有文章的分布——澳門篇初稿 5,097 字，比 main 上最長的還長，已退回壓縮，指定可砍的是
世遺步行路線的站名清單與計程車附加費細項，官方票價、班距與入境規定一個都不砍。
第八批規劃時把 README 的字數規則改成貼近實際的區間（例如 1,800 到 4,200），或者在規格階段就把內容量壓下來——
真正的問題是規格把太多東西塞進一篇，不是撰稿者寫太長。
