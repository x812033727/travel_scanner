## 1. 建議順序

1. **先提高現有分潤入口的相關性與可見性。** 旅遊服務已有整套就緒檢查、揭露、POST 外連與點擊報表，先用它。
2. **展示廣告集中在完整文章。** 以少量內文廣告作為比較基線；城市、搜尋與行程的主要目的仍是協助規劃。
3. **架站／工具文章使用對應品牌的合作連結。** 只在有真實核准連結、文章確實討論產品時加入。
4. **直接贊助先做單次試案。** 有實際廣告主需求才做排期、曝光與計價系統；不用歷史流量猜售價。

這是根據站內頁面用途做的建議，不是已量到「分潤比廣告賺更多」。目前未取得最新流量、AdSense 收益及夥伴佣金。

## 3. 各頁配置

下列數量是**建議測試配置**，不是全站強制上限，也不是 Google 的規定。現有文章廣告最多三個與既有間距規則保留；
要測試較低密度，先選同類文章做可回復的比較。

| 頁面 | 第一順位 | 建議位置／數量 | 配置原則 |
| --- | --- | --- | --- |
| 首頁、探索與文章列表 | 導向站內高意圖內容 | 一個服務入口，通往城市／住宿／攻略 | 第一屏讓讀者理解網站與開始探索；暫不加展示廣告 |
| 城市指南 | 住宿、活動、交通、eSIM | 城市概覽之後的規劃區；每類只顯示已就緒夥伴 | 保留官方與站內資訊；以需求順序排列，不以佣金排序 |
| 旅遊攻略 | 相關分潤，廣告補充 | 決策段落後一個相關模組；文末補未出現的相關模組 | 交通文接交通、上網文接 eSIM、住宿文接住宿；規範／禮儀文可沒有合作入口 |
| 長篇教學與生活文章 | 產品相關合作連結＋少量內文廣告 | 產品選擇／註冊步驟後一個合作連結；測試 1–2 個廣告 | AI 文不因填了城市就放整套旅遊服務；沒有相關夥伴時維持純內容 |
| 飯店詳情、住宿結果 | 對應飯店的預訂入口 | 讀者看完地點與條件後比較平台 | 保留一般官網入口；精確飯店、日期與價格僅在來源可驗證時顯示 |
| 美食與店家 | 可靠訂位入口 | 店家資訊／訂位段落 | 免費資訊優先；現有非分潤訂位連結保持原樣 |
| 行程編輯、地圖、帳號、分享 | 完成使用者的操作 | 展示廣告維持隔離；有關聯的準備事項可用既有合作入口 | 不把廣告放在拖曳、播放、導航或提交按鈕旁；分享網址不交給第三方腳本 |
| 影片內容 | 內容與對應服務 | 說明區中的相關入口 | 播放與全螢幕操作保持清楚；不要另加會蓋住播放器的廣告 |

例：東京交通攻略先解釋路線與適用條件，再提供「查看東京交通與接送」；
只有目的地入口時，要照目前文案明說它不是特定商品。不要稱為「最便宜」或暗示網站已驗證即時價格。

## 4. AdSense 建議

- **第一輪以現有手動內文廣告為主。** 中長文比較 1–2 個位置；短文不硬塞第二個。先讓讀者讀到完整的實質內容。
- **保留現有防干擾機制。** 廣告有獨立標示、預留尺寸、下方廣告延遲載入，與合作按鈕有內容間距。
- **Auto ads 建議基線：** vignette／ad intents 關閉；有固定手機導覽時 bottom anchor 先關閉；若開 Auto ads 內文格式，
  務必把它與手動廣告合計，避免實際總數高於預期。先用預覽與排除區域確認，不憑程式的三個上限推斷 Auto ads 總數。
- **精準排除工具與私密頁。** 現有文件邊界只讓符合條件的公開文章載入標籤；維持此限制。
- **登入讀者的處理還有待決策。** 現有票 `2026-09-24-adsense-tag-loads-for-signed-in` 原本以廣告關閉為阻擋理由，
  現在公開設定已開啟。建議有 `travel_access` cookie 的文章文件也不載入標籤與廣告空間；代價是少掉登入讀者的廣告收入。
  本次不增加 `/auth/me` 查詢或修改這個登入策略，正式優化排程應優先處理此票。
- **CMP 執行驗證仍待完成。** 本輪已確認 mokaair.com GDPR 訊息在 Google 帳戶中已發布；仍需驗證歐洲訪客的實際顯示與同意訊號，不能只靠本站旗標。

Google 提醒廣告靠近播放、導航、下拉與其他操作容易造成誤點，也禁止把廣告偽裝成內容。
以上頁面排除與格式關閉是本網站的體驗建議，政策本身沒有一般控制項統一的像素距離。
來源：[AdSense 配置政策](https://support.google.com/adsense/answer/1346295?hl=en)、
[Auto ads 格式與排除](https://support.google.com/adsense/answer/9305577?hl=en)、
[CMP 要求](https://support.google.com/adsense/answer/13554116?hl=en)。

## 5. 分潤與直接贊助

### 分潤

- 第一期沿用已審核的 Klook 與住宿入口，逐目的地驗落地頁；eSIM 等類別取得實際核准連結後再擴充。
- 單一決策區先放一至兩個有差異的選擇，讓讀者看清楚品牌、用途與外部確認事項；大量供應商集中在比較頁。
- 手機按鈕全部可見，長文案換行，點擊區至少 44px；桌面兩欄。保留平台既定順序。
- 直接合作超連結統一 `rel="sponsored noopener"` 與清楚揭露；既有 POST clickout 表單維持 `noopener`。
  **表單不要加 `noreferrer`：** 會讓 Origin 變成 null、被同來源保護拒絕；303 外連已設定 no-referrer。
- 主機文只放文章教的品牌；使用正式 Affiliate Program 產生的連結，不使用 Hostinger 個人 Referral Program URL。
- Stay22 優先使用明確住宿入口；全站腳本需逐項確認 Spark／Nova 開窗行為、排除頁與廣告相容性，不直接套預設。

來源：[Google 付費連結標示](https://developers.google.com/search/docs/crawling-indexing/qualify-outbound-links)、
[Hostinger 個人推薦限制](https://support.hostinger.com/en/articles/6080777-how-to-use-the-referral-program-at-hostinger)、
[Hostinger Affiliate Program](https://www.hostinger.com/affiliates)、
[Stay22 Script 設定](https://community.stay22.com/how-to-set-up-your-letmeallez-script)、
[Stay22 Retail／Nova 說明](https://community.stay22.com/retail-monetization-update-phased-rollout)。

### 直接贊助

先以「一個城市／主題、指定語系、固定檔期、一張明確廣告卡」洽談試案；不保證點擊或成交，
不出售評分、排名與推薦結論。贊助入口不要與同卡分潤競爭，也不放在贊助商自己的排名／評測內。

報價單只填真實資料：近 28 天可量測流量、主要語系與來源、版位示意、檔期、交付與取消條件、曝光／點擊口徑。
成本底價可用製作與服務工時計算，收益售價再用實際需求談；目前不提供憑空的 CPM 或每月收入。
要保證曝光交付前，須完成獨立排期模型、廣告標示、可見曝光與點擊計數；不能沿用只支援分潤佣金的品牌欄位。
「約 3 萬月文章瀏覽或真實廣告主需求」是既有內部開發觸發建議，不是聯播網加入門檻。
完整設計延續 `2026-09-24-first-party-sponsor-placements-design`，本次不啟用販售。

## 6. 28 天比較與收入判斷

先取得同類文章的 28 天基線，再改一個因素（位置或 CTA），下一段等長期間比較，記錄來源／語系／裝置組成。
流量足夠才隨機分組；流量少時以方向性結果為主，不把幾筆點擊當成統計結論。

| 指標 | 目前取得方式 | 用途／限制 |
| --- | --- | --- |
| 文章瀏覽與分潤外連 | 站內分析及 affiliate ledger | 點擊／已量測瀏覽只能看方向；兩者的 DNT／GPC／bot 排除口徑不同，不稱嚴格 CTR |
| 真正版位 CTR | 待同一口徑的可見曝光與有效點擊計數 | 可見曝光建議先定為卡片至少 50% 進入視窗連續一秒、同頁一次；這是內部定義，尚未實作 |
| 廣告填充、可視率、page RPM、收益 | AdSense 帳戶報表 | 判斷增加版位是否真的提高 page RPM，而非只增加請求 |
| 訂單、取消與核准佣金 | 各夥伴後台每月對帳 | 點擊不等於成交；不同夥伴的佣金與取消期依該帳戶條款 |
| 頁面體驗 | 行動版 LCP／CLS、完成行程比例、錯誤率 | 收入提升必須和閱讀／操作完成一起評估，保留可回復版本 |

展示廣告試算用「AdSense 同期報表的 page views ÷ 1,000 × 該報表的 page RPM」。
若改用站內文章瀏覽，須核對 DNT／GPC、廣告阻擋與標籤觸及造成的口徑差異；估計收入不等於最終入帳。
公式來源：[Google page RPM 定義](https://support.google.com/adsense/answer/112030?hl=en-GB)。
分潤收益採夥伴已核准、扣掉取消／退款的佣金，再扣實際新增成本；兩者不要混成預估保證收益。
目前 partner SubID 不含文章 slug，不能可靠宣稱某篇文章賺多少；先按夥伴、目的地、模組、語系與位置對帳。
若要文章收入歸因，另行設計夥伴允許的對帳方式，不把文章 slug 或個人識別資料直接塞進外部追蹤。
