桌面版的日常工作，核心是讓工作階段、檔案差異與預覽結果互相對得上。本篇以待辦清單的小功能為例，示範如何命名工作、補充上下文、評論修改、處理中斷並收尾。你不需要一次用完所有側欄功能，先建立可重複的檢查節奏就能減少混亂。

請先完成[桌面版第一個任務](article:claude-code-desktop-setup)，並準備一份能正常啟動的練習專案。若先前已修改材料，先看目前差異並記錄基準；不知道那是誰的工作時，先保留現況。接續工作應從檔案事實開始，而不是單靠記憶中的上一段對話。

## 讓每個工作階段有清楚目的

在側欄選取既有 session，或為新的獨立任務建立工作階段。把名稱寫成成果，例如「待辦篩選：三種狀態」，比「測試一下」容易找回。名稱只是識別對話，真正的執行範圍仍取決於所選環境、資料夾、分支或隔離工作目錄。

桌面可以並行多個 session，但不要因此假設它們的檔案一定互不影響。Git 專案可能使用 worktree 隔離，非 Git 資料夾或不同設定也可能直接操作原目錄。開始第二個任務前，請它回報實際路徑和分支，理解[Worktree](article:claude-code-worktrees-parallel)如何提供檔案隔離。

```text Claude Code 桌面版對話框：開始一天的工作
請先檢查目前工作目錄、分支和既有變更。
整理哪些是本次任務需要的檔案，哪些變更已經存在。
本次目標是在待辦清單加入三種篩選；先提出範圍與驗收方式。
不要清除或覆蓋與本次無關的工作。
```

## 用檔案與圖片補充上下文

輸入 @ 後選擇相關檔案，或將圖片拖入對話，能把需求指向具體材料。引用 model.js 是為了提供資料操作邏輯，附畫面草圖則是說明篩選按鈕的位置；兩者用途不同，最好在提示詞中各用一句話交代。不要只丟十張圖，期待 Claude 自行猜測哪張是目標。

如果只想問某段程式，先選取或附上那個範圍，指出你想知道的輸入與輸出。資料夾很大時，先請它建立結構摘要，再逐步讀必要檔案。上下文越多不一定越好，與目標無關的歷史錯誤、日誌與草稿會增加判斷負擔。

## 安排對話、差異與預覽

依自己的螢幕寬度調整面板。桌面寬螢幕可以並排對話、差異與 Browser；筆電則先保留對話與一個檢查面板，需要時切換。目的不是把每個窗格都塞進來，而是能在 Claude 說完成某一步時立刻看到對應證據。

| 面板或資訊 | 用來回答的問題 | 篩選功能的檢查例子 |
|---|---|---|
| 對話 | 它如何理解需求 | 是否保留原始待辦資料 |
| 差異 | 實際改了什麼 | 是否新增篩選邏輯與測試 |
| 終端機紀錄 | 命令是否成功 | 測試結束碼與失敗訊息 |
| Browser 預覽 | 使用者操作結果如何 | 點已完成是否只剩完成項目 |

## 把評論寫在具體變更上

打開差異後，先確認改動檔案範圍，再看關鍵邏輯。例如切換顯示狀態時是否只是建立顯示清單，沒有直接覆蓋原始資料。你可以對特定行留下評論，描述可重現的問題；這比在對話只說「篩選怪怪的」更能引導修正。

```text 差異評論或桌面版對話框：提供可重現回饋
目前在「未完成」篩選下勾選第一筆後，再按「全部」，該筆資料不見了。
預期它只是離開未完成清單，仍可在全部與已完成找到。
請檢查篩選是否改寫原始陣列，補上這個情境的測試並修正。
```

修正後回到同一個操作順序重新驗證。不要只看它有沒有改另一行程式；真正的完成判準是原本失敗的行為已改善，而且新增、刪除等舊功能仍能工作。若評論引出額外需求，例如資料持久化，先把它另列，避免今天的篩選任務持續擴張。

## 中斷、補充與接續

如果你也在編輯器手動修改同一個檔案，先告訴 Claude 哪一段是自己的調整。桌面檔案面板可能提示磁碟版本已變，這時先比較兩邊內容，再決定保存或放棄。不要把工具剛才提出的版本視為唯一正確版本；它可能還沒讀到你最新的修改。多人或多 session 協作時，這個核對尤其重要。

發現方向明顯偏離時，可以使用停止按鈕中斷，再說明需要修正的範圍。只是補一個限制時，也可以送出補充訊息並確認它已納入。停止工作不會自動把先前檔案與外部操作回復，因此中斷後第一件事是看現有差異，再決定如何繼續。

暫時離開前，請 Claude 記錄已完成、待處理與最後測試結果。回來後在同一工作階段接續，先確認檔案是否被其他人修改。對話記得某個版本不表示磁碟仍是該版本；若基準已變，請它重新讀取相關部分，更新接下來的方案。

> 工作階段名稱與對話摘要方便找回脈絡；Git 提交保存程式版本。兩者可以互補，但不要用一段聊天摘要代替實際檔案備份。

## 預覽與測試的收尾方式

請 Claude 啟動正確工作目錄的伺服器，記錄 Browser 使用的位址，再執行三種篩選的操作。開著多個 session 時特別注意埠號，不同視窗可能指向不同專案。若畫面一直像舊版本，先查伺服器的啟動路徑，而不是反覆要求清快取。

```text Claude Code 桌面版對話框：收尾報告
請整理本次最終改動、實際修改的檔案與測試結果。
逐項對照三種篩選、勾選、刪除與切回全部的驗收結果。
列出預覽使用的工作目錄與網址，清楚指出未驗證項目。
本次先保留為本機可審查成果，不進行遠端推送或部署。
```

桌面提供的 PR 監看與自動合併是後續選項，不是每個工作階段都必須啟用。當你真的要送出版本，先讀[Git 與 PR 審查](article:claude-code-git-review-pr)，確認差異、目標分支及測試。尤其多工作階段同時進行時，要知道本次提交包含哪一份成果。

小練習是把同一個功能分成「讀取現況」「實作」「審查」三次指示，保留在同一 session，並用一個具體錯誤評論完成修正。結束時應能用側欄找到工作、用差異指出改動、用預覽重做驗收；這三件事都做到，才算建立可持續的桌面工作流程。
