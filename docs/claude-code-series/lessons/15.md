Android 手機可以透過 Claude App 查看程式任務、補充需求與回應問題。本篇從官方 App 安裝開始，用雲端與 Remote Control 兩種工作各做一次只讀驗證，也說明通知、附件和離線時應如何判斷狀態。讀完後，你會知道手機是操作入口，真正的工具執行仍在另一個環境。

適用於 Google Play 目前支援的 Android 裝置與符合功能資格的帳號。請先看[平台選擇](article:claude-code-platforms-guide)，選定要連雲端還是自己的電腦。若你只有 Console API 計費登入，先核對手機所需的 claude.ai 帳號資格，不要把 API 金鑰貼進 App 對話當作授權。

## 安裝官方 App 並進入 Code

由官方手機文件前往 Google Play 的 Claude App 頁面，確認發行者後安裝。Claude Code 沒有另一個獨立的官方手機 App，因此不要為了找 Code 字樣安裝來路不明的替代程式。完成登入後，確認帳號與電腦使用的組織相同，再尋找 Code 分頁。

如果你已在電腦使用 Claude Code，可透過 /android 或 /mobile 顯示官方下載入口。下載入口只負責取得 App；要連進特定本機任務，還要另用 Remote Control 的 session 連結。把兩種 QR code 的用途分清楚，可以避免掃完碼卻一直找不到工作。

```text 電腦的 Claude Code 對話框：取得 Android App 下載入口
/android
```

Code 分頁沒有出現時，先確認 App 是否更新、是否選錯帳號或組織，以及該方案是否開放功能。若一般 Chat 可用但 Code 不可用，這不足以證明專案連線正常。先解決入口資格，再檢查儲存庫或本機程序，會比較容易定位問題。

## 選擇雲端或本機接續

| 需求 | 建議入口 | 需要事先準備 |
|---|---|---|
| 關閉電腦仍要跑任務 | 雲端 Code session | GitHub 儲存庫與雲端環境 |
| 使用電腦上的檔案與工具 | Remote Control | 本機 Claude 程序與登入 |
| 傳訊息讓桌面端派工 | Dispatch | 支援方案與配對的桌面 App |

三種入口可能都出現在同一個 Claude App，卻不共享完全相同的執行前提。尤其 Remote Control 與 Dispatch 都需要你的電腦保持運作；手機改用行動網路不會把工作搬到手機上，也不會把睡眠中的電腦變成雲端主機。

## 查看已有的雲端工作

先依[網頁版教學](article:claude-code-on-the-web)在電腦完成儲存庫連接，送出一個待辦專案的只讀任務。Android 開啟 Code 清單，找到相同名稱，對照最近一則指示與工作分支。第一次先接續已存在的任務，能把手機端驗證與雲端設定分開。

```text Android Claude App 的雲端 Code 對話框
請整理目前任務狀態：儲存庫與分支、已完成的檢查、尚未完成的檢查。
如果有失敗，指出第一個相關錯誤與發生步驟。
這次只回報，不建立新 PR，也不擴大修改範圍。
```

回覆應能指出具體工作內容與測試結果。若任務正在等待回答，先閱讀問題再補充條件；不要在另一個新對話重新描述整份需求，卻期待它帶著原本的 session 狀態。若真的想開新任務，應清楚指定新的目的與基準。

## 用 Remote Control 接續電腦

在電腦的練習專案啟動 Claude Code，完成登入與專案信任確認，再於既有對話啟用 /remote-control。用 Android 相機或瀏覽器開啟畫面提供的官方連結，也可以從 App Code 清單選取線上的電腦工作階段。詳細啟動方式請讀[Remote Control](article:claude-code-remote-control)。

連接後先問只讀問題，例如請它列出目前路徑與 README 的測試指令。回到電腦確認同一則訊息存在，且檔案路徑與你啟動的位置一致。這個雙向對照能證明接的是正確工作，不只是手機碰巧顯示一個相似的標題。

```text Android Claude App 的 Remote Control 對話框
請確認目前工作目錄，讀取 package.json 的 scripts。
告訴我 npm test 會呼叫什麼，先不要執行或修改檔案。
回覆時明確指出這是本機工作階段。
```

若電腦睡眠，先等它重新上線並確認連線狀態，再查看訊息是否送達。不要用重複點送出來取代狀態檢查，尤其原任務包含建立檔案、提交或外部操作時。手機上看到歷史紀錄，只能證明對話可讀，不能證明本機程序仍在執行。

## 通知與 Android 背景設定

允許 Claude App 的通知後，仍要留意手機廠牌自己的背景與省電設定。有些裝置會延後背景通知；這時先打開 session 看最新結果，確認是通知延遲還是工作本身停住。調整設定時只處理 Claude App 對應項目，不必為一次練習停用整台手機的省電功能。

你可以在任務中要求測試完成時通知，但實際是否送達仍取決於該功能與帳號的通知設定。收到通知後核對是完成、失敗還是等待決定，再進入對話處理。若你不需要提醒，可以關閉通知偏好；停止任務則要在工作階段中另行操作。

## 附件與手機端限制

附照片時先說明用途，例如「這是目前畫面，篩選按鈕被擠到第二行」。Remote Control 支援把附件交給本機工作階段；需要使用下載的檔案時，請 Claude 回報位置並確認內容。手機附件、專案檔案和 Git 已追蹤檔案是三種不同狀態，不能直接畫上等號。

> App 並不支援所有終端機專用指令。遇到 /plugin 或本機 session 管理不可用時，回到電腦操作；不要把指令當成自然語言要求它猜測執行方式。

小練習是從 Android 補充一次只讀要求，鎖定手機後再開啟同一個 session 查看結果，最後到電腦確認訊息與檔案狀態。完成判準包括帳號一致、工作名稱正確、知道執行位置，以及能區分通知問題與任務問題。接著閱讀[跨裝置完整流程](article:claude-code-cross-device-workflow)，把對話接續與程式版本交接一起整理清楚。
