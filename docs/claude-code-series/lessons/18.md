跨裝置工作最容易混淆的，是對話、程式檔案與 Git 版本不一定同時移動。本篇用待辦專案示範兩條完整路線：本機工作透過手機接續，以及雲端成果帶回本機。你會建立一份簡短交接紀錄，知道接下來的工具在哪裡執行、目前是哪個版本，以及哪些驗證還要重做。

請先完成[網頁版](article:claude-code-on-the-web)或[Remote Control](article:claude-code-remote-control)其中一篇，並了解[Git 基礎](article:claude-code-terminal-git-basics)。兩條路線可以獨立練習，不需要同時開啟所有平台。先選一條完成，再比較另一條的差別。

## 先分清楚三種狀態

對話保存需求、推理脈絡與工具紀錄；工作目錄保存當下檔案；Git 分支與提交保存版本關係。從手機看到同一個對話，不代表手機擁有相同目錄。把雲端分支抓到本機，也不代表原雲端 session 會自動看見你之後的本機修改。

| 需要交接的內容 | 用什麼確認 | 常見誤解 |
|---|---|---|
| 對話脈絡 | session 名稱與最近指示 | 名稱相同就一定是同一個 session |
| 檔案現況 | 工作目錄與差異 | 對話同步等於檔案複製 |
| 程式版本 | 儲存庫、分支與提交 | 雲端完成等於主分支已更新 |
| 執行環境 | 工具版本與測試結果 | 換裝置後所有環境條件都相同 |

## 路線一：電腦開始，手機接續本機

在電腦進入練習專案，啟動 Claude 並請它先讀取現況。接著用 /remote-control 開啟接續入口，在手機 Code 分頁選同一 session。傳送一個只讀問題，核對電腦出現同一則訊息；這是確認同步最直接的方法。

```text 本機 Claude Code 對話框：離開電腦前的紀錄
請整理目前工作目錄、分支、已存在的修改與最後測試結果。
下一步只需要檢查篩選需求，先不要修改。
請用一段短摘要保留這個接續點。
```

```text 手機的 Remote Control 對話框：接續同一份工作
請依剛才的接續點，說明三種篩選要保留哪些原始資料行為。
只補充方案，先不要實作。
```

回到電腦後，先確認網路與程序仍正常，再看這段方案。若中途睡眠，應檢查恢復狀態與訊息時間，不要把舊摘要當成最新結果。這條路線中，程式始終在原電腦，沒有把 repository 另搬一份到手機；因此 Git 檢查仍在原工作目錄進行。

## 路線二：雲端完成，再帶回本機

先讓雲端 session 完成小修改，檢查差異與測試，確認成果分支已能從遠端取得。官方提供 teleport，把雲端對話和分支帶回本機終端機。它與 resume 不同：resume 尋找本機歷史對話，teleport 才是選取雲端工作。

在本機同一儲存庫的 checkout 中，先檢查 Git 狀態。若有未提交修改，先理解並保存它們；工具可能提示 stash，但你應先知道其中包含什麼，以及之後如何找回。初學者可使用專用且乾淨的測試 checkout，降低混入其他工作的機會。

```bash 本機終端機：同一儲存庫中先做只讀檢查
git status --short
git branch --show-current
git remote -v
```

確認登入與雲端相同帳號、儲存庫正確、工作目錄乾淨，以及雲端分支已推到遠端後，再開啟選擇器。遠端位址可能包含自己的組織名稱，分享診斷紀錄時可只保留必要部分。

```bash 本機終端機：選擇要帶回的雲端 session
claude --teleport
```

也可從雲端 session 的 Open in → Terminal 取得對應命令。使用選擇器時看清楚工作名稱與儲存庫，不要只挑最新一個。工具會核對環境並取得分支，若提示不符，先修正那個具體條件，不要直接強制切換或清除現有檔案。

## 接續後重新確認環境

teleport 完成後，本機有自己的 session 副本。之後的本機工作不會持續回寫到原雲端對話；如果仍想用手機接續現在的本機程序，就在本機重新啟用 Remote Control。這是很重要的交接點，要避免同時在舊雲端和新本機對話下達衝突修改。

```text 帶回本機後的 Claude Code 對話框
請確認目前儲存庫、分支與工作目錄，核對剛才帶回的變更。
檢查本機 Node.js 版本並執行 npm test。
開啟本機預覽，驗證修改後的主標題及新增、勾選、刪除功能。
請區分雲端已做過的檢查與這次本機實際完成的檢查。
```

雲端測試通過不保證本機工具版本相同；本機預覽成功也不代表正式網站已部署。把每個環境的驗證結果分開記錄，才能清楚知道成果目前可用到哪一層。若兩邊結果不同，先比較版本、環境變數與啟動指令，再找程式碼原因。

## Dispatch 任務如何交接

Dispatch 會派送工作，相關 Code session 出現在桌面側欄。從手機轉回桌面時，先用 Dispatch 回報的名稱和路徑找到真正執行的工作，再讀差異。派工對話可以保留摘要，但程式細節應以該 Code session 與實際檔案為準。

如果你要把這份本機成果交給雲端，必須另行確認程式版本如何提供給新環境。不要假定所有入口都能雙向搬移既有對話；CLI 新建雲端任務與 Desktop 的 Continue in 功能有不同條件，應依當前官方流程選用。第一次練習先完成單向交接即可。

> 交接前後各做一次「路徑、分支、差異、測試」核對。這四項能把大部分跨裝置誤會轉成可檢查的事實。

## 做一份自己的交接紀錄

交接還應記錄目前正在執行的程序，例如預覽伺服器與長測試。另一台裝置看到網址不代表能存取原機器的 localhost；若要在手機直接看網站，要另外選擇適當的預覽連線方式。不要把對話的遠端控制與網站網路存取當成同一種能力。

小練習是選其中一條路線，記錄開始裝置、真正執行位置、session 名稱、分支、已完成和未完成事項。換到另一裝置後，依紀錄找回工作並重做一個只讀檢查。完成判準是你能說明哪些內容同步了、哪些內容沒有搬移，以及下一個修改會落在哪個資料夾。準備交付程式時，再接著使用[差異與 PR 審查](article:claude-code-git-review-pr)完成版本管理。
