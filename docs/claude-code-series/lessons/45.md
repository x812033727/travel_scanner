Plugin 可以把 Skills、代理、Hooks、MCP 或語言伺服器相關設定打包，方便安裝與管理。本篇會從官方目錄查看一個外掛的內容、選擇作用範圍、完成一次能力驗證，再練習停用與移除。安裝成功只是開始，還要確認依賴、登入與實際工具能否使用。

先具備可運作的 Claude Code CLI，並理解 [Skills](article:claude-code-skills-skill-md)和 [MCP](article:claude-code-mcp-servers)的角色。目錄、外掛版本與組織允許清單會變動，以下以查證時官方目錄操作方式為準，實際選擇以前台顯示的名稱與內容為準。

## 目錄與外掛是不同層次

Marketplace 是外掛清單來源，Plugin 是清單中的一個套件。加入目錄不代表已安裝其中全部外掛，更新目錄也不等於所有已安裝外掛已更新。把這兩層分開，才能判斷「找不到外掛」是目錄問題還是安裝問題。

官方目錄通常在首次互動啟動時加入。若網路或管理政策阻擋，可能需要另外處理；不要為了排錯就加入名稱相似但來源不明的目錄。組織限制應由管理者確認，避免從另一個來源安裝同功能套件來繞過規則。

## 先查看內容再選擇

```text Claude Code 對話框：開啟外掛瀏覽器
/plugin
```

在 Discover 查看候選外掛，進入詳細頁確認來源、版本、提供的元件及必要依賴。這次可選擇官方目錄中的 GitHub 整合，使用自己的測試儲存庫；沒有 GitHub 帳號時，先選適合現有環境且無外部帳號依賴的技能外掛做練習。

若顯示官方目錄不存在，先核對網路與政策，再使用官方提供的加入方式。這個命令只加入目錄，不代表已經信任其中每個套件的所有操作。

```text Claude Code 對話框：僅在官方目錄缺少時使用
/plugin marketplace add anthropics/claude-plugins-official
```

## 安裝並選擇範圍

下面是官方文件列出的 GitHub 外掛安裝名稱。安裝前閱讀細節，確認目前仍存在且符合需求；若名稱或內容已改變，回到目錄選擇，不要猜測替代名稱。安裝過程可能要求選擇使用者、專案或本機範圍。

```text Claude Code 對話框：安裝前先查看外掛詳細內容
/plugin install github@claude-plugins-official
```

個人練習先選個人適用的範圍，避免把共享設定直接加入團隊專案。project 範圍會影響使用同一專案的人，應把設定變更納入版本審查。即使外掛安裝在使用者範圍，它提供的 Hook 或工具仍可能在多個專案中生效。

有些外掛只提供語言伺服器的整合設定，不會替你安裝真正的語言伺服器程式。看到「已啟用」但功能不存在時，先檢查依賴文件，而不是重裝同一外掛多次。需要外部服務認證的外掛，也要另外完成授權。

## 驗證一個具體能力

如果外掛提供 MCP，在 /mcp 中確認伺服器與工具，再對測試儲存庫做只讀查詢。若提供 Skill，使用詳細頁顯示的完整命名空間呼叫。不要把安裝訊息或名稱出現在清單中，當成工具已完成一次操作的證據。

```text Claude Code 對話框：驗證 GitHub 外掛時填入自己的測試儲存庫
請查看剛安裝外掛提供的工具。
只讀取我的測試儲存庫 [owner/repository] 的基本資訊與預設分支。
不要建立議題、修改檔案、提交或發布評論。
回報實際工具名稱與結果；若需要授權，指出目前缺少的步驟。
```

核對儲存庫名稱與 GitHub 頁面是否一致。這次只證明讀取能力，並沒有測試建立 PR、提交或其他寫入功能。若之後需要寫入，先把目標、操作與預期結果說清楚，再逐項驗證。

## 更新時記錄前後版本

先在管理介面記下已安裝版本，再檢查目錄與外掛更新。讀取更新內容，留意新增 Hooks、MCP 權限或依賴。更新完成後重新執行相同的最小能力測試，比較結果是否仍符合原本流程。

從終端機使用 claude plugin 安裝的內容，通常在新 session 或重新載入外掛後生效。互動介面與不同元件的即時更新時機可能不同；若畫面提示需要重新載入，照提示完成，不只檢查磁碟版本。

```text Claude Code 對話框：依更新提示重新載入外掛
/reload-plugins
```

## 停用、移除與撤銷授權

停用適合暫時排錯，移除則取消安裝。兩者都不必然撤銷外部服務已發出的權杖，也不會自動還原外掛過去修改的檔案。需要完整收尾時，另外檢查設定差異、服務授權與產出資料。

```text Claude Code 對話框：以本篇範例為例，分次執行
/plugin disable github@claude-plugins-official
/plugin enable github@claude-plugins-official
/plugin uninstall github@claude-plugins-official
```

部分管理命令會開啟並停留在外掛面板，完成選擇後按 Esc 返回輸入框，再輸入下一個命令。不要一次貼三行期待自動完成三個動作。停用後開新 session 確認能力不再出現，才能證明停用效果。


維護多個外掛時，先記錄每個外掛提供的能力與使用原因。兩個外掛若都提供同類 Hook 或 MCP，可能產生重複呼叫與命名衝突；停用其中一個後以相同任務比較，通常比同時重新安裝全部更容易定位。

更新後新增的權限與程式應重新審查，過去某版使用正常不代表新版完全相同。把版本、作用範圍與最小驗證放在同一筆紀錄，讓回復舊流程或移除依賴時有清楚依據。

## 常見問題與小練習

| 問題 | 檢查重點 | 處理方式 |
|---|---|---|
| 找不到指定外掛 | 目錄來源與更新狀態 | 核對完整名稱及目錄 |
| 安裝成功但工具不能用 | 依賴與服務認證 | 依元件類型逐層驗證 |
| 呼叫到同名技能 | 命名空間與作用範圍 | 使用詳細頁的完整名稱 |
| 停用後舊對話仍有指引 | 已載入上下文 | 開新 session 再確認 |

小練習是保存一次外掛清單、版本、範圍與只讀操作結果，接著停用並確認能力消失。完成判準是能說明這個外掛實際增加什麼、需要哪些依賴，以及如何恢復。若只需要單一專案的短流程，直接使用 SKILL.md 往往更容易維護。
