學 Claude Code 指令，第一步是分清楚輸入位置。終端機命令啟動或管理程式，啟動參數調整這一次執行，對話內的斜線指令則操作目前工作階段。本篇會建立一份分類索引，帶你完成查說明、啟動、命名與找回的小練習，避免把所有文字都貼到同一個框。

請先完成自己作業系統的安裝，並知道如何進入[練習專案](article:claude-code-practice-project-setup)。所有範例都標示輸入位置；這篇只使用小型只讀任務，不需要安裝外掛或開啟額外服務。不同平台、帳號與版本的可用指令可能不同，實際選單與官方參考是核對依據。

本篇於 2026-09-14 另以 Windows 上的 Claude Code 2.1.233 實際執行 claude --version 與 claude --help，確認本文所述啟動參數的說明入口。這項檢查只讀取版本與命令說明，沒有啟動代理、登入帳號或呼叫付費服務；對話內斜線指令仍以文末官方指令表核對。

## 三種指令放在三個位置

| 類型 | 範例 | 應輸入的位置 |
|---|---|---|
| 終端機命令 | claude doctor | PowerShell、Bash 或 Zsh |
| 啟動參數 | claude --continue | 終端機，隨 claude 啟動 |
| 對話指令 | /context | 已開啟的 Claude Code 對話 |
| 自訂 Skill | /todo-review | 安裝該 Skill 後的對話 |

斜線指令通常要放在訊息開頭，後面的文字才會當成參數。例如 /compact 後面可以補充摘要重點；若把它埋在普通段落中央，可能只是談論這個指令。遇到教學寫「輸入 /help」，先確認你已經在 Claude 對話，而不是停在 PowerShell 提示字元。

啟動參數常以兩個連字號開頭，短寫可能是一個連字號，例如 --continue 的短寫 -c。不要把文件用來表示可選參數的中括號一起輸入；同樣地，範例中的 session 名稱或路徑若是佔位文字，應換成你自己的值。

## 從只讀說明開始

先在終端機查看版本與完整啟動說明，不會因此建立一個程式修改任務。閱讀說明時先找 Usage、Options 與 Commands，理解哪些是參數、哪些是子命令。需要子命令專屬說明時，可以在後面接 --help，而不是猜測用法。

```bash 專案終端機：查看 CLI 說明
claude --version
claude --help
claude mcp --help
```

接著執行 claude 進入互動對話，輸入 /help。這裡看到的是目前 session 能使用的功能，其中可能包含內建指令、附帶 Skill 與你自己的擴充。名字都以斜線開頭，不代表實作方式與副作用完全相同。

```text Claude Code 對話框：查看對話內指令
/help
```

## 依工作目的找指令

需要了解環境時，先讀[說明與診斷](article:claude-code-help-status-doctor)；要離開後再回來，讀[對話管理](article:claude-code-sessions-resume)；對話很長時，讀[上下文整理](article:claude-code-context-compact-clear)。把用途記住，比一次背完整個指令表更容易使用。

| 目的 | 常用入口 | 操作前要知道 |
|---|---|---|
| 看狀態與診斷 | /status、claude doctor | 兩者輸入位置不同 |
| 命名與找回對話 | /rename、--resume | 名稱不會建立 Git 分支 |
| 整理上下文 | /context、/compact | 摘要仍需保留關鍵條件 |
| 新任務清空對話 | /clear | 不會還原專案檔案 |
| 規劃與授權 | /plan、/permissions | 模式與具體規則要一起看 |
| 查模型與用量 | /model、/usage | 依帳號與版本顯示 |

表格列的是入口，完整操作與限制在專篇中。尤其 /doctor 目前是能提出並協助修正的附帶 Skill，而終端機 claude doctor 是只讀診斷；這種同名差異很容易被舊教學忽略。執行前先看指令分類，避免把主動修改流程當成純資訊查詢。

## 完成一個最小工作流程

在練習資料夾啟動 Claude，先要求只讀介紹專案，再用 /rename 命名。這個名稱用來找回對話，與資料夾名稱和 Git 分支無關。命名後檢查提示列或 session 清單，確認名稱實際套用。

```text Claude Code 對話框：先讀專案
請閱讀 README.md 與 package.json，說明網站如何啟動與測試。
只讀取，不修改檔案或安裝工具。
```

```text Claude Code 對話框：命名本次練習
/rename todo-cli-basics
```

依畫面的退出方式離開 Claude，回到原本終端機，再用 resume 找回。不要在仍開啟的 Claude 對話裡貼 claude --resume，否則可能只是在對話中要求它再啟動另一個程序。

```bash 專案終端機：找回剛才命名的對話
claude --resume todo-cli-basics
```

回來後先看最近訊息是否是剛才的只讀介紹，再問它下一步應如何驗證。若名稱對到多筆結果，選擇器可能要求你挑選；核對時間與專案後再繼續。不要以為命令沒有直接進入對話就是失敗，可能只是需要消除歧義。

## 自訂 Skill 與內建指令

本系列後面會建立 /todo-review 等自訂 Skill。它們只有在對應 SKILL.md 已安裝並載入時才會出現，不能直接把教學中的名稱當成內建功能。第一次使用自訂流程前，閱讀它的內容、工具需求與輸出要求，再決定是否適用目前專案。

內建命令也會隨版本調整別名或功能。看到「unknown option」時，先用相同位置的 --help 核對參數；看不到斜線指令時，查平台、資格與安裝狀態。不要只把所有斜線移除再重試，因為那可能變成另一種自然語言任務。

> 每次複製前先讀程式碼區塊上方的輸入位置。先知道在哪裡輸入，再知道輸入什麼，能避開大部分新手的指令錯置。

小練習是從總目錄搜尋 /compact、MD 與權限，找到三篇不同用途的教學，再各記下一個指令及其輸入位置。完成判準是能辨認終端機命令、啟動參數、內建斜線指令和自訂 Skill，並成功命名、退出與找回一次只讀 session。日常需要快速查找時，再使用[速查與範本庫](article:claude-code-templates-cheatsheet)。
