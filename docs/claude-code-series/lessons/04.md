終端機是用文字操作電腦的介面；Shell 則是解讀那些文字的程式。你在 PowerShell 輸入指令，和在 Bash 輸入指令，雖然都像在黑底視窗打字，語法卻不完全相同。使用 Claude Code 前，先學會確認目前路徑、列出檔案與辨認 Git 狀態，已經足夠開始大部分入門練習。

本篇使用待辦清單資料夾作例子，目標是讓你能自行找到專案，不會在不相關的地方啟動工具。你需要一個可自由修改的練習資料夾；Git 部分需要另外安裝 Git。這裡的查詢指令不會刪除檔案，練習時仍請逐行看懂再執行，不必一次貼上所有範例。

## 確認所在位置

路徑是檔案或資料夾的位置。絕對路徑從磁碟或系統根目錄開始，相對路徑則從目前工作資料夾出發。例如 `model.js` 指目前資料夾裡的檔案，`tests/model.test.mjs` 指 tests 子資料夾中的測試。Claude 啟動時的工作目錄會影響它看到的專案，所以同樣一句指令，在不同位置可能得到不同結果。

Windows 路徑可能包含磁碟代號、空白與中文。把路徑放在引號中，能避免空白被當成參數分界。macOS 與 Linux 常見以斜線開頭的路徑；`~` 通常代表目前使用者的家目錄。先使用檔案管理員找到練習資料夾，再複製它的路徑，會比憑印象猜名字可靠。

```powershell Windows PowerShell：查詢位置與檔案
Get-Location
Get-ChildItem
```

```bash macOS／Linux 終端機：查詢位置與檔案
pwd
ls
```

如果清單裡看不到 README、package.json 或你預期的檔案，先不要啟動 Claude。可能是還停在下載資料夾的上一層，也可能是解壓縮多包了一層同名資料夾。進到真正包含程式的那一層，再列一次檔案；這個小確認能避免把錯誤工作目錄帶到後面的所有步驟。

## 切換到練習資料夾

`cd` 用來改變目前資料夾，後面接目的路徑。以下路徑只是範例，請換成你自己的實際位置；不要把「你的帳號」當成電腦上真的存在的資料夾名稱。`..` 表示上一層，適合從 tests 回到專案根目錄，但連續使用很多次之前，最好再查一次目前位置。

```powershell Windows PowerShell：請替換成自己的實際路徑
Set-Location -LiteralPath 'C:\Users\你的帳號\Downloads\starter'
Get-ChildItem
```

```bash macOS／Linux 終端機：依實際解壓縮位置調整
cd "$HOME/Downloads/starter"
pwd
ls
```

| 操作 | PowerShell | Bash／Zsh |
|---|---|---|
| 顯示位置 | Get-Location | pwd |
| 列出檔案 | Get-ChildItem | ls |
| 切換資料夾 | Set-Location 或 cd | cd |
| 回上一層 | cd .. | cd .. |
| 停止前景程式 | Ctrl+C | Ctrl+C |

## 認識 Git 的三個層次

Git 用來記錄檔案版本。工作目錄是你正在編輯的檔案；暫存區是準備放進下一筆提交的變更；提交則是一筆有訊息的版本紀錄。這三層分開的好處，是你可以檢查正在修改的內容，再決定哪一些屬於同一個完整工作。不要因為 Claude 說修改完成，就把資料夾中所有檔案一起提交。

如果你取得的是 ZIP，裡面通常沒有 Git 紀錄。可以在確定的練習資料夾執行 `git init` 建立新的版本庫；若拿到的是既有專案，先執行 `git status`，不要重建或清除它的設定。本系列後面的[差異與 PR 教學](article:claude-code-git-review-pr)會進一步處理提交和遠端儲存庫。

```bash 已安裝 Git 的終端機：只查看版本與狀態
git --version
git status --short
git diff
```

`git status --short` 會用短標記列出有變更或未追蹤的檔案；`git diff` 顯示尚未暫存的文字差異。第一次看到紅色與綠色區塊，先把它理解成移除和加入的內容，而不是程式正確與錯誤的判定。刪掉一段舊文字也可能是正常修改，關鍵在於是否符合你交代的需求。

## 分清指令與對話

在一般終端機輸入 `claude`，才會啟動 Claude Code 的互動介面。進入後，你可以輸入自然語言任務與它支援的斜線指令；離開後又回到 PowerShell 或 Bash。把 `/compact` 貼到一般 Shell，Shell 不會知道你想整理對話；把 PowerShell 專用語法當作 Bash 指令，也可能出現不相干的錯誤。

1. 在終端機確認目前資料夾。
2. 找到練習專案的 README 與 package.json。
3. 確認你使用的是 PowerShell、Bash 或其他 Shell。
4. 工具安裝完成後，在該資料夾啟動 claude。
5. 使用完畢回到終端機，再次查詢位置與 Git 狀態。

> 執行指令前先看教學標示的輸入位置。冒號、引號、換行與空白可能是語法的一部分，複製後不要為了看起來整齊而任意刪除。


練習時每次切換目錄後都再看一次提示符號或目前路徑。相同的 npm test 在不同資料夾可能執行完全不同的腳本；檔案名稱看似一樣，也不代表來自同一個 Git 分支。把路徑與分支寫進筆記，之後排錯會容易許多。

## 小練習與排錯

請從專案根目錄切到 tests，列出測試檔，再回根目錄，確認 README 又出現在清單中。接著執行 Git 狀態查詢，觀察自己的修改是否被列出。完成判準是你能解釋每一步目前在哪裡，知道檔案沒有因為切換資料夾而消失，也能分清楚「找不到檔案」和「指令尚未安裝」。如果路徑仍常弄錯，把它寫在私人練習筆記，再讀[安裝教學](article:claude-code-install-windows)或你作業系統對應的篇章。
