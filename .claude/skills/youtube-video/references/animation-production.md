# 動畫攝製：來源、聲音、分鏡、小樣與交付

這份 reference 用於要完成動畫表演的漫劇製作，特別是 2026-10-01 的十部、400 集。可執行規格在 `docs/videos/series-plans/production-20261001/profile.json`；每部 `production-design.json` 綁定該版 `source.mjs` 的 `SHA-256(JSON.stringify(source))`。舊匯入文件、內容審稿、生成設計、已渲染、已核准與已上架是不同狀態。

## 先準備可審閱的版本

```text
node tools/video/cli.mjs production-check
node tools/video/cli.mjs production-check --slug wedding-reckoning
node tools/video/cli.mjs production-build --out <LOCAL_REVIEW_DIR>
```

兩個指令都離線：`production-check` 查來源雜湊、逐集覆蓋、開場時碼、角色、造型與規格；`production-build` 產生新待審 bundle、試音文字與本機分鏡預覽。它們不呼叫模型、不做試音、不修改正式站、不替人核准，也不更改歷史收據。新 bundle 的設定集加上 `production_design` 與 `shot_looks`；原故事 source 保留。來源或製作資料改動後重建，比對新雜湊，不能把舊核准當新版本核准。

先讀 `production-review.md` 的具體問題，再核對每集 `hero_shot`、`risk_controls`、`prop_checks`、來源定位與造型 cue。機械檢查只能確認資料契約，不能證明鏡頭好看、聲音自然或劇情沒有矛盾。正式更新 bundle、付費生成與上架依當次已授權範圍執行；這次準備文件不等於已操作正式站。

## 中文版先定案

先完成 zh-TW 自然台灣口音的角色與旁白、全片和可開關 CC。中文版核准並鎖定後，再做 ja、ko、en 角色音軌與各自 CC；漫劇多角色多語配音仍標 `planned-not-implemented-for-drama`，不可把投影片路線的既有 dub 功能當成它已完成。

所有對白、旁白、翻譯與聲音描述都用可開關 CC：`subtitles.burn_in: false`。正片不燒字幕。關閉 CC 仍需看懂主要因果；戲內文件、時鐘、站牌是道具資訊，必要文字另行排版查核後合成在物件上，不信任生成模型直接寫字，也不藉道具名義把整段對白燒進畫面。

## 試音與聲線固定

1. 每角色選定一個 provider/voice_name，旁白另選，保留跨集相同 speaker id。先試平靜對峙、低聲、情緒轉折及本劇人名；選定音色不等於已試聽。
2. 依角色年齡、氣息、停頓、語尾和關係寫表演方向，避免把「生氣」等同加音量。台灣口音不靠把用字改成中國慣用語、誇張捲舌或故意卡音。低聲仍要聽懂。
3. 檢查人名、數字、物件名、同音誤讀與連句一致性，保存採用的短樣片及其 source/voice 版本。不同語言保持同一角色身份，但音色不合可重新 casting，需另留記錄。
4. 人物發音表裡的拼音、片假名、諺文與英文都是草案；須經該語母語聽校後才定案，不用書面轉寫代替實際聽感。

Gemini 聲音描述與模型能力以 [官方語音文件](https://ai.google.dev/gemini-api/docs/speech-generation) 為準；聲音名稱不是性格指令的替代，也不表示每語言已驗收。

## 對時分鏡與代表小樣

先用實際中文台詞時間軸與分鏡做 timed animatic。此步可以用核定靜畫檢查節奏、空間、眼線、造型、道具交接；它是前製預覽，不是完成動畫。

挑一段含「可聽清的角色對話、一個有接觸/重量的動作、會影響劇情的道具」的代表 pilot，另涵蓋同集換裝或傷勢（該劇有時）。例如撕展示副本而原件保留、拿票比對實體站號、交雨衣後原持有人空手。不能只用無人風景證明整套流程可拍。

小樣逐項看：臉與年齡穩定、準備動作→接觸→重量→收勢、視線對到對方、左右手/出口沒有反轉、物件只一份、字可讀、聲音不被配樂蓋住、CC可關且同步。嘴部大特寫另需口型同步驗收；目前沒有因這份文件而實作 lip-sync，不得宣稱自動對嘴。可誠實使用反應鏡、越肩與道具插入承接對白。

問題修完後固定已接受的角色臉、命名造型、聲線、音效母題與視覺樣式，再按篇章放量。修某鏡不等於允許無限重試；沿用既有 retake/預算守門，保存未知結果避免重複付費提交。小樣未渲染/未聽校時清楚標待驗，不寫「已完成」。

## 同一角色的逐鏡造型

保留 `characters[].appearance` 基底及 `characters[].shot_looks: [{id, appearance}]`。每個命名造型的 appearance 是可獨立使用的完整外觀，不只是「同上換衣」；保留臉、年齡、髮型與固定識別點，精準移除已交出的包、錶、鑰匙、徽章等。每鏡用：

```json
{"characters":["zhitang"],"character_looks":{"zhitang":"zhitang-bride-veiled"}}
```

以上是 `scene.data` 片段。id 必須存在於該角色的核定目錄；不換人物 id、不捏造新臉。`look_states[].episodes` 表示該集可能選用，`cue` 決定前後條件；婚紗/前世褲裝、摘冠前後、交袋前後不能用整集覆寫。未選 named look 時仍有基底，不能讓生成器自動補回已離手的招牌物。人物臉參考沿用核定基底；換裝不聲稱供應商支援多圖影片參考。

## Veo 3.1 Lite 的實際鏡頭契約

這批選 `gemini` / `veo-3.1-lite-generate-preview` / `1080p` / `16:9`；原片固定 8 秒、24 fps。支援首格圖及末格，無 `referenceImages`、無 extension。不要悄悄切到 Fast、其他模型或 720p；供應商能力與價格在 [官方Veo文件](https://ai.google.dev/gemini-api/docs/veo)、[官方價目](https://ai.google.dev/gemini-api/docs/pricing) 與 profile 的核實日期查看。既有剪輯時間網格是30 fps；24→30轉換不等於增加真實動作細節。

此 profile 是 `clips`：正片每鏡都要有可見、合乎因果的動作，拒 `visual: still` 和 freeze padding。每鏡只一個主要動作與一個 camera 意圖；「伸手、拿起、交出、對手反應」拆鏡。8秒素材可剪2–8秒有效段，通常2–5秒（節奏、開場與鏡位的目標見 `.agents/skills/youtube-video/references/drama-craft.md`，分鏡寫完用它的檢查腳本量）；對白不合就調台詞/分鏡並重新量時，不硬拖慢、凍結或加無意義旁白補秒。鏡頭不能超過原片8秒。

`data.prompt` 寫單格構圖；`data.motion` 寫一個行為；`data.camera` 選一種運動。證物插鏡也讓手、紙邊、視線或環境有可信運動；別把縮放一張公文當成完成動畫。關鍵文字在動態物件上做經檢查的合成，避免每幀錯字漂移。

## 聲音與後續四語

乾燥角色人聲、旁白、環境/音效、音樂各自保存。丟棄Veo原生人聲/音訊，不與TTS雙重發聲。重要台詞時降低雨、車、火與樂床；同時只一個人交代必要資訊。依 profile 用現有兩次量測混音，內部目標 -14 LUFS / -1 dB true peak，實際數值與聽感都要驗，不把它說成YouTube保證標準。

日、韓、英版使用同一已核准畫面主版，但對白要按角色關係與可演性翻譯。保留 line/speaker ids、關鍵否定、數字、方向、知情先後與謎底揭露時點；先縮短措辭再考慮句速。不能把完整中文混音墊在外語人聲下面。各語用自己的實際音軌重算CC落點和閱讀速度，不複用中文時間碼，不讓字幕提前劇透。四個語言的試聽/全片/CC/播放器接受狀態分開記。

已核定的後續語言計畫須保存為 `video.json.localization_plan`，工作區另存 `localization-retention.json`。`tidy` 會保留這類集數及其合集的畫面、逐句乾聲、音效與音樂來源；中文上架、當次網站語言選擇為空、滿七天或放棄狀態都不代表已交付日／韓／英。舊集數可由 `series.json.production` 認出保留要求。驗證歸檔及站主解除保留的介面尚未實作，不能手改為「已完成」讓清理放行。

配音聽審須綁定實際逐句 WAV 與整段旁白的 SHA-256，不能只看文字及秒數。同字同長度的重錄也要重新聽審，既有聽校結論與成片快取不得套到新 take。缺少或不匹配的音訊證據先停止；舊時間軸可用現有錄音離線重建證據，再重新送審，不能把重建 metadata 當作已聽過或自動付費重錄。

## 觀眾與交付驗收

片名前的承諾、縮圖及預告只用已允許的前段資訊，前5秒鉤子與30秒第一次回報要用實際聲音和剪輯量測。每集hero行為與代價可見，不連續念文件。結尾完成主要選擇，不為留存捏造續集危機。

百萬觀看是成效目標，不保證。上架後以頻道自己的曝光基準比較點擊與前30秒/換篇留存，檢查流失和重看原因，不捏造通用CTR門檻。準备好设计、通过lint、或有一段能播放的小样，都不能代替整片觀看、各聲軌/CC檢查及站主最後上架。

## 未成年人物與供應能力

Veo Lite目前首格I2V的`allow_adult`不能視為已支援未成年人入鏡。先按來源年齡與實際畫面核對`characters[].video_constraints`；`min_visual_age_years < 18`、`veo_lite_i2v: "not-verified-under-18"`表示該人物的Lite入鏡路徑未驗證，不能直接送付費生成。純畫外配音與未顯示該人物的鏡頭分開判斷。

未列角色ID的孩子也不能漏掉：`production.episode.video_constraints.veo_lite_i2v: "unverified-minor-on-screen"`表示該集有來源已確認、尚未解決的未成年入鏡。整集先停止等待可用的製作路徑，不用成人同場ID通過檢查就放行。

保留原劇年齡。不得改成年，也不能把背影、局部、不寫年齡、卡通風格或「只是幻象/照片」當作保證可用的捷徑。先選手繪動畫或合法可支援該年齡的供應商，以含該角色的pilot確認能力與效果再排量。成人角色只是背景史提到13歲，不把成人ID所有鏡頭全域降成13歲；真要拍少年回望時，必須先明列那個look及集/鏡，再做相應能力驗證。尚未驗證時不能宣稱全400集可直接照Lite規格開拍。
