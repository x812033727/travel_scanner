## 指定的額外檢查

- **第一秒、開場 30–60 秒：**`x160101`／`x16-b01-s01` 從 0:00 開始，但具體性不足如 Q1。第一章 127 個口播單位，按每分鐘 230–250 單位及 JSON 的場景留白，工具紙面估時約 **35.5–38.2 秒**，在 30–60 秒內；末句 `[x160109]` 確實是全片問題。
- **正文至少八分鐘：**第二章首 `x160201` 到 outro 前 `x160630` 共 **2,209 個口播單位、163 句**。只算字的純說話時間，在每分鐘 250／230 單位下約 **8:50／9:36**；連 JSON 場景留白，估時約 **10:02／10:49**。這是紙面推估，**沒有實際 TTS 音訊長度或實聽驗證**。
- **30–45 秒鉤子：**`loops` 有 30 組，工具按 240–250 單位／分鐘的估算沒有 >45 秒形式空檔；用稿中允許的較慢 230 單位／分鐘估算，`[x160205]` 約 01:05 至 `[x160214]` 約 01:51 有 **46 秒**，略超 45 秒。多個問句下一句就答（如 `x160305 → x160306`），成音後仍須以真正的懸念而非問號數量審節奏。
- **章末與章首：**`x160332 → x160401` 回答實關 205，`x160426 → x160501` 回答一月是另一批，`x160527 → x160601` 回答同店轉正；`x160227 → x160301` 的重述則使 Q5 未過。
- **三句結尾：**`x160641`–`x160643` 形式上恰有三句，留言題與有理由的訂閱邀請成立。但首句只重講「現在與未來回報、不看店齡」，**沒有用數字回答標題與 `x160109` 承諾的「最後關幾家」**；588 已在 `x160630` 提前說出。因此品牌故事的三句結尾內容關卡 **NO**，即使 Q10（不提下一支）是 YES。
- **兩支 Shorts：**`shorts.json` 有兩支、各八景，結構驗證 `episodeShortsProblems` 回傳空陣列。Short 1 從約 600／七成新店走到分母及選店條件；Short 2 從同店 −6%／+7% 走到第 53 週、交易與客單及不可單歸關店；各自有 hook、turn、proof、payoff，不靠「到長片找答案」。口播單位為 **137／142**，每分鐘 230–250 單位的純說話估時約 **33–36／34–37 秒**。
- **9:16 裁切／原生卡：**兩支共 16 個 `shot` 引用都能在主片找到，16 個相應 prompt 都明寫人物、手與主要物件留在 1920×1080 畫面中央 **608 px** 走廊。Shorts 工具採 **1080×1920** 輸出，將長片 keyframe 置中裁切作背景，另以 Shorts 自己的 `headline`／字幕透明卡覆蓋；不是把主片 `stats` 卡直接擠進直幅。這只證明 JSON 意圖與程式路徑；沒有已生成 keyframes 或 Short 成片，不能保證每一張實際構圖、字卡安全區及可讀性。

優先修稿點是把 `x160101` 的公告變成有可見動作的開場時刻、讓 `x160301` 直接給新進展、刪合併重述與旁支，並將 588 留給三句結尾首句作承諾的數字答案。畫面若要支撐口播的同一條線，應讓七月那批店卡或某個匿名門市有可追蹤的視覺特徵與空間後果；概念插畫仍不應冒充任何真店或真員工。
